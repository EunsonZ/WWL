# Bases 导航

> [!abstract] 一句话理解 Bases
> 笔记和属性仍保存在本地 Markdown 文件中；`.base` 文件保存过滤、列、排序与视图定义。本批 Base 只定位并读取 `Obsidian知识/` 下的教学材料；把它们当作只读导航与 schema 样本，不在此教学区修改源属性。

> Base 的目标集合可以合法为空，例如新建教学目录尚无课程，或视图的额外条件没有匹配项。但若已知课程存在而视图为空，应先检查筛选。[[Obsidian知识/20-功能/02-社区插件实验室/03-Dataview与Bases对比|Dataview 与 Bases 对比课]] 应出现在“社区实验”；[[Obsidian知识/20-功能/02-社区插件实验室/00-社区插件实验室-MOC|社区插件实验室 MOC]] 不应作为课程行出现。
>
> 排查顺序：确认文件已保存并被 Obsidian 索引；核对真实路径、`type` 和被排除的 MOC 文件名；再看视图的附加筛选与显示列。不要为了让视图出现结果而补写未定义属性。

“课程目录”覆盖基础课程、官方实验与社区实验；`status` 显示作者标记的内容状态，不表示你已学会。`stage` 是课程阶段，`order` 是单元内顺序；`difficulty` 和 `level` 保留原页不同的难度标记，空白表示该页未记录，不能据此推断容易或已完成。

Base 不可用时，按 [[Obsidian知识/10-基础/01-Markdown基础/00-Markdown基础-MOC|Markdown 基础]]、[[Obsidian知识/10-基础/02-链接与知识网络/00-链接与知识网络-MOC|链接与知识网络]]、[[Obsidian知识/10-基础/03-属性标签与检索/00-属性标签与检索-MOC|属性标签与检索]] 的顺序学习基础；插件课从 [[Obsidian知识/20-功能/01-官方插件实验室/00-官方插件实验室-MOC|官方实验路线]] 与 [[Obsidian知识/20-功能/02-社区插件实验室/00-社区插件实验室-MOC|社区实验路线]] 进入，正文 MOC 仍说明操作目的与先后关系。

## 轮到你做

1. 打开 [[Obsidian知识/40-视图/02-Bases/示例笔记目录.base|示例笔记目录]]。
2. 切换“全部样例”和“样例卡片”。
3. 在表格中比较 `type`、`status`、`topics`、`fixture_reviewed`。
4. 阅读甲的源 Markdown，确认 `energy: 4` 是被 Base 显示的属性。
5. 本教学样本不要求修改属性；如在个人副本试验，先确认可回滚。

## Base 与 Search 的分工

- Search 适合临时提问、全文命中与任务行上下文。
- Base 适合反复使用的结构化集合、列、排序、分组和卡片。
- Search 结果中的文本命中非常精确；Base 更依赖文件与属性 schema。
- 两者都引用源文件，不是副本。

## 常见问题

### 为什么刚创建的笔记没有出现

依次检查：文件是否已保存并完成索引；路径是否满足 `file.inFolder(...)`；`type` 是否符合该 Base 的实际课程类型；该文件是否是被明确排除的 MOC；最后再检查视图自身的附加筛选。标签只有在该 Base 明确使用标签时才是条件。

### 为什么一列看起来混乱

同名属性可能被写成不同类型。例如 `progress: 40` 是数字，`progress: "40%"` 是文本。用 Properties view 检查全 vault 的属性类型，不要直接编辑 `.obsidian/types.json`。

### Base 能否代替 MOC

不能完全代替。Base 擅长按规则重组，MOC 则表达作者设计的叙事顺序、说明与取舍。本页就是 MOC，四个 `.base` 是动态目录。
