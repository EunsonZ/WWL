# 从论文主张到可复现实验

**先修与定位：** 先读下面同一次判断，再把它推广为实验协议。需要选择对照、核查算子或核对论文身份时，分别借读[[AI/10-机器学习与深度学习基础/18-嵌套验证配对实验与指标陷阱|实验设计]]、[[AI/12-PyTorch/06-梯度诊断数值验证与自定义算子|实现检查]]和[[AI/90-资源/07-本轮研究来源与证据台账|来源台账]]，随后返回当前主张，不把整套规范当作有限例的入场条件。

## 先读一次已经能判定的主张

沿用 [[AI/20-LLM/80-研究拓展/01-机制可解释性Probe干预与稀疏特征#把原反例走完：改变 a，输出会不会跟着变|Probe 反例的完整对照表]]：`h=(a,b)`，`a,b∈{0,1}`，probe 读 a，原输出只读 b。此处继续审同一主张，不换成模型性能或 GPU 加速的问题。

1. **主张与预测。** “probe 准确恢复 a，足以说明原输出依赖 a。”若要支持这种依赖，至少需要解释固定 b 后改变 a 对原输出有什么作用。
2. **对照。** 固定两个读出函数，从基线 `(0,1)` 分别只改 a 为 1、只改 b 为 0；两次变化幅度相同。比较单位是这一次干预前后的原输出，不能把 probe 输出偷偷替换成主指标。
3. **观察。** 改 a 后 probe 从 0 变 1，原输出仍为 1；改 b 后 probe 仍为 0，原输出从 1 变 0。这两种结果都由原映射计算得到，后者也说明当前读出并非无法变化。恢复基线后两个读出恢复原值。
4. **结论与限制。** 已足以否定“可解码就推出原模型使用”的普遍推论；只说明这个模型中 a 的可解码性与原输出依赖不同。它不是 LLM 实测、统计显著性结论或新电路发现，也不能把真实模型的一次无效应干预解释成所有条件下都无依赖。

上一课另借读的 decoder 未来 ID 替换，是有源码与历史运行记录的计算图依赖检查；两坐标表则是已知映射的代数反例。这两个对象分别回答“可解码是否足以推出使用”和“指定前缀会不会受到未来输入影响”。输入、读出与证据层都不同；它们共同采用固定其余条件的比较，不能把一个检查通过移作另一个主张的验证。

现在才推广到论文：真实研究通常没有预先给出的 `y=b`，所以要写清可能失败的预测、替代解释、结果与剩余混淆。填写记录或成功运行，只能说明相应步骤完成；主张是否成立仍取决于这些对照与观察。

## 把结论拆成可以失败的命题

“方法更好”至少包含目标任务、对照方法、数据、预算、指标和差异大小。改写为“在固定数据与训练 token 下，方法A相对B将独立测试平均错误率降低至少某个量”，才知道什么结果能支持或反驳它。不要把“理论存在一种参数配置”直接翻译成“常规训练必然学到”，也不要把一个算子更快翻译成全系统更快。

本库把证据分为定义/代数推导、受控数值测试、特定实验观察和跨设置推广。前一级成立并不自动保证后一级。注意力梯度通过验证，只说明该计算正确；它不证明模型泛化，也不证明数据无污染。

## 每个方法都写出替代解释

假设加入模块后分数上升，替代解释可能是参数更多、训练更久、超参数搜索更多、数据过滤改变或测试泄漏。设计参数匹配、算力匹配、空模块、随机模块和旧配方加强基线，可以排除不同解释。没有一种对照能排除所有因素，应写清剩余混淆。

同时记录负结果和失败种子，避免只保留最好的一次。若方法仅在某个域有效，限制结论范围比把它平均掉更有信息。效应量与不确定性见[[AI/11-数学与统计桥梁/05-统计估计置信区间与因果边界|统计估计]]。

## 理论证明与代码验证如何互补

推导先列假设和形状，检查极限、单位、对称性与不变量。代码用小规模解析解、有限差分、独立库实现和故意注入错误的反例验证。两个共享同一错位标签的实现可以彼此完全一致，所以差分测试也要保证参照独立。

例如[[AI/20-LLM/20-架构/10-注意力反向传播与Softmax竞争|注意力]]有行梯度和为零的不变量，[[AI/20-LLM/40-推理/08-投机解码接受拒绝与分布不变性|投机采样]]有输出概率归一及分布还原，[[AI/15-卷积神经网络/04-卷积反向传播与转置卷积|卷积]]有伴随内积恒等式。把这些性质变成测试，比仅随机跑一遍检查“不报错”更有价值。

## 复现至少有三种含义

第一，**算子复现**：重现关键公式和算法在小样本上的行为。第二，**实验复现**：在明确环境、数据和预算下重现论文某项实验及误差范围。第三，**独立验证**：改变数据、实现或环境后检验主要结论稳健性。

本轮数值实验主要属于第一层；原有CPU小实验属于其声明的具体小规模运行。没有真实GPU或模型权重实验，就不把 FlashAttention-4、Mamba-3 等论文性能列为本库实测。其论文身份和发布日期已核对，性能仍作为作者报告而非本轮结论。[^S21][^S22]

## 可直接复用的实验记录模板

回看有限读例，`claim` 是待反驳的推出方式，`controls` 是固定另一坐标与读出规则，观测要同时保留原输出改变和不改变的两行，`limitations` 则明确已知映射与真实 LLM 的距离。下面增加数据版本、预算、seed 和停止规则，是为了处理未知机制与真实实验的不确定性；这些字段写齐也不会把缺失的干预或观测补出来。

```yaml
claim: "要验证的具体命题"
hypothesis: "可能机制与方向性预测"
alternatives: ["预算差异", "数据重叠", "优化未收敛"]
primary_metric: "主指标及聚合单位"
minimum_effect: "有实际意义的差异"
train_data_version: "不可变清单或哈希"
evaluation_protocol: "切分、盲化、失败计分"
controls: ["算力匹配基线", "单因素消融"]
seeds: [0, 1, 2]
resources: "实际硬件、时长、token与显存记录"
stop_rule: "预先约定的预算与停止条件"
limitations: "未控制因素与不能推出的结论"
```

这个模板不是预设三个 seed 就总够，而是要求记录；合适重复次数取决于差异规模与资源。最终保存原始逐样本结果，不只保存汇总截图。审计与恢复连接[[AI/12-PyTorch/07-完整训练状态恢复与可复现实验|训练状态]]和[[AI/20-LLM/70-工程应用与工具链/10-LLM评测污染裁判偏差与统计检验|评测记录]]。

## 如何读不断变化的新论文

先核对标题、作者、首发日期、所用版本和是否有更正，再沿“主张、方法、对照、数据、指标、限制”提取。动态文档要注明访问日期，代码接口尽量绑定实测版本。标题中出现新代号不代表它已经成为共识，也不能只因不熟悉就断言不存在。

自测：论文主张算子在某GPU上加速2倍，本库CPU测试输出一致，是否已经复现该性能？没有。算子语义验证和GPU性能验证是不同实验，需要分别报告。
