# 错误作为数据：Result、模块边界和可验证的失败路径

> **学习位置**：[[计算机知识/00-开始/课程地图/03-Rust-课程地图|Rust课程地图]] · **适用边界**：Rust 2021 edition 兼容示例；2024 edition 差异另行标识。

## 先分类错误，再决定传播方式

`Option` 表示可缺失，`Result` 表示成功或携带错误。找不到可选配置不一定是错误，读到配置但语法损坏则可能需要报告。把两者都变成 `None` 会丢失决策信息。

一个解析器可以把语法错误、数值超范围和未知字段分成不同错误变体。应用层再决定哪些给用户看、哪些记录日志、哪些允许重试。底层过早返回任意字符串，会让上层难以可靠分类。

```rust
#[derive(Debug, PartialEq)]
enum CountError { Syntax, Range }
fn parse_count(text: &str) -> Result<u16, CountError> {
    if text.is_empty() || !text.bytes().all(|b| b.is_ascii_digit()) {
        return Err(CountError::Syntax);
    }
    let n: u32 = text.parse().map_err(|_| CountError::Range)?;
    if n > 1000 { return Err(CountError::Range); }
    Ok(n as u16)
}
```

这个合同只接受 ASCII 数字，不接受空白和符号；超长纯数字串归入范围错误。转换到 u16 前的上界已经证明转换安全。若业务需要保留原始解析错误，可定义携带原因的错误类型，而不是丢弃上下文。

## `?` 只传播，不回滚外部副作用

`?` 在失败时提前返回，并按类型转换规则处理错误。已被修改的普通状态不会自动回到调用前，已发送的请求也不会自动撤销。需要强失败保证时，先在局部构造候选状态，验证成功再提交；需要事务时使用真正的事务协议。

`unwrap` 适合已证明前提的受控场景，不能作为外部输入的常规验证策略。即使是“理论不可能”的分支，也应在注释或类型结构中给出证明来源，而不只是写 `expect("impossible")`。

## panic 与资源清理的边界

panic 可能采用展开或终止策略。展开时正常 RAII/Drop 机制可以清理许多资源，但进程中止、强制结束、内存耗尽等并不保证执行全部清理。内存安全不等于不会泄漏、不会死锁、不会耗尽资源或不会产生错误业务结果。

跨 FFI 边界的展开规则取决于 ABI 与语言契约，不能让 panic 或外部异常任意穿过不支持的边界。库应明确哪些错误以 Result 返回，哪些条件可能 panic，哪些函数可能阻塞。

## package、crate、module 各有职责

package 由 Cargo 清单组织，可含库和二进制 crate；crate 是编译与名称组织的重要单元；module 控制内部结构与可见性。`use` 主要提供名字路径便利，不等同于像 Python 那样每次执行一段动态导入逻辑。

`pub` 应尽量围绕稳定领域类型和必要行为开放，而不是把所有内部实现公开。集成测试通过公共 API 发现接口不完整，单元测试可针对内部不变量。workspace 组织多个 package，feature 通常在构建解析中参与能力选择，不是随意独立的运行时开关。

## 测试从规格出发

对 `parse_count`，先列出空串、0、1000、1001、负数、尾随字符、Unicode 数字和超长数字串，再写预期错误类别。只断言 `is_err()` 无法发现错误分类被破坏。

属性测试可以生成很多输入，差分测试可与简单参考解析器比较，模糊测试适合寻找崩溃或资源问题。它们覆盖的是输入分布与执行路径，不是全称证明。文档测试可以让教程示例接受编译检查；故意不能编译的例子要标为 compile-fail，并验证失败原因不是无关拼写错误。

## 构建也是信任边界

构建脚本和过程宏会在构建阶段执行代码。下载一个 Rust 仓库后运行 Cargo，并不只是“静态看源码”。依赖来源、锁文件、审计、许可证、最小 feature 集和 CI 权限都属于工程边界。

2021 edition 与 2024 edition 是语言兼容模式，不是编译器版本号。新增语法和库 API 还受最低支持 Rust 版本约束。项目清单及实验报告应分别记录 edition、工具链版本和目标平台。

## 练习与答案

把解析与 I/O 拆开有什么好处？纯解析可以在内存中覆盖所有边界，不需要制造文件权限或网络故障；I/O 层只负责有限读取、编码及上下文。错误组合时保留原始原因，日志进行脱敏，这使失败真正成为可分析的数据。
