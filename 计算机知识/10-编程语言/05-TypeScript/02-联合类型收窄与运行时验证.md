# TypeScript：联合类型、收窄与输入边界

> 阅读定位：严格类型检查；运行时语义属于 JavaScript，宿主 API 另行区分。返回 [[计算机知识/00-开始/课程地图/05-TypeScript-课程地图|TypeScript · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## 用互斥状态代替松散标志

```typescript
type State<T> =
  | { kind: "loading" }
  | { kind: "success"; value: T }
  | { kind: "error"; message: string };

function describe(s: State<number>): string {
  switch (s.kind) {
    case "loading": return "加载中";
    case "success": return String(s.value);
    case "error": return s.message;
    default: {
      const unreachable: never = s;
      return unreachable;
    }
  }
}
```

判别字段使编译器知道每个分支有哪些属性。增加新状态后，never 检查帮助找到遗漏分支。它只证明静态输入类型中的覆盖；若你把未经验证的 JSON 强行断言为 State，运行时仍可能出现陌生 kind。

## unknown 比 any 更适合信任边界

any 会使相关检查被绕开并传播不受约束的操作；unknown 要求先取得证据。`as`、非空断言 `!` 和类型断言函数都不会凭空验证数据。用户自定义类型守卫可以写错，因此守卫内部的检查也需要测试。

```typescript
type User = { id: number; name: string };

function parseUser(value: unknown): User {
  if (typeof value !== "object" || value === null || Array.isArray(value)) {
    throw new Error("需要普通记录形状");
  }
  const v = value as Record<string, unknown>;
  if (typeof v.id !== "number" || !Number.isSafeInteger(v.id) || v.id < 0) {
    throw new Error("id 无效");
  }
  if (typeof v.name !== "string" || v.name.length === 0) {
    throw new Error("name 无效");
  }
  return { id: v.id, name: v.name };
}
```

断言只把检查后的对象交给可逐字段读取的视图，后续实际验证每个字段。返回新对象避免把未知额外字段直接传播。这仍不是面对任意恶意 JavaScript 对象的完全隔离器：getter/proxy 可执行代码。本例的输入合同应是已解析、带长度上限的 JSON 数据。

## 可选不等于所有缺失方式都相同

`x?: number` 表示属性可能不存在，与“属性总存在但值可为 undefined”存在区别，尤其启用 `exactOptionalPropertyTypes` 时。数组下标也可能越界，启用 `noUncheckedIndexedAccess` 可让静态类型提醒处理缺失，但仍需正确运行时逻辑。`strictNullChecks` 防止把 null/undefined 无差别混进普通值。

练习：为解析器加入 name 长度上限与未知字段策略，测试 null、数组、缺字段、浮点 id、超出安全整数的 id、空名字。解释“JSON.parse 成功”“通过形状校验”“符合业务规则”这三个证据层次。
