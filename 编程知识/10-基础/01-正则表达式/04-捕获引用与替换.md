# 04 · 捕获、引用与替换

## 本课目标

把一次匹配中的字段单独取出，理解编号组和命名组，并在替换时安全地重排文本。

## 捕获组把结果分成字段

模式：

```regex
^([0-9]{4})-([0-9]{2})-([0-9]{2})$
```

输入 `2026-08-31` 时，通常得到：

| 组 | 内容 |
| --- | --- |
| 完整匹配 / group 0 | `2026-08-31` |
| group 1 | `2026` |
| group 2 | `08` |
| group 3 | `31` |

编号按捕获组的左括号从左到右产生。在旧表达式中间新增一个捕获组，后面所有编号都可能变化。因此，仅用于结构的括号应写成 `(?:...)`，重要字段则适合命名。

## 命名组的方言差异

Python：

```regex
^(?P<year>[0-9]{4})-(?P<month>[0-9]{2})-(?P<day>[0-9]{2})$
```

现代 JavaScript：

```regex
^(?<year>[0-9]{4})-(?<month>[0-9]{2})-(?<day>[0-9]{2})$
```

命名后的结果更接近业务语言：`year`、`month`、`day` 比“第 1、2、3 组”更不容易误用。具体读取方式由宿主 API 决定。

## 反向引用要求再次出现相同文本

反向引用不是“重复同一个规则”，而是“匹配先前捕获到的完全相同文本”：

```regex
\b([A-Za-z]+)\s+\1\b
```

它可发现 `the the`、`is is` 这类连续重复词。`\1` 指向第 1 个捕获组。

命名反向引用的语法也依引擎而异：

- Python 模式中常用 `(?P=name)`；
- JavaScript 模式中常用 `\k<name>`；
- RE2 不支持反向引用。

反向引用会增加引擎需要记忆和尝试的状态，也会降低跨引擎兼容性。能用普通逻辑比较两个字段时，不一定要把比较塞进正则。

## 替换语法不属于正则本体

替换字符串由宿主工具解释，常见写法并不统一：

| 环境 | 常见编号组引用 | 常见命名组引用 |
| --- | --- | --- |
| Python `re.sub` | `\g<1>` | `\g<name>` |
| JavaScript `replace` | `$1` | `$<name>` |
| 一些编辑器 | `$1` 或 `\1` | 依编辑器而异 |

因此必须分别记录：

1. 查找模式；
2. 替换模板；
3. 使用的语言或编辑器；
4. 替换前后的样本。

## 同一业务规则在 Python 与 JavaScript 中的完整差异

下面两段代码都把日期字段提取为命名组，并重排为 `DD/MM/YYYY`。**模式形状相似，不代表组语法、取值 API 或替换模板相同。**

Python 使用 `(?P<name>...)`、`match.groupdict()` 与 `\g<name>`：

```python
import re

date = re.compile(r"(?P<year>[0-9]{4})-(?P<month>[0-9]{2})-(?P<day>[0-9]{2})")
match = date.fullmatch("2026-08-31")
assert match is not None
assert match.groupdict() == {"year": "2026", "month": "08", "day": "31"}
assert date.sub(r"\g<day>/\g<month>/\g<year>", "2026-08-31") == "31/08/2026"
```

现代 JavaScript 使用 `(?<name>...)`、`match.groups` 与 `$<name>`：

```javascript
const date = /^(?<year>[0-9]{4})-(?<month>[0-9]{2})-(?<day>[0-9]{2})$/;
const match = date.exec("2026-08-31");
if (match === null) throw new Error("expected a date");
if (JSON.stringify(match.groups) !== JSON.stringify({ year: "2026", month: "08", day: "31" })) {
  throw new Error("unexpected groups");
}
if ("2026-08-31".replace(date, "$<day>/$<month>/$<year>") !== "31/08/2026") {
  throw new Error("unexpected replacement");
}
```

两段代码都故意使用完整匹配，避免“只从一段较长文本中找到了日期片段”被误认为通过校验。它们只验证文本形状；日期真伪仍应交给日期时间库。Python 中字符串、异常与文件 I/O 的基础语义见 [[计算机知识/10-编程语言/01-Python/05-异常文件IO与上下文管理|异常、文件 I/O 与上下文管理]]，测试组织见 [[计算机知识/10-编程语言/01-Python/14-测试调试与代码质量|测试、调试与代码质量]]。

## 可观察例子：重排日期

查找：

```regex
\b([0-9]{4})-([0-9]{2})-([0-9]{2})\b
```

JavaScript 风格替换：

```text
$3/$2/$1
```

结果：

```text
2026-08-31  ->  31/08/2026
```

这个操作只重排字段，不验证日期真实存在。批量替换前应先预览全部命中，并保留可恢复的版本快照。

## 可选组与空值

```regex
^([A-Za-z]+)(?:-([0-9]+))?$
```

输入 `item` 时，第 2 个捕获组没有参与匹配；不同 API 可能把它返回为 `None`、`undefined`、空字符串或缺失字段。下游代码必须明确处理，而不是假设每个组都有值。

## 练习

从下面一行中提取 `date`、`level` 和 `code`：

```text
2026-08-31 level=ERROR code=E104 message=timeout
```

要求：

- 为三个字段使用命名组；
- 不捕获固定文本 `level=` 与 `code=`；
- 再写一个替换方案，输出 `ERROR/E104 @ 2026-08-31`；
- 标明使用 Python 还是 JavaScript 的命名组与替换语法。

把结果写入 [[编程知识/30-实践/01-正则表达式实验区/02-练习场#练习 4 · 日志字段提取|练习场]]。

## 成功标准

- 我能区分完整匹配、编号捕获组和命名捕获组。
- 我知道 `\1` 表示先前捕获的文本，而不是重新执行第 1 组的规则。
- 我会单独确认查找语法与替换语法。
- 批量替换前，我有输入样本、预期输出和恢复方案。
- 我能把同一命名字段规则分别写成 Python 与 JavaScript 的模式、取值和替换代码，而不混用两边的方言。
