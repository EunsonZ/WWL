# C++ 实验室

这里是可修改、可重建的 C++ 实验区。每个实践把 Markdown、源码、`CMakeLists.txt` 和测试放在同一目录；文中的 `code-sync` 区块逐字对应伴随文件。稳定概念先回到 [[计算机知识/10-编程语言/02-C++/00-C++-MOC|C++：从语言到 llama.cpp · MOC]]，再把本页当作动手验证的地方。

## 使用顺序

1. [[计算机知识/80-实践/03-C++/01-构建与调试小项目/README|构建与调试小项目]]：从 CMake、单元测试与调试器的失败现场建立最小闭环。
2. [[计算机知识/80-实践/03-C++/02-RAII与张量缓冲区/README|RAII 与张量缓冲区]]：用所有权与形状不变量解释“为什么不手写 `new` / `delete`”。
3. [[计算机知识/80-实践/03-C++/04-布局缓存与并行归约/README|布局、缓存与并行归约]]：以测试、计时、优化报告三层证据比较 AoS/SoA、线程局部归约和 SIMD 候选循环。
4. [[计算机知识/80-实践/03-C++/03-llama.cpp-token概率与耗时trace/README|llama.cpp token 概率与耗时 trace]]：在固定上游提交与本地 GGUF 模型前提下读 C API 的 logits 与时序；它不会下载模型、不会发送提示词。

## 安全边界与恢复

- 每次构建只允许在相应项目目录的明确 `build/` 下进行；不要把构建目录设为仓库根目录、家目录或其他课程目录。
- 清理前先确认当前目录是目标项目目录，并确认 `build/CMakeCache.txt` 存在。课程给出的清理动作只移除该目录创建的 `build/`，源文件、模型与其他实验目录不会成为目标。
- 若改坏源码，优先用编辑器撤销或版本控制的差异查看恢复；本课程不会自动暂存、提交、下载依赖或删除任何目录。

## 跨域地图

资源生命周期、缓存局部性和 ABI 的解释见 [[计算机知识/30-计算机系统/00-计算机系统-MOC|计算机系统 MOC]]；把连续张量缓冲区搬到设备端前，先走 [[计算机知识/40-并行与异构计算/01-CUDA/00-CUDA-MOC|CUDA 学习路线]]。llama.cpp 的实践连接到 AI 课程的 [[AI/20-LLM/50-实现/04-llama.cpp构建后端与调用链|构建、后端与调用链]]、[[AI/20-LLM/50-实现/05-llama.cpp源码阅读与小型扩展|源码阅读与小型扩展]]，以及 [[AI/20-LLM/60-模型格式与量化/03-GGUF结构转换与验证|GGUF 结构、转换与验证]]。

## 完成标准

- 前三项不依赖外部源码的实践都能在各自独立的 build 目录中配置、编译并通过 CTest。
- 你能让第一项的失败分支停在调试器中，并说清调用栈、局部变量和异常抛出点分别回答什么问题。
- 你能指出第二项张量的所有者、形状、元素总数与越界检查位置。
- 你能在第三项把正确性测试、计时结果和 SIMD 代码生成证据分开记录，不把一次最快结果当作普遍性能结论。
- 你能在第四项记录完整提交 SHA、CMake 配置、模型文件校验值、`n_ctx`、线程/后端与 trace 输出；不同设置的数字不能直接混比。
