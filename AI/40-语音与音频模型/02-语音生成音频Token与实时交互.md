# 语音生成、音频 Token 与实时交互

<!-- deep-review-02 -->

语音生成不仅要输出词，还要输出时长、韵律、停顿和声学细节。因此“文本正确”“声音自然”“延迟够低”应分开评估。

## 两类主要接口

传统模块化路线把文本规范化与发音信息转成声学特征，再由声码器生成波形。它容易定位前端读音、时长、声学和波形问题，但模块误差会累积。另一类路线先用神经音频 codec 把连续波形压成离散代码，再用序列模型预测代码，最后解码成波形。

量化代码是声学表示，不是文字词表。若使用多级残差量化，后续码本逐步描述前一级未表示的误差。减少码本可降低码率，却可能损失细节；模型还要决定时间轴与码本轴怎样串行、并行或交错预测。文本 token 和音频 token 的单位不能直接比较。

## 与 LLM 组合时会失去什么

ASR → LLM → TTS 的级联便于替换组件，但纯文本中间层可能丢掉说话节奏、笑声、犹豫和非语言声音。端到端音频语言模型可以保留更多声学条件，却更难归因：错误究竟出在听觉、语言推理还是发声，需要设计干预测试。

双工交互还需要知道用户何时开始说话、何时停下、是否打断系统，以及生成缓存是否应该取消。端点检测过早会截断语句，过晚会增加延迟。任何网络或工具失败都应能中止播放，而不是不断读出已失效的回答。

## 成本和评测

总时延包含采集缓冲、特征提取、模型首块生成、音频解码、传输和播放缓冲。模型“每秒产生多少音频 token”只是其中一项。分别记录首个可播放片段延迟、稳态实时系数、抖动、断句错误和打断恢复。

自然度可通过预先规定的人类听测评价，但需要盲测、样本随机化和足够听者。内容正确率、可懂度、音素/文字错误和噪声鲁棒性是不同轴。不能仅用一个自动感知分数证明声音可靠。

## 本包实验边界

本页是机制与系统接口教程，没有预置声纹克隆、真实录音或特定模型权重。实验只使用合成信号验证时间/频率轴与 CTC 折叠。真实录音需要来源、同意、保留期和访问范围记录；合成内容应明确标示，不用于冒充真实发言。

**练习：** 0.6 的平均实时系数能否保证 200 ms 首响？不能。若开始前先等待 2 秒音频，首响已经超过目标。应测量端到端时间线，而不是只看模型计算段。
