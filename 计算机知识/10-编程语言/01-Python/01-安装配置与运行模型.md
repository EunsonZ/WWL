# 01 · 安装配置与运行模型

## 本课目标

学完后，你将能够：

1. 区分 Python 语言、Python 实现、解释器可执行文件、虚拟环境和编辑器；
2. 在 Windows、macOS 或 Linux 上选择并确认一个受支持的 Python 版本；
3. 分清 REPL、脚本运行和 `-m` 模块运行；
4. 用 `PATH`、`sys.executable` 和版本信息判断“现在究竟运行了哪个 Python”；
5. 处理命令找不到、版本不一致、导入失败和乱码等常见问题；
6. 知道哪些环境可以删除重建，哪些系统 Python 不应改动。

> [!info] 版本快照
> 截至 2026-09-01，Python 3.14 是最新稳定功能版本系列，最新维护版本为 3.14.7；3.15 仍是预发布系列。初学者没有项目约束时，选择 python.org 标示的最新稳定版即可；已有项目时，以项目声明、依赖和部署环境支持的版本为准，不要为了“数字最大”擅自升级。

## 心智模型：先找解释器，再运行代码

“运行 Python”不是编辑器把文字直接变成结果，而是一条可以逐层检查的链：

```text
你输入 python / python3 / py
        ↓
终端按 PATH、别名或启动器规则找到一个可执行文件
        ↓
某个 Python 实现启动（本课默认 CPython）
        ↓
它建立运行环境：版本、标准库、sys.path、当前目录、环境变量
        ↓
它读取 REPL 输入、脚本文件，或按 -m 查找模块
        ↓
代码被解析、编译为字节码并由该实现执行
```

这几层不是同一个东西：

| 层 | 是什么 | 常见误解 |
| --- | --- | --- |
| Python 语言 | 语法和语义规则 | “Python 就是某个 `python.exe`” |
| Python 实现 | 执行这门语言的软件 | 所有实现的性能和扩展兼容性都相同 |
| CPython | 用 C 编写、最普及且最主要维护的实现 | 名字里的 C 表示只能写 C 扩展 |
| 解释器可执行文件 | 一次实际启动的 `python`、`python3` 或 `python.exe` | 同名命令在所有终端都指向同一文件 |
| 虚拟环境 | 基于某个解释器创建的项目隔离环境 | 它会下载任意想要的 Python 大版本 |
| 编辑器 / IDE | 编辑、启动和调试代码的工具 | “运行”按钮一定使用当前终端里的 Python |

CPython 是本课程默认对象。Python 也有 PyPy、Jython、IronPython 等其他实现；它们可能有不同的运行时、即时编译能力或宿主平台集成。除非项目明确要求，入门阶段先用 CPython，可以减少第三方扩展、工具链和文档之间的差异。

## 从现有解释器到第一个脚本

如果终端已经有 Python，先用当前平台惯用命令确认版本：Windows 用 `python --version`，macOS / Linux 用 `python3 --version`。运行一个单文件程序不需要改系统 Python，也不必先创建虚拟环境。若命令不存在，或现有版本不符合课程/项目要求，再按下方对应操作系统的说明处理；不确定实际启动了谁时，继续用本页稍后的 `sys.executable` 检查。

接着回到 [[计算机知识/10-编程语言/01-Python/00-Python基础-MOC#零基础的第一个程序|Python 基础 MOC 的第一个程序]]：把其中代码保存为 `hello.py`，在文件所在目录用刚确认的同一命令运行，即 Windows 的 `python hello.py` 或 macOS / Linux 的 `python3 hello.py`。代码、创建的 `hello.txt` 和当前目录因此都有明确位置。

完成基础 01–05 后，[[计算机知识/10-编程语言/01-Python/10-系统课程/00-Python系统课程索引|Python 系统课程唯一索引]]会带你进入首个累计程序：在库根目录下的 `计算机知识/80-实践/01-Python/04-测量记录导入与分析/` 项目根运行 `python3 -B examples/first_record.py`（[[计算机知识/80-实践/01-Python/04-测量记录导入与分析/README#从一个有限程序开始|源码位置与结果说明]]）。它只用标准库；不需为这一步安装第三方包或先搭环境。等项目需要隔离依赖、创建可重建环境时，再回到本页 [[计算机知识/10-编程语言/01-Python/01-安装配置与运行模型#虚拟环境与编辑器：让项目选中同一个 Python|虚拟环境与编辑器]]，并按需读基础课 [[计算机知识/10-编程语言/01-Python/09-venv与虚拟环境原理|venv 主解释]]。

## 选择版本：稳定、兼容、可复现

按下面的优先级决定版本：

1. **已有项目**：先读项目的版本约束、持续集成配置和部署环境，不自行换大版本。
2. **课程或团队任务**：使用课程或团队指定的小版本系列，例如 `3.14`。
3. **全新个人练习**：选择最新稳定 CPython，不选 alpha、beta 或 release candidate。
4. **必须支持旧系统或旧依赖**：选择仍受 Python 官方支持、并且依赖明确兼容的版本。

补丁版本通常包含错误和安全修复。项目约束为 `3.14` 时，一般应使用可获得的最新 `3.14.x`，但升级后仍要运行项目测试。不要把“系统自带 Python”“最新 Python”和“项目需要的 Python”当成同一个选择。

## 按操作系统安装与确认

### Windows

Python 官方当前推荐使用 **Python Install Manager**，可从 python.org 下载或通过 Microsoft Store 安装。安装管理器与 Python 运行时是两层：管理器负责发现、安装和选择运行时，卸载管理器本身不会自动卸载已安装的运行时。

新开 PowerShell 或 Windows Terminal 后检查：

```powershell
python --version
py list
py -V:3.14 --version
```

- 日常启动默认解释器用 `python`；
- 管理或选择多个版本用 `py`，例如 `py -V:3.14`；
- Windows 也可能提供 `python3` 兼容命令，但官方不建议把它作为 Windows 的主要习惯；
- 如果 `python` 打开商店、命令不存在或与 `py` 结果不同，先检查“管理应用执行别名”、`py list` 和命令解析结果，不要反复安装多个发行版。

查看 PowerShell 实际能找到哪些命令：

```powershell
Get-Command python -All
Get-Command py -All
```

### macOS

从 python.org 获取的官方 `.pkg` 提供适用于受支持 Intel 与 Apple Silicon Mac 的 `universal2` 构建。安装后通常使用 `python3`，也可以用带版本号的命令明确选择版本。

```bash
python3 --version
python3.14 --version
command -v python3
type -a python3
```

macOS 可能在 `/usr/bin/python3` 提供由 Apple 管理、供开发工具使用的 Python。**不要修改或删除它。** python.org 安装的 CPython 可以与它并存；需要判断当前使用哪一个时，以 `command -v` 和稍后的 `sys.executable` 为准。

### Linux 与其他 Unix

许多 Linux 发行版已提供 `python3`，但版本、附加组件和生命周期由发行版决定。优先使用发行版的受支持安装方式；若项目需要不同版本，再选择隔离的版本管理方案、容器或按 Python 官方说明构建，不要覆盖 `/usr/bin/python3`。

```bash
python3 --version
command -v python3
type -a python3
```

Linux 发行版的软件包名不同，因此不要从别的发行版照抄一条安装命令。系统工具可能依赖发行版 Python；手动改系统符号链接，可能让包管理器或桌面工具停止工作。

## `PATH`、`python` 与 `python3`

`PATH` 是终端查找命令的一组目录，通常按从前到后的顺序匹配。它回答的是“输入这个命令名时先启动哪个文件”，不保证那就是编辑器、定时任务或另一个终端使用的解释器。

在 Linux 与其他 Unix Shell 中，`PATH` 如何由环境变量、Shell 启动文件和当前会话共同形成，可继续阅读 [[计算机知识/20-操作系统/01-Linux/07-环境变量Shell启动与PATH|环境变量、Shell 启动文件与 PATH]]。

常见约定是：

- Windows 的官方安装管理器以 `python` 为日常命令、`py` 为多版本入口；
- macOS 和 Linux 的系统级 Python 3 常以 `python3` 命名；
- 激活虚拟环境后，环境自己的 `python` 应排到 `PATH` 前面；
- 文档中的 `python` 常表示“你已选定的解释器”，不是要求所有系统都必须存在这个全局命令。

不要用一个全局别名粗暴地让 `python` 永久等于某个绝对路径。它可能掩盖虚拟环境或系统工具的选择逻辑。更可靠的做法是：安装时配置好入口，项目内使用虚拟环境，需要固定版本时使用明确的版本选择命令。

### 用 Python 自己确认身份

外部命令只能说明终端如何解析名称；下面的代码说明**已经启动的进程**是谁。磁盘上的解释器程序与每次启动后拥有地址空间、文件描述符、身份和环境的进程不是同一个概念；操作系统层的解释见 [[计算机知识/20-操作系统/01-Linux/01-计算机系统与Linux分层|Linux 的程序与进程模型]]。

```bash
python -c "import platform, sys; print(platform.python_implementation()); print(sys.version); print(sys.executable); print(sys.prefix); print(sys.base_prefix)"
```

在 macOS / Linux 全局环境中，如果入口叫 `python3`，把开头替换为 `python3`。重点看：

- `platform.python_implementation()`：通常应为 `CPython`；
- `sys.version`：实际版本和构建信息；
- `sys.executable`：当前解释器可执行文件的路径；
- `sys.prefix != sys.base_prefix`：通常表示当前解释器处于虚拟环境中。

以后遇到“终端能运行，IDE 不能”或“安装了库却导入失败”，先保存这组输出作为证据。

## 四种常见运行入口

### 1. REPL：快速观察

终端只输入解释器命令，会进入交互模式：

```text
$ python
Python 3.14.x ...
>>> 2 + 3
5
>>> name = "Python"
>>> print(name.lower())
python
>>> exit()
```

REPL 适合验证一个表达式、查看对象和做短实验。它不适合保存可重复程序；多行缩进出错时，退出后写成脚本通常更清楚。Unix/macOS 也可按 `Ctrl-D` 发送文件结束，Windows 通常是 `Ctrl-Z` 后按 Enter。

### 2. 脚本：按文件路径运行

把下面的运行探针源码保存到当前工作目录，文件名为 `hello_runtime.py`：

```python
from pathlib import Path
import platform
import sys

print("implementation:", platform.python_implementation())
print("version:", platform.python_version())
print("executable:", sys.executable)
print("working directory:", Path.cwd())
print("module name:", __name__)
```

运行：

```bash
python hello_runtime.py
```

解释器按给出的文件路径读取脚本，顶层模块名是 `__main__`。脚本所在目录和终端当前目录是两个概念：前者参与初始模块搜索，后者影响许多相对文件路径。不要假定双击文件或 IDE 的“运行”按钮具有同一个当前目录。

### 3. 模块：按导入名称运行

```bash
python -m module_name
python -m package.module_name
```

`-m` 使用 Python 的导入机制查找模块，再把它作为顶层程序执行。这里写的是模块名，不写 `.py`。当代码属于包、使用相对导入，或工具需要确保绑定到当前解释器时，`-m` 通常比直接执行包内文件更可靠。

例如，这会显示当前解释器的模块搜索路径和用户目录信息：

```bash
python -m site
```

包要支持 `python -m package_name`，通常需要提供 `package_name/__main__.py`。

### 4. `-c`：一次性短命令

```bash
python -c "print(6 * 7)"
```

它适合诊断和自动化中的短检查。超过一两行时应写脚本并纳入版本控制，否则引号、缩进和不同 Shell 的转义会迅速变得难以维护。

## shebang：Unix 上的启动提示

希望脚本在 Unix 类系统上直接执行时，可以把下面一行放在文件第一行：

```python
#!/usr/bin/env python3
```

然后赋予执行权限：

```bash
chmod +x hello_runtime.py
./hello_runtime.py
```

`/usr/bin/env` 会按当前 `PATH` 寻找 `python3`，因此激活虚拟环境后通常能选中环境内解释器。它带来的是便利，不是版本锁定：若程序必须使用精确版本，应由项目环境、启动脚本或部署配置保证。某些 Unix 没有 `env`，这时需按目标系统选择明确路径。

shebang 不代替 Windows 的命令解析，也不会在你显式运行 `python file.py` 时决定解释器——此时决定权在前面的 `python` 命令。

## 编码：把三件事分开

1. **源码编码**：Python 3 默认把源文件当作 UTF-8。编辑器也应保存为 UTF-8；通常不需要写编码声明。
2. **外部文件编码**：读写文本文件时应按数据格式明确指定，例如 `encoding="utf-8"`。
3. **终端输入输出编码**：由操作系统、终端、管道和 Python 配置共同决定，可能与源码编码不同。

可复制例子：

```python
from pathlib import Path

path = Path("hello.txt")
path.write_text("你好，Python！\n", encoding="utf-8")
message = path.read_text(encoding="utf-8")
print(message, end="")
```

非 UTF-8 源码可以在第一行声明编码；如果第一行是 shebang，编码声明放第二行。但新项目优先统一使用 UTF-8，不要把“加一行编码声明”当作所有乱码的修复。出现乱码时，先判断问题发生在源码、文件解码还是终端显示哪一层。

## 虚拟环境与编辑器：让项目选中同一个 Python

虚拟环境把项目使用的解释器入口和第三方包与其他项目隔离。它基于**创建它的那个 Python**，不会把 Python 3.12 自动变成 3.14。

在项目根目录创建：

```bash
python -m venv .venv
```

激活方式：

```bash
# macOS / Linux，bash 或 zsh
source .venv/bin/activate
```

```powershell
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

激活只是把虚拟环境的可执行目录放到当前 Shell 的 `PATH` 前面；并非使用虚拟环境的必要条件。也可以直接运行 `.venv/bin/python` 或 `.venv\Scripts\python.exe`。退出激活状态使用：

```text
deactivate
```

编辑器或 IDE 的选择原则：

- 明确把“项目解释器”设为该项目的 `.venv`；
- 在 IDE 终端和“运行”按钮中分别打印 `sys.executable`，确认结果一致；
- 确认运行配置的当前目录、环境变量和参数，不把编辑器界面当作隐藏魔法；
- 启用 Python 语法、四空格缩进和 UTF-8；不要混用 Tab 与空格；
- 初学阶段优先选择能清楚显示实际命令、输出和错误的工具，功能多少不是首要指标。

安装第三方包时使用：

```bash
python -m pip --version
python -m pip install package_name
```

`python -m pip` 把 pip 明确绑定到已经选中的解释器，比单独输入 `pip` 更容易避免“安装到了另一个 Python”。真实项目还应记录依赖并允许重建环境。

## 排错：按证据逐层缩小范围

### 命令不存在，或 Windows 打开了商店

1. 确认 Python 或 Python Install Manager 确实已安装；
2. 关闭并新开终端，让新的 `PATH` 或应用执行别名生效；
3. Windows 检查 `Get-Command python -All`、`py list` 和应用执行别名；
4. macOS / Linux 检查 `command -v` 与 `type -a`；
5. 不要靠复制可执行文件或覆盖系统链接“修好”命令。

### 版本不是预期版本

同时记录：

```text
python --version
命令解析结果（Get-Command / type -a）
sys.executable
sys.version
```

若终端和 IDE 的 `sys.executable` 不同，修正 IDE 的项目解释器；若激活虚拟环境后仍指向全局解释器，检查激活命令是否适合当前 Shell，并新开终端重试。

### `pip` 安装成功，但 `import` 失败

比较下面两条命令显示的解释器与安装位置：

```bash
python -m pip --version
python -c "import sys; print(sys.executable)"
```

然后确认包名与导入名是否相同、IDE 是否使用同一解释器。不要用管理员权限全局重装作为第一反应。

### 直接运行包内文件时相对导入失败

回到包的上级目录，改用模块入口：

```bash
python -m package.module
```

如果仍失败，再检查包结构、模块名和当前目录。不要在脚本里临时追加一串机器专属的绝对 `sys.path` 来掩盖结构问题。

### 中文乱码或 `UnicodeDecodeError`

依次确认：

1. 源文件是否真的是 UTF-8；
2. 读取外部文件时是否使用了正确的 `encoding=`；
3. 终端直接显示是否正常，还是只在重定向、日志或管道后出错；
4. 错误信息指出的是编码失败、解码失败，还是字体缺字。

### 新语法报 `SyntaxError`

先查 `sys.version` 和 `sys.executable`。很多“语法突然失效”其实是运行按钮选中了旧解释器，而不是代码文件损坏。

## 恢复与卸载边界

从最小、可恢复的动作开始：

- **退出虚拟环境**：运行 `deactivate`，只影响当前 Shell 会话；
- **重建虚拟环境**：确认项目代码和依赖清单不在 `.venv` 后，可删除 `.venv` 并用目标解释器重新创建；虚拟环境本来就应是可丢弃、可重建的；
- **撤销 PATH 修改**：只移除自己新增且已确认无用的条目，先记录原值，并新开终端验证；
- **Windows**：用 `py list` 确认运行时标签，再用 `py uninstall <TAG>` 移除由安装管理器管理的指定运行时。卸载管理器不会自动移除运行时；不要未经盘点使用清除全部运行时的选项；
- **macOS**：只移除自己通过 python.org 或其他明确渠道安装的那一套；不要触碰 Apple 管理的 `/usr/bin/python3`；
- **Linux**：不要手动删除 `/usr/bin/python3`、标准库目录或系统符号链接。是否能卸载某个包，应由发行版包管理器和依赖关系决定；
- **编辑器**：删除或重设“项目解释器”配置不会卸载 Python。先确认只是修正选择，还是确实要移除运行时。

> [!danger] 不要把“只留一个 Python”当作清理目标
> 多个解释器可以安全共存。真正需要控制的是：项目使用哪个解释器、依赖装在哪里、命令如何解析，以及环境能否重建。盲删系统 Python 或批量清理所有版本，可能破坏系统工具和其他项目。

## 练习：证明你运行的是谁

1. 在终端运行命令解析检查：Windows 使用 `Get-Command python -All`；macOS / Linux 使用 `type -a python3`。
2. 选择实际可用的解释器，运行本课“用 Python 自己确认身份”的单行命令。
3. 新建一个无个人数据的练习目录，在其中创建 `.venv` 并激活。
4. 再次记录 `sys.executable`、`sys.version`、`sys.prefix` 和 `sys.base_prefix`。
5. 把 `hello_runtime.py` 复制到练习目录，分别用脚本方式运行，并用 `python -m site` 观察模块运行。
6. 退出虚拟环境，确认 `sys.executable` 回到全局解释器。
7. 删除练习产生的 `hello.txt`；若不再需要该练习环境，确认没有项目代码后再删除 `.venv`。

## 常见坑速查

| 现象 | 更可能的原因 | 第一条检查 |
| --- | --- | --- |
| 终端与 IDE 版本不同 | 选择了不同解释器 | 两边打印 `sys.executable` |
| `python` 与 `python3` 结果不同 | `PATH` 中存在多个入口 | `Get-Command` 或 `type -a` |
| `pip` 安装后仍无法导入 | pip 和运行代码不属于同一解释器 | `python -m pip --version` |
| 包内相对导入失败 | 把包内文件当普通脚本执行 | 从包上级目录用 `python -m` |
| shebang 没按预期选版本 | 它跟随当前 `PATH` | 运行前检查命令解析和环境 |
| 读取中文文件报错 | 文件编码与解码参数不一致 | 明确 `encoding=` |
| 激活后仍是全局 Python | 激活脚本或 Shell 不匹配 | 比较 `sys.prefix` 与 `sys.base_prefix` |
| 删除环境后命令失效 | 编辑器仍指向旧 `.venv` | 重新选择项目解释器并重建环境 |
