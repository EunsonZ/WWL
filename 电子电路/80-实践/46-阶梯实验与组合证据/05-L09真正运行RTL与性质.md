# L09：预期、正常运行与故障运行要怎样对齐

问题是：一张A1/B2波形能否证明源码运行过、故障确实被检出？基础入口先用纸上队列做下面六拍，再逐步执行命令；快进入口直接核WIDTH、宏、沿前交易和沿后观察。两者使用同一单槽RTL，目的不是换一份模型来“通过”。

## 原源码、假设与采样责任

正式原真源为 [[电子电路/80-实践/26-HDL缓冲器与性质/README#真源和观测合同]] 中 elastic_slot.sv、tb_slot.sv、slot_properties.sv 和 slot.sby；本卡没有复制或修改它们。RTL WIDTH1…8，异步低有效复位、单时钟，无直通。组合ready=rst_n∧(¬full∨m_ready)，valid=rst_n∧full；输入事务push=s_valid∧ready、输出事务pop=valid∧m_ready均取**沿前端口**。沿后full'=s_valid若ready否则full；data只在push改写。满格同沿pop/push合法：交旧字，存新字。

TB以accepted历史和delivered游标作为参考，不用复制full下一态；独立约束accepted=delivered前缀+未交付队列。合法上游受阻时保持pending，复位取消pending与未交付字，新的epoch不能交旧字。实际跨域复位同步释放、setup/hold、亚稳态不由此零延迟仿真检验。

## 六拍是可核预期，不是VCD

时钟周期10ns；20/30/40/50/60/70ns下降沿驱动，21/31…ns检查沿前，25/35…ns上升沿，26/36…ns观察NBA之后。第一拍A1、sv1、mr1：空格不直通，沿前pop0/push1，26ns持A1。第二与第三拍B2、mr0：push0/pop0，36/46ns仍A1。第四拍55ns交A1接B2，56ns数据是B2；第五65ns交B2，66ns空；第六75ns空。不能把56ns的B2解读成55ns已交付B2。

![[电子电路/80-实践/26-HDL缓冲器与性质/assets/expected-cycles.svg]]

这是原生成器的手绘/CPU预期，来源身份在图与数据明确；本组不将CSV改名为VCD。`pipeline_lab.py` 的 L09 调用原CPU directed与有限W2图，正常六拍、突变第二拍36ns head不等A1，是**CPU预测**。

## 真正工具输入与输出

从WWL库根，换成两个不同的全新库外绝对目录：

```bash
.venv/bin/python -B '电子电路/80-实践/26-HDL缓冲器与性质/run_hdl.py' --output /private/tmp/L09-normal-new
.venv/bin/python -B '电子电路/80-实践/26-HDL缓冲器与性质/run_hdl.py' --output /private/tmp/L09-mutant-new --fault
```

runner真正用iverilog -g2012 -Wall -s tb_slot 编译，再vvp +VCD=/绝对目录/slot.vcd；每步45s预算。宏 U26_FAULT_OVERWRITE 把写条件push改sv，受阻B2覆盖未交A1。**正常应exit0；突变应编译成功、执行逻辑head mismatch、exit1**。仅编译错误或缺+VCD的fatal都不是这个逻辑反例。缺工具时exit2，仅execution-status.json=not_run；本机实际工具缺失，未产生编译stdout或VCD。

运行后核源码/宏SHA、工具版本、精确argv/returncode、normal PASS摘要、实际非空VCD；mutant应观察36ns错误和期望/实得字。只看退出码不足以辨别语法、超时和逻辑反例。预期图不能取代这份运行身份。

形式命令在原源码目录执行，目录参数仍在库外：

```bash
cd '电子电路/80-实践/26-HDL缓冲器与性质'
sby -d /private/tmp/L09-bmc-new slot.sby bmc
sby -d /private/tmp/L09-prove-new slot.sby prove
sby -d /private/tmp/L09-cover-new slot.sby cover
sby -d /private/tmp/L09-formal-mutant-new slot.sby mutant
```

BMC深度12只核有限展开；prove需要基例和归纳闭合；cover需要替换/阻塞/非空复位见证；mutant需FAIL及逻辑反例，ERROR另判前端或solver。harness首拍假设复位，连续非复位时assume受阻源保持；rst任意并取消旧epoch，past_valid防无过去值。没有“下游最终ready”的公平假设，就不能从这些安全断言得每字最终交付。async2sync抽象不能证明亚周期复位脉冲或恢复移除。工具配置使用boolector，当前SBY/Yosys/solver未运行，且没有安装。

## 陌生条件与三题

1. 将mr永远置0，正常RTL不丢A1，但“最终交付”断言能证明吗？**不能。** 安全成立，活性需要环境公平或有界响应假设；加assume必须说明外设如何兑现。
2. WIDTH4仍用A1/B2刺激，能原样比较8bit期望吗？**不能。** 接口截成1/2，需同宽参考与期望，不能把截断当任意溢出bug；原runner定向为WIDTH8。
3. 在上升沿同一active区驱动再立即观察，为何容易误判？**采样/提交责任混杂。** DUT与TB执行顺序可竞争，且NBA尚未提交；下降沿驱动、沿前交易、沿后1ns观察是一份明确有限测试合同。

这张卡交付完整源码入口、命令/时间/性质/故障合同。CPU实际有限运行不等于真实HDL或无界证明；真实编译日志、VCD与证明日志仍not_run。组合执行方法见 [[电子电路/80-实践/46-阶梯实验与组合证据/README-B#固定连接器与复现]]。
