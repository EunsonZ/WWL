# 数据库：从业务不变量到关系模型

> 阅读定位：关系理论通用；实现示例区分 SQLite 与 PostgreSQL 17。返回 [[计算机知识/00-开始/课程地图/10-数据库-课程地图|数据库 · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## 表格不是关系模型的全部

关系由属性和元组组成，属性有取值域；纯关系理论通常按集合思考，SQL 实际常有重复行、NULL 和无保证顺序。没有 ORDER BY 就不应依赖某次输出顺序。数据库的价值不仅是保存数据，还在于维护并发情况下的约束和可恢复状态。

以课程选课为例：Student(student_id,name)、Course(course_id,title)、Enrollment(student_id,course_id,grade)。学生可选多门课，课程可有多名学生，中间关系表达多对多。把课程列表塞进学生表的一列，会使逐项约束与查询变得困难。

## 键与约束共同表达允许的世界

候选键是能唯一标识元组的最小属性集合，主键是在候选键中选择的一个，外键表达引用关系。唯一性、非空、检查约束与外键各有角色；“应用层已经检查过”不能代替数据库约束，因为并发请求可能同时通过检查。

```sql
CREATE TABLE student (
  student_id INTEGER PRIMARY KEY,
  name TEXT NOT NULL
);
CREATE TABLE enrollment (
  student_id INTEGER NOT NULL,
  course_id INTEGER NOT NULL,
  grade INTEGER CHECK (grade BETWEEN 0 AND 100),
  PRIMARY KEY (student_id, course_id),
  FOREIGN KEY (student_id) REFERENCES student(student_id)
);
```

这是教学片段，完整模型还需 course 表与相应外键。grade 允许 NULL 表示未出成绩，因为 CHECK 在 SQL 的三值逻辑下不能简单替代 NOT NULL。SQLite 的外键执行需要按连接配置核对，类型与主键细节也不能无条件照搬 PostgreSQL。

## 事务中的一致性由你定义

“库存不可为负”“同一用户对同一课程最多一条记录”是业务不变量。ACID 中的一致性不意味着数据库自动知道所有业务规则；你需要把能表达的部分放进约束，其余通过正确事务与并发协议保持。

使用自然键还是代理键，要同时考虑业务稳定性、外部可见性、索引宽度和关联成本。新增代理主键不意味着原有业务唯一性可以删除。时间记录应区分瞬间、当地日期和持续时间，金额应使用明确精度和舍入规则。

## 练习

建模订单、订单明细、商品和支付，指出哪些一对多，哪些状态互斥，哪些字段允许缺失。构造两个并发请求同时创建重复记录的时间线，说明为什么唯一约束比“先 SELECT 再 INSERT”更可靠。接着进入 SQL 和事务课程。
