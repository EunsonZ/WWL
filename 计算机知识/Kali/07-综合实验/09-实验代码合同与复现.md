## 输入域与失败政策

`can_read` 将身份视为调用方已确认的输入，**不是认证实现**；未知用户、未知对象及不合类型均拒绝。`query_names` 使用临时SQLite，安全分支绑定参数，不安全分支只演示反例；非法调用和SQL错误抛 `LabInputError`，不返回伪空结果。

`summarize_logs` 要求每行JSON对象、整数100..599状态、非空time/actor/path文本；空输入返回零，空行或坏记录立即报带行号的错误。time字段只是保留文本，**未进行完整ISO日期验证、时区换算或可信来源认证**。大小与资源防护也只是小型教学输入边界，不声称是处理恶意超大文件的生产解析器。

生成器拒绝已存在的目的目录和检查时发现的符号链接路径；固定内部相对文件名不接收外部归档路径。仍不构成敌对多用户目录的竞态安全沙盒，必须在你控制的本地新目录中运行。失败后的部分输出不能当作完成，需要保留失败说明并选新目录重试。

## 重建夹具而不覆盖旧证据

```bash
cd "$HOME/kali-lab/code"
python3 generate_fixtures.py "$HOME/kali-lab/fixtures-regenerated"
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_offline_lab.py
```

再次运行到相同目的目录应失败，这是正常保护，不是需要“修复”的功能。比较新旧 expected.json 和各文件SHA-256；生成器使用固定时间戳与确定字节序，所以相同代码版本应重现相同夹具内容。生成时间与数据中的合成时间不是同一字段。

## 已验证与尚未验证

首次 v1 构建执行了标准库测试，并在构建容器用系统C编译器编译 `hello.c`，测试无参数、一个参数和过多参数三种行为。该次数量、输出和环境见 [[计算机知识/Kali/90-来源与维护/03-验收与构建记录|v1 历史验收记录]]。源码语法检查和C编译成功不代表Kali工具、YARA编译器、GDB交互或Obsidian界面已运行。

PCAP测试独立检查包头/校验和/序号，但仅覆盖本生成器输出格式，不是泛化到所有PCAP/PCAPNG的验证器。单元测试不证明所有潜在输入正确；接口、夹具和说明任何一项变化，都要更新必要测试并复核相邻章节。

## v2 新增真源与独立验证

[[计算机知识/Kali/07-综合实验/代码/reasoning_lab.py|reasoning_lab.py]] 负责四个实验共享的纯函数模型；[[计算机知识/Kali/07-综合实验/代码/test_reasoning_lab.py|test_reasoning_lab.py]] 负责正常、拒绝、歧义和边界；[[计算机知识/Kali/07-综合实验/代码/generate_reasoning_fixtures.py|generate_reasoning_fixtures.py]] 生成独立的 `reasoning-v2.0` 夹具，不调用被测授权策略计算预期；[[计算机知识/Kali/07-综合实验/代码/length_record.c|length_record.c]] 是有界标准输入解析器；[[计算机知识/Kali/07-综合实验/代码/verify_c_examples.py|verify_c_examples.py]] 仅在显式执行时调用已经安装的编译器，构建并运行两个自有 C 示例。

生成 v2 夹具时，目的父目录必须存在、目的目录必须不存在，不接受检查时发现的符号链接路径；仍不声称抵抗敌对目录中的并发路径替换。输出中途失败留下的目录不是成功结果，需保留说明并选择新目录重试。

```bash
cd "$HOME/kali-lab/code"
PYTHONDONTWRITEBYTECODE=1 python3 generate_reasoning_fixtures.py \
  "$HOME/kali-lab/fixtures-v2-regenerated"
# 下面是显式编译与执行自有 C 的步骤；未安装编译器时停止，不自动安装。
PYTHONDONTWRITEBYTECODE=1 python3 verify_c_examples.py --compiler cc \
  --sanitizer none --report "$HOME/kali-lab/output/c-normal.json"
```

C 报告文件也必须为新文件。需要检查器插桩时，用本机支持的编译器显式选择 `--sanitizer undefined` 或 `--sanitizer address-undefined`，不同配置分别写新报告，不覆盖旧记录。驱动器编译限时、每次输入执行限时，完整目标只限这两个已审阅源文件；不是任意源码执行沙盒，也不会启动 AFL++。

Python v2 时间模型比原 `summarize_logs` 更严格：原函数保留 time 文本的合同没有被悄悄改写。扫描解析器支持的是有限 XML 子集，不实现 Nmap 完整 DTD、服务分类或 NSE结果。v2 授权模型不验证身份令牌、不修改状态、不实现事务。逐项限制在函数文档和对应实验中声明；不能因一套模型通过就给未实现功能打勾。

最新运行记录见 [[计算机知识/Kali/90-来源与维护/05-v3深度审阅与变更记录|v3 深度审阅与变更记录]]；原 [[计算机知识/Kali/90-来源与维护/03-验收与构建记录|首次构建记录]] 保留为历史证据。
