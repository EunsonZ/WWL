# C：指针、数组和字符串为什么总在边界处出错

> 阅读定位：C17 核心；扩展和标准版本差异单独注明。返回 [[计算机知识/00-开始/课程地图/01-C语言-课程地图|C语言 · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## 指针保存地址，不保存对象所有权和完整边界

设 `int a[3] = {10,20,30}`。`a` 在多数表达式中转换成指向首元素的指针，`a+1` 跨过一个 `int`，不是一个字节。`a[1]` 等价于 `*(a+1)`。但数组本身并不等于指针：对数组做 `sizeof a` 得到整个数组的字节数，对指针做 `sizeof p` 得到指针对象大小；作为函数形参写 `int a[]` 会被调整为指针形参，长度不会神奇地跟着传过去。

因此接口通常需要“地址 + 元素个数”，例如 `int sum(const int *a, size_t n)`。约定必须说明：`n>0` 时 `a` 指向至少 n 个有效元素；`n==0` 时是否允许空指针；结果是否可能溢出。`const` 只约束通过该访问路径修改，不是所有权证明或线程同步。

## 逐步跟踪一个越界

对 3 元素数组，`a+3` 可以作为尾后指针构造和比较，不能解引用。`a+4` 已超出允许的数组指针运算范围。`for (size_t i=0; i<=3; ++i)` 的前三次访问看似正常，第四次越界；越界没有发生崩溃也不代表程序正确。对象相邻布局或优化改变后，错误可能才暴露。

二维数组 `int a[2][3]` 的元素是 3 个整数组成的数组，衰变后类型为“指向 3 元素数组的指针”，不是 `int**`。前者描述连续矩形布局，后者描述指针表，不能仅通过强制转换互换。

## 字符串是带约定的字节数组

`char text[] = "hi"` 有 3 字节，最后是 `\0`；`strlen(text)` 为 2，`sizeof text` 为 3。`char *p = "hi"` 指向字符串字面量，不能通过 `p` 修改其内容；需要修改应使用数组或拥有的动态缓冲区。

`strlen` 要一直找终止符，不适合直接扫描长度未知的网络输入。二进制数据可以含零字节，应传显式长度。字符串长度、UTF-8 字节数、Unicode 码点数、用户看到的字形数不是同一个指标。把中文按字节截断可能切开编码序列。

`memcpy` 要求源目标不重叠；可能重叠时使用 `memmove`。`strncpy` 不保证所有情况下都补终止符，也不是通用安全替代品。更好的策略是先确定容量、长度上限和失败协议，再选择复制函数。

## 生命周期比地址数值重要

返回局部变量地址会让调用者拿到生命期已结束对象的指针。`free(p)` 后把 `p=NULL` 只能清空这个变量，其他别名仍会悬空。扩容一旦搬迁存储，旧的元素指针、尾指针和切片都可能失效。调试时应画“谁拥有，谁借用，何时失效”，不能只画地址箭头。

## 练习与答案线索

实现一个带边界的字节查找接口，返回“是否找到 + 下标”，输入允许零长度。对空输入、首元素、末元素、不存在、包含零字节分别测试。思考为何返回一个指向输入的指针要求调用者维持输入生命期，而返回下标只保留位置关系，仍需确认它对应的数组没有改变。
