# 生命周期不是倒计时：约束、方差与高阶借用

> **学习位置**：[[计算机知识/00-开始/课程地图/03-Rust-课程地图|Rust课程地图]] · **适用边界**：Rust 2021 edition 兼容示例；2024 edition 差异另行标识。

## 标注描述关系，不制造更长的生命

```rust
fn choose<'a>(left: &'a str, right: &'a str, use_left: bool) -> &'a str {
    if use_left { left } else { right }
}
```

返回借用必须能在两个输入共同满足的范围内使用，因为函数可能返回任一输入。`'a` 不是要求两个原对象真的在同一时刻销毁，也不是让局部对象延寿。调用者可以用原本活得更久的引用，以较短的有效使用范围参与调用。

生命周期省略只是常见关系的简写。一个输入引用返回一个引用时，编译器常能采用明确规则推断；有多个输入时，通常需要说明返回值与谁关联。方法中 `&self` 也有相应省略规则，但业务关系与语法默认不一致时，应显式设计接口。

## 结构体中的引用把外部寿命带进类型

```rust
struct Token<'src> {
    text: &'src str,
    offset: usize,
}
```

token 借用源文本，源文本必须覆盖 token 的使用期。优点是避免为每个 token 分配字符串；代价是 token 不能自由脱离源文本存活。需要长期保存时，可改用拥有字符串、共享拥有源缓冲区加范围，或受控 arena。

不要把含引用的结构体总是改成 `'static`。`T: 'static` 大致要求 T 不携带不满足该约束的短期借用，并不表示某个 T 值永不销毁。一个拥有数据的 `String` 可以满足 `'static` 类型约束，但它仍会在正常作用域结束时释放。

## 方差从“能否安全替换”理解

若一个较长有效期的共享引用能在需要较短有效期引用的地方使用，这是生命周期协变的直觉。只读观察不允许把短期值塞回原来长期保存的位置，因此这种缩短通常安全。

可变引用对其所指类型的方差更严格。想象允许把“保存长期引用的可变槽位”当成“保存短期引用的可变槽位”，调用者就能写入即将失效的引用，破坏原槽位对长期有效的承诺。**能读取和能写入共同存在时，替换关系不能只按读取方向推导。**

正式讨论还要区分 `&mut` 对自身借用生命周期与对被引用类型 T 的方差，不能简单说“所有 mutable 都在所有参数上不变”。`UnsafeCell`、函数输入输出、`PhantomData` 等会影响具体方差与自动 trait 行为；安全抽象应按参考文档逐参数分析。

## 高阶生命周期约束 HRTB

某些回调必须对任意一次临时借用都能工作，而不是只接受某一个预先固定生命周期。例如 `for<'a> Fn(&'a str) -> usize` 表达回调可接受任意合法借用期的字符串。它与“函数外先选定一个 `'a`”的量词位置不同。

这像数学中的“对每个输入都成立”，不是“存在一个方便的输入”。HRTB 常出现在借用回调、迭代器适配和框架接口中。读不懂时先把量词写成自然语言，再看哪个对象负责提供借用。

## 自引用结构为何难以直接构造

结构体若同时拥有 `String` 并保存指向其缓冲区的引用，必须分别分析“指针指向哪里”和“什么操作会使它失效”。移动 `String` 的指针、长度与容量等拥有性元数据，并不因这一动作本身搬迁堆缓冲区；因此不能笼统说移动结构体必然使指向 String 堆内容的指针失效。指向结构体内联字段的指针则不同，整个结构体搬迁会改变字段位置。扩容、替换、释放，以及不满足借用合同的修改都需要另行审查，见 [String 的表示与容量契约](https://doc.rust-lang.org/std/string/struct.String.html#representation)。普通结构体生命周期参数仍不自动表达“这个引用永远指向我自己的那个字段”。

更简单的设计是保存偏移范围而不是内部指针，使用时再从拥有缓冲区切片。必须依赖稳定地址时才研究 pinning、arena 或经过审计的自引用抽象；`Pin` 也不是替你检查所有内部引用有效性的魔法。

## 练习：设计零复制解析结果

需要把一份文本解析成多个字段。短期处理可以返回借用源文本的字段切片；跨线程长期缓存可以保存 `Arc<str>` 和各字段的字节区间。每次取字段仍需保证区间合法且处于 UTF-8 边界。

答案的重点是：前一种把生命周期约束暴露给调用者，后一种把生命期管理放进拥有性共享对象，但增加引用计数及间接定位成本。设计不是“尽量多写生命周期”，而是选择最容易表达并验证的资源关系。
