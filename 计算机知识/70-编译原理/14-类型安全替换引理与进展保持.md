# 类型安全：为什么替换之后仍能继续运行？

类型检查给出一个静态判断，求值会删除函数、复制实参、选择分支。要证明二者配合，需要展示每种语法与求值规则怎样衔接。[[计算机知识/70-编译原理/06-类型系统约束求解泛型与语义检查|类型约束与检查]] 负责类型系统和统一算法；[[计算机知识/70-编译原理/10-系统课程/11-类型统一泛化与值限制|泛化和值限制]] 负责 HM 与可变引用。本课使用上一课的**注解 Bool STLC 核心、闭项、左到右弱 CBV**，不含 let 多态、引用、子类型或 fix，先证明其进展与保持。

## 1. 全部类型规则与环境约定

Γ 是从有限个变量名到类型 T 的映射，`Γ,x:S` 是把 x 更新为 S，内层绑定可遮蔽外层。`Γ⊢e:T` 是一个可由规则构造的判断，不是运行结果。∅ 是空环境。

$$
\frac{\Gamma(x)=T}{\Gamma\vdash x:T}\quad
\frac{}{\Gamma\vdash true:Bool}\quad
\frac{}{\Gamma\vdash false:Bool}
$$

$$
\frac{\Gamma,x:S\vdash b:T}{\Gamma\vdash\lambda x:S.b:S\to T}
\qquad
\frac{\Gamma\vdash f:S\to T\quad\Gamma\vdash a:S}{\Gamma\vdash f\ a:T}
$$

$$
\frac{\Gamma\vdash c:Bool\quad\Gamma\vdash a:T\quad\Gamma\vdash b:T}
{\Gamma\vdash if\ c\ then\ a\ else\ b:T}.
$$

类型环境的条目不是运行时整数存储。对于确定的注解项，检查器按结构递归；没有约束变量或泛化。由规则归纳可得自由变量引理：若 Γ⊢e:T，则 FV(e)⊆dom(Γ)。变量情况靠查表；λ 删除被绑定的 x；应用与条件取并集。因此 ∅ 下可类型化的项确实闭合。

跟算 `not=λx:Bool.if x then false else true`：环境 x:Bool 下，x 的类型为 Bool，两个分支都 Bool，故条件式 Bool；抽象规则得到 not:Bool→Bool；false:Bool，由应用规则得 `not false:Bool`。运行后条件式与 true 也都具有 Bool 类型。

## 2. 两个辅助事实让替换引理没有跳步

**环境不变性**：若 Γ、Δ 对 FV(e) 中每个变量给同一类型，Γ⊢e:T 推出 Δ⊢e:T。按 e 的类型推导归纳：变量正是查表相同；常量无前提；应用和条件对子项使用归纳假设；λ 的体环境分别扩展相同 x:S，体中自由于 λ 的变量仍同型，x 的新绑定也相同，然后重建抽象规则。

由此得弱化：若 Γ⊢e:T，给 Γ 添加不遮蔽其所需自由名字的新绑定，仍有类型 T。特别地，闭项能从空环境弱化到任何 Γ。另一辅助事实是 α 改名保持类型：给 λ 的绑定选全新 z，把它在体中绑定的出现改为 z 后，类型推导中原来查该绑定的叶子改查 z:S；内层遮蔽另有绑定叶子不改，其余规则不变。故新抽象同型。这是对绑定位置的重标记，而非把所有同名字符串替换。

## 3. 替换引理：把一个类型假设换成真正的项

采用可用于开项的版本：x∉dom(Γ)，若

$$\Gamma,x:S\vdash e:T,\qquad\Gamma\vdash s:S,$$

则避捕获替换满足 `Γ⊢e[x:=s]:T`。先对 e 中的绑定做 α 改名，使所有会干扰 x、Γ 或 FV(s) 的绑定名新鲜；辅助事实保证类型不变。随后按 e 的类型推导归纳，注意 Γ 要随归纳参数变化，不能只证明空环境的一个实例。

| 最后规则 | 替换后为什么仍有同一类型 |
| --- | --- |
| 变量 y=x | 原判断的类型必为 S；替换后正是 s，第二个前提给 Γ⊢s:S |
| 变量 y≠x | 查的是 Γ(y)，删除额外 x 不影响查表，项仍为 y |
| true / false | 无出现也无类型前提，原常量规则即可 |
| 应用 e₁e₂ | 分别对函数 S₁→T 和实参 S₁ 使用归纳假设，再用应用规则 |
| 条件式 | 条件仍 Bool、两个分支仍 T，重建条件规则 |
| λy:U.b，y≠x且新鲜 | 对 Γ,y:U 使用体的归纳假设；s 由弱化得此环境下 S，故体仍 T₁，再抽象得 U→T₁ |
| λx:U.b，未改名的遮蔽情况 | 替换停止；体的环境 `(Γ,x:S),x:U` 等于 Γ,x:U，直接重建抽象规则 |

最后一行说明遮蔽为什么不能漏；新鲜化路线可把它改为前一行。这里写开项版本，比 SF StlcProp 的“替换项在空环境类型化”版本更强，依赖完整避捕获替换。比如 Γ={y:Bool}、e=`λy:Bool.x`、s=y，得到 `λz:Bool.y:Bool→Bool`；错误的捕获结果虽偶然同型，却改变语义，所以类型检查通过不能独自发现所有替换错误。

### 同型反例与三种不同的保持承诺

带着上面的 Γ={y:Bool}、e=`λy:Bool.x`、s=y，进入[[计算机知识/70-编译原理/13-操作语义求值策略与程序等价#同一闭合上下文怎样区分捕获结果|同一外部 y=false 与实参 true 的观察]]：正确项 λz:Bool.y 与错误项 λy:Bool.y 都可检查为 Bool→Bool，闭合后的两个函数也都在空环境具有这个类型，但同一调用分别返回 false 与 true。返回本页只需指出三种承诺的前提和结论：

| 承诺 | 必须满足的条件 | 得到什么 |
| --- | --- | --- |
| 合法 α 改名保持意义 | 只重标一个绑定及它绑定的出现，新名不捕获自由引用，也不跨遮蔽 | 自由引用与绑定身份不变；本课纯语言在相同外部环境下的观察不变 |
| 本节替换引理保持类型 | 两个类型前提、x∉dom(Γ) 及避捕获替换 | Γ⊢e[x:=s]:T；不宣称任意改写与原项行为相同 |
| 某个程序改写保持行为 | 声明语言与观察，并证明对所需上下文观察相同 | 如第13课所定义的上下文等价；仅有同型判断不够 |

类型系统约束合法输入与求值规则的配合；本反例表明“错误捕获恰好也同型”不能由类型检查单独检出，不取消进展与保持定理。要定位是哪条引用变了，去[[计算机知识/70-编译原理/05-作用域名称解析与符号表#按 SymbolId 改名并检查捕获|声明与 use-def 的改名检查]]；再从那里返回第13课的同一捕获例。若需要公式的语义对照，回到[[哲学与文化/20-论证知识与规范/04-量词有效性与反模型#同一赋值下，把捕获的后果逐格算出来|同一关系与赋值的真值表]]，说明它检验真值而本例检验求值返回值。

## 4. 值的标准形态（canonical forms）

若 ∅⊢v:Bool 且 v 是值，则 v 只能 true 或 false；若 ∅⊢v:S→T 且 v 是值，则 v 只能 `λx:S.b` 且 x:S⊢b:T。证明不是猜测：按值语法只分三个构造；常量规则仅给 Bool，抽象规则仅给箭头；语法中的 Bool 与箭头构造不同，逐一排除，剩余推导的前提由规则反演读出。没有子类型、类型转换或“任意项任意型”的规则是这一步必要前提。

## 5. 进展：闭良类型项是值或能走一步

定理：∅⊢e:T，则 e 是值，或存在 e′ 使 e→e′。按类型推导归纳；仅在空环境的当前子项上应用此定理，不对 λ 体强求空环境。

变量分支不可能，空环境无条目；两个布尔常量和抽象都是值。应用 f a 的两个前提也在空环境：若 f 可走一步，应用函数位置规则；否则 f 是值。若 a 可走一步，应用实参位置规则；否则 a 也是值。由 f 的箭头类型与标准形态，f 必为 λ，故 β 规则可用。条件式先对 c 使用归纳假设：可步则走条件位置；是值则按 Bool 标准形态为 true/false，选择对应分支。所有最后规则已覆盖。

为何闭项必需？Γ={x:Bool} 下 x:Bool，但 x 不是值也无规则，进展失败。实验有这个反例。为何不能删除 β 规则？良类型 `(λx:Bool.x) false` 会变成卡住。进展是在类型与运行规则成对定义后成立。

## 6. 保持：一步不会改变类型

定理：若 ∅⊢e:T 且 e→e′，则 ∅⊢e′:T。按类型推导归纳，同时反演实际一步规则：

- 应用的函数位置步：原 f:S→T，归纳假设给 f′:S→T，原 a:S，用应用规则重建。
- 应用的实参位置步：原 a:S，归纳假设给 a′:S，原 f:S→T，重建。
- β 步：由应用与抽象反演得 x:S⊢b:T 和 ∅⊢v:S；替换引理取 Γ=∅，得 ∅⊢b[x:=v]:T。
- 条件的条件位置步：c:Bool，经归纳保持 Bool，两分支 T 不变，重建。
- 真假选择步：结果就是原已具有 T 的相应分支。
- 变量、常量、抽象没有一步规则，因此无其他分支。

箭头是证明所用前提，不是学习成果评分；替换支撑 β 保持，标准形态支撑应用与条件的进展。连续执行的安全推论：对有限步数归纳，用保持把每个可达项仍标为 T，再用进展排除可达非值卡住。无限执行并未被排除。

## 7. 反方向、递归和终止边界

保持不能反向使用。`(λx:Bool.true)(λy:Bool.y)→true` 是合法无类型运行步，结果 Bool，但原实参 Bool→Bool 与形参 Bool 冲突。还有条件式未选分支可以不合法；运行碰巧避开它，不会生成源项的类型证明。

若添加上一课的 fix，类型规则为 Γ⊢f:T→T 推出 Γ⊢fix f:T，运行对 λ 做递归替换。进展新增分支：先求 f，否则箭头标准形态使 fix 可展开；保持的展开分支用替换引理，因为递归项 fix f 本身为 T。于是安全仍可成立，δ=`fix (λz:Bool.z):Bool` 却无限执行。

无 fix 的纯 STLC 的终止需要独立归一化论证，常用逻辑关系：Bool 的可归约项要求良类型且终止；S→T 的可归约项还要求把任意可归约 S 实参代入后得到可归约 T 结果，再证明类型推导中的每个构造保持该性质。本课不以这段路线充当完整证明。SF [Norm，Logical Relations / The Fundamental Property](https://softwarefoundations.cis.upenn.edu/plf-current/Norm.html) 提供专章，其中另定义含 Bool、函数、条件与积类型的 STLC 变体，部分条件与积的论证留作练习；该章给出逻辑关系方法及强于“不会卡住”的性质；递归扩展不满足其基础前提。

## 8. 练习与解答

1. 在 β 保持中去掉替换项类型前提会怎样？解：令体 x:Bool，代入 `λy:Bool.y`，结果为函数，丢失 Bool；“名字替换”本身不保型。
2. 给 `if true then (λx:Bool.x) else false` 检查类型。解：条件 Bool，但分支 Bool→Bool 与 Bool 不同，拒绝。它能运行到函数值，说明运行完成不推出检查成功。
3. 把 Bool 标准形态错写为“任何值都能作条件”，哪里断了？解：`if (λx:Bool.x) then true else false` 运行无规则；若错误类型规则允许函数为 Bool，进展立刻失败。
4. 616个小项的枚举全通过是否完成一般证明？解：不；本实验只限节点≤5、两种参数注解且无 fix，一般规则证明量化任意有限项。本页逐分支证明承担一般性，枚举只检查实现与固定反例。
