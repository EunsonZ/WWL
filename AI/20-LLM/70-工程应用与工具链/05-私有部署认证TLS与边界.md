# 私有部署、认证、TLS 与边界

> 传输保护、身份认证与模型隐私不是同一性质。检索权限、工具授权和数据保留仍需独立限制，不能把“私有部署”当作泄漏不可能的证明。 深化与验证：[[AI/20-LLM/70-工程应用与工具链/09-Agent状态机幂等执行与提示注入边界|Agent状态机幂等执行与提示注入边界]]；[[AI/20-LLM/80-研究拓展/04-隐私记忆成员推断与机器遗忘|隐私记忆成员推断与机器遗忘]]。


## 目标与适用场景

本页要把“本地能跑”收紧为“只有预期主体能访问、能停止、能恢复”的私有服务。学完后，你应能区分监听地址、防火墙、认证、授权和 TLS 的职责，并为 loopback 或经审批的 LAN 部署写出可验收、可回退的边界。

> [!danger] 本路线不提供公网暴露方案
> 不包含公网 IP、路由器端口转发、公网反向代理、隧道或穿透的开通路线。若需对外服务，应进入组织的独立安全架构、隐私、运维和应急审批，而不是放大本页的 LAN 示例。

## 先画边界，再选服务器

一个“本地模型服务”仍可能读取权重、缓存、提示词、检索资料和凭据，生成新输出，甚至调用工具。应先列出四类东西：

| 边界 | 要回答的问题 | 默认 |
| --- | --- | --- |
| 身份边界 | 谁可以发请求？谁可以管理模型？ | 只有本机当前用户 |
| 网络边界 | 哪个网卡、地址和端口接受连接？ | `127.0.0.1` 或 `::1` |
| 数据边界 | 输入、权重、缓存、输出、日志和凭据分别在哪？ | 分离目录、最小读写权限 |
| 能力边界 | 请求能否促成文件写入、命令、浏览器或外部请求？ | 工具调用关闭 |

“没有公网 IP”不等于没有攻击面；同一 LAN 内仍可能有访客设备、IoT、恶意软件或误配置客户端。

## 默认只有 loopback

loopback 表示连接不离开本机网络栈。它缩小了网络面，却不会自动阻止本机其他用户、被攻破进程或浏览器页面访问服务。因此，loopback 仍要配合进程身份、认证、文件权限和请求限制。

下面是**静态配置草稿**，不是启动命令：

```text
BIND_HOST=127.0.0.1
BIND_PORT=            # 空值：尚未核对端口，拒绝启动
DEPLOY_SCOPE=loopback
AUTH_SECRET=          # 空值：不在文档中填真实凭据
TLS_CERT_FILE=        # loopback 开发可保持空；LAN 必须是受控文件
TLS_KEY_FILE=         # 绝不进入 Git、笔记、镜像或日志
TOOL_CALLING=off
```

程序的安全默认应是“缺少必要变量就失败退出”，而不是悄悄补上 `0.0.0.0`、无认证或自签名且客户端不校验的降级配置。

## LAN 是显式门禁，不是一个监听参数

只有 loopback 无法满足已确认的需求时，才评估 LAN。以下门禁必须**全部**具备：

| 门禁 | 可验收的要求 | 常见伪安全 |
| --- | --- | --- |
| 必要性与责任人 | 记录使用人、用途、时段和停止权 | “先开了再说” |
| 精确监听 | 只绑定获批的 LAN 接口/地址和单一端口 | 把 `0.0.0.0` 当作方便别名 |
| 认证 | 每个主体有可撤销身份；管理与推理分权 | 共享一个长期 token |
| TLS | 客户端校验证书链和主机身份；有轮换与失效方案 | 只加密但不验证对端 |
| 防火墙 | 入站默认拒绝，只放行精确来源、目标和端口 | “应用有认证，防火墙不重要” |
| 请求限制 | 输入/输出 token、并发、队列、频率和超时都有上限 | 只限单次 body 大小 |
| 日志隐私 | 默认不记提示词、生成文、凭据和文件全路径 | 用“调试”长期保存原文 |
| 停止与恢复 | 有单一停止入口、撤销身份、收回规则与确认不再监听的清单 | 只“杀进程”却留下自启和凭据 |

TLS 保护传输，不决定“谁能做什么”；防火墙缩小可达范围，不替代应用认证。这三层不能互相抵消。

### LAN 配置的空值门禁

可把以下规则写成启动前验证：

```text
if DEPLOY_SCOPE == "lan":
    require BIND_HOST is one approved interface address
    require AUTH_SECRET is non-empty and comes from a secret store
    require TLS_CERT_FILE and TLS_KEY_FILE are non-empty, readable only as intended
    require FIREWALL_CHANGE_ID and STOP_OWNER are non-empty
otherwise:
    require BIND_HOST in {127.0.0.1, ::1}
```

这是伪代码，不会启动服务，也不含真实密钥。门禁的目的是让“没有审批材料”变成可观察的失败，而不是默认放行。

## 资产隔离：权重不是缓存，输出不是凭据

| 资产 | 权限与保留策略 | 绝不应出现的地方 |
| --- | --- | --- |
| 模型权重 | 只读挂载，记录来源、revision/哈希和模型许可 | 公开镜像、无限制共享目录 |
| 下载/编译缓存 | 独立可删目录，设容量与过期时间 | 与唯一权重副本或凭据混放 |
| 会话与生成输出 | 按项目/用户隔离，明确用途和删除时间 | 模型目录、不可控全局日志 |
| 日志 | 优先记请求 ID、状态、延迟、用量和错误类别 | 提示词原文、生成原文、Authorization 头 |
| 凭据与 TLS 私钥 | 由密钥机制注入，最小读权限，可轮换 | 笔记、代码、环境镜像、错误回显 |

## 容器优先，但宿主边界仍在

对可容器化的推理服务，优先用固定镜像摘要、非 root 用户、只读权重挂载、独立输出和不发布端口的容器记录项目用户空间。但容器不提供自己的 GPU 内核驱动，也不自动隔离你主动挂载的目录、宿主网络或凭据。

- Ubuntu native 适合依赖稳定发行版支持周期、APT 包和厂商驱动组合的主机；项目 Python/推理依赖仍应隔离。
- Arch native 适合理解滚动内核、驱动和用户空间的一致升级；它不提供长期 ABI 不变的假设，更不应 partial upgrade。

宿主排错应回到 [[计算机知识/20-操作系统/01-Linux/02-启动链Kernel与systemd|Kernel 与 systemd]]、[[计算机知识/20-操作系统/01-Linux/09-设备驱动内核模块与udev|设备驱动]]、[[计算机知识/20-操作系统/01-Linux/07-环境变量Shell启动与PATH|环境变量与 PATH]]和 [[计算机知识/20-操作系统/01-Linux/10-网络存储日志与故障排查|网络、存储、日志与故障排查]]；GPU 边界见 [[计算机知识/40-并行与异构计算/01-CUDA/00-CUDA-MOC|CUDA MOC]]。

## 停止、验证与恢复

停止不只是中断一个前台进程：

1. 停止唯一服务单元或容器，并阻止自动重启；
2. 从另一本机会话确认 loopback 端口不再监听；LAN 情况还要从获批客户端确认不可达；
3. 撤销本次身份、证书或临时授权，收回精确防火墙放行；
4. 按保留策略清理独立缓存、输出和调试日志，不删唯一权重副本；
5. 恢复先前的只读配置，再次确认只剩 loopback 或完全停止状态。

systemd 服务的“停止”“禁用”“被 socket/timer 再次激活”不是同一状态；参见 [[计算机知识/20-操作系统/01-Linux/02-启动链Kernel与systemd|Kernel 与 systemd]]。

## 练习：只做静态评审

不启动服务、不改防火墙。为“一个容器读只读模型权重，向本机客户端提供生成 API”填写一页部署卡：

- `BIND_HOST=127.0.0.1`，端口保持空值，直到确认无冲突；
- 权重、缓存、输出、日志、凭据的目录类别与读写权限；
- 认证与工具调用默认；
- 请求超时和 token 上限；
- 停止后的三项观察证据；
- 若有 LAN 需求，列出尚未满足的全部门禁，但不写开通命令。

## 成功标准

- 能解释 `127.0.0.1`、防火墙、认证、授权与 TLS 的不同职责。
- 能识别 `0.0.0.0`、空凭据、禁用证书校验和原文日志的风险。
- 能为 LAN 需求列出认证、TLS、防火墙、精确监听、日志隐私、停止与恢复的证据。
- 能证明资产已隔离，且本页练习没有启动服务或打开端口。

## 恢复方法

本页操作仅为静态规划，不会产生服务或防火墙状态。若将来实践中的边界与预期不同，立即停止服务，撤销当次身份与防火墙变更，恢复为 loopback 配置，并用只读网络与日志证据确认。不知道如何撤销时，就不进入 LAN 门禁。
