# 动态规划状态转移与空间优化

## 本课目标

- 把“状态”写成带边界、单位和语义的句子，而不只是一个数组下标；
- 判断最优子结构与无后效性是否成立，并由此推出转移；
- 区分自顶向下的记忆化搜索与自底向上的表格法；
- 知道一维压缩为什么依赖更新顺序，以及何时绝不能压缩。

## 1. DP 不是公式表，而是状态语义

动态规划适用于子问题反复出现、且整体最优解可由较小子问题的最优解组合而成的问题。核心不是先写 `dp[i]`，而是先完整读出它：

> `dp[i][c]` 表示：**只使用前 $i$ 件物品，在总重量不超过容量 $c$ 的条件下，能够取得的最大总价值。**

这里 $i$ 的范围、容量单位、“前 $i$ 件”、`不超过` 和 `最大价值` 都是状态的一部分。缺少其中任意一个，转移就可能偷偷改变问题。

**无后效性**说的是：一旦状态变量已经固定，未来决策的可行选择和最优结果只依赖这个状态，不依赖到达它的完整历史。它不是“程序以后不读取旧变量”，而是“旧历史中与未来有关的信息已经被状态充分概括”。

例如最短路径若状态只写“当前顶点”，但路径成本还受“已经用过的优惠券”影响，就不满足无后效性；状态必须加入“优惠券是否已用”。

## 2. 例子：0/1 背包的状态与转移

有 $n$ 件物品，第 $i$ 件重量 $w_i$、价值 $v_i$；每件最多选一次，背包容量为 $C$。本课这个表格 DP 的输入契约是：$C\in\mathbb Z_{\ge0}$、$w_i\in\mathbb Z_{>0}$，$v_i$ 为有限可比较数值（例中为整数），并且**允许一件也不选**。因此即使所有价值为负，答案仍可为 0；若题目要求至少选一件或恰好装满，边界与不可达状态必须另行定义。对第 $i$ 件物品，最优解只有两类：

- 不选它：价值为 `dp[i-1][c]`；
- 若 $w_i\le c$，选它：剩余容量为 $c-w_i$，价值为 `dp[i-1][c-w_i]+v_i`。

所以

$$
dp[i][c]=
\begin{cases}
dp[i-1][c], & w_i>c;\\
\max\bigl(dp[i-1][c],\ dp[i-1][c-w_i]+v_i\bigr), & w_i\le c.
\end{cases}
$$

边界是 `dp[0][c]=0`（没有物品）和 `dp[i][0]=0`（没有容量）。证明按 $i$ 归纳：第 $i$ 件要么不在任何最优解中，要么在；两类穷尽且互斥，去掉已选物品后余下部分必须是前 $i-1$ 件、容量 $c-w_i$ 的最优解，否则可替换为更优子解，矛盾。

### 手算一个表

物品依次为 $(w,v)=(2,3),(3,4),(4,5)$，容量 $C=5$。每行是“可用物品数”，每列是容量：

| $i\backslash c$ | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 0 件 | 0 | 0 | 0 | 0 | 0 | 0 |
| 加入 $(2,3)$ | 0 | 0 | 3 | 3 | 3 | 3 |
| 加入 $(3,4)$ | 0 | 0 | 3 | 4 | 4 | 7 |
| 加入 $(4,5)$ | 0 | 0 | 3 | 4 | 5 | 7 |

答案是 7，对应前两件。表中 `dp[2][5]=7` 不是“恰好装满 5”的唯一语义，而是“不超过 5 的最大价值”；若问题改成“恰好装满”，不可达状态应使用 $-\infty$ 或单独标记，不能仍用 0。

## 3. 记忆化搜索与表格法

两种写法计算的是同一递推关系，却有不同的控制流。

| 方法 | 方向 | 优点 | 需要警惕 |
| --- | --- | --- | --- |
| memoization（记忆化） | 从目标状态递归向下 | 只求真正访问到的状态；递推式接近数学定义 | 递归深度、函数调用开销、缓存键必须包含完整状态 |
| tabulation（表格法） | 从边界向目标迭代 | 没有深递归；依赖顺序可见、容易控内存 | 必须先填完依赖，初始化和遍历方向容易写错 |

0/1 背包的表格伪代码：

```text
for c from 0 to C:
    dp[0][c] = 0
for i from 1 to n:
    for c from 0 to C:
        dp[i][c] = dp[i - 1][c]
        if weight[i] <= c:
            dp[i][c] = max(dp[i][c], dp[i - 1][c - weight[i]] + value[i])
return dp[n][C]
```

记忆化版本要先检查缓存；否则递归树仍会重复求解。无论哪种方法，时间上最多访问 $n(C+1)$ 个状态，空间为 $O(nC)$；这里 $C$ 是数值容量，所以是**伪多项式**，不是输入位数意义上的多项式时间。

> [!example] 为什么 `C` 和 `log C` 不能混写
> 若容量 `C = 1,000,000`，表格法会为每件物品考虑约一百万个容量格；但把这个数写进二进制只需要约 20 位，因为 $2^{20}\approx1,000,000$。因此 `O(nC)` 对**数值 C**是线性的，却可能相对输入的编码长度 `log C` 很大；这就是“伪多项式”要额外说明参数口径的原因。

## 4. 空间压缩：先问“读取的是旧行还是新行”

二维转移只读取上一行 `dp[i-1][*]`，因此可以把它压成一维 `dp[c]`。但处理第 $i$ 件物品时，`dp[c-w_i]` 必须仍代表**上一行**；所以容量必须从大到小更新：

```text
dp[0..C] = 0
for each item (weight, value):
    for c from C downto weight:
        dp[c] = max(dp[c], dp[c - weight] + value)
return dp[C]
```

倒序让 `dp[c-w]` 尚未在本轮被覆盖，因而每件物品至多用一次。压缩后空间为 $O(C)$，时间不变。

### 失败反例：0/1 背包错误地正序更新

只有一件物品 $(w,v)=(2,3)$，容量为 4。若正序更新：

- $c=2$ 时得到 `dp[2]=3`；
- $c=4$ 时读取的是**刚刚本轮写入的** `dp[2]=3`，于是算出 `dp[4]=6`。

这等于把同一件物品拿了两次，悄悄把 0/1 背包改成了完全背包。错误不是循环写反这么简单，而是状态语义被破坏。

对于**完全背包**，每种物品可以无限次使用，恰好希望本轮的 `dp[c-w]` 可见，容量应从小到大更新。这里仍须先拒绝或单独报告 `w=0, v>0` 的物品：可无限次拿取而不耗容量，最优价值无界，普通表格转移没有有限答案。`w=0, v≤0` 是否保留则由“可空选/是否必须选物品”的契约决定；本课的可空选最大化契约可安全忽略它。更新方向来自依赖关系，不能靠背诵。

## 5. 哪些情况下不能只保留一行

压缩前逐项确认：

- 转移是否只依赖相邻的固定数量层？若依赖整段历史，可能需单调队列、前缀结构或保留更多层；
- 同一层是否有相互依赖？有时需要双缓冲，不能原地更新；
- 是否需要恢复具体方案？只有最优值时可压缩；要回溯选了哪些物品，通常保留决策表，或另行做可恢复设计；
- 边界值是否与“不可达”混淆？最小化常用 $+\infty$，最大化常用 $-\infty$，布尔可达性用 `false`。

节省内存是实现优化，不是正确性前提。与时间/空间层级和实际测量有关的工程成本，可参照 [[计算机知识/30-计算机系统/04-缓存局部性带宽与延迟|缓存、局部性、带宽与延迟]]；先证明语义等价，再测量是否真的值得压缩。

## 6. 状态设计的常见失败

1. **状态太少**：旅行问题只记录城市，却忘记剩余油量或已访问集合；不同历史被错误合并。
2. **状态太多**：把完整路径字符串放进状态，即使它不影响未来选择，状态数会爆炸。
3. **目标混淆**：把“最多价值”与“最少件数”写在同一个数里，却没有定义比较规则。
4. **边界不一致**：把不可达初始化成 0，导致不存在的方案被当作有效最优解。
5. **先压缩后证明**：只看数组下标没有越界，却没有验证读到的是哪一轮语义。

## 练习

1. 对物品 $(1,2),(3,4),(4,5)$ 与容量 5，画出完整的 0/1 背包表，给出最优值和一组物品选择。
2. 用“当前顶点、是否已用一次免费边”设计最短路状态。解释为什么只写“当前顶点”会丢失未来相关信息。
3. 用单件 $(2,3)$、容量 4 亲手执行正序和倒序一维更新，说明每个数组格在两种循环中的语义。
4. 把背包目标改成“恰好装满且价值最大”。写出不可达状态的初始化，并解释为何不能用 0 代表它。

## 成功标准

- 你能把一个 DP 状态读成完整的自然语言约束，而非只读数组名；
- 你能说明 0/1 背包的两种转移穷尽所有解，并用最优子结构解释替换为何矛盾；
- 你能区分 memoization 与 tabulation 的方向、缓存/依赖要求；
- 你能用单件物品的反例证明 0/1 背包一维更新必须倒序，并说明完全背包为何相反。
