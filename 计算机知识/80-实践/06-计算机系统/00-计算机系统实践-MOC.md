# 计算机系统实践 MOC

前七个用户态观察实验把 [[计算机知识/30-计算机系统/00-计算机系统-MOC|计算机系统稳定课]] 中的抽象变成 macOS/Linux 普通用户可观察的现象。它们不读写块设备、不挂载文件系统、不需要 `root`/`sudo`，不修改现有项目或用户数据。

## 证据分层

| 证据 | 能说明 | 不能说明 |
| --- | --- | --- |
| 源码与静态解释 | 调用了哪些 API，奇偶分支与资源边界是什么 | 本机一定观察到某个计数或性能排序 |
| 自测试或单元测试 | 结果契约、边界值与清理路径成立 | 虚拟内存、缓存或持久化机制的全部内核实现 |
| 一次实际运行 | 当前机器、当前负载下的观察值 | 其他 CPU、内核、文件系统或负载下必然相同 |
| 重复测量与中位数 | 将单次调度噪声与趋势初步分开 | 自动消除频率、热管理、预取、页缓存等混杂因素 |

## 开始前检查

1. 在终端中运行 `python3 --version` 和 `cmake --version`；Python 实验只要 Python 3，C++ 实验要求 CMake 3.20+ 与 C++20 编译器。
2. 每个 README 的命令都在**该 README 所在的实验目录**执行；命令中的 `.` 指当前实验目录，不是 Vault 根目录。
3. 只想使用 Python 时，先做虚拟内存和原子替换；想使用 C++ 时，先做数据表示，再做缓存和 POSIX pipe。
4. 如果出现需要 `sudo`、真实设备、外部 PID 或真实用户路径的步骤，已经超出这些实验的安全边界，应立即停止。

特权态、Sv39 与定时抢占实验另需支持RISC-V目标的Clang、`ld.lld`与`qemu-system-riscv64`，通过参数显式传入工具路径；构建产物使用独立临时目录，具体命令与超时见该实验README。下列“统一安全边界”和“七个实验”完成标准针对原用户态观察组，特权态组按其单独约束验收。

## 特权态、异常入口与系统调用

先读[[计算机知识/30-计算机系统/08-异常中断系统调用与特权级|ISA入口与系统调用ABI]]，再做[[计算机知识/80-实践/06-计算机系统/09-RISC-V特权态与系统调用/README|RISC-V特权态与系统调用]]：把教学ABI、`scause/sepc`分流、trapframe保存恢复和`sret`放进实际RV64 ELF，由QEMU `virt`系统仿真执行。未知调用与U态非法CSR形成对照。

这是单hart、无分页和调度的最小教学内核。QEMU使用TCG、无BIOS、无网络、无端口转发或宿主共享；运行器设总超时，默认临时构建目录会清理。`satp=0`且PMP广泛放行，因此只验证特权转换、CSR权限和软件trap路径，**不证明U/S内存隔离、宿主隔离或真实硬件安全**。验收需退出码、完整有序语义标记和无失败标记同时成立，不能只看启动行。

### Sv39 页表与权限故障

完成特权态实验后，继续做 [[计算机知识/80-实践/06-计算机系统/10-Sv39页表与故障隔离/README|Sv39 页表与故障隔离]]：用真正的三级页表把低地址 U 态虚拟别名映射到高地址物理页，手算同一个 VA 的三个索引与 PTE，并在 QEMU `virt` 中实测 store/load/instruction page fault。实验逐项核对 `scause/sepc/stval`、物理后备值、trapframe canary 与 `sfence.vma` 后的权限收紧。

这是单 hart、无调度的最小教学内核；S 态身份映射仍为教学用 RWX，未实现 ASID、多核 TLB shootdown、COW、按需分页或通用进程终止。TCG 结果不证明宿主隔离、完整 OS 安全或真实硬件行为。

### 定时器中断与抢占上下文切换

完成 09/10 实验后，先读 [[计算机知识/30-计算机系统/09-进程线程调度同步与IPC|进程、线程、调度、同步与 IPC]] 和 [[计算机知识/30-计算机系统/10-IO设备总线DMA与中断|I/O、设备、总线、DMA 与中断]]，再做 [[计算机知识/80-实践/06-计算机系统/11-定时器中断与抢占调度/README|定时器中断与抢占调度]]：让两个不会主动 `yield` 的 U 态热循环被真实 Sstc timer interrupt 交替打断，逐次核对 cause 5、`sepc`、两份 trapframe、两个 U 栈、寄存器/栈 canary 和双方工作进度，再由 `sret` 恢复另一份上下文。

这是固定两任务、单 hart、单地址空间的最小抢占调度器；没有阻塞、优先级、动态任务、内核线程 context switch、地址空间切换、公平性证明或多核 timer/IPI。QEMU TCG 只证明该 guest 的架构路径，不证明宿主隔离、生产 OS 安全或真实硬件时序。

## 统一安全边界

- C++ 实验要求 CMake 3.20+ 和 C++20；Python 实验只使用 Python 3 标准库。
- 实验运行时样本数据位于匿名映射或 `tempfile.TemporaryDirectory` 创建的精确临时目录；上下文结束后由标准库清理。三个 CMake README 中的默认命令会在当前实验目录创建 `build` 或 `build-release` 本地构建产物，它们不属于样本数据，也不会自动清理；每个 README 都给出了该实验的精确清理边界和可选 `/private/tmp` 外部构建方式。
- 不对基准耗时、页错误数量或 major fault 必须大于零写硬断言。
- 若你修改实验使其接收外部路径，必须重新设计目标校验、失败清理和恢复方法；默认版故意不接收真实文件路径。

## 完成标准

七个实验的测试全部通过；你能把每个输出归类为“语言/API 契约”、“当前进程观察”或“含测量噪声的性能样本”；能说明为何这些结果不证明物理页号、TLB/cache 命中率、生产 NUMA 收益、宿主机全局资源或突然断电后的实际持久性。
