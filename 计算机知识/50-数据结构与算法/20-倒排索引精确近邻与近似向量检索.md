# 20 · 倒排索引、精确近邻与近似向量检索

> [!info] 历史证据已补入
> 原有证据字段保持其历史记录；所指 [[Logs/2026-09-05_改造证据/内容审阅记录|内容审阅记录]] 已从 WorkWithLLM 按原字节补入。其范围见 [[Logs/来源材料/WorkWithLLM/README|来源说明]]；本批未重新认证本页内容或提升证据等级。

## 本课目标

学完后，你应该能够：

- 从 `term → postings` 解释倒排索引如何生成候选，并区分 AND、OR、短语与打分语义；
- 用精确余弦穷举建立小规模 oracle，说明 top-k 的排序、平局与零向量合同；
- 解释随机超平面 LSH 或近邻图如何用召回换延迟，而不是把 ANN 当成“更快的精确搜索”；
- 在同一快照、同一过滤语义和同一 $k$ 下评测 recall@k、延迟与内存；
- 把 ACL/租户过滤放在候选和 top-k 的安全边界内，并区分“检索到证据”和“证据证明事实”。

## 1. 检索不是一种数据结构

“找到最相关文档”至少包含五层：规范化输入、生成候选、计算分数、权限过滤、选择 top-k。倒排索引擅长词项匹配；向量索引擅长按几何相似度找候选；过滤索引约束租户、时间和类型；重排器再综合更昂贵的信号。任一层都不能自动替代其他层。

在 RAG 中，文档先被切成 chunk 并生成 embedding；检索结果只是送给模型的候选上下文。完整数据流与最小实现见 [[AI/20-LLM/70-工程应用与工具链/02-Embedding-Chunking与最小RAG|Embedding、Chunking 与最小 RAG]]，向量表示的语义边界见 [[AI/20-LLM/10-原理/03-Embedding表示与语义空间|Embedding 表示与语义空间]]。

## 2. 倒排索引：从词项回到文档

前向文档保存 `doc_id → text/fields`；倒排索引反过来保存 `term → postings`。一个 posting 至少含文档 ID，也可含词频、位置、字段、版本或压缩块信息：

```text
文档：
d1: "cache index cache"
d2: "graph index"

postings：
cache -> [(d1, tf=2, positions=[0,2])]
index -> [(d1, tf=1, positions=[1]), (d2, tf=1, positions=[1])]
graph -> [(d2, tf=1, positions=[0])]
```

查询 `cache AND index` 可求两个有序 posting list 的交集；`cache OR graph` 求并集。短语 `"cache index"` 还必须比较位置，只有词项共现并不足够。BM25 等排序会使用词频、文档频率和文档长度；本课 toy 实现只把查询词频命中的文档词频求和，不能称为搜索引擎质量。

### 规范化是索引合同

大小写折叠、Unicode 规范化、分词、停用词、词干化、语言和字段选择必须在索引与查询两侧一致。中文没有天然空格分词；课程中的 `\w+` 只是可运行样例。规范化版本变化意味着需要重建或双版本迁移，不能把旧 postings 和新查询分析器静默混用。

倒排表可看成从词项到有序文档 ID 序列的映射，与 [[计算机知识/50-数据结构与算法/04-哈希表集合与冲突处理|哈希表]]、[[计算机知识/50-数据结构与算法/06-平衡树B树Trie与索引结构|B 树、Trie 与索引结构]] 相连。真实索引通常分段、压缩、缓存并持久化；顺序扫描 posting block 的局部性与随机指针结构不同，见 [[计算机知识/30-计算机系统/04-缓存局部性带宽与延迟|缓存、局部性、带宽与延迟]]。

## 3. top-k：候选、分数与稳定语义

若有 $C$ 个候选，先算全部分数再排序通常花 $O(C\log C)$；维护大小为 $k$ 的最小堆可把选择写成 $O(C\log(k+1))$，但仍要计算每个候选分数。常见的 $O(C\log k)$ 简写默认 $k\ge 2$；写成 $\log(k+1)$ 可以覆盖 $k=1$，避免把常数工作的字面上界误读成零。阈值算法、跳表和 block-max 上界可进一步跳过不可能进入 top-k 的候选，其正确性依赖分数上界。

top-k 合同还需定义：

- 分数越大越好还是越小越好；NaN、无穷和缺失值如何处理；
- 同分时是否按稳定文档 ID、时间或业务优先级打破平局；
- $k$ 大于可见候选数时返回较短列表还是补齐；
- 重复 chunk、同文档多 chunk 与多路召回如何去重；
- 快照更新中分页是否稳定，游标是否绑定索引版本。

没有稳定平局规则时，同一分数集合可能在重建后改变顺序，使回归测试、缓存键和分页漂移。

## 4. 精确余弦搜索：先建立 oracle

对非零向量 $q,x$，余弦相似度为

$$
\cos(q,x)=\frac{q\cdot x}{\lVert q\rVert_2\lVert x\rVert_2}.
$$

若所有向量预先单位化，排序只需点积；否则每次还需范数。零向量的余弦未定义，必须在摄取或查询边界拒绝/单独约定，不能让 `0/0` 变成静默 NaN。

对 $N$ 个 $d$ 维向量逐个计算是 $O(Nd)$ 时间。它在小数据集、离线评测和过滤后候选较少时很有价值，因为没有 ANN 候选遗漏：在给定数值精度、相同向量快照、过滤集合、分数与平局规则下，它是本课 recall@k 的精确 oracle。它不是事实 oracle，也不证明 embedding 的语义质量。

精确搜索仍可能受浮点精度、量化、不同归一化和库实现影响。评测近似索引时，必须让 exact 与 ANN 使用同一距离语义；拿 cosine ANN 对比欧氏距离 oracle 得到的 recall 没有明确含义。

## 5. ANN：用候选遗漏换资源

Approximate Nearest Neighbor（ANN）索引试图少看一些向量，换取更低查询延迟或更大可扩展规模。代价是可能漏掉精确 top-k；索引构建时间、内存和更新成本也可能上升。

### 随机超平面 LSH 的 toy 思路

为每个随机超平面 $r_i$ 计算一位签名：

$$
b_i(x)=\mathbf{1}[r_i\cdot x\ge 0].
$$

把多位拼成 bucket key，只在与查询同 bucket（或少量邻近 bucket）的向量中精确打分。对于方向夹角为 $\theta$ 的两个向量，一条随机超平面的同号概率为 $1-\theta/\pi$；拼接更多位会缩小候选集，也可能让相近向量因一位不同而被漏掉。多个独立表或 multi-probe 可提高 recall，却增加内存或查询工作。

本课实践的 toy LSH 只有**一个表、固定高斯伪随机平面、同桶查询**，没有多表、探测预算、动态更新、并发、持久化、向量化、安全隔离或经过验证的参数调优。因此它只用于观察候选-召回权衡，绝不应描述为生产可用 ANN。

### 受限近邻图的另一条路线

图式 ANN 把向量视为顶点，为每个顶点保留少量近邻边；查询从入口沿“更接近查询”的边探索并维护候选队列。搜索预算越大通常 recall 越高、延迟也越大。局部最优、入口选择、建图质量、删除与并发更新都会影响结果；教学上的普通 BFS/DFS 不等于生产近邻图搜索。图表示与遍历不变量见 [[计算机知识/50-数据结构与算法/07-图的表示BFS-DFS与拓扑排序|图的表示、BFS、DFS 与拓扑排序]]。

## 6. recall@k：在相同问题上比较

令 $E_k(q)$ 是精确方法对查询 $q$ 的 top-k，$A_k(q)$ 是近似方法返回集合，则

$$
\operatorname{recall@k}(q)=\frac{|E_k(q)\cap A_k(q)|}{|E_k(q)|}.
$$

当可见语料不足 $k$ 时，分母应使用精确结果的实际数量；空语料时需明确约定。多个查询通常报告均值、分位数和分组结果，不能只报告最好样例。精确 top-k 有边界同分时，单一集合 oracle 可能任意选择同分项；严谨评测需固定 tie-break，或把边界同分等价集合纳入定义。

recall@k 只测“近似方法是否找回精确方法的邻居”。它不测标注相关性、答案正确性、覆盖率、公平性或新鲜度。若要评测检索质量，还需要带相关性标注的 precision、MRR、nDCG 等任务指标；若要评测 RAG，还需上下文归因和答案事实核验。

## 7. 延迟与内存不能只报一个数字

一次公平比较至少固定：数据/向量快照、查询集、过滤条件、$k$、距离、硬件、线程、预热、并发、缓存冷热、构建参数和重复次数。

| 维度 | 至少记录 | 常见误导 |
| --- | --- | --- |
| 查询延迟 | p50、p95/p99、吞吐、并发与冷热状态 | 只报一次最快 wall time |
| recall | 均值、低分位/分组、同一 exact oracle | ANN 和 exact 用不同过滤或快照 |
| 内存 | 原始向量、图/桶、ID/元数据、运行时峰值 | 只数向量 payload，不数索引对象 |
| 构建 | wall time、峰值内存、临时磁盘 | 把构建成本从总预算中消失 |
| 更新 | 可见延迟、删除、重建、版本切换 | 静态 benchmark 代替在线更新 |

Python 的 `sys.getsizeof` 递归和本课 `perf_counter_ns` 中位数只是进程内教学代理值，不等于 RSS、分配峰值、磁盘大小或跨机器 SLA。微基准还会受解释器、GC、CPU 调频和缓存影响。测量必须与正式负载测试分层报告。

## 8. 过滤语义属于正确性与权限边界

假设未过滤 top-1 是私有文档，而用户只能看公开文档。若先做全库 top-1 再把私有结果删掉，用户可能得到空结果；更严重的是，索引、缓存、日志、计时或调试信息可能已经处理并泄露不可见对象。

安全语义应写成：对**已获授权的候选域**求 top-k。实现可以把租户/ACL 作为索引分区、候选生成约束或检索中的强过滤，但最终仍要由权威权限层复核。若 ANN 后过滤不可避免，必须承认它改变 recall、结果数和延迟，并用过量召回或受限重查处理；不能把“最后删掉”称为与过滤前 top-k 等价。

权限过滤还不是事实过滤：能访问某文档，不表示它当前、真实、无冲突。RAG 应保留来源 ID、版本、时间与引用，让答案可回到权威材料验证。图边、关键词命中、embedding 相似度和模型措辞都只是证据信号，不是事实本身。

## 9. 混合检索与系统设计

关键词检索擅长精确名称、编号和罕见词；向量检索可找词面不同但语义相近的候选。混合检索可分别产生列表后做 rank fusion，或把一种结果当另一种候选/重排输入。分数尺度通常不可直接相加；先定义归一化或基于名次的融合，再用任务标注评测。

一个可审计的最小数据流是：

```text
query + identity
    -> 规范化
    -> 权威 ACL/tenant 约束
    -> 倒排和/或向量候选
    -> 同语义打分与稳定 top-k
    -> 来源、版本、分数随结果返回
    -> 事实核验/答案生成
```

缓存检索结果时，cache key 必须包含权限主体或等价授权范围、索引版本、过滤器和查询规范化版本；否则跨租户复用会泄露结果。缓存层与持久化边界见 [[计算机知识/30-计算机系统/11-存储设备块层页缓存与持久化|存储设备、块层、页缓存与持久化]]。

## 实践

进入 [[计算机知识/80-实践/05-数据结构与算法/11-概率结构与检索评测/README|概率结构与检索评测实践]]，运行标准库实现：

- 检查 `term → postings`、稳定 top-k 与过滤前排名；
- 用穷举余弦建立 exact oracle，再测 toy LSH 的 recall@k；
- 在同一数据与查询上观察中位延迟和递归对象大小代理值；
- 更改随机平面数量并记录 recall、候选数、延迟和内存的变化；不要从一组小样例推出生产结论。

## 练习

1. 为 `"vector index"` 写出 AND、OR、短语三种 postings 运算，并说明需要保存哪些字段。
2. 构造三个二维向量，手算给定查询的 cosine top-2；加入一个零向量，设计拒绝或隔离策略。
3. 解释增加随机超平面位数为什么通常缩小同桶候选，又为什么可能降低 recall；再说明多表如何改变内存与延迟。
4. 构造“私有文档是全库第一、公开文档是第二”的例子，对比过滤后删除与授权域内 top-1。
5. 写一张 benchmark 记录表，至少含数据版本、过滤语义、$k$、recall@k、p50/p95、索引内存和构建时间。

## 成功标准

- 你能从 postings 推导布尔候选，并说明位置表对短语查询的必要性；
- 你能用精确余弦定义 ANN 的 oracle，并避免距离、快照、过滤和 tie-break 不一致；
- 你能解释 toy LSH 的漏召回机制，且不会称其为生产 ANN；
- 你能在召回、延迟、内存和构建/更新成本之间做可复现实验；
- 你能把权限与事实核验放在检索分数之外的明确边界上。
