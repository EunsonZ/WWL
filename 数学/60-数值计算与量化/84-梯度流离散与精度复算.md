# 同一二次目标的梯度流、离散与精度复算

先在 [[数学/60-数值计算与量化/83-同一二次目标从梯度流到浮点停滞|同例正文]] 做一次预测，再用本页核对数字。本实验固定 $f=\frac12(x^2+10y^2)$、$\theta_0=(2,3/5)$；仅“迁移题”明示改第二曲率为 100，“隐藏方向反例”明示改变第二初值。所有参数、模型时间与误差均无量纲。这里保留数据和运行入口，主解释与推导在正文。

## 文件与逐字镜像

- [真源 gradient_flow_precision_lab.py](gradient_flow_precision_lab.py)：精确有理 GD 闭式、ODE 参照、逐运算 binary16/32 过程，以及本单元两幅图的生成器。
- [测试真源](test_gradient_flow_precision_lab.py)：有理闭式与另一递推核对、固定终点阶数、稳定却判断翻转、两种舍入停滞、隐藏方向、联合迁移与无效输入，共 8 项测试。
- [源码镜像](code-sync/gradient_flow_precision_lab.md) 与 [测试镜像](code-sync/test_gradient_flow_precision_lab.md)：Markdown 封装使用正式 `code-sync` 标记和紧邻 Python 围栏，代码块逐字同源并由库检查保护；修改时以真源为准并同时交接镜像。
- [计算结果 JSON](assets/gradient-flow/results.json)：输入、各层误差、低精度步长、初值表示误差、首个完全不动步次、最终梯度/更新量、迁移题、实际 Python/NumPy 和机器类型。
- [轨迹 CSV](assets/gradient-flow/trajectories.csv)：`case,format,h_rational,k,t,x,y,objective,distance_to_minimum_2,rounding_error_2,ode_error_2` 与两个布尔判定列。步数不超过 400 的运行保留全部状态；更长运行只保存注明的若干整数步，复算函数本身仍执行全部更新。

`rounding_error_2` 对低精度行是状态相对于原初值/预定步长的**实数 GD** 的二范数差，包含输入表示与运算；对实数 GD 行为 0。JSON 的 `input_representation_error_2` 与 `operation_error_2` 使用已存浮点输入的理想实数闭式再分开两项。JSON 的 ODE 条目不定义 GD 舍入误差，因此该字段为 `null`。

`ode_error_2` 是状态相对于同一模型时间的 ODE 参照的二范数；`distance_to_minimum_2` 相对于 $(0,0)$。`objective` 和范数用 binary64 诊断，不在低精度优化循环中计算。布尔列只是教学阈值的判定：`x<=0.72` 和二维距离 `<=1e-8`。它们不是泛化指标、真人学习评估或真实训练得分。

## 哪些检查已经运行，哪些还没有？

本次相关测试 8 项通过；图/数据生成完整运行，两个新图的 425px PNG 已离线查看，坐标、中文、图例与浅底可读。数据核对覆盖这些具体条件：

| 输入条件 | 可核对的结果 | 不能据此推广的结论 |
| --- | --- | --- |
| $h=0.1,N=10,T=1$ | 稳定但轨道误差约 0.0384，阈值判断不同 | 不能把稳定当作任意容差的精度证明 |
| $h=10^{-4},N=10000,T=1$ | binary16 第一分量全程为 2，第二分量仍变 | 不能称二维状态从第一步全部停滞 |
| $h=0.1,N=400,T=40$ | binary16 第 150 次转移开始完全不动，非零梯度而更新量 0 | 不能说该状态是数学最优点，或所有容差都不合格 |
| $h=0.1,N=1600,T=160$ | binary32 第 972 次转移开始完全不动 | 不能说提升精度消除了全部范围极限 |
| $c=100$ 的明确迁移条件 | 误差、容差与预算可以分别接受或拒绝方案 | 不能把指定 CPU 过程认证成 GPU 或混合精度流程 |

数学 GD 闭式在有理输入下是精确的，转为图数据和范数时有 binary64 诊断误差。ODE 的解析形式是精确解，但本代码的 `exp` 数值是 binary64 近似；很小的第二分量在 $T=160$ 已舍入为 0。测试没有证明指数求值的无限精度或所有输入下的浮点正确舍入规范。

主机 NumPy 在这组调用中实际保留了可观察的次正规值；这不认证整个机器或所有内核的 FTZ/DAZ 设置。真实 GPU、原生半精度指令、FMA、混合精度累加、随机 SGD、Adam、控制系统、Obsidian 实际客户端和真人试读均未验证。来源核对范围是 Euler 算法/局部误差说明、NumPy 标量类型与 `finfo` 范围语义；来源和代码各承担不同证据。
