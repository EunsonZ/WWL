# 嵌套标签

> [!goal] 你将学会
> 使用 `/` 构造嵌套标签，区分标签、文件夹与内部链接，并避免把标签体系设计成一棵难以维护的“完美分类树”。

## 标签是一条横向信号

标签适合跨文件夹筛选状态、主题或教学用途。例如三篇样例都在同一文件夹，但拥有不同的子标签：

- [[Obsidian知识/30-实践/01-实验区/数据/甲-晨间笔记|甲-晨间笔记]]：`#playground/sample/daily`
- [[Obsidian知识/30-实践/01-实验区/数据/乙-阅读卡片|乙-阅读卡片]]：`#playground/sample/source`
- [[Obsidian知识/30-实践/01-实验区/数据/丙-项目记录|丙-项目记录]]：`#playground/sample/project`

`/` 构成层级。Tags view 会把它们折叠在 `playground → sample` 下，而搜索父级标签时可以观察整个分支。

## 三种组织手段不要混为一谈

| 你想表达 | 推荐手段 | 例子 |
| --- | --- | --- |
| 文件稳定放置位置 | 文件夹 | `Obsidian知识/30-实践/01-实验区/数据/` |
| 与一个具体对象的关系 | 内部链接 | `[[Obsidian知识/30-实践/01-实验区/数据/丙-项目记录]]` |
| 跨目录共享的状态或主题 | 标签 | `#status/active` |
| 可排序、可校验的单值 | 属性 | `status: active` |

`#person/李雷` 看似方便，但人物有了别名、资料和关系后，更适合成为一篇人物笔记；标签不应替代所有实体。

## 标签规则

- 标签不能包含空格；需要分词时可用 `-`、`_` 或 `/`。
- 标签大小写不敏感，但显示形式会受首次或常用写法影响；教程统一使用小写。
- 标签可以包含数字，但不能全部由数字组成，所以 `#2026-notes` 可用，`#1984` 不适合作为标签。
- 正文可写 `#playground/sample`；frontmatter 中通常写 `playground/sample`，不必带 `#`。
- 不要同时维护 `#active`、`#status-active`、`#status/active` 三种同义写法。

## 轮到你做

1. 打开 Tags view，展开 `playground`。
2. 点击 `playground/sample`，确认能看到甲、乙、丙。
3. 点击 `playground/sample/project`，确认只剩丙。
4. 在搜索中输入：

```text
tag:#playground/sample
```

5. 再加入类型属性：

```text
tag:#playground/sample [type:project]
```

6. 在甲的正文末尾临时写入 `#status/experiment`，观察 Tags view 后撤销。

## 标签命名的轻量约定

这个 playground 建议把标签的第一段留给用途：

```text
#playground/core/search
#playground/sample/project
#playground/community/tasks
#status/inbox
#topic/learning
```

这不是唯一正确方案。真正的原则是：能稳定复用、能预测、能删减。每周回顾时，如果一个标签只有一次使用且不再帮助检索，可以移除它。

## 检查结果

- 父标签是一个可浏览的层级入口，不是磁盘目录。
- 一篇文件可以有多个标签，却只能存放在一个文件夹位置。
- 属性 `status: active` 适合 Base 排序；标签 `#status/active` 适合快速点击与跨类型浏览。两者可以并存，但应有明确理由。
- 一个具体项目应链接到 [[Obsidian知识/30-实践/01-实验区/数据/丙-项目记录|丙-项目记录]]，而不是只加模糊的 `#project`。

## 挑战与复原

设计一个最多两级的标签：把“正在学习 Obsidian”表达为状态或主题。将它临时加到乙，分别用 Tags view 和 Search 找到它，然后删除。不要为这一次练习创建五层标签树。
