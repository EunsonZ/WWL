偏好优化的目标不是让模型“学会真理”，而是在给定提示与允许的回答空间中，让它更常给出人（或经审计的评价器）偏好的回答。它通常接在预训练与 [[AI/20-LLM/30-训练/03-SFT-LoRA与QLoRA|SFT、LoRA 与 QLoRA]] 之后：预训练让模型会续写，SFT 让它能遵循示例，而偏好优化处理“同样看似能回答时，哪一个更有帮助、诚实、安全、简洁或符合任务规范”。

> [!warning] 偏好不是客观标签
> 一对 `chosen / rejected` 只说明**在明确的评价准则、标注人群、语言、提示分布和比较语境中**，前者被判得更好。它不自动证明事实正确、不会产生偏见、适用于新语言，或能在越狱、长上下文和高风险场景中保持可靠。

## 先画坐标：反馈来源、数据生成与优化目标是三回事

“RLHF”“RLAIF”“DPO”“PPO”“GRPO”经常被排成同一列，但它们回答的问题不同：

|轴|典型选择|真正决定什么|
|---|---|---|
|反馈从哪里来|人类、AI 评价器、规则/校验器、环境结果|标签或奖励的来源、偏差和可审计性|
|候选怎样产生|固定离线数据、当前策略在线 rollout、best-of-$n$/rejection sampling|训练信号覆盖的是旧分布还是当前策略分布|
|怎样更新策略|SFT、DPO/ORPO/KTO、PPO、group-relative policy optimization 等|损失、参考策略、优势估计和所需模型状态|

因此 **RLAIF 描述反馈来源，不是一种唯一损失**；它可以与离线比较、奖励模型或在线策略更新组合。best-of-$n$/rejection sampling 是“生成多个候选、按评价器筛选，再用于选择或后续监督”的数据生成/选择路径，不等于 PPO。GRPO 一类方法用同一提示下的一组 rollout 构造相对优势并进行在线策略更新，工程上仍要承担生成、奖励可靠性、KL/裁剪、旧/新策略关系和分布漂移；它不是“无需价值模型，所以无需 RL 稳定性检查”。具体公式、参数和支持范围依实现版本而变，本页不把某个训练库的当前接口写成方法定义。

AI 评价器能扩展标注，却会继承模型偏差、提示敏感性、位置/长度偏好和潜在训练污染。应保留评价器模型 revision、prompt/rubric、采样参数、原始判定与抽样人工复核；“AI 偏好更一致”不等于更接近真实用户或更安全。

## 从“奖励”到“策略”的两层问题

对同一提示 $x$，有候选回答 $y_1,y_2$。偏好数据记录为 $y_w \succ y_l$，即 `chosen` 胜过 `rejected`。一种常见建模方式是假设潜在奖励函数 $r(x,y)$ 通过 Bradley–Terry / logistic 比较生成该标签：

$$P(y_w \succ y_l\mid x)=\sigma(r(x,y_w)-r(x,y_l)).$$

这不是“人脑中存在一个精确奖励标尺”的事实，只是把比较标注转换为可估计模型的假设。奖励模型即使在保留集上能排序，也可能学到长度、格式、免责声明或标注器文风等捷径；它能被生成策略钻空子（reward hacking）。因此奖励模型要与最终模型分离评测，并查看胜率之外的事实性、拒答边界、长度、重复、毒性和领域切片。

有奖励后，策略 $\pi_\theta(y\mid x)$ 的经典目标可以写成：

$$\max_\pi\;\mathbb E[r(x,y)]-\beta\,D_{KL}(\pi(\cdot\mid x)\Vert\pi_{ref}(\cdot\mid x)).$$

参考策略 $\pi_{ref}$ 往往是 SFT checkpoint。KL 项不是装饰：没有它，策略会为追逐奖励而迅速偏离原有语言能力和分布；但它也不能修复有害或错误的奖励信号。$\beta$、奖励缩放、长度归一和采样温度都改变这个权衡，不能脱离代码版本和评测集引用一个“通用最佳值”。

### 每人排序都传递，为什么共同奖励仍会失配

刚才的 BT 假设要求每份回答有同一标量奖励，所有比较都由奖励差产生。但“每个人都能给出严格排序”并不保证混合人群的比较概率还能由一个共同标量表示。带着“循环来自某个人，还是来自跨人聚合？”去[[AI/20-LLM/30-训练/12-从KL约束到DPO的逐步推导#三个人都能排序，合在一起为什么没有共同标量|三人三回答的完整聚合例]]，逐对计数后检验奖励差能否闭环。回来改变的是你是否接受**同一条件下共同标量可精确拟合**的建模判断，不能把这个表示限制改说成 DPO 无法训练。

如果问题移到“为什么这三人有资格代表所有受影响者、为何等权”，去[[哲学与文化/20-论证知识与规范/02-伦理与政治正当性#偏好聚合：谁被代表，为什么等权|聚合规则的理由与负担]]。带回一条代表规则及其最强反对理由，再在本页[[#聚合之后，先改数据还是改模型|聚合后的数据与模型决策]]决定保留哪些比较条件、承认何种拟合误差。

## 传统 RLHF：Reward Model + PPO

典型管线有四个互相依赖的阶段：

1. **定义准则与收集比较。** 对每类提示、风险等级与语言制定可操作 rubric；盲法、标注者分歧和拒绝样本要保留。只存最终胜者会丢掉不确定性与可审计性。
2. **训练奖励模型（RM）。** 用成对损失提高 $r(x,y_w)$、降低 $r(x,y_l)$。应按 prompt 或来源切分，避免同一模板的近重复泄漏到验证集；还应测量一致性和校准，而非只报 accuracy。
3. **用当前策略在线采样。** 策略生成新回答，RM 给奖励，参考模型计算 KL。这里首次出现昂贵的多模型前向、生成延迟与显存压力；离线偏好数据无法完全覆盖策略后来会生成的分布。
4. **PPO 更新策略并持续约束。** PPO 用 importance ratio 的裁剪目标限制一次更新过大，通常还跟踪 KL、熵、价值函数/优势估计和奖励统计。工程上须保存策略、value head（如有）、优化器、随机状态、数据游标、RM 与参考模型的精确版本，否则中断恢复和结果解释都不可信。

### 为什么 PPO-RLHF 昂贵且脆弱

它不只是“多跑几轮训练”。每轮至少涉及生成、策略 log-prob、参考 log-prob、奖励模型前向，以及常常还有价值网络；长回答使这些序列级成本成倍增长。更难的是反馈回路：RM 在旧分布上训练，策略却主动寻找它的盲区。奖励上升可能伴随事实性、帮助度或安全性下降。

出现下列信号时，先停止扩大训练而不是调大 batch：KL 突增或塌缩、回答异常变长/变短、RM 分数上升但人工盲评下降、特定语言或敏感主题退化、拒答模板化、训练/验证胜率差距扩大。恢复动作是回到上一可验证 checkpoint，固定采样与评测集，比较数据切片、RM 版本、长度分布和 KL 曲线；不能只保留“最好奖励”的权重。

## DPO：直接把偏好比较变成策略损失

Direct Preference Optimization（DPO）从带 KL 正则的最优策略关系出发，不显式训练奖励模型，也不做 PPO 的在线 rollout。它比较策略相对参考模型对胜/负回答的对数概率优势：

$$\mathcal L_{DPO}=-\log\sigma\left(\beta\left[
\log\frac{\pi_\theta(y_w\mid x)}{\pi_{ref}(y_w\mid x)}-
\log\frac{\pi_\theta(y_l\mid x)}{\pi_{ref}(y_l\mid x)}
\right]\right).$$

它改善的是相对参考策略的 chosen/rejected 对数概率比；损失下降不保证 chosen 的绝对概率上升。训练仍是逐 token 的 teacher-forcing log-prob；“直接”不代表不需要 tokenizer、聊天模板、长度处理和数据清洗。`beta` 源自前述 KL 正则目标：在来源目标中，较大的 `beta` 表示更强的参考策略锚定、较小的最优策略偏离；在 DPO loss 中，它同时缩放 log-ratio margin。有限训练中的实际变化还受学习率、reduction、数据和实现影响，因此不能把 `beta` 当成简单单调的“偏好强度”旋钮，更不能在不同实现、平均方式或数据集间直接比较。

固定 prompt、三个回答、均匀参考策略和 $\beta=1$，比较两个可行策略 $(0.30,0.20,0.50)$ 与 $(0.20,0.05,0.75)$，前两项是 chosen/rejected。chosen 从 0.30 降为 0.20，但概率比从 1.5 升为 4；损失 $\log(1+\pi_l/\pi_w)$ 从约 0.5108 降为 0.2231。这是目标函数反例，不是一次实际训练轨迹。自检：剩余概率质量去了哪里？为何相对 margin 增长不能证明更常生成 chosen？检查点：第三项增长；应同时跟踪绝对 log-prob、相对 margin 与独立任务评测。

**DPO 的收益：** 少了 RM、value model 与在线采样回路，训练通常更易实现、重放和 checkpoint；对于高质量、覆盖目标分布的离线成对数据，常是很实用的起点。

**DPO 的假设与边界：**

- `chosen` 与 `rejected` 必须是同一 prompt 下可比较的完整回答；把两个不同问题的“好答案”凑成一对没有统计含义。
- 比较偏好可被上述 logistic / 隐式奖励关系近似；总体循环可使共同标量无法精确表示，有限样本的循环则需先核抽样与比较条件。[[#每人排序都传递，为什么共同奖励仍会失配|聚合反例入口]]把这两种判断分开；分歧本身不能直接判为错误标签。
- 参考模型、tokenizer 与 chat template 是目标的一部分。token 边界或模板变了，两个 log-prob 不再表示同一条件事件。
- DPO 是离线目标：它不会自动暴露当前策略最常犯的新错。上线分布漂移、攻防提示和长尾语言仍需独立采样、红队与人工评测。

## ORPO：把 SFT 与 odds-ratio 偏好项合在一起

Odds Ratio Preference Optimization（ORPO）将偏好信号和对 `chosen` 的监督学习结合，避免单独的参考模型前向这一常见成本。它一面保留 chosen answer 的 NLL，让模型仍会写出目标回答；一面比较 chosen/rejected 概率的 odds ratio，惩罚相对偏向 rejected 的策略。直觉上，它不是只说“喜欢 A 胜于 B”，也持续说“请把 A 写出来”。

这使 ORPO 在训练资源有限、希望一个阶段完成 SFT + 偏好调整时有吸引力，但“没有显式 reference model”不是没有锚点：SFT 项、初始化模型、数据长度、实现中的系数和训练日程共同形成隐式锚点。ORPO 不会消除成对数据质量问题；若 rejected 只是更短、更少格式词或来自另一模型族，它可能学到表面风格偏好。

## KTO：只有好/坏标签时如何学习

Kahneman–Tversky Optimization（KTO）适用于没有严格 `chosen/rejected` 成对关系、但每条回答有 desirable / undesirable 标签的情况。它根据策略相对参考模型的 log-ratio 构造效用，并用类似前景理论的增益/损失处理来鼓励 desirable、抑制 undesirable。其价值在于让真实反馈、审核结果或单条质量标记可以成为训练信号，而不用伪造一个“同 prompt 的败者”。

代价是信息更弱：标签只能说一条回答可取或不可取，不能说明两个候选之间的细粒度取舍。正负样本比例、标签噪声、提示覆盖与对“不可取”的定义会显著影响结果。KTO 也仍需要一个参考策略来界定偏移；它不适合被宣传为“无配对数据就等价于 DPO”。如果数据本来有可靠成对比较，丢掉配对结构通常是在丢信息。

## 选择方法前先选证据

|可用证据与约束|优先考虑|理由|不要据此推断|
|---|---|---|---|
|高质量同 prompt 成对偏好；希望离线、可重放|DPO|目标直接利用胜负对，省去 RM/PPO 在线环|自动获得事实性或鲁棒安全性|
|既要保留 SFT 学习，又有成对偏好且参考模型前向很贵|ORPO|把 chosen 的 NLL 与相对偏好一起优化|不再需要控制长度、数据质量或评测|
|只有审核通过/失败等单条二元标签，无法可信配对|KTO|不伪造 pair，利用 desirable/undesirable 证据|标签的信息量等于排序偏好|
|需要探索当前策略分布，且有成熟 RM、在线评测与大预算|RM + PPO RLHF|可对新 rollout 优化并监控闭环|RM 分数即人类价值，或 PPO 必然优于离线法|
|评价标准含事实核验、工具执行或高风险政策|先建评测与数据治理|损失函数无法取代可审计的裁判和升级路径|“偏好训练”足以完成安全认证|

## 数据合同与最小可观察练习

把数据当作版本化证据，而不是一堆 JSON。DPO/ORPO 的最小记录应含 `id`、`prompt/messages`、`chosen`、`rejected`、准则版本、语言/领域/风险切片、来源许可和去标识化状态；KTO 将 pair 换成 `response` 与 `label`，仍要记录同样元数据。训练、验证、测试必须按 prompt/source 分组切分，防止同一问题的改写泄漏。

下面是读取本地 JSONL、选择性显示字段名和 ID 的预检；它会接触文件内容，不能把只显示部分字段解释为没有读取数据。ID 也可能敏感，应只使用已审核的样本。命令只有在你主动设置门禁和指向已审核的本地文件时才会运行；若任一变量缺失会失败退出。

```bash
if [ "${PREFERENCE_PREFLIGHT:-}" = "1" ] \
  && [ -n "${PREFERENCE_DATASET:-}" ] \
  && [ -f "$PREFERENCE_DATASET" ]; then
  jq -c 'select(has("chosen") and has("rejected")) | {id, keys: keys}' \
    "$PREFERENCE_DATASET" | head -n 3
else
  printf '%s\n' 'Set PREFERENCE_PREFLIGHT=1 and PREFERENCE_DATASET=/absolute/local/file.jsonl to run the read-only preflight.' >&2
  exit 2
fi
```

成功标准不是“命令有输出”，而是抽样记录确有同 prompt 的两个回答、字段对应既定 schema、敏感数据未写入终端日志，并且数据切分计划可说明。发现不一致时，先修 schema/模板/标注说明，再开始训练。

### 聚合之后，先改数据还是改模型

从[[AI/20-LLM/30-训练/12-从KL约束到DPO的逐步推导#循环出现后，怎样决定下一步|循环的三层诊断]]回来，先明确记录对应什么目标：若是在估计同条件下的偏好概率，需保存候选、提示、评价说明、比较方向与抽样规则，并在合法可行范围保留去标识化的原判断或条件分层及其不确定性；不能只存最后多数胜者。若允许多个条件，需把条件如何进入模型和部署时如何确定条件写清，不能把相反条件当同一个 $x$。

至少比较两种决定：继续用共同标量，公开各对的预测与残差，接受不能精确保留的分歧；或保留条件/群体差异、采用更丰富的比较模型，承担更多数据、复杂度与解释责任。[[哲学与文化/20-论证知识与规范/02-伦理与政治正当性#偏好聚合：谁被代表，为什么等权|伦理回程]]要求你给总体与权重一个理由；它可以改变目标定义，却不会替你证明某模型拟合更好。

把自己的决定写成四句话：**估计谁在什么条件下的判断；哪条证据支持当前诊断；选择哪条模型路径及代价；哪项新证据或反对理由会迫使修改。** 例如，三人教学总体的精确 $2/3$ 已排除该构造里的抽样解释，仍允许共同标量折中；若发现部署受影响者被系统性排除，首先要重审代表规则，不能靠调低训练损失处理。记录个人分歧没有获得可比较的福利单位，拟合残差小也没有证明权利或正当性。

## 评测、恢复与版本复核

训练前固定：基础/参考 checkpoint 的仓库 ID 与 revision、tokenizer 与 chat template、数据 manifest 哈希、训练代码 commit、损失实现和超参。训练中保存可恢复 checkpoint（模型/adapter、优化器、scheduler、随机状态、数据游标及运行配置），并分开保存“训练中最佳指标”和“盲评最佳模型”。训练后至少比较 SFT 基线与偏好模型在冻结的成对胜率、任务正确性、长度、拒答、语言/领域切片和攻击提示上的表现；没有相应评测就写“未验证”，不要用训练 loss 代替能力结论。

工具、支持模型、参数名和兼容矩阵属于快速变化信息；实施当天应复核 [[AI/90-资源/05-官方资料与版本核验记录|官方资料与版本核验记录]] 中的上游链接、具体 release/commit、模型卡、许可证、CUDA/驱动与硬件。本文未下载数据或权重，未启动训练，也未对任何模型作性能、安全或许可证合规结论。

## 练习

### 练习 1：把名字放回正确的轴

对“用 AI 评价器给同一 prompt 的 8 个当前策略回答打分，按组内相对奖励更新策略”分别写出反馈来源、候选生成方式和优化家族。说明为什么只写“RLAIF”不足以复现实验。

### 练习 2：检查一个 DPO pair

给出两条同 prompt 回答，设计检查表：模板是否相同、`chosen/rejected` 是否真可比、答案长度是否构成捷径、标注准则/分歧是否保留、prompt/source 是否跨 split、参考模型身份是否固定。至少写出一个应隔离而非训练的例子。

### 练习 3：给在线优化设停止条件

为 RM + PPO 或 group-relative 在线更新写出至少六个监控项，必须包含 KL/策略漂移、回答长度、奖励与人工盲评分歧、任务正确性、安全切片和资源预算。预先写明哪三个信号触发回退到上一 checkpoint。

<details>
<summary>核对要点</summary>

- 练习 1 的反馈来源是 AI，候选来自当前策略在线 rollout，更新属于组内相对优势的在线策略优化；还缺评价器、rubric、策略/参考版本、具体损失和实现。
- 两个不同 prompt、不同 system template 或不同语言任务的回答不能为凑格式强行组成 DPO pair；明显长度捷径也应先修数据。
- 奖励上升但人工盲评、任务正确性或安全门下降时必须停；KL 和长度异常、NaN/Inf、预算超限也应有明确回退规则。

## 成功标准

- 能把反馈来源、离线/在线候选生成和策略更新目标分成三条轴；
- 能解释 RM + PPO、DPO、ORPO、KTO 与 group-relative 在线方法各自省掉和新增的状态；
- 能审计 pair/label/rubric、参考模型、chat template、长度捷径和 split 泄漏；
- 能用冻结基线、独立任务指标、盲评、安全切片和停止条件约束偏好分数；
- 不把“奖励更高”“拒答更少”或“AI 评价一致”写成事实性、安全性或人类普遍偏好已经提高。
