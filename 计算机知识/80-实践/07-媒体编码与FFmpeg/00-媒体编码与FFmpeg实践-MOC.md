# 媒体编码与 FFmpeg 实践

这组实验只使用 FFmpeg 自带的 `lavfi` 合成短视频和正弦波，不下载媒体、不读取摄像头或麦克风、不联网，也不覆盖现有文件。每个脚本默认在系统临时目录下创建一个唯一目录并打印其绝对路径；若可信操作者显式传入输出目录，该目录必须尚不存在且父目录已经存在。默认 `mktemp` 路径最安全；显式路径的父目录符号链接、共享目录和并发替换不属于不可信输入防护承诺。这样可以观察真实容器、码流、时间戳和滤镜行为，同时把副作用限制在可辨认的小目录内。

> [!info] 本机验证快照
> 2026-09-03 在 macOS arm64 上使用 Homebrew `ffmpeg 9.0.1`、`ffprobe 9.0.1` 完成 Bash 语法检查和全部四个默认小样运行。编码器包括 `libx264`、原生 AAC、FFV1 与 PCM。版本、编译选项和编码器可用性会变化，复现实验时先运行 `ffmpeg -version`、`ffprobe -version` 和 `ffmpeg -encoders`；此处快照不是其他主机的兼容性保证。

## 安全边界

- 脚本以 `set -euo pipefail` 启动；所有产生持久媒体输出的 FFmpeg 命令使用 `-nostdin -n`，任一关键命令失败就停止，`-n` 明确拒绝覆盖。第 2 个实验的指标计算只写入 null muxer，使用 `-nostdin` 而不需要 `-n`。
- 默认输入是硬编码的 `lavfi` 合成源。第 4 个实验才允许清单输入，并把协议、绝对路径、目录穿越、符号链接、过大文件和过多任务挡在编码前。
- 临时输出不会被 Git 跟踪；它们也不会自动删除，便于先检查再按脚本打印的精确绝对路径清理。显式输出位置只供可信操作者使用；不要传入 Vault 根目录、家目录、`/`、父目录不可信或多人并发写入的位置。
- 解码器仍是复杂的原生解析器。文件名、大小与协议白名单只能缩小攻击面，不能替代隔离进程、CPU/内存/磁盘/时限、补丁管理和生产沙箱。

## 统一运行方式

在本目录执行：

```bash
bash -n ./*.sh
bash ./01_generate_probe.sh
bash ./02_transcode_compare.sh
bash ./03_filtergraph_sync.sh
bash ./04_batch_manifest.sh
```

退出码 `77` 只表示 PATH 中缺少 `ffmpeg` 或 `ffprobe`，应记录为环境 `SKIP`，不能写成实验通过。其他非零退出码表示输入、输出边界或处理步骤失败，应阅读错误而不是追加覆盖选项。

## 完成标准与恢复

- [ ] 能从 JSON 指出视频/音频流、codec、time base、duration 与容器格式；
- [ ] 能解释 remux 为什么通常不改变码流，transcode 为什么会改变像素/样本与质量；
- [ ] 能画出第 3 个实验的带标签 filtergraph，并区分 PTS 修正与“自动理解正确同步点”；
- [ ] 能说明第 4 个实验挡住了哪些字符串和文件系统风险，以及哪些生产风险仍需沙箱；
- [ ] 所有输出只位于脚本打印的临时绝对目录，且没有下载、联网或覆盖用户文件。

恢复时先打开输出目录并核对 `.lab-marker` 内容以及本次终端打印的绝对路径。只删除该次唯一临时目录；若路径记录丢失、标记不符或目录出现额外文件，停止自动清理，改为人工检查。脚本不修改 FFmpeg 配置、系统软件或 Vault 内容。
