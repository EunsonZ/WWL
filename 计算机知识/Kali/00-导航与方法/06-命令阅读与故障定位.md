# 命令阅读与故障定位

**先修关系：** [[计算机知识/Kali/01-系统与网络基础/04-Shell文件权限与文本处理|Shell文件权限与文本处理]]。

## 命令先经过Shell，再到程序

以 `nmap -sT -p 8000 127.0.0.1` 为例：Shell先拆词、展开变量和重定向，随后启动nmap；nmap再解释参数。引号保护的是Shell层，不能自动保护SQL、正则、URL或另一个解释器。Shell基础的完整说明只放在 [[计算机知识/Kali/01-系统与网络基础/04-Shell文件权限与文本处理|权威章节]]，这里用于诊断。

代码块中的 `$`若只是终端提示符不要复制；本包多数命令省略提示符。反斜杠续行必须是行尾最后字符。`<TARGET>`一类尖括号在Shell中可能被当成重定向，本包尽量使用明确的示例值，并将需要替换的整行注释掉。

## 运行前的四项检查

确认当前目录与路径；确认程序实际存在及版本；确认身份和最低必要权限；确认网络目标、输出位置、超时和停止条件。比如：

```bash
pwd
id
command -v nmap
nmap --version
```

程序不存在时先记录环境缺失，不接着尝试网上随机同名脚本。发行版包名不一定等于可执行文件名，见 [[计算机知识/Kali/01-系统与网络基础/03-APT软件源与Python环境|APT与环境]]。帮助网页中的历史截图也不等于本机接口。

## 标准输出、标准错误和退出状态

```bash
# 仅示例：先按实验A手动开启回环服务。
curl --noproxy '*' --connect-timeout 2 --max-time 5 \
  http://127.0.0.1:8000/health \
  > "$HOME/kali-lab/output/health.body" \
  2> "$HOME/kali-lab/output/health.stderr"
rc=$?
printf 'curl exit=%s\n' "$rc"
```

退出状态必须紧接目标命令保存；先执行`echo`或`ls`再看`$?`会得到另一个命令的状态。curl默认可能在HTTP404时仍退出0，因为传输成功与业务成功不同；是否需要 `--fail-with-body`要按当前版本与实验目标决定。不能把单一退出码定义成所有安全测试的“通过”。[^s1]

输出重定向会覆盖同名文件；真实实验使用新的前缀或自行启用合适的防覆盖策略。管道默认可能只反映末尾命令状态，Bash `pipefail`也不是全部错误处理的替代；结合 [[计算机知识/Kali/01-系统与网络基础/08-BashPython与可复核自动化|可复核自动化]] 阅读。

## 一张按层排查的表

| 现象 | 优先核对 | 不应立刻得出的结论 |
| --- | --- | --- |
| command not found | PATH、包名、虚拟环境 | “这个工具已停用” |
| Permission denied | 文件权限、执行位、挂载选项、身份 | “必须整段sudo” |
| Connection refused | 目标地址、监听端口、拒绝策略 | “目标主机不存在” |
| Timeout | 路由、代理、过滤、服务处理、超时阶段 | “没有漏洞” |
| 空文件 | 退出码、stderr、输入匹配、缓存/过滤 | “全部安全” |
| 参数不识别 | 实际版本、本地help、大小写 | “删掉安全参数继续跑” |

## 代理、秘密和清理

回环请求不应因环境代理意外出网，直连示例可用 `--noproxy '*'`；有意通过Burp/ZAP时则显式指定本机代理并记录。真实口令、Cookie、令牌不要进入命令历史或分享日志；优先按工具支持的受控输入渠道处理，不把玩具明文示例迁移到真实账户。

最后停掉自己启动的服务，恢复自己的代理，检查输出文件与预期一致。自动化的成功是“命令、输入、状态和结论相互一致”，不只是终端没有红字。
