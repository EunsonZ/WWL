训练不是“把文本喂给显卡”这一条命令，而是一条可以逐段验证的生产线：先证明数据有权使用且没有污染，再把文本稳定地变成 token；随后让模型按明确目标更新参数、保存完整状态；最后才根据任务、显存与风险选择全量微调、LoRA、偏好优化或分布式扩展。

本模块面向会写基础程序、掌握高中代数的读者。数学定义和推导不在这里复制；遇到损失、梯度、优化、低秩或量化时，先进入对应数学权威页，再回来解释它在训练系统中的角色。

## 全景直觉：训练是一组受约束的状态转移

模型不是把语料“存进一个文件”，而是在一批批 token 上计算误差，用梯度改变参数，并把足以继续这段过程的状态保存下来。数据决定可以学到什么，目标决定鼓励什么行为，参数化方法决定哪些权重能改变，并行策略决定状态和计算放在哪里，治理则决定这条链是否有权运行、能否审计和应当何时停止。

## 本模块完成后你能做什么

- 画出从数据权属、清洗、去重、切分、tokenization、packing 到预训练的完整流程；
- 区分 micro-batch、梯度累积、optimizer step、epoch、checkpoint 与 resume；
- 根据任务选择全量 SFT、LoRA 或 QLoRA，并解释 4-bit 基座与优化器状态分别占什么资源；
- 区分 data、tensor、pipeline parallel，以及 FSDP、DeepSpeed、Megatron 各自解决的层次；
- 设计能发现数据污染与评测泄漏、但不会把“未检出”冒充“绝对没有”的治理记录；
- 从权重、梯度、优化器状态、激活、通信和 checkpoint 六个账本估算训练成本。

## 六个容易混淆的精确定义

1. **预训练（pretraining）**：从随机初始化或既有权重出发，在大规模通用或领域语料上优化自监督目标；本模块主线是自回归 next-token NLL。
2. **持续预训练（continued pretraining）**：从已有预训练权重继续使用自监督目标训练，常用于领域适配；它仍不是 SFT。
3. **监督微调（SFT）**：用输入—目标输出或多轮对话样本，让指定 token 的监督损失更新模型。
4. **参数高效微调（PEFT）**：只训练全部参数中的一小部分或新增的小模块；LoRA 是 PEFT 的一种，不是 PEFT 的同义词。
5. **偏好优化**：用排序、偏好对或奖励信号改变候选回答的相对倾向；它与“给出唯一参考答案”的 SFT 目标不同。
6. **模型编辑**：针对较局部的知识、行为或内部方向做定向改变；编辑成功不自动代表总体能力、安全与合规改善。

> [!important] 名称不决定证据
> “预训练”“对齐”“指令微调”是过程类别，不证明数据合法、结果无污染、模型安全或产品可用。每次实验都要保存输入、配置、基线、评测和未验证项。

## 一条完整训练流程

以下是流程定义，不是可执行命令：

```text
权利与来源登记
  -> 原始快照与哈希
  -> 解码、格式和质量清洗
  -> PII/secret 风险处置
  -> 文档级精确/近似去重
  -> 先冻结验证与测试集合，再排除重叠
  -> 只用训练数据拟合 tokenizer
  -> tokenize、加边界标记、packing 与 mask
  -> 小 batch 过拟合测试
  -> 微型预训练/SFT 基线
  -> 定期 full-state checkpoint 与恢复演练
  -> 独立评测、污染复核、模型卡与训练记录
  -> 按许可和风险决定是否保存、合并、分发或删除
```

每个箭头都要有输入、输出、版本、统计、失败处理和恢复方法。只记录最终模型而不记录这些中间状态，无法说明模型到底学了什么，也很难复现实验。

## 统一成本模型

先用符号建立账本：

- $N$：用于近似的参数数，必须说明是否按常见口径排除 embedding；$T_{processed}$：实际送入模型并由底层 kernel 处理的 token 位置数；
- $T_{loss}$：loss mask 后真正参与监督和 loss normalization 的 token 数，通常满足 $T_{loss}\le T_{processed}$；
- $S$：序列长度；$B_\mu$：每个 data-parallel rank 的 micro-batch 序列数；
- $A$：梯度累积次数；$D$：data-parallel 副本数；
- $b_w,b_g,b_o$：每个参数的权重、梯度、优化器状态字节数；
- $M_{act}$：激活及其临时缓冲，依赖 batch、序列长度、层数、隐藏维和 checkpointing 策略。

每次全局 optimizer step 处理的序列数近似为

$$
B_{global}=B_\mu\times A\times D,
$$

固定 shape 的 dense 实现中，每步处理位置上限近似为 $T_{processed,step}=B_{global}S$；实际 $T_{loss,step}$ 要对 loss mask 求和。二者不能共用“有效 token”这个模糊名字：assistant-only、prefix mask 或忽略 PAD label 会减少 $T_{loss}$，却通常仍让这些 prompt/PAD 位置参加 embedding、attention、MLP 等 dense 计算。只有实现真的使用 unpadding、packed/varlen kernel、block-sparse 计算或减少了提交给模型的序列位置，才会相应减少 $T_{processed}$。

显存至少要分别记

$$
M\approx N(b_w+b_g+b_o)+M_{act}+M_{buffer}.
$$

这只是分项框架，不是硬件保证：混合精度主权重、参数共享、量化元数据、分片、临时 all-gather、通信 bucket 和 allocator 碎片都会改变实测。dense Transformer 全参数预训练常用约 $6N T_{processed}$ FLOPs 作量级估算；这里不能把 $T_{loss}$ 代入硬件成本公式。训练目标、LoRA/冻结参数、激活重计算、架构、序列长度、稀疏专家和具体 kernel 都会使常数或口径偏离，预算与采购必须以固定实现的短跑实测为准。

## 怎样选择训练方法

| 目标与约束 | 第一候选 | 先排除的误解 |
| --- | --- | --- |
| 从零学习语言分布并理解完整链路 | 微型预训练 | 小模型实验不能外推成前沿模型成本或能力 |
| 让已有模型稳定遵循一类输入输出格式 | SFT | 格式学会了不等于事实正确或安全 |
| 显存有限、需要保留多个任务版本 | LoRA | adapter 小，不代表激活和基座显存消失 |
| 基座权重本身也放不下常规精度 | QLoRA | 4-bit 通常指冻结基座存储，不是把全部训练状态变成 4-bit |
| 偏好排序而不是唯一参考答案 | 偏好优化 | 先验证数据、监督信号、基线与独立评测；是否独立先跑 SFT 取决于方法和初始化，见 [[AI/20-LLM/30-训练/04-偏好优化RLHF-DPO-ORPO与KTO\|ORPO 的单目标说明]] |
| 单设备放不下 optimizer state | FSDP/ZeRO 类分片 | 分片不自动减少激活，也会增加通信和恢复复杂度 |
| 单层矩阵或整模型仍放不下一台设备 | tensor/pipeline parallel | 更多设备可能被通信和 pipeline bubble 抵消 |

## 贯穿例子：先选最小足够方案

任务：用 200 条有明确训练权利的人工审校样本，让一个单卡可加载的基础模型把自然语言字段转成固定 JSON。先按模板家族分成 160/20/20，冻结 dev/test，并扫描与训练集的精确和近似重叠。

由于目标是有限的输出格式改变，不需要从零预训练；基础模型按常规精度能放进单卡，也不需要 QLoRA 或分布式。第一候选是 assistant-only SFT + 小 rank LoRA。若 $B_\mu=2$、$A=4$、$D=1$、$S=256$，固定 shape dense 实现每个 optimizer step 最多处理 $T_{processed}=2\times4\times1\times256=2,048$ 个位置；实际 $T_{loss}$ 仍以 loss mask 求和。assistant-only 只改变监督分母，不会自动省去 prompt token 的前向/反向依赖计算。

训练前记录 base、tokenizer 和未微调基线；先过拟合 8 条样本，再做短跑和恢复测试。checkpoint 保存 adapter、optimizer/scheduler、RNG、数据游标与 base identity，而不是重复保存一个来源不明的基座。最终只在冻结的 20 条 test 上做一次验收，并报告 JSON 有效率、数值正确率、回归、污染命中和未验证项。

这个例子展示了选择顺序：**目标 → 数据隔离 → 最小训练自由度 → 资源实测 → 可恢复性 → 独立评测**，而不是看到某个工具名就先安装整套栈。

## 工具与版本边界

训练框架、CUDA 组合、Unsloth、LLaMA-Factory、FSDP、DeepSpeed、Megatron 和 4-bit 加载接口都会变化。本模块只讲稳定职责与验证方法；实际命令、参数名、支持模型和兼容矩阵必须在操作当天从 [[AI/90-资源/05-官方资料与版本核验记录|官方资料与版本核验记录]] 进入官方来源，并固定 release、commit、模型 revision、Python/框架/驱动与硬件。

“官方文档写支持”不是本机验证；“训练跑完”也不是质量、隐私、安全、许可证或可复现性证明。

## 安全、许可与资源总边界

- **数据**：不得把私有聊天、账号数据、secret、未获授权的个人信息或受限制材料直接送入训练；哈希不是匿名化证明。
- **模型**：基础权重、tokenizer、adapter、合并权重和导出格式要分别核对许可、可接受使用政策和再分发条件。
- **工具**：代码许可证与模型/数据许可证相互独立；使用某个开源训练器不会自动获得训练数据或权重的权利。
- **资源**：先做 CPU/单卡、小数据、短步数的可恢复验证；设置时间、显存、磁盘、网络与费用上限，保留停止条件。
- **外部系统**：不要默认上传数据、模型、日志或遥测；共享集群上的 checkpoint、缓存和日志也可能泄露样本。
- **结果**：训练损失下降只证明优化目标在已见数据上下降；必须另测验证集、污染、稳健性、偏差与任务风险。

## 综合练习

给出一个假想任务：“用 1,000 条团队内部问答让一个开放权重模型回答产品问题，只有一张显卡。”写一页训练卡，至少包含：

1. 数据来源、授权、PII/secret 检查和 train/dev/test 切分单位；
2. SFT/LoRA/QLoRA 三选一及原因；
3. $B_\mu,A,D,S$、每步 $T_{processed}$ 与 $T_{loss}$ 的分别计算，并说明哪一个进入 FLOPs 量级估算；
4. checkpoint 必须保存的状态和一次恢复测试；
5. 与训练集隔离的评测，以及污染扫描和未验证项；
6. 基础模型、tokenizer、adapter 与数据各自的许可记录。

### 成功标准

- 能在一张图中标出数据、token、参数更新、checkpoint、评测与治理的边界；
- 不把预训练、SFT、PEFT、偏好优化和模型编辑混为一谈；
- 能用成本公式解释 batch、显存和训练步数，而不是只写“需要很多 GPU”；
- 能说明 loss mask 为什么会减少 $T_{loss}$ 却不一定减少 $T_{processed}$，并把 $6N T_{processed}$ 与 loss normalization 分账；
- 能指出至少三个“运行成功但结论仍不成立”的情况；
- 知道何时应停止训练并回到数据、许可或污染调查。
