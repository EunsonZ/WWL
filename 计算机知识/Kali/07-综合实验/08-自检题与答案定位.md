## 综合题：提出一个竞争解释

工具说“发现服务A”，手工访问得到服务B页面。至少提出三个竞争解释，并给每个解释一个最小区分测试：不同Host/虚拟主机、负载均衡、代理、指纹误判、版本更新等均可。好的回答会写出要改变的变量和保持不变的变量，而不是连续换工具碰碰运气。参照 [[计算机知识/Kali/00-导航与方法/04-从观察到结论的安全方法|证据方法]]。

## 综合题：从局部正确迁移到系统边界

`can_read('bob',17)` 返回 False，但HTTP导出端点仍能下载报告。说明离线函数测试为什么没有充分证明系统安全；列出至少一条可能未调用检查的路径，并设计包含合法访问的回归。参照 [[计算机知识/Kali/03-Web与API安全/08-认证会话越权与API测试|授权模型]] 与 [[计算机知识/Kali/07-综合实验/04-实验CWeb请求与访问控制|实验C]]。

## v2 迁移自检：条件改变以后，原结论还成立吗

**协议与测量。** 目标同时匹配 `/24` 和 `/27`，后者 metric 更大，先选谁？检查点：在本包单表模型中先比前缀长度，见 [[计算机知识/Kali/07-综合实验/10-实验G路由与扫描状态推理|G]]。TCP SYN 与 UDP 都无回应，是否同属 closed？不是，分别考虑 filtered 与 open/filtered 的观察语义。一次 XML 运行 success，但目标端口没在范围中，能否判定关闭？不能，见 [[计算机知识/Kali/07-综合实验/11-实验H扫描XML差异与不确定性|H]]。抓包过滤器没有保留某协议，输出为空能否否定它存在？不能，这是观察选择改变了样本。

**浏览器与身份。** 子域名跨 origin 却可能同 site，这会怎样影响 CORS 和 SameSite 的解释？前者涉及浏览器跨源访问，后者使用不同的站点边界；不能相互替代，见 [[计算机知识/Kali/03-Web与API安全/07-XSSCSRF与浏览器安全边界|浏览器专题]]。JWT 解码成功能否证明签名、发行方、受众和对象授权？均不能。reviewer 能读摘要为何仍看不到 private_note？对象读权限与字段投影不同，见 [[计算机知识/Kali/07-综合实验/12-实验I多租户字段与动作授权|I]]。

**配置与执行。** 修改服务文件后实际进程仍使用旧配置，配置扫描通过能否宣称修复生效？不能，需要运行状态和行为证据。数据库握手成功但 SELECT 被拒绝，是网络故障吗？不是同一层，见 [[计算机知识/Kali/04-服务身份与主机评估/09-数据库服务与最小权限审计|数据库权限]]。容器 YAML 写了非 root，是否等价于实际所有进程和集群权限都最小化？不等价，需核对准入、实际运行与角色策略。

**密码与检测。** 候选独立同分布和按真实高频顺序排序时，“平均一半搜索空间”是否都成立？不是，非均匀时应按猜测排名分布计算，见 [[计算机知识/Kali/05-密码无线与专门领域/01-哈希口令KDF与估算|口令估算]]。检出率 90% 能否直接推出告警大多正确？不能，还需要负类误报率及正类基率。没有告警时 precision 是 100% 吗？分母为零时未定义，见 [[计算机知识/Kali/07-综合实验/13-实验J时间线与检测基率|J]]。

**逆向与证据。** `icat` 的输出文件存在，是否证明导出成功？Shell 可先创建文件，必须结合退出码和 stderr。ASan 没报错能否证明所有输入安全？不能，只支持已执行路径及其检测范围。修复后拒绝所有文件是否通过功能合同？没有，合法空载荷和最大载荷仍须成功，见 [[计算机知识/Kali/06-取证逆向与检测/09-模糊测试Sanitizer与崩溃归因|有界解析]]。

作答时至少给出：原假设、改变的条件、目前证据、下一项最小补证。不要只写“取决于情况”；应明确具体条件和补证步骤。

## 理论联结自检：32 个可解释的判断

这些题只需要文字、集合关系和小规模手算，不要求新增程序、目标或主动操作。先写答案，再对照检查点。下面的数字均是各正文已经明示前提的原创教学模型，不是实际工具性能；来源仍以对应正文为准。

### 网络测量与单位

**Q01｜ACK 探测得到 unfiltered，而 SYN 探测得到 closed，为什么不一定矛盾？**

检查点：先写两种探测各支持的命题。ACK 反馈可支持该探测未被过滤，不证明端口有监听；SYN 收到 RST 可支持该条件下关闭。不要把 unfiltered 翻译成 open。 定位：[[计算机知识/Kali/02-信息收集与网络测量/03-Nmap主机发现与端口状态#两种模式得出不同标签，为什么不一定互相矛盾|机制与推演]]。

**Q02｜应用写入已被 TCP 确认，可以向用户宣布数据库事务提交成功吗？**

检查点：不能。ACK 的对象是 TCP 序号空间中的接收位置；业务解析、授权、持久化和事务提交在更高层，需要对应层的证据。 定位：[[计算机知识/Kali/01-系统与网络基础/06-TCPIP路由DNS与TLS#从字节到业务动作：每层确认的对象不同|机制与推演]]。

**Q03｜往返时延 40 ms、目标吞吐 100 Mbit/s，所需在途量约多少？若窗口只有 128 KiB 呢？**

检查点：量纲先换成字节和秒：100×10⁶×0.04÷8 = 500,000 B；128×1024×8÷0.04 ≈ 26.2 Mbit/s。后者只是窗口约束的理想上界，尚未扣除其他瓶颈。 定位：[[计算机知识/Kali/01-系统与网络基础/06-TCPIP路由DNS与TLS#把窗口、时延与吞吐放进同一张量纲表|机制与推演]]。

**Q04｜移除显示过滤器后仍找不到某段通信，可以断定它没有发生吗？**

检查点：还要区分是否被捕获过滤器排除、观察点是否经过流量、是否丢包，以及解密、重组和协议解析是否具备条件。显示过滤器只能隐藏已经保留的材料。 定位：[[计算机知识/Kali/02-信息收集与网络测量/05-WiresharkTcpdump与Tshark#捕获、重组、解析、显示是四道不同的门|机制与推演]]。

### HTTP 与工具实验设计

**Q05｜两个子域名处于同一站点，能否推出它们同源并可任意读彼此响应？**

检查点：不能。origin 与 site 的构成不同；还要分开浏览器读取规则、是否附带凭据与服务器业务授权。应给出跨 origin 但同 site 的例子。 定位：[[计算机知识/Kali/01-系统与网络基础/07-HTTP浏览器会话与信任边界#同源、同站、凭据与授权：四道不同的判断|机制与推演]]。

**Q06｜租户 A 与 B 各有报告 17，缓存只按路径编号建键，即使源站授权正确仍缺什么？**

检查点：缓存把两种本不应共享的请求视为同一类；需分析缓存是否允许存储/共享、哪些身份或租户条件影响复用，以及响应生成位置。不能只以缓存新鲜度合格作答。 定位：[[计算机知识/Kali/03-Web与API安全/13-HTTP中间层与消息解释#缓存键是对请求划分等价类|机制与推演]]。

**Q07｜两个位置分别有 3 与 4 个候选；单载荷集模式使用公共的 3 项集合。四种 Intruder 模式的请求数为何不同？**

检查点：在正文给定输入设计下分别为 6、3、3、12。必须先重述 Sniper/Battering ram/Pitchfork/Cluster bomb 的载荷集安排；数字不是无条件公式，也不是本轮工具运行记录。 定位：[[计算机知识/Kali/03-Web与API安全/03-BurpSuite工作流#Intruder的组合模式其实是四种实验设计|机制与推演]]。

**Q08｜20 个相互独立检验，每个显著性水平 0.05，至少一次误拒真的概率约多少？这能直接等同 Sequencer 实现吗？**

检查点：原创独立模型中为 1−0.95²⁰≈64.2%。该计算解释多重检验，不声称工具采用这 20 个独立检验；统计未拒绝随机性也不证明预测攻击不可能。 定位：[[计算机知识/Kali/03-Web与API安全/03-BurpSuite工作流#Sequencer：统计上未发现规律，不等于无法预测|机制与推演]]。

### 认证、授权与状态

**Q09｜ID token 可以被任意 API 当作 access token 接受吗？**

检查点：不能仅凭格式与签名判断。先说明接收者、用途、发行方、受众和应用允许的类型，再检查权限；OIDC 的身份断言与资源访问凭证职责不同。 定位：[[计算机知识/Kali/03-Web与API安全/08-认证会话越权与API测试#OAuth与OIDC：先分清谁接收哪种凭证|机制与推演]]。

**Q10｜Kerberos 票据与认证器为什么不是同一种凭证？只检查时间戳还缺什么？**

检查点：票据封装给服务的会话材料；认证器体现当前请求者持有会话材料。时间窗内仍可能重放，所以还要理解重放缓存及相应协议条件。 定位：[[计算机知识/Kali/04-服务身份与主机评估/03-LDAPKerberos与AD基础#票据是给服务看的封装，认证器证明当前使用者持有会话材料|机制与推演]]。

**Q11｜权限图中边 A 有效期为 [1,2]，边 B 为 [3,4]，静态连通能证明两步在同一时刻可执行吗？**

检查点：不能，两条件交集为空。要区分关系图、同时成立的前提，以及允许状态随步骤变化时的状态转移模型；这里只否定同时有效，不否定所有可能的顺序历史。 定位：[[计算机知识/Kali/04-服务身份与主机评估/05-BloodHound权限图与修复验证#关系图与状态转移图：箭头连得上还需要条件同时成立|机制与推演]]。

**Q12｜请求 R={read,write}，模型 DACL 先允许 read、再拒绝 write，为什么不能因某项允许就接受整个请求？**

检查点：按正文限定的普通访问检查模型跟踪尚未满足的权利集合；允许 read 后仍缺 write，后续匹配拒绝使请求失败。不要把该教学模型推广成所有 Windows 特权与对象规则。 定位：[[计算机知识/Kali/04-服务身份与主机评估/08-Windows权限边界与本机审计#用请求权利集合逐步读DACL|机制与推演]]。

### 查询、解析与业务执行

**Q13｜所有查询都参数化以后，为什么报告查询仍可能越权？**

检查点：参数化约束数据的语法角色；对象所有权、租户、字段与动作权限仍需单独实现。需给出“语法安全但权限条件缺失”的解释，而非构造注入载荷。 定位：[[计算机知识/Kali/03-Web与API安全/06-SQL注入原理与sqlmap限界验证#参数化固定的是语法角色，不是自动完成所有业务约束|机制与推演]]。

**Q14｜对一个 HTML 上下文正确的编码，能否直接复用到脚本或 URL 接收点？**

检查点：不能。先标明解释器与上下文，再区分编码、HTML 清洗和安全接收点；变换后的输出若又进入不同解释器，必须分析新的边界。 定位：[[计算机知识/Kali/03-Web与API安全/07-XSSCSRF与浏览器安全边界#编码、清洗与安全接收点的职责不同|机制与推演]]。

**Q15｜GraphQL 请求深度相同，扇出改变为何可能使示意成本从 211 变成 2101？**

检查点：按正文给定层级逐层计算 1+10+10×20 与 1+100+100×20。成本模型只计示意节点，不能自动等同 CPU 时间、数据库次数或真实计费。 定位：[[计算机知识/Kali/03-Web与API安全/12-现代API业务逻辑与并发边界#GraphQL成本：深度相同，工作量也可能相差很大|机制与推演]]。

**Q16｜请求结果可重放、业务效果幂等、消息恰好交付一次，为什么不能写成一句“没有重复”？**

检查点：分别界定响应合同、状态效果与传输次数；第一次已经提交而响应丢失时，重试可能产生多个消息，却仍应保持约定效果。外部副作用还需要自己的合同。 定位：[[计算机知识/Kali/03-Web与API安全/12-现代API业务逻辑与并发边界#幂等效果、消息交付与响应重放不是同一个保证|机制与推演]]。

### 口令与无线观察

**Q17｜概率分布为 (0.7,0.1,0.1,0.1)，按概率排序后两次猜测的成功率与平均猜测次数分别多少？**

检查点：前两项相加为 0.8；平均排名为 1×0.7+2×0.1+3×0.1+4×0.1=1.6。香农熵约 1.357 bit，最小熵约 0.515 bit，二者不等于平均猜测次数。 定位：[[计算机知识/Kali/05-密码无线与专门领域/01-哈希口令KDF与估算#三种熵回答三个不同问题|机制与推演]]。

**Q18｜Argon2 的 m=65536 KiB、p=4，是否意味着每实例占 256 MiB？**

检查点：正文参数语义中的 m 为总内存成本，约 64 MiB，不直接乘 p。2 GiB÷64 MiB=32 只是忽略额外开销的内存并发上界，不是吞吐保证。 定位：[[计算机知识/Kali/05-密码无线与专门领域/01-哈希口令KDF与估算#Argon2的m、t、p：内存、遍数与并行通道不能互换|机制与推演]]。

**Q19｜简化模型中每次机会捕获概率 q=0.1，20 次独立机会至少捕获一次约多少？固定跳频能否照用？**

检查点：1−(1−q)²⁰≈87.84%。固定周期与固定发射相位可能相关，甚至持续错开；独立性与机会定义不成立时，不应套公式宣称覆盖率。 定位：[[计算机知识/Kali/05-密码无线与专门领域/05-KismetBluetooth与无线风险#用驻留概率解释漏采，而不是只看跳频速度|机制与推演]]。

**Q20｜接收功率从 −55 dBm 到 −45 dBm，是距离缩短十倍吗？**

检查点：功率差为 10 dB，对应接收功率十倍。距离还依赖传播模型、遮挡、天线等条件；不能把功率比直接转换成距离比。 定位：[[计算机知识/Kali/05-密码无线与专门领域/05-KismetBluetooth与无线风险#dBm是功率比的对数，不是距离|机制与推演]]。

### 证据与重建

**Q21｜两份材料 SHA-256 相同，能否严格证明字节相同并且采集没有遗漏？**

检查点：有限长度摘要不是数学上的单射；常规比较下提供强一致性证据，但碰撞、来源、采集覆盖和记录真实性是不同问题。不能用摘要替代采集完整性证明。 定位：[[计算机知识/Kali/06-取证逆向与检测/01-取证流程镜像与时间线#哈希的三种保证不能混在一起|机制与推演]]。

**Q22｜同一时钟的共同偏差很大，为什么两个事件间隔仍可能估得较准？**

检查点：写出 t_obs=t_true+b+e；同一稳定 b 在差值中消去，剩余相对误差。若来自不同时钟或 b 随时间漂移，就不能无条件消去。 定位：[[计算机知识/Kali/06-取证逆向与检测/01-取证流程镜像与时间线#同一时钟的共同偏差，为什么可能在相减时消失|机制与推演]]。

**Q23｜文件系统列出的已删除名字与 carving 的输出无法一一对应，必须有一个工具错了吗？**

检查点：不一定。前者依赖目录和元数据关系，后者依赖内容特征；删除、碎片、覆盖和元数据缺失会使它们保留不同信息。先比较恢复对象和前提。 定位：[[计算机知识/Kali/06-取证逆向与检测/02-SleuthKitAutopsy与文件恢复#文件系统恢复与 carving 为什么会给出不同答案|机制与推演]]。

**Q24｜psscan 命中而 pslist 未列出的候选，能直接认定为隐藏恶意进程吗？**

检查点：不能；检查活动链、残留结构、采集一致性、候选有效性与符号前提，关联地址、创建/退出时间等。PID 相同也不自动等于同一进程实例。 定位：[[计算机知识/Kali/06-取证逆向与检测/03-Volatility3与内存证据#pslist 与 psscan 的差集是待解释集合|机制与推演]]。

### 逆向与错误判据

**Q25｜控制流两分支各定义 3 和 7，SSA 的合流为何不是 10？**

检查点：合流节点选择与实际前驱对应的版本，不做算术求和；还应指出原始指令、分析中间表示与反编译伪代码并非同一表示层。 定位：[[计算机知识/Kali/06-取证逆向与检测/05-GhidraRadare2与静态逆向#SSA 的合流不是把两个分支的值相加|机制与推演]]。

**Q26｜8 位模式 0xFF 与数值 1 比较，改变有符号解释可能怎样影响判断？**

检查点：解释为无符号数是 255，为有符号二补码是 −1；小于 1 的判断不同。真实程序还要核对指令、位宽、扩展及语言转换规则。 定位：[[计算机知识/Kali/06-取证逆向与检测/05-GhidraRadare2与静态逆向#位模式的数值解释会改变比较结果|机制与推演]]。

**Q27｜strace 先显示 unfinished，随后显示 resumed，第一行是不是调用失败？**

检查点：不是，仅凭 unfinished 不能下失败结论；要关联恢复输出和返回值。再区分接口返回值、应用处理分支与业务最终状态。 定位：[[计算机知识/Kali/06-取证逆向与检测/06-GDBGefStrace与动态观察#为什么 unfinished 不是一次失败调用|机制与推演]]。

**Q28｜模糊器覆盖率提高且 ASan 不报错，能否证明逻辑正确？**

检查点：不能。区分搜索策略、覆盖反馈与错误判据；覆盖某路径不代表所有输入语义正确，ASan/UBSan 的检查类别也不相同。 定位：[[计算机知识/Kali/06-取证逆向与检测/09-模糊测试Sanitizer与崩溃归因#搜索策略、覆盖反馈与错误判据是三个部件|机制与推演]]。

### 检测、版本与风险

**Q29｜相同字符串出现在原始文件、解压内容和 HTTP 规范化缓冲区中，匹配为何仍可能不同？**

检查点：规则作用于指定对象和表示；压缩、解码、规范化、分段、范围和引擎设置会改变可见输入。必须报告扫描对象，而不只报告规则名称。 定位：[[计算机知识/Kali/06-取证逆向与检测/07-YARA日志与检测规则#一条规则的完整含义包含扫描对象|机制与推演]]。

**Q30｜Metasploit check 返回 Safe，与 Unknown、Detected、Vulnerable 能否排成通用安全分数？**

检查点：不能。这些是带具体模块语义和条件的命题；Safe 还可能涉及未检测到目标，Unknown 是未能判断，Detected 不等于已证实漏洞。先审阅模块检查逻辑。 定位：[[计算机知识/Kali/04-服务身份与主机评估/06-SearchsploitMetasploit与漏洞验证#工具结果状态是一组不同命题，不是一条安全分数轴|机制与推演]]。

**Q31｜两个镜像摘要不同、漏洞数相同，或签名验证成功，可推出相同风险吗？**

检查点：均不能。先对齐物料、来源、版本/回移补丁、漏洞知识库与实际部署条件；摘要支持对象辨识，签名支持特定信任关系，二者都不替代安全审查。 定位：[[计算机知识/Kali/05-密码无线与专门领域/06-容器Kubernetes与IaC审计#SBOM到漏洞结论之间有四次匹配|机制与推演]]。

**Q32｜30 次独立同条件机会零发现，在简化模型下 p 的单侧 95% 上界为何约 9.50%，而不是零？**

检查点：令 (1−p)³⁰=0.05，解得 1−0.05^(1/30)≈0.0950。必须先定义一次机会、检测成功率与独立同分布条件；不完整扫描不能直接成为这 30 次试验。 定位：[[计算机知识/Kali/00-导航与方法/04-从观察到结论的安全方法#零次发现能支持多强的阴性结论|机制与推演]]。

### 一次合格作答包含什么

明确原命题、关键对象、必要前提、中间推理和结论范围；再改变一个前提，说明答案哪一步失效。只回答“不能保证”不够，至少解释一种能区分竞争解释的观察。数字相同但条件不同也不能算作正确迁移。
