# PyTorch 张量：形状之外还有存储

<!-- deep-review-02 -->
> [!tip] 本轮深化：从当前概念继续追问
> 逻辑形状、物理布局和计算成本是三层问题。view/reshape 能否共享存储以及隐式拷贝，可能影响内存；先明确语义轴，再谈布局优化。 深化与验证：[[AI/00-开始/06-统一符号形状与公式阅读方法|统一符号形状与公式阅读方法]]；[[AI/12-PyTorch/09-性能剖析编译动态形状与内存账本|性能剖析编译动态形状与内存账本]]。


一个张量不仅是多维数组。读代码时至少同时问：每根轴代表什么、元素怎样存在内存、用什么数值类型、在哪台设备上。四者任何一个混淆，都可能让“跑得通”变成“算错了”。

## 从地址理解 stride

连续的 `x.shape == (2, 3)` 通常有 `x.stride() == (3, 1)`：第一轴移动一次跨过三个元素，第二轴移动一次跨过一个。转置会改变查看同一存储的方法，不必搬动数据。于是一个张量的 shape 正确，不代表它的内存布局可直接被所有算子接受。

```python
import torch
x = torch.arange(6).reshape(2, 3)
y = x.transpose(0, 1)
assert y.shape == (3, 2)
assert not y.is_contiguous()
z = y.reshape(-1)  # 必要时复制；不要假设一定共享存储
assert z.tolist() == [0, 3, 1, 4, 2, 5]
```

`view` 需要兼容的 stride；`reshape` 可以复制来满足请求。`contiguous()` 保证所选内存格式连续，但不是“所有计算之前都调用”的免费操作。基础切片经常返回视图，高级索引通常返回新张量；修改共享存储时要特别小心。

## 广播检查轴，不检查语义

广播从最后一轴对齐，两个维度相等或其中一个为 1 才可兼容。`(B, C)` 加 `(C,)` 表示给每个类别加偏置。但 `(B, 1)` 减 `(B,)` 会产生 `(B, B)`，不是每个样本的误差。

```python
pred = torch.zeros(4, 1)
target = torch.arange(4.0)
assert (pred - target).shape == (4, 4)  # 静默错误示例
correct = pred.squeeze(-1) - target
assert correct.shape == (4,)
```

因此损失之前最好断言预测和标签的任务 shape。不要无条件 `squeeze()`：batch 恰好为 1 时，它也会删掉 batch 轴。

## dtype 与 device 的真正边界

类别标签通常是整数索引，交叉熵常用 `torch.long`；模型特征和权重通常是浮点。`float16` 和 `bfloat16` 的范围与有效精度不同，不能只因都占两字节就互换。`.to(device)` 一般返回转移后的对象，写成 `x.to(device)` 却继续用旧 `x` 可能没有达到预期。

Embedding 的输入 ID 不是连续可优化变量。需要解释输入敏感性时，一般对 embedding 或连续输入求梯度，而不是把 token ID 当实数坐标微分。

NumPy 与 CPU 张量可能共享存储，进入训练前要确认原数组之后是否会改变。跨 CPU/GPU 传输以及 GPU 结果 `.item()` 都可能引入同步；训练每一层打印标量会改变性能。异步拷贝是否真正重叠，还取决于固定页内存、流和硬件条件。

## 三份形状合同

图像常用 `[B,C,H,W]`，文本隐藏状态常用 `[B,T,D]`，分类 logits 常用 `[B,C]`。`nn.Linear(D,H)` 只变最后一轴，因此 `[B,T,D]` 可得到 `[B,T,H]`。矩阵乘法中的 batch 维会广播；`einsum` 可以更明确地写轴的配对，但仍需核查维度含义。

**练习：** 写出 `x.shape=(2,5,8)`、`w.shape=(8,3)`、`b.shape=(3,)` 时 `x @ w + b` 的形状，并解释参数为何对所有 token 共享。答案是 `(2,5,3)`，不是给十个 token 分别创建十套权重。
