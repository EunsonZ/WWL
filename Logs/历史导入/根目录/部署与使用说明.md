# 部署与使用说明

本包是“进一步审计＋Codex 改造交接”，不是已经改造完成的 Vault，也不是可覆盖原库的完整备份。

## 需要长期放在 Vault 根目录的文件

`AGENTS.md` 是长期契约。`CHANGE.md` 是临时执行单，现在必须一起使用。改造通过其删除门槛后，仅删除根 `CHANGE.md`，保留 `AGENTS.md`。

两份文件本身已包含执行所需的具体问题、路径、边界和验收条件；即使不把本报告和证据放入 Vault，也可以理解并执行主要任务。证据包用于复查，不是另一个规则权威。

## 先处理文件名冲突，不直接覆盖

原库根目录存在小写 `agents.md`。在 Windows 和部分 macOS 文件系统上，它可能与大写 `AGENTS.md` 被视为同一文件。不要把新文件直接拖进去后随手选择覆盖，也不要保留两个互相竞争的现行规则。

推荐把整个本包先解压到 Vault 外的临时交接目录，让 Codex 读取新文件和原根规则，再按 `CHANGE.md` 的 T00／T01 执行：备份旧内容与哈希，核查未提交修改，用唯一临时名完成大小写安全迁移，更新活跃引用，明确 `NewAgents.md` 和 `CONTRIBUTING.md` 的从属关系。备份留在本地，不分享带实际配置的原库副本。

如果已经安全部署两个新文件，应从 Vault 根目录启动新的 Codex 会话，确认实际加载的指令。不要假定工具会自动扫描任意祖先目录，也不要修改全局权限或 fallback 配置来掩盖入口问题。

可给 Codex 的启动消息如下；将“交接目录”替换为实际路径，不需要添加新的扩写目标：

```text
请先读取交接目录中的 AGENTS.md 和 CHANGE.md，以及当前 Vault 根目录的现有规则。
这两份新文件是本次获准采用的长期契约与临时改造单。
先按 T00/T01 保存现有改动并安全部署，特别处理 agents.md 与 AGENTS.md 的大小写冲突。
然后严格进入 REFACTOR_ONLY：不新增主题、课程或功能，先修正、深化并验证已有内容。
逐批执行 CHANGE.md，更新真实状态和证据；不运行未知脚本，不安装依赖或启动服务。
只有完成删除门槛后才删除根 CHANGE.md；之后仅按 AGENTS.md 和新的明确用户任务行事。
```

原快照含实际凭据，轮换需要用户在可信环境处理；本包没有执行该操作。Codex 可继续不依赖凭据的本地工作，但不能把尚未轮换标记成完成。

## 复核观察脚本

需要 Python 3.10 或更新版本，以及已经安装的 NumPy。脚本不会自动安装依赖。应先阅读脚本，并只在可信、受控本地环境运行。

在本包目录执行，两个路径替换为实际值，输出放在原 Vault 外：

```bash
python -B scripts/reproduce_round2.py \
  --vault "/path/to/original-vault" \
  --output "/path/to/outside-vault/round2-observations.json"
```

脚本在导入源文件前校验已审阅版本的 SHA-256；源码变化后应拒绝执行。这是保护措施，不应为了继续复现而随意修改钉住的哈希。它不会反序列化真实 checkpoint、启动 HTTP 服务或训练模型；LoRA 路径测试仅使用临时文件。

**退出码 0 只表示观察结果已记录，不表示知识库正确，更不表示修复已完成。** 修改后的正式验收必须把这些反例转成针对新合同的测试，而不能要求旧错误继续复现。

本轮新文件没有自动复制进你的真实 Obsidian，没有改写原课程，没有替你填写掌握度，也没有声称 UI 已通过。`CHANGE.md` 保持初始待执行状态是刻意的事实区分。
