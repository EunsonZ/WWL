# v3 深度审阅与变更记录

## 目标、输入与本轮边界

本轮响应“深度查漏补缺，进一步详细化”，以已交付 v2 ZIP 为基线，不从旧待办推导额外任务。原始维护契约保留于 [[计算机知识/Kali/90-来源与维护/附件/AGENTS-原始上传.txt|原始上传附件]]；该附件只约束组织、维护和验证，不是 Kali 技术内容的来源。实际提供的包与工作根目录没有 `CHANGE.md`。未访问用户本机 Vault，也没有用户在本地新增笔记的副本。

基线 ZIP SHA-256 为 `a47884d162581c4efc95eab75aed64c77bd95a33c5d72595a21acb1d8d8c555e`。所有改动发生在独立解压副本；不改动原 ZIP，不移动既有章节，不修改 Obsidian 配置，不安装依赖，不启动服务、网络扫描、无线采集或真实环境操作。旧源码、夹具与历史实验输出保留；当前来源账本按记录追加本轮核查范围。

本轮优先修复“工具输出 → 成立条件 → 可复核判断”之间的断点，补充真实失败反例、诊断分流、输入输出合同和中间推演。新增的 K、L 是原有 TLS、授权与业务状态章节的可执行证据，不是另起一套主题分类。

## 两个新增实验的合同

[[计算机知识/Kali/07-综合实验/14-实验K离线证书链与身份校验|实验 K]] 在受控临时目录生成证书与私钥，调用已安装 OpenSSL 验证证书路径，删除临时目录，仅保留状态、错误代码和证书摘要。没有真实 TLS 握手、服务监听、在线吊销查询或私钥导出。密钥和日期每次变化，不能拿两次证书摘要不同当成实验失败。

[[计算机知识/Kali/07-综合实验/15-实验L事务幂等与并发控制|实验 L]] 使用 Python 标准库 SQLite，在临时数据库中真实提交、回滚和锁冲突。模型 `transactions-v3.1` 复用 `reasoning-v2.0` 的初始对象定义，但每次从新数据库开始，不能把两个独立运行拼成一条对象历史。固定身份是教学设定，不实现认证；两连接固定交错不是性能压测、任意并发证明或分布式 exactly-once。

`.jq` 小型数据合同是独立源文件；正文引用命令，不维护第二份完整程序。新 CLI 检查覆盖该程序的正常与坏记录，另以标准库对正文中的算术和集合例子作独立复核。

## 有意义的失败与修复

**旧日志示例的反例。** 一条数组随后接一条合法对象，旧 `jq -e` 返回 0；交换记录顺序则返回 1。[[计算机知识/Kali/90-来源与维护/验证/revision-v3/jq-before-fix.json|修复前实际输出]]保留，新的整体合同及反例测试见 Shell 正文与 `test_cli_workflows.py`。

**本轮 TLS 检查器的自我修正。** 初稿把任何非零退出码当成负例成功。独立构造“选项错误”后，这个判定会错误放行；因此增加特定 X.509 错误代码、退出状态与结果形态的联合判断。保留 [[计算机知识/Kali/90-来源与维护/验证/revision-v3/tls-oracle-before-fix.json|修复前反例]] 与 [[计算机知识/Kali/90-来源与维护/验证/revision-v3/tls-v3-initial-source.txt|历史初稿快照]]。快照不是现行真源，当前实现是 `tls_verify_lab.py` 的 `tls-v3.1`。未识别的错误必须判失败，不能因为“本来希望拒绝”就予以通过。

**事务错误的同类反例。** 初始演示器会把任何 `OperationalError` 收入锁冲突结果。用独立注入的 `SQLITE_IOERR` 复现后，现行 `transactions-v3.1` 只接受实际 `SQLITE_BUSY`，缺少或不同的错误代码均使演示失败；测试也不再用预期代码填充缺失值。修复前的 `transaction-error-before-fix.txt`、初始源码快照和修复后 28 项事务测试保留。该实验明确需要 Python 3.11+ 的 SQLite 诊断属性。

**构建工具与导航。** 初始补丁遇到绝对路径不被应用及末尾换行断言不匹配；在限定范围恢复自己的部分修改后修正驱动器，未重置整库。中途静态检查发现 K/L 指向尚未建立的本页，随后建立真实维护入口。过程记录保留，不将中间失败文件改写为最终通过。具体范围见 `build-issues.json` 与 `intermediate-static.json`。

## 来源、教学与实验分开记账

官方资料的实际读取记入既有 `验证/sources.json` 的 `revision_v3_review`，旧来源账本按字节留存为 v2 快照。资料所支持的是接口、协议或机制；本包的小数字、合成请求、状态表和故障安排是原创教学。实际执行只证明所运行输入与环境中的输出，不给未运行工具背书。

本轮未重新读取的旧条目保留原记录，不补填新的“已核验”日期。对会变化的软件行为，正文给出所查分支或版本和定位；文档读取成功、语法可解析和程序运行通过分别记录。完整入口见 [[计算机知识/Kali/90-来源与维护/01-来源索引与核验边界|来源索引]]。

## 合并、回滚与后续复核

这是完整包，导入路径仍为 `Vault/计算机知识/Kali/`。不要把 `Kali/` 单独设为 Vault 根。已有个人改动时，先把 v3 解到新目录，按逐文件差异审阅后合并，不直接覆盖真实记录。

回滚点是原始 v2 ZIP。只回滚本轮变更，不能据此删除用户后来添加的材料。当前源码、夹具、来源与输出的关联发生变化时，需重跑相应测试，而不是把本次报告当成永久认证。后续优先在真实隔离 Kali 与 Obsidian 环境补验未运行项；这里没有替用户执行或预填这些结果。
