# 搜索语法速查表

> [!tip] 三种“找”不要混淆
> 已知笔记名：`Cmd/Ctrl + O` Quick Switcher。知道正文片段或条件：`Cmd/Ctrl + Shift + F` Search。不知道怎样执行动作：`Cmd/Ctrl + P` Command Palette。

## 组合规则

| 需求 | 查询 | 说明 |
| --- | --- | --- |
| 同时包含两个词 | `会议 决定` | 空格默认是 AND |
| 包含任意一个词 | `会议 OR 讨论` | `OR` 必须大写 |
| 精确短语 | `"下一步行动"` | 双引号保留词序和空格 |
| 排除一个词 | `会议 -周会` | `-` 紧贴要排除的表达式 |
| 控制优先级 | `会议 (项目A OR 项目B)` | 括号先计算 |
| 排除组合 | `会议 -(取消 草稿)` | 排除同时满足括号内容的结果 |
| 正则表达式 | `/\d{4}-\d{2}-\d{2}/` | JavaScript 风格正则；慎用宽泛表达式 |

### 容易写错

```text
会议 or 讨论       # 错：or 不是布尔运算符
会议 OR 讨论       # 对

"项目 A"          # 精确短语
-"项目 A"         # 排除精确短语

meeting -work      # 有 meeting 且没有 work
meeting -(work meetup) # 排除同时含 work 和 meetup 的结果
```

## 原生 Search 运算符

| 运算符 | 作用 | 示例 |
| --- | --- | --- |
| `file:` | 文件名；可匹配 Vault 中任何文件类型 | `file:.pdf`、`file:2026` |
| `path:` | 完整相对路径 | `path:"30-工作流"` |
| `content:` | 笔记/Canvas 正文内容 | `content:"核心观点"` |
| `match-case:` | 区分大小写 | `match-case:API` |
| `ignore-case:` | 忽略大小写 | `ignore-case:obsidian` |
| `tag:` | 标签，忽略代码块中的伪标签 | `tag:#status/inbox` |
| `line:` | 多个条件必须出现在同一行 | `line:(决定 负责人)` |
| `block:` | 多个条件必须出现在同一 Markdown 块 | `block:(来源 结论)` |
| `section:` | 多个条件在同一标题小节 | `section:(风险 缓解)` |
| `task:` | 任何任务项目 | `task:回顾` |
| `task-todo:` | 未完成任务 | `task-todo:整理` |
| `task-done:` | 已完成任务 | `task-done:发布` |

> [!info] 搜索范围
> 普通内容搜索主要索引 Markdown 笔记和 Canvas；需要按任意附件文件名/路径查找时，使用 `file:` 或 `path:`。Settings 中的 Excluded files 不出现在 Search 结果中。

## 标签查询

```text
tag:#topic/learning
tag:#status/inbox -path:"99-归档"
tag:#project (task-todo: OR [status:active])
```

- `tag:#work` 不会把代码块里出现的 `#work` 当标签。
- 嵌套标签使用 `/`；搜索父标签时会包含其子标签。
- 标签不允许空格；多词使用 `kebab-case`、`snake_case` 或嵌套标签。

## 属性查询

| 需求 | 查询 | 说明 |
| --- | --- | --- |
| 存在某属性 | `[status]` | 值可为空 |
| 属性等于某值 | `[status:ready]` | 文本匹配 |
| 多个允许值 | `[status:(ready OR draft)]` | 用括号更清晰 |
| 属性为空 | `[status:null]` | `status: ""` 与 `status: []` 不算 null |
| 数值小于 | `[rating:<3]` | 比较式放在属性方括号内 |
| 数值大于等于的替代写法 | `[rating:>3] OR [rating:3]` | 原生文档示例主要说明 `<` 与 `>`；显式组合最稳妥 |
| 日期精确匹配 | `[created:2026-08-30]` | ISO 日期最可预测 |
| 有类型且非归档 | `[type:concept] -[status:archived]` | `-` 可否定属性查询 |

### 本 Playground 常用查询

```text
[type:lesson] [status:ready]
[type:reference]
[difficulty:入门]
[estimated_minutes:<15]
[platforms:mobile]
[community_plugins] -[community_plugins:null]
[status:(inbox OR seed)]
```

> [!warning] 属性类型决定比较意义
> 若同名属性一会儿是数字、一会儿是文本，排序和比较会产生意外结果。先查 [[Obsidian知识/90-资源/02-参考/03-属性字典|03-属性字典]]，再统一属性类型。

## 限定在同一位置

```text
line:(TODO 负责人)
block:(来源 结论)
section:(风险 缓解)
task-todo:(电话 OR 邮件)
```

由窄到宽理解：`line:` 同一行；`block:` 同一段落/列表块；`section:` 同一标题区间；无前缀则只要求在同一文件。

## 正则表达式

```text
/\d{4}-\d{2}-\d{2}/
file:/^2026-08-/
path:/Daily\/2026-/
content:/\bTODO\b/
```

- Obsidian 使用 JavaScript 风格正则。
- 正则以 `/.../` 包围；路径中的 `/` 需要转义为 `\/`。
- 大 Vault 中先用 `path:`、`tag:` 或属性缩小范围，再加正则。
- 不熟悉正则时优先用普通词、精确短语和属性查询。

## 搜索结果的再利用

### 收藏搜索

1. 打开 Search 并确认结果正确。
2. 点击结果数量附近的三点菜单。
3. 选择 **Bookmark**。
4. 在 Bookmarks 中给它命名，例如“待整理收件箱”。

Bookmarks 保存的是查询入口，不会复制搜索结果。

### 嵌入搜索结果

````md
```query
[status:inbox] -path:"99-归档"
```
````

- `query` 代码块在 Obsidian 内动态显示当前结果。
- 它不是普通 Markdown 标准；关闭 Obsidian 后仍可看到查询源码。
- Obsidian Publish 不支持嵌入的 Search 结果；发布前准备静态替代内容。

### 复制结果

Search 三点菜单中的 **Copy search results** 可把当前结果复制到剪贴板。复制得到的是某一时刻的静态列表，Bookmark 和 `query` 则保持动态。

## Search、Quick Switcher、Omnisearch、Bases、Dataview

| 工具 | 最适合 | 不适合/边界 |
| --- | --- | --- |
| Quick Switcher | 已知文件名或别名；快速打开/创建 | 不检索复杂正文条件 |
| 原生 Search | 精确词、路径、标签、任务、属性、正则 | 不做复杂计算或自定义表格 |
| Omnisearch | 宽松、模糊、相关性排序的全文检索 | 不能替代原生运算符的可解释精确查询 |
| Bases | 根据属性显示、编辑、过滤、排序文件 | 不等于全文搜索；数据仍在 Markdown 属性中 |
| Dataview | 复杂聚合、分组、计算和自定义呈现 | 依赖社区插件；DataviewJS 有代码执行风险 |

## 排错速查

| 症状 | 处理 |
| --- | --- |
| 结果太多 | 加精确短语、`path:`、`tag:`、属性或括号 |
| 结果太少 | 暂时移除否定项；检查 `OR` 大写；逐段增加条件 |
| 标签搜不到 | 使用 `tag:#完整标签`；确认不是代码块内文本 |
| 属性搜不到 | 检查属性名、类型、空值写法；在 Properties view 中确认实际值 |
| 附件名搜不到 | 使用 `file:` 或 `path:`，不要只输入普通词 |
| 中文分词不理想 | 先用精确短语或较短词组；再比较 Omnisearch/中文分词插件 |
| 复杂查询无法理解 | 打开 Search settings → Explain search term |
| 某目录完全不出现 | 检查 Settings → Files and links → Excluded files |
