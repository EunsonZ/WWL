# 研究证据与版本边界

返回 [[11-难点导读与研究证据|难点导读]]。本页把本轮新增专题的出处与验证类型集中记录；具体主张优先看正文脚注，而不是把一个主页链接当整门课的依据。这里没有复制整篇标准、教材或在线图像；数值、反例、图表和实验由本库围绕声明的模型重新构造。

## 什么证据支持什么结论

语言标准/规范说明符合实现应满足的合同；官方运行时文档说明某个库或版本的行为；课程材料帮助建立算法和证明；本地实验只能说明列出的版本、输入和环境下观察到了什么。范例成立不自动证明一般性，类型系统的保证也不自动扩展到外部数据库或设备。

本轮逐篇扫描了基线全部 Markdown 的结构与链接；语义阅读围绕难点和候选过度概括进行。`baseline_inventory.json` 保存逐文件清单，`claims_to_review.json` 是 134 个启发式候选，不是 134 个已确认错误，更不是对所有旧内容的形式化证明。实际改写及理由见 `content_corrections.json`；本轮新增专题和原稿回接见 `new_content_registry.json` 与 `old_new_bridges.json`。

## 版本选择不是“永远最新”

C 示例以 C17 模式编译；公开 N1570 是 C11 委员会草案，正文只借它定位本页涉及的基础合同，不冒充 C17 的正式全文。`port70.net` 是便于按条款定位的转录，原始 WG14 PDF 也列在下方。WG14 缺陷报告用于补充边界，不把它们当所有后续版本都已采纳的结论。

C++ 使用固定 C++20 草案 N4861 的条款编号；公开草案 HTML 镜像不是某个编译器的实现手册。Python 采用 3.13 系列文档，实际解释器与微版本记在实验日志中。TypeScript 文档为检索时版本，实际 tsc/Node 版本、严格选项分别记录。Rust/Tokio 标准库和运行时文档含滚动链接，不能反推本机已安装这些版本；本机没有 Rust 编译器。

数据库具体并发与 WAL 参数说明以 PostgreSQL 17 文档为例，不能套到其他数据库同名隔离级别。RISC-V Supervisor 链接固定到文档快照 v20260120；BOOM 是一种微架构实例，不是所有 CPU。Linux man-pages、内核和 Bash 文档也不代替具体部署环境的选项与内核版本检查。

网络采用逐条 RFC 的定义；Reno、RTO 推荐下限和 PMTU 教学模型都有适用条件，不把它们称为所有现代网络栈的唯一实现。性能页的 M/M/1 是明确假设下的数学推演，不是引用 SRE 经验就得到的真实服务器数据。

## 本轮核对过的关键边界

Tokio 丢弃 JoinHandle 与丢弃实际拥有的 Future 不同；移动 String 拥有性元数据与搬迁堆缓冲区不同；C++ 的原子字段与复合操作不同；Python 数据描述符在读取路径中还要具有取值协议；RFC 6298 的更新顺序和推荐下限不能与任意实现默认值混写；SLR 表由项目集和 FOLLOW 构造而不是手填结果。

数据库页分别验证无损连接与依赖保持，WAL 页明确区分教学 undo 模型和 PostgreSQL 的 MVCC 恢复策略；文件页区分原子可见性与稳定存储；所有示例均从主张的适用范围出发，避免一条“总是如此”的句子吞掉前提。
