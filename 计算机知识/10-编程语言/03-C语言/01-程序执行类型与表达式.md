# C：从一个程序理解类型、表达式与执行

> 阅读定位：C17 核心；扩展和标准版本差异单独注明。返回 [[计算机知识/00-开始/课程地图/01-C语言-课程地图|C语言 · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## 先建立运行链，而不是背关键字

源文件不是 CPU 能直接执行的东西。预处理展开头文件与宏，编译把一个翻译单元变为目标代码，链接解析跨文件符号，装载器再把可执行文件映射进进程。编译失败、链接时找不到定义、运行时访问错误地址是三个阶段的问题。头文件中的声明只告诉编译器“函数长什么样”，不是把库函数的实现复制进来。

```c
#include <stdio.h>

static int sum_to(int n) {
    int total = 0;
    for (int i = 1; i <= n; ++i) total += i;
    return total;
}

int main(void) {
    printf("%d\n", sum_to(4));
    return 0;
}
```

例子在输入 4 时依次形成 `0 → 1 → 3 → 6 → 10`，循环不变量是“进入第 i 次循环时，total 为 1 到 i−1 的和”。但这不是接受任意 `int` 的安全接口：足够大的输入会令求和或循环变量发生有符号溢出。算法的数学结论必须加上机器表示的前提。用 `cc -std=c17 -Wall -Wextra -Wpedantic demo.c -o demo` 构建；命令不会替你证明输入范围。

## 类型同时决定范围、运算与接口

`char`、短整型、`int`、`long`、`long long` 的位数不能仅凭名称推断，查看 `<limits.h>`。`sizeof(char)` 为 1，但 C 的一字节有多少位由 `CHAR_BIT` 表示。需要精确格式时用 `<stdint.h>`，其中恰好宽度的类型如 `uint32_t` 只在实现能提供时存在。`size_t` 适合对象大小，不是“任何整数都应该无符号”。

整数提升会先把较小整数类型提升，接着通常算术转换决定两个操作数的共同类型。常见平台上 `-1 < 1u` 为假，因为 `-1` 被转为很大的无符号数。无符号运算按模数回绕是规定的行为，却仍可能使缓冲区长度判断失效；有符号溢出不能依赖回绕。`5 / 2` 先做整数除法，结果再赋给 `double` 仍是 2；`5.0 / 2` 才是 2.5。

浮点数近似表示实数。累加顺序改变舍入误差，不能把 `(a+b)+c` 和 `a+(b+c)` 当成普遍等价。钱的精确小数业务通常需要整数最小单位或明确的小数表示，而不是简单加一个“很小的 epsilon”。比较容差还应结合量纲、绝对误差与相对误差。

## 表达式不是任意顺序的数学式

`&&`、`||` 会短路，因此 `p != NULL && *p > 0` 会先排除空指针，再决定是否求值 `*p`。非空只排除了这一种无效值；解引用仍要求 `p` 指向生命周期内、对齐且可读的相应对象。不能写 `i = i++ + 1` 来试探求值顺序；同一标量未排序的读写会破坏语言规则。函数参数求值次序也不应被当成从左到右。需要顺序，就拆成语句。

`switch` 默认允许贯穿；`break`、`continue`、`return` 的目标不同。函数按值传参，想修改调用者对象须传入它的地址，但“传入一个指针”也只是复制这个指针值。递归要说明终止条件，并考虑真实调用栈资源。

## 练习与自检

把求和改为只接受 `0 ≤ n ≤ 1000` 并显式拒绝其他输入。解释 `sizeof(int)` 与 `sizeof(int*)` 为什么没有必然相等关系。预测 `7/3`、`7%3`、`7.0/3` 的差别，再验证。合格标准不只是输出正确，还能写清范围、终止条件和整数转换发生的位置。
