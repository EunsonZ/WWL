# C++ 深化：对象模型、值类别和异常安全

> 阅读定位：C++20 核心；原有工具与仓库内容保留。返回 [[计算机知识/00-开始/课程地图/02-C++-课程地图|C++ · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## 先确定对象，再谈“栈和堆”

对象有类型、存储和生命期。局部对象常对应自动存储期，动态对象常通过分配获得存储，但优化后不保证每个源码对象都对应独立栈槽。引用是别名，指针是可保存地址的对象；二者都可能悬空。拥有容器和借用视图必须区分：`std::string` 拥有字符，`std::string_view` 不拥有；`std::vector<T>` 拥有元素，`std::span<T>` 不延长它们的生命期。

真正声明为 const 的对象不能通过强制转换后写入来合法修改。另一方面，指向原本可变对象的 `const T*` 仅限制这条访问路径；其他合法可变别名仍可修改它。不要把这两种情况压成“const 对象仍可以从别处改”。

## 值类别决定重载选择，不直接等于复制次数

lvalue 通常表示有身份且可继续使用的对象表达式；prvalue 用于产生值和初始化；xvalue 表达可以转移资源的既有对象。`std::move(x)` 只是转换表达式类别，不会单独搬走资源。实际是否调用移动构造、是否可退化为复制、转移代价多大，取决于类型和重载。

对于标准库类型，移动后一般应遵守其具体合同；很多对象保证“有效但未指定状态”，不能普遍假设空。用户自定义类型则必须自己定义并维持可析构和其他承诺。`return local;` 常应让返回值优化和隐式移动发挥作用，不应习惯性加 `std::move(local)` 干扰优化。

## RAII 与 Rule of Zero

RAII 把资源的释放绑定到对象析构，不仅用于内存，也适用于文件、锁和事务守卫。类成员若都是 `vector`、`string`、`unique_ptr` 等拥有正确资源语义的类型，通常不必手写析构、复制和移动，这就是 Rule of Zero 的价值。

`unique_ptr` 表达唯一所有权；`shared_ptr` 表达共享销毁责任，但共享计数线程安全不意味着被指对象线程安全。双向强引用会形成不能自然归零的环，必要时用 `weak_ptr` 表达观察关系。用 shared_ptr 解决每个生命周期问题，会引入不明确的存活边界与额外开销。

## 异常安全要写到接口里

无抛出保证指操作不抛出；强保证指失败时外部可观察状态保持原状；基本保证指保持不变量且不泄漏，但内容可能变化。一个“先删除旧文件，再写新文件”的函数很难给强保证；先准备并验证临时状态，再提交替换更容易。

```cpp
#include <string>
#include <vector>

void add_two(std::vector<std::string>& values,
             const std::string& a, const std::string& b) {
    auto candidate = values;
    candidate.push_back(a);
    candidate.push_back(b);
    values.swap(candidate);
}
```

在标准分配器等通常前提下，复制和追加失败不会改动 values，最后交换完成提交。代价是复制整个容器；强保证不是免费。析构函数不应在栈展开期间再抛出。`noexcept` 是接口承诺，违反时不是自动转换为错误返回。

## 例题

为什么向 vector 追加时，先保存的元素引用可能失效？因为重新分配会移动/复制元素并结束旧对象生命期。`reserve` 可减少这类失效但不是永久保险，且它改变 capacity 不改变 size。练习为“追加两个元素”分别给出基本保证和强保证版本，解释时间、空间和失败状态的差异。
