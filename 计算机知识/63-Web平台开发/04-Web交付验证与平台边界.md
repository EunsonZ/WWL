# Web交付验证与平台边界：把每层证据写清

**测试显示全部通过，网页就能交付吗？** 测试只回答它实际执行的条件。Node模型测试能控制异步先后，却没有浏览器布局、原生表单验证或真实辅助技术；HTTP探测能验证服务返回，却没有人点击按钮。完整小组必须交接HTML/CSS/脚本/模型/服务器/测试与源码镜像，并让下一层知道未验证项。

## 由一个任务设计不同证据

任务仍是查Web、加入35与50分钟两门、删除35分钟、在慢查询期间取消。模型层有限枚举三门课程的8种子集与所有可选toggle，检查id集合和独立求出的分钟总和；异步测试穷举两个请求的两种完成顺序，另外控制“响应头到达后，旧体才返回”，避免只测一种幸运时序。它们验证的是模型，不是DOM。

真实接口层运行标准库服务器并用HTTP客户端请求，正常应有两门Web课程、503不伪装成200、格式故障确实是错误JSON/字段、断开场景无完整响应；Node原生Fetch连接此服务，另测abort及新请求替代旧请求。故障注入是本地真实TCP上的教学行为，不是公网高丢包性能实验。

| 验收层 | 具体动作与预期 | 仍不能推出什么 |
| --- | --- | --- |
| 静态结构/镜像 | YAML列表、链接存在、code-sync与源码字节一致；JS/Python解析 | 知识都正确、布局可读 |
| 模型执行 | 先后、取消、失败分类、空结果、阅读列表唯一id与总量 | 浏览器默认行为/焦点通过 |
| loopback接口 | 短期服务真GET，HTTP状态、JSON与断连路径 | HTTPS/CORS/认证/公网部署正确 |
| 实际浏览器 | Enter提交；按键选课删除；窄屏；慢请求取消/替代；错误重试 | 读屏播报、真人可理解 |
| 辅助技术与人 | 记录OS、浏览器、读屏版本和听到的状态；真实任务反馈 | 全WCAG符合性、总体成功率 |

本批作者实际完成范围见 [[计算机知识/63-Web平台开发/80-可交互Web小项目与源码#执行证据与未验证范围|实验证据]]。源码中声明role/status不等于听到了播报；[W3C状态消息说明](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)给的是核查依据。

## 实际浏览器的可复现动作

默认Web正常查询后确认两门，列表总量从0→35→85→50。只用Tab、Shift+Tab、Enter或Space操作，检查焦点可见、按钮名称、删除后下一个/前一个/空标题；原生required挡空串，纯空白由业务验证保留输入并报字段错误。切慢场景提交后立刻取消，应报告已停止等待且两秒后不回写结果；慢Web紧接正常网络，最终只有网络课程。503后点重试仍503；改回正常并提交才恢复。这区分“重试上次意图”和“新意图”。

在320 CSS px视口与常规宽屏各观察横向溢出、标题/按钮折行、DOM和视觉顺序；再在浏览器放大文字后复核。实际结果应记录版本、动作序列、焦点位置及失败样本，不能只截图首页。若某个按钮更新把焦点丢到body，修复须回到对应生命周期路径，相关浏览器动作重新执行。

**练习：**模型通过9项，HTML中有role=status，是否可以写“取消后读屏播报通过”？答案：不能。需要真实读屏组合实际操作与输出，且即使这一路径通过也不等于整页WCAG认证。人的研究设计与形成性样本边界读 [[计算机知识/75-软件工程与人机交互/04-交互任务反馈可用性与无障碍#一项能暴露问题的研究设计|HCI研究主解释]]，不在此课复制研究。

## 从演示迁到真实平台，哪些前提变了

当前只显式启动127.0.0.1短期服务，默认10分钟退出，Ctrl+C可提前终止，不创建常驻服务；静态白名单只公开演示必需文件，不把知识库根当HTTP目录。浏览器页面和 `/api/courses`同源，直接file打开则没有对应接口；模型测试中的transport注入也不是绕过浏览器安全策略。生产部署还会改变账户权限、资源上限、持久化、服务端写入、TLS、缓存、监控、恢复与依赖版本条件。

需要解释CORS、CSRF、输出编码时，去 [[计算机知识/10-编程语言/05-TypeScript/10-系统课程/07-Web边界安全与全栈协议#浏览器安全边界|Web安全主解释]]；需要DNS/TLS到HTTP路径时，去 [[计算机知识/35-计算机网络/06-DNS-TLS-HTTP与端到端请求|端到端请求主解释]]。同源演示不能宣称这些部署层验收通过。页面内存列表不跨刷新、更不跨设备，若加持久化必须重审其失败、同步和身份边界。
