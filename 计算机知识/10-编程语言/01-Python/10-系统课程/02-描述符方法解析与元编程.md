# 描述符、方法解析与元编程：属性访问是一段程序

> **学习位置**：[[计算机知识/00-开始/课程地图/04-Python-课程地图|Python课程地图]] · **适用边界**：Python 3.11+；CPython 实现细节明确注明。

## 点号不是简单的字典查找

读 `obj.x` 时，默认实例属性访问大致按“类及其基类中的数据描述符 → 实例字典 → 非数据描述符或普通类属性”查找；最终失败后，属性访问机制才可能调用 `__getattr__`。覆写 `__getattribute__`、特殊方法查找和元类的属性访问会改变细节，因此这是一张默认规则图，不是所有对象的唯一实现。

描述符是实现 `__get__`、`__set__` 或 `__delete__` 的对象；定义在**类**上才会参与通常的属性协议。具有 `__set__` 或 `__delete__` 的描述符是数据描述符，即使 setter 只抛异常也有优先级。函数是非数据描述符，所以从实例取方法会绑定 `self`；`property` 则把读取与验证封装成数据描述符。

```python
class Positive:
    def __set_name__(self, owner, name):
        self.storage = '_' + name
    def __get__(self, obj, owner=None):
        if obj is None:
            return self
        return getattr(obj, self.storage)
    def __set__(self, obj, value):
        if isinstance(value, bool) or not isinstance(value, int) or value <= 0:
            raise ValueError('需要正整数')
        setattr(obj, self.storage, value)

class Batch:
    size = Positive()
    def __init__(self, size):
        self.size = size
```

这里验证属于每一次赋值的契约，而不是只在构造时执行。下划线并不提供安全隔离，调用者仍可直接改 `_size`；这是一种协作式 API。生产代码若需复杂单位、不可变性和跨字段约束，通常让构造函数创建已经验证的值对象更清楚。

## 继承是线性化的协作，不是任意跳转

多重继承的 MRO 用 C3 线性化协调局部顺序与一致性。`super()` 的含义是沿当前实例类型的 MRO 继续找，而不总是“调用我的直接父类”。菱形继承中，各层保持兼容签名、只做自己的工作并调用一次 `super()`，才可能避免重复初始化。混用显式父类调用与协作式 `super()` 容易重复或跳过步骤。

验证方式比记图可靠：构造 `D(B, C)`，让每层方法打印类名，查看 `D.__mro__`。改变基类顺序后输出可能变化；某些矛盾顺序在创建类时就会报错。业务对象优先考虑组合；只有存在清楚的可替换关系或协作混入协议时才增加继承层级。

## 类创建过程中的扩展点

类体执行得到命名空间，再由元类创建类对象，随后应用类装饰器。`__init_subclass__` 适合对子类注册或检查；类装饰器适合局部变换；真正需要控制类创建和命名空间时才使用元类。元类冲突不是给更多类加 `type` 就能解决。

`__slots__` 可以限制默认实例字段并改变存储方式，但继承自带 `__dict__` 的基类仍可能有字典；弱引用需要相应支持。它不是通用性能按钮，应测量大量实例的实际内存。特殊运算通常在类型上查找特殊方法，因此给单个实例设置 `__len__` 不保证 `len(obj)` 使用它。

## 装饰器与可观察接口

函数装饰器在定义时返回包装后的对象，不是每次调用前重新定义。使用 `functools.wraps` 保留名称、文档和 `__wrapped__` 等元信息；它不自动保证签名的类型安全、同步与异步兼容或递归安全。缓存装饰器要求键可哈希，缓存会延长参数和结果的存活期，方法缓存也可能持有实例。带时间、权限或外部状态的函数需要失效策略，不能只加一个装饰器就宣称正确。

## 练习与答案

把 `Batch.size` 换成只有 `__get__` 的描述符，再向 `obj.__dict__['size']` 写入值：非数据描述符会被实例属性遮蔽。原来的数据描述符不会。这个对照实验能直接解释为何只读 `property` 仍能拒绝普通赋值。进一步写一个计时装饰器，要求异常发生时也记录耗时，同时原样传播异常；正确的计时清理位置是 `finally`，而不是只写在成功返回之后。
