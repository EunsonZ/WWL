# 压缩原理：熵编码、字典编码与有损压缩

## 本课目标

学完后，你能从“冗余”而非“神奇缩小”理解压缩；区分无损和有损的验收标准；解释 Huffman、算术/范围编码、LZ 字典、预测/变换/量化在管线中的角色；并把压缩比、码率、质量和安全资源限制一起纳入判断。

## 直觉：压缩不是把信息凭空删掉

如果来源中 `A` 出现得远比 `Z` 频繁，为 `A` 分配短码、为 `Z` 分配长码，平均长度便可下降；如果片段反复出现，可以用“回到前面复制”代替重复写出；如果人眼/人耳不敏感的误差允许丢弃，还可以先近似再编码。它们利用的是不同冗余：统计不均匀、重复、可预测性，或感知不重要性。

没有免费午餐：对所有同长度输入都无损变短不可能。一个无损压缩器把某些输入缩短，就必须让另一些输入不变或变长；高质量密文、随机数据和已经压缩的数据常缺少可利用冗余。

## 1. 无损与有损：先声明要重建的对象

“无损”必须先回答“对哪一个对象无损”。通用压缩器常以任意输入的**字节串**为对象；媒体 codec 常以容器解出的**样本序列**为对象。后者即使样本完全恢复，也不必重建原来的容器、metadata、chunk 顺序、padding 或未使用位。

| 类型 | 解码后的目标 | 典型场景 | 关键验收 |
| --- | --- | --- | --- |
| 字节域无损压缩 | 原始输入字节逐一恢复 | 源代码、文本、数据库、归档、模型权重 | 解压字节与原始字节完全相同 |
| 媒体样本域无损 codec | 格式声明的 PCM sample frame 或像素样本逐一恢复 | FLAC、无损图像/视频 codec | 解码样本值、shape、采样率/时间基与声道/像素布局按格式契约一致；容器字节不必相同 |
| 有损压缩 | 保留业务/感知可接受的近似 | JPEG、现代照片/视频/语音 codec | 在指定任务、设备和码率下的质量指标与人工感知 |

“看起来差不多”不能证明任何一种无损；“文件更小”也不能证明有损质量足够。对模型权重，常被称为“量化”的近似与传统媒体有损压缩一样会改变数值，但误差结构、模型行为和容器开销必须单独评估，见 [[数学/60-数值计算与量化/02-量化Scale-Zero-Point-Group与误差|量化的 Scale、Zero-Point、Group 与误差]]。

## 2. 熵给出平均码长的方向，不是每个文件的承诺

离散符号来源的熵为：

$$
H(X)=-\sum_x p(x)\log_2p(x).
$$

它以 bit 为单位衡量已知分布下的平均不确定性。若符号概率接近均匀，平均上较难用短码表示；若很偏斜，则可利用频率差异。熵、交叉熵及其“平均编码代价”的完整数学定义在 [[数学/50-信息论/01-熵交叉熵KL散度与互信息|熵、交叉熵、KL 散度与互信息]]，本页只使用其工程直觉。

现实压缩器还要写入文件头、字典或概率模型，处理有限块和上下文变化，并满足可随机访问、延迟和 CPU 预算。因此熵是理论参考，不能保证一个 20 字节小文件会缩小，也不能仅凭熵估算最终容器大小。

## 3. 熵编码：把“更常见”映射为更短的比特串

### Huffman 编码

Huffman 为一组已知频率构造前缀码：没有一个码字是另一个码字的前缀，因此解码器从左到右可唯一切分。设四个符号频率近似为 `A: 1/2, B: 1/4, C: 1/8, D: 1/8`，一种合适的码可能是：

```text
A → 0
B → 10
C → 110
D → 111
```

它不是唯一答案；交换同频符号仍合法。固定长度编码每符号要 2 bit，而这个例子平均为：

```text
1/2×1 + 1/4×2 + 1/8×3 + 1/8×3 = 1.75 bit/符号
```

Huffman 的单个码字长度为整数，概率不恰好是二的负幂时会留下间隙。还必须传输/重建码表，并限制码树深度与符号数。

### 同一串消息：概率、载荷与文件开销

把上面的概率固定为精确的 $P=(1/2,1/4,1/8,1/8)$，再比较均匀模型 $Q=(1/4,1/4,1/4,1/4)$。消息固定为 `AAAABBCD`；长度是 **8 个四元符号**，不是宣称某个文本文件已经只占 8 byte。

| 计量项 | 按 $P$ 编码 | 按均匀 $Q$ 编码 |
|---|---|---|
| 共享码表 | A→0，B→10，C→110，D→111 | A→00，B→01，C→10，D→11 |
| 有效载荷（竖线只用于展示） | `0\|0\|0\|0\|10\|10\|110\|111` | `00\|00\|00\|00\|01\|01\|10\|11` |
| 有效载荷长度 | $4\times1+2\times2+1\times3+1\times3=14$ bit | $8\times2=16$ bit |
| 该 iid 模型的序列 NLL | $-\log_2[(1/2)^4(1/4)^2(1/8)^2]=14$ bit | $-\log_2[(1/4)^8]=16$ bit |
| 每符号平均 NLL | 1.75 bit/符号 | 2 bit/符号 |

前缀码可逐 bit 走树还原八个符号；这里的分隔线不传输。消息频率恰好等于 $P$，所以这条消息的平均 NLL 恰好等于总体熵/交叉熵。按 $P$ 平均，$H(P)=1.75$、$H(P,Q)=2$、失配多付 $D_{\rm KL}(P\Vert Q)=0.25$ bit/符号；定义与计算见 [[数学/50-信息论/01-熵交叉熵KL散度与互信息#从平均损失到有限码流|熵、交叉熵与 KL 的同一笔账]]。换成其他有限消息，经验频率不必恰等于 $P$。

**14 与 16 是有效载荷，不是完整文件大小。** 若采用按整字节打包的格式，14 bit 可以占 2 byte，其中有 2 bit 填充；解码器仍须知道有效长度或结束规则。这时两种载荷仅按字节占用就可能相同。文件还可能包含符号映射、码表/概率模型、原始长度、格式标识和校验。哪些字段共享、哪些实际写入，以及字段长度，都取决于具体格式；没有生成并测量该格式前，不为它虚构头部字节数。

实际账本应分层写：源消息 → 压缩有效载荷 → 模型/头部/校验/填充后的文件 bit → 加入信道编码冗余后的信道使用次数。校验用于检测损坏，纠错码用于抗噪恢复，容器负责组织；三者不能算成同一个“熵”。

#### 一个可逐字节复算的教学格式

现在把“可能有哪些开销”固定成一个真实字节格式。下面的 **IC v1 是本课自定义的有限教学容器**，不是通用压缩格式或生产协议。它只处理 `A/B/C/D`，消息长度为 1–255 个符号，有效载荷为 1–255 bit，码字长度为 1–8 bit；解码器拒绝越界输入。它直接传送显式码表，不要求接收者预先拥有 $P$ 或 $Q$。码表已经足够解码，本格式不另传概率表；若使用自适应算术编码，概率模型和更新规则仍须另行约定。

| 字节 offset | 长度 | 字段与合法性 |
|---|---:|---|
| 0–1 | 2 byte | magic：ASCII `IC`，即 `49 43` |
| 2 | 1 byte | 版本：`01` |
| 3 | 1 byte | 码表项数：固定 `04` |
| 4 | 1 byte | 原始符号数 $N$，无符号 `u8`，范围 1–255 |
| 5 | 1 byte | 有效载荷位数 $L$，无符号 `u8`，范围 1–255 |
| 6–17 | 12 byte | 按 A、B、C、D 顺序写四个三字节项：ASCII 符号、`u8` 码长、`u8` 右对齐码值 |
| 18 起 | $\lceil L/8\rceil$ byte | 按码流顺序打包，先到的 bit 放字节最高位；末字节低位用 0 填充 |
| 最后 | 1 byte | `sum8`：此前所有字节的无符号值之和模 256，不含校验字段本身 |

所有整数头字段都是单字节，不存在多字节大小端选择；码值的数值解释由“右对齐”固定，例如 C 的码字 `110` 写成码长 `03`、码值 `06`。载荷跨字节时明确采用高位先到，不能使用本机内存布局代替格式规则。

固定消息仍为 `AAAABBCD`。按 $P$ 的载荷是 `00001010110111`，右补两个 0 后成为 `0a dc`；按 $Q$ 的载荷是 `0000000001011011`，成为 `00 5b`。完整文件可直接由十六进制重建：

```text
P：
49 43 01 04 08 0e
41 01 00 42 02 02 43 03 06 44 03 07
0a dc
af

Q：
49 43 01 04 08 10
41 02 00 42 02 01 43 02 02 44 02 03
00 5b
1c
```

`sum8` 可手算：P 的头、表、载荷字节之和为 $167+290+230=687$，$687\bmod256=175=\texttt{af}$；Q 为 $169+280+91=540$，$540\bmod256=28=\texttt{1c}$。

| 同一消息的成本 | 按 $P$ | 按 $Q$ |
|---|---:|---:|
| 已声明 iid 模型下的序列 NLL | 14 bit | 16 bit |
| 压缩有效载荷 | 14 bit | 16 bit |
| 载荷末尾填充 | 2 bit | 0 bit |
| 实际载荷区域 | 2 byte | 2 byte |
| 解码模型：显式码表 | 12 byte | 12 byte |
| 容器头 | 6 byte | 6 byte |
| 校验 | 1 byte | 1 byte |
| **完整文件** | **21 byte = 168 bit** | **21 byte = 168 bit** |

这是所声明格式的精确序列化成本，不能推广为某个通用压缩器的实测结果。若原消息以 ASCII 字节保存则为 8 byte，本格式还会扩大它；若双方预先共享码表、消息长度或采用其他格式，成本必须重新计算。源符号的二位表示、ASCII 文件和这里的容器属于不同计量对象。

解析时先限制总长度，再检查 magic、版本、字段范围和由 $L$ 推出的完整文件长度，拒绝尾随字节；之后核对 `sum8`，验证四个有序符号及码值范围、码表无重复码字且无前缀冲突。只读取前 $L$ 个有效 bit，要求剩余 pad 位全为 0；载荷必须在完整码字处结束，解码符号数必须恰为 $N$。校验通过不能替代这些语义检查。

例如，P 末尾 pad 位从 0 改为 1，即使重算校验仍应被格式解析器拒绝；把消息数改为 7 并重算校验，也应因实际解出 8 个符号而拒绝。载荷截成 `11`、声明 $N=1,L=2$ 并合法填充后，则应因码字未完成而拒绝。

`sum8` 只是为了让本例完全可手算，检测能力很弱。Q 的载荷从 `00 5b` 改成 `01 5a`，字节和不变，校验仍为 `1c`，却会合法解出另一条消息 `AAABBBCC`。这说明某些损坏会漏检；主动改写者还可重算校验。实际 CRC 的算法和覆盖范围应有完整协议，但 CRC 同样不提供防篡改认证，相关区别见 [[计算机知识/60-数据编码与媒体系统/03-二进制文件格式魔数字节序对齐与校验#5. 校验和、哈希与认证各能证明什么|校验、哈希与认证]]。

可执行真源与固定输入见 [[数学/50-信息论/80-运行证据/information_container_practice|有限容器实践接口]]。正文中的字节和答案是格式定义与手算预期；实际运行回执另行保存，不以接口存在宣称已执行。

这个例子能让 NLL 与码长恰好一致，是因为概率为二的负幂且双方共享匹配码表。一般非二幂概率还受整数码长、有限块、算术编码精度和终止约定影响。[[数学/50-信息论/10-信源信道与率失真/02-前缀码Kraft不等式与信源编码|Kraft 与信源编码]] 证明哪些码长可行、平均为何不能低于熵，以及渐近结论允许什么错误；[[数学/30-概率与统计/03-似然负对数似然与困惑度#从 NLL 到码长：八个符号只算一次账|NLL 与困惑度]] 则解释按 token、字节或符号归一化的区别。

### 算术编码与范围编码

算术编码不为每个符号分别交付一个码字，而是把整段序列逐步缩小到 `[0,1)` 中与其概率区间对应的子区间。最后输出一个能落在该子区间内的数的比特表示；范围编码是常用的整数实现思路。它可以更贴近非二幂概率的理论码长，并可结合上下文概率模型。

关键边界是：编码器和解码器必须使用同一初始分布、同一上下文更新规则、同一有限精度/归一化约定。模型不同步会使后续所有符号失步；不可信码流还应限制输出长度和运算步骤，避免“小输入展开为巨大输出”。

## 4. 字典编码：把重复内容改写为引用

LZ 家族的核心是：若当前待输出片段在已出现的窗口或字典中存在，就发出“距离、长度”引用；否则发出字面量。比如已输出 `ABCD` 后再出现 `ABCD`，概念上可写成：

```text
字面量：A B C D
引用：  (distance = 4, length = 4)
```

真实 bitstream 还会把 literal、length、distance 分配为标志与可变长编码。LZ77 常引用滑动窗口中的历史字节；LZ78/LZW 侧重增长字典。DEFLATE 等格式会组合 LZ 匹配和 Huffman 编码：**字典找重复，熵编码缩短描述重复的符号**，二者不是竞争关系。

字典方法对重复日志、文本模板和相近块常有效；对短小、随机、已压缩或加密数据可能变长。解压器要限制窗口、引用合法性、递归/嵌套层数、总输出字节与压缩比，防止压缩炸弹。

## 5. 有损媒体压缩：预测/变换后，再量化

有损图片、音频和视频通常不是“直接删掉几个字节”，而是根据信号结构分阶段处理：

```text
样本 → 预测或变换 → 系数/残差 → 量化（有损） → 熵编码（无损） → 码流
```

- **预测**：用邻近像素、先前音频样本或前后视频帧预测当前值，只发送较小的残差；
- **变换**：把相关的时域/空间域样本转到更集中的频域或其他基；能量集中后更容易分配比特；
- **量化**：把连续或高精度系数映射到较粗网格，是经典有损失真的主要来源；
- **熵编码**：对量化后的零、短残差和常见符号再无损压缩。

量化步长越大，码率通常更低而误差通常更大；但“误差多大”还与内容、感知模型、码率控制、预测结构和解码后处理有关。视频 codec 还会引入帧间预测与运动补偿，随机访问、延迟和错误传播会影响编码结构选择。

> [!warning] 不要把“熵编码”叫作有损
> Huffman、算术/范围编码和 LZ 的解码目标是精确还原其输入；有损性通常由量化、降采样、裁剪或其他近似步骤引入。一个媒体文件可以同时包含有损量化与之后完全无损的熵编码。

允许有损以后，问题变成“在指定失真 $D$ 下，至少需多少 bit/源符号”。[[数学/50-信息论/10-信源信道与率失真/04-率失真与信源信道分离|率失真主课]] 给出 $R(D)$ 的定义、一般上下界证明和二元例子，并说明工程中的 $J=D+\lambda R$ 只在选定编码工具与候选内优化；它不是当前 codec 已达到理论界的证据。

## 6. 比率、码率、质量与资源：比较时先固定条件

- **压缩比**常写作 `原始大小 / 压缩后大小`；必须说明是否计入容器、索引和元数据。
- **码率**是每秒使用的 bit 数；同样的码率在不同长度、内容或 codec 设置下不代表相同质量。
- **质量指标**（如像素误差或感知指标）只能在明确参考、色彩/采样处理、内容集和版本时比较；数值高不必然等于人更满意。
- **速度、内存、延迟、随机访问和错误恢复**往往与压缩比相互拉扯。

压缩既是性能问题也是安全边界。解析不可信压缩数据应先设定：压缩输入最大值、声明/实际输出最大值、最大嵌套层数、CPU/时间预算和取消机制；在写入磁盘前执行这些限制，避免解压炸弹填满资源。

## 练习

1. 对 `AAAAABCD`，说明 Huffman 与 LZ 各可能利用什么冗余；不要假设它们一定在这么短的输入上减少总文件大小。
2. 某 JPEG 文件的熵编码阶段无损。为什么重新解码再保存 JPEG 仍可能继续失真？指出有损步骤在哪里发生。
3. 解释为什么“先加密再 gzip”通常不压缩，以及为什么“先 gzip 再加密”也仍需要长度侧信道分析。
4. 为接收用户上传 `.zip` 的服务写出至少五项解压前/中限制与一个成功标准。

5. 使用上面的 IC v1 文件，把 `AAAABBCD` 的完整成本迁移到一次传输。先分别列出按 P/Q 的理想 NLL、有效载荷、填充、显式码表、容器头、校验和总文件 bit。题设把完整文件的每个 bit 重复两次，码率 $R_c=1/2$；随后使用每个符号承载 2 个信道 bit 的四相位映射。另发送 8 个同步符号、4 个导频符号，符号率固定为 1000 symbol/s。求数据符号数、总符号数与发射时长；再求取消重复编码后的对应预算。说明这个计算为什么没有证明指定误码率、纠错效果或已经达到信道容量。

   **答案：** P 的理想 NLL/有效载荷为 14 bit，填充 2 bit；Q 为 16 bit，填充 0 bit。两者码表均 96 bit、头 48 bit、校验 8 bit，因此完整文件均为 $14+2+96+48+8=16+0+96+48+8=168$ bit。二重复后为 $168/(1/2)=336$ 个信道 bit，数据区为 $336/2=168$ 个调制符号；计入同步和导频，发送 $168+8+4=180$ 个符号，发射时长为 $180/1000=0.180$ s。取消重复后，数据区为 84 个符号，总计 96 个符号、0.096 s。两种源编码在这个完整格式下有相同预算。

   这里包含重复编码冗余、导频与同步；不包含重传、其他协议头、帧间空闲、传播与排队时间。二重复码的两个接收 bit 不一致时没有唯一多数，不能只凭增加冗余便声称可以纠正该错误。四相位映射和 1000 symbol/s 是题设，不是测量；实际同步、检测、误码率和吞吐需要 #181/#219 的实现与证据。[[数学/50-信息论/10-信源信道与率失真/03-离散信道容量与编码定理|容量主课]] 中的容量以模型下的 bit/use 计，也不能直接替代这里的 symbol/s 或实测传输速率。

- 我会先声明重建对象：字节域无损验收原始字节；媒体样本域无损验收解码样本与其格式契约；有损压缩再定义任务和质量预算。
- 我能区分 Huffman 的前缀码、算术/范围编码的区间思想、LZ 的重复引用，以及它们可以组合的原因。
- 我知道预测/变换本身不必有损，量化常是有损误差的关键来源，而熵编码通常是无损的后续步骤。
