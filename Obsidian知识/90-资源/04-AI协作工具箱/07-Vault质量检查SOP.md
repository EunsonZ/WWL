# Vault 质量检查 SOP

检查强度与实际影响相符。较复杂验收可按需用 [[Obsidian知识/90-资源/01-模板/核心模板/Vault质量检查|Vault质量检查模板]]；模板和全套工具测试都不是每次修改的前置。

## 最小检查

语义不变的标点、措辞或图注小修，由作者对照局部差异，确认没有改公式、事实、代码行为和引用目标。重要定义、推导、因果、数量、代码行为或关键先修的变化，由未参与该论证或行为修改者独立核对；只扩大到必要上下文。

已有 Git 时可用 `git diff --check` 和 `git status --short` 辅助看当前改动；没有 Git 时对照局部原件与候选，不为检查初始化仓库。正文修改不默认运行检查器自身的全部单元测试。

## 涉及链接、属性、Bases 或 Canvas

先核受影响目标和结构。需要运行库级静态检查时，从库根使用真实入口：

```bash
python3 -B scripts/check_vault.py --help
python3 -B scripts/check_vault.py --require-yaml
```

只检查源码镜像时，可从库根运行 `python3 -B scripts/check_mirrors.py --root .`。候选根、退出码与未覆盖语法见 [[scripts/CHECKS|维护检查说明]]。PyYAML 缺失时相应层未运行，`--require-yaml` 会报告错误；按已有安装授权处理，没有相应授权不安装。

需要 JSON 报告时，使用 `--json /库外已存在目录/新证据.json`，输出目录必须已存在且在被检查库外，文件名必须全新，不能覆盖旧证据。报告可能含私密路径，按本次授权保管。

静态入口没有客户端语义检查选项。只有受影响的公式、表格、链接、Base、Canvas 或配置需要显示核对时，才在可用 Obsidian 中预览相应页面。没有客户端则说明未实测的显示范围，不能用文件存在或静态通过代替。

## 涉及配置或插件

- 解析改动的配置并核对其具体路径、数据和过滤条件；不因一项变化要求全视图检查。
- 对相关的自动执行、凭据、外发与权限边界做必要核查，不读取或输出无关秘密。
- 需要重载才能生效的变化，在实际客户端确认；文件已修改不证明旧会话已加载。
- 已有授权继续有效；超出授权的安装、启用、外传或费用才另行确认。

## 交付标准

分别报告静态结构、相关执行、语义来源、真实显示与人的理解。保留精确的教学反例、历史导入身份和快照获取差异；不把排除 PDF 的快照当仓库删链依据，不为检查变绿批量改作者属性或扩大例外。已有检查可在相关输入与环境不变时注明复用；未运行、失败和未覆盖项如实保留。
