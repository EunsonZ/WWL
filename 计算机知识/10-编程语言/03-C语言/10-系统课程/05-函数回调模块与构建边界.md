# 从函数到库：回调、封装、翻译单元和链接契约

> **学习位置**：[[计算机知识/00-开始/课程地图/01-C语言-课程地图|C语言课程地图]] · **适用边界**：ISO C17；C23 与 POSIX 扩展另行标识。

## 一个函数接口同时传递四类信息

参数类型只覆盖一部分契约。一个可靠函数还应说明：指针是否允许为空；哪些输入可重叠；谁拥有返回资源；失败怎样报告、哪些状态已改变。`const char *` 不足以表达终止符是否存在、可读区间多长、返回后指针是否继续有效。

C17 中 `int f(void)` 明确声明无参数；旧式 `int f()` 不是同一件事。不要把 C++ 的解释直接搬过来。C23 对无原型函数声明等规则有变化，本课程的可运行示例不依赖这些新变化。

函数参数按值传递。传指针也是复制一个指针值，函数可以通过它修改所指对象，但想替换调用者保存的指针，往往需要二级指针或返回值。接口中采用哪一种，应优先让成功、失败与所有权转移清晰。

## 回调把算法与业务决策分开

排序算法不应该知道每种记录的业务顺序，因此接受比较回调。比较函数必须形成合适的一致顺序，并返回负、零、正值。不要用 `return *(int*)a-*(int*)b;` 比较任意整数，因为差值可能溢出。

```c
int compare_int(const void *left, const void *right) {
    int a = *(const int *)left;
    int b = *(const int *)right;
    return (a > b) - (a < b);
}
```

`qsort` 不保证相等元素的稳定性；名字也不承诺底层必须用某一种快速排序实现。比较浮点数还要决定 NaN 与有符号零的顺序，不能让非自反关系破坏排序算法的假设。

需要状态的回调可以显式接收 `void *context`。标准 `qsort` 没有这个上下文参数，不同平台的 `qsort_r` 签名也不能混用。自己的库可以设计 `visit(item, context)`，但上下文的类型、生命周期与线程安全仍由协议负责。

## 不透明结构体让实现可以改变

公共头文件只暴露：

```c
struct table;
struct table *table_create(void);
void table_destroy(struct table *t);
int table_put(struct table *t, const char *key, long value);
```

实现文件才定义 `struct table` 的成员。调用者不能 `sizeof(struct table)` 或直接访问字段，于是库能改变哈希策略、锁或布局，而不要求调用者跟着修改内部访问代码。代价是通常需要间接访问、动态分配或专门的就地初始化接口。

头文件应能独立包含，使用 include guard，放声明而不是随意定义具有外部链接的全局对象。`extern int counter;` 通常声明对象，某一个 `.c` 文件中提供定义。文件作用域 `static` 可限制符号的链接范围；函数内 `static` 则强调静态存储期，两个语境不要混淆。

## 编译和链接解决不同问题

预处理展开包含和宏；编译把一个翻译单元变成目标文件；链接解析符号、安排代码与数据；装载再把程序放入进程环境。`undefined reference` 通常不是 C 语法错误，可能是目标文件没加入、库顺序不当、符号名称不匹配或接口根本没实现。

```sh
cc -std=c17 -Wall -Wextra -Wpedantic -c table.c
cc -std=c17 -Wall -Wextra -Wpedantic -c main.c
cc main.o table.o -o demo
```

这只是独立示例的构建方式。可复现工程应记录编译器版本、标志、依赖、生成文件与测试命令；Make 或 CMake 负责表达依赖图，而不是神奇地修复类型和 ABI 错误。

## 宏、内联函数和 `_Generic`

`#define SQUARE(x) ((x)*(x))` 加了括号仍会求值两次，`SQUARE(i++)` 不安全。宏适合条件编译和生成重复结构，普通计算优先函数。`static inline` 可在头文件中提供具有内部链接的辅助函数，避免误把“inline”理解为强制机器码内联。

C11 的 `_Generic` 可以按表达式类型选择实现，但不是 C++ 模板的完整替代；它没有同样的实例化、约束和重载机制。`#` 字符串化、`##` 记号拼接和可变参数宏应配合最小预处理输出检查，不要把可维护性全部押在宏技巧上。

## 练习：定位一个构建故障

头文件声明 `int add(int,int);`，实现写成 `long add(long,long)`，为什么只靠链接可能发现不了全部问题？链接器主要围绕符号与目标文件信息工作，并不必然以 C 源码类型规则跨翻译单元检查整个接口。正确做法是实现文件也包含公共头文件，让编译器直接检查声明和定义一致性，并在 CI 中构建所有配置。

进一步思考：兼容性包括源码 API、二进制 ABI 和语义契约。一个函数签名没改但把“失败不修改输入”改成“部分修改后返回错误”，同样可能破坏调用者。
