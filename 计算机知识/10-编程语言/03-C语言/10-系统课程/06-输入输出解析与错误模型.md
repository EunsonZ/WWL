# 输入不是可信整数：stdio、解析器与错误报告

> **学习位置**：[[计算机知识/00-开始/课程地图/01-C语言-课程地图|C语言课程地图]] · **适用边界**：ISO C17；C23 与 POSIX 扩展另行标识。

## 一次读操作有三种结果，不是两种

读到数据、正常到达文件末尾、发生 I/O 错误需要区分。`fgetc` 返回 `int`，才能表示所有 `unsigned char` 的值及 `EOF`。把结果先存入 `char`，可能把合法字节和 EOF 混为一谈。

```c
int c;
while ((c = fgetc(in)) != EOF) {
    /* 按字节处理 c；不得假定每个字节都是完整字符。 */
}
if (ferror(in)) {
    /* 处理读取失败。 */
}
```

`while (!feof(in))` 常常多处理一次，因为 EOF 标志通常要在尝试越过末尾后才出现。应以读取函数返回值控制循环，再检查结束原因。

## `fgets` 读到一段，不一定读到完整逻辑行

缓冲区太小时，一行会被分成多段。只检查 `fgets` 非空就立即解析，可能把同一条输入拆成两条命令。需要检测是否包含换行，决定继续拼接、拒绝超长行，还是按协议处理末尾无换行的最后一行。

`scanf("%s", buffer)` 没有限制宽度会越界；带宽度也需要给终止符留下空间。更可控的流程是先按长度限制读取原始文本，再单独解析。不要把读取、类型转换和业务校验揉进一个难以判断部分成功的表达式。

## `strtol` 的完整成功条件

可靠整数解析至少验证：输入确实包含数字；转换没有超出 `long` 范围；结尾只有协议允许的字符；结果在目标业务范围内。例子接受十进制整数，不自动接受尾随垃圾：

```c
#include <errno.h>
#include <limits.h>
#include <stdlib.h>
#include <stdbool.h>

bool parse_int(const char *text, int *out) {
    char *end;
    errno = 0;
    long value = strtol(text, &end, 10);
    if (end == text || errno == ERANGE || *end != '\0') return false;
    if (value < INT_MIN || value > INT_MAX) return false;
    *out = (int)value;
    return true;
}
```

前提是两个指针有效，输入已终止。这个版本仍接受 `strtol` 允许的前导空白与正负号；若协议要求只有 ASCII 十进制数字，需另行限制语法。`errno` 只有在接口文档规定的失败情境下才有解释意义，成功后遗留的旧值不能被当成当前失败。

## 文本、字节和 locale 是三层问题

`fread`、`fwrite` 按元素数返回成功数量；若元素大小大于 1，部分元素读取对后续恢复有额外含义。跨平台二进制文件使用 `rb`、`wb`，避免某些系统文本模式的转换。输出成功进入 stdio 缓冲，并不等于掉电后仍可恢复。

`ctype.h` 的 `isdigit` 等函数通常要求参数是 EOF 或可表示为 `unsigned char` 的值。若 `char` 有符号，直接把负值传进去可能越过接口定义域，常用写法是 `isdigit((unsigned char)c)`，但首先仍要按协议决定是否接受 locale 相关分类。

UTF-8 文本处理不能用“一个 char 就是一个汉字”建模。宽字符、`mbstate_t` 与多字节转换接口有各自契约，`wchar_t` 的宽度和编码也不跨平台统一。网络协议通常规定 UTF-8，并在边界显式解码、验证及规范化策略。

## 错误类型应该保留决策信息

“失败”可能是可重试 I/O、格式不合法、权限不足、空间耗尽或程序不变量破坏。不要只返回含糊的 `-1` 而不提供上下文。一个小型库可以返回枚举错误码，把详细消息写入调用者提供的缓冲区，避免静态全局错误字符串带来的并发问题。

清理失败与主要操作失败同时发生时，应保留原始错误并附加清理错误，而不是覆盖根因。错误日志也不应无意打印密码、令牌或全部用户数据。

## 从标准 C 到系统接口

stdio 的 `FILE*` 和 POSIX 文件描述符 `int fd` 不是同一对象。`read`/`write` 可能短读短写；`EINTR`、非阻塞 `EAGAIN`、文件偏移共享和 `fsync` 属于系统接口契约，不能从 ISO C 的 `fread` 行为直接推导。

时间处理同样如此：墙上时间可以被校时改变，测量间隔和 deadline 更适合单调时钟接口。`time.h`、`locale.h`、`signal.h`、`setjmp.h` 提供标准库能力，但异步信号处理安全和非局部跳转的清理限制需要单独学习。

## 练习与答案

输入 `"12x"`、`""`、`" 12"`、超出 `long` 的长数字串，分别怎样处理？上面的解析器依次拒绝、拒绝、接受、拒绝。若你的产品要求第三个也拒绝，修改语法层，不要靠更换整数类型碰运气。

为什么 `printf(user_input)` 是安全问题？输入会被解释为格式串，而不是普通数据。写 `printf("%s", user_input)`，并继续检查输出错误；这与 SQL 参数绑定、Shell 参数分离属于同一类“把数据误作程序”的边界问题。
