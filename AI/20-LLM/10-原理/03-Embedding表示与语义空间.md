# Embedding、表示与语义空间

<!-- deep-review-02 -->
> [!tip] 本轮深化：从当前概念继续追问
> 向量长度、点积和余弦相似度是不同量；语义近似也不等于证据蕴含。先检查几何定义，再把检索效果与答案正确性拆开验证。 深化与验证：[[AI/11-数学与统计桥梁/01-向量空间投影SVD与低秩|向量空间投影SVD与低秩]]；[[AI/20-LLM/70-工程应用与工具链/08-混合检索重排RAG误差分解与证据|混合检索重排RAG误差分解与证据]]。


## 直觉：把离散 ID 放进可学习的坐标系

token ID `712` 只是词表索引，不能直接表达“它和哪个 token 相近”。Embedding 表把每个 ID 对应为一串可训练数字，例如一个长度为 $D$ 的向量。模型随后对向量做加法、投影和比较；训练若反复让相似上下文出现，某些几何关系会变得有用。

> [!note] 数学先修
> 向量、矩阵、张量和 shape 的完整定义见 [[数学/20-线性代数与几何/01-向量矩阵与张量|向量、矩阵与张量]]；点积、距离与余弦相似度的假设和推导见 [[数学/20-线性代数与几何/03-点积范数距离与余弦相似度|点积、范数、距离与余弦]]。本页只说明这些对象在 LLM 中的用途。

## 最小机制

设词表大小为 $V$、表示维度为 $D$，输入 embedding 表可理解为一个形状为 $V \times D$ 的参数表。一次查表取出第 `id` 行，得到该 token 的 $D$ 维向量。这个“查表”不是查询百科；它只是选择一行可训练参数。

位置不同、前缀不同的同一个 token 会在网络层中得到不同的**上下文化表示**。因此要分清：

| 名称 | 来自哪里 | 能表达什么 | 不能自动表达什么 |
| --- | --- | --- | --- |
| 输入 embedding | token ID 查表 | token 的初始可训练表示 | 本句中唯一确定的含义 |
| 上下文化 hidden state | 多层计算后的某个位置 | 该位置与其上下文相关的特征 | 可直接读取、稳定的自然语言解释 |
| 检索 embedding | 由专门模型编码的文本块 | 为某个相似度目标优化的向量 | 文档事实已被验证或完整覆盖 |

## 输入查表与输出词表投影

输入 embedding 把 ID 变为长度 $D$ 的向量；网络最后还要把长度 $D$ 的 hidden state 投影回 $V$ 个词表 logits。若输入表为 $E\in\mathbb{R}^{V\times D}$，输出矩阵可独立学习，也可与 $E$ 共享（weight tying）：

$$
z_t=h_tW_{out},\qquad W_{out}\in\mathbb{R}^{D\times V}.
$$

在本页的行向量记号下，weight tying 令 $W_{out}=E^\top$。共享权重能减少参数并把“读入 token 的表示”与“对 token 打分的方向”联系起来，但不是所有架构都共享，也不表示 embedding 空间可以直接当作一张可解释的知识地图。是否共享应由配置和权重 shape 确认，完整数据流见 [[AI/20-LLM/20-架构/01-Transformer完整数据流|Transformer 完整数据流]]。

## 一个二维玩具例子

为了画图，假设三个短文本被表示为**未归一化的二维示意向量**：`猫喜欢晒太阳` 为 $a=(0.9,0.1)$，`小猫在窗边取暖` 为 $b=(0.8,0.2)$，`数据库索引优化` 为 $c=(-0.7,0.4)$。这些是解释几何的人工构造，不是真实模型输出，向量长度也不等于 1。

$$
\|a\|=\sqrt{0.82},\quad \|b\|=\sqrt{0.68},\quad
\cos(a,b)=\frac{0.74}{\sqrt{0.82\cdot0.68}}\approx0.991,\quad
\cos(a,c)=\frac{-0.59}{\sqrt{0.82\cdot0.65}}\approx-0.808.
$$

因此，在这个人为例子里，前两者方向更接近。直接用点积替代余弦会把长度混进分数；只有明确单位化或把长度也纳入建模目标时，才能说明这种选择的含义。几何相近仍不保证检索材料支持答案中的具体主张。

这只说明在这个**特定表示与度量**下它们相近。它不等价于“两个句子完全同义”，更不等价于“它们的所有事实都一致”。否定、日期、数量、专有名词和多义词常会使“整体相近”掩盖关键差异。

## 语义空间的有用边界

- 相似度依赖训练数据、模型、输入模板、是否归一化和距离度量；换任一项，排序可能改变。
- 向量空间可以编码统计相关性，也会携带语料中的偏见、陈旧性和歧义；“距离近”不构成因果、道德或真实性结论。
- embedding 维度更大不必然更好；实际效果要在目标语言、任务、数据分布和延迟/隐私约束下评测。
- RAG 的召回只是候选发现。仍需检查来源、时间、权限、分块边界与回答是否真正受证据约束；在进入工程实现前先从 [[AI/20-LLM/40-推理/00-LLM推理-MOC|LLM 推理 MOC]] 核对生成与运行边界。

## 练习

1. 解释 token ID 与 embedding 向量分别是什么；为什么“ID 相差 1”没有语义含义？
2. 某检索结果与问题余弦相似度最高，却给出了错误日期。列出至少两种你会追加的验证。
3. 为什么必须把“静态 token embedding”和“上下文化 hidden state”分开？用“bank”可指银行或河岸的例子说明。
4. 输入 embedding 表 shape 为 `[V,D]`。写出独立输出矩阵的 shape，并说明 weight tying 共享的是哪一组参数、没有共享什么语义保证。

## 成功标准

你能说清输入查表、上下文化 hidden state、输出词表投影、检索相似度和事实核验是不同层；能写出 `[V,D]` 与 `[D,V]` 的 shape 关系，并把 embedding 用作候选信号，而不会把高相似度当作同义、正确或授权访问的证明。
