# 问题驱动的工具选择与理论路线

这页不是新的工具百科，而是把已有权威解释连接成可连续阅读的路径。每条路径围绕同一个问题：先界定对象，再选择能观察该对象的工具，随后解释结果，最后检查结论还依赖哪些条件。只学理论时，不必执行命令；旧实验用于有授权和相应环境时的可选验证，不是本轮新增任务。

**全篇共同的先修**是[[计算机知识/Kali/00-导航与方法/04-从观察到结论的安全方法#工具其实在做一个有条件的逆问题|有条件的逆问题]]。工具得到的是在某种配置与观察条件下的输出，不是系统全部状态的直接副本。各段给出的“完成标准”是供自己检验的目标，不表示已经掌握。

## 一、服务没有响应：究竟是哪个层没有回答

从[[计算机知识/Kali/01-系统与网络基础/06-TCPIP路由DNS与TLS#从字节到业务动作：每层确认的对象不同|各层确认的对象]]进入：地址能路由到、TCP 能建立连接、协议能回应、身份被接受和业务写入提交，依次回答不同问题。不要先把所有失败归为网络问题，也不要把连接成功写成交易成功。

**工具分工。** DNS 客户端用于保留查询名称、类型、响应状态和解析器条件；Nmap 用受控探测推断可达性、端口与服务；tcpdump/Wireshark/Tshark 检查选定位置实际保留的帧和解析结果；协议客户端再观察应用交互。沿[[计算机知识/Kali/02-信息收集与网络测量/02-DNS域名与证书信息#“没有地址”至少要分成四种解释|四类 DNS 阴性]] → [[计算机知识/Kali/02-信息收集与网络测量/03-Nmap主机发现与端口状态#按问题读扫描方式，而不是按“强度”排序|扫描方式与所问问题]] → [[计算机知识/Kali/02-信息收集与网络测量/05-WiresharkTcpdump与Tshark#捕获、重组、解析、显示是四道不同的门|捕获、重组、解析、显示]]阅读。

**把难点连起来。** 比较[[计算机知识/Kali/02-信息收集与网络测量/03-Nmap主机发现与端口状态#两种模式得出不同标签，为什么不一定互相矛盾|ACK 与 SYN 标签为何不矛盾]]与[[计算机知识/Kali/01-系统与网络基础/09-状态防火墙与网络命名空间#conntrack 的状态不是应用的状态|连接跟踪的含义]]；再比较[[计算机知识/Kali/02-信息收集与网络测量/05-WiresharkTcpdump与Tshark#重传字节不能当成新的业务数据|重传的唯一字节数]]与[[计算机知识/Kali/01-系统与网络基础/06-TCPIP路由DNS与TLS#把窗口、时延与吞吐放进同一张量纲表|窗口、时延与吞吐的量纲]]。前一组解决状态含义，后一组解决计数单位，不能互相替代。

**完成标准。** 对“无响应”至少提出两种可区分解释，并写明下一次观察要改变什么；对“100 Mbit/s 链路为何未跑满”先判断接收窗口、往返时延与其他瓶颈，而不是直接调高扫描并发。历史实验对应 G、H、B；没有运行这些工具时，结论保持为理论推演。

## 二、同一 URL 得到不同结果：谁解释了请求，谁生成了响应

从[[计算机知识/Kali/03-Web与API安全/13-HTTP中间层与消息解释#从字节流到业务对象：每一层回答不同问题|字节、消息、路由和业务对象]]进入，然后读[[计算机知识/Kali/01-系统与网络基础/07-HTTP浏览器会话与信任边界#同源、同站、凭据与授权：四道不同的判断|同源、同站、凭据与授权]]。浏览器、代理、缓存和源站并不是同一个观察者。要比较结果，首先写清客户端身份、请求目标、协议表示和响应生成位置。

**工具分工。** Burp Proxy/History 用于保留经过代理的交互，Repeater 用于受控重放，Intruder 用于明确的输入组合，Sequencer 用于样本统计；ZAP 的爬取负责到达候选状态，被动扫描负责分析已观察消息；curl 则提供另一个协议客户端视角。读[[计算机知识/Kali/03-Web与API安全/03-BurpSuite工作流#组件分工：采集、变换、比较和统计不是同一种能力|Burp 组件分工]]与[[计算机知识/Kali/03-Web与API安全/04-ZAP代理与被动扫描#三种覆盖：可到达、已观察、已分析|ZAP 的三种覆盖]]，再用[[计算机知识/Kali/03-Web与API安全/03-BurpSuite工作流#用三次重放区分输入效应与环境漂移|三次对照]]控制环境漂移。

**把难点连起来。** [[计算机知识/Kali/03-Web与API安全/13-HTTP中间层与消息解释#缓存键是对请求划分等价类|缓存键的等价类]]决定哪些请求可能共享响应，[[计算机知识/Kali/01-系统与网络基础/07-HTTP浏览器会话与信任边界#缓存判断要把存储许可、缓存键和新鲜度分开|缓存新鲜度计算]]决定已存响应何时仍可复用；两者是不同问题。[[计算机知识/Kali/03-Web与API安全/10-TLS证书与服务配置评估#SNI、HTTP Host 与 ALPN 分别做什么|SNI、Host 与 ALPN]]又分别关联握手选择、应用路由和协议协商，不能统称“主机名验证”。

**完成标准。** 对两个租户读取同一编号报告的例子，分别解释业务对象键、缓存键与身份来源；对浏览器与重放工具响应不同的情况，列出必须保持一致的变量。不能用源站单次授权正确，替代整条响应路径的授权分析。

## 三、认证通过却没有权限：到底接受了谁的什么证明

先读[[计算机知识/Kali/03-Web与API安全/08-认证会话越权与API测试#OAuth与OIDC：先分清谁接收哪种凭证|OAuth/OIDC 的接收方与凭证类型]]，再读[[计算机知识/Kali/04-服务身份与主机评估/03-LDAPKerberos与AD基础#票据是给服务看的封装，认证器证明当前使用者持有会话材料|Kerberos 中的封装与持有证明]]。两者不是同一协议，但都需要区分凭证面向谁、证明什么、在何种上下文中被接受。

**工具分工。** 协议客户端观察特定交互；Impacket 提供协议实现与示例客户端，NetExec 组织多目标流程，BloodHound 将采集到的关系用于图分析。连接顺序是[[计算机知识/Kali/04-服务身份与主机评估/04-ImpacketNetExec与身份评估#库、协议客户端和批量框架的职责边界|库、客户端与框架]] → [[计算机知识/Kali/04-服务身份与主机评估/04-ImpacketNetExec与身份评估#成功标记背后的谓词必须可写成完整句子|把成功标记写成谓词]] → [[计算机知识/Kali/04-服务身份与主机评估/05-BloodHound权限图与修复验证#关系图与状态转移图：箭头连得上还需要条件同时成立|关系图与可执行条件]]。

**把难点连起来。** [[计算机知识/Kali/04-服务身份与主机评估/07-Linux权限边界与配置审计#ACL 的有效权限不是把所有允许项相加|Linux ACL 的匹配规则]]、[[计算机知识/Kali/04-服务身份与主机评估/08-Windows权限边界与本机审计#用请求权利集合逐步读DACL|Windows 请求权利集合]]和[[计算机知识/Kali/04-服务身份与主机评估/09-数据库服务与最小权限审计#登录角色、继承权限与当前角色不应合成一个名字|数据库角色与当前身份]]都问谁能对哪个对象做什么，却使用不同的主体、继承和匹配规则。只能迁移提问方式，不能照搬某平台的判定算法。

**完成标准。** 分别解释“密码被接受”“会话已建立”“某对象可读”“状态确实修改”需要什么证据。对图上两条边的有效时间不相交的情况，说明静态连通为什么不足以证明同一时刻存在可走路径。接下来再读现代 API 的原子状态变更，不把权限判断函数当成已提交事务。

## 四、口令工具跑完了：搜索了什么，成功概率又是什么

先从[[计算机知识/Kali/05-密码无线与专门领域/01-哈希口令KDF与估算#非均匀口令分布为什么改变“平均破解时间”|非均匀猜测分布]]读到[[计算机知识/Kali/05-密码无线与专门领域/01-哈希口令KDF与估算#三种熵回答三个不同问题|熵、最大概率与猜测排名]]。这些量回答的问题不同；密码长度、字符集合、分布假设和实际候选顺序必须明确。

**工具分工。** Hashcat/John 的候选生成、格式解析、摘要计算、设备后端和结果缓存是不同环节。沿[[计算机知识/Kali/05-密码无线与专门领域/02-HashcatJohn与离线审计#把计算过程拆成可观察的流水线|离线计算流水线]] → [[计算机知识/Kali/05-密码无线与专门领域/02-HashcatJohn与离线审计#速度比较必须先保证实际计算的是同一个问题|可比较的计算速度]] → [[计算机知识/Kali/05-密码无线与专门领域/01-哈希口令KDF与估算#Argon2的m、t、p：内存、遍数与并行通道不能互换|Argon2 的内存参数]]理解，不以速度数字代替同一问题的定义。

**把难点连起来。** 线上 Hydra/Medusa 类工具还依赖[[计算机知识/Kali/05-密码无线与专门领域/03-HydraMedusa与认证控制验证#协议模块在判断什么，认证系统又在判断什么|认证响应分类]]与[[计算机知识/Kali/05-密码无线与专门领域/03-HydraMedusa与认证控制验证#限流是状态随时间变化，不是一个固定错误码|随时间变化的限流]]。无线捕获中的认证材料则有特定协议前提，见[[计算机知识/Kali/05-密码无线与专门领域/04-WiFi协议与Aircrackng离线分析#PMK、PTK与认证信息：不要把所有密钥叫作WiFi密码|PMK、PTK 和认证信息]]。离线资源预算不能照搬到线上身份系统。

**完成标准。** 对同一组非均匀概率，分别求前两次猜测成功率和平均猜测次数；解释加盐、增加 KDF 成本、改变用户选择分布各改变了哪一项，而不是把它们一律叫作“增加熵”。

## 五、镜像、目录列表和内存视图矛盾：重建过程哪里可能不同

先读[[计算机知识/Kali/06-取证逆向与检测/01-取证流程镜像与时间线#哈希的三种保证不能混在一起|哈希、来源与采集完整性]]，再读[[计算机知识/Kali/06-取证逆向与检测/02-SleuthKitAutopsy与文件恢复#从目录名到字节：四个对象之间的连接|名字到元数据再到字节]]。完整保留一次工具输出，只保留了一个派生结果；它的解释还依赖输入来源和解析条件。

**工具分工。** Sleuth Kit/Autopsy 解释文件系统结构；PhotoRec/Foremost 类 carving 主要依赖内容特征；Volatility 用地址层和符号解释内存结构；Binwalk 定位候选嵌套内容，ExifTool 读取具体格式的元数据。按[[计算机知识/Kali/06-取证逆向与检测/02-SleuthKitAutopsy与文件恢复#文件系统恢复与 carving 为什么会给出不同答案|文件系统恢复与 carving]] → [[计算机知识/Kali/06-取证逆向与检测/03-Volatility3与内存证据#地址翻译层与结构解释层不是同一件事|地址翻译与结构解释]] → [[计算机知识/Kali/06-取证逆向与检测/04-文件元数据Binwalk与ExifTool#嵌套内容、候选偏移与实际解包分别意味着什么|嵌套内容与解包偏移]]比较它们的输入与单位。

**把难点连起来。** [[计算机知识/Kali/06-取证逆向与检测/03-Volatility3与内存证据#pslist 与 psscan 的差集是待解释集合|pslist 与 psscan 的差集]]首先产生待解释集合；[[计算机知识/Kali/06-取证逆向与检测/01-取证流程镜像与时间线#同一时钟的共同偏差，为什么可能在相减时消失|共同时间偏差的消去]]则要求比较误差是否共享。重复引用同一元数据生成的多份报告，不会自动产生独立证据。

**完成标准。** 对“目录项存在但内容导出异常”“扫描到结构但不在活动链表”“两个时间戳先后不可靠”分别写出输入、解释层、替代原因和可增加的独立观察。不要直接将任一差异升级为恶意行为结论。

## 六、反编译结果很像源码：为什么仍需要校验

从[[计算机知识/Kali/06-取证逆向与检测/05-GhidraRadare2与静态逆向#从指令到伪代码：控制流与数据流的两条线|控制流与数据流]] → [[计算机知识/Kali/06-取证逆向与检测/05-GhidraRadare2与静态逆向#SSA 的合流不是把两个分支的值相加|SSA 合流的选择语义]] → [[计算机知识/Kali/06-取证逆向与检测/05-GhidraRadare2与静态逆向#位模式的数值解释会改变比较结果|位模式的不同数值解释]]连续阅读。先理解表示转换，再判断一个高层表达是否保留了原指令的条件与类型。

**工具分工。** Ghidra/Radare2 支持静态分析；GDB 观察实际暂停的执行状态；strace 观察系统调用接口；Sanitizer 对某些错误建立运行判据；模糊器寻找能触发这些判据的输入。读[[计算机知识/Kali/06-取证逆向与检测/06-GDBGefStrace与动态观察#调试器、系统调用跟踪和业务日志是三种观察粒度|三种观察粒度]]与[[计算机知识/Kali/06-取证逆向与检测/09-模糊测试Sanitizer与崩溃归因#搜索策略、覆盖反馈与错误判据是三个部件|搜索、反馈和错误判据]]，不要把“覆盖更多”写成“程序已经正确”。

**把难点连起来。** [[计算机知识/Kali/06-取证逆向与检测/05-GhidraRadare2与静态逆向#在一个装载段里完成地址换算，再故意越界一次|文件偏移与内存地址]]解决对象位置，[[计算机知识/Kali/05-密码无线与专门领域/07-AndroidADBJadx与移动应用分析#从看到常量到确认安全问题还缺少使用路径|常量出现与实际使用]]解决数据流是否到达安全相关操作。两者都要求保留中间连接，不能从一个可见字符串直接跳到漏洞。

**完成标准。** 解释两个分支的值为什么在合流处是选择而非相加，说明同一字节作为有符号与无符号数时比较可能如何改变；指出静态推断和一次动态运行分别没有覆盖什么。

## 七、告警少了或扫描通过：是风险降低，还是分母变了

先阅读[[计算机知识/Kali/06-取证逆向与检测/07-YARA日志与检测规则#一条规则的完整含义包含扫描对象|规则扫描对象]]与[[计算机知识/Kali/06-取证逆向与检测/08-SuricataZeek与网络检测#包、流、应用事务与业务动作：四个计数单位|包、流、事务与业务动作]]。规则匹配的是特定表示，统计结果还必须保留任务完成状态和观察单位。

**工具分工。** YARA 面向规则选定的文件或其他扫描输入；Suricata 在配置、规则与运行模式下分析网络事件；Zeek 提供协议行为记录；Nuclei 依赖具体模板请求和匹配器；漏洞平台还涉及目标、凭据与知识库。沿[[计算机知识/Kali/02-信息收集与网络测量/07-漏洞扫描NucleiGreenbone与复核#读懂 matcher 的逻辑，才能读懂告警|matcher 的逻辑]] → [[计算机知识/Kali/06-取证逆向与检测/08-SuricataZeek与网络检测#Sticky buffer 改变的是匹配对象，不只是速度|协议字段缓冲区]] → [[计算机知识/Kali/06-取证逆向与检测/07-YARA日志与检测规则#检测覆盖率与分类指标应联合报告|完成覆盖与分类指标]]阅读。

**把难点连起来。** [[计算机知识/Kali/02-信息收集与网络测量/07-漏洞扫描NucleiGreenbone与复核#严重性、利用可能性与本地处置顺序分开记录|严重性、概率和本地处置]]不同于[[计算机知识/Kali/05-密码无线与专门领域/06-容器Kubernetes与IaC审计#SBOM到漏洞结论之间有四次匹配|SBOM 到漏洞的匹配]]；后者又不同于[[计算机知识/Kali/05-密码无线与专门领域/06-容器Kubernetes与IaC审计#摘要、签名与安全审查是三种证据|摘要与签名]]。告警、实际阻断、已修复和没有暴露，是四类需要分别举证的说法。

**完成标准。** 对扫描输入 100、完成 80、跳过 15、失败 5 的例子，分别说明能算和不能算的指标。再用[[计算机知识/Kali/00-导航与方法/04-从观察到结论的安全方法#零次发现能支持多强的阴性结论|零次发现的条件化推断]]检查：哪些情况可以做二项模型估计，哪些情况连概率模型的前提也没有。

## 如何把路线转成自己的理解记录

每次只选择一个问题，先不用工具名称作答：写清目标命题、观察对象、关键机制、原结论依赖的条件。然后解释为何选择该工具而不选择相邻工具，预测一种正例和一种能击穿错误理解的反例。最后用[[计算机知识/Kali/07-综合实验/08-自检题与答案定位#理论联结自检：32 个可解释的判断|跨工具理论自检]]核对，记录自己缺失的是概念、推导还是观察。
