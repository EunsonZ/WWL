# 压缩原理：熵编码、字典编码与有损压缩

## 本课目标

学完后，你能从“冗余”而非“神奇缩小”理解压缩；区分无损和有损的验收标准；解释 Huffman、算术/范围编码、LZ 字典、预测/变换/量化在管线中的角色；并把压缩比、码率、质量和安全资源限制一起纳入判断。

## 直觉：压缩不是把信息凭空删掉

如果来源中 `A` 出现得远比 `Z` 频繁，为 `A` 分配短码、为 `Z` 分配长码，平均长度便可下降；如果片段反复出现，可以用“回到前面复制”代替重复写出；如果人眼/人耳不敏感的误差允许丢弃，还可以先近似再编码。它们利用的是不同冗余：统计不均匀、重复、可预测性，或感知不重要性。

没有免费午餐：对所有同长度输入都无损变短不可能。一个无损压缩器把某些输入缩短，就必须让另一些输入不变或变长；高质量密文、随机数据和已经压缩的数据常缺少可利用冗余。

## 1. 无损与有损：先声明要重建的对象

“无损”必须先回答“对哪一个对象无损”。通用压缩器常以任意输入的**字节串**为对象；媒体 codec 常以容器解出的**样本序列**为对象。后者即使样本完全恢复，也不必重建原来的容器、metadata、chunk 顺序、padding 或未使用位。

| 类型 | 解码后的目标 | 典型场景 | 关键验收 |
| --- | --- | --- | --- |
| 字节域无损压缩 | 原始输入字节逐一恢复 | 源代码、文本、数据库、归档、模型权重 | 解压字节与原始字节完全相同 |
| 媒体样本域无损 codec | 格式声明的 PCM sample frame 或像素样本逐一恢复 | FLAC、无损图像/视频 codec | 解码样本值、shape、采样率/时间基与声道/像素布局按格式契约一致；容器字节不必相同 |
| 有损压缩 | 保留业务/感知可接受的近似 | JPEG、现代照片/视频/语音 codec | 在指定任务、设备和码率下的质量指标与人工感知 |

“看起来差不多”不能证明任何一种无损；“文件更小”也不能证明有损质量足够。对模型权重，常被称为“量化”的近似与传统媒体有损压缩一样会改变数值，但误差结构、模型行为和容器开销必须单独评估，见 [[数学/60-数值计算与量化/02-量化Scale-Zero-Point-Group与误差|量化的 Scale、Zero-Point、Group 与误差]]。

## 2. 熵给出平均码长的方向，不是每个文件的承诺

离散符号来源的熵为：

$$
H(X)=-\sum_x p(x)\log_2p(x).
$$

它以 bit 为单位衡量已知分布下的平均不确定性。若符号概率接近均匀，平均上较难用短码表示；若很偏斜，则可利用频率差异。熵、交叉熵及其“平均编码代价”的完整数学定义在 [[数学/50-信息论/01-熵交叉熵KL散度与互信息|熵、交叉熵、KL 散度与互信息]]，本页只使用其工程直觉。

现实压缩器还要写入文件头、字典或概率模型，处理有限块和上下文变化，并满足可随机访问、延迟和 CPU 预算。因此熵是理论参考，不能保证一个 20 字节小文件会缩小，也不能仅凭熵估算最终容器大小。

## 3. 熵编码：把“更常见”映射为更短的比特串

### Huffman 编码

Huffman 为一组已知频率构造前缀码：没有一个码字是另一个码字的前缀，因此解码器从左到右可唯一切分。设四个符号频率近似为 `A: 1/2, B: 1/4, C: 1/8, D: 1/8`，一种合适的码可能是：

```text
A → 0
B → 10
C → 110
D → 111
```

它不是唯一答案；交换同频符号仍合法。固定长度编码每符号要 2 bit，而这个例子平均为：

```text
1/2×1 + 1/4×2 + 1/8×3 + 1/8×3 = 1.75 bit/符号
```

Huffman 的单个码字长度为整数，概率不恰好是二的负幂时会留下间隙。还必须传输/重建码表，并限制码树深度与符号数。

### 算术编码与范围编码

算术编码不为每个符号分别交付一个码字，而是把整段序列逐步缩小到 `[0,1)` 中与其概率区间对应的子区间。最后输出一个能落在该子区间内的数的比特表示；范围编码是常用的整数实现思路。它可以更贴近非二幂概率的理论码长，并可结合上下文概率模型。

关键边界是：编码器和解码器必须使用同一初始分布、同一上下文更新规则、同一有限精度/归一化约定。模型不同步会使后续所有符号失步；不可信码流还应限制输出长度和运算步骤，避免“小输入展开为巨大输出”。

## 4. 字典编码：把重复内容改写为引用

LZ 家族的核心是：若当前待输出片段在已出现的窗口或字典中存在，就发出“距离、长度”引用；否则发出字面量。比如已输出 `ABCD` 后再出现 `ABCD`，概念上可写成：

```text
字面量：A B C D
引用：  (distance = 4, length = 4)
```

真实 bitstream 还会把 literal、length、distance 分配为标志与可变长编码。LZ77 常引用滑动窗口中的历史字节；LZ78/LZW 侧重增长字典。DEFLATE 等格式会组合 LZ 匹配和 Huffman 编码：**字典找重复，熵编码缩短描述重复的符号**，二者不是竞争关系。

字典方法对重复日志、文本模板和相近块常有效；对短小、随机、已压缩或加密数据可能变长。解压器要限制窗口、引用合法性、递归/嵌套层数、总输出字节与压缩比，防止压缩炸弹。

## 5. 有损媒体压缩：预测/变换后，再量化

有损图片、音频和视频通常不是“直接删掉几个字节”，而是根据信号结构分阶段处理：

```text
样本 → 预测或变换 → 系数/残差 → 量化（有损） → 熵编码（无损） → 码流
```

- **预测**：用邻近像素、先前音频样本或前后视频帧预测当前值，只发送较小的残差；
- **变换**：把相关的时域/空间域样本转到更集中的频域或其他基；能量集中后更容易分配比特；
- **量化**：把连续或高精度系数映射到较粗网格，是经典有损失真的主要来源；
- **熵编码**：对量化后的零、短残差和常见符号再无损压缩。

量化步长越大，码率通常更低而误差通常更大；但“误差多大”还与内容、感知模型、码率控制、预测结构和解码后处理有关。视频 codec 还会引入帧间预测与运动补偿，随机访问、延迟和错误传播会影响编码结构选择。

> [!warning] 不要把“熵编码”叫作有损
> Huffman、算术/范围编码和 LZ 的解码目标是精确还原其输入；有损性通常由量化、降采样、裁剪或其他近似步骤引入。一个媒体文件可以同时包含有损量化与之后完全无损的熵编码。

## 6. 比率、码率、质量与资源：比较时先固定条件

- **压缩比**常写作 `原始大小 / 压缩后大小`；必须说明是否计入容器、索引和元数据。
- **码率**是每秒使用的 bit 数；同样的码率在不同长度、内容或 codec 设置下不代表相同质量。
- **质量指标**（如像素误差或感知指标）只能在明确参考、色彩/采样处理、内容集和版本时比较；数值高不必然等于人更满意。
- **速度、内存、延迟、随机访问和错误恢复**往往与压缩比相互拉扯。

压缩既是性能问题也是安全边界。解析不可信压缩数据应先设定：压缩输入最大值、声明/实际输出最大值、最大嵌套层数、CPU/时间预算和取消机制；在写入磁盘前执行这些限制，避免解压炸弹填满资源。

## 练习

1. 对 `AAAAABCD`，说明 Huffman 与 LZ 各可能利用什么冗余；不要假设它们一定在这么短的输入上减少总文件大小。
2. 某 JPEG 文件的熵编码阶段无损。为什么重新解码再保存 JPEG 仍可能继续失真？指出有损步骤在哪里发生。
3. 解释为什么“先加密再 gzip”通常不压缩，以及为什么“先 gzip 再加密”也仍需要长度侧信道分析。
4. 为接收用户上传 `.zip` 的服务写出至少五项解压前/中限制与一个成功标准。

## 成功标准

- 我会先声明重建对象：字节域无损验收原始字节；媒体样本域无损验收解码样本与其格式契约；有损压缩再定义任务和质量预算。
- 我能区分 Huffman 的前缀码、算术/范围编码的区间思想、LZ 的重复引用，以及它们可以组合的原因。
- 我知道预测/变换本身不必有损，量化常是有损误差的关键来源，而熵编码通常是无损的后续步骤。
- 我不会在未写明内容集、设置、容器开销和资源限制时，宣称某压缩算法“更好”。
