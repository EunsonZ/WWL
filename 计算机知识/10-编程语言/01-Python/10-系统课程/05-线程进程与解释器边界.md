# 线程、进程与解释器边界：GIL 不是同步设计

> **学习位置**：[[计算机知识/00-开始/课程地图/04-Python-课程地图|Python课程地图]] · **适用边界**：Python 3.11+；CPython 实现细节明确注明。

## 根据瓶颈选择并发模型

线程共享地址空间，通信便宜但需要保护共享不变量；进程有独立地址空间，隔离更强但启动、序列化和数据搬运有成本；异步任务适合大量可等待操作，但不能自动并行运行 CPU 指令。选择前先测量时间花在计算、等待还是复制上。

常规带 GIL 的 CPython 中，多个 Python 线程执行 Python 字节码受到全局解释器锁限制，但许多 I/O 和扩展代码能够释放 GIL。不能据此推断“所有 Python 都只能用一个核”。Python 3.13 起提供可选 free-threaded 构建；构建方式、扩展兼容性及运行状态都需要确认，不能仅凭版本号断言 GIL 已关闭。更不能把内建容器的某次实现表现当成复合操作线程安全的语言承诺。[版本与实现边界](https://docs.python.org/3/howto/free-threading-python.html)。

## 真正需要保护的是不变量

“读取余额 → 检查足够 → 扣减 → 写回”必须作为一个协作协议维护。即使某个列表追加操作在特定实现中有内部锁，两个列表长度相等这样的跨对象约束仍不会自动受到保护。用锁将完整状态变化包起来，或让一个工作者拥有状态并通过队列接收消息。

死锁常来自持有 A 等 B，而另一个线程持有 B 等 A。规定全局锁顺序、缩短持锁区、禁止在锁中调用未知回调，比把锁换成可重入锁更根本。条件变量等待要检查谓词，事件通知不等于状态永远成立。

## 进程边界意味着序列化边界

```python
from concurrent.futures import ProcessPoolExecutor

def work(n: int) -> int:
    return sum(i * i for i in range(n))

if __name__ == '__main__':
    with ProcessPoolExecutor(max_workers=2) as pool:
        results = list(pool.map(work, [1000, 2000]))
    assert results == [332833500, 2664667000]
```

主模块保护和顶层可导入函数有助于兼容采用 spawn 等启动方式的环境。默认启动方式随平台与 Python 版本而异，不能把某一台 Linux 上的 fork 行为当成跨平台合同。把大数组随每个任务重复传入可能让序列化开销压倒计算；应考虑批处理、共享内存、内存映射或在工作者初始化时加载只读数据。

共享内存解决字节复制，不解决并发写、生命周期和崩溃恢复。父进程必须设计谁创建、谁关闭映射、谁删除命名资源。进程死亡可能发生在写了一半时，消费者需要完整性标志或版本协议。

## 性能上界要包含串行部分

若可并行部分占比为 $p$，理想的 $N$ 个执行单元加速比是

$$S(N)=\frac{1}{(1-p)+p/N}.$$

这是忽略调度与通信的上界模型。例如 $p=0.9,N=8$，得到约 $4.71$ 倍，不是八倍。现实还要加上通信、缓存竞争和负载不均；任务太细会因固定开销变慢。用吞吐量与尾延迟同时评估，不能只看 CPU 利用率。

## 安全和可复现实验

只反序列化可信 pickle 数据；它不是普通无执行能力的数据格式。子进程命令优先用参数数组而非拼接 shell 字符串。线程池或进程池都应有数量上限与退出策略，不能在每个请求里无界创建。

练习：把同一计算拆成 10、100、10000 个任务，测量总时间并解释拐点。预期不要求某个平台的固定赢家；应报告任务大小、启动方式、CPU 数量、数据体积和重复次数。再给共享计数器增加锁，检验最终值，但说明通过有限次数测试不能证明不存在数据竞争。
