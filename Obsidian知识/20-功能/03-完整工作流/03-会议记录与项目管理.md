# 会议记录与项目管理

会议笔记的成果不是“记录得很完整”，而是让项目目标、讨论证据、决定和行动可以彼此追溯。

本练习使用 [[Obsidian知识/30-实践/03-示例项目/周末读书会/00-周末读书会项目主页|00-周末读书会项目主页]]、[[Obsidian知识/30-实践/03-示例项目/周末读书会/01-读书会启动会议|01-读书会启动会议]]、[[Obsidian知识/30-实践/03-示例项目/周末读书会/人物/林晨|林晨]]、[[Obsidian知识/30-实践/03-示例项目/周末读书会/人物/周野|周野]] 和 [[Obsidian知识/30-实践/03-示例项目/周末读书会/决定/下次分享主题|下次分享主题]] 组成的示例网络。

## 项目主页：稳定信息的唯一入口

项目主页至少回答：

- 为什么做？
- 当前状态是什么？
- 谁参与？
- 下一里程碑是什么？
- 最近的决定、会议和资料在哪里？

```yaml
---
type: project
status: active
topics:
  - reading
participants:
  - "[[林晨]]"
  - "[[周野]]"
---
```

项目主页不必复制每场会议内容。用链接和嵌入的 Base 展示相关文件即可，例如 [[Obsidian知识/40-视图/02-Bases/示例项目资料.base|示例项目资料.base]]。

## 会前：从模板创建结构

使用 [[Obsidian知识/90-资源/01-模板/核心模板/会议|核心模板-会议]] 新建一篇练习会议；若已经学过 Templater，也可以为同一结构增加动态提示。至少包括：

```markdown
## 目标
这次会议结束时必须得到什么？

## 参与者
- [[林晨]]
- [[周野]]

## 议题

## 讨论

## 决定

## 行动项
```

在页面属性中将 `project` 指向 `[[00-周末读书会项目主页]]`。这一属性让 Base 可以筛选会议，正文链接则让 Backlinks 可追溯上下文。

## 会中：区分讨论、决定和行动

- **讨论**保留必要证据和分歧，不要求逐字记录。
- **决定**说明选择了什么、为什么、何时重新评估。
- **行动**必须有动词、负责人和可验证结果。

```markdown
## 决定

- 选择 [[下次分享主题]] 作为下一场内容，因为它能连接三张现有概念卡。

## 行动项

- [ ] [[林晨]] 整理三条分享要点
- [ ] [[周野]] 在下一场前补充 [[Obsidian知识/30-实践/03-示例项目/周末读书会/概念/渐进式总结|渐进式总结]] 的例子
```

重要决定可抽成独立笔记，类型为 `decision`，并同时链接会议与项目。这样未来改变决定时，理由不会消失在旧会议里。

## 会后：把结果送回项目

1. 检查行动项是否明确。
2. 把独立决定链接到项目主页。
3. 在项目主页更新下一里程碑，而不是复制整篇会议。
4. 从人物页和项目页的 Backlinks 检查关系。
5. 在 [[Obsidian知识/40-视图/01-Canvas/周末读书会规划.canvas|周末读书会规划.canvas]] 中使用真实会议/决定笔记卡更新计划。

## 原生与插件增强

| 需求 | 最小方式 | 可选增强 |
| --- | --- | --- |
| 固定会议结构 | 核心 Templates | Templater 动态提示 |
| 查询项目相关笔记 | Bases | Dataview |
| 简单行动项 | checkbox | Tasks |
| 行动需要独立正文/属性 | 普通笔记 | TaskNotes |
| 快速创建会议 | 新建 + 模板 | QuickAdd |

> [!practice] 创建第二场读书会会议
> 必须链接项目、两位参与者、一个概念和一个决定；写两个带负责人的行动项；最后从项目主页的 Backlinks 找回会议。

> [!success] 成功标准
> 项目主页显示当前状态和下一步；会议有目标、决定和行动；决定能追溯到理由；人物和项目 Backlinks 中能找到会议；Canvas 引用真实笔记而非复制内容。
