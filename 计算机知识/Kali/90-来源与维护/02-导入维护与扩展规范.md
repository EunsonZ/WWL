# 导入维护与扩展规范

## 首先保护现有内容

首次导入规则见 [[计算机知识/Kali/README-导入与范围|README]]。本包没有你的原Vault状态，因此不要直接覆盖同名Kali文件；先比较文件路径、标题、用户修改与链接语义。重命名不是单纯文件移动，正文、属性、标题/块链接、Canvas和代码附件都可能受影响。[^s1]

本包所有新链接都使用`计算机知识/Kali/...`完整路径。迁移到另一目录时，需要建立路径映射并验证，不可用“文件名相同就算对”的回退掩盖错误。路径未改但正文语义改变，也要审阅旧链接是否仍表达原关系。

## 保持单一权威解释

新增内容先问：是在解释旧页已有问题，还是确有独立职责？例如HTTP状态码应在HTTP页解释，Nmap页只保留对照；SQL页与授权页互相链接，但不复制两个完整安全模型。长源码保存在`07-综合实验/代码`，正文只解释关键路径；生成夹具和expected.json同步更新，不能只修文档不修测试。

本包不自动创建待办课程，不从未来路线推导写入许可。大专题扩展需使用真实需求和可复核输入，在合适的已有页中补齐缺口，避免“一条命令一页”。

## 元数据的稳定含义

`domain`、`type`为文本；`stage`若存在是整数；`prerequisites`、`sources`、`aliases`为列表。`content_status`只描述材料可用性，`evidence_status`只描述有记录的核验范围。学习成果保存在自己的记录中，不从编辑量或测例数推断。Obsidian属性具体显示由本机应用版本和配置决定，本包未修改全局属性文件。[^s2]

核心搜索与Canvas只提供可重建入口，正文和源码才是信息来源。无需Dataview、Templater、第三方主题或API连接器；没有隐藏安装步骤。实际UI未测试，就保留这一事实而非补一个“通过”。

## 运行附带的局部检查器

[[计算机知识/Kali/90-来源与维护/工具/check_vault.py|check_vault.py]] 仅检查这个新专题：元数据、代码围栏、完整路径、标题/块目标、Canvas、可达性、先修环和分享目录禁入项。它不是完整Obsidian解析器，也不是上传契约的全部机器实现。

```bash
# 在解压后的Vault根目录执行；本机需有Python与PyYAML。
# 检查器不自动安装依赖、联网或修改知识页。
python3 计算机知识/Kali/90-来源与维护/工具/check_vault.py \
  . --report kali-local-validation.json
```

报告显式写到你指定的路径；读取真实Vault时结果可能与本包不同，应审阅而非机械覆盖。`--self-test`可运行检查器自己的正反例。未安装PyYAML会报依赖缺失，不静默跳过类型验证。[^s3]

## 分享包与私密备份分开

只从明确白名单复制知识页、原始授权材料中可公开部分、源码和合成夹具。不要把Vault整体打包后仅依赖`.gitignore`。审查私钥、token、Cookie、potfile、真实PCAP、内存镜像、用户日志、历史配置、符号链接和压缩路径；本包的模式扫描只覆盖特定特征，不是所有秘密检测的保证。

`MANIFEST.sha256`覆盖归档中除自身外的每个文件，避免自引用。从解压后包含`计算机知识`目录的根目录，可运行 `sha256sum -c 计算机知识/Kali/MANIFEST.sha256` 逐项核对。清单校验不应修改任何正文或源码；一旦修改文件，就应在明确的新分享版本中重新生成清单。最终ZIP也提供单独SHA-256；它检查一致性，不构成发布者签名。回滚本包新建文件时先核对你后续编辑的差异，不删除与此次导入无关内容。
