## 先把生命周期看成使用范围约束

```rust
fn select<'a>(x: &'a str, y: &'a str, first: bool) -> &'a str {
    if first { x } else { y }
}
```

它不宣称两个原字符串同时销毁，而是让调用者证明返回引用在使用范围内，无论来自 x 还是 y 都有效。函数体可以选任一输入，调用方就不能只按实际某次 `first=true` 猜测更长寿命。生命周期标注传递的是接口层关系，不是运行时计时器。[^rust-life]

若返回值始终来自 x，应写成只把返回关系绑定到 x 的签名，而不是为了“看上去统一”把所有输入都套同一个 `'a`。过度关联会使本来可行的调用被不必要地限制。

把这条关系用于 [[计算机知识/10-编程语言/04-Rust/10-系统课程/11-类型化数据管道与标准库实作#谁有数据，谁只是看一眼|类型化测量任务的 Batch 接口]]：`records(&self) -> &[Record]` 的结果借用 Batch，不能跨 Batch 的冲突修改继续使用；`into_records(self) -> Vec<Record>` 则转移拥有权，结果不借用解析时的码文本。工程入口 [[计算机知识/80-实践/10-Rust/01-类型化测量任务/README|源码与本轮验证]] 同时保留因冲突借用而被拒绝的用例和“最后使用 view 后再修改”的通过例。读完该例，再回本节解释返回值到底依赖哪个输入对象；它不需要 HRTB 或把借用改为 `'static`。

## 重借用为什么不会制造第二份任意写权限

```rust
let mut number = 10;
let outer = &mut number;
{
    let inner = &mut *outer;
    *inner += 5;
}
*outer += 1;
assert_eq!(number, 16);
```

`inner` 是从 `outer` 派生出来的较短可变借用。在其有效使用期间，不能同时通过 outer 做冲突访问；inner 结束后，outer 恢复可用。可以把它看成暂时转交一部分使用时段，而不是复制了无限制的写许可。

现代借用检查常依据实际使用点缩短借用范围，而非机械延续到整个词法花括号末尾。这就是许多“先读，读完再修改”的代码能通过检查的原因；但不要把它理解成编译器会分析任意业务不变量来证明两个索引不同。[^rust-borrow]

### 两个索引不同，为什么仍可能报错

`&mut xs[i]` 与 `&mut xs[j]` 在语言表面上来自同一个切片，可变索引借用的通用规则未必能利用 `i != j`。先验证顺序，再用 `split_at_mut` 把一个切片分成两个不重叠区域，可以由安全接口提供需要的证明。

```rust
fn add_pair(xs: &mut [i32], i: usize, j: usize) -> Result<(), &'static str> {
    if i >= xs.len() || j >= xs.len() || i == j { return Err("bad indices"); }
    let (lo, hi) = if i < j { (i, j) } else { (j, i) };
    let (left, right) = xs.split_at_mut(hi);
    left[lo] += 1;
    right[0] += 1;
    Ok(())
}
```

这个演示还假定加一不会溢出 `i32`。对外部任意输入的库应使用 `checked_add` 并决定失败原子性，不能把借用安全误写成所有数值和业务边界都安全。

## 方差的最小反例：一个能写回的槽位

较长生命周期共享引用通常可在只需要较短引用的地方使用。困难在于嵌套可变引用：假设允许把 `&mut &'static str` 当成 `&mut &'short str`，被调用者就能写入只活到 short 结束的字符串引用。返回后，原槽位类型仍声称它保存 `'static` 引用，承诺被破坏了。

因此 `&'a mut T` 对自身借用期 `'a` 与对所指类型 T 的方差不同：对 `'a` 协变，对 T 不变。`&'a T` 通常对两者协变。共享引用若指向 `UnsafeCell<T>`，内部可变性又会限制相关方差。不要把这张表简化成“mutable 一律不变”。[^rust-variance]

这和 [[计算机知识/10-编程语言/05-TypeScript/10-系统课程/09-条件类型never与可选属性推演|TypeScript 可写类型关系]]、[[计算机知识/10-编程语言/02-C++/10-系统课程/09-推导引用折叠与完美转发|引用与推导]] 有相似的读写直觉，但语言的健全性目标和静态保证并不相同，不能一比一套结论。

## HRTB 是量词换了位置

`for<'a> Fn(&'a str) -> usize` 要求一个回调能处理每一次合法提供的短借用；外层预先指定 `'a` 的回调约束则只承诺那个关系。前者像“任意给你一个合适寿命的借用都能工作”，后者像“我们事先约定某个寿命”。

理解量词后，`T: 'static` 也不神秘：拥有数据且不携带短借用的 `String` 可满足它，但这个值仍可在下一行被 drop。它并不等于泄漏到进程结束，也不应通过给所有引用添加 `'static` 来消除真正的拥有关系问题。

## 自引用难点不要归错原因

如果结构体内部有一个指针直接指向另一个内联字段，移动整个结构体会改变那个字段的地址。若内部关系指向 `String` 的堆缓冲区，单纯移动 String 的指针、长度、容量这组元数据通常不搬动字符缓冲区；风险更多来自扩容、替换、释放和无法直接表达的自引用借用关系。

两种情形都需要审计，但不能用“移动 String 必然移动堆字符”解释它们。常见的简化设计是拥有源缓冲区、只存字节范围，用 `get(range)` 检查 UTF-8 边界。需要长寿命共享时用 `Arc<str>` 加范围；需要特定地址稳定性时再研究 [[计算机知识/10-编程语言/04-Rust/10-系统课程/10-Pin投影任务所有权与取消协议|Pin 的合同]]。
