# 栈、队列、双端队列与单调结构

## 本课目标

学完后，你应该能够：

- 用端点操作契约区分栈、队列和双端队列；
- 写出内容、边界和空结构的不变量；
- 用调用栈和任务调度说明 LIFO/FIFO 的意义与边界；
- 用“每项最多入/出一次”分析单调结构；
- 区分逻辑接口和数组、环形缓冲或链表实现。

## 1. 首先是受限接口，不是某块特定内存

数组和链表主要描述存储表示；栈、队列、双端队列描述的是**允许从哪一端操作**。同一个动态数组可以实现栈或双端队列，同一链表也可实现队列。限制接口能避免在不应插删的任意位置误操作。

| 抽象 | 可操作端 | 顺序规则 | 常见操作 |
| --- | --- | --- | --- |
| 栈 stack | 同一端（顶端） | LIFO，后进先出 | push、pop、top/peek |
| 队列 queue | 尾加入、头取出 | FIFO，先进先出 | enqueue、dequeue、front/peek |
| 双端队列 deque | 两端都可加入/取出 | 不强加单一方向 | push/pop front/back |

空栈 `pop` 或空队列 `dequeue` 没有元素。接口必须明确返回错误/状态、可空结果或异常；不能用任意默认值悄悄伪装成功，因为默认值可能是合法数据。

## 2. 栈：只处理最近压入的工作

若栈从底到顶为 `[a₀, a₁, ..., aₖ₋₁]`：

- `push(x)` 后为 `[a₀, ..., aₖ₋₁, x]`；
- 非空 `top()` 返回 `aₖ₋₁` 且不改变内容；
- 非空 `pop()` 返回并移除 `aₖ₋₁`。

核心不变量：逻辑顺序由入栈顺序决定，只有栈顶可读写。用动态数组末尾实现时 push 是摊还 `Θ(1)`，pop 通常为 `Θ(1)`；用链表头实现时头插头删也为 `Θ(1)`。表示不同，LIFO 契约相同。

### 手工例子：括号匹配

从左到右读：左括号压栈；右括号要求栈非空且栈顶类型匹配，然后弹栈；读完必须为空。

```text
输入:  ( [ ] )
栈:    [] → [(] → [(, [] → [(] → []

输入:  ( ]
读到 ] 时栈顶为 (，类型不匹配，失败
```

循环不变量：处理完任一前缀后，栈恰好保存该前缀尚未匹配的左括号，顺序与出现顺序一致。每个字符至多压栈一次、弹栈一次，因此时间 `Θ(n)`，最坏辅助空间 `Θ(n)`。

## 3. 调用栈：为什么嵌套调用恢复时是 LIFO

函数调用需保存返回位置、局部状态和尚未结束的作用域。`A` 调用 `B`、`B` 调用 `C` 时，只有先完成 `C` 才能恢复 `B`，再恢复 `A`：最近暂停的调用最先恢复。

```text
调用 A
  A 调用 B
    B 调用 C
    C 返回 → 恢复 B
  B 返回 → 恢复 A
A 返回
```

这是控制流模型，不是所有平台上一模一样的内存布局。ABI、寄存器保存、尾调用优化和协程实现会变化；不要把调用栈与某种语言的自动存储期或固定地址图等同。系统接口见 [[计算机知识/30-计算机系统/03-ABI调用约定与静态动态链接|ABI、调用约定与静态/动态链接]]，资源生命周期见 [[计算机知识/10-编程语言/02-C++/04-栈堆RAII与智能指针|栈、堆、RAII 与智能指针]]。

递归深度为 `d` 时，尚未返回的调用帧通常需要 `Θ(d)` 辅助栈空间。递归时间和递归栈空间是独立指标：一个算法可能线性时间却线性深度，也可能指数时间却只有线性深度。

## 4. 队列：FIFO 是顺序，不是完整调度政策

队列从头到尾为 `[a₀, ..., aₖ₋₁]`：`enqueue(x)` 在尾部加入；非空 `front()` 返回 `a₀`；`dequeue()` 返回并移除 `a₀`。消息缓冲、打印任务与广度优先搜索的待处理节点都需要这种“等待最久者先离开”的顺序。

单核、不可抢占且任务需求相近时，FIFO 是直观公平规则；真实操作系统还需处理优先级、时间片、I/O 阻塞、多核平衡与实时期限，可能使用多个队列或优先队列。因此“调度器有队列”不等于“所有任务严格按到达顺序完成”。进程与作业控制入口见 [[计算机知识/20-操作系统/01-Linux/06-用户权限进程与作业控制|用户、权限、进程与作业控制]]。

若紧凑数组每次 `dequeue` 后都把剩余元素左移，单次最坏 `Θ(n)`，连续 `n` 次可达 `Θ(n²)`。维护 `head` 与 `tail` 逻辑位置，或使用环形缓冲，可避免每次搬移。

## 5. 环形缓冲区：用模运算复用槽位

容量为 `C` 的数组维护 `head`（下次取出位置）和 `size`（现有元素数）。第 `j` 个逻辑元素在：

```text
physical_index(j) = (head + j) mod C, where 0 ≤ j < size
```

入队位置为 `(head + size) mod C`；出队后令 `head ← (head + 1) mod C`、`size ← size - 1`。记录 `size` 可区分空（0）与满（`C`），避免 `head = tail` 的歧义。

```text
容量 5，head = 3，size = 4
物理槽位:  0   1   2   3   4
内容:       B   C   _   X   A
逻辑顺序:   X → A → B → C
```

不变量：恰有 `size` 个按模 `C` 连续的有效元素，`head` 指向首元素，其余槽位不属于队列。满时应返回无空间，除非接口明确约定覆盖旧元素；可增长的环形缓冲扩容时要按逻辑顺序复制，旧引用也可能失效。

## 6. 双端队列：两端均可成为工作端

双端队列允许两端插入、删除。它可退化为栈（只用同端）或队列（两端各用一个），也适合滑动窗口：队首淘汰过期候选、队尾淘汰不再有希望的候选。它可由双向链表、环形数组或分块数组实现；不同语言的 `deque` 容器不承诺相同布局、索引复杂度或失效规则，须查实际库文档。

## 7. 单调栈：删除已不可能有答案的候选

求每个元素右侧第一个更大值时，扫描数组并维护从底到顶**非递增**的未决索引栈：当前值 `x` 到来时，只要栈顶值小于 `x`，就弹出该位置并记 `x` 为其答案；随后压入当前索引。因为规则只弹出严格小于 `x` 的值，相等值会一同留在栈中。结束后仍在栈中的位置没有右侧更大值。

```text
values = [2, 1, 4, 3]
读 2: [2]
读 1: [2, 1]
读 4: 弹 1（答案 4），弹 2（答案 4），压 4 → [4]
读 3: [4, 3]
```

不变量：处理完前缀后，栈中索引递增、对应值非递增，且每个栈内元素尚未遇到右侧更大值。虽然每轮有 `while`，每个索引最多压一次、弹一次，总时间仍为 `Θ(n)`。

## 8. 单调队列：滑动窗口中保留仍可能获胜的候选

对窗口宽度 `w` 求最大值，维护保存**索引**的双端队列，并使对应值从头到尾非递增：

1. 新位置 `i` 到来前，从队首移除窗口 `[i - w + 1, i]` 外的索引；
2. 从队尾移除值不大于当前值的索引：它们更早过期且不更大，已不可能成为未来最大值；
3. 将 `i` 加到队尾；队首就是当前窗口最大值索引。

保存索引是为判断过期；只存值无法知道重复值的年龄。对相等值选择“移除小于”还是“移除小于等于”会影响保留哪个副本，但只要不变量一致都能正确。

### 手工例子：窗口宽度 3

| 读入位置和值 | 队列中的索引（括号为值） | 当前完整窗口最大值 |
| --- | --- | --- |
| 0(1) | [0(1)] | 尚未形成 |
| 1(3) | [1(3)]，0 被尾部淘汰 | 尚未形成 |
| 2(1) | [1(3), 2(1)] | 3 |
| 3(2) | [1(3), 3(2)]，2 被尾部淘汰 | 3 |
| 4(0) | [3(2), 4(0)]，1 从头部过期 | 2 |
| 5(5) | [5(5)]，4、3 被尾部淘汰 | 5 |

不变量：队列索引递增、全部属于当前窗口、对应值单调；被队尾淘汰者都被更晚且不小的元素支配。每个索引最多入队一次、从一端离开一次，总时间 `Θ(n)`，额外空间至多 `Θ(w)`。

## 常见误解与边界

- **“栈就是内存的栈区。”** 栈首先是 LIFO 接口；调用栈只是一个应用。
- **“FIFO 自动保证系统公平。”** 真实调度还受优先级、抢占和资源约束影响。
- **“数组队列出队一定搬移。”** 环形缓冲可通过 head/tail 复用槽位。
- **“`head = tail` 一定为空。”** 未记录 size 或未预留空槽时，满队列也可能如此。
- **“单调结构里的 while 一定平方。”** 应按元素的入/出次数总计，而非只看嵌套文本。
- **“单调队列保存完整窗口。”** 它会删除被支配候选；完整数据需另存。

## 练习

1. 手工执行括号匹配：`([{}])`、`([)]`、`((`。每步记录栈，并用“未匹配左括号”不变量解释结论。
2. 对容量 4 环形队列执行 `enqueue(A), enqueue(B), dequeue(), enqueue(C), enqueue(D), enqueue(E)`；画出每步的 head、size 与槽位，说明最后一步是否成功取决于什么策略。
3. 对 `[5, 2, 6, 1, 4]` 维护递减单调栈，写出每项右侧第一个更大值；说明每个索引为何最多弹出一次。
4. 对 `[2, 1, 3, 4, 6, 3]`、窗口宽度 3 手工维护单调队列，给出每个完整窗口最大值，并区分队首过期和队尾支配两种删除。

## 成功标准

- 你能说明栈、队列、双端队列的端点契约并处理空结构；
- 你能用 LIFO 解释嵌套调用恢复，用 FIFO 解释但不夸大调度公平；
- 你能维护环形缓冲的 head、size 与逻辑顺序；
- 你能以每项至多入/出一次证明单调栈或单调队列的线性总时间。
