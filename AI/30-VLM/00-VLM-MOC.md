视觉语言模型（Vision-Language Model，VLM）研究如何把图像、文档、视频帧或其他视觉输入与文本表示放进同一任务流程。它能回答图中有什么、图文是否匹配、页面结构如何被读出，也能在语言模型生成前把视觉证据编码进上下文。它不是“看懂世界”的证明：模型输出可能忽略细节、误读文字、把训练集偏见投射到图片上，或在没有证据时自信补全。

本轮已补齐下列两篇核心课程，含直觉解释、主要公式、小例、图示与一手资料。原有地图保留为进阶学习和实验设计；不能把完整主题目录理解为全部研究深度、真实模型运行或 GPU 性能均已验收。共用先修：[[AI/20-LLM/20-架构/07-编码器解码器与多模态接口|编码器、解码器与多模态接口]]。

## 领域问题与边界

VLM 的核心问题可分为四层：视觉输入怎样变成有空间语义的表示；文本和视觉表示怎样对齐；语言模型怎样使用这些表示完成问答或生成；又如何证明结果来自输入而非猜测、模板或数据泄漏。图像分类、目标检测、OCR、文档理解和视频理解在输入、标注、指标与失败模式上不同，不能因都包含“视觉”而用同一分数替代全部判断。

- **任务边界**：把图文问答、图文检索、描述生成、文档/表格理解、视觉定位与多帧视频理解分别定义输入、输出与可接受错误；不要把生成文字当作对对象位置、数量或因果关系的证据。
- **模型边界**：编码器、投影层、连接器、视觉 token 压缩与语言解码器各有职责。模型可用截图中的像素，却未必能可靠地读小字、精确计数、判断时间顺序或识别图像是否被篡改。
- **部署边界**：本路线讨论学习与受控实验，不自动接入摄像头、云端识图、个人相册或生产系统。上传图片会带出 EXIF、面孔、地点、屏幕内容和第三方版权风险。

## 与 LLM 共用和不同的部分

| 层次 | 与 LLM 共用 | VLM 新增或改变的部分 |
| --- | --- | --- |
| 表示 | token 序列、位置、Transformer、投影、shape 检查 | 像素、Patch、视觉编码器、二维/多尺度位置信息与图像预处理 |
| 训练 | 损失、优化器、数据拆分、checkpoint、微调与复现 | 图文配对质量、负样本、视觉增强、跨模态对齐与多任务配比 |
| 推理 | prompt、上下文长度、解码、批处理、延迟/吞吐 | 图像解码、裁剪/缩放、视觉 token 预算、分辨率与多图/视频帧选择 |
| 评测 | 基准集、误差分析、回归测试与污染风险 | 感知、OCR、空间关系、指代、计数、跨图推理及对抗性图像的分项检查 |

## 进阶课程结构与持续学习方向

| 模块 | 计划课程 | 要回答的问题 | 可观察完成标志 |
| --- | --- | --- | --- |
| 1. 输入与表示 | 图像张量、颜色空间、尺寸、裁剪与归一化 | 模型实际收到哪些像素和 shape？ | 能追踪一张图从文件到 batch 的每一轴 |
| 2. 空间编码 | Patch、卷积编码器、ViT 与位置表示 | 局部、全局和位置怎样保留或丢失？ | 能估算视觉 token 数与分辨率代价 |
| 3. 图文对齐 | 对比学习、匹配、投影层与连接器 | 两种模态如何相互可比较？ | 能区分检索目标与生成目标 |
| 4. VLM 架构 | 双塔、编码器—解码器、视觉前缀与跨注意力 | 视觉证据在哪一步进入语言模型？ | 能画出数据流并标出 shape |
| 5. 数据与训练 | 图文数据、清洗、去重、SFT 与参数高效微调 | 配对、标注和切分怎样制造泄漏或偏见？ | 能写出数据卡与训练配置边界 |
| 6. 推理与系统 | 图像预处理、批处理、缓存、量化与服务边界 | 为什么同一模型在不同图片上显存和延迟不同？ | 能记录端到端延迟与显存峰值 |
| 7. 评测与可靠性 | 感知、OCR、空间、幻觉、鲁棒性与人工复核 | 一个总分遗漏了什么？ | 能给出分项指标、失败样本和结论范围 |
| 8. 应用治理 | 文档、辅助无障碍、检索与人机协作 | 哪些用途需要人工复核或禁止自动决定？ | 能写出数据流、保留期与退出机制 |

## 进阶实验设计

实验只使用明确可再分发、可本地保存的最小公开样本或合成图像；不自动下载权重，不采集摄像头，不上传个人文件。计划提供三层可恢复实验：

| 层级 | 设计 | 成功标准 | 不得据此声称 |
| --- | --- | --- | --- |
| CPU 概念实验 | Patch 化、坐标叠加和图文相似度的微型数组 | 输入 shape、Patch 数和手工预期一致 | 真实视觉理解或模型性能 |
| 小型离线评测 | 固定许可样本的图文匹配/OCR 分项清单 | 数据版本、切分、指标脚本和失败例均可复查 | 对开放世界、不同语言或人群的泛化 |
| GPU 推理剖析 | 同一固定样本比较分辨率、batch 与视觉 token 预算 | 记录硬件、软件、精度、峰值显存、预热后延迟与输出差异 | “某 GPU 最好”或生产容量承诺 |

硬件路线从 CPU shape 检查开始；8–16 GB 显存优先做小模型或量化推理并限制图片数/分辨率；24 GB 级别才评估较小的参数高效微调；更大训练需要先计算样本规模、序列/视觉 token 长度、激活、优化器状态和检查点空间。这是预算顺序而非兼容性或可运行承诺；统一账本见 [[AI/90-资源/03-GPU显存与资源预算表|GPU 显存与资源预算表]]，模型/工具的快速变化资料只在实际模型实验前按 [[AI/90-资源/05-官方资料与版本核验记录|一手来源核验规则]] 补入。

## 数据、隐私、许可与评测边界

- 为每份数据记录来源、许可证、再分发条件、是否允许训练/商业用途、删除或撤回机制；网页可访问不等于可训练。
- 不把人脸、身份证件、医疗影像、聊天截图、地点线索或未获许可的屏幕内容混进练习集；去除元数据不等于去除了身份风险。
- 训练集、验证集和测试集按实体、时间或来源隔离，避免近重复图像、模板题与同一网页泄漏；记录过滤规则，而不是只报告数量。
- 指标至少拆分语言、分辨率、文字大小、场景和失败类型，并保留人工复核协议。模型回答并不是事实来源；高风险决定必须由合格人员和独立证据复核。
