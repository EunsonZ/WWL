# 05 · struct、类、模板与 STL

## 本课目标

在数据结构、封装和泛型之间选择最小合适抽象。`struct` 与 `class` 的核心差别是默认访问权限；前者常表示透明数据，后者常用于维护不变量。模板在编译期按类型实例化，不等于运行时动态分发。

> [!note] 已退役的伴随实现
> 用户在本次改造前已删除 `stl.cpp`，参见 [[Logs/2026-09-04_1519-Codex-新增NewAgents协作与知识编写指南|原删除状态记录（WorkWithLLM 历史记录）]]。以下保留为历史 C++ 片段供解释模板和容器，已退出源码同步与构建合同；当前目录没有可直接重建的 `stl` 目标，不凭镜像恢复源文件。
```cpp
#include <algorithm>
#include <iostream>
#include <numeric>
#include <vector>

template <class T>
T sum(const std::vector<T>& values) {
    return std::accumulate(values.begin(), values.end(), T{});
}

int main() {
    std::vector<int> values{4, 1, 3, 2};
    std::ranges::sort(values);
    std::cout << sum(values) << "\n";
}
```

`std::vector` 管理连续元素与自身内存；扩容可能使指向元素的指针、引用和迭代器失效。标准算法通过迭代器/range 表达“处理哪些元素”，通常比手写索引循环更容易复用和测试。

## 泛型不等于“接受任何类型”

模板的有效输入仍有契约。上面的 `sum` 要求 `T{}` 能产生合适初值、元素能参与 `+`/累加，而且结果类型不会在目标范围内溢出。真实库可用 C++20 concept 或 `requires` 把要求写入接口，并为数值类型显式选择累加类型；不能把“某次实例化编译成功”当作所有 `T` 都正确。

容器操作前还要查失效规则：`vector` 扩容会使全部元素地址失效，删除/插入可能使操作点之后的迭代器失效；`span` 与 iterator 都不会延长容器寿命。llama.cpp/ggml 中的 tensor view、buffer view 也遵循同一个阅读问题：**谁拥有存储，哪一步可能重分配或释放？**

## 读大型仓库时的分层

| 层 | 先找什么 | 常见陷阱 |
| --- | --- | --- |
| 数据 | `struct` 字段、枚举、`span`/view | 把非拥有 view 当成长寿命存储 |
| 行为 | 类的不变量、构造/析构、public API | 只看方法名，不看状态约束 |
| 泛型 | `template` 参数、concept、实例化点 | 误以为模板声明本身已经产生机器码 |
| 容器/算法 | 容量、迭代器失效、复杂度 | 把 vector 的容量当成元素个数 |

## 练习与成功标准

阅读历史片段，手算 `vector<int>{4,1,3,2}` 经排序和累加的输出为 `10`；说明换成 `long long` 后模板的运算要求为何仍成立。再解释超过 capacity 的追加为何可能改变 `data()`，以及为何不能解引用先前保存的指针。成功标准是能指出类型要求和失效边界；此处不再声称存在可重建的 `stl` 目标。需要可运行练习时进入 [[计算机知识/80-实践/03-C++/00-C++实验室|C++ 实验室]]。
