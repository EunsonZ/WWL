# 环境与依赖实验

## 目标

不安装业务所需的第三方 Python 包，也能观察：解释器在哪里、是否处于虚拟环境、pip 会安装到哪里、激活改变了什么。标准库 venv 路线不需要访问包索引；Conda 路线会访问配置的渠道并安装 Python 及其基础依赖，边界在路线 C 单独说明。

## 先创建唯一的临时实验根

不要在课程 Vault、下载目录、已有项目或系统目录直接创建 `.venv`。本页的 venv 和 uv 路线都只在一个**新建、为空、有标记**的临时目录中进行；四个清理示例也会逐项核对这个目录、标记和 `.venv` 本身。若该目录已存在，命令会拒绝继续，避免把旧实验误当成这一次的目标。

macOS / Linux（在普通终端执行一次）：

```bash
LAB_ROOT="${TMPDIR:-/tmp}/workwithllm-python-env-lab"
LAB_MARKER="workwithllm-python-env-lab-v1"

if [ -e "$LAB_ROOT" ] || [ -L "$LAB_ROOT" ]; then
  printf '拒绝开始：临时实验目录已存在：%s\n' "$LAB_ROOT" >&2
else
  mkdir -- "$LAB_ROOT" &&
    cd -- "$LAB_ROOT" &&
    printf '%s\n' "$LAB_MARKER" > .workwithllm-env-lab &&
    printf '实验目录：%s\n' "$(pwd -P)"
fi
```

Windows PowerShell（在普通 PowerShell 窗口执行一次）：

```powershell
$LabRoot = Join-Path ([System.IO.Path]::GetTempPath()) "workwithllm-python-env-lab"
$LabMarker = "workwithllm-python-env-lab-v1"

if (Test-Path -LiteralPath $LabRoot) {
    throw "拒绝开始：临时实验目录已存在：$LabRoot"
}

New-Item -ItemType Directory -Path $LabRoot -ErrorAction Stop | Out-Null
Set-Location -LiteralPath $LabRoot
Set-Content -LiteralPath ".workwithllm-env-lab" -Value $LabMarker -NoNewline
Write-Host "实验目录：$((Get-Location).ProviderPath)"
```

恢复方式：先 `deactivate` 或 `conda deactivate`，再只使用本页相应的守卫式 `.venv` 清理。实验结束后，打开系统废纸篓/回收站前先人工确认目录正是上面打印的 `workwithllm-python-env-lab`，其中仍有 `.workwithllm-env-lab` 标记；将这个**整个临时目录**移入废纸篓/回收站即可。不要复制递归删除命令来清理临时根目录。

## 路线 A：标准库 venv

先阅读 [[计算机知识/10-编程语言/01-Python/09-venv与虚拟环境原理|venv 与虚拟环境原理]]；pip 的安装目标判断见 [[计算机知识/10-编程语言/01-Python/08-pip与PyPI依赖管理|pip 与 PyPI 依赖管理]]。

在一个专门的临时项目目录中：

```bash
python -m venv .venv
```

macOS / Linux：

```bash
. .venv/bin/activate
```

Windows PowerShell：

```powershell
.\.venv\Scripts\Activate.ps1
```

诊断：

```bash
python -c "import site, sys; print(sys.executable); print(sys.prefix); print(sys.base_prefix); print(site.getsitepackages())"
python -m pip --version
python -m pip list
```

记录激活前后 `sys.executable`、`PATH` 中最前面的条目，以及 `sys.prefix == sys.base_prefix` 是否变化。再停用：

```bash
deactivate
```

最后直接调用环境解释器，证明激活并非必要：

```bash
.venv/bin/python -c "import sys; print(sys.executable)"
```

Windows 对应路径为 `.venv\Scripts\python.exe`。

### 路线 A 的守卫式清理与重建

清理会永久删除环境内尚未记录的安装状态。先停用环境；以下守卫只允许删除本页创建的临时根中、含 `pyvenv.cfg`、且**不是符号链接**的精确 `.venv`。任一检查失败就停止，并通过上一节的恢复方式人工处理。

macOS / Linux：

```bash
LAB_ROOT="${TMPDIR:-/tmp}/workwithllm-python-env-lab"
LAB_MARKER="workwithllm-python-env-lab-v1"

if test "$(pwd -P)" = "$LAB_ROOT" &&
  test ! -L .workwithllm-env-lab &&
  test -f .workwithllm-env-lab &&
  test "$(cat .workwithllm-env-lab)" = "$LAB_MARKER" &&
  test ! -L .venv &&
  test -f .venv/pyvenv.cfg; then
  if rm -rf -- .venv && test ! -e .venv; then
    python -m venv .venv &&
      .venv/bin/python -c "import sys; print(sys.executable); print(sys.prefix != sys.base_prefix)"
  else
    printf '清理未完成：停止，不在旧目录上重建\n' >&2
  fi
else
  printf '拒绝删除：实验根、标记或非符号链接 .venv/pyvenv.cfg 不匹配\n' >&2
fi
```

Windows PowerShell：

```powershell
$LabRoot = Join-Path ([System.IO.Path]::GetTempPath()) "workwithllm-python-env-lab"
$LabMarker = "workwithllm-python-env-lab-v1"
$CurrentPath = (Get-Location).ProviderPath
$MarkerPath = Join-Path $LabRoot ".workwithllm-env-lab"
$VenvPath = Join-Path $LabRoot ".venv"

if ($CurrentPath -ne $LabRoot) { throw "拒绝删除：当前目录不是本页临时实验根" }
if (-not (Test-Path -LiteralPath $MarkerPath -PathType Leaf)) { throw "拒绝删除：缺少实验标记" }
if ((Get-Content -LiteralPath $MarkerPath -Raw) -ne $LabMarker) { throw "拒绝删除：实验标记内容不匹配" }
if (-not (Test-Path -LiteralPath $VenvPath -PathType Container)) { throw "拒绝删除：没有 .venv 目录" }
if ((Get-Item -LiteralPath $VenvPath -Force).Attributes -band [IO.FileAttributes]::ReparsePoint) { throw "拒绝删除：.venv 是 ReparsePoint" }
if (-not (Test-Path -LiteralPath (Join-Path $VenvPath "pyvenv.cfg") -PathType Leaf)) { throw "拒绝删除：缺少 .venv\\pyvenv.cfg" }

Remove-Item -LiteralPath $VenvPath -Recurse -Force

if (Test-Path -LiteralPath .venv) { throw ".venv 未清理干净" }
py -m venv .venv
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable); print(sys.prefix != sys.base_prefix)"
```

最后一条命令应打印新环境的解释器路径和 `True`。这证明环境来自重建，而不是从别处搬回旧目录。

## 路线 B：如果已经安装 uv

```bash
uv venv
uv run python -c "import sys; print(sys.executable); print(sys.prefix)"
uv pip list
```

`uv venv` 只创建环境，本路线没有初始化 uv project，因此**不会产生 `uv.lock`**。只有进入带 `pyproject.toml` 的 uv project，并按项目工作流解析、锁定依赖后，才会维护 `uv.lock`。

不要为了本练习临时安装 uv；先阅读 [[计算机知识/10-编程语言/01-Python/11-uv项目依赖与工具管理|uv 项目、依赖与工具管理]]。在不含 `pyproject.toml` 或既有 `uv.lock` 的专用临时目录中，用 uv 完成自己的守卫式清理与重建。

macOS / Linux：

```bash
LAB_ROOT="${TMPDIR:-/tmp}/workwithllm-python-env-lab"
LAB_MARKER="workwithllm-python-env-lab-v1"

if test "$(pwd -P)" = "$LAB_ROOT" &&
  test ! -L .workwithllm-env-lab &&
  test -f .workwithllm-env-lab &&
  test "$(cat .workwithllm-env-lab)" = "$LAB_MARKER" &&
  test ! -L .venv &&
  test -f .venv/pyvenv.cfg; then
  if rm -rf -- .venv && test ! -e .venv; then
    uv venv &&
      .venv/bin/python -c "import sys; print(sys.executable); print(sys.prefix != sys.base_prefix)" &&
      test ! -e uv.lock
  else
    printf '清理未完成：停止，不在旧目录上重建\n' >&2
  fi
else
  printf '拒绝删除：实验根、标记或非符号链接 .venv/pyvenv.cfg 不匹配\n' >&2
fi
```

Windows PowerShell：

```powershell
$LabRoot = Join-Path ([System.IO.Path]::GetTempPath()) "workwithllm-python-env-lab"
$LabMarker = "workwithllm-python-env-lab-v1"
$CurrentPath = (Get-Location).ProviderPath
$MarkerPath = Join-Path $LabRoot ".workwithllm-env-lab"
$VenvPath = Join-Path $LabRoot ".venv"

if ($CurrentPath -ne $LabRoot) { throw "拒绝删除：当前目录不是本页临时实验根" }
if (-not (Test-Path -LiteralPath $MarkerPath -PathType Leaf)) { throw "拒绝删除：缺少实验标记" }
if ((Get-Content -LiteralPath $MarkerPath -Raw) -ne $LabMarker) { throw "拒绝删除：实验标记内容不匹配" }
if (-not (Test-Path -LiteralPath $VenvPath -PathType Container)) { throw "拒绝删除：没有 .venv 目录" }
if ((Get-Item -LiteralPath $VenvPath -Force).Attributes -band [IO.FileAttributes]::ReparsePoint) { throw "拒绝删除：.venv 是 ReparsePoint" }
if (-not (Test-Path -LiteralPath (Join-Path $VenvPath "pyvenv.cfg") -PathType Leaf)) { throw "拒绝删除：缺少 .venv\\pyvenv.cfg" }

Remove-Item -LiteralPath $VenvPath -Recurse -Force

if (Test-Path -LiteralPath .venv) { throw ".venv 未清理干净" }
uv venv
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable); print(sys.prefix != sys.base_prefix)"
if (Test-Path -LiteralPath uv.lock) { throw "本路线不应生成 uv.lock" }
```

验证输出应重新指向当前目录的 `.venv`，比较结果应为 `True`，目录中仍不应凭空出现 `uv.lock`。

## 路线 C：如果已经安装 Conda

先阅读 [[计算机知识/10-编程语言/01-Python/10-Conda-Anaconda与Miniconda|Conda、Anaconda 与 Miniconda]]。下面的 `conda create` 会访问当前配置的渠道，下载并安装 Python 及其基础依赖；环境通常写入 Conda 的环境根，而不是当前实验目录。运行前先用 `conda info` 核对渠道、环境目录和磁盘空间，不要在含凭据的配置或不可信渠道下进行本练习。

```bash
conda create --name env-observe python --no-default-packages
conda activate env-observe
python -c "import sys; print(sys.executable); print(sys.prefix)"
conda list
conda deactivate
```

删除前精确核对环境名：

```bash
conda env remove --name env-observe
```

不要为了比较命令而在同一目录同时叠加 `.venv`、uv project 和 Conda 环境。三条路线选一条主线即可。
