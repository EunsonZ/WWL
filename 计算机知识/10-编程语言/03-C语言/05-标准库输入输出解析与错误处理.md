# C：把标准库调用变成可靠的输入输出协议

> 阅读定位：C17 核心；扩展和标准版本差异单独注明。返回 [[计算机知识/00-开始/课程地图/01-C语言-课程地图|C语言 · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## 输入成功不是“没有崩溃”

读取整数有三层检查：字节是否完整读入，文本是否符合语法，数值是否处于业务范围。`atoi` 不提供足够的错误区分。使用 `strtol` 时，应先将 `errno=0`，检查结束指针是否前进、是否有不允许的尾随字符，再检查 `ERANGE` 和目标类型范围。若需要严格十进制，明确传入基数 10，不让前缀自动改变解释。

例如输入 `42x`：`strtol` 能成功解析前缀 42，但整个输入不是一个严格整数。输入空串没有发生有效转换。输入过长数字可能超范围。接受什么空白、正负号、前导零，属于接口合同，不能由偶然的库默认值决定。

## 文件是流，读写都可能部分完成

`fgetc` 返回 `int`，因为需要表示全部 `unsigned char` 值外加 EOF；先存进 `char` 可能丢失这个区别。读到 EOF 后使用 `feof` 与 `ferror` 区分正常结束和错误。不要使用 `while (!feof(file))` 作为“下一次一定能读到数据”的判断，应让读取操作决定循环是否继续。

`fread`/`fwrite` 返回完成的元素个数，必须检查短读短写。`fgets` 读取有界字符，但缓冲区被填满不表示整行结束；长行需继续拼接或明确拒绝。`printf(user_input)` 把外部数据当格式串，应写成 `printf("%s", user_input)`。长度、编码和格式三个层次各有自己的验证。

文件流缓冲、系统调用、页缓存和设备持久化是不同阶段。`fflush` 主要把 C 标准库缓冲交给下层，不等于断电后保证数据还在。`fclose` 也可能报告写回错误，不能只检查 `fopen`。真正的持久化需要操作系统和文件系统层协议。

## 标准库知识地图

`<string.h>` 管理字节和 C 字符串；`<stdlib.h>` 含分配、转换、排序及进程相关基础；`<stdio.h>` 是流；`<ctype.h>` 做字符分类，传参须为 EOF 或可表示为 `unsigned char` 的值；`<math.h>` 涉及数值运算与定义域；`<time.h>` 涉及时间，不是可靠计时的万能抽象；`<locale.h>` 会影响部分文本转换。`<assert.h>` 是开发断言，不能代替生产输入检查，因为断言可被关闭。

还有 `<stdbool.h>`、`<stdint.h>`、`<inttypes.h>`、`<stddef.h>`、`<limits.h>`、`<float.h>`。格式化定宽整数应关注 `<inttypes.h>` 的格式宏，不要假设 `int64_t` 必然对应某个固定的 printf 长度修饰符。随机业务中 `rand` 不是密码学随机源。

## 自检

为“读一行非负整数”的函数列出空文件、空行、负数、溢出、尾随垃圾、超长行、底层 I/O 错误七类结果。接口可使用枚举错误码和输出参数，但错误时是否写输出参数要明确。本库本地实验中的边界校验和网络分帧可以复用同一套思考方式。
