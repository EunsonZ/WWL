# 正则表达式 · MOC

正则表达式（regular expression，常写作 regex）是一种描述**文本模式**的语言。它适合搜索、校验、提取和替换局部文本；它不是通用解析器（parser），也不应该代替 JSON、CSV、HTML 或编程语言的正式解析器。

> [!abstract] 学完后的能力
> 你将能把需求拆成可验证的匹配规则，读懂常见元字符，提取和替换结构化片段，识别引擎差异，并避免容易失控的回溯与“一条正则解决一切”。

> [!tip] 零基础先跑通一个例子
> 打开 [[编程知识/30-实践/01-正则表达式实验区/04-5分钟运行与测试模板|5 分钟运行与测试模板]]，在 Python 3 或现代 JavaScript 中二选一。看到断言“全部通过”后再开始第 1 课；不必同时掌握两种语言。

## 第一次只需知道的语法边界

课程的基础例子优先使用 **Python 3 `re` 与现代 JavaScript `RegExp` 的共同子集**。开始时只需记住三件事：

1. 先选定语言、版本和正则引擎；
2. 分清搜索、完整匹配、全部查找和替换；
3. 记录标志（flags），例如忽略大小写或多行模式。

> [!info]- 进阶兼容提醒
> - Python 命名组常写作 `(?P<name>...)`，JavaScript 常写作 `(?<name>...)`；
> - JavaScript 常用 `g` 做全部查找、`i` 忽略大小写、`m` 多行、`s` 让点号匹配换行，`u` / `v` 改变 Unicode 相关语义；
> - Python 通常把对应选项传给 `re.MULTILINE`、`re.DOTALL`、`re.IGNORECASE` 等标志；
> - 后行断言、原子组、占有量词、Unicode 属性转义并非所有引擎都支持；
> - Google RE2 一类引擎主动放弃反向引用和环视等能力，以换取可预测的线性时间。

运行表达式前，应先回答：“它将在哪个语言、库、编辑器或命令中执行？”

## 一次可靠匹配的工作流

```mermaid
flowchart LR
  A[写真实样本] --> B[列出应匹配和不应匹配]
  B --> C[先写最小模式]
  C --> D[逐段增加约束]
  D --> E[检查捕获结果]
  E --> F[加入边界样本]
  F --> G[确认引擎与标志]
  G --> H[评估性能和维护性]
```

每个表达式至少要有三类样本：

- **正例**：确实应该匹配；
- **反例**：看起来相似，但不应该匹配；
- **边界例**：空字符串、极长输入、Unicode、换行、缺字段或重复分隔符。

## 先看一个完整例子

目标：从 `order-20260831-0042` 中提取日期与序号。

```regex
^order-([0-9]{8})-([0-9]{4})$
```

拆解：

- `^` 与 `$` 通常把模式限制到输入两端；Python 等引擎的 `$` 对最终换行有例外，严格校验优先用完整匹配 API；
- `order-` 是字面文本；
- 第一个括号 `([0-9]{8})` 捕获第 1 组，其中 `[0-9]{8}` 匹配 8 个 ASCII 数字；
- 第二个括号 `([0-9]{4})` 捕获第 2 组，其中 `[0-9]{4}` 匹配 4 个 ASCII 数字。

它只验证“8 位数字 + 4 位数字”的形状，不会判断 `20261340` 是否是真实日期。语法匹配与业务有效性是两层检查。

## 什么时候不要用正则

| 问题 | 更合适的工具 |
| --- | --- |
| 解析 JSON、YAML、CSV | 对应格式的标准解析库 |
| 修改 HTML DOM | HTML 解析器与 DOM API |
| 解析嵌套括号或完整编程语言 | 词法器、语法分析器或现成解析器 |
| 精确验证电子邮箱、URL、国际电话号码 | 成熟库 + 业务规则 + 必要时实际验证 |
| 只判断固定前缀、后缀或分隔符 | `startsWith`、`endsWith`、`split` 等字符串 API |

> [!warning] “能匹配”不等于“适合上线”
> 真实系统还要考虑输入长度、超时、Unicode、区域规则、误报成本、可测试性和维护者是否能读懂。
