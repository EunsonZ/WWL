# 虚拟机快照与网络隔离

**先修关系：** [[计算机知识/Kali/01-系统与网络基础/01-Kali定位与安装校验|Kali定位与安装校验]]。

## 隔离解决哪一个问题

实验可能产生扫描流量、暴露弱配置服务或污染证据。隔离不是“我没有恶意”的替代品，而是把一次误输入的影响范围缩小。本课程把实验分成**纯离线夹具**与**显式启动的本机服务**两层；需要域控制器、无线设备或大型靶场时另行建立可恢复环境。

虚拟机是一道边界，不是绝对安全容器。共享文件夹、剪贴板、宿主机端口映射和 USB 透传，都可能跨越这道边界。来源不明的恶意样本不应放进日常工作宿主机上的普通教学环境。

## 三种网络模式如何选择

| 模式 | 通信含义 | 本课程用途与限制 |
| --- | --- | --- |
| NAT | 虚拟机常可借宿主机出站；入站取决于映射和平台 | 下载与更新阶段使用；不能把 NAT 叫作“断网” |
| Host-only | 宿主机与选定虚拟机之间可达，外部连通取决于额外路由 | 少量可控教学服务；宿主机仍在风险范围内 |
| Internal / 私有虚拟网络 | 仅连接同一虚拟交换网络的参与虚拟机 | 多机靶场优先；具体名称和行为查虚拟化平台配置 |

桥接模式让虚拟机成为真实局域网中的设备。它对学习并非默认必需，也容易把练习流量送入家用路由器、校园网或办公网。**私有 IP 地址不是授权证据**；同样的 `192.168.x.x` 可能属于别人的系统。

## 可审阅的建网流程

先写 [[计算机知识/Kali/00-导航与方法/02-授权范围与风险分级|范围清单]]，再配置网卡；不要反过来先发现一个网段，然后把它全部算成靶场。设定课程示例：Kali 与自建靶机连接同一个 Internal 网络；教学服务只监听指定实验地址。示例网段可选一个不与宿主机/VPN 重叠的私网，本包正文使用 `192.168.56.0/24` 只是约定，**不是要你直接扫描的目标**。

确认三件事：虚拟交换机连接了哪些机器；来宾机路由表把默认流量发向哪里；宿主机是否做了转发、共享或代理。仅看到 `ip addr` 中有一个私网地址，不能回答后两件事。

```bash
# 读取本机配置，不主动扫描别的设备
ip -br link
ip -br address
ip route
ip -6 route
ss -lntup
```

检查 IPv4 时也看 IPv6，避免只隔离一种地址族。若练习只需要 `127.0.0.1:8000`，就没有必要引入第二张网卡。端口绑定 `0.0.0.0` 表示所有本地 IPv4 接口，绝不是“只给我自己用”。

## 快照、备份与证据冻结

快照记录的是虚拟化平台管理的机器状态，适合撤销配置变化；它不必包含共享文件夹，也未必覆盖外部数据库或独立磁盘。备份强调可独立恢复。两者都不能代替对实验输出的版本管理。

建议保留三个有明确含义的状态：可信初装、工具版本确认、某次实验开始前。实验后保存命令、输出与目标快照标识，再决定回滚。不要先回滚靶机，随后凭记忆重写一份“当时的日志”。

对于本包附带的纯离线脚本，只需 Python 标准库；它们不会自动打开端口。后续 [[计算机知识/Kali/07-综合实验/02-实验A从路由到HTTP与Nmap|实验 A]] 的 HTTP 服务需要读者自行显式启动，服务目录只指向公开教学夹具，不能指向整个 Vault 或家目录。

## 反例与诊断

一个服务仅在 Kali 内 `curl localhost` 可达，不代表宿主机一定可达；`localhost` 始终是执行命令那台机器自己的回环地址。跨机连接失败时，按“监听地址 → 来宾防火墙 → 虚拟交换机 → 路由 → 对端策略”检查，而不是立即关闭所有防火墙。

自检：两台虚拟机都显示 `/24` 掩码，却互相不通，可能有哪些解释？检查点包括虚拟交换机不同、地址冲突、链路未连接、服务绑定回环、目标防火墙；“同一前缀”只是 IP 层条件，不保证二层相邻。

## 双网卡为什么会悄悄破坏隔离

教学机同时接 NAT 和 Internal 网络很方便，但方便本身不是隔离证明。两张网卡至少引入三类问题：默认路由可能走更新网络；应用可能绑定所有接口；宿主机、来宾机或代理可能连接原本分开的两侧。是否转发还取决于系统配置，并非“插两张网卡必然转发”，也不是“没有手动转发所以一定隔离”。

对仅需离线实验的批次，最容易审阅的做法是断开不需要的虚拟网卡，而不是依赖一套自己尚未理解的复杂路由。重新联网更新后再次记录接口和路由，不把更新前的截图沿用成更新后的隔离证据。

```bash
# 只读取当前网络命名空间的规则和路由，不产生目标探测。
ip rule show
ip route show table all
ip -6 rule show
ip -6 route show table all
```

`ip route` 的默认显示并不是所有策略路由表；VPN、容器及策略规则可能改变查表顺序。完整观察需要把规则与相应表结合起来。[^v2-iproute]

## 克隆、时间与证据归属

复制实验机应记录新旧实例标识及用途，特别注意 IP 冲突、相同主机名、相同应用数据造成的误认。不要为了课程方便复制真实生产身份或实际私钥。恢复快照后，服务状态、文件时间、应用会话与客户端缓存也可能不再处于同一时间线；先重新建立观察基线再复测。

最小验收表不必复杂：写出“哪台机器发请求”“目的地址由谁解析”“服务监听哪张网卡”“谁能访问这个端口”“输出保存在谁的磁盘”。任何一项答不清，暂时不要扩大扫描范围。具体证据目录沿用 [[计算机知识/Kali/00-导航与方法/03-实验室拓扑与证据目录|实验拓扑]]，不另建一套互不一致的机器编号。
