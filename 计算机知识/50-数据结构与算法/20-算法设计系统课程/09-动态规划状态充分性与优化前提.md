## 状态是对历史的有损压缩，先问丢掉的信息有没有用

动态规划并不是“发现子问题重复就建表”。你必须说明：被归到同一个状态的不同历史，在之后拥有相同的可行选择和同样的增量代价；否则保存其中一个最优值可能丢掉未来必需的信息。

例如路径规划同时限制总费用与经过红色边的数量，只用“当前顶点”作为状态就不够。两条同样到达 v 的路线，一条更便宜却已用完红边额度，另一条稍贵却保留额度，未来可达性不同。可增加剩余额度维度，或者维护不能互相支配的标签集合。状态设计是在证明历史可以压缩，不是在给变量起名字。

## 0/1 背包：二维递推如何变成一维程序

假定每件物品最多选一次，重量为正整数，容量 W 为非负整数。定义 $D_i(c)$ 为前 i 件物品中，总重量不超过 c 的最大价值。这里的“不超过”决定基础状态全为 0，允许什么都不选。[^knapsack]

$$
D_i(c)=\begin{cases}
D_{i-1}(c),&c<w_i,\\
\max(D_{i-1}(c),D_{i-1}(c-w_i)+v_i),&c\ge w_i.
\end{cases}
$$

两项分别是不选、选第 i 件；选的分支必须来自上一层，才能保证不重复使用当前物品。只保留一维数组后，遍历顺序必须保存这条依赖。

```python
def knapsack01(items: list[tuple[int, int]], capacity: int) -> int:
    if capacity < 0 or any(w <= 0 for w, _ in items):
        raise ValueError("capacity must be nonnegative; weights positive")
    dp = [0] * (capacity + 1)
    for weight, value in items:
        for c in range(capacity, weight - 1, -1):
            dp[c] = max(dp[c], dp[c - weight] + value)
    return dp[capacity]
```

只有一件 `(weight=2,value=3)`，容量 4。倒序更新 c=4 时，dp[2] 仍是上一层的 0，所以结果为 3；随后 c=2 更新为 3。若正序，先把 dp[2] 改成 3，到 c=4 时再次使用这个 3，得到 6，相当于把同一物品选两次。

正序不一定“写错了 DP”，而是改成了允许反复使用当前物品的完全背包语义。程序相似不能掩盖问题定义改变。它与 [[计算机知识/50-数据结构与算法/10-数据结构系统课程/09-懒标记的代数与完整实现|先后更新的复合顺序]] 一样，是数据依赖而非风格偏好。

## “恰好填满”需要不同的不可达状态

如果要求重量恰好为 c，dp[0]=0，其他状态应为负无穷或显式 None。初始化为 0 会把本来不可达的容量当作已经有一个零价值解。

例如只有重量 2、价值 3 的物品，容量 3。“不超过 3”最优值为 3，“恰好 3”无解。若两种问题都返回 3，你改变的不是实现细节，而是可行解集合。路径计数通常以 0 表示无方案，最短路通常以正无穷表示不可达，求最大值则常用负无穷。单位元必须服务具体运算。

一维压缩还会影响方案恢复。只保存当前最佳值而不断覆盖来源，可能无法追溯同一层的选择。可靠做法包括保留分层选择、重新计算分界，或使用适当的持久化来源结点；不能随手记录一个前驱下标就宣称能恢复所有 0/1 选择。

## 带权区间调度：先排序，再定义前驱

设作业为半开区间 `[start,finish)`，持续时间为正，按结束时间排序。令 p(i) 为 i 之前最后一个满足 `finish <= start_i` 的作业下标，找不到则为 0。定义 D[i] 为前 i 项的最优收益：

$$
D[i]=\max(D[i-1],w_i+D[p(i)]).
$$

例子按结束时间列为 A=(0,3,5)、B=(1,4,6)、C=(3,5,5)、D=(4,7,4)、E=(5,8,11)。前驱依次为 0、0、1、2、3；D 从 D[0]=0 开始，依次得到 5、6、10、10、21。最优解为 A、C、E。

为什么选了 i 后只需看 p(i) 以前？排序确保所有与 i 不冲突且结束更早的候选都在该前缀中。半开端点使 A 在 3 结束、C 在 3 开始可以相接；若题目认为相同端点也冲突，二分比较就要改成严格小于。边界约定应写在推导前，而不是等测试失败才补。

## 优化必须有第二份证明

记忆化和制表都只是求值策略。状态依赖为 DAG 时，可以按拓扑顺序求值；有环时，可能需要不动点、最短路算法或证明收敛，而不是递归函数套缓存就结束，见 [[计算机知识/70-编译原理/10-系统课程/10-活跃性不动点与抽象解释|数据流不动点]]。

分治优化常要求最优决策位置单调；Knuth 优化还针对特定区间递推和费用条件；凸包优化要求转移可转成相应线性函数的比较，查询顺序、斜率顺序与重复斜率处理也各有条件。看到双重循环，不代表其中一层可以按某个知名技巧删掉。

对只用于竞赛约束的算法，应明确数值范围和输入结构。$O(nW)$ 背包是伪多项式时间：W 的二进制表示只需 $O(\log W)$ 位，W 对编码长度可能指数大。这里没有与 NP 困难性矛盾。[^knapsack]

## 可验证的证明模板

先写状态意义与不可达状态，再用最后一个决策把所有可行解划分成互不遗漏的类别，证明每类最优值可由已定义子问题获得。随后说明计算顺序与存储压缩保留了哪一层值，最后计算状态数、转移数和算术成本。

本轮用小规模子集枚举交叉验证背包与带权区间调度，并专门保留“正序会重复使用物品”“恰好填满不可达”的反例。随机覆盖是寻找漏洞的方法，不是把最优子结构的证明外包给计算机。
