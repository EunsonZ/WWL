# TypeScript：模块、工程、测试与生态边界

> 阅读定位：严格类型检查；运行时语义属于 JavaScript，宿主 API 另行区分。返回 [[计算机知识/00-开始/课程地图/05-TypeScript-课程地图|TypeScript · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## tsconfig 是编译合同，不是运行环境

`target` 影响输出语法目标，`lib` 提供可用 API 的类型声明，`module` 与 `moduleResolution` 参与模块输出和解析。声明中存在某个 API，不代表运行环境真的提供它；修改 lib 不会安装 polyfill。Node 类型与 DOM 类型也不应无条件混入所有项目。

建议从 strict 开始，再根据工程加入 `noUncheckedIndexedAccess` 和 `exactOptionalPropertyTypes`。启用 noEmitOnError 可以防止类型检查失败时仍输出本次构建产物，但旧产物清理、打包工具行为与发布流水线仍需自己管理。

ESM/CommonJS、package.json 的 type/exports、文件扩展名、路径别名和打包器解析要相互匹配。TypeScript 的 paths 配置不一定重写运行时导入地址；“编辑器不报错，运行时找不到模块”常由此产生。库发布还需验证 `.d.ts` 是否与实际 JavaScript 导出一致。

## 测试应该跨过类型擦除边界

编译期测试检查误用能否被拒绝，单元测试检查纯逻辑，集成测试检查 I/O、序列化和真实宿主行为。测试外部响应缺字段、错误编码、超时、取消、重复投递和极大输入。快照测试可以发现变化，但大块快照不能代替业务不变量断言。

错误对象应保留类别和原因，日志不能无差别写入 token、密码与完整个人数据。浏览器中的 CORS 是特定跨源访问控制机制，不等于认证；把字符串交给 innerHTML 仍可能引入 XSS，TypeScript 不会自动净化 HTML。数据库查询应参数化，静态类型不会自动防止 SQL 注入。

## 至少要知道这些知识属于哪里

语言层有函数、对象、类、原型、迭代器、生成器、正则、BigInt、Symbol、异常与模块；类型层有联合、交叉、泛型、收窄、类型运算与声明文件；宿主层有 DOM、Fetch、URL、Streams、Worker、文件和进程；工程层有构建、lint、测试、依赖锁定、版本兼容和部署。

装饰器存在不同语义与工具配置路线，不应混用旧教程的假设。框架如组件系统、路由、状态管理、服务端运行时，是建立在这些基础之上的选修，不等于 TypeScript 本身。WebAssembly、原生扩展、边缘运行时和源码映射也有各自的边界。

## 综合验收

完成一个读取本地 JSON 或受控响应的程序：unknown 输入经过解析，领域模型禁止不合法状态，异步任务有上限，错误可分类，测试覆盖缺失和失败，构建输出可在指定宿主真正执行。把宿主版本写进实验记录，而不是泛称“JavaScript 都能跑”。
