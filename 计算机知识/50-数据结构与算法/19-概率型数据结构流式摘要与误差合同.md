# 19 · 概率型数据结构、流式摘要与误差合同

## 本课目标

学完后，你应该能够：

- 把“内存小”改写成可审计的**误差合同**，明确哪类错误允许、概率对谁成立、依赖哪些假设；
- 解释 Bloom filter 为什么会假阳性却不应假阴性，以及容量、哈希数和误判率的关系；
- 解释 Count-Min Sketch 为什么只高估频次，并写出标准 $\varepsilon,\delta$ 保证的适用条件；
- 用不变量证明水库抽样在不知道流长度时仍给每项相同的入样概率；
- 区分概率定理、固定种子回归样例和生产环境的实测指标，不把摘要结构当权限系统或事实来源。

## 1. 从“近似”开始写合同

精确集合、频次表和完整样本都可能随输入基数增长。流式摘要用固定或受控空间换取近似回答，但“近似”不能只写成一句“通常很准”。至少要回答：

| 合同字段 | 必须说清楚的问题 |
| --- | --- |
| 查询语义 | 回答 membership、频次、基数还是样本？ |
| 错误方向 | 会假阳性、假阴性、高估、低估，还是抽样波动？ |
| 误差大小 | 是加性误差、相对误差，还是概率事件？ |
| 概率对象 | 随机性来自哈希函数、算法抽签、输入分布还是测试数据？ |
| 前提 | 是否只允许插入和非负更新？哈希族是否满足独立性要求？ |
| 作用域 | 保证针对单次查询、固定查询集合，还是任意自适应查询？ |
| 生命周期 | 种子、参数、序列化版本、窗口和合并规则是否固定？ |
| 失败后果 | 误判只多做一次磁盘读取，还是会误拒绝业务、越过 ACL？ |

这与 [[数学/30-概率与统计/05-统计估计置信度与模型评测|统计估计、置信度与模型评测]] 的共同原则相同：先定义随机变量、总体与假设，再谈概率。概率上界不是“本次一定如此”，一次固定数据集的观测也不能替代定理。

## 2. Bloom filter：省空间的 membership 前置筛选

Bloom filter 用 $m$ 个 bit 和 $k$ 个哈希位置保存“见过的键”。插入键时把对应 bit 全部置 1；查询时，只要有一个对应 bit 为 0，就确定该键没有按当前合同加入；全部为 1 只表示**可能加入过**。

```text
ADD(x):
    for i in 1..k:
        bits[h_i(x) mod m] = 1

MAY_CONTAIN(x):
    return 所有 bits[h_i(x) mod m] 都是 1
```

在只插入、不清零、查询使用同一哈希与参数、bitset 没损坏的前提下，已插入键的 $k$ 个位置仍为 1，所以没有假阴性。未插入键却可能恰好碰到其他键置过的 bit，产生假阳性。若插入约 $n$ 个不同键并把哈希近似看成独立均匀，误判率近似为：

$$
p_{fp}\approx\left(1-e^{-kn/m}\right)^k
$$

固定 $m,n$ 时，连续近似下 $k\approx(m/n)\ln 2$ 附近较优；实践还要取整数并计入哈希 CPU 成本。若目标误判率为 $p$，常用规划式为 $m\approx-n\ln p/(\ln 2)^2$、$k\approx(m/n)\ln 2$。这些式子依赖模型，应该和生产键分布、真实装载量与实测误判率一起记录。

### 边界与反例

- 普通 Bloom filter 不能把某键的 bit 直接清零；那些 bit 也可能属于别的键，错误删除会制造假阴性。Counting Bloom filter 用计数器支持受约束删除，但计数溢出、并发与内存合同都改变了。
- 把“可能存在”当成“已授权”会越权；把“确定不存在”用于跳过昂贵后端读取才是常见安全用法。权限必须由权威 ACL/租户过滤决定。
- 重新启动后换 seed、哈希实现或编码，却继续读取旧 bitset，会破坏合同。版本、规范化规则和 seed 是持久化格式的一部分。
- Bloom filter 会暴露 membership 信号，不能因为没有存原文就宣称没有隐私风险。

哈希碰撞与对抗性输入的基础见 [[计算机知识/50-数据结构与算法/04-哈希表集合与冲突处理|哈希表、集合与冲突处理]]。Bloom filter 的概率误判不是普通哈希表“碰撞后再比原始键”的同一种行为。

## 3. Count-Min Sketch：只高估的频次摘要

Count-Min Sketch（CMS）维护 $d$ 行、每行 $w$ 个非负计数器。收到 `(x, c)` 时，在每行由独立哈希选一个位置加上 $c$；查询返回这些位置的最小值：

```text
UPDATE(x, c >= 0):
    for row in 1..d:
        table[row][h_row(x) mod w] += c

ESTIMATE(x):
    return min(table[row][h_row(x) mod w] for row in 1..d)
```

真实频次 $f_x$ 对每行贡献了 $f_x$，其他键的碰撞只会增加计数，因此在**非负更新**模型中有确定性的 $\hat f_x\ge f_x$。标准分析在每行使用合适的独立哈希并令

$$
w=\lceil e/\varepsilon\rceil,\qquad d=\lceil\ln(1/\delta)\rceil
$$

时，对一个预先固定的查询键给出：以至少 $1-\delta$ 的概率，

$$
f_x\le \hat f_x\le f_x+\varepsilon\lVert f\rVert_1
$$

其中 $\lVert f\rVert_1$ 是流的总非负计数。它是**相对总流量的加性误差**，并非“每个键相对误差不超过 $\varepsilon$”。重尾流里小频次键可能被误差淹没；对很多查询同时承诺时还要做联合失败概率预算，不能对每个查询都用同一个 $\delta$ 后宣称整体仍为 $1-\delta$。

### 合并、窗口和负更新

参数、seed 与行哈希完全相同的 CMS 可以逐格相加，表示流的拼接；不同 seed 或维度不能静默合并。普通 CMS 不负责时间窗口：若要“过去五分钟”，需设计滚动窗口、分桶摘要或衰减语义。允许任意负更新会失去“碰撞只增加”的证明；turnstile 流需要另选分析和结构。

CMS 适合估计热点、网络流量或事件频次的候选信号，不宜直接作为计费、配额和审计账本。精确账本仍是权威数据；摘要只能在其错误后果可接受的位置加速。

## 4. 水库抽样：不知道 $n$ 也保留均匀样本

容量为 $r$ 的 reservoir 初始装入前 $r$ 项。看到第 $t>r$ 项时，从 `0..t-1` 均匀抽一个位置 $j$；若 $j<r$，用新项替换 reservoir 的第 $j$ 项，否则丢弃新项。

新项进入样本的概率是 $r/t$。对任一旧项：它在处理前 $t-1$ 项后留存概率为 $r/(t-1)$；本轮不被替换的概率为 $1-1/t=(t-1)/t$，因此处理第 $t$ 项后仍为

$$
\frac{r}{t-1}\cdot\frac{t-1}{t}=\frac{r}{t}.
$$

所以流结束于 $n$ 时，每一项的边际入样概率都是 $\min(1,r/n)$。这不意味着样本位置相互独立，也不意味着任意按键分组后仍自动均匀；加权抽样、分层抽样和分布式合并都有不同算法。

随机种子在实验中用于让伪随机选择可重复。**同一 seed 得到同一 reservoir，只证明实现可复现，不证明样本“有代表性”。** 代表性还依赖流覆盖、缺失机制、顺序、分层需求与随机数质量。期望、方差与抽样背景见 [[数学/30-概率与统计/02-期望方差协方差与抽样|期望、方差、协方差与抽样]]。

## 5. 三种结构的合同对照

| 结构 | 空间主项 | 查询答案 | 允许的近似 | 绝不能省略的前提 |
| --- | ---: | --- | --- | --- |
| Bloom filter | $m$ bit | 可能存在 / 确定未加入 | 假阳性 | 只增、相同哈希与编码、bitset 完整 |
| Count-Min Sketch | $w\times d$ 计数器 | 频次上界估计 | 非负加性高估 | 非负更新、合适哈希、参数/seed 一致 |
| Reservoir sampling | $O(r)$ 个项目 | 均匀容量受限样本 | 抽样波动 | 每步均匀随机、正确记录已见数量 |

如果失败后果是“多读一次缓存后端”，假阳性可能可接受；若后果是“拒绝合法用户”“收费”“泄露私有文档”，概率摘要不能独自作决定。缓存层还要区分命中、陈旧性和持久化，见 [[计算机知识/30-计算机系统/11-存储设备块层页缓存与持久化|存储设备、块层、页缓存与持久化]]。

## 6. 从定理到运行指标

上线前至少同时保留三层证据：

1. **理论层**：写出错误方向、$\varepsilon/\delta$ 或误判率公式、哈希与更新模型假设；
2. **固定种子层**：回归测试确保实现和序列化变化可见，但不把某一 seed 的通过率当总体保证；
3. **运行层**：在真实键分布与目标负载下测假阳性率、频次绝对误差/分位数、延迟、内存、窗口陈旧性，并监控参数漂移。

生产实现还需解决线程安全、计数器溢出、快照一致性、版本升级、哈希拒绝服务、容量扩张和恢复。课程实践只展示单进程、内存内、标准库版本，不声称覆盖这些职责。

## 实践

进入 [[计算机知识/80-实践/05-数据结构与算法/11-概率结构与检索评测/README|概率结构与检索评测实践]]：

- 用固定 seed 观察 Bloom 的无假阴性前提、CMS 的单向估计和 reservoir 的容量不变量；
- 把理论误判率与枚举域上的实测误判率分开记录；
- 修改 Bloom 容量、CMS 的 $w,d$ 与 reservoir 容量，解释内存、误差和 CPU 的变化；
- 运行同目录测试，确认错误参数会被拒绝。

## 练习

1. 预计插入 $10^7$ 个键、目标假阳性率 $1\%$，用规划式估算 $m$ 与 $k$；再说明结果为何仍需真实键分布实测。
2. 一个 CMS 设 $\varepsilon=0.001,\delta=10^{-6}$，流总计数为 $10^9$。把标准保证翻成频次加性误差，并说明它对频次 100 的键为何可能不实用。
3. 证明 reservoir 中一个旧项经过第 $t$ 项后仍以 $r/t$ 概率保留；指出固定 seed 测试能验证与不能验证的内容。
4. 为“缓存穿透防护”“财务扣款”“私有知识库 ACL”分别判断 Bloom/CMS 是否可作为最终决定，并写出权威回查路径。

## 成功标准

- 你能为三种结构各写出错误方向、空间主项、概率对象和破坏合同的操作；
- 你不会把 $\varepsilon$ 误写成每个键的相对误差，也不会把单查询 $\delta$ 静默扩展到无限查询；
- 你能说明固定种子、理论概率与生产实测是三种不同证据；
- 你能指出近似摘要必须位于权限、计费与事实权威数据的哪一侧。
