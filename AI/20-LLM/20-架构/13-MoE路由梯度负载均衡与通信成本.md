# MoE路由梯度、负载均衡与通信成本

**先修与定位：** 先理解[[AI/11-数学与统计桥梁/02-矩阵微积分VJP与反向传播|离散选择与梯度]]、[[AI/12-PyTorch/09-性能剖析编译动态形状与内存账本|算量与带宽]]，再比较 MoE 架构。

## 条件计算不等于只拥有少量参数

MoE 将若干普通前馈层替换为多个专家，用路由器为每个 token 选择少量专家。输出可简写为 $y(x)=\sum_{e\in\mathcal T(x)}g_e(x)f_e(x)$。总参数包括所有专家；每 token 激活参数只计算被选专家及共享组件。显存、加载和优化器仍可能需要容纳所有专家，除非采用相应分片或卸载。

稀疏激活的收益取决于专家计算是否大到足以摊薄路由与通信。Switch Transformer 给出了简化稀疏路由的重要方案。[^S33] 不同 MoE 的共享专家、top-k、容量与丢 token 策略不同，不能从同一个缩写推出相同工程行为。

## top-k的梯度究竟流向哪里

硬 top-k 选出的索引随 logits 分段恒定，在索引不切换的区域，普通自动微分不对离散选择本身提供梯度。但选中专家的连续门控权重可以收到梯度，专家内部也能学习。因此“硬选择完全不能训练”和“top-k处处平滑可导”都不准确。

一个容易遗漏的特例：若 top-1 后把唯一被选中的概率重新归一化为 1，则局部输出就是 $f_e(x)$，**仅由该任务输出产生的梯度不会通过常数门控训练路由 logits**。若保留全体 Softmax 中该专家的原概率、加入辅助路由损失或采用其他估计器，情况不同。这个反例针对特定实现，不是对全部 top-1 MoE 的断言。

## 为什么均衡损失同时看分配与概率

一种常用思路结合实际分配比例 $f_e$ 与平均路由概率 $\bar p_e$，形如

$$
L_{\rm bal}=E\sum_{e=1}^{E}f_e\bar p_e.
$$

实际选择计数通常视为不求导，梯度通过 $\bar p_e$ 影响路由倾向。若大部分 token 都拥挤到一个专家，损失鼓励降低该方向倾向；但过度均衡可能压制有价值的任务专门化。必须说明 $f_e$ 按 token 数还是 top-k assignment 数归一化，以及统计范围是 batch、设备还是更大组。

例如两专家分配为 90%/10%，即使平均算量不大，第一个专家也可能形成瓶颈。按总 batch 的平均负载估算显存会漏掉峰值。容量溢出后丢弃或改路由 token 还可能改变任务梯度和有效目标，需要计入指标，见[[AI/12-PyTorch/05-变长批处理Packing与有效Token归一化|有效监督与分母]]。

## 通信与优化的耦合

专家并行常需要把 token 分发到专家所在设备，再把结果送回。流量取决于 token 数、隐藏维、top-k、数据类型和跨机拓扑；小 batch 可能受固定延迟主导。共享专家可能减少某些能力碎片化，但不是免通信的通用方案。

### 稀疏算力为何不自动等于低系统成本

“每 token 激活较少参数”描述的是一部分专家 FFN 的计算路径，不是端到端账单。总专家权重仍要加载、分片或按需搬运；attention 与 KV cache 仍在；all-to-all 分发还会使流量在网络热点处聚集。于是两个激活参数量相同的 MoE，可能因 $k$、专家位置、batch、拓扑、容量溢出和利用率而有完全不同的延迟、峰值内存与单位请求成本。

这也解释了为什么系统比较要分开报告总参数、激活参数、驻留／搬运内存、专家利用率、通信时间和端到端尾延迟。只报“稀疏倍数”无法判断固定硬件是否被有效利用，更不能推出服务价格或投资回报。本段是机制性解释，未采用原始对话中关于具体厂商、模型或资本市场的时效性断言；参见 [[Clippings/WorkWithLLM/对话原稿/分析大模型算力极限 2|《分析大模型算力极限 2》“条件计算：MoE、Mixture-of-Depths 和动态 token 路由”]]。

路由还会改变每个专家的有效数据分布。热专家更新更频繁，冷专家可能欠训练；负载随输入域漂移时，训练平衡也不代表生产平衡。监控应包括按层专家利用率、最大/平均负载、丢 token 率、每域质量和端到端延迟。梯度同步范围与未使用参数处理连接[[AI/12-PyTorch/08-DDP全局目标通信与分片边界|DDP与分片边界]]。

## 自测与参考解

两个模型各有同样的每 token 激活参数，能否认为推理成本相同？不能。还要比较注意力、共享组件、专家选择数、通信、缓存、总参数驻留和实际硬件效率。若宣称某路由改进提升质量，也要固定数据与预算并测不同域，防止仅对热门任务更偏置。

[[AI/80-实践/08-深层机制数值实验/00-数值实验导航与验收|数值实验]]展示 top-1 重归一化导致的门控任务梯度消失；它只验证局部连续计算，不模拟分布式 all-to-all 或大规模专家训练。
