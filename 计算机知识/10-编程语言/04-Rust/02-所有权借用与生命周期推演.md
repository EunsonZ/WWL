# Rust：所有权、借用和生命周期的逐步推演

> 阅读定位：基础示例兼容 Rust 2021 edition；不把 edition 等同于编译器版本。返回 [[计算机知识/00-开始/课程地图/03-Rust-课程地图|Rust · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## 所有权是销毁责任，不是“变量住在栈上”

`String` 的变量可持有缓冲区地址、长度和容量等管理信息，字符数据通常位于动态分配区域。把 String 移动给另一个绑定，转移的是管理该资源的责任；这不意味着需要复制所有字符，也不要求值一定发生可观察的物理搬移。`Copy` 类型允许隐式复制，`Clone` 表示显式克隆操作，其代价由实现决定。

```rust
fn main() {
    let mut name = String::from("Ada");
    let size = name.len();
    {
        let view = &name;
        assert_eq!(view.len(), 3);
    }
    name.push('!');
    let moved = name;
    assert_eq!(moved.len(), size + 1);
    // 此后不能继续使用 name；销毁责任属于 moved。
}
```

逐步看：创建资源；临时共享借用只读观察；借用最后使用后允许可变操作；移动使原绑定不可再当所有者使用；最终由新所有者释放。借用的有效期通常由实际使用约束决定，不必简单等于整个词法块。

## 一个可变借用与多个共享借用为何冲突

假设你在遍历向量时追加元素，扩容可能搬走缓冲区，遍历指针就悬空。借用规则在编译期阻止这类同时依赖旧存储和改变存储的组合。共享引用并非“永远不变”的万能语义，内部可变性类型有自己的运行时或同步规则；但它们不会取消安全要求。

解决借用冲突应先明确数据关系：先计算下标再修改；缩短借用范围；用 `split_at_mut` 证明两个区域不重叠；必要时返回拥有值。到处 `clone()` 可能让编译通过，却隐藏不必要的复制，也可能掩盖错误的所有权设计。

## 生命周期标注描述关系，不延长生命

```rust
fn longer<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() >= b.len() { a } else { b }
}
```

返回值借用的有效使用范围必须同时满足两个输入的约束，因为静态签名不知道运行时选哪一个。`'a` 不是“让字符串活这么久”的指令。返回局部 String 的 `&str` 仍然不合法；正确方案常是返回 String，或者借用调用者提供的存储。

`'static` 引用要求指向的数据满足静态有效期；泛型约束 `T: 'static` 主要表示 T 不包含不满足该约束的借用，不表示某个 T 值永远不析构。把所有生命周期错误改成 `'static` 会把真实接口问题藏起来。

## 练习

写“返回输入中第一个单词”的借用函数，再写“返回新建大写字符串”的拥有函数。解释为什么二者返回类型不同。为非 ASCII 文本避免非法字节切片，并分别说明空输入、全空白和无空格时的结果。对照 C 的地址加长度接口，指出编译器替你排除了哪些路径，仍由你保证哪些逻辑条件。
