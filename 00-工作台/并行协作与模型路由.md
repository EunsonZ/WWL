# 并行协作与模型路由

稳定边界见 [[AGENTS|AGENTS.md]]；内容方法见 [[00-工作台/维护指南|维护指南]]。本页在需要分工时阅读，普通小修由主进程直接完成，不要求每名代理加载整套手册。

## 先选问题，再决定是否并行

一个作者负责一个可交付的读者问题，必要时覆盖多篇正文、图源和代码。作者自己串起对象、直觉、推导或论证、例子、实现与边界；不要把连续解释拆成互不相识的“概念作者、公式作者、代码作者”。独立查源、复算、制图和重要结论核查可以并行，仍由该作者接成完整解释链。

主进程确定读者终点、共同前提、文件归属和优先顺序。共享主库同一时刻一名已授权整合者，默认主进程，可明确交接。领域作者承担内容判断，核查者检查重要结论；整合者不重做所有查源与逐段审阅。职责随任务分配，作者不能独立核查自己修改的论证或行为。

## 容量、工作区与写入

启动时读取当前工具实际提供的容量、计数方式、模型选项与权限。总槽位应计入主进程和全部后代；另有子代理上限时同时满足。文件中的目标值不证明真实容量，不通过另开会话放大数量，也不为填槽拆任务。指令或配置改变后确认实际加载，旧会话不会因文件已改就自然成为新配置的运行证据。[1][2]

主进程派发具体文件归属：例如一名作者负责某几篇正文及其图源、脚本与镜像，另一名作者负责不重叠的另一条链。共同定义、入口和同一源码的镜像不能同时交给不同写者独立定稿。归属只持续到这次交付，不占有整个学科；需要交接时明确哪份候选是接续版本。

子代理只读或写各自获授权的候选区，由当前已授权整合者落库。需要分开文件状态时按需使用独立工作区 / worktree；原只读角色不能靠提示词升级为写者，不能借插件、CLI 或其他工具越权。目录与 worktree 不替代实际权限边界；没有适当隔离时并行只读提案即可。[2][3]

有独立结果就滚动接收，优先解除关键阻塞和消化待审稿；审阅或整合积压时减少新作者。无需等全批齐步，不为一个阻塞冻结无关问题。线程、CPU、内存与外部接口各有真实限制，不同时重复跑全库检查或昂贵实验。

## 派发只有四组输入

1. **问题**：读者哪里卡住，本次准备让他理解什么。
2. **入口与前提**：必要文件、原始依据、共用定义，以及已有授权中的边界。
3. **写文件**：本任务可写的具体候选文件；共享文件交给谁整合，只读时直接说明。
4. **完成标准**：能解释、复算或观察什么；哪些重要结论需要独立核查，哪些范围尚不覆盖。

这些信息可由主进程从用户请求与现场补全，不要求用户填模板。已经明确的内容不用逐字段重写；多名代理也不用共写清单。工作者在既定任务与授权内持续推进，常规修订不逐步请示；新权限、费用或超出范围的问题才另行确认。

普通链接不是等待关系。只读稳定前提的任务可以并行；确实要使用尚未形成的新定义时，先澄清这个前提，或先做不依赖它的部分。改变共同定义、删除责任或计量口径时，核对最终组合；两篇各自通顺不保证组合没有缺口。

## 模型、推理强度与经济性

枚举、路径、差异与确定性计算优先使用脚本。范围清楚的定位、提取和局部表达用足够完成任务的能力；跨层推导、因果辨析、复杂代码语义或高影响前提直接给足推理能力，不强迫先让较轻模型失败。核查的能力取决于问题难度和影响，不取决于角色名称；不固化型号、价格、角色配比或 effort 档位。

只使用当前工具支持且获授权的选项；无法指定或观察模型时如实说明，不把请求值写成实际值。先区分资料缺失、上下文漏项、工具权限、限流、格式问题与推理不足，再决定补证据、缩小任务或调整能力。重复尝试需要新的依据或方法，不能靠增加推理强度替代缺失材料。

上下文只给必要入口与局部材料，不复制全库说明、历史日志和长对话；常驻指令不抄写目录与正文摘要。先定位需要的原文再按需读取，单纯把同样内容移进多层技能文件不保证节省上下文；被明确要求全文阅读的任务仍须读完规定范围。只有实际反复需要的窄流程才考虑技能，不为每域另建协议。核查者看标准、原文和候选，按需独立复算后再对照作者说明；同一代理摘要不算多份独立证据，分歧靠原文和反例解决。

经济性看得到的成果、端到端耗时、返工和必要核查成本。仅在评估或调整模型路由、协作方式时，用两组已有代表性任务比较实际交付、重复阅读/测试和整合等待，优先复用已有证据，不作为每次内容任务的前置；把关键结论正确性与必要内容完整性分别核对，不能用引用更多、篇幅更短或合成总分抵消其中的退步。短文件、更多代理或少几个token都不是自动成功指标。没有可靠用量时只报告观察到的工作变化。用户设置费用上限时，主进程为收尾与核查留余量；没有实际用量就不报精确金额，不把订阅用量套成 API 账单。只有确需金额核算时才查 [[scripts/MODEL_COST|离线费用说明]] 与当时价格，不给普通内容任务维护请求账本。

## 核查、整合与完成

语义不变的小修作者自查；重要定义、推导、因果、数量、代码行为或关键先修变化，由未参与该论证或行为修改的人或代理独立核查。核查具体变化及必要上下文，不因本组另一处措辞参与而失去资格，也不换角色名自审。核查资源暂缺时保留相关候选，继续无关工作，不降低重要内容门槛。

当前已授权整合者落库前检查最新目标与候选差异，保留人的新改动，核对受影响的共享定义、引用、图源与源码镜像。重要新变化只补核相关差异，不能用旧结论覆盖新内容。完整小组就绪即可整合，无须等全批；交接明确接续版本，不同时写共享主库。

验证强度见 [[00-工作台/维护指南|维护指南]]，实际命令见 [[scripts/CHECKS|维护检查说明]]。复杂迁移有实际恢复需要时才参考 [[scripts/COORDINATION|协作检查说明]]；普通多页内容修订不以 manifest、哈希收据或发布状态机为前置，也不要求各作者重复全库检查。专用检查器一旦用于某次复杂交付，仍按其原有校验合同执行；本约定只收窄启用场景，不放宽校验、伪造收据或绕过阻塞。

阶段完成或需要交接时一次简报：解决了什么、产物在哪里、做了哪些必要检查、真正未决项与下一步。已有结果可直接复用，详细证据保留在相应来源、实验或差异中；不另造逐次回执和用户待办。完成标准满足就停止，维护记录或无依据返工成为主要工作时先删步骤，不继续加规则。
