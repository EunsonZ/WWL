# Python 深化：异步并发、取消与可靠工程

> 阅读定位：核心语言与标准库；结构化并发示例需要 Python 3.11+。返回 [[计算机知识/00-开始/课程地图/04-Python-课程地图|Python · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## async 解决等待，不自动加速所有工作

调用 `async def` 函数得到协程对象，不等于已完成工作。事件循环在协程等待可让出时推进其他任务；把 CPU 密集循环放进协程且不让出，仍会堵住循环。线程适合某些阻塞 I/O 和释放解释器锁的本地扩展，多进程可隔离地址空间但有序列化和进程成本。CPython 的 GIL 行为应按版本、构建和扩展确认，不能用“Python 永远只能单线程”作总解释。

## 结构化并发让子任务有归属

```python
import asyncio

async def square(x: int) -> int:
    await asyncio.sleep(0)
    return x * x

async def main() -> list[int]:
    async with asyncio.TaskGroup() as group:
        tasks = [group.create_task(square(x)) for x in range(4)]
    return [task.result() for task in tasks]

if __name__ == "__main__":
    assert asyncio.run(main()) == [0, 1, 4, 9]
```

这个例子需要 Python 3.11+。TaskGroup 让任务结束与退出上下文对应，并按约定处理子任务失败与其他任务取消。它与 `gather` 的失败传播和兄弟任务处理并不完全相同。实际任务可能抛出异常组，调用者需按错误分类处理，而不是以为退出上下文必然代表业务成功。

取消通常通过在适当位置注入取消异常实现；清理放在 finally 或异步上下文管理中。不要吞掉 CancelledError 后无限继续，否则会破坏上层超时与关闭协议。取消请求不等于远端已经停止，尤其当请求已发出或事务已提交时，需要幂等键、状态查询或补偿逻辑。

## 背压比“同时创建全部任务”可靠

给十万条输入各建一个任务，可能在真正工作前就消耗大量内存。用有界队列、固定数量 worker 或适当的并发限制，把生产速度与消费能力关联。限制同时持有资源的任务数，与限制总共创建的任务数不同；仅在每个任务里放 semaphore 并不消除所有任务对象开销。

超时应尽量从统一的单调时钟 deadline 推导剩余预算，而不是每一层重新给完整超时。重试应识别暂时失败、限制总次数并加入退避；不可重试的数据格式错误不应反复轰击下游。

## 测量和工程地图

先用小型可重复输入确认正确性，再区分 wall time、CPU time、峰值内存和尾延迟。微基准受缓存、解释器预热和输入分布影响；`cProfile` 定位调用开销，tracemalloc 观察受其追踪的分配，而不是整个进程的所有原生内存。

完整工程还包括 packaging、版本锁定、日志结构化、测试替身、属性测试、配置与秘密分离、数据校验、时区、数值精度、数据库事务和 API 兼容。练习为失败 worker 加测试，确保其他 worker 能退出、队列不会永久等待、已提交操作不会因重试重复生效。
