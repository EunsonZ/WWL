# 词法分析：最长匹配、位置追踪与可靠错误报告

> **学习位置**：[[计算机知识/00-开始/课程地图/12-编译原理-课程地图|编译原理课程地图]] · **适用边界**：教学语言与教学 IR；不把简化模型等同于 LLVM 全语义。

## 编译流水线先交付什么

词法器把字符序列转换成 token 序列，例如 `let total = 12 + x;` 变成关键字、标识符、等号、整数、加号、标识符与分号。token 应保留种类、必要的字面量信息与源位置；不要只返回几个字符串，直到类型错误时才发现已经无法指出问题在哪里。

字节偏移、Unicode 码点位置、用户看到的字形列和 UTF-16 单元偏移可能不同。编辑器协议、文件编码和错误下划线必须采用一致转换。编译器应先定义编码错误如何处理，不能靠“通常都是英文代码”避开。

## 最长匹配与规则优先级

输入 `>=` 应优先识别为一个大于等于 token，而不是 `>` 和 `=`。最长匹配决定最长可接受前缀；同长冲突再按明确规则解决。标识符与关键字重叠时，可以先读完整标识符，再查关键字表。

输入 `ifx` 不应拆成关键字 if 加标识符 x，因为整体是更长的标识符。负号是否属于数值字面量需由语言规格定义；常见设计把 `-12` 看成一元负号作用于正数字面量，这会影响最小负整数的解析边界。

## 一个不会悄悄跳过坏字符的扫描器

```python
import re
TOKEN = re.compile(
    r"(?P<WS>\s+)|(?P<INT>[0-9]+)|"
    r"(?P<ID>[A-Za-z_][A-Za-z_0-9]*)|"
    r"(?P<OP>>=|<=|==|!=|[+*/()=;<>-])"
)
def scan(source: str):
    pos = 0
    while pos < len(source):
        m = TOKEN.match(source, pos)
        if m is None:
            raise SyntaxError(f"unexpected character at offset {pos}")
        if m.lastgroup != "WS":
            yield (m.lastgroup, m.group(), pos, m.end())
        pos = m.end()
    yield ("EOF", "", pos, pos)
```

使用 match 并显式维护位置，是为了不让搜索接口跳过 `@` 等未知字符。该教学语言限定 ASCII 标识符，不实现注释、字符串、Unicode 标识符或任意进制整数；限制已经属于语言规格，不应伪装成完整 Python/C 词法器。

## 字符串、注释和词法状态

字符串中的反斜杠转义、引号和换行规则通常需要状态；块注释是否允许嵌套是语言设计选择。若允许任意深度嵌套，不能仅依靠经典有限自动机记住无界深度，需要计数/栈等额外机制。

保留 trivia（空白、注释）有利于格式化和源到源变换；直接丢弃在只执行语义的编译器中可能合理，但会限制后续工具用途。具体语法树保留更多源形态，抽象语法树舍去对语义不重要的标点结构，两者用途不同。

## 错误恢复与测试

在非法字符后立即退出易于实现，但编辑器通常希望一次显示多个错误。词法恢复可以跳到可识别边界，语法恢复可以跳到分号或右括号等同步点；必须防止恢复不消耗输入导致无限循环，也要避免一个错误引发几十个无意义级联错误。

测试应覆盖空输入、文件末尾无换行、最长运算符、关键字前缀、非法字符、未闭合字符串和超长字面量。字面量数值转换还要检查目标范围，而不是依赖实现语言整数恰好足够大。

**练习**：为何不能用 `findall` 找出所有合法 token 就结束？因为它可能跳过不匹配的字符，使错误程序被悄悄当成删掉坏字符后的另一个程序。扫描器的覆盖不变量应是：每个输入字符都被有意接受或明确报错。
