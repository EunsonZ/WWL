# Web测试模型与手工基线

**先修关系：** [[计算机知识/Kali/01-系统与网络基础/07-HTTP浏览器会话与信任边界|HTTP浏览器会话与信任边界]]；[[计算机知识/Kali/00-导航与方法/04-从观察到结论的安全方法|从观察到结论的安全方法]]；[[计算机知识/Kali/00-导航与方法/02-授权范围与风险分级|授权范围与风险分级]]。

## 从业务动作而不是漏洞名字开始

Web 测试的基本单位应是“某个身份在某个状态下对某个对象做某个动作”。先梳理路由、参数、角色、对象所有权和数据流，再选择工具。一个没有业务模型的扫描，很容易重复报告无关首部，却漏掉真正的跨账户访问。

本课程沿用 Alice、Bob 与报告对象：Alice 拥有 17，Bob 拥有 18。核心安全合同是“普通用户只可读自己的报告；管理员权限需单独声明”。这个合同既能用 HTTP 手工检查，也能在离线函数测试中验证。

## 建立三张相互连接的表

资产表回答哪些域名/服务在范围内；接口表记录路径、方法、参数与状态改变；权限表记录身份、对象、操作与预期。表的作用是支持推理，不是为了堆字段。

| 动作 | 身份 | 对象 | 预期与可观察证据 |
| --- | --- | --- | --- |
| 读取报告 | Alice | Alice 的 17 | 返回 17 的公开教学内容 |
| 读取报告 | Alice | Bob 的 18 | 拒绝或按产品设计隐藏对象，不返回 18 内容 |
| 读取报告 | 未认证 | 17 | 不泄露私有内容 |
| 更新报告 | Alice | 17 | 需要会话与防重放/跨站控制，记录状态变化 |

前三项可以先在 [[计算机知识/Kali/07-综合实验/04-实验CWeb请求与访问控制|离线权限模型]] 中完成；第四项需要专门应用与清理策略，本包静态 HTTP 服务没有更新接口。

## 测试流程与工具入口

先用浏览器正常操作，再用 [[计算机知识/Kali/03-Web与API安全/02-curlHTTPie与接口重放|curl]] 重现一个请求；用 [[计算机知识/Kali/03-Web与API安全/03-BurpSuite工作流|Burp]] 或 [[计算机知识/Kali/03-Web与API安全/04-ZAP代理与被动扫描|ZAP]] 观察字段和状态；只有当问题空间明确后，才用 [[计算机知识/Kali/03-Web与API安全/05-ffufGobuster与内容发现|ffuf/Gobuster]] 扩展输入或路径。涉及数据库边界时读 [[计算机知识/Kali/03-Web与API安全/06-SQL注入原理与sqlmap限界验证|SQL 注入]]，涉及对象权限时读 [[计算机知识/Kali/03-Web与API安全/08-认证会话越权与API测试|授权矩阵]]。

OWASP WSTG 提供系统化测试分类，但分类不能替代应用自己的安全需求。[^s1] 没发现某类问题，不代表所有业务权限都覆盖了；发现一条路径可达，也不说明它可以被所有角色安全访问。

## 一个实验只改变一个关键因素

比较 Alice 与 Bob 时固定对象；比较对象 17 与 18 时固定身份；比较登录前后时固定请求。若同时换用户、浏览器、代理、Host、路径和数据库状态，结果差异就难以归因。

至少保留正常输入、异常输入和修复后重复检查三个位置。边界值、空值、重复参数、编码形式可能触发不同解析路径，但每次应说明期望，不是盲目粘贴大量 payload。

## 状态改变与停止条件

GET 也可能因错误实现改变状态。支付、发邮件、发短信、创建账户、删除对象和上传文件都需要明确测试数据、回滚与预算。遇到真实敏感数据，停止扩大读取，只保存最小必要且脱敏的证据，并按约定通知负责人。

停止条件可包括连续 5xx、响应时间异常、限流、认证锁定或超出范围的重定向。具体阈值由系统负责人批准；本课程不把某个固定请求速率包装成所有环境都安全。

## 自检

一个应用所有端点都返回 200，但响应体分别包含“成功”和“无权限”。只按状态码统计会发生什么？会把业务拒绝误判成成功，可能高估越权或漏掉错误授权。应使用状态、内容、对象标识和后端记录共同判定。

完成本页后，你应能把“测一测这个网站”改写成一个有目标、变量、控制条件、证据和停止规则的小实验；这比一次运行十个扫描器更接近可复核评估。

## 将一个发现写成可以被推翻的假说

继续使用报告系统：假说不是“接口有问题”，而是“已认证 Alice 能读取归 Bob 所有、按产品合同应为私有的报告 18”。其中主体、对象、动作、期望和环境都可单独核对。

先以 Bob 读取 18 建立存在性与正常路径，再以 Alice 读取自己的 17 建立会话有效性，最后固定 Alice 的会话只改变对象为 18。若第三步返回拒绝，不能立即宣布全站授权安全；该结论只覆盖这个主体、对象、动作和状态。若返回数据，也先检查该报告是否实际上被共享、缓存是否用错身份、浏览器是否串了会话。业务授权合同仍是判定基准。

把这三个步骤按顺序保存，能避免两个很常见的伪结论：拿不存在对象的错误响应证明拒绝有效；拿已经过期会话的拒绝证明对象权限正确。

## 让证据包同时支持发现和反证

请求记录应包含方法、经过脱敏的路径/参数、所用测试身份、观察时间、工具版本、前置状态和请求编号；响应记录同时保留状态、首部、经过最小化的业务字段以及服务端相关日志编号。会话值不进入笔记或分享包。脱敏不能把两个不同账户都改成同一个字符串而破坏对照关系。

预先列出三个结果分支：符合预期、违反预期、无法判定。超时、502、验证码、登录重定向和解析错误通常属于第三类，除非实验本来研究这些现象。修复验证再加一项“原来的合法功能仍能完成”，否则关闭接口也可能制造漂亮但无意义的阴性结果。

## 自动扫描应该放在什么位置

手工基线给出身份与业务语义；代理保存可审阅请求；扫描器提供需要复核的候选；日志和源码解释机制；回归测试固定已经理解的安全合同。这些层次互相补证，没有一个层次能够取代全部其他层次。
