# 深层机制数值实验：把难点变成可失败的断言

这一组实验检验的是明确的小型数学对象和 CPU 实现，不把大模型名字当作测试内容。42 个 unittest 方法分别比较手算、精确枚举、有限差分或 PyTorch 自动微分；部分方法包含多个断言。统计时按测试方法计数，不按断言数膨胀。

## 运行方法

本轮实际环境是 Python 与 PyTorch 2.10.0+cpu，使用 CPU 和双精度小张量。没有 GPU、联网下载、外部模型权重，也不要求私人数据。进入本页所在目录后运行：

```bash
python -m unittest discover -s . -p 'test*.py' -v
```

源码是 [mechanisms.py](mechanisms.py) 和 [test_mechanisms.py](test_mechanisms.py)。不要修改参考值来消除失败；先确定假设是否成立、哪个实现独立、误差容限是否合理。实际全库执行结果见[../../90-资源/维护/深化研究/test_runs.json](../../90-资源/维护/深化研究/test_runs.json)。

## 理解验收强度

小例通过意味着指定实现没有被这些断言推翻，不意味着不存在其他 bug。解析式对自动微分可发现实现差异，有限差分提供额外独立检查；两边调用同一函数的自我比较则可能一起出错。因此测试采用多个来源交叉核验，仍需明确覆盖面。

本轮没有真实多卡/多机 DDP、CUDA kernel、BF16/FP16 GPU 数值稳定性、真实大模型训练、线上服务或 Obsidian 桌面逐页点击测试。相关章节提供方法与边界，不能在复现记录里填写“已通过”。完整核验和历史记录区分见[[AI/90-资源/08-本轮深化修订与验收报告|本轮报告]]。
