# 从比特到表达式：整数提升为什么会改变答案

> **学习位置**：[[计算机知识/00-开始/课程地图/01-C语言-课程地图|C语言课程地图]] · **适用边界**：ISO C17；C23 与 POSIX 扩展另行标识。
> **先修要求**：能读懂变量、条件和循环。

## 先把“数值”和“存储表示”分开

C 的类型不是给数学整数换个名字，而是同时规定可表示范围、运算规则和接口约束。`sizeof(char)` 恒为 1，但这个 1 是一个 C 字节，不承诺在所有实现上恰好是 8 位；位数查 `<limits.h>` 的 `CHAR_BIT`。`int` 至少满足标准规定的最小范围，却不保证是 32 位。网络格式需要恰好 32 位时可以使用 `<stdint.h>` 的 `uint32_t`，但这种精确宽度类型只在实现能提供时存在。

不要用“这台电脑是 64 位”推导 `long`、指针和文件偏移的大小都一样。LP64 与 LLP64 的差异解释了为什么一个程序在 Linux 上运行正常，迁到 Windows 后打印或序列化出错。格式化输出使用与类型匹配的格式说明符；`size_t` 用 `%zu`，精确宽度整数可用 `<inttypes.h>` 的 `PRIu32` 等宏。

## 一次计算之前，编译器先决定用什么类型

考虑常见的 32 位 `int` 实现：

```c
unsigned short a = 60000;
unsigned short b = 2;
int x = a * b;
```

乘法不一定在 `unsigned short` 中完成。若 `int` 能表示该类型的全部值，两个操作数先提升为 `int`，因此得到 120000。若 `int` 不能表示全部值，提升规则不同。这不是“乘完再看接收变量”，而是**操作数决定计算类型，赋值只发生在后面**。

同理，`long long result = x * y;` 不能修复两个 `int` 相乘时已经发生的有符号溢出。应该先在足够宽的类型中算，例如 `(long long)x * y`，并继续检查结果类型本身是否足够大。

再看混合符号：在常见实现中，`-1 < 1u` 为假。比较前的通常算术转换可能把 `-1` 转为无符号大数。解决方案不是到处强制转换，而是让数量、索引、差值拥有一致的类型协议：大小使用 `size_t`，确实可能为负的差值使用能表示该差值的有符号类型；跨边界时先检查范围再转换。

## 溢出检查要发生在运算之前

无符号加法按模 $2^w$ 运算；这对哈希和位操作有用，却不适合悄悄计算分配长度。判断 `n * element_size` 能否放入 `size_t`：

```c
#include <stdbool.h>
#include <stdint.h>
#include <stddef.h>

bool checked_product(size_t a, size_t b, size_t *out) {
    if (a != 0 && b > SIZE_MAX / a) return false;
    *out = a * b;
    return true;
}
```

前提是 `out` 指向有效的可写对象。先乘再判断结果是否变小是错误方向：对有符号数，乘法可能已经触发未定义行为；对无符号数，也存在不能由单一大小比较识别的回绕情况。

对有符号加法，在计算 `a+b` 前可分正负检查：当 `b>0` 时要求 `a<=INT_MAX-b`；当 `b<0` 时要求 `a>=INT_MIN-b`。检查式本身也必须不溢出。生产代码可使用平台提供的 checked-arithmetic 接口，但必须标清它是不是 C17 标准接口；C23 的 `<stdckdint.h>` 属于另一个语言版本边界。

## 移位和除法的边界比运算符外观重要

移位量必须非负且小于提升后左操作数的位宽。不要以为 `x << 32` 在 32 位类型上会“自然变成零”。位掩码优先在无符号类型中构造；`1 << 31` 与 `UINT32_C(1) << 31` 的类型和合法性并不相同。

C17 中负有符号数右移的结果具有实现定义性质；负数左移和无法表示的有符号左移结果不可随意使用。整数除法向零截断，例如 `-7/3 == -2`、`-7%3 == -1`，与 Python 的向下取整不同。还要检查除数零，以及最小负整数除以 `-1` 这一不可表示结果。

## 浮点数：先问误差来自哪一层

十进制 `0.1` 在常见二进制浮点中不能精确表示。误差可以来自输入舍入、每一步运算舍入和算法对误差的放大。比较近似量时可使用绝对与相对容差的组合：

$$
|a-b|\le \varepsilon_{\rm abs}+\varepsilon_{\rm rel}\max(|a|,|b|).
$$

这里的容差必须由问题尺度决定，而不是机械使用机器 epsilon。接近零时绝对容差重要；数值量级很大时相对容差更合理。NaN 不等于自己，`a==a` 不能作为普遍数学真理参与重写。金融金额通常应先定义最小计量单位与舍入规则，再选择整数或十进制定点方案。

## 推演练习与答案

在 `size_t` 为无符号类型时，为什么 `for (size_t i=n-1; i>=0; --i)` 不可靠？先考虑 `n=0`，初始化已经回绕；即使 `n>0`，条件也永远为真。安全的反向遍历形式之一是 `for (size_t i=n; i>0; ) { --i; use(i); }`。

为什么 `(double)(a/b)` 与 `(double)a/b` 不等价？前者先做整数除法，丢掉的小数无法通过转换恢复。这个例子也适用于时间平均值、吞吐量统计和算法中的概率估计。
