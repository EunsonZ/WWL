# SleuthKitAutopsy与文件恢复

**先修关系：** [[计算机知识/Kali/06-取证逆向与检测/01-取证流程镜像与时间线|取证流程镜像与时间线]]。

## 分区偏移为什么会决定整个分析是否有效

磁盘镜像可能包含分区表和多个文件系统；文件系统镜像则可能从自己的起点开始。Sleuth Kit 的 `mmls` 显示卷/分区布局，`fls` 列出文件系统内的名称项，`icat` 按元数据地址导出内容。先判断输入是哪种镜像，而不是遇到失败就随机增加参数。[^s1][^s2][^s3]

本包未分发磁盘镜像。以下 `own-disk-copy.img` 必须是你授权取得的工作副本，输出目录不能位于待恢复的源介质上。

```bash
mmls own-disk-copy.img
```

假设**示意输出**中一个分区从扇区 2048 开始，且已确认逻辑扇区为 512 字节，则起始字节偏移是

$$2048\times512=1{,}048{,}576\ \text{bytes}.$$

这不是对所有镜像的默认值。`fls -o` 与 `icat -o` 接收的是**扇区偏移**，不能把算出的 1048576 字节误传进去；不同扇区大小需核对 `-b` 和镜像元数据。[^s1][^s2]

## 补强：把偏移量的单位一直带到最后一步

前例的 `2048 × 512 = 1048576` 只在逻辑扇区确为 512 字节时成立。同样的起始扇区 2048，若证据确认为 4096 字节逻辑扇区，字节偏移就是 8388608。`mmls` 的分区起点和 `fls` 的 `-o` 使用扇区语义；`-b` 指定设备逻辑扇区字节数。不要根据磁盘商品标注的物理扇区大小，擅自改写镜像所使用的逻辑单位。[^v2-mmls] [^v2-fls]

正确的核对链是：采集说明或镜像元数据确定逻辑扇区大小 → `mmls` 读取卷布局 → 记录目标分区起点与长度 → 在下游文件系统命令中使用同一单位 → 核对识别出的文件系统及合理大小。识别失败首先回查“整盘镜像还是分区镜像”“是否缺分片”“扇区单位是否一致”，不是轮流猜偏移，直到碰巧出现几个文件名。

`fls -r` 的递归也不意味着恢复了删除目录的完整历史。目录项、元数据节点和数据块有不同的存活条件；工具可读出一个名字，不保证对应内容仍完整。[^v2-fls]

## 从目录名到字节：四个对象之间的连接

理解 `fls` 和 `icat`，先区分目录项中的名字、文件系统元数据记录、指向内容的数据分配信息，以及实际字节。`fls` 面向文件名与目录项并给出相应元数据地址；`icat` 依据指定元数据地址重建内容。这不是简单地“按名字把一段磁盘复制出来”。不同文件系统的记录和分配结构不同，下述 inode 只是便于理解的类 Unix 例子。[^v5-tsk-fls][^v5-tsk-icat]

原创例子：目录项 `report.txt` 指向元数据记录 42；该记录描述长度 6000 字节，逻辑内容映射到两个非相邻数据区。正确导出要按**逻辑文件顺序**组合，并截断到约定长度，不能把镜像中名字后面的 6000 字节当成文件。两个硬链接可共享同一个内容身份；同一个名字在不同时间也可能指向不同记录。名称、记录号和内容哈希不能互相替代。

删除目录项不等于立即擦除全部内容；反过来，发现旧名字也不等于旧内容仍完整可恢复。元数据已重用、部分数据被覆盖、文件系统具有驻留内容或稀疏区时，恢复所需条件各不相同。前面的“三种身份”应据此理解，而不是只为导出文件增加几个标签。

## 先列目录，再定位，再导出

```bash
# 2048 仅用于上述已确认的示例布局，实际必须替换。
fls -r -o 2048 own-disk-copy.img > files.txt
# 假设上一输出中的目标元数据地址为 42；不是通用编号。
icat -o 2048 own-disk-copy.img 42 > recovered-42.bin
sha256sum recovered-42.bin
```

`fls` 的名称项与元数据地址帮助定位对象；不能仅从文件名决定内容可信。若元数据已复用、数据块被覆盖或文件碎片严重，恢复结果可能不完整。命令成功退出不保证语义上恢复了原文件。继续用 [[计算机知识/Kali/06-取证逆向与检测/04-文件元数据Binwalk与ExifTool|file、十六进制与格式解析]] 检查长度、头部和内部结构。

`fls -m / -r -o 2048 ...` 可输出供时间线处理使用的记录；之后的 `mactime` 需要明确时区、日期范围与格式。不要把所有 MACB 时间当成同一种“发生时间”。本包只提供工作流，不伪造镜像执行输出。

## Autopsy、PhotoRec 与 Foremost 的分工

Autopsy 提供案件管理和分析界面，但 Kali 包、旧 Web 界面版本和当前其他平台发行版可能不是同一代产品；先核对实际版本与插件。新建案件记录时保留输入摘要、时区、导入选项和派生位置，不把 GUI 展示视为独立证据。

PhotoRec、Foremost 偏向按内容签名恢复；TestDisk 偏向分区与文件系统恢复任务。它们的“恢复”不都等于只读分析，写回分区表尤其具有破坏性。本包只说明定位，不让初学者对真实介质执行写回。恢复应面向副本，派生输出与原件分离。

## 文件系统恢复与 carving 为什么会给出不同答案

文件系统恢复利用元数据的关系来回答“哪些字节属于这个文件”；carving（文件雕刻）主要依赖内容格式的结构、边界或签名来寻找候选。前者可能因元数据丢失受限，后者可能在没有文件名时找到候选，但候选的原路径、原时间和碎片顺序通常不能只靠一个文件头推出。这里描述的是方法差异，不宣称所有 carving 工具都只处理连续片段。

设一种教学格式要求头、长度、内容和尾部互相一致。仅发现头部支持“存在候选起点”；头尾间隔符合长度进一步支持“结构可解释”；独立解析器完整解析支持“当前输出能按该格式读取”。三层证据仍不自动恢复原始文件名，也不证明中间片段未被其他数据替换。将“格式候选、可解析输出、可归属原件”分开报告，比给所有输出统称“成功恢复”准确。

工具选择上，Sleuth Kit 的命令暴露各层中间结果，Autopsy 把证据对象、分析模块与案例管理组合起来；PhotoRec/Foremost 等内容恢复工具提供另一类候选。它们不是互相投票确认真相的三位独立证人。关于签名候选和嵌套格式，继续读 [[计算机知识/Kali/06-取证逆向与检测/04-文件元数据Binwalk与ExifTool|Binwalk 与文件结构]]；关于字节、元数据和记录时间的区别，返回 [[计算机知识/Kali/06-取证逆向与检测/01-取证流程镜像与时间线|取证论证]]。

## 补强：导出文件存在，不等于 icat 成功

Shell 在启动命令前就可能创建 `>` 的目标文件。因此，即使 `icat` 失败，`recovered.bin` 也可能存在或为空。应把输出身份、退出码和错误输出一起保存。本段是工作目录中的步骤示例，`disk.img`、扇区和元数据地址必须由你已有的授权镜像确定；本包没有磁盘镜像，不可原样视为可运行实验。[^v2-icat]

```bash
# 已核实的教学假设：512 字节逻辑扇区，分区始于 2048，元数据地址为 42。
# 在新的空输出目录运行；不覆盖已有恢复证据。
set -o noclobber
if icat -b 512 -o 2048 disk.img 42 > recovered.partial.bin 2> icat.stderr.txt; then
    sha256sum recovered.partial.bin
    wc -c < recovered.partial.bin
    # 成功后仍需核对期望大小、格式和上下文；自行决定是否重命名。
else
    rc=$?
    printf 'icat failed: %s; preserve partial output and stderr\n' "$rc" >&2
fi
```

保留失败时的部分输出，但标记为不完整。零填充区域可能来自稀疏文件、采集缺口或工具处理策略；导出选项可能改变洞区的表示。不要把“有一片零”直接解释成擦除，也不要把 carving 找到的文件头当成完整原文件。独立核对内部长度、尾部结构和关联元数据，记录不能恢复的部分。

## 一份恢复结果需要三种身份，而不只一个文件名

输入镜像的摘要标识“分析的是哪份字节”；元数据地址及相关属性标识“解析器从哪里找内容”；导出文件的摘要标识“这次实际得到哪份字节”。这三者不能互相替代。原路径名可帮助理解上下文，但目录项和内容的存活情况不同，同名或相同元数据编号也不自动证明时间上的连续身份。

以已有示意地址 42 为例，记录不能只写 `recovered-42.bin`，还应写镜像摘要、镜像类型、分区起点、逻辑扇区大小、文件系统类型、完整元数据/属性地址和 icat 选项。某些文件系统具有多个数据属性或流，`icat` 接受的地址形式不一定只是一个无附加含义的整数。应沿实际 fls/元数据结果定位，不从“42 看着像 inode”推定每种文件系统一致。[^v3-icat]

### 稀疏洞区的表示可以改变派生文件

icat 的稀疏区处理选项会改变导出结果的表示。若省略洞区，输出长度、后续字节偏移和摘要都可能不同；这不是原镜像被篡改的充分证据。比较两次恢复时，先固定导出选项，再区分文件逻辑内容、实际占用块与恢复文件的物理存储。[^v3-icat]

用一个原创纸面例子：逻辑文件为 4096 字节数据、4096 字节洞区、4096 字节数据。逻辑长度是 12288 字节；忽略中间洞区后形成的连续派生字节只有 8192 字节。这种导出可用于特定分析，但不能悄悄称为逐字节完整的原逻辑文件。洞区表示也不能凭自身证明用户曾执行擦除。

恢复到内容后仍需按文件格式验证内部结构。可打开、头部合理、解压成功、上下文一致是不同强度的证据。镜像没有包含原始数据或已被覆盖时，应保留无法恢复的事实，不利用猜测补齐“完整文件”。本包不附磁盘镜像，本节仍是文档推演；实际流程参照 [[计算机知识/Kali/06-取证逆向与检测/01-取证流程镜像与时间线|证据链与时间线]]。

## 三种常见错误

“没有分区表”不表示镜像损坏，输入可能本来就是文件系统镜像。“发现 JPEG 头”不表示尾部和压缩数据完整。“恢复了文件名”不表示内容与删除前一致。每次结论应带上工具版本、解析前提、偏移单位和内容检查结果，参见 [[计算机知识/Kali/06-取证逆向与检测/01-取证流程镜像与时间线|证据链]]。

> [!question] 自检
> 分区起始扇区相同但扇区大小从 512 换成 4096，字节偏移是否仍相同？不同，放大八倍。这个单位错误会导致解析落在完全错误的位置。
