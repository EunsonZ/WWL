# 数据编码与媒体系统 · MOC

“编码”至少可能指字符到字节、对象到文件、信息压缩、音视频 codec，甚至被误用来指加密或封装。这门课的第一目标，是让这些层次不再混成一团；第二目标，是从文件系统读出字节后，能沿着 **demux → decode → filter → encode → mux** 的数据路径解释 FFmpeg 在做什么。直觉上：**demux** 从容器拆出压缩轨道，**decode** 把压缩数据还原成帧/样本，**filter** 变换帧/样本，**encode** 重新压缩，**mux** 把轨道、时间戳和元数据写回容器；完整对象边界见 [[计算机知识/60-数据编码与媒体系统/12-FFmpeg架构Demux-Decode-Filter-Encode-Mux|FFmpeg 架构]]。

> [!info] 学习时长
> 18 篇稳定理论课的 frontmatter 预估合计约 **1320 分钟**；加上四个现有实践约 **1470 分钟**，不含选做、二读、资料核验和真实设备验收。这是课程规划量，不是必须一次完成的会话时长。

> [!abstract] 学完后的能力
> 你将能区分表示、编码、序列化、压缩、加密、codec 与 container；能解释图像、音频和视频从连续世界采样为数字数据时丢失了什么；能用 `ffprobe` 收集证据，并用 FFmpeg 完成安全、可复现的小型转封装、转码和滤镜任务，而不会把“命令成功”误当成时间戳、质量、许可或兼容性都正确。

## 先建立分层词典

| 层次 | 典型问题 | 例子 |
| --- | --- | --- |
| 表示与字符编码 | 符号或数值怎样对应位模式？ | 整数、浮点、Unicode、UTF-8 |
| 序列化与文件格式 | 多个字段怎样组成可解析对象？ | JSON、WAV、PNG header、GGUF metadata |
| 压缩 | 怎样利用冗余，用更少位表达信息？ | Huffman、LZ、预测、变换与量化 |
| Codec | 样本或帧怎样编码/解码？ | FLAC、Opus、AAC、H.264、AV1 |
| Container | 多路流、时间戳和元数据怎样封装？ | MP4、Matroska、WebM、MPEG-TS |
| 工具流水线 | 怎样探测、转换、过滤并验证？ | ffprobe、FFmpeg CLI、libav* 组件 |
| 文件与传输系统 | 字节怎样被读取、缓存、持久化或发送？ | VFS、page cache、socket、HLS/DASH |

> [!warning] 加密不是压缩，扩展名也不是证据
> 加密改变谁能理解数据，压缩改变冗余，container 组织多路数据，codec 定义媒体样本的编码方式。文件名后缀只是提示；真实判断还要结合魔数、结构、metadata、stream 信息和解码结果。

## 90—150 分钟最小媒体处理闭环

如果当前目标只是安全判断并转换一个受控媒体文件，不必先通读 18 课。按 `01 → 03 → 08 → 10 → 13 → 实践 01/02`：先分清格式层次和二进制证据，再认识视频时间基、stream 与容器，最后用 `ffprobe` 建立输入/输出对照并区分 remux 与 transcode。

完成这条路线时，至少交付一张诊断表：记录输入与输出的 container、每条 stream 的 codec、time base、时长、尺寸或采样率、所用命令、工具版本和验证结果。它能证明这次受控转换的观察事实，不能替代目标播放器、画质/听感、许可或硬件路径验收。

## FFmpeg 命令的证据顺序

1. 用 `ffprobe` 保存输入的 streams、format、duration、time base、codec 和关键 metadata；
2. 明确本次是复制压缩流、重新编码，还是只经过 filter；
3. 明确输入、输出和全局选项各自作用域，显式选择 stream；
4. 输出到新的、受控路径，不默认覆盖用户文件；
5. 再次 probe 输出，并检查预期 stream、时间戳、时长、尺寸、采样率和 codec；
6. 需要判断质量时，在对齐和同一处理链前提下使用指标，并保留主观检查；
7. 保存 FFmpeg 版本、完整命令、输入哈希或合成方式、日志和环境；
8. 不把一次退出码 0 扩大为播放兼容、视觉质量、音画同步、许可证和硬件路径全部验证。

快速变化的选项、硬件后端、codec 可用性与许可状态必须在执行当天回查官方文档和本机 `ffmpeg -version` / `ffmpeg -buildconf`，不要把本 Vault 的快照当作永久事实。

## 结课成功标准

- [ ] 我能用自己的例子区分编码、序列化、压缩、加密、codec 与 container。
- [ ] 我能解释采样率、位深、色彩采样、帧率、码率和时间基分别描述什么。
- [ ] 我能说明有损转码为何不能通过提高输出码率恢复已经丢失的信息。
- [ ] 我会先 probe、再设计流水线、输出到新路径、最后重新 probe 和验证。
- [ ] 我能画出一个媒体文件从 VFS/page cache 到 demux、decode、filter、encode、mux 的数据路径。
- [ ] 我不会把 PSNR、SSIM、VMAF 或某个音频分数当成无条件的人类感知真值。
- [ ] 我知道不可信媒体、协议输入、字幕、滤镜参数、metadata、专利和许可证都需要独立边界。
