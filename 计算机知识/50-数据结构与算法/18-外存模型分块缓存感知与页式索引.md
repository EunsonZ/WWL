# 18 · 外存模型、分块、缓存感知与页式索引

## 本课目标

学完后，你能把 RAM 模型的“一次访存”与外存模型的“一次块传输”分开；用块大小 `B`、快存容量 `M` 和数据量 `N` 分析扫描、搜索、归并与页式索引；能说明分块和缓存感知布局何时有效、何时只是把未验证假设写进程序；并用页读取次数而不是单次毫秒数比较索引布局。

## 1. 直觉：慢的不是每个比较，而是一次次去搬数据

在 RAM 模型中，随机读一个机器字通常算常数代价，因而二分搜索是 `O(log N)` 次比较。但数据在 SSD、磁盘、远程存储或页缓存之外时，系统常以整页/块传输：取 1 个键也可能搬来相邻的整块。连续使用这块中的多个键，就比每次跳到新块更能摊薄传输代价。

这是 [[计算机知识/30-计算机系统/04-缓存局部性带宽与延迟|缓存、局部性、带宽与延迟]]在算法代价模型中的继续；存储设备、块层、页缓存、写回与持久化的系统语义见 [[计算机知识/30-计算机系统/11-存储设备块层页缓存与持久化|存储设备、块层、页缓存与持久化]]。

## 2. 外存/I-O 模型的参数与不变量

经典两层外存模型用：

- `N`：元素数；
- `B`：一次外存与快存之间传输的元素数；
- `M`：快存最多容纳的元素数；
- 主要代价：块传输次数（I/O 次数）；快存内计算在简化模型中被次要化。

基本前提是数据在使用前必须在快存中，且一次 I/O 传输一个完整块。因此连续扫描 `N` 个元素的理想 I/O 数是 `Θ(N/B)`，更精确地说是与 `ceil(N/B)` 同阶，而不是 `Θ(N)` 次块读取。

这是抽象，不直接等于某台机器：操作系统预读、设备内部缓存、SSD 映射层、写合并、并发队列深度和远程请求都可改变实测。模型用于比较数据移动阶数，产品结论还要在目标层次测量。

## 3. 分块：在一块驻留时完成尽可能多的工作

**分块（blocking/tiling）**把计算拆成能在快存中重用的小块。例如矩阵乘法的朴素三重循环若反复跨越大行/列，同一数据可能被多次从慢层取回。分块后，先取一小块 A、B 和结果 C，在它们仍居留时完成多次乘加。

正确性不变量与性能假设必须分开：

1. 正确性：每个输出单元应累加的所有项被恰好处理一次，块边界不能遗漏尾部；
2. 容量前提：同时活跃的块与必需元数据能容纳在 `M` 中；
3. 布局前提：块内数据在物理/虚拟存储上足够连续，并能被预读或批量传输；
4. 代价前提：分块的索引计算、复制、填充、对齐和边界分支没有吞掉节省的传输代价。

“块越大越好”是反例：块大于可用快存会发生抖动，与其他数据争抢容量，并且增大无用数据传输。

## 4. 缓存感知与缓存无关

**缓存感知（cache-aware）** 算法在布局或块大小中显式使用 `B`/`M` 或实际页尺寸。例如让 B+ 树节点大致填满一页，或选择一个能容纳三个工作矩阵块的 tile size。优点是能针对目标层次；代价是参数可能随硬件、页大小、并发负载或数据大小改变。

**缓存无关（cache-oblivious）** 算法不把特定 `B`/`M` 写进算法，常用递归分解产生多尺度局部性。这不等于“完全不受缓存影响”，也不保证在每台机器上快于调优的缓存感知版本。理论 I/O 界通常仍有理想缓存、替换策略和“高缓存足够大”等假设，必须随结论一起陈述。

## 5. 外存归并：用 `M/B` 条有序流并行缩减轮数

当 `N>M` 时，数据不能一次在快存排序。外排的基本路线是：

1. 每次读入至多 `M` 个元素，在快存中排序，写成有序 run；
2. 为每个输入 run 保留一个大小约 `B` 的输入缓冲，并保留输出缓冲；
3. 一轮可合并与 `M/B` 同阶的 run，每轮顺序读写全部数据。

注意 `M/B` 是归并 fan-in 的数量级，但必须实际大于 1：内存要同时容纳多个输入 run 的缓冲区和至少一个输出缓冲区。若 `M/B ≤ 1`，对数底不成立，不能仅凭 `N>M` 套用下式。在常见前提下，外排 I/O 复杂度写作 `Θ((N/B) log_(M/B)(N/B))`。这个式子的直觉是：每轮扫描 `N/B` 块，每轮把 run 数缩小约 `M/B` 倍。式子不包含比较次数、压缩/解压、写放大、远端 API 限流或崩溃恢复代价。

## 6. 页式索引：扇出、填充率和范围扫描

B 树/B+ 树的具体结构见 [[计算机知识/50-数据结构与算法/06-平衡树B树Trie与索引结构|平衡树、B 树、Trie 与索引结构]]。在 I/O 模型里，若一页可容纳 `Θ(B)` 个键/指针且非根节点有受保证的最小填充率，扇出与 `B` 同阶，从根到叶的页数是 `O(log_B N)`。根和上层若常驻缓存，实际慢 I/O 还可更少；若页半空、键变长或附带巨大载荷，不能拿“最大扇出”当成高度保证。

B+ 树范围查询先用对数层定位下界叶页，再沿叶页顺序扫描。若返回 `K` 个紧凑元素，理想 I/O 数可表示为 `O(log_B N + K/B)`。这需要叶页按键有序链接/可顺序定位，且返回记录不又引发 `K` 次随机回表。

一个两层玩具索引可把每页首键（fence key）保存在驻留内存的目录中：先二分 fence keys，再读一个候选页。它展示“比较许多住留元数据，换取一次页读取”，但不是完整 B+ 树：没有动态分裂/合并、持久化、校验、事务、并发控制或崩溃恢复。

## 7. 不要把页读少误说成系统已快且安全

| 算法证据 | 它支持什么 | 不支持什么 |
| --- | --- | --- |
| 固定页尺寸的页读计数 | 在该抽象布局下搬运的页数 | 真实 SSD 延迟、OS 缓存命中或远端计费 |
| 键比较计数 | 索引导航和页内搜索的逻辑工作 | 变长键、locale 比较、解压或对象分配的固定成本 |
| 顺序范围结果正确 | 边界和排序语义 | 并发写入时的快照一致性 |
| 程序正常结束后文件可读 | 某次进程级成功 | 断电持久性与部分写入恢复 |

页式数据结构一旦落盘，正确性不变量还要加上页 ID 有效、类型/版本可解析、父子范围一致、自由空间不重叠，以及更新失败后能回到允许状态。文件系统日志/CoW 与应用索引事务不是同一层保证，可从 [[计算机知识/30-计算机系统/13-文件系统布局日志CoW与一致性|文件系统布局、日志、CoW 与一致性]]继续区分。

## 8. 完整例子：页大小改变搬运次数，不改变查询语义

键为 `0..127`，查询 `[32,96)`。若每页 16 个键，结果恰好来自 4 页；若每页只放 1 个键，需 64 页。两种布局都应返回同一组 64 个键，只是页传输数不同。这个对比隔离了结果正确性与 I/O 代价；它没有声称 Python tuple 就是真实磁盘页。

## 练习

1. 当 `N=10^9`、`B=4096` 个记录时，估算顺序扫描的块读数量级；解释为何么这不是毫秒估计。
2. 为矩阵分块列出正确性不变量、容量前提和一个块过大的反例。
3. 一个页式树的叶页有 70% 填充率，键又是变长的。说明为何么不能用“页容量除以一个固定键大小”直接宣称最坏扇出。
4. 运行 [[计算机知识/80-实践/05-数据结构与算法/10-区间结构与外存代价/README|区间结构与外存代价实验]]，保持查询不变，把 `page_size` 从 1、8、16 改到 32，记录页读与键比较计数，再解释两项指标为何可能交换。

## 成功标准

- [ ] 我能用 `N,B,M` 和块传输定义外存模型，并把它与 RAM 操作计数分开。
- [ ] 我能推导扫描 `Θ(N/B)` 的 I/O 直觉，并说明外排中 `M/B` 路归并为何减少轮数。
- [ ] 我能用页扇出和填充率解释 `O(log_B N)` 索引高度的前提。
- [ ] 我能把页读计数、键比较、真实计时、持久性和并发一致性分为不同证据层。
