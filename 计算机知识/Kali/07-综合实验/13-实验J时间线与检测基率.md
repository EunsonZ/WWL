# 实验 J：时间线、检测基率与文件熵

> [!abstract] 三种数值结果，共同的解释纪律
> UTC 时间用于比较时刻，精确率用于解释告警，字节熵用于描述频率分布。数值算得出，不等于因果、恶意性或来源真实性已经得到证明。

## 1. 时间转换与不确定区间

输入 [[计算机知识/Kali/07-综合实验/夹具/v2/timeline.json|timeline.json]] 记录 A 为 16:00:00+08:00、误差 ±3 秒，B 为 08:00:02Z、误差 ±1 秒。它们是合成时间，并非采集自你的计算机。

```bash
cd "$HOME/kali-lab/code"
PYTHONDONTWRITEBYTECODE=1 python3 - <<'PYCODE'
from reasoning_lab import utc_timestamp, definitely_before
print(utc_timestamp('2026-09-05T16:00:00+08:00').isoformat())
print(definitely_before('2026-09-05T16:00:00+08:00', 3,
                        '2026-09-05T08:00:02Z', 1))
PYCODE
```

预期为 `2026-09-05T08:00:00+00:00` 和 False。A 最晚可到 08:00:03，B 最早为 08:00:01，区间重叠；False 表示不能确定严格先于，不表示已经证明 B 先发生。误差界为输入假设，本程序没有从真实设备估计时钟偏差。[^v2-python-datetime]

模型要求大写 T/Z、秒字段、最多六位小数和明确偏移；拒绝缺时区、闰秒、未知本地偏移记号 `-00:00`，以及小时/分钟越界的偏移。RFC 3339 中 `-00:00` 表示 UTC 已知但本地偏移未知，并不等于“时间毫无意义”；本模型选择不接受它，是为了保留该语义差异，不能把本模型的拒绝政策说成 RFC 禁止此格式。[^v2-rfc3339]

Python 的日期解析函数接受范围不一定与这里的严格输入合同完全相同，因此先检查外层格式和偏移范围，再转换。单纯“库函数没有抛异常”不能代替应用合同检查。

## 2. 从混淆矩阵算出告警含金量

使用 [[计算机知识/Kali/07-综合实验/夹具/v2/metrics.json|metrics.json]]：TP=900、FP=9990、TN=989010、FN=100，总数一百万。TP/FP 等是相对于独立真值标签定义的计数，不能由规则是否命中自行产生。

```bash
cd "$HOME/kali-lab/code"
PYTHONDONTWRITEBYTECODE=1 python3 - <<'PYCODE'
from reasoning_lab import detection_metrics
print(detection_metrics(900, 9990, 989010, 100))
print(detection_metrics(0, 0, 0, 0))
PYCODE
```

第一项的 precision 约为 0.0826446、recall 为 0.9、FPR 为 0.01。第二项三者都为 None，表示分母为零而未定义，不是检测性能为零，也不是没有误报因此完美。计数必须是非负整数，布尔值、负数、字符串和浮点数一律拒绝。

把分母说清楚：precision 的分母是所有告警；recall 的分母是全部真实正类；FPR 的分母是全部真实负类。这三者混用时，即使数值计算无误，结论也会错误。完整推导与基率反例的权威解释在 [[计算机知识/Kali/06-取证逆向与检测/07-YARA日志与检测规则|检测指标专题]]，这里只负责执行与解释合同。

## 3. 一个高熵却完全可预测的输入

```bash
cd "$HOME/kali-lab/code"
PYTHONDONTWRITEBYTECODE=1 python3 - <<'PYCODE'
from reasoning_lab import byte_entropy
print(byte_entropy(b'A' * 256))
print(byte_entropy(bytes(range(256))))
print(byte_entropy(b'ABAB'), byte_entropy(b'AABB'))
PYCODE
```

预期分别为 0、8，以及两个 1。本次首项实际显示 `-0.0`，它与数值 0 相等，来自负号与浮点零的表示，不表示出现了负熵。后两种字符串排列不同，却有相同字节频率，所以本统计量相同。0 到 255 顺序排列极易预测，却得到最大经验字节熵；这直接反驳“熵为 8 就是安全加密”的推断。公式、单位和窗口边界见 [[计算机知识/Kali/06-取证逆向与检测/04-文件元数据Binwalk与ExifTool|文件分析]]。

空字节串没有本模型所需的经验分布，因此报 InputError，不偷偷填 0。输入最多 1 MiB，仅用于离线小样本。未实现滑动窗口曲线，也不据此自动分类文件格式。
