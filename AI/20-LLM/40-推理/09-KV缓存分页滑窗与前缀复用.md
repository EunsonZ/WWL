# KV缓存、分页、滑窗与前缀复用

**先修与定位：** 连接生成循环、[[AI/20-LLM/20-架构/11-RoPE相对位置缓存偏移与长度外推|位置与掩码]]、[[AI/20-LLM/20-架构/12-MLA线性注意力与状态空间的记忆取舍|压缩状态]]。

## KV缓存保存的是计算结果，不是新的知识库

因果 Transformer 中，给定相同模型、相同前缀和相同计算约定，过去位置的 K/V 不因后来 token 到来而改变。因此可以保留它们，避免逐步重新计算前缀。模型权重不变，缓存属于一次请求或可复用前缀的运行状态。

若标准注意力有 $L$ 层、batch 为 $B$、缓存长度 $T$、KV 头数 $H_{kv}$、头维 $d_h$、每元素 $b$ 字节，理想稠密缓存主体为

$$
M_{KV}=2LBTH_{kv}d_hb.
$$

例如 $L=32,B=1,T=8192,H_{kv}=8,d_h=128,b=2$，主体为 $2^{30}$ 字节，即 1 GiB。这里没有计算页表、对齐、量化尺度、临时张量或复制开销。MHA 使用更多 KV 头会增大缓存；MLA 则应按真实潜变量与位置分支另算，不能盲套这个公式。

## 分页是物理布局优化，不是删去历史

逻辑 token 连续，不要求显存地址也连续。分页把缓存分成块，通过映射访问，可以降低预留过大与外部碎片，并支持部分共享。PagedAttention 研究围绕这一思路构建了服务系统。[^S48] 它并不自动减少注意力需要读取的逻辑历史，也不等于线性注意力或内容压缩。

块大小会在页表开销、最后一块内部空余和内核访问效率之间权衡。复制共享页时要保持写入隔离，通常需要类似写时复制的策略；否则不同请求的后续 token 可能互相污染。最后一个未填满的块尤其需要明确有效长度。

## 前缀相同要相同到什么程度

只比较显示出来的提示字符串不够。缓存键至少要绑定精确 token 序列、模型权重和适配器、位置编码规则、相关 attention mask 与模板版本；涉及多模态还要绑定图像等编码内容。相同文字在不同 tokenizer 或特殊标记规则下可以生成不同输入。

访问权限也是必要约束。即使内容碰巧相同，也不应让跨租户复用绕过隔离、审计或泄漏用户活动。权限过滤不能只放在生成后的文本上，见[[AI/20-LLM/70-工程应用与工具链/09-Agent状态机幂等执行与提示注入边界|工具与数据授权]]。生产缓存策略还需考虑时间侧信道和敏感日志，本文不把哈希键等同于完整安全方案。

## 滑动窗口何时等价，何时改变模型

若模型原本就使用局部窗口，每层仅需保留其定义中的可访问位置，可以按精确掩码淘汰其他 K/V。若全注意力模型在推理时临时丢弃旧 token，则改变了计算，质量是否可接受需要任务测试。中间层隐藏状态可能已融合更早信息，并不意味着所有历史都可无损恢复。

窗口移动后 position id 是否继续增长、RoPE 如何处理、保留特殊 token 是否符合训练，都要明确。将位置从零重新编号而不调整已旋转 key，会造成不一致，见[[AI/20-LLM/20-架构/11-RoPE相对位置缓存偏移与长度外推|缓存偏移]]。

## 服务调度的三个不同目标

首 token 延迟受排队和 prefill 影响，每 token 间隔主要与 decode 调度有关，总吞吐则涉及同时容纳多少有效工作。提高大批吞吐可能让单请求等待更久。Chunked prefill 可把长提示计算切段穿插执行，但需比较调度与缓存开销，不能只看平均延迟。

容量规划要看并发长度分布和高分位尾部，而不是只用平均上下文长度乘平均并发。超出资源时明确排队、拒绝或降级策略，不能无声截断用户材料后仍声称读完。

自测：把 KV 缓存量化后，能否继续声称与全精度缓存完全等价？一般不能。存储近似会改变读取向量和后续概率，需要[[AI/20-LLM/60-模型格式与量化/08-量化误差传播校准目标与端到端评测|端到端误差评估]]；分页布局若保持数值和索引不变则是另一类优化。
