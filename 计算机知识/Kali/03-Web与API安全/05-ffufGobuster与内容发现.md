# ffufGobuster与内容发现

**先修关系：** [[计算机知识/Kali/03-Web与API安全/02-curlHTTPie与接口重放|curlHTTPie与接口重放]]；[[计算机知识/Kali/03-Web与API安全/01-Web测试模型与手工基线|Web测试模型与手工基线]]。

## 内容发现本质上是一个分类实验

字典把候选输入逐个代入请求，工具再用状态码、长度、词数或正则把响应分类。结果的质量取决于字典覆盖与分类规则，不取决于屏幕滚动多快。

先请求一个存在路径和一个明确不存在路径。如果不存在路径也返回 200 与统一页面，就遇到了软 404 或泛化路由。此时只匹配 200 会把每个词都列成“发现”，过滤也可能误删真实资源。

## 把“发现路径”转化为一个分类问题

先为自建站点建立三类对照：确认存在的 `/health`、确认不存在的 `/missing-lab-page`、另行设置的受保护教学路径。观察状态、Location、Content-Type、稳定文本与长度，再制定过滤条件。

| 合成观察 | 不能直接下的结论 | 最小后续核验 |
| --- | --- | --- |
| 200，正文是统一错误模板 | 路径存在且可访问 | 与随机不存在路径作稳定字段比较 |
| 302 到登录页 | 存在某敏感文件 | 分清全站统一登录跳转与真实路由 |
| 403，长度与许多路径一致 | 私有资源确实存在 | 检查反向代理是否统一拒绝所有请求 |
| 超时 | 路径不存在 | 单次低速重试并查看服务健康状态 |

`-mc`/`-fc` 等匹配与过滤在工具内部有具体组合语义，应按本机帮助确认。先保留未经积极过滤的低预算 JSON，再离线试分类规则；否则误过滤的条目从输出消失后，很难解释召回率损失。自动校准也会发出额外请求，不是零成本预处理。[^v2-ffuf]

## 路径、虚拟主机和 DNS 是不同枚举空间

URL 路径改变的是同一 HTTP 主机中的资源名；`Host` 改变可能选择不同 HTTP 虚拟主机；DNS 查询观察名字解析；HTTPS 的 SNI 在 HTTP 之前影响证书与 TLS 路由。一个字典发现过程不能自动代表其他三种边界。

本包默认只做 loopback 路径练习，不向共享 CDN、第三方域名或未授权子域扩展。Gobuster、Feroxbuster 与 dirsearch 的迁移应复用这里的预算和分类方法，再查各自选项，不应机械替换命令名。

## 字典如何影响结论

SecLists 是公开测试字典集合，包含许多不同目的的数据；不是所有字典都适合公开站点或登录接口。rockyou 等泄露口令字典也不应成为本课程默认依赖，本包只附自行编写的微型合成字典。

字典没包含一个路径，扫描没发现它属于**覆盖缺口**，不是“该路径不存在”的证据。字典命中只是路径响应的证据，不证明资源敏感或无授权。发现 `/admin` 返回登录页，通常不能直接报告“后台泄漏漏洞”。

## ffuf 的最小工作流

ffuf 用 `FUZZ` 标记替换位置，可用于路径、参数或首部等不同位置。[^s1] 本章只在自建静态服务中代入小路径字典，未使用凭据或敏感对象标识。

```bash
# paths.txt 使用附带的五项教学字典；先阅读每一项
ffuf -w paths.txt -u http://127.0.0.1:8000/FUZZ \
  -t 1 -rate 2 -timeout 3 -maxtime 15 -mc all \
  -of json -o "$HOME/kali-lab/output/ffuf.json"
```

前提是已启动 [[计算机知识/Kali/07-综合实验/02-实验A从路由到HTTP与Nmap|回环静态服务]] 且当前目录有教学字典。`-t` 是并发工作线程，`-rate` 是请求速率约束，`-maxtime` 是执行时间预算；它们不是同一个参数。先保留所有响应观察基线，再考虑过滤。

`-fc` 按状态过滤，`-fs` 按内容大小过滤，`-fw/-fl` 可按词数/行数；`-ac` 自动校准会产生额外请求，并且不是正确分类的保证。通用代理错误页、登录跳转与动态内容都可能误导过滤。

## Gobuster 与其他目录工具

Gobuster 的 `dir`、`dns`、`vhost` 对应不同空间，参数与默认行为会随主版本变化。先用 `gobuster dir --help` 确认支持的选项。[^s2]

```bash
gobuster dir --help
# 当前帮助确认后，才在相同的本机靶场执行小字典示意：
# gobuster dir -u http://127.0.0.1:8000/ -w paths.txt -t 1 --delay 500ms
```

Feroxbuster 更关注递归内容发现；dirsearch、Dirb 同属路径枚举工具。递归会让请求数从字典长度变成多个目录层的组合，默认深度、扩展名与重试必须审阅。Wfuzz 是更一般的输入替换工具，适合与 ffuf 比较过滤模型，不需要为了“覆盖”同时运行它们。

## 请求预算要包含组合和递归

只替换一个位置、每词一次且无额外请求时，5 个词产生 5 个候选请求；两个位置做全组合时，5×4=20。若改为按行配对则不是乘法。递归每发现一个目录又启动下一层任务，实际数量取决于分支与深度，不由初始字典行数单独决定。

因此同时控制并发、速率、总时间和递归范围。`-rate 2` 并不意味着运行多久都无影响，也不保证下游业务每个请求成本相同。先测一个小样本，再依据服务负载与授权调整，不从大型词典直接起步。

## 自动校准是在学习背景响应，不是在证明不存在

ffuf 的匹配、过滤、自动校准与输入组合控制的是怎样保留候选；Gobuster 的 dir、dns、vhost 等模式则改变枚举对象。它们都需要用户选择正确的观察空间与分类条件。[^v5-ffuf][^v5-gobuster]

把一条响应概括为特征向量 $x=(状态码,长度,词数,重定向目标,内容特征)$。过滤器其实是决定是否保留 $x$ 的函数。自动校准利用背景样本估计“常见无效响应”，但背景若随身份、时间、语言或防护状态变化，旧分类边界就可能失效。这是分类模型的解释，不是对某个版本具体学习算法的断言。

原创反例：不存在路径与存在但无权限路径都返回同一登录模板。按模板长度过滤，会同时去掉两者；保留全部又会制造很多假发现。下一步应增加能区分假设的证据，例如在已经授权的有效身份下比较资源语义，而不是把阈值反复调到屏幕看起来整洁。

还要分清候选数、请求数、不同响应数和真实资源数。多个路径可以被重写到同一对象，一个路径也可能在不同租户下对应不同对象。工具索引应保留原始候选及其请求条件，去重则按清楚声明的等价关系进行；相关原理见 [[计算机知识/Kali/03-Web与API安全/13-HTTP中间层与消息解释#缓存键是对请求划分等价类|请求等价类]]。

## 过滤器选错时，结果“更干净”可能恰好更错

构造一个纸面数据集：五个候选中两个是真实公开页面，三个不存在；其中一个真实页面与错误模板都恰好 100 字节。用 `-fs 100` 去掉模板时，也会丢掉这个真实页面。剩下列表更短，却不是准确率自动提高。

假设这个过滤器保留一个真实页面和一个错误响应，那么 TP=1、FP=1、FN=1、TN=2。这里 TP 表示保留的真实项，FP 表示误报，FN 表示漏掉的真实项，TN 表示正确排除的不存在项。精确率是 `1/(1+1)=50%`，召回率也是 `1/(1+1)=50%`。这是一份知道真值的原创教学对照；真实评估通常不知道所有遗漏路径，不能据此随意填召回率。

先用手工验证的小对照集选分类特征，再冻结规则跑微型字典；最后独立重放命中项并抽查被过滤项。状态、稳定正文、跳转目标和业务字段可以互补，但每加一个特征都要说明如何避免过拟合当前错误模板。工具的 matcher/filter 参数只负责按你指定的条件处理响应，不证明条件本身正确。[^v3-ffuf]

### 预算还需要一个停止判据

已有的并发、速率与总时间之外，写清“什么现象使这轮结果不可比较”。例如出现统一 429 后，后续状态分布可能主要反映限流，而不是路径是否存在；不能把该阶段的所有未命中都写成阴性。停止后保留失败数、最后正常响应时间和覆盖进度，下一轮恢复条件由服务负责人或本机实验状态决定，不增加并发试图越过控制。

该分类框架也适用于 [[计算机知识/Kali/06-取证逆向与检测/07-YARA日志与检测规则|检测规则]]：先说明真实问题和独立真值来源，再比较指标。工具名换了，误报与漏报的逻辑没有换。

## 输出、复测与预算

保存目标、字典 SHA-256、过滤规则、工具版本、并发、超时、总请求/失败数以及原始结果。不同 run 的结果比较必须固定这些条件。出现 429、连续 5xx 或响应延迟显著上升时停止并检查，不通过提高线程数强行“测完”。

自检：第一次用了 5 个词、第二次用了 50 万词，第二次发现更多是否说明工具更准确？不能，测试覆盖改变了；要比较工具，需要相同输入与独立确认的真实结果。
