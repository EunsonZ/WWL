## 类型推断的输入不是“程序看起来像什么”

先限定一个纯函数式核心：变量、函数、函数应用、`let`、整数和布尔值；类型包括变量、基础类型和函数箭头。这里讨论 Hindley–Milner 风格推断，不把它直接套到 C++ 重载解析、Rust trait 求解或 TypeScript 的结构类型上。它们共享约束思想，却有不同语法、子类型与决策边界。

类型推断分三步理解最清楚：为未知类型引入变量；按语法产生约束；求解约束并在合法位置泛化。推断失败可能是程序类型不一致，也可能超出该推断系统支持的表达能力，并不等于数学意义上“不存在任何安全解释”。[^infer]

## 一次逐行统一：f(f x)

考虑 `fun f -> fun x -> f (f x)`。设 `x:α`，`f:φ`。内层应用 `f x` 的结果设为 `β`，因此 `φ=α→β`。外层再调用同一个 `f`，其参数现在是 `β`，结果设为 `γ`，得到 `φ=β→γ`。

统一两种对 `φ` 的要求：

$$
\alpha\to\beta=\beta\to\gamma
\quad\Longrightarrow\quad
\alpha=\beta,\quad\beta=\gamma.
$$

于是 `f:α→α`，整个表达式类型为 `(α→α)→α→α`。最后两个箭头右结合：它接受一个函数，再返回接受 `α` 的函数，不是一次接收两个机器参数的 ABI 声明。

统一不是字符串替换。求出 `α=β` 之后，后续类型和环境中所有相关位置都必须一致应用替换；组合替换时有顺序，类比 [[计算机知识/50-数据结构与算法/10-数据结构系统课程/09-懒标记的代数与完整实现|懒标记的函数复合]]。求解器忘记把新替换递归应用到旧替换，常会产生“局部看对、整体矛盾”的结果。

## occurs check 为什么不可省

表达式 `fun x -> x x` 中，同一个 `x` 同时作为函数和自己的参数。若 `x:α`，结果为 `β`，要求：

$$\alpha=\alpha\to\beta.$$

在有限树形的 HM 类型语法中，没有这种有限解。绑定变量前必须检查该变量是否已经出现在右侧类型中，这就是 occurs check。省略它可能构造环，导致打印或后续替换无限递归；允许显式递归类型的系统则必须定义对应等价关系，不能靠删掉检查“支持高级类型”。[^occurs]

教学统一器至少要处理：同名变量直接成功；变量与不含它的类型建立绑定；同构造器、同元数递归统一；`int` 与 `bool`、函数与基础类型等构造器冲突立即失败。错误报告应保留约束来源，例如“第二次调用要求布尔输入，但第一次已固定为整数”，而不是只输出内部变量编号。

## let 多态与函数参数的区别

```text
let id = fun x -> x in
(id 1, id true)
```

在标准 HM 的这个纯表达式中，`id` 可以泛化为 `∀α. α→α`。每次使用先实例化为全新的变量：第一次 `α1→α1`，第二次 `α2→α2`。第一次统一为 `int→int` 不应污染第二次。

而下面表达式中的 `id` 是函数参数，普通 HM 不自动把它当高阶多态参数：

```text
fun id -> (id 1, id true)
```

两次使用共享同一个单态函数类型，要求参数同时为 `int` 和 `bool`，于是失败。支持显式高阶多态注解的语言可以表达相关意图，但那已经扩大了类型系统。

一般泛化规则为：

$$Gen(\Gamma,\tau)=\forall(FV(\tau)\setminus FV(\Gamma)).\tau.$$

`FV` 表示自由类型变量。意思是只量化本类型中独立于环境的未知量。若 `f` 捕获了外部未知类型的 `y`，`fun x -> y` 的返回类型受 `y` 约束，不能在每次使用时凭空变成另一个类型。泛化之前要先把已经求出的替换应用于环境和类型。

## 可变引用为什么破坏“每次用一个新类型”

假设允许把 `let r = ref []` 无限制泛化为 `∀α. α list ref`。第一次把 `r` 实例化为整数列表引用，写入 `[1]`；第二次实例化为布尔列表引用，把读出的第一个元素作为布尔值。两个静态实例实际指向同一个可变槽位，类型系统等于给同一段存储发了互相矛盾的许可证。

值限制防止这类不安全泛化。OCaml 用弱类型变量表达“尚未确定、但最终只能固定成一种类型”，并有基于协变的放宽规则。不能简化成“任何含 `let` 的地方都泛化”或“任何出现可变状态的程序都不能多态”。构造一个每次调用才创建新引用的函数，与在共享引用外套一个看起来像函数的表达式，也必须分别分析。[^value]

这个反例与 [[计算机知识/10-编程语言/04-Rust/10-系统课程/09-借用检查中的量词方差与重借用|可变引用的方差约束]] 相通：只读地观察值与允许向同一个槽位写值，对类型替换有不同要求。但 Rust 生命周期量词、OCaml 泛化和 TypeScript 条件类型的 `infer` 不是同一个机制，比较时要指出对应关系的边界。

## 推断成功之后还没有证明什么

推断器必须依赖可信的原语类型、FFI 声明和语言实现。网络返回值并不会因为被赋予 `Order` 类型而自动满足业务约束；运行时校验见 [[计算机知识/10-编程语言/05-TypeScript/10-系统课程/10-运行时边界状态机与取消安全|unknown 到可信状态]]。内存安全也不推出无死锁、终止、授权正确或数值稳定。

类型约束还存在不同层次：等式约束适合统一；子类型约束有方向；trait/typeclass 要查实例并解决相应限制；依赖类型可能包含值级证明义务。不要把所有错误解释成“统一失败”，也不要把 TypeScript 的 `any` 当成 HM 的一个普通未知变量。`any` 会放松检查，未知量则必须在约束中保持一致。

## 自检与实验

附带教学统一器对有限类型树测试链式替换、箭头拆分、构造器冲突和 occurs check；并核对 `f(f x)` 的类型、两次多态实例化不共享变量、环境自由变量不被泛化。它不是完整 OCaml 编译器，也不声称实现模式匹配穷尽性或完整 Algorithm W。练习：推导 `fun f -> fun g -> fun x -> f (g x)`；再给 `x x` 写出导致失败的唯一关键约束。
