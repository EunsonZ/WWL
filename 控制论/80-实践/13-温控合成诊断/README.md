# 温控器报告正常：这些日志能证明什么？

“每行都 `status=ok`，所以温度达标。”这句话把回执升格成了温度计。这里立即固定含义：**`ok` 只表示命令已被接收；是否施加、何时施加、物体是否达到目标，各需自己的证据。** 完成本项目时，你要交出一份允许写“现有信息无法判断”的调查报告。

全部文件都是**教学合成数据**。只读本页和 [student 记录包](data/student/README.md) 开始；其中五份日志用 case-01 至 case-05 编号，编号没有原因标签。教师材料、生成输入与源码另在 [教师入口](TEACHER.md)，公开保存便于复算；这里的分入口用于教学顺序，不是防作弊系统。先做预测再看答案，才能区分自己提出的解释与事后认出来的答案。

## 先规定“达到”指什么

对象是一块集中参数热体，所有温差均相对同一恒定环境基准，单位 K；目标为相对环境升高 **2 K**。不把温差 K 偷换成绝对温度 °C。本项目的有限记录验收约定为：在 **140 s 至 150 s 的整数采样时刻**，物体的温差均落在目标 ±0.05 K 内。记录只覆盖这些时点，不能据此保证样本间或未来永远达标。

你首先拿到的是一个读数通道与程序/执行记录。读数满足目标带，只能先记“读数带通过”；没有独立的测量可信度依据，就不能填写“物体温差通过”。新增独立参考若给出误差界 ±0.02 K，参考读数离目标不超过 0.03 K 才能直接保证该时刻的物体温差在 ±0.05 K 内；只给最终一个参考点也不能代替全部十一点的验收。

热对象、保持解和旧积分状态的基础解释在 [[控制论/10-系统课程/03-采样保持积分调节与实现边界#先规定测量、计算、保持和更新|03 的时序合同]] 与 [[控制论/10-系统课程/03-采样保持积分调节与实现边界#数字积分用旧状态，另外证明稳定|数字 PI]]。本页只保留调查需要的约定。

| 公开量 | 值与单位 | 在这里的用途 |
| --- | --- | --- |
| 热容量 C、散热系数 h | 10 J/K、1 W/K | 无额外净热作用时，平衡维持功率为 h×目标温差 |
| 采样周期、目标 | 1 s、2 K | 第 k 行从 k s 开始 |
| 比例增益、积分增益 | 3 W/K、0.4 W/(K·s) | 命令为 h×2 K + 比例增益×误差 + 积分增益×旧积分状态 |
| 初始积分状态 | 每份记录均为 0 K·s | 不是第一拍积分后的状态 |
| 名义功率范围 | 0 至 10 W | 是声明范围，实际施加仍查日志 |
| 初始读数 | 五份均为 0 K | 这没有独立认证物体初始温差 |
| 时间与数值比较 | 理想同钟、无抖动；数值对照容差 10⁻⁹ K | 这些是合成前提，不是设备测量报告 |

## 每行究竟记录哪一拍

从 [case-01.csv](data/student/case-01.csv) 开始。五份日志均有 150 行转移，最后一行的下一读数位于 150 s；上一行的 `y_next_K` 等于下一行的 `y_K`，不能把两者当成两次独立测量。

| 列 | 含义与单位 |
| --- | --- |
| `k`、`t_sample_s`、`y_K` | 整数拍号、拍首采样时刻 s、该时刻读数 K |
| `z_old_K_s` | 本拍计算命令所用旧积分状态 K·s |
| `u_cmd_W` | 本拍 PI 计算的原始命令 W，可能超过实际能力 |
| `ack_time_s`、`status` | 接收时刻 s、接收回执；本例均即时接收成功 |
| `apply_start_s`、`apply_end_s`、`u_applied_W` | 在左闭右开区间内保持的实际功率 W；这是模型给出的执行记录 |
| `z_next_K_s` | 旧积分状态加本拍误差×1 s，下一拍才能用于命令 |
| `next_sample_time_s`、`y_next_K` | 保持区间末的新采样时刻 s、读数 K |

时序为“拍首读数 → 用旧积分算命令 → 收到回执 → 在声明区间保持日志中的实际功率 → 下一拍读数”。积分更新与对象演化使用同一拍首误差，但本拍功率不会回头使用新积分状态。即使接收时刻相同，命令与本区间实际功率也未必相同。先从记录找这种差别，再提出执行时序解释。

## 先预测，再调查

1. 暂不读曲线和答案，手算即时使用本拍命令、无额外净热作用时的第一拍功率与下一读数。若第一次保持的实际功率是 0 W，第一秒读数又应怎样？列出旧积分与下一积分各是多少，说明你用了哪一个。
2. 检查五份日志中哪些回执成功，哪些命令与同区间实际功率一致。逐案给出 140–150 s 的读数带判断，并说明这离“物体达标”还差哪项证据。不能从有限曲线判定所有未来稳定。
3. 找到两份在 10⁻⁹ K 数值容差内观测一致的日志。为它们提出至少两个能解释相同记录的物理世界。若无法唯一定位原因，说明究竟缺什么信息；增加拟合阶数需要说明新增信息从哪来。
4. 对持续未达到读数目标的一份，先核实际施加功率的上界，再用热平衡检查目标需要多少功率。讨论累计误差继续增长能否扩大可实现的平衡集合。
5. 只允许增加一次观测，你会选择“原通道再读一千遍”“更复杂的拟合函数”“经过独立校准的第二参考温度”“已知独立初态”中的哪一个？指出各自新增的信息或假设。可提交多个合法方法，但须给可区分性和误差界，不能把两个相同来源的读数称为独立基准。
6. 将“协议/程序执行、实际施加、读数、物体目标”画成四行证据账。哪个记录支持哪一行？在哪个推理箭头上只能写条件句？

提交一张五行调查表，列“观察事实、可排除解释、仍相容解释、所需新增信息、判断适用范围”。好答案允许保留多个相容世界；强行给每份记录贴一个标签会丢失本题最关键的结果。

## 撤去提示：换尺度后能否复用结论

把 C 改成 20 J/K、h 改成 2 W/K，比例/积分增益分别改为 6 W/K、0.8 W/(K·s)，其余时间和目标不变，所有功率相关输入、上下界都加倍。预测读数与积分状态是否改变，命令与实际施加功率又怎样变化。给出系数/单位的理由，再请教师用第二组固定输入复算。不要仅把第一组数值复制进一张新表。

## 这个项目为何值得做

- **高优先：观测等价与离散时序。** 相同日志未必对应相同真实温度；旧积分/旧命令差一拍就改变模型和诊断。它们容易写错，而且会直接改变“可以知道什么”的结论。
- **高优先、真实接口未验证：独立校准参考。** 要把读数升级成物体温差证据，须接入确有独立校准链和绝对误差界的参考。当前只演示合成参考的区分能力，没有校准本机或任何外接温度计。
- **中优先：画时间曲线。** 画图可帮助发现持续偏差或错拍；重复表格已经清楚的现象时可以省略。数值预算与观测等价证明不能由曲线形状代替，所以本包直接保留可复算 CSV。

真实参考接口若将来另获硬件实验授权，最低记录为：同环境基准下的时刻、原通道读数、参考读数、独立校准记录、误差界和两通道对时误差。预期区分的是“同原读数、不同独立参考”，证据应存入该次实验的原始记录。**本项目没有运行这个接口，也没有连接加热器。** CPU 合成不认证硬件安全、未知真实故障、所有控制器或真人学习效果。

可比较 [[计算机知识/63-Web平台开发/03-Fetch请求取消与陈旧响应|Fetch 的协议成功与业务结果]] 的证据层级，再返回这里指认物理测量新增的责任：HTTP 响应和传感器不是同一种对象，“成功”二字不能消除端口与证据的差别。完成后返回 [[控制论/10-系统课程/03-采样保持积分调节与实现边界|采样与积分的主解释]]，指出本次调查实际用到了哪条前提。
