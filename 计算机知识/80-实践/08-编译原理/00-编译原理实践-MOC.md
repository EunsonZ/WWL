# 编译原理实践 MOC

这组实验把“编译器阶段”变成可运行、可检查、可失败的对象。基础路径只用 Python 标准库和合成输入；每个目录都能独立运行，不下载依赖、不修改系统工具链，也不执行外部不可信程序。

实践围绕一个受控的 MiniLang 展开，但各实验保持独立，避免前一课的实现错误让后面所有实验无法开始。最终实验再把阶段连成一条纵向流水线。

## 统一语言与证据合同

MiniLang 的核心值只有 `i32` 模运算和 `bool`；逐步使用 `let`、赋值、表达式、条件、循环、函数、返回与输出。课程明确不实现指针、不安全内存、并发、文件/网络 I/O、生产级 GC 或真实原生 JIT。

| 证据 | 能说明什么 | 不能自动说明什么 |
| --- | --- | --- |
| 静态阅读 | 数据结构、规则和边界写得自洽 | 代码实际运行、所有输入都正确 |
| 单元与性质样本 | 当前 Python 和受控样本满足断言 | 全称正确、工业编译器行为 |
| 差分测试 | 已生成输入上优化前后输出一致 | 未生成输入、并发、浮点或 UB 条件下仍等价 |
| verifier | 结构不变量满足当前实现的规则 | 业务语义正确、优化合法 |
| LLVM/MLIR 探针 | 当前机器上找到某版本工具并观察到一次结果 | 其他版本、目标或平台相同 |
| AI lowering toy | shape、guard 与融合规则在 CPU 小样中可复算 | 真实 GPU kernel 已运行或更快 |

## 运行约定

在每个实验自己的目录中运行：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest -v
```

- `PYTHONDONTWRITEBYTECODE=1` 与 `-B` 避免生成 `__pycache__`；即使忘记，也只能在确认精确目录后清理缓存，不执行仓库级删除。
- Python 实验不得写用户文件；需要临时内容时使用语言提供的安全临时目录并在退出时清理。
- LLVM/MLIR 实验只观察已安装工具。找不到工具时输出 `SKIP` 或退出 77 是合格结果，不自动安装。
- 所有随机样本使用固定 seed 并把 seed 写进失败信息；通过一次测试不等于形式证明。

## 实验路线

### A. 前端与语义

1. [[计算机知识/80-实践/08-编译原理/01-MiniLang词法解析与诊断/README|MiniLang 词法、解析与诊断]]
   - 看见：token kind、lexeme、span、AST 与恢复后的诊断。
   - 成功：错误有位置；parser 每步消费输入或明确同步；后续合法语句仍能出现。
2. [[计算机知识/80-实践/08-编译原理/02-名称解析类型检查与错误定位/README|名称解析、类型检查与错误定位]]
   - 看见：symbol identity、scope、shadowing 和约束来源。
   - 成功：每个 use 绑定唯一声明；错误指出冲突的两端，而不只说“类型不对”。

### B. IR、分析与优化

3. [[计算机知识/80-实践/08-编译原理/03-三地址码CFG与SSA/README|三地址码、CFG 与 SSA]]
   - 看见：basic block、terminator、边、dominator、phi 与定义—使用关系。
   - 成功：verifier 能拒绝缺 terminator、坏边或不支配使用。
4. [[计算机知识/80-实践/08-编译原理/04-数据流优化与差分验证/README|数据流、优化与差分验证]]
   - 看见：有限格工作列表、传播事实、DCE 和差分样本。
   - 成功：分析达到不动点；优化有前置条件；固定测试集上前后结果相同。

### C. VM 与后端

5. [[计算机知识/80-实践/08-编译原理/05-字节码VM内联缓存与JIT观察/README|字节码 VM、内联缓存与 JIT 观察]]
   - 看见：bytecode verifier、operand stack、热点计数、guard 与回退 trace。
   - 成功：坏跳转或栈下溢在执行前被拒绝；类型假设失效后返回通用路径。
6. [[计算机知识/80-实践/08-编译原理/06-指令选择寄存器分配与重定位/README|指令选择、寄存器分配与重定位]]
   - 看见：toy ISA、活跃区间、spill/reload 和符号重定位。
   - 成功：互相干涉的值不共享寄存器；未解析和越界重定位明确失败。

### D. 真实生态的受控观察

7. [[计算机知识/80-实践/08-编译原理/07-LLVM与MLIR工具链探针/README|LLVM 与 MLIR 工具链探针]]
   - 看见：实际工具路径、版本、验证和 lowering 的一次现场结果。
   - 成功：结果明确是 `passed` 或 `skipped`；临时产物被限制在唯一目录；不把主线文档当固定 release。
8. [[计算机知识/80-实践/08-编译原理/08-AI计算图Lowering融合与Shape特化/README|AI 计算图 Lowering、融合与 Shape 特化]]
   - 看见：shape propagation、fusion legality、layout/alias guard 和 fallback。
   - 成功：合法融合与被阻止的融合都有反例；reference 数值对照通过。

### E. 纵向闭环

9. [[计算机知识/80-实践/08-编译原理/09-MiniLang端到端编译器/README|MiniLang 端到端编译器]]
   - 看见：source → token → AST → semantic check → IR → optimize → bytecode → VM。
   - 成功：不能只检查最终输出；中间结构、失败诊断、确定性和优化前后等价都要单独验收。

## 失败时怎样定位

1. 先确认你位于对应实验目录，而不是 Vault 根目录或其他项目。
2. 记录 `python3 --version`；不要通过临时安装另一套环境掩盖失败。
3. 区分 import/语法错误、测试断言失败、可选工具缺失和环境权限问题。
4. 阅读第一个失败及其输入/seed；不要先删除缓存或改预期答案。
5. 使用 `git diff -- <精确实践路径>` 或编辑器历史查看实验修改；不要 reset 整个仓库。

## 完成整组实践的标准

- [ ] 我能指出每个阶段的输入、输出和结构不变量。
- [ ] 我能让非法输入在最早负责的阶段失败，并保留源位置。
- [ ] 我能区分 verifier 通过、语义等价和性能收益。
- [ ] 我能解释工作列表为何终止，以及分析为何可能保守。
- [ ] 我能让优化前后实现接受同一语义合同，并提供差分证据。
- [ ] 我能让 VM 或 toy 后端拒绝坏跳转、栈下溢、寄存器冲突和越界重定位。
- [ ] 我能诚实记录 LLVM/MLIR 工具的真实版本或 `SKIP`。
- [ ] 我能从任一实验返回稳定课程，而不会把 toy 实现当作权威定义。
