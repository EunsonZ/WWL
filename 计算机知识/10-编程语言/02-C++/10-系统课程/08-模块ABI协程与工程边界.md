# 把 C++ 放进真实工程：模块、ABI、协程与标准库全景

> **学习位置**：[[计算机知识/00-开始/课程地图/02-C++-课程地图|C++课程地图]] · **适用边界**：C++20；ABI、容器实现与后续标准不混同。

## 构建图就是项目的一部分

头文件声明与模板定义、源文件实现、生成代码、目标库、可执行文件、测试目标之间存在依赖图。CMake 的 target-oriented 用法让 include 路径、编译选项和链接依赖跟随目标传播，比全局堆积标志更容易理解。

ODR 约束定义的一致性；头文件中不当定义全局对象、不同翻译单元看到不同宏配置、库版本混用，都可能破坏这个约束。编译通过和链接成功不是全部兼容性证明。

C++20 modules 提供语言级模块边界，减少某些文本包含问题，但不自动消除所有宏、ABI、依赖扫描和构建缓存问题。具体编译器及构建工具支持具有版本差异，课程主实验仍提供普通多文件构建，不把某个模块命令当成跨工具链通用写法。

## Named module怎样实际消费现有报告组件

## ABI 与 API 各能稳定什么

API 描述源码层接口；ABI 涉及名称修饰、调用约定、对象布局、异常与运行库等二进制约定。改变私有成员布局，也可能破坏直接实例化该类的调用方。PImpl 把实现放在间接对象中，可以减少头文件依赖并帮助隔离布局变化，但会增加间接访问和所有权管理。

跨动态库边界应关注分配/释放配对、标准库版本、异常能否穿越、RTTI 和编译选项。提供 C ABI 包装可以缩小边界，却仍需要定义字符串、长度、错误和所有权；`extern "C"` 不会自动让 `std::string` 变成可移植线协议。

## 从报告组件走到实际动态边界

[[计算机知识/10-编程语言/02-C++/10-系统课程/17-动态C接口版本与释放边界|第17讲：动态C接口版本与释放边界]]把这里的ABI问题落到同一个ReportSession：版本和精确结构尺寸先于字段读取，C调用方拥有输入/输出缓冲，库拥有不透明句柄并负责释放，每个导出函数捕获异常并返回状态。原C++统计实现仍由安装包消费；独立纯C工程只链接安装的SHARED库。短缓冲不写、失败替换保留旧报告、布局及实际加载路径都有实验，AppleClang21与Homebrew clang23实现配AppleClang21 C消费者的结果只覆盖当前macOS/arm64和系统libc++组合。它不承诺任意平台ABI兼容，也不引入模块或协程运行时。

## 协程首先是可暂停状态机

C++20 协程在挂起点保存需要跨暂停继续使用的状态。`co_await`、`co_yield`、`co_return` 与 promise、awaiter、coroutine handle 协作；语言提供机制，但不提供一个适用于所有应用的统一调度器。

协程不自动创建线程，也不保证并行；什么时候恢复、在哪个线程恢复由运行时与 awaiter 协议决定。局部引用、`this`、视图和回调在挂起后是否仍有效，是比语法更重要的检查点。

协程帧的拥有者何时销毁帧、取消后是否仍可能恢复、异常存在哪里、最终挂起后由谁回收，都需要明确。不应在仅有几行演示代码时宣称“完整异步库已经实现”；先把状态转移和资源释放画清楚。

## 标准库的广度地图

文本处理包括 `string`、字符转换、格式化和正则；数值包括 `numeric`、随机数、复数、比率和数学函数；时间使用 `chrono` 区分时钟、时点与持续时间；文件与路径由流和 `filesystem` 等组织。随机引擎与分布是两层，安全令牌不应直接依赖普通伪随机引擎。

通用值工具包括 `tuple`、`pair`、`optional`、`variant`、`any`、类型特征和函数包装；容器、算法与迭代器构成数据处理主线；并发涉及 thread、mutex、condition variable、atomic、future、latch、barrier、semaphore 等不同协议。

并非列出头文件就算掌握。比如 `filesystem::path` 表示路径语法，不保证路径安全或目标不变；`future` 表示结果取得协议，不自动实现取消；`regex` 的语法与性能也不能与 Python 或 JavaScript 引擎混同。

## 标准库怎样组成一个真实窗口报告

[[计算机知识/10-编程语言/02-C++/10-系统课程/13-可交付组件与并发测量工程|测量组件的继续段]]把上面的广度落实到同一个C++20应用：charconv完整解析window、微伏标定和毫秒间隔；filesystem::path承载输入/输出路径，fstream实际打开并报告错误；chrono::milliseconds给每个完整窗口保存首末样本的相对时间；数值算法消费已有describe_codes；to_chars把有单位字段写入pmr字符串。不是把几个头文件分别跑通就称为组合完成，CLI测试实际读取固定文件、改变参数并核对输出文件全文中的窗口结果。

参数语法、数值范围、单位、路径打开和输出关闭分别验证。ReportSession的内存报告先构造再提交，文件写入仍有独立失败边界；`path`不使文件输出原子，`milliseconds`不把采样时间变成墙上时钟。[[计算机知识/80-实践/03-C++/05-测量分析组件/README#窗口报告：完整应用参数与逐点资源故障|源码与完整运行入口]]复用原库安装目标，并提供只含公开头文件的独立consumer。本段按O(Kw)参考算法交付；[[计算机知识/10-编程语言/02-C++/10-系统课程/14-有界任务关闭取消与性能证据|第14讲]]用同一报告组件继续队列、取消与本机性能分布，单份窗口报告的数值真源不变。

## 序列化、网络和安全边界

C++20 标准库没有一个可直接替代所有平台 socket API 的统一网络库；生产网络程序需要选择明确的系统接口或第三方库。依赖引入后记录版本、许可证、构建来源、升级策略和回归测试，不把“库封装好了”当成业务协议自动正确。

不可信反序列化需要限制长度、递归深度、分配量和允许类型。异常安全保证不等于输入安全；内存安全工具也不能发现全部权限、路径或注入逻辑问题。

## 结课任务与可验证结果

实现一个带线程安全队列的文本统计服务核心：拥有性字符串跨线程传递；队列明确关闭；工作线程用 RAII 管理；聚合结果以确定顺序输出；解析错误和取消分别建模；性能实验比较不同批量大小。

需要给出对象生命周期图、锁保护的不变量、容器失效分析、失败与关闭测试、构建命令和测量配置。进一步可以学习协程版本或插件 ABI，但每一步都应说明新增的证明义务，而不是只把语法换得更现代。
