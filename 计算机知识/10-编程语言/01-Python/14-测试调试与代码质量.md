# 测试、调试与代码质量

## 本课目标

完成本课后，你将能：

- 把“我运行过”改成可以重复的测试；
- 区分测试失败、未处理异常、警告和日志；
- 使用 traceback、`breakpoint()`、`pdb` 与 IDE debugger 找到状态变化；
- 解释格式化、lint、类型检查和测试分别能发现什么；
- 建立“先复现—再缩小—后修改—最后防回归”的排错流程。

## 先区分五种证据

| 工具 | 主要回答 | 不能证明 |
| --- | --- | --- |
| 测试 | 给定输入时，行为是否满足明确预期？ | 没写到的场景也正确 |
| traceback | 异常沿哪些调用帧传播？ | 根因一定就在最后一行 |
| debugger | 某一执行点的变量和控制流是什么？ | 代码在所有输入下正确 |
| 日志 | 程序在真实运行中发生了哪些事件？ | 日志文字本身就是真相或安全审计 |
| formatter / lint / type checker | 格式、可疑写法和静态类型关系是否符合规则？ | 业务逻辑正确、性能安全或运行时输入有效 |

## 从一个失败测试开始

待测函数：

```python
def average(values: list[float]) -> float:
    return sum(values) / len(values)
```

它在非空输入下工作，但空列表会触发 `ZeroDivisionError`。先把期望写清楚：

```python
import pytest

from stats import average


def test_average_of_three_values() -> None:
    assert average([2.0, 4.0, 6.0]) == 4.0


def test_average_rejects_empty_input() -> None:
    with pytest.raises(ValueError, match="at least one"):
        average([])
```

再实现约定：

```python
def average(values: list[float]) -> float:
    if not values:
        raise ValueError("average needs at least one value")
    return sum(values) / len(values)
```

这就是最小的回归保护：未来有人修改 `average()` 时，空输入行为仍可被重复检查。

## `assert` 的两个不同角色

在 pytest 测试中，`assert actual == expected` 用于表达测试预期。业务代码中的 `assert` 则只适合检查程序员认为“不可能被破坏”的内部不变量。

不要用 `assert` 校验用户输入、权限或安全边界，因为 Python 可在优化模式下移除断言：

```python
# 不要这样验证外部输入
assert age >= 0

# 应显式处理
if age < 0:
    raise ValueError("age must be non-negative")
```

## 标准库 `unittest` 与 pytest

- `unittest` 随 Python 提供，适合零第三方依赖、传统 xUnit 风格或已有项目；
- pytest 是第三方测试框架，使用普通函数、丰富断言显示、fixture 和插件生态；
- 两者都可以写好测试。选择团队已经能稳定运行和维护的工具，不要为语法偏好同时维护两套风格。

一个标准库版本：

```python
import unittest

from stats import average


class AverageTests(unittest.TestCase):
    def test_three_values(self) -> None:
        self.assertEqual(average([2.0, 4.0, 6.0]), 4.0)

    def test_empty_input(self) -> None:
        with self.assertRaisesRegex(ValueError, "at least one"):
            average([])


if __name__ == "__main__":
    unittest.main()
```

## 一条测试只表达一个可观察行为

推荐使用 Arrange—Act—Assert：

```python
def test_normalize_name() -> None:
    # Arrange
    raw = "  Ada LOVELACE  "

    # Act
    result = normalize_name(raw)

    # Assert
    assert result == "Ada Lovelace"
```

优先测试公开行为，不要把测试绑死在私有辅助函数和临时实现细节上。边界至少包括：

- 典型输入；
- 空值和最小值；
- Unicode、换行或路径；
- 非法输入及异常类型；
- 曾经出现过的 bug。

文件测试使用 pytest 的 `tmp_path` 或标准库 `tempfile`，不要污染真实用户目录。相关资源管理见 [[计算机知识/10-编程语言/01-Python/05-异常文件IO与上下文管理|异常、文件 I/O 与上下文管理]]。

## 读 traceback，而不是只看最后一句

```text
Traceback (most recent call last):
  File "app.py", line 18, in <module>
    print(load_total("orders.json"))
  File "app.py", line 11, in load_total
    return sum(item["amount"] for item in data)
KeyError: 'amount'
```

阅读顺序：

1. 最后一行告诉你异常类型和直接信息；
2. 从最靠近自己代码的调用帧向上看；
3. 检查进入该帧的数据，而不是立刻包一个宽泛 `except Exception`；
4. 用最小输入稳定复现；
5. 写失败测试，再修改代码。

`except Exception: pass` 会销毁证据。若确实要转换异常，使用 [[计算机知识/10-编程语言/01-Python/05-异常文件IO与上下文管理|异常链与 `raise ... from ...`]] 保留原始原因。

## `breakpoint()` 与 `pdb`

在需要观察状态的位置加入：

```python
def calculate_total(items: list[dict[str, float]]) -> float:
    breakpoint()
    return sum(item["price"] for item in items)
```

常用 pdb 命令：

| 命令 | 含义 |
| --- | --- |
| `l` / `ll` | 查看附近 / 当前函数源码 |
| `p expr` / `pp expr` | 显示表达式 |
| `n` | 执行当前行，停在同一帧下一行 |
| `s` | 进入即将调用的函数 |
| `r` | 运行到当前函数返回 |
| `c` | 继续到下一个断点 |
| `w` | 查看调用栈 |
| `u` / `d` | 在调用栈中上移 / 下移 |
| `q` | 退出调试器 |

不要把 `breakpoint()` 留在提交的生产路径中。IDE debugger 提供图形界面，但断点、调用栈、帧和变量的模型相同。

## 日志不是更高级的 `print`

```python
import logging

logger = logging.getLogger(__name__)


def process_order(order_id: str) -> None:
    logger.info("processing order %s", order_id)
```

库代码应获取模块 logger，不应擅自调用 `basicConfig()` 改变整个应用。应用入口可统一配置级别、handler 和格式：

```python
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s %(message)s",
)
```

不要记录密码、token、私钥、完整个人数据或未经控制的巨大输入。当 Python 程序作为 Linux 服务运行时，应用 logger 的输出还会进入服务管理与系统日志语境；如何按 unit、boot 和时间范围取证，见 [[计算机知识/20-操作系统/01-Linux/10-网络存储日志与故障排查|Linux 日志与可回退排错]]。日志级别的一般含义：

- `DEBUG`：诊断细节；
- `INFO`：正常生命周期事件；
- `WARNING`：仍能继续，但发生值得关注的情况；
- `ERROR`：当前操作失败；
- `CRITICAL`：应用或关键子系统可能无法继续。

## 格式化、lint 与类型检查的分工

| 环节 | 典型工具 | 建议 |
| --- | --- | --- |
| 格式化 | Black 或 Ruff formatter | 选择一种自动格式，不为个人空格风格反复争论 |
| lint | Ruff 等 | 从少量稳定规则开始，逐步处理旧代码，不一次开启所有规则 |
| 类型检查 | mypy、Pyright 等 | 先覆盖公共边界和核心模型；类型通过不等于输入已验证 |
| 测试 | unittest、pytest | 固定命令和工作目录，确保本地与 CI 一致 |

配置通常放进 `pyproject.toml`，但每个工具拥有自己的配置表和版本行为。依赖安装与工具隔离见 [[计算机知识/10-编程语言/01-Python/11-uv项目依赖与工具管理|uv 项目、依赖与工具管理]] 和 [[计算机知识/10-编程语言/01-Python/12-包管理器选择锁定与迁移|包管理器选择、锁定与迁移]]。

## 可重复的排错流程

```text
记录现象与完整错误
→ 固定版本、命令、工作目录和输入
→ 缩成最小复现
→ 判断位于语法、数据、环境、导入、I/O 还是依赖层
→ 写一个失败测试
→ 做一项最小修改
→ 运行相关测试与完整测试
→ 删除临时 print/breakpoint
→ 记录根因和防回归措施
```

环境错位时先打印 `sys.executable`；导入错误先回到 [[计算机知识/10-编程语言/01-Python/07-模块包导入与项目结构|模块、包、导入与项目结构]]；安装错误先回到 [[计算机知识/10-编程语言/01-Python/08-pip与PyPI依赖管理|pip 与 PyPI]]。

## 练习：把 bug 变成证据

> [!note] 开放式自评
> 本题的空列表、非法字符串和金额精度策略需要由你写成明确契约，因此没有唯一实现。先用本页成功标准复核，再参看[[计算机知识/80-实践/01-Python/03-练习答案与解释#开放式自评的答案思路|开放式自评的答案思路]]，确认你的测试确实覆盖了这些决策。

下面函数错误地把字符串价格相加：

```python
def total(prices: list[str]) -> float:
    result = 0
    for price in prices:
        result += price
    return result
```

完成以下任务：

1. 运行它并保存完整 traceback；
2. 写测试覆盖 `['1.5', '2.0']`，预期为 `3.5`；
3. 决定空列表的行为并写测试；
4. 决定非法字符串的行为，保留异常因果链；
5. 使用 `breakpoint()` 观察第一次循环的 `type(result)` 与 `type(price)`；
6. 修复后删除断点，运行全部测试。

### 成功标准

- [ ] 修复前测试确实失败，而不是从一开始就绿；
- [ ] 测试名称能说明行为；
- [ ] 非法输入产生明确异常，不被静默吞掉；
- [ ] 修复后全部测试通过；
- [ ] 代码中没有遗留 `breakpoint()`、敏感日志或无说明的 `except Exception`。
