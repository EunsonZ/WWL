# TypeScript：事件循环、Promise、并发与取消

> 阅读定位：严格类型检查；运行时语义属于 JavaScript，宿主 API 另行区分。返回 [[计算机知识/00-开始/课程地图/05-TypeScript-课程地图|TypeScript · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## async 函数不是线程创建语法

JavaScript 在一个执行上下文中的同步代码先运行；Promise reaction 通常进入微任务队列，定时器等由宿主调度。浏览器和 Node 的具体阶段不完全相同，不能把一个环境的细节当成所有宿主规范。长时间同步计算会阻塞该执行线程，即使它位于 async 函数内部。

Promise 表示未来完成或失败的结果。`await` 暂停当前 async 计算直到对应结果可继续，不阻塞成“整个世界都不工作”，但它并不保证马上切到你期待的任务。多个独立任务先创建再一起等待，可重叠 I/O 等待；有依赖的任务不能为追求并发而乱序执行。

## 聚合完成不等于停止其他任务

`Promise.all` 在一项拒绝时让聚合结果拒绝，但不会自动取消其他已经开始的任务。`allSettled` 收集每项状态，适合独立任务汇总；`race` 决定谁先完成，也不自动停止输家。用 `Promise.race([request, timeout])` 实现超时却不取消请求，会留下仍然消耗资源的工作。

AbortController/AbortSignal 是协作式取消协议，具体 API 必须支持并观察信号；已经提交的远端副作用不能因此撤销。清理计时器、关闭流、释放连接应在 finally 等路径执行。重试写请求需要幂等设计，而不是捕获所有异常后无条件再来一次。

## 并发上限与背压

不要直接对海量输入 `items.map(fetchOne)` 然后 Promise.all，那会立刻创建大量工作。使用固定 worker，从共享索引或有界队列逐项取任务。限制并发数时还需限制输入缓存、响应体大小、排队长度和总截止时间。

流的生产者速度大于消费者时，要暂停读取、拒绝或丢弃，不能无限缓存。浏览器流与 Node 流 API 不同，但背压的核心相同：下游能力约束上游推进。异步迭代器让分批消费更自然，却仍须处理提前退出时的资源回收。

## 练习

设计 3 个独立请求，其中一个失败，一个很慢，一个成功。分别预测 all、allSettled、race 的返回行为，并单独记录其余任务是否继续运行。再增加统一 deadline 和 AbortSignal，验证取消处理，而不把“调用 abort 返回了”写成“服务端操作已经撤销”。
