# 社区插件选型矩阵

本页覆盖 WorkWithLLM 历史快照中**已安装的 17 个商店插件包**；其中一部分当时启用，另一部分作为可选实验包保留。版本来自该来源库各插件本地 `manifest.json` 快照；这些内容不描述 WWL。启用状态、版本、维护状态和目录评分会变化，使用前应在当前 Vault 的 Settings、官方社区目录与项目仓库重新核对。

> [!danger] 先理解信任模型
> Restricted mode 默认阻止第三方插件代码运行。关闭后，Obsidian 无法可靠地把每个插件限制到单一目录或细粒度权限；插件可继承 Obsidian 的文件、网络和系统访问能力。目录扫描、Scorecard 与人工评审是风险信号，不是权限沙箱。

## 先用核心功能建立基线

| 需求 | 先掌握 | 何时再加插件 |
| --- | --- | --- |
| 写 Markdown | 原生编辑器、命令面板、属性编辑器 | 确定自己需要工具栏、表格导航、数学片段或自动格式化 |
| 找内容 | Quick Switcher、Search、Bookmarks | 中文模糊检索/相关性排序确实不足时用 Omnisearch |
| 属性视图 | Properties、Search、Bases | 需要复杂聚合/计算时用 Dataview |
| 任务 | Markdown 任务、Search、Daily Notes | 需要截止/重复/跨文件查询时用 Tasks；需要“一任务一笔记”时评估 TaskNotes |
| 模板与捕获 | Templates、Daily Notes、Command palette | 需要捕获动作/宏时用 QuickAdd；需要动态脚本时才用 Templater |
| 视觉思考 | Canvas、Graph | 需要手绘、局部图片引用时用 Excalidraw |
| PDF | 原生 PDF 查看和内部链接 | 需要原生式批注摘录工作流时用 PDF++ |
| 恢复/版本 | File Recovery + 独立备份 | 熟悉 Git 后才让 Obsidian Git 自动提交/推送 |

## 如何读“改写面”

| 等级 | 含义 | 应对 |
| --- | --- | --- |
| 窄 | 主要影响当前编辑器、当前笔记或插件索引 | 仍需备份；在实验文件先试 |
| 中 | 可创建/改写多篇笔记、附件或结构化数据 | 一次配置一个动作；核对目标路径和恢复方法 |
| 广 | 可批量改写整个 Vault、执行代码/系统命令、联网或对外提供 API | 隔离测试、最小配置、独立备份、审计脚本和凭据 |

这不是“安全分数”。即使标记为“窄”，社区插件仍以 Obsidian 权限运行。

## 写作与编辑体验

| 插件（本地版本） | 平台 | 解决什么 | 改写面与边界 | 建议 |
| --- | --- | --- | --- | --- |
| Simplified Chinese Word Splitting `1.13.4` | 桌面 + 移动（manifest） | 改善编辑器/Vim 模式中的简体中文分词和按词移动/删除 | 窄：编辑器行为；升级后重点测试选择、删除、撤销和输入法 | 中文长文常用者可保留；不影响原生全文搜索逻辑 |
| Editing Toolbar `4.1.1` | 桌面 + 移动（manifest） | 提供可定制格式工具栏和命令按钮 | 窄到中：本质上触发编辑命令；移动端布局与桌面不同 | 对不熟 Markdown/快捷键者有帮助；仍应学会源码含义 |
| Advanced Tables `0.23.2` | 桌面 + 移动（manifest） | 表格内 Tab/Enter 导航、格式化、行列操作和公式 | 中：会重写当前表格；插件文档提示实验性功能可能导致当前笔记数据损失 | 只在练习表格先用；大量结构化数据优先 Bases |
| Latex Suite `1.12.8` | 桌面 + 移动（manifest） | 数学片段、文本展开和编辑增强 | 窄到中：片段自动展开为 LaTeX；自定义规则需审查 | 高频写数学再启用；普通用户无需为“以后可能用”而配置 |
| Linter `1.32.0` | 桌面 + 移动（manifest） | 统一 YAML、标题、空格、脚注和 Markdown 风格 | **广**：可按文件保存或批量格式化；规则之间可能改变语义/产生大 diff | 先复制 3 篇样例做 dry run；启用规则应分批、每批审查 diff |

## 检索、数据与任务

| 插件（本地版本） | 平台 | 解决什么 | 改写面与边界 | 建议 |
| --- | --- | --- | --- | --- |
| Dataview `0.5.68` | 桌面 + 移动（manifest） | 查询 Markdown 属性/内联字段，生成表、列表和任务视图 | DQL 主要读取索引；**DataviewJS/Inline JS 为广**，可改文件和联网 | 初学区只用 DQL；先比较 Bases 是否已经足够 |
| Omnisearch `1.30.1` | 桌面 + 移动（manifest） | 模糊全文搜索、相关性排序和快速检索 | 窄：主要读取并建立索引；索引性能/中文效果需按设备测试 | 作为原生 Search 补充；精确运算符仍用原生 Search |

### Dataview 的安全分层

````md
TABLE status, rating
FROM "20-Playground"

```
````

### Tasks 与 TaskNotes 的选择

| 问题 | Tasks | TaskNotes |
| --- | --- | --- |
| 数据单元 | 任意笔记中的 Markdown 任务行 | 独立任务笔记/属性 |
| 上下文 | 天然留在项目、会议、日记中 | 通过关系链接到项目/笔记 |
| 适合 | 轻到中型、上下文优先任务管理 | 任务有大量字段、日历/看板/时间跟踪 |
| 风险 | 查询中完成任务会改源笔记 | 结构和视图较复杂，迁移/退出成本更高 |

| 能力 | 核心 Templates | QuickAdd | Templater |

## 安装前的 10 项检查

- [ ] 我能用一句话描述具体问题，而不是“大家都装”。
- [ ] 我已尝试对应的核心插件或原生 Markdown 方案。
- [ ] 插件目录显示作者、许可证、支持平台和兼容版本。
- [ ] 我查看了更新时间、最近 release、开放 issue 和维护响应。
- [ ] 我查看了官方目录的 Scorecard/Health/Review；知道它不是安全保证。
- [ ] 我知道插件会读什么、写什么、是否联网、是否运行脚本/系统命令。
- [ ] 我已为 Vault 建立独立备份；知道 Sync 不是备份。
- [ ] 我先在 `10-实验区` 或临时 Vault 试用，不触碰真实敏感资料。
- [ ] 我只启用这一个新插件，能在问题出现时准确归因。
- [ ] 我知道如何禁用、卸载，以及关闭插件后数据是否仍可读。

## 安全安装与升级流程

1. 阅读目录页、仓库 README、release notes 和已知问题。
2. 核对 Desktop/Mobile；manifest 的 `isDesktopOnly: false` 不保证触控 UX 完全等价。
3. 备份 Vault 和 `.obsidian` 配置；记录当前插件版本。
4. 一次只安装或升级一个插件。
5. 使用非敏感示例文件验证创建、修改、撤销、删除和重启。
6. 检查命令面板新增命令和 Settings 页面；不要立即授予/配置所有能力。
7. 在移动端单独验证启动时间、布局和关键命令。
8. 社区插件不会出于安全原因自动更新；定期手动 **Check for updates**，但不要盲目全量升级。
9. 出现问题时打开 Restricted mode、默认主题、关闭 CSS snippets 后复现；详见 [[Obsidian知识/90-资源/02-参考/08-常见问题与排错|常见问题与排错]]。
