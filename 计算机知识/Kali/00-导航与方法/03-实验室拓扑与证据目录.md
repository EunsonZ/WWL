# 实验室拓扑与证据目录

**先修关系：** [[计算机知识/Kali/00-导航与方法/02-授权范围与风险分级|授权范围与风险分级]]；[[计算机知识/Kali/01-系统与网络基础/02-虚拟机快照与网络隔离|虚拟机快照与网络隔离]]。

## 先分清“本机”指谁

用户电脑、运行Kali的虚拟机、靶机和容器是不同网络命名空间或主机。127.0.0.1在每个环境分别指向自身；Kali里的127.0.0.1不会自动连接宿主机上的服务。0.0.0.0是常见的监听通配地址，不是推荐的浏览器目标，也不是隔离边界。

本包最小路线只用**同一Kali/实验机内部**的回环服务与离线文件。这样减少了网络拓扑干扰，但不能用来证明跨网络防火墙策略。

```text
同一实验机
  终端B：curl / Nmap ── 127.0.0.1:8000 ── 终端A：静态公开目录
  离线分析：PCAP / JSONL / SQLite内存库 / 无害文本
  不需要宿主机转发，不需要真实组织账户，不需要互联网目标
```

## 可选的双虚拟机扩展

当研究路由、共享或AD时，可在独立内部网络中放置Kali与自建靶机；更新系统用的出口与实验网络分开管理。具体网卡模式和默认路由要按 [[计算机知识/Kali/01-系统与网络基础/02-虚拟机快照与网络隔离|虚拟机章节]] 实际核对，不因界面叫“内部/仅主机”就假定全部安全。

| 用途 | 地址或名称 | 使用限制 |
| --- | --- | --- |
| 真正执行的最小服务 | `127.0.0.1:8000` | 由读者手动启动，公开静态目录 |
| 关闭端口对照 | `127.0.0.1:8001` | 必须确认没有其他进程使用 |
| 合成PCAP | `192.0.2.10`→`192.0.2.20:8000` | 文档用途地址；不实际扫描这些地址 |
| 逻辑域名 | `web.lab.test` / `lab.test` | 教学名称，不默认可解析；不替代真实DNS配置 |
| 自备扩展靶场 | SQL演示8081、WordPress8082、TLS8443 | 本包未安装、未启动、未执行 |

192.0.2.0/24属于文档示例地址范围，出现在PCAP里仅用于避免混入真实资产。[^s1] `.test`名称在这里仅作为课程标识，不构成已配置DNS的声明。

## 实验目录与分享目录分离

`$HOME/kali-lab/code` 放代码副本；`fixtures` 放原始合成输入；`output` 放自己的实际输出。原Vault保存课程、来源和必要附件，不写入口令缓存、大型PCAP、真实凭据或不断刷新的扫描结果。失败记录也进入output并注明状态。

准备路径的完整命令见 [[计算机知识/Kali/07-综合实验/01-离线实验准备与夹具说明|夹具准备]]。若要保留多个实验，创建不同的新目录，不对旧目录盲目 `rm -rf`。真实数据与公开教学目录必须分开；静态服务只允许暴露 `fixtures/web`，且不添加指向其他目录的符号链接。

## 代理和DNS是隐含路由

curl可能受环境代理影响，浏览器可能保留Burp/ZAP配置，SSH转发会改变请求实际出发点。对回环实验，在发起请求的终端确认代理设置，并在不使用代理时给curl加 `--noproxy '*'`；有意经过本机代理的练习则明确该观察路径。DNS也可能把一个“实验域名”解析到外部地址，未知结果应停止，而不是继续扫描。参见 [[计算机知识/Kali/02-信息收集与网络测量/08-NetcatSocatSSH与受控代理|代理与转发]]。

最终清理只停止自己启动的服务、撤回自己的代理设置，并确认输出保存位置；不修改不相关的网卡、系统服务或用户资料。
