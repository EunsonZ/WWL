# 网络：IP、子网、路由与控制平面

> 阅读定位：协议以明确 RFC 为依据；模型例题注明假设。返回 [[计算机知识/00-开始/课程地图/09-计算机网络-课程地图|计算机网络 · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## 子网是前缀匹配，不是记住几种地址类别

CIDR 用前缀长度表示网络部分。IPv4 `/26` 留下 6 个主机位，总共有 64 个地址。在普通广播子网模型下常有 62 个可分配主机地址，但 `/31` 点到点和 `/32` 主机路由等不能机械套“减二”。例如 `192.0.2.130/26` 所在区间是 192.0.2.128 到 192.0.2.191。

路由查找采用最长前缀匹配：若同时匹配 `/0`、`/16`、`/24`，通常选择最具体的 `/24`。路由表还可能受策略、源地址、标记和多个表影响，因此“有默认网关”不证明所有流量都沿同一路径。

## 转发与路由协议分离

转发数据平面按既有规则处理一个包，路由控制平面计算或传播可达性。距离向量、链路状态和路径向量的知识不能混成一个算法：OSPF 类协议使用链路状态与最短路思想，BGP 交换路径与策略信息，其选择不是全球最短物理距离保证。

TTL/Hop Limit 防止包无限循环。ICMP 反馈部分控制与错误信息，ping 成功只能说明某种往返可达；ping 失败也不充分证明所有业务流量都不可达，因为可能被过滤或限速。

## 分片、路径 MTU 和 IPv6

路径上的最小 MTU 约束可直接发送的 IP 分组大小。分片会增加丢失放大和重组成本，因此需要合理发现与适配。IPv4 与 IPv6 在路由器分片行为、头部和控制消息上不同；IPv6 路由器不会像 IPv4 某些情形那样替源主机做分片。阻断所有相关 ICMP 信息可能造成难排查的 MTU 黑洞。

IPv6 有 128 位地址、链路本地地址、扩展头、邻居发现和自动配置等机制，没有 IPv4 式广播。地址变长不是它唯一变化，也不是安全保证。双栈环境还需要分别检查 IPv4 与 IPv6 的解析、路由和监听。

## NAT、DHCP 与隧道

NAT 改写地址，有些还改端口；它保存映射状态，影响入站连接、超时和端到端可达性。NAT 不是加密，不等同于完善防火墙。DHCP 分配租约和相关配置，DNS 解析名字，二者常一起出现在故障现场但职责不同。隧道在一种封装里装另一种报文，会增加头部并影响有效 MTU。

练习：手算 `/26` 的四个区间，再给出三条重叠路由，说明匹配结果。把“没有地址”“没有路由”“邻居不可达”“回程路径不通”写成不同故障，分别指出需要读取哪类信息。
