# 定时中断DMA与实时预算

## 两个入口

基础入口：先在图上找到采样、就绪、IRQ、CPU 结束四条时间线，再读所有权。快进入口：先复算 1.7 ms 裕量与 5 ms 失败例，再核对 cache/epoch 分支。两者描述同一个 1 ksample/s、四点一块、两个缓冲的教学采集器。

## 采样时刻不是中断时刻

定时器触发 ADC，不意味着模拟开关在完全同一理想瞬间动作；这里已将固定采集相位并入 t0，定义 t[n]=t0+nTs+ε[n]，Ts=1 ms，ε 为相对于这个规则的采样抖动。ISR 入口时刻 =块就绪时刻+IRQ 响应延迟，包含屏蔽、优先级和调度。用 IRQ 入口时间当每点采样时间，会把四个不同时刻误合成一个时刻。

如果 v=A sin(2πft)，微小抖动电压误差约 (dv/dt)ε，最坏界 |δv|≤2πfA|ε|。f=100 Hz、A=1 V、|ε|≤1 μs 给 0.6283 mV。它小于还是大于一个码，取决于本组 Δ≈0.8057 mV 及总误差预算。这个界是小抖动一阶估计，ε 统计方差或频谱不同会改变 RMS 误差；不能从一次 ISR 时间推得 ε 的分布。样本时标规则必须源自采样触发/捕获合同。

## 从块周期推出最坏预算

采样 n=0..3 在 0,1,2,3 ms；本例保守规定第一块在 4 ms 就绪，包含末点完成及搬运的余量。DMA 切到另一槽，第一槽在 8 ms 再次被写入。若最坏 IRQ 延迟 J=0.3 ms，处理 C=2 ms，第一块从 4.3 到 6.3 ms，释放裕量 8−6.3=1.7 ms。首点数据年龄为 6.3 ms，末点年龄为 3.3 ms；“算法耗时 2 ms”不是端到端延迟。

第 k 块（从0起）定义

\[
r_k=(k+1)BT_s,\quad h_k=r_k+J,\quad s_k=\max(h_k,f_{k-1}),\quad f_k=s_k+C,
\quad d_k=(k+2)BT_s.
\]

必须 f_k≤d_k 且所有权/可见性成立；等号采用本模型“先释放再复用”的排序，硬件实现还需要正裕量和明确同步。时间单位在代码里统一 ns 整数。C=5 ms 时第一块 9.3 ms 才结束，已经超过 8 ms 复用；之后积压增长。CPU 平均利用率或一次漂亮截图都不能免除最坏条件。`schedule` 将此类块标为 discard，它模拟时间风险，没有假装硬件自动暂停。

## 所有权比指针更重要

槽状态为 FREE→DMA 写→READY→CPU→FREE；READY 必须等硬件完成后发布。CPU 只能处理完成且未被复用的槽。双缓冲的另一地址虽然可更新，仍需核对具体寄存器条件。ST [AN4031 Rev3 §1.1.9、§1.1.11–1.1.12](https://www.st.com/resource/en/application_note/an4031-using-the-stm32f2-stm32f4-and-stm32f7-series-dma-controller-stmicroelectronics.pdf) 说明循环及双缓冲，当前目标由 CT 区分。RM0090 Rev21 本次只实际取得 CT/DBM 和 §10.5.9 M1A 的官方索引正文摘段；没有完整 PDF 读取，所以这里没有把全手册当验收证据。

环形 DMA 仍可继续写，软件的队列满检测不能凭空产生硬件回压。发生满槽需按设备合同停止/重同步、记录丢失区间、换 epoch，并处理已在途传输。槽编号每绕一圈会重复，因此 token 用 (epoch,generation,slot)；迟来的旧 completion/release 不得释放新数据。CPU 实践 `OwnedRing` 是这个所有权状态机的不可变载荷模型，忙槽抛 OverflowError；它不是 DMA 驱动，也不模拟电气时序。

## 内存可见性与 cache 是另一个合同

CPU 缓存中的数据与 DMA 可见内存可能不同。以带 D-cache 的 Cortex-M7 为例，DMA 写完 SRAM 后，CPU 读取前需要适当 invalidate；若目标 cache 行原本脏，必须在交给 DMA 前处理它，避免后来回写旧数据覆盖 DMA 的新数据。不能在 DMA 完成后以 clean 操作把旧 cache 内容写回覆盖新样本。缓冲应独占完整 cache 行，避免 invalidate 顺带丢掉邻居的 CPU 脏数据，并位于该 DMA 实际可访问的内存。

[ST AN4839 Rev2 §2.1、§3.2](https://www.st.com/resource/en/application_note/an4839-level-1-cache-on-stm32f7-series-and-stm32h7-series-stmicroelectronics.pdf) 给出了 CPU/DMA 两种可见性方向。[Arm CMSIS6 M7 D-cache API](https://arm-software.github.io/CMSIS_6/latest/Core/group__Dcache__functions__m7.html) 的按地址接口要求 32 byte 对齐，本例据此把缓冲划为独占的 32 byte 行。M7 cache 示例与 F4 的 AN4031 双缓冲不是同一款已验证设备，不得把两份例子拼成虚构板卡记录。

volatile 影响编译器观察，既不替代 cache 维护，也不替代同步发布。完成 ISR 先核对硬件状态、取得稳定槽、完成可见性操作，再以平台规定的屏障和临界区/原子发布 READY；CPU 取得 READY 后才读取，再发布 FREE。本实验的 C 文本是接口伪代码，只列必须兑现的原子性和内存条件，没有编译或板卡执行。

读 [[计算机知识/30-计算机系统/10-IO设备总线DMA与中断#10. 一条危险故障链：descriptor 没有真正就绪]]，把 descriptor、doorbell、completion 的顺序对应到本页槽发布，返回判断“指针已赋值”是否足够；具体 ISA 和 DMA 屏障规则不能由类比产生。读 [[计算机知识/20-操作系统/02-操作系统原理/10-系统课程/08-虚拟化实时系统与安全#实时系统关心截止时间]]，把 C、J 和复用 d_k 带回 deadline 概念，区分平均吞吐与最坏失效。

## 四题与理由

1. 第一块 IRQ 到达4.3 ms，能把四点时间都记4.3 ms吗？答：不能，采样在0..3 ms；IRQ时间只描述观察延迟。
2. C=5 ms、每块周期4 ms，扩成100槽会永久解决吗？答：不会。长期服务率低于到达率，积压最终耗尽任何有限缓冲，增加槽只推迟失败。
3. 为什么旧 token release 要拒绝？答：同一槽已经复用，旧回调若释放它，会允许生产者覆盖新一代仍在用的内容。
4. DMA 完成后 clean 脏缓存为什么危险？答：它可能把旧CPU缓存写回SRAM覆盖新DMA数据；所有权移交前先处理脏行，完成后按合同使CPU看见新内存。
