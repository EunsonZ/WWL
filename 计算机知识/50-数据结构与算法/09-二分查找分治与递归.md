# 二分查找、分治与递归

## 本课目标

你将用半开区间 `[lo, hi)` 写出可证明、不会漏边界的二分查找，理解“有序”究竟是哪一条前置条件，区分找任意命中、下界与上界；还会用规模递推解释分治与递归栈，而不把递归简洁误当成无成本。

本页只有伪代码。可运行实现、随机/边界测试和实际栈限制属于 `计算机知识/80-实践/05-数据结构与算法/` 实践目录。

## 1. 二分之前：你有哪一种单调性？

普通二分查找要求数组按同一个比较规则**非递减**排列。若目标为 `target`，比较 `A[mid] < target` 后才有资格丢弃左半边；这是由有序性推出的，不是“中间比较一下”天然正确。

更一般地，二分可在形如 `false, false, ..., true, true` 的单调谓词 `P(i)` 上找第一个 `true`。数组下界就是 `P(i) = (A[i] >= target)`。若数组未排序、排序方向反了、比较器与排序时不同，丢弃半区的推理都失效。

> [!warning] 反例：局部看起来有序不够
> 在 `[1, 100, 2, 3, 4]` 找 `2`，中点比较后丢弃一半可能直接丢掉答案。二分的前置条件是整个搜索区间按比较器有序，不是样例前后“差不多递增”。

## 2. 半开区间：把边界变成统一规则

用 `[lo, hi)` 表示候选下标为 `lo, lo+1, …, hi-1`：`lo` 可以等于 `hi`，表示空区间；长度永远是 `hi-lo`。初始 `lo=0,hi=n`，所以最后一个有效索引仍是 `n-1`，而无需为“闭区间的 -1”另写分支。

### 找任意一个命中

```text
BINARY_SEARCH_ANY(A, target):          // A 按非递减顺序，搜索 [0, n)
    lo = 0
    hi = length(A)
    while lo < hi:
        mid = lo + (hi - lo) // 2      // 避免 lo + hi 的固定宽度溢出
        if A[mid] < target:
            lo = mid + 1               // mid 不可能是答案
        else if target < A[mid]:
            hi = mid                   // mid 不可能是答案
        else:
            return mid
    return NOT_FOUND
```

循环不变量：若 `target` 在原数组中，则它一定在当前 `[lo,hi)` 内。若 `A[mid] < target`，有序性说明 `[lo,mid+1)` 都小于目标，安全令 `lo=mid+1`；若 `target < A[mid]`，`[mid,hi)` 都大于目标，安全令 `hi=mid`。每次未返回都使区间长度至少缩小 1，通常约减半；空区间时不变量说明不存在命中。

### 逐步例子

在 `A=[1,3,3,3,7,9]` 查找 `7`：

| 轮次 | `[lo,hi)` | `mid` | `A[mid]` | 下一步 |
| --- | --- | ---:| ---:| --- |
| 1 | `[0,6)` | 3 | 3 | `lo=4`，候选变 `[4,6)` |
| 2 | `[4,6)` | 5 | 9 | `hi=5`，候选变 `[4,5)` |
| 3 | `[4,5)` | 4 | 7 | 命中，返回 4 |

若查找 `4`，同样会收敛到空的 `[4,4)`，返回未找到。空数组直接从 `[0,0)` 开始，循环不运行；这是半开区间统一掉的一个边界。

## 3. 重复键：`any` 不等于第一个/最后一个

上面的函数对 `3` 可返回 1、2 或 3，取决于中点和实现。若需求是插入位置、时间线分页或稳定去重，必须明说边界语义。

```text
LOWER_BOUND(A, target):                 // 第一个满足 A[i] >= target 的 i
    lo = 0
    hi = length(A)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if A[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo

UPPER_BOUND(A, target):                 // 第一个满足 A[i] > target 的 i
    lo = 0
    hi = length(A)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if A[mid] <= target:
            lo = mid + 1
        else:
            hi = mid
    return lo
```

`LOWER_BOUND` 的更强不变量是：所有 `i < lo` 都满足 `A[i] < target`；所有 `i >= hi` 都满足 `A[i] >= target`。循环结束 `lo==hi`，这个位置正是两类区域的分界。`target` 存在当且仅当 `lo<n` 且 `A[lo]==target`；重复目标的范围是 `[LOWER_BOUND, UPPER_BOUND)`。

**边界反例。** 若把 `hi=mid-1` 用在半开区间，或 `A[mid] < target` 时只写 `lo=mid`，当区间为 `[0,1)` 时 `mid=0` 不动，可能死循环或跳过答案。不要混搭闭区间教程的更新规则与半开区间的循环条件。

## 4. 复杂度：为什么是对数，而不是“每次少一半”的口号

初始候选数为 `n`。经过 $t$ 次近似二分后，候选最多约为 $n/2^t$；到常数大小需满足 $n/2^t\le1$，故 $t\ge\log_2n$。每轮做常数次比较和索引，时间为 $O(\log n)$，迭代版本额外空间为 $O(1)$。

这是假设随机访问 `A[mid]` 是 $O(1)$ 的数组模型。链表定位中点要线性走节点，二分会失去该优势；磁盘/网络索引还要计入 I/O、页大小、缓存和批量请求。局部性与带宽的现实代价见 [[计算机知识/30-计算机系统/04-缓存局部性带宽与延迟|缓存、局部性、带宽与延迟]]。

## 5. 分治：分开解决，再正确合并

分治常有三步：

```text
SOLVE(problem):
    if problem is small enough:
        return solve_directly(problem)
    subproblems = divide(problem)
    answers = SOLVE(each subproblem)
    return combine(answers)
```

“递归”是表达自调用的控制流；“分治”是把问题拆成更小子问题并合并的算法结构。二分查找通常只递归/迭代到**一半**，没有合并两个答案；归并排序则递归两半并线性合并，详见 [[计算机知识/50-数据结构与算法/08-排序选择与稳定性|排序选择与稳定性]]。

### 递推的两种常见形状

| 递推 | 直觉 | 结果 |
| --- | --- | --- |
| $T(n)=T(n/2)+O(1)$ | 每层只沿一个分支，工作常数 | $O(\log n)$ |
| $T(n)=2T(n/2)+O(n)$ | 每层两个子问题，本层合并总共线性 | $O(n\log n)$ |

第二式的每一层总工作为 $O(n)$，层数为 $O(\log n)$。但不是见到 `2T(n/2)` 就自动是 $n\log n$：合并工作、基例、子问题是否重叠与是否平衡都会改变结论。

## 6. 递归栈：时间和空间是两张账

递归调用要保存返回位置及必要的状态；概念上每层占一帧，最深同时活跃调用数是栈深度。二分递归的深度为 $O(\log n)$，归并排序的递归深度也是 $O(\log n)$，而“每次只减 1”的递归可能深达 $O(n)$。

```text
LINEAR_RECURSION(n):
    if n == 0:
        return
    LINEAR_RECURSION(n - 1)             // 最深会同时保留 n 层
```

尾递归在某些语言/构建条件下可能优化为循环，但这不是通用保证。运行时栈上限、调试信息、局部对象、异常路径与优化都会影响实际表现；调用约定和栈帧的系统边界见 [[计算机知识/30-计算机系统/03-ABI调用约定与静态动态链接|ABI、调用约定与静态/动态链接]]。若生产输入深度不可控，改为显式栈或迭代往往能让资源上限更可观察，但仍要设计溢出、取消和错误路径。

## 7. 搜索索引与并行：不要过度类比

- 有序数组上的二分是精确比较；RAG 的向量检索、倒排索引和重排序通常在巨大候选空间中找近似/相关候选，复杂度、召回和权限语义不同。RAG 索引的版本、ACL 与评测边界见 [[AI/20-LLM/70-工程应用与工具链/02-Embedding-Chunking与最小RAG#评测应分离检索与生成|RAG 检索评测]]。
- 分治可以并行处理独立子问题，但合并、任务创建、内存带宽和负载不均会限制收益。必须先证明子问题不共享可变状态，再评估同步与端到端指标，见 [[计算机知识/30-计算机系统/05-并发并行SIMD与加速器|并发、并行、SIMD 与加速器]]。

## 练习

1. 在空数组、单元素数组、目标小于全部元素、目标大于全部元素四种情形，写出 `[lo,hi)` 的初始和终止状态。
2. 对 `[1,3,3,3,7,9]` 求 `LOWER_BOUND(3)` 与 `UPPER_BOUND(3)`，并用 `[lower,upper)` 验证三个 `3` 恰在该范围。
3. 找出一个把 `lo=mid` 用于半开区间的死循环输入，逐轮写出 `lo,hi,mid`。
4. 为“在链表里按位置找第 `mid` 个结点”估算成本，解释为什么它不能直接获得数组二分的 $O(\log n)$ 优势。
5. 分别给 $T(n)=T(n/2)+O(1)$、$T(n)=2T(n/2)+O(n)$ 画三层递归树，标注每层总工作和最大深度。
6. 一个递归解析器可能接收攻击者控制的嵌套输入。写出你会限制的最大深度、错误信息和可恢复策略；不要把“实际通常不深”当安全保证。

## 成功标准

- 你能写出并检查半开区间不变量，处理空数组及所有边界，而不混用另一套更新规则；
- 你能分清任意命中、下界、上界与重复范围，并说明各自的产品语义；
- 你能从有序/单调前置条件证明一次半区丢弃安全，并给出未排序反例；
- 你能推导 $O(\log n)$ 与常见分治递推，而不是只记结论；
- 你能把递归时间、最大调用栈和实际运行时资源限制分别报告。
