# 正则表达式实验室

这里是 `编程知识/` 内允许反复修改的正则练习区。课程正文提供稳定讲解；你的表达式、测试记录和失败样本写在 [[编程知识/30-实践/01-正则表达式实验区/02-练习场]]，不会改乱课程导航。

## 实验材料

- [[编程知识/30-实践/01-正则表达式实验区/01-测试样本]]：固定输入，包含正例、反例和边界例；
- [[编程知识/30-实践/01-正则表达式实验区/02-练习场]]：逐课填写模式、引擎、标志、结果和限制；
- [[编程知识/30-实践/01-正则表达式实验区/03-练习答案与解释|练习答案与解释]]：完成后对照，不建议一开始就复制；
- [[编程知识/30-实践/01-正则表达式实验区/04-5分钟运行与测试模板]]：Python / JavaScript 二选一，先跑通 API、捕获、替换和断言；
- [[编程知识/30-实践/01-正则表达式实验区/05-Python差异断言.py|Python 差异断言]]、[[编程知识/30-实践/01-正则表达式实验区/06-JavaScript差异断言.js|JavaScript 差异断言]]：用可运行断言观察 Unicode、点号、命名组、替换与 JavaScript 状态性差异；
- [[编程知识/90-资源/01-正则表达式速查表|正则表达式速查表]]：忘记语法时快速查询；
- [[编程知识/10-基础/01-正则表达式/00-正则表达式-MOC|正则表达式 MOC]]：返回课程地图。

## 推荐实验循环

1. 第一次练习先从 [[编程知识/30-实践/01-正则表达式实验区/04-5分钟运行与测试模板]] 选择一种语言并跑通断言；跨 Python / JavaScript 部署时，再运行两份差异断言并记录版本。
2. 从 [[编程知识/30-实践/01-正则表达式实验区/01-测试样本]] 复制一小组输入。
3. 在 [[编程知识/30-实践/01-正则表达式实验区/02-练习场]] 写清楚目标引擎、版本、标志和调用方式。
4. **先预测**“应匹配”和“不应匹配”，再写表达式。
5. **实际运行**，记录完整匹配和每个捕获组，不只记“成功/失败”。
6. **对照差异**，一次只加一条约束，再重新运行。
7. 增加空值、过长值、Unicode、换行或缺字段等边界。
8. 解释已知限制；必要时决定不用正则。
9. 完成后才打开 [[编程知识/30-实践/01-正则表达式实验区/03-练习答案与解释|练习答案与解释]] 对照。

## 工具边界

可以使用任何你明确选择的本地语言运行时、编辑器查找或可信测试器，但记录以下信息：

```text
目标语言或工具：
版本：
正则引擎：
标志（flags）：
调用方式（搜索 / 完整匹配 / 全部查找 / 替换）：
替换语法：
```

> [!warning] 在线测试器不是生产环境
> 不要粘贴个人数据、token、日志凭据或未公开源代码。在线工具的默认引擎、标志和替换语法也可能与你的项目不同。

## 安全规则

- 样本只使用 `example.com`、文档保留 IP 和虚构标识；
- 不生成极长 ReDoS 攻击负载；
- 不对真实目录执行未经预览的批量替换；
- 不把一条表达式成功运行当成业务语义验证；
- 对结构化格式优先使用正式解析器；
- 如果要试批量替换，先复制样本，并保持 Git 或文件恢复可用。

## 重置方法

若只修改了 [[编程知识/30-实践/01-正则表达式实验区/02-练习场]]，可以手工清空自己填写的代码块和结果。若误改课程或样本，可通过 Git 查看本任务前的基线提交 `a817a7c` 与当前文件差异；不要使用会丢弃整个工作树的命令。

## 成功标准

- [ ] 每条练习都记录了引擎、版本与标志。
- [ ] 每条表达式都有正例、反例和边界例。
- [ ] 我能解释捕获组，而不只看高亮区域。
- [ ] 我记录了已知限制与不用正则时的替代方案。
