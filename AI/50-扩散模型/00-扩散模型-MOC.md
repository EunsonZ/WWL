扩散模型把生成建模表述为“向数据逐步加噪，再学习如何从噪声回到数据分布”。它可用于图像、音频、视频、3D 或其他连续表示的生成与编辑。模型产生一个看似合理的样本，并不表示它检索到了事实、获得了版权授权、保留了原图的身份，或能安全地用于证据、医疗、设计交付或社会判断。

本轮已补齐下列两篇核心课程，含直觉解释、主要公式、小例、图示与一手资料。原有地图保留为进阶学习和实验设计；不能把完整主题目录理解为全部研究深度、真实模型运行或 GPU 性能均已验收。

## 领域问题与边界

- **建模边界**：前向加噪、去噪网络、条件控制、采样器、VAE/latent 空间和安全过滤器是不同层。不能把“采样步数多”“提示词更长”或“图像更逼真”误解成模型一定更准确或更可控。
- **任务边界**：文本生成图像、图像编辑、inpainting、控制条件、视频和音频生成对输入编辑权、输出溯源、时间一致性与失败代价有不同要求；课程会逐项分开，而不以一张漂亮图片代替评测。
- **治理边界**：生成输出可能含近似训练样本、风格挪用、错误文字、虚构文件、敏感内容或可被误认为真实事件的媒体。学习实验默认不生成真人仿冒、虚假证据、违法内容或未获授权的受保护角色/素材集合。

## 已有入口与完整先修路径

整体入口是 [[AI/00-开始/00-AI-首页|AI 首页]]。先完成 [[AI/10-机器学习与深度学习基础/00-机器学习与深度学习基础-MOC|机器学习与深度学习基础]]，并从 [[AI/20-LLM/00-LLM-MOC|LLM MOC]] 取得 Transformer、训练循环、参数高效微调、推理采样、量化与评测的共同语言。扩散模型和 LLM 都是生成模型，但前者通常在连续向量或 latent 中进行多步去噪，而后者在离散 token 上自回归生成；这种不同会改变训练目标、缓存方式、延迟和控制手段。

概率、高斯噪声、score、ODE/SDE 与采样直觉从 [[数学/70-信号处理与多模态数学/03-高斯噪声扩散Score与ODE-SDE直觉|高斯噪声、扩散、Score 与 ODE-SDE 直觉]] 进入。进一步需要数学域的线性代数（高维表示）、概率统计（密度/条件分布）、微积分优化（梯度与训练）和数值计算（步长、稳定性、低精度）。AI 页不复制这些定义或省略其假设。

实际训练、推理和性能解释还需 Python/Linux 的环境与文件权限、计算机系统的内存/存储概念，以及 [[计算机知识/40-并行与异构计算/01-CUDA/00-CUDA-MOC|CUDA MOC]]。CUDA 路线用于理解 U-Net/Transformer 算子、VAE 编解码、attention、显存、批处理、低精度和多步采样；它不是自动拥有模型权重或生成权限的理由。

## 与 LLM 共用和不同的部分

| 层次 | 与 LLM 共用 | 扩散模型的新问题 |
| --- | --- | --- |
| 表示 | embedding、条件输入、Transformer 可作骨干、tokenizer/VAE 可压缩表示 | 连续噪声状态、时间步/噪声级别、score/噪声预测与 latent 图像空间 |
| 训练 | 数据治理、优化、checkpoint、微调、复现与数据切分 | 噪声日程、去噪目标、条件丢弃、VAE 重建误差和样本/条件配比 |
| 推理 | 条件、随机种子、精度、批处理、量化与硬件测量 | 多步 sampler、guidance、scheduler、初始噪声、步数与解码开销 |
| 评测 | 人工复核、基准、分布差异、提示词版本和失败集 | 保真/多样性、文字/结构准确度、编辑一致性、记忆风险和来源透明度 |

## 进阶课程结构与持续学习方向

| 模块 | 计划课程 | 要回答的问题 | 可观察完成标志 |
| --- | --- | --- | --- |
| 1. 生成建模地图 | 自回归、VAE、GAN、flow 与扩散的目标差异 | 为什么选扩散而不是另一类生成模型？ | 能按任务/约束写出选择理由 |
| 2. 前向与反向过程 | 高斯加噪、时间步、score、噪声预测和参数化 | 网络到底在预测什么？ | 能用小数组解释单步和任意时刻采样 |
| 3. 架构与 latent | U-Net、DiT、VAE、条件编码器与 cross-attention | 图像如何被压缩、处理、再解码？ | 能追踪尺寸、通道和条件流 |
| 4. 条件与控制 | 文本条件、classifier-free guidance、inpainting、ControlNet 类控制 | 条件如何增强，也会怎样扭曲输出？ | 能区分控制目标和未经保证的副作用 |
| 5. 训练与微调 | 数据集、caption、过滤、去重、LoRA 与 checkpoint | 训练样本和设置是否允许该用途？ | 能写出数据卡、许可台账与复现实验表 |
| 6. 采样与系统 | DDPM/DDIM 类思路、scheduler、步数、种子、量化与内存 | 速度、稳定性、随机性如何取舍？ | 能在固定条件下复现并记录资源曲线 |
| 7. 评测与溯源 | 保真、多样性、提示词遵循、编辑一致性、记忆与水印限制 | 输出“好”是什么意思，又不能说明什么？ | 能保留提示词、种子、版本、失败样本与人工判据 |
| 8. 风险与应用 | 版权、肖像、深度伪造、偏见、内容分发与退出机制 | 哪些输出必须披露或拒绝自动生成？ | 能写出用途限制、标注和人工复核点 |

## 推荐阅读顺序

1. 原理路线：ML 基础 → LLM 的训练/推理章节 → 数学 70/03 → 模块 1、2、3。
2. 可靠性路线：模块 4 → 模块 5 → 模块 7 → 模块 8。先能解释条件与数据来源，才展示或比较生成结果。
3. 工程路线：CUDA MOC → 模块 6 → 受控微型实验。先固定一条输入、随机种子和版本，再改变一个变量，避免把随机波动当成改进。

## 进阶实验设计、成功标准与硬件路线

| 层级 | 设计 | 成功标准 | 结论边界 |
| --- | --- | --- | --- |
| CPU 概念实验 | 一维/二维小数组上的加噪与解析去噪可视化 | 公式、随机种子、噪声级别和图形一一对应 | 不等于训练了生成模型 |
| 最小模型验证 | 经许可的小型合成/公开数据，固定条件与划分 | 训练曲线、配置、checkpoint 哈希、样本与失败例可复查 | 不证明审美、商业可用性或版权安全 |
| GPU 推理剖析 | 固定模型/提示/种子，比较步数、分辨率、batch、精度 | 记录驱动、框架、scheduler、峰值显存、预热后时延与输出差异 | 不把一次输出或单一自动指标当成质量总判决 |

硬件从 CPU 数学与数组实验开始；8–16 GB 显存主要用于小型或量化推理，并限制分辨率、batch 和并发；24 GB 以上仍只在数据权利、训练目标、显存/磁盘预算和可恢复 checkpoint 方案明确后评估小规模 LoRA。图像分辨率、latent 尺寸、注意力、VAE 编解码与采样步数都可能改变峰值显存或时间；因此必须同时记录输入尺寸、步数、batch、精度与预热状态，而不是只写“使用了某张显卡”。这是预算次序，不是运行/质量或兼容性结论；使用 [[AI/90-资源/03-GPU显存与资源预算表|统一 GPU 预算表]]，在实际模型实验前再按 [[AI/90-资源/05-官方资料与版本核验记录|一手来源核验规则]] 固定模型与工具。

## 数据许可、隐私与评测边界

- 为图像、caption、控制图、风格参考、权重和输出分别记录来源、许可证、训练/微调/商业/再分发条件与保留期。模型许可证不能覆盖不具备授权的数据。
- 禁止把私密照片、人脸、医疗或未公开设计、聊天截图和包含位置/身份线索的素材作为默认练习输入；删除文件不一定收回已上传或已训练的影响。
- 输出须保留足以复查的非敏感谱系信息：模型/权重版本、生成日期、提示词或受控摘要、种子、采样器、步骤、编辑链和人工审核状态。敏感提示词、个人素材和密钥不写入 Vault 或 Git。
- 自动指标与人工偏好只能支持有限主张；需要额外检查文字渲染、对象关系、少数群体刻画、近似记忆、编辑前后身份/结构保持和误导性。高风险媒体必须显著披露为合成，并保留人工拒绝与下架路径。
