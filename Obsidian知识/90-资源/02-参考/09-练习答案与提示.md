# 练习答案与提示

> [!warning] 使用规则
> 先实际操作 3–5 分钟，再依次展开“提示 1”“提示 2”“参考答案”。答案展示一种可行结果，不是唯一正确结构；涉及真实主题和毕业挑战时，以“能解释选择、能检索、能恢复”为准。

## 30 分钟快速上手

对应：[[Obsidian知识/00-开始/02-30分钟快速上手|02-30分钟快速上手]]。

> [!hint]- 提示 1：视图与入口
> `Cmd/Ctrl + P` 找动作，`Cmd/Ctrl + O` 找笔记，`Cmd/Ctrl + E` 在编辑/阅读间切换（以本机 Hotkeys 为准）。

> [!hint]- 提示 2：链接与属性
> 内部链接输入 `[[` 后选择目标；属性可用 `Cmd/Ctrl + ;` 添加。不要直接手敲一个你不确定的完整路径。

> [!answer]- 检查答案
> - 能在 Source mode 看见 Markdown，在 Reading view 看见渲染。
> - 至少两篇笔记用 `[[...]]` 相连；目标页 Backlinks 能看到来源。
> - 一篇笔记有 `type`、`status`、`topics`，类型稳定。
> - 一个标题/块链接或嵌入能跳到正确位置。
> - 今天的 Daily Note 是普通 `.md` 文件，并链接回课程/项目。

## Markdown：基础排版

对应：[[Obsidian知识/10-基础/01-Markdown基础/01-基础排版|01-基础排版]] 与 [[Obsidian知识/30-实践/01-实验区/Markdown/01-自由草稿纸|01-自由草稿纸]]。

> [!hint]- 提示 1
> 标题的 `#` 后必须有空格；段落间空一行。`**粗体**`、`*斜体*` 的标记必须成对。

> [!hint]- 提示 2
> 需要显示星号本身时用 `\*`；内部链接显示文字写成 `[[目标|说明文字]]`。

> [!answer]- 最小参考片段
> ```md
> # 我的第一篇练习
>
> 这是第一段，包含 **重点** 和 *术语*。
>
> ## 我学到的
>
> 我会用 [[Obsidian知识/10-基础/01-Markdown基础/00-Markdown基础-MOC|Markdown 课程导航]] 返回学习路线。
> ```

## Markdown：列表、任务与表格

对应：[[Obsidian知识/10-基础/01-Markdown基础/02-列表任务与表格|02-列表任务与表格]] 与 [[Obsidian知识/30-实践/01-实验区/Markdown/02-表格练习场|02-表格练习场]]。

> [!hint]- 提示 1
> 列表符号后有空格；子项缩进至少两个空格，编辑器中用 `Tab` 最稳。

> [!hint]- 提示 2
> 表格必须有标题行和 `---` 分隔行；单元格中要显示 `|` 时写 `\|`。

> [!answer]- 参考片段
> ```md
> - [ ] 完成一个小实验
>   - [x] 打开练习页
>   - [ ] 写下观察
>
> | 功能 | 是否理解 | 下一步 |
> | :--- | :---: | ---: |
> | 列表 | 是 | 练习嵌套 |
> | 表格 | 否 | 修改一行 |
> ```

## Markdown：附件、数学与脚注

对应：[[Obsidian知识/10-基础/01-Markdown基础/04-附件媒体与数学|04-附件媒体与数学]]、[[Obsidian知识/10-基础/01-Markdown基础/05-脚注与进阶语法|05-脚注与进阶语法]] 和实验区数学页。

> [!hint]- 提示 1
> Vault 图片用 `![[图片.png|宽度]]`；行内数学用单个 `$`，块级数学用成对 `$$`。

> [!hint]- 提示 2
> 脚注引用 `[^id]` 与定义 `[^id]: 内容` 的 ID 要一致；定义可以放在笔记末尾。

> [!answer]- 参考片段
> ```md
> 行内公式 $E=mc^2$，完整推导见资料。[^source]
>
> $$
> \sum_{i=1}^{n}i=\frac{n(n+1)}{2}
> $$
>
> [^source]: 示例来源与链接。
> ```

## Markdown 综合练习

对应：[[Obsidian知识/10-基础/01-Markdown基础/06-综合练习|06-综合练习]]。

> [!hint]- 提示 1：先完成骨架
> 不要一开始加插件或复杂 CSS。先确保标题、摘要、内部链接、任务、Callout、脚注六项在 Reading view 正确。

> [!hint]- 提示 2：检查网络
> 在学习卡中链接 [[Obsidian知识/10-基础/01-Markdown基础/00-Markdown基础-MOC|00-Markdown基础-MOC]]；到 MOC 的 Backlinks 找到作品。嵌入课程标题时使用 `![[笔记#标题]]`。

> [!answer]- 一张合格学习卡应满足
> - frontmatter 从第一行开始；`estimated_minutes` 是 Number，`topics` 是 List。
> - 标题层级连续，不用空行堆视觉间距。
> - 至少一条链接显示去向，一项任务以动词开头。
> - 脚注引用与定义匹配。
> - 能从作品到课程，也能从课程 Backlinks 返回作品。
> - 插件全部关闭后，核心正文仍可读。

## 链接迷宫

对应：[[Obsidian知识/30-实践/01-实验区/链接迷宫/00-链接迷宫-说明|链接迷宫]]。

> [!hint]- 提示 1：路线
> A 的两个已解析链接分别到 B、C；B 和 C 都能返回其他节点。不要点击创建“隐藏房间”。

> [!hint]- 提示 2：四种关系
> 在 B 查 `^maze-clue`；在 C 查前导 `!` 的块嵌入；在 A 的 Outgoing links 看未解析目标；在 C 的 Backlinks 展开两类 mentions。

> [!answer]- 参考答案
> - 路线：A → B → C → A。
> - 固定块：B 中的 `^maze-clue`；C 使用 `![[...#^maze-clue]]` 嵌入。
> - 未解析目标：A 中的 `[[迷宫-D-隐藏房间]]`。
> - C 的 Linked mentions：A、B；Unlinked mention：实验说明中的普通文本“迷宫-C-终点”。
> - 孤立文件：`迷宫-X-孤岛.md`。
> - Graph 过滤器：`path:"Obsidian知识/30-实践/01-实验区/链接迷宫"`。

> [!warning]- 为什么不把所有异常都“修复”？
> 未解析链接可以是未来计划；普通同名文本可能没有语义关系；孤立模板/草稿可能有意不链接。先判断用途，再修改。

## 属性与检索挑战

对应：[[Obsidian知识/10-基础/03-属性标签与检索/07-检索挑战|07-检索挑战]]。下面只给紧凑答案；课程页内有逐关解释。

| 关卡 | 查询/结果 |
| --- | --- |
| 样例目录 | `path:"Obsidian知识/30-实践/01-实验区/数据"` → 甲、乙、丙 |
| active | `path:"Obsidian知识/30-实践/01-实验区/数据" [status:active]` → 甲、丙 |
| 未复习 | `path:"Obsidian知识/30-实践/01-实验区/数据" [fixture_reviewed:false]` → 甲、丙 |
| 项目标签 | `tag:#playground/sample/project` → 丙 |
| source 或 project | `path:"Obsidian知识/30-实践/01-实验区/数据" ([type:source] OR [type:project])` → 乙、丙 |
| 未完成任务 | `path:"Obsidian知识/30-实践/01-实验区/数据" task-todo:`；只观察，勾选会改源文件 |
| 非 processed | `path:"Obsidian知识/30-实践/01-实验区/数据" -[status:processed]` → 甲、丙 |
| 综合条件 | `path:"Obsidian知识/30-实践/01-实验区/数据" [status:active] [fixture_reviewed:false] -[type:daily]` → 丙 |

> [!hint]- Bookmark 题
> Bookmark 保存添加当时的查询入口，不会跟着你后来在搜索框的修改变化，也不会复制结果文件。

> [!answer]- Base 题
> 全部样例：[[Obsidian知识/40-视图/02-Bases/示例笔记目录.base|示例笔记目录.base]]；项目样例：[[Obsidian知识/40-视图/02-Bases/示例项目资料.base|示例项目资料.base]]。

## 核心 Templates 与 Daily Notes

对应：[[Obsidian知识/20-功能/01-官方插件实验室/02-核心 Templates|02-核心 Templates]]、[[Obsidian知识/20-功能/01-官方插件实验室/03-Daily Notes|03-Daily Notes]]。

> [!hint]- 提示 1
> Templates 设置要指向模板文件夹；Daily Notes 还要单独指定日期格式、新文件位置和模板文件。

> [!hint]- 提示 2
> 模板变量只有插入时替换。已创建日记不会因模板后来变化而自动同步更新。

> [!answer]- 最小验证
> - `{{title}}` 变成新笔记标题。
> - `{{date:YYYY-MM-DD}}` 变成当天日期。
> - 模板 Properties 与现有 Properties 正确合并。
> - Daily Note 创建在设定目录，是普通 Markdown。
> - 日记链接到项目后，项目 Backlinks 能看到日记。

## Canvas

对应：[[Obsidian知识/20-功能/01-官方插件实验室/04-Canvas|04-Canvas]]。

> [!hint]- 提示 1
> 从 File explorer 拖入真实笔记，而不是把内容复制成多个文本卡；给连线写“支持”“反驳”“下一步”等关系标签。

> [!hint]- 提示 2
> 纯文本卡不会出现在 Backlinks；要参与链接网络，右键转换为文件。

> [!answer]- 合格 Canvas
> 至少三张真实文件卡、一个分组、两条有语义标签的连线和一张临时说明卡。打开其中一篇源笔记确认内容只存一份。

## Bases

对应：[[Obsidian知识/20-功能/01-官方插件实验室/05-Bases|05-Bases]] 和 [[Obsidian知识/40-视图/02-Bases/00-MOC-Bases|00-MOC-Bases]]。

> [!hint]- 提示 1
> 先让源目录/过滤器返回文件，再加列、排序和分组。一次加太多条件时很难知道哪条过滤掉了结果。

> [!hint]- 提示 2
> 若数字排序怪异，打开源笔记检查属性类型：`4` 是 Number，`4/5` 是 Text。

> [!answer]- 检查答案
> - Base 的每一行/卡片指向真实文件。
> - 直接在 Base 改属性后，源 Markdown 的 frontmatter 同步变化。
> - 删除 Base 视图不会删除源笔记。
> - 至少有一个过滤和一个排序；它们都能用一句话解释。

## Bookmarks 与 Workspaces

对应：[[Obsidian知识/20-功能/01-官方插件实验室/06-Bookmarks与Workspaces|06-Bookmarks与Workspaces]]。

> [!hint]- 提示 1
> Bookmark 保存入口；Workspace 保存布局。两者都不复制笔记内容。

> [!answer]- 检查答案
> - Bookmark 能打开文件、标题或搜索之一。
> - 修改搜索框后，已保存 Bookmark 仍回到保存时的查询。
> - 保存“学习”Workspace 后打乱标签页，再加载可恢复布局；正文修改不因切 Workspace 回退。

## File Recovery 与 Sync 边界

对应：[[Obsidian知识/20-功能/01-官方插件实验室/08-File Recovery与Sync边界|08-File Recovery与Sync边界]]。

> [!hint]- 提示 1
> File Recovery 在本机保存有限快照；Sync 让设备内容一致；备份是独立的一向副本。

> [!answer]- 正确配对
> - 刚误改单篇本机笔记：先查 File Recovery。
> - 使用 Obsidian Sync 且需找旧版本/已删除文件：查 Sync version history。
> - 整台设备损坏或同步错误传播：依赖独立备份。
> - 需要审计文本变更且此前有提交：查 Git history/diff。

## Linter 实验

对应：[[Obsidian知识/30-实践/01-实验区/插件/01-Linter手动实验-故意混乱|01-Linter手动实验-故意混乱]]。

> [!hint]- 提示 1
> 只运行 **Lint the current file**，不要运行全 Vault 命令。先看 Source mode，再执行，再用 Undo/Git diff 比较。

> [!answer]- 应观察到
> 格式、空格、标题/YAML 风格可能改变，但内容判断不会被 Linter 替代。若变化超过预期，撤销并一次只启用一条规则。

## Advanced Tables 与 LaTeX Suite

对应：[[Obsidian知识/30-实践/01-实验区/插件/02-Advanced Tables表格实验|02-Advanced Tables表格实验]]、[[Obsidian知识/30-实践/01-实验区/插件/03-LaTeX Suite数学公式实验|03-LaTeX Suite数学公式实验]]。

> [!hint]- Advanced Tables
> 光标放进表格后用 `Tab`/`Shift+Tab` 导航；移动端改把 Next Cell/Next Row 加入工具栏。先操作实验表格。

> [!answer]- Advanced Tables 的底层
> 插件会重排普通 Markdown 表格；关闭插件后表格仍应可读。若只需要属性集合和排序，Bases 往往更合适。

> [!hint]- LaTeX Suite
> 先确认原生 `$...$`、`$$...$$` 能渲染，再体验 snippet。插件只加速输入，最终内容仍应是可读 LaTeX 文本。

## Tasks 与 TaskNotes

对应：[[Obsidian知识/30-实践/01-实验区/插件/04-Tasks查询实验|04-Tasks查询实验]] 与 [[Obsidian知识/30-实践/04-TaskNotes/Start Here|TaskNotes 静态教学入口]]。

> [!hint]- 提示 1
> Tasks 的数据是一行 checkbox；TaskNotes 的数据是一篇带 Properties 的任务笔记。不要把同一真实任务同时维护两份。

> [!hint]- 提示 2
> Tasks 查询中的勾选会回写源文件。实验前先记住每个任务所在页。

> [!answer]- 选择答案
> - 会议行动项、日记待办、上下文优先：Tasks。
> - 每个任务需要大量属性、日历/看板/时间跟踪：评估 TaskNotes。
> - 只需少量待办：原生 Markdown + Search 可能已经足够。

## Dataview DQL

对应：[[Obsidian知识/30-实践/01-实验区/插件/06-Dataview DQL实验|06-Dataview DQL实验]]。

> [!hint]- 提示 1
> 先确认目标目录中有带 Properties 的 Markdown；查询没有结果时逐步去掉 `WHERE`、排序和复杂表达式。

## QuickAdd 与 Templater

对应：[[Obsidian知识/30-实践/01-实验区/插件/07-QuickAdd与Templater对照|07-QuickAdd与Templater对照]]。

> [!hint]- 提示 1
> 核心 Templates 解决固定结构；QuickAdd 解决“捕获/创建到指定位置”；Templater 解决动态值和高级逻辑。先写出原生手动流程。

> [!hint]- 提示 2
> 第一个 QuickAdd 只做单一 Capture；第一个 Templater 只用内建日期/文件变量。不使用用户脚本或 system commands。

## 综合毕业挑战

对应：[[Obsidian知识/20-功能/03-完整工作流/05-综合毕业挑战|05-综合毕业挑战]]。

> [!hint]- 提示 1：先画最小清单
> 先定 1 个主页 + 3 张角色不同的内容笔记 + 1 篇日记。链接与属性稳定后，再做 Base 和 Canvas；插件最后决定。

> [!hint]- 提示 2：限制是验收工具
> 最多 8 篇 Markdown、1 Canvas、1 Base、2 模板、2 社区插件。若想增加内容，先合并重复职责或删掉无意义视图。

> [!answer]- 一个 10 分参考结构
> - 主页：`type: project`、`status: active`、`topics`，链接概念/来源/会议，写下一步。
> - 内容：一张概念、一张来源、一张决定/实验；一张有 alias，一处 heading/block embed，中心笔记有两条 Backlinks。
> - 日记：链接项目；含一个完成、一个明确下一步、一个链接到资料/人物的任务。
> - Base：显示三张内容笔记；过滤项目范围，按类型/状态排序；第二视图按角色分组。
> - Canvas：真实笔记卡 + 关系标签 + 下一步文本卡；知识不重复复制。
> - Search：用 `path:` + `[type:]`/`[status:]` 精确命中；Local Graph 无意外孤立。
> - 插件说明：每个都能说出原生替代和关闭后的数据状态；不需要插件也可得满分。
> - 恢复：知道单文件 File Recovery/Sync history/Git/独立备份中至少一种适用路径。

### 自评追问

| 维度 | 达到 2 分前问自己 |
| --- | --- |
| 内容 | 每篇能脱离上下文独立理解吗？有自己的判断吗？ |
| 连接 | 每条链接能说出关系吗？Backlinks 能追溯来源吗？ |
| 结构 | 同名属性类型一致吗？Search/Base 稳定命中吗？ |
| 工作流 | 收集之后有整理、行动/输出和复盘吗？ |
| 可维护性 | 关闭社区插件后正文仍可读吗？恢复入口明确吗？ |

低于 7 分时只修最低维度，不要推倒重来。

## 仍然卡住？

1. 把任务缩小到一个动作，例如“让一条链接可点击”。
2. 打开 [[Obsidian知识/90-资源/02-参考/01-Markdown速查表|01-Markdown速查表]] 或 [[Obsidian知识/90-资源/02-参考/02-搜索语法速查表|02-搜索语法速查表]] 查最小语法。
3. 在 Source mode 比较参考片段与自己的源码。
4. Restricted mode + 默认主题判断是否为插件/样式问题。
5. 按 [[Obsidian知识/90-资源/02-参考/08-常见问题与排错|常见问题与排错]] 建最小复现；保留你的真实笔记，不为重置样例覆盖它。
