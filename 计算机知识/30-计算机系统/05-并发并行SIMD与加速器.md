# 并发、并行、SIMD 与加速器

## 本课目标

学完后，你应该能够：

- 区分并发、并行、线程级并行、数据级并行与任务级并行；
- 解释 CPU SIMD 与 GPU SIMT 的共同点和边界；
- 识别数据竞争、同步、归约、分支分歧和传输开销；
- 用 Amdahl 定律直觉判断“加更多核心”的上限；
- 为 C++、CUDA 或 llama.cpp 工作负载选择初步执行策略。

## 1. 并发不保证同一时刻并行

**并发**描述多个任务在一段时间内都在推进；单核也可以通过交替调度实现并发。**并行**描述多个工作在同一时刻由多个执行资源处理。

| 形式 | 划分对象 | 例子 |
| --- | --- | --- |
| 任务级并发/并行 | 不同任务 | 一边读取下一批数据，一边计算当前批 |
| 线程级并行 | 同一程序的多个执行流 | 多核 CPU 分块处理数组 |
| 数据级并行 | 同一操作的多个元素 | SIMD 同时处理一组数 |
| 流水线并行 | 不同处理阶段 | 预处理、推理、后处理重叠 |

这些形式可以叠加。一个推理程序可能有请求级并发、CPU 线程池、线程内部 SIMD，以及 GPU kernel。

## 2. 正确性先于速度：数据竞争与同步

当多个执行流访问同一内存位置，至少一个是写，并且没有合适同步时，就可能发生数据竞争。结果不只是“最后值随机”：在 C++ 等语言内存模型中，数据竞争可能让程序行为失去定义。

更精确地说，C++ 的 **data race** 要同时满足：两个可能并发的求值对同一内存位置作**冲突访问**（读/写、写/写，或对象生命周期开始/结束与重叠位置的访问）；其中至少一个访问是**非原子**；并且两者之间没有 `happens-before` 关系。满足这三个条件，程序就有未定义行为。把每个单独字段都改成原子操作可以消除这类 data race，却**不**自动让业务正确：例如两个原子余额分别更新，仍可能破坏“不能透支、总额守恒”的复合不变量；一个原子 `ready` 标志若没有正确的发布/获取关系，也不保证它所代表的 payload 已经可安全读取。

常见协调工具有：

- 互斥锁：让临界区一次只有一个执行流进入；
- 原子操作：对特定共享状态提供定义良好的不可分割操作和内存顺序；
- 屏障：让参与者在阶段边界会合；
- 消息/队列：通过所有权转移减少共享可变状态；
- 每线程局部结果 + 归约：先独立计算，最后合并。

同步并非免费。锁竞争、缓存一致性流量、屏障等待和原子热点都可能抵消并行收益。

`release`/`acquire` 怎样为“先写数据、再发布标志”建立 `happens-before`，以及为何原子性不等于复合业务不变量，会在 [[计算机知识/30-计算机系统/09-进程线程调度同步与IPC#6. 原子性、顺序与可见性是三个问题|第 09 课的发布/获取协议]]中展开。

## 3. SIMD：一条指令处理多个数据通道

SIMD 把多个同类型元素装进向量寄存器，用一条向量指令进行成组加、乘、比较等操作。适合：

- 元素相互独立或能按规律归约；
- 内存连续、对齐和别名关系足够清楚；
- 分支能转为掩码，或各通道走相似路径；
- 循环长度足以摊销准备与尾部处理。

数组长度不一定是向量宽度的整数倍，剩余元素需要标量尾循环或掩码处理。自动向量化能否发生还取决于编译器是否能证明依赖和别名安全；“打开优化”不保证每个循环都生成 SIMD。

## 4. GPU 的 SIMT：很多线程按组执行

CUDA 用大量轻量线程表达数据并行。线程组织成 block 和 grid，硬件又以 warp 为调度和执行的重要单位。warp 内线程通常共同推进同一条指令路径，各线程处理自己的数据，这常称为 SIMT。

SIMT 与 CPU SIMD 都利用数据并行，但编程抽象不同：

- SIMD 明确操作向量寄存器的多个 lane；
- SIMT 让程序写出许多线程，硬件按 warp 组织执行；
- warp 内分支路径不同会产生分歧，路径可能被分批执行；
- GPU 依靠大量可运行 warp 隐藏一部分内存与指令延迟。

具体映射见 [[计算机知识/40-并行与异构计算/01-CUDA/03-Kernel与Grid-Block-Thread-Warp|Kernel、Grid、Block、Thread 与 Warp]]。

## 5. CPU 与 GPU 不是“弱核心”和“强核心”

| 特征 | CPU 更常擅长 | GPU 更常擅长 |
| --- | --- | --- |
| 控制流 | 复杂分支、低延迟串行任务 | 规则、可批量的数据并行 |
| 并行资源 | 少量复杂核心 + SIMD | 大量线程与高吞吐执行资源 |
| 内存 | 大缓存、主存、低延迟优化 | 高带宽设备内存、显式层级与合并访问 |
| 启动成本 | 普通函数/线程工作较直接 | kernel 启动与主机—设备协调有固定成本 |

GPU 不是所有循环的自动加速器。小任务、频繁往返传输、强串行依赖、分支高度不一致或工作量太少时，CPU 可能更合适。

## 6. 小例子：一百万个独立乘加

任务：对一百万个元素计算 `y[i] = a[i] * scale + bias`。

- 单线程标量：一次处理一个元素，结构最简单；
- CPU SIMD：一个核心每条向量指令处理多个相邻元素；
- CPU 多线程 + SIMD：先把索引范围分块，每线程内部再向量化；
- GPU：大量线程各处理一个或多个元素，要求访问尽量连续，并计入数据是否已经在设备侧。

若数据本就在 GPU 并且后续计算也留在 GPU，这个简单 kernel 可能适合融合进更大操作；若每次只处理几十个数却来回传输，启动与传输成本可能超过计算。

## 7. 归约：并行结果为何会略有不同

求和、最大值、直方图等需要把多个局部结果合并，称为归约。树形并行求和改变加法顺序；浮点加法不满足严格结合律，因此并行结果可能与串行逐项求和有微小差异。

这不等于“并行结果一定错误”。应根据任务设定误差容差、选择累加精度和稳定算法，并区分可重复性要求与数学正确性要求。量化推理还会叠加低位宽表示与反量化误差。

## 8. Amdahl 定律：串行部分决定上限

在“固定问题规模、串行比例 `s` 不随核心数变化、其余工作可理想线性加速、且忽略调度、同步、传输等额外开销”的 Amdahl 模型中，`0 < s <= 1` 时无限并行资源下的速度上限是 `1/s`。若 `s = 0`，该理想模型的极限不再给出有限的 `1/s` 上限；现实硬件仍会受资源与开销限制。

例如 20% 时间无法并行，理想上限就是 5 倍。真实系统常有线程创建、同步、数据划分、设备传输和负载不均衡，因此通常更低；只有确实存在这类非零损失，或并行部分没有达到理想加速时，真实加速才会**严格小于**相同核心数下的无开销公式结果。

改进方向不只是“加核心”，还包括：

- 减少串行部分；
- 增大每批工作，摊销固定开销；
- 合并 kernel 或阶段，减少往返和同步；
- 调整数据布局，提高缓存或合并访问效率；
- 让各工作单元负载更均衡。

## 9. llama.cpp 的分层并行图

本地 LLM 推理常同时包含：

- 请求或批次之间的任务并发；
- CPU 线程对矩阵块、注意力或预处理分工；
- CPU 内核使用 SIMD 处理量化块；
- 部分层或算子卸载到 GPU；
- CPU 与 GPU 之间的队列、传输和同步；
- 逐 token 依赖带来的不可并行部分。

因此线程数、batch、GPU offload 层数和上下文长度会共同影响速度与内存。优化某个矩阵 kernel 不代表端到端生成速度同倍增长；应回到 [[计算机知识/30-计算机系统/04-缓存局部性带宽与延迟|缓存、局部性、带宽与延迟]]的指标与证据链。

将这些层次与实际构建选项、设备后端和调用路径对应起来，见 [[AI/20-LLM/50-实现/04-llama.cpp构建后端与调用链|llama.cpp 构建、后端与调用链]]；需要继续定位 kernel 或添加小型扩展时，见 [[AI/20-LLM/50-实现/05-llama.cpp源码阅读与小型扩展|llama.cpp 源码阅读与小型扩展]]。

## 10. 选择执行方式的五问

1. 单个输出之间是否独立，还是存在前后依赖？
2. 每个工作单元做多少计算、搬多少字节？
3. 数据当前在哪：CPU 主存、页缓存还是 GPU 显存？
4. 是否需要频繁同步、原子更新或跨设备传输？
5. 目标是单请求低延迟、总吞吐、内存占用、能耗还是可重复性？

只有回答这些问题，才有理由选择线程、SIMD、GPU 或它们的组合。

CPU 侧动手验证见 [[计算机知识/80-实践/03-C++/04-布局缓存与并行归约/README|布局、缓存与并行归约实验]]：先用线程局部 partial 避免共享写热点，再分别验证数学结果、端到端计时和 SIMD 代码生成。CUDA 侧必须另做设备级验证，不能继承 CPU 结论。

## 练习

1. 把“下载模型、校验文件、加载权重、执行一次矩阵乘法、生成下一个 token”分类为可并发、可数据并行或存在严格依赖的阶段，并说明理由。
2. 一个程序 10% 串行、90% 可完全并行。计算无限核心的理想上限；再说明在额外开销、负载不均衡或并行部分未达到理想线性加速任一条件存在时，为什么 8 个核心的真实加速会严格小于无开销公式结果。
3. 为一百万元素乘加分别设计 CPU 多线程 + SIMD 与 GPU 划分。标出尾部元素、同步点和数据传输。
4. 两个线程共同更新一个总和。比较“每次原子加”“每线程局部和后一次归约”的一致性流量与合并成本。
5. 解释 GPU warp 分支分歧与 CPU 多线程数据竞争为何是两个不同问题。

## 成功标准

- 你能给出“并发但不并行”和“并行数据处理”的不同例子；
- 你不会把 SIMD lane、CPU 线程和 CUDA thread 当成同一抽象；
- 你能在并行设计中明确共享写、同步、归约和跨设备传输；
- 你会用串行比例与端到端指标约束“加速多少”的结论。
