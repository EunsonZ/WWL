# 属性类型

> [!goal] 你将学会
> 识别 Obsidian 属性的七种常见类型，理解同名属性为何应保持同一类型，并能安全地在 YAML 与属性界面之间切换。

## 属性在哪里

属性写在笔记最上方的 YAML frontmatter 中，由两条 `---` 包围。在 Source mode 中，它看起来像这样：

```yaml
---
type: source
status: processed
rating: 5
fixture_reviewed: true
finished: 2026-08-28
topics:
  - obsidian
  - learning
related:
  - "[[Obsidian知识/30-实践/01-实验区/数据/丙-项目记录]]"
---
```

Obsidian 可以用更友好的属性界面显示这些字段，但底层仍是普通文本。切换到 Source mode 就能验证。

## 七种常见类型

| 类型 | YAML 例子 | 适合做什么 | 常见陷阱 |
| --- | --- | --- | --- |
| 文本 | `status: active` | 状态、作者、摘要 | `active` 与 `Active` 会成为不同的值 |
| 列表 | `topics: [obsidian, learning]` | 多主题、多人物、多链接 | 不要用逗号拼成一整段文本 |
| 数字 | `rating: 5` | 评分、页数、进度 | 写成 `"5"` 会变成文本 |
| 复选框 | `fixture_reviewed: true` | 教学样例的复习勾选 | 使用 `true/false`，不要混用“是/否”文本 |
| 日期 | `due: 2026-09-05` | 截止、完成、创建日 | 建议使用 `YYYY-MM-DD` |
| 日期时间 | `captured_at: 2026-08-30T09:30:00+08:00` | 精确时间点 | 时区不同可能显示成不同本地时间 |
| 标签 | `tags: [playground/sample]` | 横向分类 | 标签不含 `#` 也能被识别；不要加空格 |

> [!important] 同名属性，共享类型
> Obsidian 会在整个 vault 中记住同名属性的类型。若一篇笔记的 `rating` 是数字，另一篇却写成 `rating: excellent`，表格排序、公式与筛选会变得含糊。需要不同含义时改用不同属性名。

## 内部链接为什么要加引号

属性中的内部链接推荐写成：

```yaml
related:
  - "[[Obsidian知识/30-实践/01-实验区/数据/乙-阅读卡片]]"
```

引号让 YAML 把整段 wikilink 当作一个文本值。正文中的 `[[链接]]` 不需要引号；这里的引号属于 YAML，不属于链接本身。

1. 打开 [[Obsidian知识/30-实践/01-实验区/数据/甲-晨间笔记|甲-晨间笔记]]。
2. 在属性区找到 `energy`，确认它是数字。
3. 将 `fixture_reviewed` 勾选，再取消勾选。
4. 给 `topics` 列表临时增加 `reflection`，观察 [[Obsidian知识/40-视图/02-Bases/示例笔记目录.base|示例笔记目录]] 的显示，然后删除它以复原。
5. 切到 Source mode，找到 YAML 中的同一组值。

## 搜索属性

在核心 Search 中尝试：

```text
[type:daily]
[status:active]
[fixture_reviewed:false]
[rating:4]
```

组合条件：

```text
path:"Obsidian知识/30-实践/01-实验区/数据" [status:active]
```

属性搜索适合精确筛选；正文搜索适合寻找某个词出现在哪里。不要把 `[status:active]` 写成普通的 `status:active`，两者含义不同。

## 检查结果

- `rating: 4` 能按数字理解，而 `rating: "4"` 是文本。
- `fixture_reviewed: false` 是可切换的布尔值，不是“false”这个单词。它只表示虚构教学样例的复习勾选，不表示个人掌握度或内容已认证。
- `topics` 可有多个值，`status` 在本教程中只保留一个值。
- 修改属性后，[[Obsidian知识/40-视图/02-Bases/示例笔记目录.base|示例笔记目录]] 会读取最新的 Markdown 属性。

## 挑战与复原

给甲临时增加日期属性 `next_review: 2026-09-01`，搜索 `[next_review:2026-09-01]`。验证后删除该属性。若类型显示不符合预期，打开 **Properties view → All properties** 检查；不要直接编辑 `.obsidian/types.json`。
