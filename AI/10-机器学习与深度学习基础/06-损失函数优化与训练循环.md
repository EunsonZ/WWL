# 损失函数、优化与训练循环

## 目标与适用场景

把“训练模型”拆成可逐项检查的循环。你将能区分损失与业务指标，理解每个训练调用的职责，并验证参数确实在学习。

## 直觉

损失函数把预测有多不好映射为可优化的数。回归常见均方误差，单标签分类常见交叉熵，但选择取决于目标、标签编码、失败代价和评估方式。

- **损失** 通常可微，供优化器产生更新方向。
- **指标** 用任务语言判断成果，如 MAE、召回率、校准和延迟。

损失下降只说明当前训练目标在当前批次或训练集下降；它不自动说明公平性、鲁棒性、成本或测试表现变好。

## 精确定义：一批数据的训练合同

先固定本页词义：**训练模式**是模型的一种工作状态，某些层会在其中采用训练专用行为；例如 Dropout 会随机屏蔽部分中间值，BatchNorm 会使用并更新批次统计量。**优化器**是按梯度更新参数的规则；本例使用最简单的 SGD。现在不必推导它们的内部公式，只需把每一步的职责放对位置。

对每个批次的输入和标签，按以下顺序：

1. 切换到训练模式，使 Dropout、BatchNorm 等训练行为正确。
2. 清零上一个批次累积的梯度。
3. 前向计算预测。
4. 用预测和标签计算损失。
5. 反向计算当前参数梯度。
6. 由优化器更新参数。

验证时切换到评估模式并关闭梯度记录，但输入、标签、指标和数据边界仍须符合任务。

## 最小可运行例

脚本用 8 个 CPU 样本拟合 y 等于 3x 加 1。它不写文件、不访问网络、不下载模型，并固定随机种子。无 PyTorch 时输出 `SKIP:` 并以状态码 77 退出，只能记为 skipped；断言全部成立且状态码为 0 才记为 passed。

<!-- code-sync: ./06_损失函数优化与训练循环.py -->
~~~python
from __future__ import annotations

try:
    import torch
except ModuleNotFoundError:
    print("SKIP: 需要已安装的 CPU PyTorch 才能运行本示例；未下载任何依赖。")
    raise SystemExit(77)

torch.manual_seed(7)
torch.set_num_threads(1)
x = torch.arange(8, dtype=torch.float32).reshape(-1, 1)
y = 3.0 * x + 1.0

model = torch.nn.Linear(1, 1)
criterion = torch.nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.03)

model.train()
for _ in range(800):
    optimizer.zero_grad()
    prediction = model(x)
    loss = criterion(prediction, y)
    loss.backward()
    optimizer.step()

model.eval()
with torch.no_grad():
    final_loss = criterion(model(x), y).item()
    weight = model.weight.item()
    bias = model.bias.item()

print(f"mse={final_loss:.8f}, weight={weight:.4f}, bias={bias:.4f}")
assert final_loss < 1e-4
assert abs(weight - 3.0) < 0.02
assert abs(bias - 1.0) < 0.08
print("训练循环检查通过：参数学到了玩具数据的线性关系。")
~~~

## 先检查标签和输出

| 任务 | 模型输出 | 标签 | 需要确认 |
| --- | --- | --- | --- |
| 回归 | 连续值，常为 [B,1] | 同形状连续目标 | 单位、异常值、MAE 与 MSE |
| 单标签分类 | logits [B,K] | 类别索引 [B] | K、dtype 和损失合同 |
| 多标签分类 | 每类一个 logit [B,K] | 0/1 多热目标 [B,K] | 每类是否可独立为真 |

不同损失函数的细节以当前官方文档为准，并在小批次上断言 shape、dtype 和损失数值合理。

## 从一批更新到完整训练

一轮批次更新不是完整实验。常见外层结构是：遍历训练批次更新参数，随后在**不更新参数**的验证集上汇总指标，再由预先写定的早停或调参规则决定下一轮。若训练集大小为 $N$、批大小为 $B$，一个 epoch 大约有 $\lceil N/B\rceil$ 个 optimizer step；梯度累积会让“微批次数”与“参数更新次数”不再相同。

学习率控制每次更新尺度。过大可能震荡或发散，过小可能在预算内几乎不动；batch 大小、梯度尺度、优化器和学习率调度共同影响轨迹。SGD、Momentum、Adam 与 AdamW 的公式与差别不在本页重复，统一见 [[数学/40-微积分与优化/04-SGD-Momentum-Adam与AdamW|SGD、Momentum、Adam 与 AdamW]]。这里的工程检查是同时记录 `epoch`、`microbatch`、`optimizer step`、学习率、有效样本/token 数和验证指标，避免把不同横轴的曲线直接比较。

## 练习

1. 去掉优化器更新，解释损失为何不会真正下降。
2. 此例没有 Dropout 或 BatchNorm；说明为何切换训练和评估模式仍是通用合同。
3. 为预测订单金额提出一个训练损失和两个报告指标，说明它们为何不必相同。
4. 数据集有 1,000 条样本，微批大小 20，每累计 4 个微批更新一次。写出每个 epoch 的微批数、完整累积组数与剩余微批；比较“丢弃剩余梯度”和“在 epoch 末用剩余梯度再更新一次”两种实现的 optimizer step 数。

## 成功标准

- 能解释六步训练合同。
- 能说明反向计算和优化器更新不能互相替代。
- 能在训练损失之外报告验证或测试指标。
- 第 1 题能指出：参数没有改变，所以同一数据上的预测与损失保持不变；若运行代码，应保留删除前后的最终损失作为证据。
- 能区分 epoch、微批与 optimizer step；第 4 题得到 50 个微批、12 个完整累积组和 2 个剩余微批：丢弃剩余梯度时 12 次更新，epoch 末再更新时 13 次；真实训练还可能跨 epoch 累积，必须查实现合同。
- 能在汇总中区分 `passed (exit 0)`、`skipped (exit 77)` 与其他非零状态的 failed，不把缺少可选依赖当作成功。
