# 类型、协议与数据边界：静态说明不能代替运行时验证

> **学习位置**：[[计算机知识/00-开始/课程地图/04-Python-课程地图|Python课程地图]] · **适用边界**：Python 3.11+；CPython 实现细节明确注明。

## 类型注解在哪个阶段起作用

Python 不会因为参数写成 `age: int` 就拒绝字符串实参。注解供静态工具、文档和框架使用；运行时是否验证取决于显式逻辑或具体库。`typing.cast` 告诉类型检查器采用某个看法，不转换对象，不检查内容。把 `Any` 放进核心接口会让许多错误绕过检查；未知外部数据应先保留为 `object`，经过验证再进入领域模型。

`Protocol` 描述结构化能力，例如“能读取字节”的对象，不必继承特定基类。`@runtime_checkable` 的运行时检查也不等于完整参数类型、返回类型和行为验证。子类型除了方法形状兼容，还应该保留调用方依赖的语义，例如不让只读接口悄悄删除数据。

## 让非法状态尽量难以表达

把“请求状态”写成字符串和一堆可选字段，容易产生 `status='success'` 却没有结果的组合。可以使用区分明确的数据类或枚举，让成功携带结果、失败携带错误。`TypedDict` 描述字典的预期形状，但依旧不在运行时验证 JSON。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Reading:
    value: int

def parse_reading(obj: object) -> Reading:
    if not isinstance(obj, dict) or set(obj) != {'value'}:
        raise ValueError('字段必须恰好为 value')
    value = obj['value']
    if isinstance(value, bool) or not isinstance(value, int):
        raise ValueError('value 必须为非布尔整数')
    if not 0 <= value <= 1000:
        raise ValueError('value 超出范围')
    return Reading(value)
```

这是明确的严格模式：未知字段被拒绝。另一个系统可以选择保留或忽略未知字段，但必须把兼容策略写进协议。验证对象形状后仍要检查单位、范围、跨字段一致性、授权和数据量上限。合法 JSON 不等于合法业务请求。

## 字符串、字节与路径不要混淆

文本是 Unicode 字符串，网络和文件最终传输字节。编码在边界显式指定；字符串长度通常不是 UTF-8 字节长度，也不等于用户看到的字素数。比较用户名时还要讨论大小写折叠和规范化策略，不能简单 `lower()` 就宣称全球唯一。

路径拼接不提供目录约束。处理用户提供的相对路径时，需要拒绝越界并考虑符号链接和检查后替换竞争；高安全需求应使用基于目录文件描述符的系统接口等机制。`Path.resolve()` 后检查前缀只是某些场景的一层防线，不是通用的无竞争沙箱。

## 序列化与命令执行的安全边界

不对不可信内容使用 `eval`、`exec` 或 pickle。即便是 `ast.literal_eval`，面对任意大输入也需要资源限制。SQL 使用参数绑定；参数化保护的是值，不会自动允许安全拼接任意表名。子进程优先传入参数列表并避免 `shell=True`，同时检查目标程序自身的选项注入风险，例如需要时使用 `--` 终止选项解析。

## 练习与答案

给 `parse_reading` 输入 `True`、`{'value': True}`、`{'value': 5, 'admin': True}`、`{'value': 1001}`，四者均应拒绝；`{'value': 0}` 应接受。再修改需求为“容忍未来新增字段”，记录哪条验证必须改变，以及为什么授权字段不能因此自动获得信任。完成标准不是类型检查器绿灯，而是边界合同与测试一致。
