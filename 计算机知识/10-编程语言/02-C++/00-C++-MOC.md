C++ 的难点不在于记住多少语法，而在于每个抽象都跨越了语言、构建工具、资源所有权和机器执行方式。本路线的终点很具体：你能在隔离目录配置并构建一个 `llama.cpp` 版本，沿着一次推理请求读懂主要调用链，并在测试保护下做一处小幅扩展。

> [!abstract] 完成后的能力
> 你将能区分预处理、编译、链接和运行；用 CMake 构建小项目；说明对象、引用、指针、生命周期和资源所有权；读懂常见 STL/模板/移动语义；用 sanitizer 与调试器定位问题；理解线程同步、ABI、缓存和 SIMD 的边界；最后将这些概念映射到 `llama.cpp` 的模型加载、图构建、后端分发与采样循环。

## 先运行一个完整小项目

本目录的 `CMakeLists.txt` 会构建所有伴随例子。在此目录执行：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
./build/toolchain
```

`ctest` 会运行八个短程序，最后一条直接观察第一个程序的输出；其余程序也可直接运行，例如 `./build/errors`、`./build/layout`。构建产物均在 `build/`，可以安全删除后重建；不要把它提交到课程目录。

## 最常混淆的边界

| 不要混为一谈 | 区别 |
| --- | --- |
| 指针 / 所有权 | 指针只表示可访问地址；所有权回答谁负责资源何时释放。 |
| `std::move` / 移动发生 | `std::move` 只是把表达式转成右值；实际是否移动取决于目标类型和重载。 |
| 原子 / 无锁 / 正确 | 原子操作避免特定数据竞争，不自动构成正确协议，也不保证无锁。 |
| C++ ABI / C ABI | C++ 名字改编、异常、类布局等跨编译器风险更高；稳定插件边界常取窄的 C ABI。 |
| “零拷贝” / 不分配 | 它通常只意味着某一段传递不复制；仍可能分配元数据、做页映射或发生设备传输。 |

## 终点验收：能小幅扩展 llama.cpp

- [ ] 我能用项目文档列出的预设和隔离 `build/` 配置 `llama.cpp`，并保存 CMake 配置输出。
- [ ] 我能从 CLI/server 的入口定位参数解析、模型加载、context 建立、decode/eval 与采样循环，而不是从随机 kernel 文件开始。
- [ ] 我能区分公共 API、`llama` 层、`ggml` 图与后端实现，并说明一个符号的所属层。
- [ ] 我能针对一个小改动先找到现有测试或新增最小回归测试，再运行目标测试与 sanitizer 构建。
- [ ] 我不会把本机模型、下载链接、访问令牌、绝对个人路径或巨型构建目录写入仓库。
