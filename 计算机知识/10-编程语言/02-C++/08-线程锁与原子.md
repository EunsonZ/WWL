# 08 · 线程、锁与原子

## 本课目标

先建立底线：两个线程未同步地读写同一非原子对象，就是数据竞争，行为未定义。锁保护复合不变量；原子适合清楚、有限的状态转移；二者都不能代替整体协议设计。

<!-- code-sync: ./concurrency.cpp -->
```cpp
#include <atomic>
#include <iostream>
#include <mutex>
#include <thread>
#include <utility>
#include <vector>

class Progress {
public:
    void record(int tokens) {
        const std::lock_guard lock(mutex_);
        ++completed_;
        tokens_ += tokens;
    }

    std::pair<int, int> snapshot() const {
        const std::lock_guard lock(mutex_);
        return {completed_, tokens_};
    }

private:
    mutable std::mutex mutex_;
    int completed_ = 0;
    int tokens_ = 0;
};

int main() {
    std::atomic<int> started{0};
    Progress progress;
    std::vector<std::thread> workers;
    for (int i = 0; i < 4; ++i) {
        workers.emplace_back([&started, &progress, i] {
            started.fetch_add(1, std::memory_order_relaxed);
            progress.record(i + 1);
        });
    }
    for (auto& worker : workers) {
        worker.join();
    }
    const auto [completed, tokens] = progress.snapshot();
    if (started.load(std::memory_order_relaxed) != 4 || completed != 4 || tokens != 10) {
        std::cerr << "concurrency contract failed\n";
        return 1;
    }
    std::cout << completed << ' ' << tokens << '\n';
}
```

`started` 只是独立计数，没有承担发布其他数据的职责，因此 `memory_order_relaxed` 足够保证它自身的原子递增。`completed_` 与 `tokens_` 必须作为一组快照满足不变量，所以由同一把 mutex 保护；只把两个字段分别改成 atomic 仍不能自动得到同一时刻的一致快照。`join()` 保证主线程在读取最终值前等待所有 worker 结束。不要从这个例子推广为“relaxed 总是最快、总是正确”。

## 选择同步原语

- 多个字段必须一起保持不变量：`std::mutex` + `std::lock_guard` 或 `std::scoped_lock`。
- 单一状态位/计数器，且能精确说明读写顺序：`std::atomic<T>`。
- 等待条件变化：mutex 配合 `std::condition_variable`，并用谓词处理伪唤醒。
- 线程生命周期：优先 `std::jthread`（可用时）或显式 `join`；这里选择 `join`。`detach()` 只让 `std::thread` 对象不再 joinable，不会延长捕获的局部引用、`this`、日志器或共享状态的寿命，也不保证进程退出前任务完成。只有被访问状态有独立且可证明的生命周期，并且停止与退出协议明确时才使用 `detach`；不要 detach 一个捕获局部引用的线程后离开作用域。

> [!warning] 不要从 CPU 线程知识推导 CUDA 同步
> GPU 的线程层级、内存空间、同步范围和 host-device 边界不同。CPU 侧调度概念可衔接 [[计算机知识/40-并行与异构计算/01-CUDA/00-CUDA-MOC|CUDA]]，但不能替代 CUDA 的内存模型。

## 练习与成功标准

把 worker 数改为 100，并把每个 worker 记录的 token 数固定为 1。成功标准：输出总是 `100 100`；你能解释为何 `started` 可用 relaxed 原子、为何 `Progress` 的两个字段由同一把锁保护，以及这仍不证明任意共享数据结构线程安全。继续用 [[计算机知识/80-实践/03-C++/04-布局缓存与并行归约/README|并行归约实验]]比较“共享热点更新”和“线程局部结果后归并”。
