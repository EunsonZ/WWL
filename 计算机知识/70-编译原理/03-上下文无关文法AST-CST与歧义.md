# 03 · 上下文无关文法、AST、CST 与歧义

## 本课目标

学完后，你能用 CFG 的终结符、非终结符、产生式和开始符号描述一门小语言；能区分推导、CST 与 AST；能给歧义文法构造两棵不同解析树；能用优先级、结合性和分层文法消除算术表达式歧义，并说明为什么消左递归有时是解析算法的需要而不是语言语义改变。

## 直觉：token 序列有顺序，却不自动有结构

词法分析器能把 `a + b * c` 变为 `Identifier Plus Identifier Star Identifier`，但它没有回答“先加还是先乘”。解析的任务是给 token 序列建立层次结构，让后续类型检查、解释、优化和代码生成不必从字符或优先级猜测中重新理解程序。

前一课给出 token 与 span 的边界，见 [[计算机知识/70-编译原理/02-词法分析正则自动机Unicode与源位置|词法分析、正则自动机、Unicode 与源位置]]。本课从 token 序列开始；不把 CFG 当作字符串正则的升级版，也不把 AST 当作唯一正确的树形数据结构。

## 1. CFG 的精确定义与推导

一个上下文无关文法（context-free grammar, CFG）可写为四元组：

$$
G=(N,\Sigma,P,S).
$$

- `N`：非终结符集合，表示尚待展开的语法类别，如 `Expr`；
- `Σ`：终结符集合，通常是 lexer 输出的 token kind/字面 token；
- `P`：产生式集合，形如 `Expr → Expr + Expr`；
- `S`：开始符号，规定一段完整输入从哪个类别开始。

产生式的左侧是一个非终结符，右侧是终结符与非终结符的序列。把某个非终结符替换为其右侧叫作一步推导，写作 `⇒`；零次或多次推导写作 `⇒*`。文法生成的语言是所有可由 `S ⇒*` 得到、且最终只含终结符的串。

例如括号匹配的简化文法：

```text
S → ( S ) S | ε
```

可做左最推导：

```text
S ⇒ ( S ) S ⇒ ( ) S ⇒ ( ) ( S ) S ⇒ ( ) ( ) S ⇒ ()()
```

它说明 `()()` 属于该语言。推导顺序是构造/证明工具；同一棵树常能有不同的左/右展开顺序。更根本的对象是树的父子结构，而不是打印推导时先替换了哪个符号。

### 语言、实现和合法推理的边界

CFG 规定的是**语法形状**，通常不足以规定所有约束：变量必须先声明、函数实参数量、类型相容、`break` 是否在循环中，往往要在语义分析处理。类似地，“解析成功”只是存在某棵符合文法的树，不推出程序满足类型、资源或业务约束。集合、量词、蕴含与反例的基本语言见 [[数学/10-数学语言与基础/03-集合映射命题与合法推理|集合、映射、命题与合法推理]]；这里要把“某串存在解析”与“所有解析结果都同义”分开。

## 2. CST 与 AST：保留什么，是接口设计

**具体语法树（CST, concrete syntax tree）**贴近产生式和源码表面：括号、分号、关键字、空白/注释（某些实现以 trivia 附着）都可能保留。它适合格式化、重构、IDE 高亮和精确错误恢复，因为工具需要知道原文如何写。

**抽象语法树（AST, abstract syntax tree）**保留对语义和后续处理最有意义的结构，常省略语法噪声。对 `let x = 1 + 2;`，一种 CST 可包含 `LetKeyword`、`Identifier`、`Assign`、`IntLiteral`、`Plus`、`IntLiteral`、`Semicolon`；相应 AST 可以更接近：

```text
Let(name = x,
    initializer = Add(Int(1), Int(2)))
```

二者没有“谁更真实”的高下：CST 是保留具体写法的表征，AST 是按后续语义压缩后的表征。一个编译器可以只建 AST；一个 IDE 可以保留 lossless CST 后再投影为 AST；错误恢复的树还可能显式含 `MissingToken` 或 `ErrorNode`。因此讨论数据结构前先问消费者是谁。

与运行时对象、调用约定和二进制布局的衔接，见 [[计算机知识/30-计算机系统/03-ABI调用约定与静态动态链接|ABI、调用约定与静态/动态链接]]；AST 不是已经生成的机器码，也不是链接器输入的目标文件。

## 3. 歧义：同一串有两棵不同的解析树

看似自然的表达式文法：

```text
Expr → Expr + Expr | Expr * Expr | ( Expr ) | id
```

它能生成 `id + id * id`，却是**歧义的**：该 token 串至少有两棵不同解析树。

```text
树 A：            Expr                     树 B：           Expr
                /  |  \                                  / | \
             Expr  +  Expr                             Expr * Expr
              id       / | \                           / | \      id
                     Expr * Expr                    Expr + Expr
                      id     id                       id     id

含义：id + (id * id)                    含义：(id + id) * id
```

对算术语言，这两种树可得不同值；因此“parser 随便选择一种”不是可靠语言设计。注意：一个文法歧义，不代表语言必然无法实现；语言规范可另行给出优先级/结合性规则，或实现可把歧义文法改写为等价的无歧义文法。风险在于若规范、parser 和工具各自选择不同规则，用户写出的同一文本会有不一致含义。

## 4. 用分层文法编码优先级与结合性

令乘法优先于加法、二者都左结合，可写成：

```text
Expr   → Expr + Term | Term
Term   → Term * Factor | Factor
Factor → ( Expr ) | id
```

`Expr → Expr + Term` 的左子节点仍是 `Expr`，右子节点才是 `Term`；因此左边可继续包含加法，右边的乘法先在 `Term` 层形成。`a + b * c` 得到 `Add(a,Mul(b,c))`，`a + b + c` 得到 `Add(Add(a,b),c)`。此文法列出的加法左递归编码左结合；若要讨论减法，须先在同层加入减法产生式。结合性不是“运算符从左向右扫描”的同义词，而是同优先级连续出现时树如何嵌套：

| 规则 | `a op b op c` 的树 | 常见例子 |
| --- | --- | --- |
| 左结合 | `(a op b) op c` | `-`、`/`（通常） |
| 右结合 | `a op (b op c)` | 赋值、幂（依语言而定） |
| 不结合 | 拒绝连续使用或要求括号 | 比较运算（依语言而定） |

需要右结合赋值时，分层文法可以写成 `Assign → Identifier = Assign | Expr`，使右边再次是 `Assign`。不要从某个语言的惯例推广到所有语言：例如幂、比较链和赋值表达式是否存在，必须以目标语言规范为准。

### 括号不是“提高优先级”，而是明确子树

`(a + b) * c` 中的括号让 `Factor → ( Expr )` 先生成一个整体；它不是把 `+` 运算符本身改造成比 `*` 更高优先级。AST 常丢弃这对括号 token，因为树已经编码了分组；若要重现用户原始括号或格式，CST/源 span 仍有价值。

## 5. 左递归与解析算法：改写形状，保持语言/结合性

上面的 `Expr → Expr + Term | Term` 是直接左递归。递归下降 parser 若直接按该规则调用 `parseExpr`，会在尚未消费 token 时再次调用 `parseExpr`，导致无限递归。常见的语言等价改写为：

```text
Expr  → Term ExprTail
ExprTail → + Term ExprTail | ε
```

这适合预测式解析，但若简单按右递归结构建树，可能把原本左结合的运算错误建成右结合。正确做法是读取第一个 `Term` 后，在每读到一个 `+ Term` 时把累积左树更新为新的父节点：

```text
left ← parseTerm()
当下一个 token 是 +：
    消费 +
    right ← parseTerm()
    left ← Add(left, right)
返回 left
```

该算法每轮消费 token，因此不会原地递归；对 `a + b + c` 依次构造 `Add(a,b)`、再构造 `Add(Add(a,b),c)`。它说明：消左递归常是为匹配某种 parser 技术而改变**文法书写**，却不应无意改变目标语言的 AST 和结合性。

并非所有 parser 都要消左递归。LR、GLR、Earley 或 packrat/PEG 等技术有不同的限制和歧义处理策略；某些工具允许直接左递归或以声明式优先级解决冲突。选择算法时要同时考虑语言类别、错误恢复、性能、工具生态和规范，而不是把一种课堂改写当作通用要求。

## 错误边界与反例

1. **正则不是 CFG 的替身**：有限自动机不能在一般情况下记住任意深度嵌套的括号；词法规则与表达式/块结构应分层处理。词法自动机的边界见 [[计算机知识/70-编译原理/02-词法分析正则自动机Unicode与源位置|词法分析、正则自动机、Unicode 与源位置]]。
2. **一棵解析树不证明文法无歧义**：要证明歧义，只需找一串和两棵不同树；未在几个例子上发现第二棵树，不能证明不存在。
3. **CST 省略不代表源信息不重要**：丢掉注释、括号、精确 token 与 span 后，格式化/重构可能无法保留用户写法。
4. **消左递归不自动保留 AST**：把递归方向机械反转，可能让 `a-b-c` 从左结合变成右结合，改变结果。

## 练习

1. 对 `S → ( S ) S | ε` 给出 `(()())` 的左最推导，并画出一棵树。说明为什么 `())(` 不能完成为只含终结符的推导。
2. 用歧义 `Expr` 文法为 `id * id + id` 画出两棵不同 CST；各自对应哪一种分组？
3. 为含 `+` 与 `*` 的表达式写分层无歧义文法，使 `*` 高于 `+` 且二者左结合；再说明 `(a+b)*c` 的 AST 为什么无需保存括号 token 也可保持语义。
4. 按本课循环式伪代码追踪 `a + b + c` 的 `left`。若你改成 `left ← Add(right, left)`，哪条不变量被破坏？
5. 选择一门熟悉语言，核对它的赋值、比较和幂运算是否存在、优先级与结合性如何规定；记录来源版本，避免从别的语言迁移结论。
