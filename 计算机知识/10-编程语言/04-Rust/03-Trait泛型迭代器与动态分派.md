# Rust：Trait、泛型、迭代器与抽象成本

> 阅读定位：基础示例兼容 Rust 2021 edition；不把 edition 等同于编译器版本。返回 [[计算机知识/00-开始/课程地图/03-Rust-课程地图|Rust · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## Trait 是可调用能力的合同

泛型函数不能因为“运行时传入的类型看起来有那个方法”就直接调用它，接口必须给出 trait 约束。`fn max<T: Ord>(a:T,b:T)->T` 表示可使用全序比较；浮点含 NaN，通常不能直接满足 `Ord`，这迫使你明确排序语义而不是悄悄忽略特殊值。

关联类型适合实现者决定的唯一角色，例如 Iterator 的 `Item`；泛型参数允许同一个 trait 在不同参数化情形下表达不同关系。trait coherence 与 orphan rules 限制冲突实现，使下游代码不至于在新增依赖后遭遇随意的重叠含义。

## 静态分派与动态分派

`T: Trait` 常通过单态化为实际类型生成相应代码，提供内联优化机会，也可能增加代码体积。`&dyn Trait` 通过运行时分派处理不同实现，适合开放的异构集合，代价包括间接调用及部分优化信息减少。并非任意 trait 都能作为 dyn 使用，必须满足 dyn compatibility 的限制。`impl Trait` 隐藏具体类型但不是随意返回多个不同类型的“动态盒子”。

不要把“零成本抽象”误解为任何写法都零分配、零拷贝或速度相同。应观察生成代码、分配次数和实际负载；优化器是否能消除中间层取决于具体代码与边界。

## 迭代器把遍历与变换分开

```rust
fn sum_positive(values: &[i32]) -> i64 {
    values.iter()
        .copied()
        .filter(|x| *x > 0)
        .map(i64::from)
        .sum()
}
```

`iter()` 借用元素，`iter_mut()` 借用可修改元素，`into_iter()` 的所有权行为由被迭代对象类型决定。多数适配器惰性构造计算，终端消费才真正推进；创建一个 map 迭代器但不消费，不会保证其中副作用执行。以上函数先把正数提升到 i64 再累加，但对于任意巨大输入仍应讨论最终和是否超出 i64，类型变宽不是无限精度证明。

闭包可以捕获环境。`Fn`、`FnMut`、`FnOnce` 分别约束调用所需的接收方式，能力存在包含关系；`move` 让捕获以拥有值方式进入闭包，但闭包是否只能调用一次还取决于它如何使用捕获值。

## 较少见但有位置的内容

关联常量、默认方法、supertrait、newtype、Deref、运算符 trait、From/TryFrom、IntoIterator、AsRef/Borrow、泛型关联类型、const generics 都是进一步表达接口的工具。声明式宏做语法级重复消除；过程宏处理 token 流，不等于在运行时反射全部类型。先用具体类型把合同讲通，再决定是否值得抽象。

练习：为一个长度单位写 newtype，避免米和毫秒混传；为字符串解析实现可失败转换。给两种策略分别写泛型和 dyn 接口，解释代码尺寸、扩展性与调用开销之间的取舍，而不是只给出一张“谁快”的排名。
