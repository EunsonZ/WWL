# 排序选择与稳定性

## 本课目标

排序不是“把数字排好”这么简单。你要能区分比较排序与利用键范围的排序，按稳定性、额外空间、最坏情况、数据分布和工程约束选择算法，并知道 `O(n log n)` 不是任何现实排序都必须达到的时间。标题中的“选择”指**选择排序算法**；它不是“第 $k$ 小元素”的 order-statistic / Quickselect 问题，后者只做分区并继续包含目标秩的一侧，通常不产生完整有序序列。

本课使用伪代码；可运行实现、基准和性质测试归入 `计算机知识/80-实践/05-数据结构与算法/` 实践目录。

## 1. 排序契约：有序、排列、稳定

给定记录序列 `A` 与比较器 `less`，正确排序至少要求：

1. **有序性：** 对任意相邻输出 `B[i],B[i+1]`，不能有 `less(B[i+1], B[i])`；
2. **排列性：** 输出恰好包含输入的每一条记录，没有丢失、复制或凭空生成；
3. **比较器契约：** `less` 应有一致的严格弱序语义；若比较器自相矛盾，算法无从保证全局顺序。

> [!warning] 三个元素就能暴露比较器矛盾
> 若一个比较器声称 `A < B`、`B < C`，却又声称 `C < A`，就形成环，任何输出都会违背其中一条“更小”关系。这违反了比较器应有的传递性；排序算法无法靠多交换几次修复一个没有全局顺序的规则。现实中常见原因是把会变化的时间、随机数或不一致的多字段规则直接写进比较函数。

若两个记录按键相等，稳定排序还要求它们保持输入相对次序。`[(A,2),(B,1),(C,2)]` 按第二列稳定排序应输出 `[(B,1),(A,2),(C,2)]`。稳定性不是“数值更正确”，却决定二次排序、日志展示、分页稳定性和同分记录的可解释性。

## 2. 比较排序的下界：信息从哪里来

若元素互异，比较一次最多产生“左小于右”或“不小于”的两种结果，可把过程看为二叉决策树。$n$ 个元素有 $n!$ 种可能排列，算法需要至少 $n!$ 个叶子区分它们，因此最坏情况比较次数至少满足：

$$
2^h\ge n!\quad\Rightarrow\quad h\ge \log_2(n!)=\Omega(n\log n).
$$

这给出**仅依赖比较**的最坏情况信息下界。它不说每个实现都恰为 `n log n`，也不约束能利用整数范围、位、桶或预先结构的算法。

> [!note] 反例：为何计数排序不违反下界
> 若键是范围 $0..k$ 的整数，算法可直接用键当索引计数，而不靠比较区分 $n!$ 种排列。因此它的时间可为 $O(n+k)$；代价是需要知道且接受键范围、额外数组与适用的数据类型。

## 3. 选择表：先列约束，再选名称

| 算法 | 核心策略 | 时间（期望/最坏；快排为随机 pivot） | 额外空间 | 稳定 | 原地 | 应优先考虑的条件 |
| --- | --- | --- | --- | --- | --- | --- |
| 插入排序 | 把当前项插入已排序前缀 | $O(n^2)$ / $O(n^2)$；最好 $O(n)$ | $O(1)$ | 可为是 | 是 | 小数组、近乎有序，或混合排序的小分区 |
| 快速排序 | pivot 分区，递归两侧 | $O(n\log n)$ / $O(n^2)$ | 期望 $O(\log n)$ 栈；最坏 $O(n)$ | 通常否 | 通常是 | 通用数组、局部性好，须防退化 |
| 归并排序 | 分半排序再合并 | $O(n\log n)$ / $O(n\log n)$ | 常见 $O(n)$ | 是 | 通常否 | 需要稳定、最坏界、外部/链式合并 |
| 堆排序 | 维护最大/最小堆 | $O(n\log n)$ / $O(n\log n)$ | $O(1)$ | 否 | 是 | 内存紧、要最坏界；常数与局部性要测 |
| 计数排序 | 统计每个整数键频次 | $O(n+k)$ / $O(n+k)$ | $O(n+k)$（稳定版本） | 可为是 | 否 | 小而可接受的整数范围 |

“原地”通常指除少量变量和递归栈外不随 `n` 增长的额外存储；不同资料是否把调用栈算入会不同，阅读声明时应核对。稳定性也取决于**具体实现**，不是只看算法名字。

## 4. 插入排序：用已排序前缀建立第一个排序证明

插入排序扫描 `i = 1..n-1`，并把 `A[i]` 插入前缀 `A[0..i)` 的正确位置。每轮开始时的循环不变量是：`A[0..i)` 已按比较器有序，且它恰是原输入前 `i` 项的一个排列。

```text
INSERTION_SORT(A):
    for i from 1 to length(A) - 1:
        value = A[i]
        j = i
        while j > 0 and value < A[j - 1]:
            A[j] = A[j - 1]
            j -= 1
        A[j] = value
```

向右移动的都是比 `value` 大的已排序元素，因此插入后新前缀仍有序；移动和写回没有丢失或新增元素，故排列性也保持。终止时 `i=n`，整个数组就有序且是原输入的排列。

只在 `value < A[j-1]` 时移动，相等元素不会跨过彼此，因而这个版本稳定；若把条件改成“小于等于”，数值仍有序却可失去稳定性。逆序输入需移动 `1+2+…+(n-1)=Θ(n²)` 次；已有序时每轮只做常数检查，为 `Θ(n)`。这也是它常被混合排序用于小分区的原因之一，但阈值仍应由具体实现和测量决定。

## 5. 快速排序：分区不变量与退化

选择 pivot 后，分区的目标不是立刻全局有序，而是建立：左区元素不大于 pivot，右区元素不小于 pivot；pivot 落到最终位置。随后独立排序两侧。

```text
QUICKSORT(A, lo, hi):                 // 半开区间 [lo, hi)
    if hi - lo <= 1:
        return
    pivot = choose_pivot(A, lo, hi)
    p = partition(A, lo, hi, pivot)
    QUICKSORT(A, lo, p)
    QUICKSORT(A, p + 1, hi)

PARTITION(A, lo, hi, pivot):
    move pivot to hi - 1
    boundary = lo
    for i from lo to hi - 2:
        if A[i] < pivot:
            swap A[i], A[boundary]
            boundary += 1
    swap A[boundary], A[hi - 1]
    return boundary
```

循环不变量是：`[lo,boundary)` 都小于 pivot，`[boundary,i)` 都不小于 pivot，`[i,hi-1)` 尚未检查。扫描结束后交换 pivot，分区正确；递归只需排序严格更小的两段。

若每次 pivot 恰为最小/最大值，子问题规模变成 `n-1,0`，比较总和为 $(n-1)+(n-2)+…+1=O(n^2)$，递归深度为 $O(n)$。已排序输入配“总取首元素”就是经典反例。表中的期望 $O(n\log n)$ 和期望 $O(\log n)$ 栈，前提是对任意固定输入，算法在每个非平凡子问题随机选择 pivot，期望取自这些随机选择；它不是对某种“典型输入”的模糊承诺。即使随机化，仍可能连续选到极端 pivot，故最坏时间和栈深仍分别是 $O(n^2)$、$O(n)$。抽样 pivot 可降低固定模式触发退化的概率，三路分区可改善大量重复键；它们不是最坏情况自动消失的证明。

快速排序常因连续扫描与原地分区有好局部性，但交换、分支预测、递归深度和元素移动成本都依赖数据与实现。实际库常是混合算法：小区间改插入排序，递归过深改堆排序等；不要凭名称假定每个平台相同。

## 6. 归并排序：稳定来自“相等时先取左边”

归并把两个已经有序的半开区间合成一个：

```text
MERGESORT(A, lo, hi):
    if hi - lo <= 1:
        return
    mid = lo + (hi - lo) // 2
    MERGESORT(A, lo, mid)
    MERGESORT(A, mid, hi)
    MERGE(A, lo, mid, hi)

MERGE(A, lo, mid, hi):                 // 合并 A[lo, mid) 与 A[mid, hi)
    output = empty sequence
    i = lo
    j = mid
    while i < mid and j < hi:
        if A[j] < A[i]:
            append A[j] to output
            j += 1
        else:
            append A[i] to output         // 相等时左侧先出，保持稳定
            i += 1
    append A[i, mid) and A[j, hi) to output
    copy output back to A[lo, hi)
```

`MERGE` 的不变量是：`output` 已按序，且恰好包含两个输入区间已消费前缀中最小的所有项。两边分别有序，所以只比较各自头部即可安全地输出较小者；剩余一侧可按原顺序追加，再写回 `A[lo, hi)`。每层合并总共移动/比较 $O(n)$ 项，递归层数约为 $\log_2 n$，故总时间 $O(n\log n)$；常规数组实现的辅助缓冲为 $O(n)$。

反例是相等时一律从右边取：数值仍有序，却颠倒跨左右半区的相等记录，稳定性消失。归并的稳定与最坏界很可靠，但 `O(n)` 临时空间可能增加峰值内存和内存带宽压力；大对象还应比较“移动对象”还是“移动索引/引用”的所有权与缓存代价。

## 7. 堆排序：用结构换取最坏界和常量空间

二叉最大堆满足：每个父节点不小于其子节点，所以根是当前最大元素。对下标 `i`（从 0 开始），子节点索引为 `2i+1`、`2i+2`；`SIFT_DOWN` 只要把较小的父换到较大孩子下方，就会恢复堆不变量。

```text
HEAPSORT(A):
    build_max_heap(A)
    for end from length(A) - 1 down to 1:
        swap A[0], A[end]              // 当前最大值就位
        sift_down(A, root=0, end)      // 堆范围为 [0, end)

BUILD_MAX_HEAP(A):
    for i from parent_of_last_element down to 0:
        sift_down(A, i, length(A))
```

从最后一个非叶结点向上建堆是 $O(n)$，不是 $O(n\log n)$：高度为 $h$ 的结点数量随高度增大指数减少，所有下沉距离的级数总和受常数倍 `n` 限制。之后执行 `n-1` 次、每次 $O(\log n)$ 的取最大/恢复，合计 $O(n\log n)$。

堆排序原地且最坏 `O(n log n)`，但通常不稳定：交换根与末端能改变相等键的相对顺序。堆的跳跃访问也可能不如顺序归并友好；“不分配大缓冲区”不等于端到端一定快。

## 8. 计数排序：范围参数就是成本的一部分

若整数键范围为 `0..k`，先统计频次再按键输出：

```text
COUNTING_SORT(keys, k):
    count[0..k] = 0
    for each x in keys:
        count[x] += 1
    output = empty sequence
    for value from 0 to k:
        repeat count[value] times:
            append value to output
    return output
```

该简化版正确地排序键，但若记录附带 payload，直接按计数重建通常不能保持相等记录原次序。稳定版要把 `count` 变为累积结束位置，并从输入右向左写入输出；其空间通常包含 `O(k)` 计数和 `O(n)` 输出。

**范围反例。** 只有 100 个 ID，却可能落在 `0..10^12`；`O(n+k)` 中的 `k` 使计数数组不可行。负数、稀疏键、内存上限和键验证也都需要显式处理。对字符串、浮点、复合对象，不应假装存在一个安全的小整数范围。

## 9. 多轮排序与并行的边界

- 稳定排序允许先按次要键排、再按主要键排；第二轮稳定性保留第一轮的次要键顺序。若第二轮不稳定，这个技巧失效。
- 并行排序会引入分块、局部排序、归并/重分布、负载不均和同步成本。`p` 个核不是自动把时间除以 `p`；端到端限制见 [[计算机知识/30-计算机系统/05-并发并行SIMD与加速器|并发、并行、SIMD 与加速器]]。
- 若排序是 RAG 检索的重排步骤，分数相同的 tie-break、索引版本、权限过滤与结果可复现性都应记录；高分候选不是事实或授权证据。见 [[AI/20-LLM/70-工程应用与工具链/02-Embedding-Chunking与最小RAG#评测应分离检索与生成|RAG 检索评测边界]]。

## 练习

1. 对 `[(甲,2),(乙,1),(丙,2)]` 写出一个稳定和一个不稳定的合法键序输出，并解释各自是否违反“有序性”。
2. 说明比较决策树为什么有 $\Omega(n\log n)$ 最坏下界；再说明计数排序为何不违反它。
3. 对 `[1,2,3,4,5]` 使用“首元素为 pivot”的快速排序，列出子问题大小并求比较数量的量级。
4. 让两段已排序记录 `[(A,2)]` 与 `[(C,2)]` 合并。分别在“相等取左”和“相等取右”时写输出，验证稳定性差异。
5. 给出一个 `n` 很小而 `k` 极大的整数键例子，说明为什么不选计数排序；再给出一个 `k=255` 的适用场景。

## 成功标准

- 你能分别检验有序性、排列性与稳定性，而不是只看输出数字；
- 你能说清比较排序下界的条件，并把 `k` 写进计数排序成本；
- 你能用分区/合并/堆不变量解释快速、归并、堆排序的正确性；
- 你能给出快速排序退化、归并稳定性失效、计数范围爆炸三个反例；
- 你能按数据、内存、最坏情况、稳定性和端到端代价说明一次选择。
