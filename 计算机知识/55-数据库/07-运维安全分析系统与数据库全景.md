# 数据库：运维、安全、分析系统与完整知识地图

> 阅读定位：关系理论通用；实现示例区分 SQLite 与 PostgreSQL 17。返回 [[计算机知识/00-开始/课程地图/10-数据库-课程地图|数据库 · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## 数据库上线是一套运行协议

连接池要有容量上限和等待超时，不是越大越快；过多活跃查询会争夺 CPU、内存和 I/O。慢查询分析应结合执行计划、锁等待、事务长度、缓存和工作负载。为每个连接设置合理事务边界，避免“忘记提交”的会话长期占用资源或妨碍版本回收。

迁移需要考虑兼容窗口：旧程序和新程序可能同时运行。先扩展可兼容结构，再迁移数据与调用方，最后删除旧结构，往往比一次破坏性修改更可控。DDL 是否阻塞、是否重写表和能否在线完成必须查具体产品及版本。

## 安全与恢复不应排在最后

使用最小权限账号、参数化查询、秘密分离、适当传输与存储保护，以及可审计的变更。备份要考虑恢复点目标 RPO 与恢复时间目标 RTO，并实际验证恢复后的约束与业务可用性。复制不是备份，误删可能也被迅速复制。

删除数据还涉及备份保留、日志、缓存和法定要求，不能把一条 DELETE 当成所有副本立即清除。涉及真实合规问题时应另行核对适用规则，本课程不提供法律结论。

## 不同数据系统解决不同访问模式

OLTP 关注短事务和在线更新，OLAP 关注大规模扫描与聚合。行存常适合整行访问，列存可减少读取不需要的列，并利用编码压缩与向量化执行。星型模型、事实表、维度表、物化视图和增量维护服务分析工作负载。

键值库、文档库、宽列系统、图数据库、时序系统、全文检索、向量检索各有数据模型与一致性边界。“NoSQL”不是一个统一模型，也不等于没有事务。嵌入式 SQLite 与服务端 PostgreSQL 在部署、并发和运维模型上不同，不能只按 SQL 语法相似度选择。

## 至少提及的进阶主题

查询代数、代价优化、分区裁剪、索引合并、递归查询、触发器、存储过程、视图、物化视图、游标、约束延迟检查、CDC、流处理、事件时间、迟到数据、水位线、数据血缘和模式演进都属于数据库知识版图。时态数据库、空间数据、多租户隔离和隐私保护则把领域约束带入设计。

## 综合验收

完成一个有客户、订单、支付和幂等请求记录的小库，写查询、约束和事务；构造重复请求、连接中断、锁冲突和恢复场景；记录哪些结论来自 SQLite 本地测试，哪些需要 PostgreSQL 双会话或真实故障实验。教学脚本不替代生产恢复验证。
