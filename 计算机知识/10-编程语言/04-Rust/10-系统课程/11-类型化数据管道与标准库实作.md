## 先确定对象，而不是先背语法

我们收到 ADC 的原码 `[2,4,6,8]`。本教学标定为每码 `1 mV`、偏置 `0 mV`，采样间隔 `1 s`；码值必须在 `0..=4095`，一次输入最多 1024 项。这是假定的数字输入与标定，没有连接 ADC 硬件，也没有测量噪声、漂移或时间戳抖动。

第 n 项从 n=0 开始，教学相对时间是 `t[n]=n×1 s`；电压为 `v[n]=code[n]×1 mV/码`。求和是 `2+4+6+8=20 mV`，算术均值 `20/4=5 mV`。和的单位仍是 mV；若要近似时间积分，必须再乘采样时间，并解释积分公式及端点。我们将 `<4 mV` 分为 Low，`4..=6 mV` 分为 Normal，`>6 mV` 分为 High；这是教学分类规则。

预测：输入 4095 合法；4096 不合法；没有输入时和是 0，均值未定义。`0 mV` 是合法观测，不能兼任“缺失”或“错误”。

## 阶段 0：在空目录里运行第一个 Cargo 程序

已有 Rust/Cargo 时，在自己选定的空工作目录执行：

```sh
cargo new --edition 2021 --vcs none first-measurement
cd first-measurement
cargo run
```

Cargo 创建 `Cargo.toml` 和 `src/main.rs`。打开 manifest，确认 `edition = "2021"`。把 `src/main.rs` 替换为下面的完整程序；本库保留相同源码的可运行检查点 `stages/first`。不要把多个 `main` 依次追加到一个文件。

<!-- code-sync: 计算机知识/80-实践/10-Rust/01-类型化测量任务/stages/first/src/main.rs -->
```rust
#[derive(Debug, PartialEq)]
enum Level {
    Low,
    Normal,
    High,
}
fn classify(code: i32) -> Result<Level, &'static str> {
    if !(0..=4095).contains(&code) {
        return Err("code outside 0..4095");
    }
    Ok(match code {
        0..=3 => Level::Low,
        4..=6 => Level::Normal,
        _ => Level::High,
    })
}
fn main() {
    let codes = [2, 4, 6, 8];
    let mut sum = 0;
    for code in codes {
        match classify(code) {
            Ok(level) => {
                println!("{code}: {level:?}");
                sum += code;
            }
            Err(error) => println!("{code}: {error}"),
        }
    }
    let result = (sum, f64::from(sum) / codes.len() as f64);
    println!("sum={} mean={}", result.0, result.1);
}
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn boundaries() {
        assert_eq!(classify(3), Ok(Level::Low));
        assert_eq!(classify(4), Ok(Level::Normal));
        assert_eq!(classify(6), Ok(Level::Normal));
        assert_eq!(classify(7), Ok(Level::High));
        assert!(classify(-1).is_err());
        assert!(classify(4096).is_err());
    }
}
```

保存后运行 `cargo run` 和 `cargo test`。预期分类依次 Low、Normal、Normal、High，最后 `sum=20 mean=5`。从实践工程目录也可用 `cargo run --manifest-path stages/first/Cargo.toml --locked` 与 `cargo test --manifest-path stages/first/Cargo.toml --locked` 重跑已保存检查点。

逐行读：`let codes = [...]` 创建四项数组；每项是 i32，数组长度属于类型。`let mut sum` 允许累计，`for` 按顺序访问。这里 i32 数组实现 Copy，按值循环没有让后面的 `codes.len()` 失效；换成拥有 String 的数组时要重新分析所有权。函数参数 `code: i32` 固定输入类型，`Result<Level, &'static str>` 说明成功给枚举，失败给固定文本。`if` 拦住范围错误，`match` 选择互斥分类；`Ok(match ...)` 的内层没有末尾分号，因为它要产生 Level 值。`(sum, mean)` 是元组，`.0/.1` 取不同类型的分量。字符串字面量是借用文本；`println!` 是格式化宏。

**两个可解释的错误**：把 `classify(4)` 改成 `classify("4")`，编译器拒绝字符串与整数的类型错配；这发生在运行前。另在检查点 `main` 中临时写 `panic!("intentional checkpoint panic")`，程序运行时终止；panic 不等于可恢复的 Result。它们是学习实验，完成后恢复原文件。固定四项和最多 16380，i32 足够；这个证明只覆盖本检查点，不覆盖无限长任意数据。

练习：改输入为 `[3,4,6,7]`，不看程序预测分类。答案为 Low、Normal、Normal、High，和20，均值5。将 7 改为 -1 时，分类函数返回 Err，循环只报告错误并跳过累计；若仍按全部数组长度求均值，会产生错误的统计。下一阶段采用“任一项非法则整批拒绝”，明确消除这种含混。

基础机制回到 [[计算机知识/10-编程语言/04-Rust/01-语法数据建模与Cargo#Cargo 与模块|package、crate 与模块]]，再回本页解释哪个文件实际被 Cargo 编译。

## 阶段 1：让类型区分码、电压和索引

检查点中一个整数可能同时充当码和 mV。现在进入实践工程根的 [src/lib.rs](../../../80-实践/10-Rust/01-类型化测量任务/src/lib.rs)：

- `AdcCode(u16)` 私有字段，公开的 `TryFrom<u16>` 验证 `0..=4095`；调用者不能靠 `AdcCode(5000)` 绕过范围。
- `Millivolt(u16)` 私有字段，`From<AdcCode>` 表示本标定的无失败转换。这条转换只属于 `1 mV/码、零偏置` 模型；真实标定改变时应改变模型及 API，不能只改打印单位。
- `SampleIndex(u16)` 表示零基序号，`Record { index, voltage }` 表示同时存在的信息。index 由 Batch 的受限长度生成，最大1023，是批内序号；主CLI只解析单批时它对应从0秒开始的相对时间。
- `InputError` 枚举区分 Syntax、Range、TooMany；`Result<Batch, InputError>` 防止成功与失败同时存在。

这里选 u16 并不是因为所有中间计算都该用 u16。转换前外部文本可能超长、非整数或数值太大；`parse_codes` 对非 ASCII 数字、符号、空白和超 u16 文本归 Syntax，解析成功但超过4095才归 Range。`65536` 因不能解析为 u16，按本合同归 Syntax；如果产品希望独立报告“数值超表示范围”，应再分一个变体，不能把现行错误分类说成语言定律。错误带从1开始的位置，`AdcCode::try_from` 单值转换没有文本位置时用0。

在工程根运行：

```sh
cargo run --locked
cargo run --locked -- --codes 0 4095
cargo run --locked -- --codes 2 4096
cargo run --locked -- --codes
cargo test --locked
```

固定数据报告 sum=20、mean=5.000，非法数据在 stderr 报 `sample 2: code 4096 outside 0..4095`，退出2且没有成功报告；空输入报告和0、均值 undefined。类型错误、运行范围错误、数值正确、退出码是四项不同的观察。

## 谁有数据，谁只是看一眼

`parse_codes` 可临时借用 token 的 `&str`，但只保存转换后的数字。返回的 Batch 拥有 `Vec<Record>`，没有把输入文本的生命周期带到返回值里。失败发生时，尚未提交的局部 Batch 被 Drop，调用方只得到错误；已经存在的别的 Batch 不受影响。

```mermaid
flowchart LR
    T[输入文本的拥有者] -->|短期借用 AsRef str| P[parse_codes]
    P -->|成功返回拥有值| B[Batch 拥有 Vec Record]
    B -->|records 共享借用| S[summary 临时观察]
    B -->|into_records 消费 self| V[新拥有者 Vec Record]
```

`batch.records()` 的返回签名是 `&[Record]`，借用期与 `&self` 关联，不能在还要用 view 时调用 `push_code(&mut self, ...)`。源码的 compile-fail 文档测试保留这一冲突，正常集成测试则先最后使用 view，再修改 batch；不靠 `'static` 或大量 clone 绕开。

`into_records(self)` 按值消费 Batch，原变量随后不可用。`Record` 只含可复制数值，因此 Copy/Clone 合理；`records().to_vec()` 明确分配另一个记录数组，允许它脱离原 Batch。Batch 本身不实现 Clone，避免不加思考地复制整个任务。`&mut Batch` 临时交出独占修改能力，`push_code` 先查长度再 push，满批失败时旧数据不变。成功 push 可能扩容，因此旧切片不能跨这一修改继续使用。

在 [[计算机知识/10-编程语言/04-Rust/10-系统课程/09-借用检查中的量词方差与重借用#先把生命周期看成使用范围约束|生命周期关系]] 中读完签名，再回到 `records(&self) -> &[Record]` 解释：结果借用的是 Batch，既不是配置文本，也不是局部临时 Vec。需要长期拥有的结果则用 `into_records`。

## 统计、累加与空输入各有什么合同

`summarize(&[Record]) -> Result<Summary, InputError>` 先验证切片长度不超过1024；即使调用者从公开 Record 复制出更长切片，也会拒绝。每项最大4095，故和最多 `1024×4095=4,193,280 mV`，代码用 u64 累加，范围证明覆盖所有成功输入。不能仅凭“用了更宽整数”断言任意长度都安全。

`mean_mv: Option<f64>` 对非空输入给浮点均值，对空输入给 None。整数总和精确；任意均值未必能用二进制浮点精确表示。打印三位小数是输出精度规则，不是测量精度声明。固定均值5可以精确表示。

练习：已满1024项时，再 `push_code` 一项，哪些对象变化？答案：Error 返回；旧 Vec 长度、记录和统计不变。若换成“先写文件，再检查下一项”，Result 错误就不能撤销已写字节；下一讲专门验证这个差异。

## 跨批状态为什么比借用检查多一层

两点移动平均为 `y[n]=(v[n]+v[n-1])/2`，初始前值 `v[-1]=0 mV`。手算每项得到 `[1,3,5,7] mV`。`Fir2` 拥有 previous，step 用 `&mut self` 更新；一项最大4095，所以两项和最大8190，u16足够。输出 `HalfMillivolt` 内部保存两倍 mV 的整数，输入1时准确表示0.5 mV，避免整数除法悄悄截断。

把输入分为 `[2,4]` 与 `[6,8]`，必须由同一个 Fir2 连续处理；若第二批另建 `Fir2::default()`，就把前值4错误重置为0，得到 `[1,3,3,7]`。两种程序都内存安全，也都可能编译通过；算法初始条件和所有权状态必须一起正确。

数学推演复用 [[信号与系统/20-数字信号处理/01-FIR滤波设计与频率规格#手算核与迁移验收|FIR 手算核]]，返回本页定位 previous 的拥有者。本实现每输入一项输出一项，EOF 不排空；若另加输入0排空，尾值4 mV属于另一个协议，不能默默加到本输出里。

迁移题：撤去实现提示，把4项分成三批 `[2]、[4,6]、[8]`，说明怎样保持结果不变。答案：三批维持顺序，一个处理器活过三次 process，批数据可被消费，previous 在批间不销毁。注意每次 parse_codes 的批内 SampleIndex 会从0重新开始；Fir2::process 输出不携带索引，只验证有序电压的跨批计算。第12讲同步API通过消费同一Batch后切分保留全局序号，并拒绝独立parse导致的序号重启；它仍未核验设备真实时间戳。测试已遍历所有单个切分位置（包括空首批/空尾批）；任意多批正确性来自按项保持相同 previous 的归纳，不以五个测试代替无限案例证明。
