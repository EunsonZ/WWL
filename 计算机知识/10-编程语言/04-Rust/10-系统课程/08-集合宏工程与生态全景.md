# Rust 的课程闭环：集合、宏、no_std 与可维护项目

> **学习位置**：[[计算机知识/00-开始/课程地图/03-Rust-课程地图|Rust课程地图]] · **适用边界**：Rust 2021 edition 兼容示例；2024 edition 差异另行标识。

## 集合按查询需求选择

Vec 连续存储，适合遍历与随机访问；VecDeque 适合双端队列；HashMap/HashSet 依赖哈希与相等契约；BTreeMap/BTreeSet 提供有序遍历与范围查询。BinaryHeap 提供堆序，不保证整个迭代顺序是完全排序。

选择键类型时同时检查 Eq 与 Hash 一致性、是否需要确定输出顺序以及攻击输入风险。把哈希容器迭代结果直接写进快照测试，可能因为不保证顺序而脆弱；需要确定结果时先排序或选择有序容器。

`Entry` API 让“查找并可能插入”在一个明确访问路径里完成，减少重复查找与借用冲突。容量预留可以减少扩容，但输入长度来自外部时仍需设上限，不能让优化成为无界分配入口。

## `Cow` 与 arena 表达不同生命周期策略

`Cow<'a,T>` 在不需修改时借用，在需要时获得拥有副本，适合大多数输入无需改变的规范化流程。它不是所有字符串 API 都该加的一层包装：调用者最终总需要拥有结果时，直接返回 String 可能更直白。

arena 把一组对象的生命期绑定到区域，减少逐对象回收开销，常用于编译器 AST 或请求级数据。跨区域保存引用、区域释放后继续使用，以及某些 arena 是否执行元素析构，都要查具体实现合同。

## 声明式宏和过程宏

`macro_rules!` 根据 token 模式展开语法，适合消除结构性重复；它不是运行时反射。过程宏在编译期处理 token 流，可实现 derive、属性或函数式宏，但需要额外编译和信任边界。

优先用函数、泛型和 trait 表达语义；只有确实需要操作语法形状时再用宏。宏错误信息、卫生性、求值次数、展开后的所有权和可读性都应纳入审计。

## 标准库的系统能力

文件与路径、Read/Write、BufRead/BufWriter、进程、环境、时间、网络、同步和集合构成日常系统编程底座。Path 不等于 UTF-8 String，操作系统路径可能包含非 Unicode 编码；强行 `to_str().unwrap()` 会把平台合法路径变成程序 panic。

`read` 和 `write` 可能只处理一部分，`read_exact`、`write_all` 在需要对应契约时更合适，但仍可能失败。缓冲写入需要显式关注 flush 与最终关闭/持久化；Drop 兜底不能替代可报告失败的提交阶段。

`Instant` 适合间隔测量，`SystemTime` 表达墙上时间，两者不能任意互换。随机性、加密、异步运行时、序列化和 Web 框架通常来自额外库，需要明确依赖而不是把生态功能归为语言内建。

## no_std 与嵌入式

`#![no_std]` 使用 core 而非完整 std；在提供分配能力时可按环境使用 alloc。它不自动表示完全无分配，也不自动表示实时或适用于任何芯片。启动、panic 处理、链接脚本、中断、外设寄存器和并发模型仍由目标环境决定。

类型安全可帮助表达寄存器状态和资源独占，但错误的 unsafe 驱动抽象仍可能破坏保证。DMA、缓存维护、MMIO 访问和中断上下文需要结合硬件及系统接口证明。

## 工程的可重复闭环

库把纯逻辑与 I/O 分开，二进制负责参数和错误呈现；公共 API 明确所有权、阻塞、线程与 panic 边界；CI 记录目标平台、工具链、edition、依赖锁和最小支持版本。格式检查、Clippy、单元/集成/文档测试服务于不同问题，不应互相替代。

语义版本承诺不仅是函数名不变，还包括 trait 实现、feature、错误行为与可观察语义。依赖升级后重新跑失败路径和资源测试，不能只看正常输出。

## 结课任务

实现有输入上限的配置解析与任务调度库：领域模型用 enum 表示互斥状态；解析返回分类错误；工作任务拥有数据；有界队列定义关闭；所有外部输入与资源操作可测试。高级分支再加入异步或 FFI，逐项写出新增前提。

验收时解释为什么没有到处 clone、为什么某些位置选择拥有而非借用、哪些错误可恢复、取消不能撤销哪些动作。能够提出这些边界问题，比“代码里没有 unsafe”更接近完整的系统工程能力。
