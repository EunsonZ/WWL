# HydraMedusa与认证控制验证

**先修关系：** [[计算机知识/Kali/03-Web与API安全/08-认证会话越权与API测试|认证会话越权与API测试]]；[[计算机知识/Kali/05-密码无线与专门领域/01-哈希口令KDF与估算|哈希口令KDF与估算]]；[[计算机知识/Kali/00-导航与方法/02-授权范围与风险分级|授权范围与风险分级]]。

## 在线认证和离线摘要是两种系统

Hydra、Medusa 是协议化的认证测试工具：将候选凭据交给真实服务，观察协议返回。与 [[计算机知识/Kali/05-密码无线与专门领域/02-HashcatJohn与离线审计|离线计算]] 不同，每次尝试都可能触发锁定、短信、告警、供应商计费或业务影响；即使只有一个成功结果，也不能从此推导用户密码质量的总体分布。工具的模块支持和失败判断取决于服务协议及版本。[^s1][^s2]

本页的首要任务不是“尽快试完密码”，而是回答：错误认证是否限速？冻结策略会否被滥用成拒绝服务？成功/失败的日志是否区分正确？相同响应是否泄露账户存在？为此必须准备专门测试账户、预先批准的最大尝试数、恢复办法和同步的服务日志。

## 协议模块在判断什么，认证系统又在判断什么

Hydra 等工具通过具体协议模块提交凭据并解析响应；支持协议名称，不代表自动理解所有站点的会话、二次验证和业务权限。官方上游说明的是模块能力与调用合同，而特定应用的成功条件必须用受控正反例校准。本页不增加批量猜测、绕过限流或真实账户测试。[^v5-hydra-upstream]

可以把服务端过程拆成凭据校验、风险判断、额外因子、会话签发和对象授权。某次响应表示密码被接受，却仍等待第二因子，不能记为“已取得完整会话”；取得会话后也不代表允许读取每个对象。反过来，已有会话 Cookie 可能让请求成功，而本次提交的密码根本未被验证。这是观测归属问题，不只是响应匹配字符串选择不佳。

## 用有限状态表校准成功与失败判定

为一个专用账户预先定义状态：可正常认证、错误凭据被拒、进入额外验证、被策略冻结、服务暂时不可用。工具看到的一个返回字符串必须映射到其中哪一项，而不能只分“成功/失败”。例如正确密码后出现 MFA 挑战，支持第一因素通过，不支持已建立完整登录会话。[^v2-authcheat]

正对照只用一条已知正确公开教学凭据；负对照只用一条已知错误凭据并低于负责人指定阈值。没有服务端日志和恢复安排时，不通过不断增加次数来“发现”锁定策略。本包原命令是单凭据校准，不是默认开展口令猜测。

## 单账户单凭据的可控检查

本包没有 SSH 服务，也没有测试账户。下面仅用于你另行建立的、隔离虚拟机中的回环 SSH 服务；不应在生产账户上试用。`PublicToy-Only-42` 是公开的虚构口令，不可用于真实系统。

```bash
hydra -h
hydra -U ssh
# 仅在专用靶机本机运行；需要先实际创建 lab_auth_test 测试账户。
# 一名用户、一条已知测试口令、一个并发任务：
hydra -l lab_auth_test -p 'PublicToy-Only-42' -t 1 -f \
  ssh://127.0.0.1
```

这不是“从未知口令恢复访问”的练习，而是校准该模块对一次预期认证的判定。如果服务不支持当前协商算法，应修正实验兼容性或停止；不要全局降低真实服务的密码学策略。Medusa 的对应模块先用 `medusa -d` 列出，`medusa -M ssh -q` 查看帮助；参数不应从 Hydra 逐字套用。

## 限流是状态随时间变化，不是一个固定错误码

认证控制可能按账户、来源、时间窗口和失败状态共同决定结果。OWASP 将锁定阈值、观察窗口与锁定时长分别讨论，并指出安全与可用性之间要平衡。仅按来源聚合与按账户聚合回答的问题不同，但增加维度也不自动保证没有误伤。[^v5-auth-throttle]

原创理论模型：状态 $s$ 包含某账户在窗口内的失败次数与锁定截止时间，事件 $e$ 包含一次凭据校验结果及其时间；系统按 $s'=F(s,e)$ 更新状态。连续两次完全相同的请求可能因为 $s$ 已变而得到不同结果。这里无需发送任何请求，就能看出“所有重试都是独立同分布样本”的假设通常不合适。

需要解释的不是“第几次看到拒绝字符串”，而是哪个计数器变化、什么事件会清零、第二因子与恢复流程是否共享政策、合法用户如何恢复，以及客户端重试是否被服务端计为额外尝试。将这些条件与 [[计算机知识/Kali/03-Web与API安全/08-认证会话越权与API测试|会话状态]] 和 [[计算机知识/Kali/05-密码无线与专门领域/02-HashcatJohn与离线审计|离线候选计算]] 比较，才能理解为何在线吞吐不能由离线每秒哈希数直接推算。

## 限流指标要有明确分母与时间窗

每账户、每来源、每设备或全局限流保护的对象不同。共享 NAT 下许多合法用户可能共用来源地址；仅按来源处罚会有误伤。验证时分开记录请求发出数、抵达认证组件数、实际密码验证数、挑战数与最终会话数；反向代理拒绝的请求不一定进入后端 KDF。

重试、连接握手和业务冷却会影响真实速率。一个并发线程不等于恒定每秒一次；观察窗口不足也可能遗漏延迟锁定。计数必须能与日志对应，不用工具进度条代替服务器实际处理数。

## 设计一个能解释的验证，而不是无止境循环

在测试计划中先写“已知正确一次、已知错误一次、若批准则有限次错误”，并把具体次数设为**低于预定锁定阈值**。锁定策略本身的测试需另立窗口和可恢复账户，不能用碰锁来发现阈值。请求级速率还受握手、重连、协议交互影响，`-t 1` 只限制并发，不是严格的每秒次数保证。

服务器端对照认证日志，区分“协议握手失败”“密码被拒”“账户锁定”“网络超时”。对 Web 表单，仅凭响应含有一个字符串可能误判：CSRF token、重定向、统一错误页、多因素挑战都会改变逻辑。先用 [[计算机知识/Kali/03-Web与API安全/03-BurpSuite工作流|Repeater]] 逐次手工理解状态机，不把复杂登录页面变成盲目自动尝试。

## 恢复渠道是同一身份系统的一部分

密码重置、邮箱变更、设备绑定、备用码与客服恢复可能改变同一账户的安全状态。评估范围应明确哪些渠道被纳入，不能从主登录启用了 MFA 推出恢复流程同样可靠。

相关操作涉及真实用户通知和状态改变时另行安排；本包只使用状态机和合成数据讨论。演练后的验收包含账户恢复、测试会话撤销与无意通知的处置记录，而不只是停止客户端进程。

## 防御与报告

报告中记录测试账户类别、计数、时间范围、客户端/服务器时钟偏差、停止原因、是否影响其他会话；真实口令不进入报告。比较按账户、按来源及设备上下文的速率控制，评估共享 NAT 误伤、分布式来源以及找回密码接口；多因素认证并不能自动保护所有恢复路径。

> [!warning] 明确停止条件
> 意外锁定、真实用户受影响、服务健康下降或范围变化时立即停止并通知负责人。授权不是一次签字后无限尝试的许可。

> [!question] 自检
> 工具显示“成功”，但应用接着要求第二因素，是否已完成登录？没有。结果只支持已通过某个认证步骤，结论必须标明边界，并与 [[计算机知识/Kali/03-Web与API安全/08-认证会话越权与API测试|会话与授权]] 区分。
