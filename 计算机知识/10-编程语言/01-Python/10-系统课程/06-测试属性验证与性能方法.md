# 测试、属性验证与性能方法：把结论变成可反驳的实验

> **学习位置**：[[计算机知识/00-开始/课程地图/04-Python-课程地图|Python课程地图]] · **适用边界**：Python 3.11+；CPython 实现细节明确注明。

## 从规格生成测试，而不是从实现抄答案

若解析器承诺接受十进制非负整数、拒绝布尔值与空串，测试应围绕这份合同展开：正常值、上下界、前后空白、符号、Unicode 数字、过长输入、`True` 和嵌套对象。实现中出现的每一个分支都被覆盖，并不意味着合同里的每一个条件都被测试。

例如读数分类器先拒绝平层 `True`，不等于拒绝 `{'value': True}`。模式 `int(value)` 也会接受布尔值，所以应在嵌套分支中明确排除。这是“覆盖了拒绝分支，但遗漏了同一错误类型的另一条数据路径”的典型反例。

## 建立三种彼此独立的证据

例子测试检查已知输入；性质测试检查大量输入都应满足的关系；差分测试把优化实现与简单参考实现比较。排序可以检查非降序与多重集合不变，但这两个条件都要有：仅检查有序会让“返回空列表”的错误实现过关。编解码可检查 `decode(encode(x)) == x`，同时还要测试解码器拒绝非规范或恶意输入，因为往返性质只覆盖编码器能产生的输入。

```python
from collections import Counter
from random import Random

rng = Random(20260906)
for _ in range(300):
    xs = [rng.randrange(-5, 6) for _ in range(rng.randrange(30))]
    ys = sorted(xs)
    assert all(a <= b for a, b in zip(ys, ys[1:]))
    assert Counter(xs) == Counter(ys)
```

这里标准排序只是演示测试协议；真正测试自写算法时把 `sorted(xs)` 换成待测函数，并用独立参考结果对照。固定随机种子使失败可复现，但一个种子不是所有输入。记录并缩小失败样本，往往比盲目增加循环次数更有效。

## Mock 应替代边界，而不是替代被测逻辑

把时钟、网络客户端、随机源作为可注入依赖，可以测试超时与重试。不要把内部函数全 mock 掉后只断言“调用了三次”，否则真正错误的计算路径从未运行。使用临时目录、内存数据库和本地回环网络可以构造成本适中的集成测试。

异常测试应校验异常类型和关键语义；不要依赖会随环境变化的完整报错字符串。清理过程也要测试：文件是否关闭、临时文件是否移除、事务是否回滚。测试自身不能依赖执行顺序、真实网络或本机用户家目录。

## 性能证据必须有比较对象

先用剖析器找热点，再对代表性输入做基准。一次微秒级结果可能主要测到计时噪声、缓存热身和解释器状态。记录 Python 实现及版本、输入分布、是否含初始化与 I/O，并给出重复结果的中位数和波动。`timeit` 的默认垃圾回收设置可能使结果偏离真实工作负载，应说明实验条件。

`tracemalloc` 适合跟踪 Python 分配，不等于进程全部常驻内存；C 扩展、内存映射和分配器保留空间需要其他观察工具。复杂度预测与实测应互相验证：若输入翻倍，线性实现理想增长约两倍，平方实现约四倍，但小样本和缓存边界可能偏离。

## 练习与答案

写一个故意只返回第一个元素的“排序器”，找出哪条性质能抓住它。再把读数分类器的嵌套布尔检查删除，回归测试必须失败，这叫变异检验：它验证测试是否真的能区分正确与已知错误。最后为日志解析器报告吞吐量、峰值内存、拒绝记录比例，而不是只写“很快”。
