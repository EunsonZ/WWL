# 数据污染、评测泄漏与训练治理

<!-- deep-review-02 -->
> [!tip] 本轮深化：从当前概念继续追问

## 本课目标

- 区分训练数据污染、评测泄漏、一般数据泄漏、记忆与 benchmark overfitting；
- 识别 exact、near-duplicate、切片、改写、翻译和流程层泄漏；
- 用“先冻结评测，再排除训练重叠”的流程建立可审计切分；
- 解释哈希、MinHash/LSH、相似度检索与人工复核的证据边界；
- 建立从来源、许可、访问、版本、删除到事件响应的训练数据治理链；
- 在报告中区分“发现污染”“未检出污染”和“无法排除污染”。

## 数学先修（第一次使用）

评测是有限样本估计，指标本身有不确定性与选择偏差。首次使用这些概念前，阅读 [[数学/30-概率与统计/05-统计估计置信度与模型评测|统计估计、置信度与模型评测]]。若用 NLL/PPL 比较训练与验证，定义见 [[数学/30-概率与统计/03-似然负对数似然与困惑度|似然、负对数似然与困惑度]]。

本页不复制统计推导，重点是信息怎样越过训练—开发—测试边界。

## 直觉：考试答案不只会“整页掉进课本”

最明显的污染是训练集中出现测试题和答案原文。但泄漏也可能发生在：

- 同一道题被改了空格、标题、变量名或语言；
- 一个长文档被切片后分别落入 train 和 test；
- 团队反复查看 test 错题，逐项修改 prompt、模板、数据和超参数；
- benchmark 名称、答案规则或隐藏标签进入 SFT 数据；
- 先在完整数据上训练 tokenizer、归一化阈值或特征，再宣布 test “没参与训练”；
- 评测服务把测试输入/输出写入日志，随后日志又被下一轮训练收集。

所以污染扫描不只是跑一次字符串匹配，而是保护一条信息隔离链。

## 精确定义

- **训练数据污染（training-data contamination）**：本应独立用于评测的内容、答案或高度相关派生物进入训练/微调数据，使评测不再测量预期的未见样本泛化。
- **评测泄漏（evaluation leakage）**：测试/benchmark 的输入、标签、评分逻辑或反复反馈影响模型、prompt、模板、数据选择、超参数或人工决策；它比“文本进入训练集”更宽。
- **数据泄漏（data leakage）**：训练时使用了部署/预测时不可获得、却与目标相关的信息；例如用未来时间字段预测过去或把同一用户的后续记录放进训练。
- **记忆（memorization）**：模型对训练实例或片段产生高保真复现倾向。记忆可在没有 benchmark 污染时发生；污染也不一定能通过一次复述测试被观察到。
- **benchmark overfitting**：团队或生态反复针对一个 benchmark 做决策，即使其原文未直接进入梯度，结果也只适用于该 benchmark 的可能性越来越高。
- **去重**：减少语料内部重复；**去污染**：针对受保护评测集合排除信息重叠。两者目标不同。
- **provenance（来源链）**：从最终训练样本追溯到原始来源、获取条件、变换、版本和处置的证据。
- **lineage（加工血缘）**：原始、清洗、切分、tokenized、packed、checkpoint 与最终模型之间的可追踪变换关系。
- **治理（governance）**：规定谁可收集、查看、修改、训练、评测、导出、保留、删除和响应事件的生命周期控制，而不只是一张许可表。

## 污染与泄漏的层次

| 层次 | 例子 | 为什么 exact hash 不够 |
| --- | --- | --- |
| 字节级 exact | 完全相同文件 | 解压、换行、编码变化会改变字节 |
| 规范化 exact | 只改空白/Unicode 表示 | 标题、模板、注释仍可改变 |
| 近重复 | 插入广告、重排段落、变量改名 | 整文档相似度可能被局部改动稀释 |
| 子串/切片 | test 段落嵌在更长训练文档 | 文档级 hash 完全不同 |
| 语义改写/翻译 | 同一题意换说法或语言 | token/字符串重叠可能很低 |
| 标签泄漏 | 训练文本含答案、评分 rubric 或隐藏字段 | 只扫问题原文会漏掉 |
| 流程泄漏 | 多次查看 test 并针对失败修改系统 | 文本可能从未进入训练文件 |
| 时间/实体泄漏 | 同用户、仓库、事件跨 split | 随机按行切分掩盖关联 |

没有单个工具能覆盖所有层次。治理要把自动候选发现、规则、人工复核与过程隔离组合起来。

## 先定义受保护评测集合

### 评测登记表

在任何训练收集/切分前，为每个 evaluation asset 记录：

- evaluation ID、版本、来源、许可和允许的使用方式；
- 输入、标签/参考答案、评分代码、rubric 的保密级别；
- split unit：文档、作者、对话、用户、仓库、时间或事件；
- canonicalization 和 fingerprint 版本；
- 谁可访问 test 输入、标签与逐样本结果；
- 模型/团队可以查询多少次，哪些结果只给聚合指标；
- 何时退役、轮换或建立新的 holdout；
- 发现泄漏后的隔离、重训、撤回结论和通知流程。

公开 benchmark 也应登记。公开不代表它没有进入预训练，也不代表可无限次用来调参后仍称“未见测试”。

### dev、test 与 shadow holdout

- **train**：允许参数更新；
- **dev/validation**：允许有限的模型选择、early stopping 和超参数决策；
- **test**：只在方法冻结后少量使用；
- **shadow holdout**：更严格隔离，用于确认长期 benchmark overfitting 或上线前复核。

test 被反复用于决策后，实际上承担了 dev 的角色。正确做法是承认角色变化并建立新的独立 holdout，而不是继续沿用“测试集”名称。

## 去污染的完整流程

### 1. 原始身份与分组

给每份原始文档稳定 ID，保留来源、时间、作者/仓库/对话等分组键。先按可能共享信息的最大合理单位分组，再切 split。若先切成段落再随机分组，同一文档必然容易跨界。

### 2. 多层 fingerprint

至少维护：

- 原始字节哈希；
- 经过保守 canonicalization 的文档哈希；
- 句段或固定窗口的哈希/指纹；
- shingle 集合的 MinHash/LSH 候选索引；
- 可选的语义向量候选，必须记录模型、版本、阈值和隐私边界。

canonicalization 只能做已经证明不改变任务身份的变换。去掉所有数字、变量名或标点可能把不同数学题/代码判为同一条，也可能掩盖答案差异。

### 3. 先排 exact，再生成 near-duplicate 候选

exact 哈希能线性扫描大量文本；近重复若朴素比较 $N$ 个训练文档与 $M$ 个评测文档，需要 $NM$ 对比较，很快不可行。候选索引用额外内存和近似误差换取更少比较；只应把它当候选生成器。

### 4. 复核与分级处置

每个候选记录：匹配层级、相似片段、来源关系、是否含答案、split、审阅者、结论和理由。处置不是只有 delete：

- **confirmed contamination**：从训练集合排除并重新构建受影响产物；
- **related but legitimate**：保留，但说明评测独立性限制；
- **ambiguous**：隔离，不进入主训练，等待进一步复核；
- **false positive**：保留，记录为何不同，帮助校准阈值。

不要静默删除命中项；否则无法估计污染规模、偏差和受影响模型。

### 5. 训练后再做行为审计

训练前扫描找数据重叠，训练后可用 canary/受控复述、成员推断候选或异常置信度分析寻找记忆迹象。但行为未复述不证明训练数据无污染；能够复述也可能来自公开常识或非评测来源，需要结合 provenance。

## 扫描的成本与证据模型

设训练集合 $N$ 个文档、评测集合 $M$ 个文档、总字节数 $B$：

- 原始/规范化 exact hashing 通常可按 $O(B)$ 扫描，并用哈希索引近似常数查找；
- 朴素文档两两比较是 $O(NM)$，大集合不可接受；
- LSH/倒排索引/ANN 降低候选数，但增加索引构建、内存与 false negative；
- 段落/窗口粒度越细，候选数和计算越多，却更容易发现嵌入长文档的测试片段；
- 语义模型本身可能有隐私、许可、语言偏差和版本漂移，不能替代人工证据。

阈值选择有两种主要代价：

- 阈值过松：假阳性多，人工复核成本高，合法数据被大量隔离；
- 阈值过严：假阴性多，改写、翻译和局部复制漏检。

报告至少包含扫描层级、规范化规则、阈值、候选数、抽样策略、确认数、假阳性样本和未覆盖类型。只写“dedup complete”没有证据意义。

## 实际例子：10,000 篇训练文档与 500 道评测题

目标：建立一个领域模型评测，500 道题来自 50 个来源文档；训练候选有 10,000 篇。

### 错误做法

- 把全部文本打乱后按 90/10 随机行切分；
- 只对完整文件做哈希；
- 看到模型 95% 得分就直接报告；
- 测试失败后把对应题解释加入 SFT，再继续在同 500 题上报告“test 提升”。

### 可审计做法

1. 先按 50 个来源文档冻结 500 题、答案、rubric 和 source IDs；
2. 训练候选按文章/站点/作者/时间建立分组；
3. 对原始字节、保守规范化文档和滑动句段分别指纹；
4. exact 扫描发现 18 篇直接复制，进入 confirmed quarantine；
5. near-duplicate 候选 73 篇，人工复核确认其中 12 篇为带广告转载、9 篇为相关但不同问题、其余为假阳性；
6. 对语义改写/翻译做定向抽样，不宣称覆盖所有改写；
7. 从训练 manifest 排除 30 篇确认污染文档，重建 tokenizer/shards，并使旧产物不可再被主 run 引用；
8. 方法和阈值只用 dev 调整，500 题 test 只在冻结模型上使用一次；
9. 报告结果时写明 30 个确认污染、扫描范围、近似方法和“无法排除未检测语义改写”。

这里的数字是教学情景，不是工具性能或真实 benchmark 结论。关键是命中、处置、重建与限制都可追踪。

## Tokenizer、超参数和人类反馈也会泄漏

### tokenizer 泄漏

用 train+test 一起训练 tokenizer 会让词表和分词统计看见 test。它未必泄漏具体标签，但已破坏“所有数据驱动选择只看 train”的严格边界。正确做法是 train-only 拟合，再用固定 tokenizer 编码 dev/test。

### 预处理/阈值泄漏

在完整数据上选择长度阈值、质量分、语言过滤或 normalize 规则，再切 test，可能针对 test 分布优化。规则若由数据估计，应只在 train/dev 上决定。

### 人类反馈泄漏

开发者看到 test 每题错误后：

- 新增类似 SFT 样本；
- 修改 system prompt/chat template；
- 调 rank、学习率或 decoding；
- 手工修特殊 case；

都已经让 test 影响系统。即使模型参数没直接见 test 文本，也属于评测泄漏。只返回聚合指标、限制查询次数、把逐样本结果交给独立评测者，能降低风险。

### 闭环日志污染

线上输入、评测 prompt 和 red-team 样本可能进入观测日志，随后又被“收集高质量对话”的任务吸回训练集。每条日志需要 purpose/retention/opt-in 标签；评测和安全测试来源应默认排除自动训练收集。

## 训练数据治理账本

### 最小实体

| 实体 | 至少记录 |
| --- | --- |
| Source | 所有者/发布者、URL/内部位置、获取时间、许可/同意、用途限制、删除入口 |
| Raw snapshot | 不可变 ID、哈希、访问级别、保留期限 |
| Transformation | 代码/规则版本、输入/输出 manifest、统计、失败与审阅 |
| Dataset version | train/dev/test IDs、分组键、去重/污染报告、schema、质量卡 |
| Tokenizer | train-only 输入版本、算法/配置、词表/special IDs、哈希与测试 |
| Training run | 数据/模型/代码身份、配置、资源、checkpoint、评测与负责人 |
| Model artifact | base/adapter/merge 关系、文件哈希、模型卡、许可、访问/删除状态 |
| Incident | 发现时间、影响范围、隔离、通知、重建/撤回和关闭证据 |

### 最小控制

- **最小权限**：收集、标注、训练、评测和发布使用不同角色；test labels 不对训练人员默认开放。
- **不可变版本**：run 只引用具体 manifest/hash，不引用会变化的 `latest` 数据目录。
- **用途限制**：能用于内部分析不自动等于能用于训练或分发模型。
- **保留与删除**：删除请求传播到 raw、清洗、tokenized shards、缓存、checkpoint、adapter 和下游模型影响调查。
- **审计日志**：记录谁在何时对哪个版本做了什么，但日志本身不含原始 secret/PII。
- **事件响应**：确认污染/未授权数据后停止新训练、冻结产物、评估受影响 runs、重建并修正既有结论。

### 删除的真实边界

从当前训练 manifest 删除一条数据，不等于它已从历史 checkpoint 或模型参数中消失。治理记录应区分：

1. 原始/派生文件已经删除或隔离；
2. 哪些 checkpoints/models 曾使用该数据；
3. 是否需要重训、下架、限制访问或做进一步隐私/法律评估；
4. 哪些备份受保留政策约束、何时到期；
5. 无法证明模型已“遗忘”时明确写出这一限制。

## 报告语言：证据要降级到合适强度

| 实际证据 | 可以说 | 不可以说 |
| --- | --- | --- |
| exact hash 无命中 | 指定规范化下未发现 exact duplicate | 数据绝对无污染 |
| near-dup 候选人工复核 | 在指定阈值/语言/粒度下确认若干近重复 | 所有改写与翻译均已排除 |
| provenance 完整 | 能追溯已登记样本的来源和变换 | 所有来源都一定合法/无隐私风险 |
| test 从未用于梯度 | 未直接进入该训练目标 | 没有 prompt/调参/人工反馈泄漏 |
| 模型未复述 canary | 此测试未观察到复述 | 模型没有记忆训练数据 |

推荐结论模板：

> 在数据版本 X 上，我们对原始/规范化 exact、长度不少于 Y 的片段和阈值 Z 的近重复候选进行了扫描与抽样复核，确认并隔离 N 项。该流程未覆盖所有语义改写、翻译和未知外部预训练来源，因此结果表示“在声明范围内未再检出”，不是“证明零污染”。

## 常见失败与修复

| 失败 | 根因 | 修复 |
| --- | --- | --- |
| test 分数异常高 | exact/片段/来源重叠，重复调 test | 隔离、重建数据、启用新 holdout |
| 近重复扫描候选爆炸 | 规范化过强、阈值过松、模板未先处理 | 分来源/模板分层，校准阈值并抽样 |
| 命中为零却能搜到原题 | 只做整文档 hash，题目嵌在长文 | 加句段/window 指纹与来源审计 |
| 删除数据后旧模型仍在用 | lineage 未覆盖 checkpoint/model | 反向追踪受影响 runs 并冻结产物 |
| 同一作者跨 split | 随机按行切分 | 按作者/文档/会话等信息单位 group split |
| test 越调越好、线上不变 | benchmark overfitting | 停止逐题反馈，换独立 shadow holdout |

## 安全、许可与资源边界

- 污染扫描本身会复制、索引或嵌入数据；只在有权处理的受控环境运行，设临时文件保留与删除策略。
- 哈希不是匿名化：低熵手机号、邮箱、常见短句可被字典猜测；不要公开私有测试内容的可逆指纹集合。
- embedding/相似度服务若是外部 API，可能上传私有训练或测试文本；未经明确授权不得使用。优先在隔离环境用已审查模型。
- benchmark 许可可能允许评测但禁止再分发或训练；训练数据许可也可能限制衍生权重。分别核对，必要时咨询合格法律/隐私人员。
- 候选片段和人工审阅界面可能暴露 PII、secret 或危险内容；最小权限、内容警告、审阅支持与不含原文的报告都要设计。
- 扫描要设置 CPU、内存、索引、临时磁盘和最长时间上限；先抽样估算候选率，避免 $NM$ 全对全任务拖垮共享系统。
- 工具、相似度模型、benchmark 与来源状态会变化；版本与官方入口只从 [[AI/90-资源/05-官方资料与版本核验记录|官方资料与版本核验记录]] 进入并在实施时固定。本页没有扫描任何真实私有数据或 benchmark。

## 练习

### 练习 1：给泄漏分类

判断下列属于 training contamination、evaluation leakage、一般 data leakage、memorization 证据或无法单独判断；可能多选。

1. 测试题答案原文出现在 SFT 文件；
2. 团队看完 test 逐题错误后修改 system prompt；
3. 时间序列任务把未来一周统计量用于训练特征；
4. 模型逐字输出一段训练 canary；
5. exact hash 无命中。

### 练习 2：设计 group split

数据包含 100 个用户、每人 20 轮对话，每轮被切成若干 message 行。写出为什么按行随机切分会泄漏，并提出 train/dev/test 的分组键、时间边界和新用户测试设计。

### 练习 3：写污染报告

假设 exact 命中 12、near-duplicate 候选 80、人工确认 9、误报 41、剩余 30 待审。写三句话：已证实什么、暂未证实什么、训练是否应继续及原因。

<details>
<summary>核对要点</summary>

- 1 是直接训练污染，也使该测试失效；2 是评测泄漏/benchmark overfitting；3 是一般数据泄漏；4 是特定复述证据但仍要确认来源；5 只能说明指定 exact 扫描未命中。
- 对话应至少按用户/会话分组；若目标包含未来行为，还应按时间切，另留完全未见用户集合。
- 30 项未审候选不应被静默当作无污染；可隔离这些候选后继续受控小跑，或在风险高时暂停主训练，取决于预先治理策略。

</details>

## 成功标准

- 能把 training contamination、evaluation leakage、data leakage、memorization 与 benchmark overfitting 分开；
- 能解释为什么 exact hash、near-duplicate、语义候选和行为测试都只能覆盖一部分风险；
- 能按文档/作者/会话/时间等信息单位设计 split，并坚持 train-only 拟合 tokenizer/规则；
- 能从模型 artifact 反向追踪到 dataset、transformation 和 raw source；
- 能写出不夸大证据的污染结论，并说明未覆盖的改写、翻译和未知预训练来源；
- 能在发现确认污染或未授权数据时停止、隔离、重建、复评并修正旧结论。
