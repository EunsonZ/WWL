# 实验 G：路由与扫描状态推理

> [!abstract] 不发包也能验证的知识
> 本实验先计算路由，再区分“收到什么”与“推断何种端口状态”。所有 IP 只作为字符串参与计算，不修改路由，不调用 Nmap，不建立连接。

## 1. 先修、输入和目标

先阅读 [[计算机知识/Kali/01-系统与网络基础/06-TCPIP路由DNS与TLS|子网与路由]] 和 [[计算机知识/Kali/02-信息收集与网络测量/03-Nmap主机发现与端口状态|端口状态]]。按 [[计算机知识/Kali/07-综合实验/01-离线实验准备与夹具说明|准备页]] 复制 v2 代码与夹具。代码真源为 [[计算机知识/Kali/07-综合实验/代码/reasoning_lab.py|reasoning_lab.py]]，数据为 [[计算机知识/Kali/07-综合实验/夹具/v2/route-cases.json|route-cases.json]]。

本实验的路由模型只有单表、普通单播前缀、metric，不包括策略路由、网关可达性、链路状态、ECMP、特殊类型路由和防火墙。`ipaddress` 用于地址与前缀运算，不负责复现整个 Linux 网络栈。[^v2-python-ipaddress]

## 2. 手算，再运行

目标 `192.168.56.37` 同时落在默认路由、`192.168.56.0/24` 和 `192.168.56.32/27` 内。最长前缀 `/27` 先获选，即使它的 metric 为 900，而默认路由 metric 只有 1。只有候选前缀长度相等时，本模型才比较 metric。

`/27` 每块包含 $2^{32-27}=32$ 个地址，37 位于 32 至 63 这一块。把目标改为 64，就不再属于该 `/27`，但仍属于 `/24`。查找 `.63` 仍会匹配该前缀，但这不代表 `.63` 能在相应普通 IPv4 子网中作为一般主机地址分配；前缀匹配与地址用途是不同问题。

```bash
cd "$HOME/kali-lab/code"
PYTHONDONTWRITEBYTECODE=1 python3 - <<'PYCODE'
import json
from pathlib import Path
from reasoning_lab import Route, choose_route
path = Path.home() / 'kali-lab/fixtures/v2/route-cases.json'
data = json.loads(path.read_text())
routes = [Route(**entry) for entry in data['routes']]
for case in data['cases']:
    route = choose_route(case['destination'], routes)
    observed = route.prefix if route else None
    print(case['destination'], observed, 'expected=', case['expected_prefix'])
    assert observed == case['expected_prefix']
PYCODE
```

预期依次为 `/27`、`/24`、IPv4 默认路由、`None`。IPv4 默认路由不覆盖 IPv6；`None` 是“给定模型中无匹配项”，不是读取真实系统后发现没有 IPv6 路由。

## 3. 用失败输入检查假设

`Route('192.168.56.37/27', 'lab')` 应拒绝，因为这里要求明确的网络前缀，不能静默丢弃主机位。两个相同长度、相同 metric 的最佳路由应报 `InputError`，不是随手选列表中的第一项。现实中的 ECMP 要另外建模，本实验没有实现它。

接口名为空、metric 为负数或布尔值、目标填主机名，以及超过模型上限的路由集也应拒绝。模型不会替主机名进行 DNS 查询。将错误输入变成默认路由是一种危险的失败策略，测试特意防止这种情况。

## 4. 相同“无响应”，为什么不是同一个结论

```bash
cd "$HOME/kali-lab/code"
PYTHONDONTWRITEBYTECODE=1 python3 - <<'PYCODE'
from reasoning_lab import infer_scan_state
print(infer_scan_state('tcp_syn', 'no_response'))
print(infer_scan_state('udp', 'no_response'))
print(infer_scan_state('udp', 'icmp_port_unreachable'))
PYCODE
```

在已用尽声明的观察窗口这一假设下，本表依次输出 `filtered`、`open|filtered`、`closed`。这是所列探测类型下的教学映射，来源中的 Nmap 状态同样依赖观察方式；不是一条适用于所有工具、所有探测包的“网络真值”。UDP 无回应可能是服务本来不答，也可能是过滤或丢包，不能挑一个解释当结论。[^v2-nmapstate]

不要把 `tcp_syn` 的映射用到 TCP connect 扫描或不同 ICMP 情形；未覆盖的输入组合会明确报错。本实验不模拟重传算法、计时器或概率丢包，所以没有测量出真实网络的误差率。
