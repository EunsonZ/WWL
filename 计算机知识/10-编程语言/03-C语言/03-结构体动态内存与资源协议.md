# C：结构体、动态内存与失败时不破坏状态

> 阅读定位：C17 核心；扩展和标准版本差异单独注明。返回 [[计算机知识/00-开始/课程地图/01-C语言-课程地图|C语言 · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## 用不变量定义一个动态数组

一个整数向量通常包含 `data`、`len`、`cap`：已经初始化的元素是 `[0,len)`，总容量是 cap，必须始终满足 `len ≤ cap`。空向量可约定为 `NULL,0,0`。接口的任务不仅是完成成功路径，还要保证分配失败后旧向量仍可使用。

```c
#include <stdbool.h>
#include <stdint.h>
#include <stdlib.h>

struct Vec { int *data; size_t len, cap; };

static bool reserve(struct Vec *v, size_t cap) {
    if (cap <= v->cap) return true;
    if (cap > SIZE_MAX / sizeof *v->data) return false;
    int *next = realloc(v->data, cap * sizeof *v->data);
    if (next == NULL) return false;
    v->data = next;
    v->cap = cap;
    return true;
}
```

这里先检查乘法范围，再把 `realloc` 的返回值放进临时指针。直接写 `v->data = realloc(...)` 会在失败返回空指针时丢掉旧地址。`realloc` 成功后必须只使用新返回值，旧存储上的借用一律重新取得；不要因地址碰巧没变就继续依赖旧借用。零大小重分配的标准与实现差异容易产生陷阱，本例只在新容量大于旧容量时调用它。

增长策略若每次只多分配一个元素，会累计复制 $1+2+\cdots +(n-1)$ 个元素，达到二次量级。按倍数增长时，成功扩容的总搬运量形成几何级数，得到摊还常数次追加，但单次追加仍可能线性。倍增本身也要防止整数溢出。

## 结构体有布局，但布局不等于文件格式

`struct { char tag; int value; }` 可能含填充字节。`sizeof` 不一定等于成员大小之和，成员对齐由实现决定。把整个结构体直接写盘会把填充、字节序、ABI 和版本变化一起写进文件。序列化应显式规定字段宽度、字节序、长度和版本。

结构体赋值复制成员值；其中含指针时通常只是复制地址，不会复制它指向的缓冲区。若两个结构体都把同一指针当成独占所有权，就可能重复释放。解决方案是禁止随意复制、提供深拷贝接口，或明确使用共享所有权协议，而不是盲目多加一层指针。

## 多资源失败如何清理

申请内存、打开文件、初始化子对象可能在不同阶段失败。为每个资源定义“未获得、已获得、已释放”状态；清理按逆序进行。C 中有一个统一的 `cleanup:` 标签并不等于滥用跳转，它可以减少遗漏的释放分支。清理函数应能处理约定的空状态，不能读取尚未初始化的字段。

分配器管理的虚拟地址、进程常驻内存 RSS、物理内存和操作系统页缓存不是同一概念。`free` 使存储回到分配器，不保证 RSS 立即下降。性能判断需要查看分配模式、碎片和真实工作集。

## 练习

扩展向量的 `push` 和 `destroy`，成功追加时 len 恰好增加 1，失败时 data、len、cap 均保持原契约。测试容量边界、连续扩容和销毁后的空状态。教学测试不能可靠耗尽机器内存来制造失败，应注入一个可控的分配失败函数。
