# 自回归建模、Logits、损失与困惑度

<!-- deep-review-02 -->
> [!tip] 本轮深化：从当前概念继续追问
> 链式分解本身不假设 token 独立；teacher forcing 计算的是观测前缀条件下的似然。评测应报告 tokenizer、掩码、截断和分母，不能只列 PPL。 深化与验证：[[AI/20-LLM/10-原理/07-语言模型目标分词粒度与评测可比性|语言模型目标分词粒度与评测可比性]]；[[AI/11-数学与统计桥梁/03-概率似然贝叶斯与信息论|概率似然贝叶斯与信息论]]。


## 直觉：补下一格，再把答案放回去

给定前缀“今天下雨，我带了”，模型不直接搜索一个唯一正确的后半句；它先对词表中的每个下一个 token 给出分数。将这些分数转成概率后，训练时看真实下一个 token 获得了多少概率，生成时再按某种规则选出一个 token 并接回前缀。如此重复，就形成一段序列。

> [!note] 数学先修
> 本页只使用概率、对数和向量的应用解释。条件概率的定义与链式规则见 [[数学/30-概率与统计/01-概率分布条件概率与贝叶斯关系|概率分布、条件概率与贝叶斯]]；负对数似然与困惑度的完整推导见 [[数学/30-概率与统计/03-似然负对数似然与困惑度|似然、负对数似然与困惑度]]；Softmax 与稳定计算见 [[数学/50-信息论/02-指数对数Softmax与LogSumExp|指数、对数、Softmax 与 LogSumExp]]。

## 关键对象，不能互换

- **上下文** $x_{<t}$：当前位置之前已经给定的 token。训练中通常来自语料；生成中包含用户输入和已生成 token。
- **logits**：模型对词表每个候选输出的未归一化实数分数。它们不是概率，也不要求和为 1。
- **概率分布**：将 logits 经 Softmax 转成非负且和为 1 的数。提高一个候选的概率通常会改变其他候选的概率。
- **目标 token**：训练语料在位置 $t$ 实际出现的 token。它是监督信号，不是模型在该步抽取的样本。
- **损失**：衡量模型给目标 token 的概率有多低的可优化标量。它是训练信号，不是事实性、安全性或用户满意度的总评分。

自回归模型用一系列条件概率描述序列：每一步只在当前前缀下预测下一个 token。完整的乘积形式以及“为何乘积可以变成损失求和”属于上述数学页；本页要掌握的是：**训练使用正确前缀计分，生成却会受到自己前一轮输出影响。** 这也是自由生成可能累积偏差的原因之一。

## 从一段 token 到训练标签

若一条序列是 `[BOS, 今天, 下雨, EOS]`，next-token 训练把同一序列错开一位：

```text
模型输入：BOS   今天   下雨
训练目标：今天  下雨   EOS
```

一次 causal Transformer 前向可以并行产生三个位置的 logits；位置 $t$ 的损失只比较真实目标 $x_t$，但该位置的 hidden state 只能读取 $x_{<t}$。这常被称为 **teacher forcing**：训练前缀来自真实序列，而生成前缀逐步包含模型自己的选择。

给有效计分位置集合 $M$，应用层的平均损失可写为：

$$
L=-\frac{1}{|M|}\sum_{t\in M}\log p_\theta(x_t\mid x_{<t}).
$$

这里必须明确哪些位置进入 $M$：padding、被忽略的提示 token、跨文档边界或特殊控制 token 可能按训练目标被 mask。分布式训练还应按**全局有效 token 数**正确归一化；简单平均每个设备的局部均值，在有效 token 数不同的情况下会改变样本权重。公式的完整概率推导仍保留在数学页，本段只固定实现合同。

## 一个最小数值例

假设词表只有 `晴`、`雨`、`雪`，在“今天”之后模型输出 logits `[2, 1, 0]`。Softmax 后它们约为 `[0.665, 0.245, 0.090]`。若训练语料的目标是 `雨`，模型并非得到“部分正确”；它会因只给 `雨` 约 0.245 的概率而收到较大损失，优化过程推动该条件下 `雨` 的相对分数上升。

若真实目标已经是最可能项，损失也不必为零：只要概率还不是 1，就仍有可减少的不确定性。反过来，一个很低的平均损失也不能说明模型产生的文字在现实中为真，原因见 [[AI/20-LLM/10-原理/06-幻觉不确定性与模型边界|幻觉、不确定性与模型边界]]。

## 困惑度能说什么，不能说什么

平均负对数似然的指数形式称为**困惑度（PPL）**。在同一计分协议下，它可直观理解为模型面对真实下一个 token 时的“等效分支数”：越低表示模型平均给参考 token 更高概率。

但比较 PPL 前必须固定：测试文本和预处理、tokenizer、特殊 token、有效位置的 mask、窗口/文档边界，以及按 token 还是其他单位归一化。不同 tokenizer 产生不同条件事件；因此“模型 A 的 PPL 更低”若没有比较协议，信息远少于看起来的那么多。PPL 也不直接测事实性、推理、拒答质量、偏见或工具调用正确性。

要把概率计分推进到实际任务比较，继续读 [[AI/20-LLM/70-工程应用与工具链/04-评测回归与可观测性#一个可回归的离线工作流|冻结评测与回归流程]]：先固定任务、代表用例、版本和判分规则，再分开检索、生成与端到端失败。该流程说明怎样记录一次改动是否退化；NLL/PPL的定义与可比性仍回到数学主解释，任务正确性也不能由一个PPL分数替代。

## 从训练到生成：同一分布，不同决策

训练通常希望提高真实 token 的概率；生成则从预测分布选择一个输出。总取最高概率是贪心解码，按分布抽样则会带来随机性；温度、top-k 和 top-p 都会改变实际选择规则。它们是推理决策，而非训练目标本身，见 [[数学/30-概率与统计/04-温度Top-k与Top-p采样|温度、Top-k 与 Top-p 采样]] 与 [[AI/20-LLM/40-推理/02-采样停止条件与生成控制|采样、停止条件与生成控制]]。

## 练习

1. 用自己的话区分 logits、Softmax 概率、目标 token 和生成出的 token。
2. 两个模型在不同 tokenizer 上报告 PPL 7 与 9；为什么不能直接宣布前者语言能力更强？至少列三项需要核对的条件。
3. 解释为何“某回答每个 token 都很高概率”不能推出整条回答是真的。
4. 把 `[BOS, A, B, EOS, PAD]` 写成输入与右移一位的目标，并说明若 `PAD` 不计分，哪些目标位置进入有效集合。

## 成功标准

你能画出“前缀 → logits → 概率 → 训练计分或生成选择 → 新前缀”的循环；能把一段 token 正确右移成输入/目标并标出 loss mask；能解释 NLL/PPL 是**参考序列概率评分**，并会在把它用于模型比较前列出 tokenizer、有效 token 归一化和评测边界。
