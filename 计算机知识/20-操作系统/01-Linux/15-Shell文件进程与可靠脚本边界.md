# Linux 深化：Shell、文件和可靠脚本的边界

> 阅读定位：只读观察优先；发行版、内核、工具版本不能混为一谈。返回 [[计算机知识/00-开始/课程地图/13-Linux-课程地图|Linux · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## Shell 在程序启动前已经做了很多工作

变量展开、命令替换、分词、通配展开、重定向和管道决定程序真正得到的 argv 与文件描述符。`"$path"` 保留一个参数，未引用的 `$path` 可能被分成多个词并继续通配。`eval` 和拼接命令把数据重新解释成程序，应避免处理不可信输入。

```sh
file='./name with spaces.txt'
printf '%s\n' 'sample' > "$file"
wc -c < "$file"
```

重定向由 shell 在启动命令前处理；`sudo echo text > protected` 不意味着重定向也获得 sudo 权限。管道连接字节流，前一个程序失败不一定自动让整个脚本按你希望的方式失败。`set -e`、pipefail 和不同 shell 的细节不能当成完整错误处理替代品。

## 文件名不是以换行为分隔的文本记录

文件名可以包含空格和换行。对 GNU 工具等适当环境可用 `find ... -print0` 与支持 NUL 分隔的消费者配合，避免按换行拆文件名。`--` 常用于结束选项，但要确认具体命令支持。不要用解析 ls 输出作为通用文件遍历方案。

路径查找还经过工作目录、目录权限、挂载点与符号链接。读取文件权限不等于有权穿过其父目录。检查再使用的两个步骤之间，目标可能被替换，这是 TOCTOU 风险；需要合适的文件描述符相对操作、标志与权限设计，而不是单纯多加一次 exists。

## 进程退出与资源清理

fork 复制相应进程状态，exec 用新程序替换当前进程映像；文件描述符是否继承受标志等影响。环境变量是传给子进程的数据，不是全系统立即同步的数据库。退出码、信号终止和标准错误输出提供不同证据，不能只看屏幕最后一行。

脚本使用独立临时目录，限制权限，并通过 trap 处理通常退出路径。SIGKILL、掉电等无法靠普通 trap 清理；长期资源需要可恢复设计。默认不要覆盖源文件，写新输出后验证，再按明确协议提交替换。

## 持久化练习

在临时目录内比较写入、关闭、rename 和同步操作的职责。Linux fsync 文档明确区分文件数据与目录项同步需求；但一次普通执行成功不能证明所有故障模型下的结果。真实故障注入只能在隔离虚拟机和可丢弃数据上进行。

练习处理带空格文件名、空输入、前置命令失败和中途取消。为每条脚本命令写出“改变什么、失败怎么看、重复运行怎样、恢复怎样”，比背命令选项更能减少事故。
