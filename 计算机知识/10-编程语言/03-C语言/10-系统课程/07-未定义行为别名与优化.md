# 未定义行为不是随机结果：从优化前提理解 C 的危险边界

> **学习位置**：[[计算机知识/00-开始/课程地图/01-C语言-课程地图|C语言课程地图]] · **适用边界**：ISO C17；C23 与 POSIX 扩展另行标识。

## 三类“不固定”不能混称为未定义行为

实现定义行为要求实现记录其选择，例如某些整数表示或移位规则；未指定行为允许多个合法选择而不一定要求文档逐次说明；未定义行为则不对程序行为施加通常的语义要求。三者的调试策略不同。

未定义行为不是“这行得到随机数，其余仍正常”。优化器在语言前提下变换整个控制流，违背前提可能让看似保护性的检查消失。`if (x+1 < x)` 不能在有符号整数溢出未定义的前提下用来检测溢出：编译器可以按合法有符号加法的数学关系推理。

## 访问对象要同时满足多条约束

一个地址落在已分配内存中，仍不足以证明访问合法。还需要对象处于生命周期内、访问范围足够、对齐满足要求、类型访问符合规则、没有数据竞争，以及读取值本身已经有效初始化。

以 `float f; int *p=(int*)&f;` 为例，强制转换不自动赋予通过 `int` 左值读取 `float` 对象的权限。观察或复制对象表示可以使用字符类型和 `memcpy`；但复制出某个位模式后，还要判断用目标类型解释是否合法。

指针来源与对象身份也不能简化成整数地址。整数转回指针、跨分配区计算、释放后地址重用等规则具有严格边界。WG14 的指针来源相关工作说明这里仍需要区分标准文本、具体实现保证和新的技术规范；本课程不把某个优化器当前接受的写法当成永久标准保证。

## `restrict` 是承诺，不是“自动加速”按钮

`restrict` 告诉实现，在规定的执行范围和访问条件下，相关对象的访问遵循受限制指针的别名协议。它不是禁止全程序中存在另一个同值指针，而是对实际访问关系作承诺。违反契约后不能要求程序保持普通别名语义。

例如数组相加函数在给出不重叠输入输出的契约后，编译器更容易向量化；调用者如果让输出覆盖输入的一部分，就必须重新检查这个承诺。先写清允许的重叠关系，再决定是否使用限定符，不能先加 `restrict` 再祈祷调用都符合。

## 求值顺序与副作用

不要写依赖未保证求值顺序的表达式。C17 中 `f(i++, i++)` 对同一标量的修改没有所需顺序保证，不能靠“编译器通常从右往左传参”解释其正确性。`a[i] = i++` 也不该用来展示聪明的简写。

拆成独立语句通常更易审计：先保存旧索引，再增加计数，再写入。短路运算符 `&&`、`||` 和逗号运算符等有特定顺序规则，但函数实参中的逗号分隔符不是逗号运算符。外观相同的标点不等于相同语义。

## `volatile`、原子与同步各解决什么

`volatile` 用于规定实现不能随意省略某些可观察访问等场景，常见于受实现约束的硬件访问。它不保证多线程的互斥、原子性或 happens-before。用 `volatile int ready` 在线程间发布普通数据，不能替代原子或锁。

`_Atomic` 提供原子对象与内存序操作。原子性防止某次访问被分裂观察，内存序约束跨线程的可见关系；两者都不自动让多步业务操作成为事务。

一个发布模型是：写线程先初始化普通数据，然后对标志执行 release 存储；读线程以 acquire 读取该标志，并且确实读到该发布对应的值后，才能依赖同步关系读取数据。若数据之后仍被其他线程无保护地改写，发布一次也不能解决后续竞争。

## 检测工具的正确位置

警告、静态分析、Sanitizer、模糊测试各提供不同证据。测试没有触发 UB 不意味着没有 UB；某个平台上地址和输出都合理也不是标准层证明。反过来，发现一个数据竞争应先修同步协议，而不是只调编译优化等级。

建议将每次修复记成：最小输入、违反的契约、产生问题的状态路径、修改后的不变量、回归测试。这样“修复崩溃”才能转化为可迁移的理解。

## 练习与答案

`memcpy` 和 `memmove` 为什么不能只按快慢选择？前者要求源和目标不重叠，后者定义了重叠情况下的效果。一个小测试暂时没坏，并不能让违反前提的 `memcpy` 合法。

为什么读一个已经 `free` 的对象，即使内存内容尚未被覆盖，也不正确？对象生命周期已经结束，可读权限不能由残留字节决定。这正是把 C 的内存规则与 Rust 的借用、C++ 的析构放在一起学习的意义。
