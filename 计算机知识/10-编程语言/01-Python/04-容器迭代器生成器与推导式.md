# 04 · 容器、迭代器、生成器与推导式

## 本课目标

学完本课，你应该能够：

- 根据“有序、可修改、按键查找、去重或集合运算”等需求，在 `list`、`tuple`、`dict`、`set` 之间做出选择；
- 正确使用索引、切片、复制、排序和哈希相关操作，并能解释别名为什么会让两个变量同时看到修改；
- 读懂 `for` 背后的迭代协议，手动使用 `iter()` 与 `next()`；
- 用生成器和 `yield` 表达“逐个产出”，并知道它与一次性建立列表的取舍；
- 使用 `enumerate()`、`zip()` 以及列表、集合、字典推导式写出清晰的转换代码。

## 先选对容器

容器是保存多个对象、并提供访问或遍历方式的对象。下面是面向需求的速查，而不是对所有实现细节的承诺。

| 类型 | 是否保持元素顺序 | 是否可变 | 重复元素 | 典型用途 |
| --- | --- | --- | --- | --- |
| `list` | 是 | 是 | 允许 | 需要按位置访问、追加或修改的一组项目 |
| `tuple` | 是 | 否（元素本身可能可变） | 允许 | 不应改变的记录、解包、作为某些映射的键 |
| `dict` | 按插入顺序迭代 | 是 | 键不重复，值可重复 | 用唯一键关联值；配置、索引、计数 |
| `set` | 不应依赖顺序 | 是；`frozenset` 不可变 | 自动去重 | 成员测试、交集、并集、差集 |

这里的“顺序”要分清两件事：`list` 和 `tuple` 是序列；字典从 Python 3.7 起保证按插入顺序迭代；集合是无序集合，不应把一次输出的显示顺序当成接口约定。

```python
names = ["Lin", "Mori", "Lin"]       # 可按位置访问，重复保留
point = (3, 4)                         # 记录通常不需要改写
prices = {"tea": 18, "cake": 25}     # 用键取值
unique_names = set(names)              # {'Lin', 'Mori'}，去重

if "tea" in prices:                   # 字典成员测试默认检查键
    print(prices["tea"])
```

空集合要写 `set()`，因为 `{}` 表示空字典。集合元素和字典键必须是可哈希对象；列表、字典和集合本身不能直接作为集合元素或字典键。

## 序列的索引与切片

索引从 `0` 开始，负索引从末尾计算。切片 `序列[start:stop:step]` 包含 `start`，不包含 `stop`；省略部分表示使用默认边界。越界的切片通常得到一个较短结果，但单个越界索引会抛出 `IndexError`。

```python
letters = ["a", "b", "c", "d", "e"]
letters[0]          # 'a'
letters[-1]         # 'e'
letters[1:4]        # ['b', 'c', 'd']
letters[:3]         # ['a', 'b', 'c']
letters[::2]        # ['a', 'c', 'e']
letters[::-1]       # 新列表，倒序

letters[1:3] = ["B", "C"]  # list 的切片赋值会修改原列表
```

切片通常会建立一个新的外层序列；它不是递归深拷贝。对二维列表尤其要小心：外层列表变新了，但其中的行对象仍可能共享。

## 别名、浅复制与深复制

赋值不会复制对象，只会再绑定一个名字。下面的 `alias` 与 `items` 指向同一个列表：

```python
items = [["tea", 18], ["cake", 25]]
alias = items
alias.append(["water", 5])
assert len(items) == 3
```

需要独立的外层列表时，可以用 `items.copy()`、`list(items)` 或 `items[:]`。它们是浅复制：内部嵌套列表仍然共享。

如果“名称重新绑定”和“对象原地修改”还容易混淆，先回看 [[计算机知识/10-编程语言/01-Python/02-基础语法与数据类型#可变与不可变|对象、名称与可变性]]。

```python
shallow = items.copy()
shallow[0][1] = 19       # items[0][1] 也会看到 19

from copy import deepcopy
independent = deepcopy(items)  # 递归复制可复制的嵌套对象；成本和语义都要审慎评估
```

判断该用哪一种复制前，先问“我是否需要共享内部对象？”不要为了习惯而无条件 `deepcopy`：自定义对象、资源句柄和循环引用可能使深复制昂贵或不符合期望。

## 排序与复杂度直觉

`sorted(iterable)` 返回新的列表；`list.sort()` 原地排序并返回 `None`。两者都支持 `key=` 和 `reverse=`。Python 的排序是稳定的：相同键的元素保留原来的相对顺序。

```python
records = [("Mori", 88), ("Lin", 95), ("Aya", 88)]
by_score = sorted(records, key=lambda record: record[1], reverse=True)
# [('Lin', 95), ('Mori', 88), ('Aya', 88)]
records.sort(key=lambda record: record[0])  # 修改 records 本身
```

复杂度只提供选择方向，不替代测量，也不把某个 Python 实现的细节当成语言保证：

- 按整数索引访问列表通常适合频繁的随机访问；在列表开头插入或删除，往往需要移动许多元素；
- 字典键查找和集合成员测试通常很快，平均上接近常数级，但依赖哈希分布和实现，不能把它当作无条件的精确保证；
- 遍历、复制和切片通常随处理的元素数量增长；
- 排序需要处理全部输入，通常比一次成员测试更贵；若只需取最小的少数项目，可另行考虑 `heapq` 等工具；
- 生成器可以避免一次性物化全部结果，但每个元素仍需要计算，且重复遍历通常需要重新创建生成器。

先说明数据规模和访问模式，再决定容器；用代表性数据测量，而不是只凭直觉。

## 哈希性：为什么有些对象不能做键

哈希表需要一个在对象生命周期内保持一致的哈希值，以及与相等比较相容的行为。通常不可变且具有稳定值的对象可能可哈希，例如整数、字符串和由可哈希元素组成的元组；可变容器如 `list`、`dict`、`set` 不可哈希。

```python
locations = {(31, 121): "Shanghai"}  # 元组由整数构成，可以作为键

try:
    bad = {[1, 2]: "not a key"}
except TypeError:
    print("list is unhashable")

hash((1, 2))       # 可以
# hash(([],))      # TypeError：元组中含不可哈希元素
```

“不可变”不自动等于“可哈希”：一个元组只要递归包含不可哈希元素，仍不能哈希。不要通过修改参与哈希的字段来破坏字典或集合的查找假设；自定义类型定义 `__eq__` 与 `__hash__` 时尤其要遵循二者的一致性规则。

## 迭代协议：`for` 实际做了什么

可迭代对象（iterable）能够通过 `iter(obj)` 提供迭代器。迭代器实现 `__iter__()`（返回自身）和 `__next__()`（返回下一个值）；没有更多值时，`__next__()` 抛出 `StopIteration`。`for` 语句会自动完成这些调用，并把 `StopIteration` 转换为循环结束。

```python
colors = ["red", "green"]
it = iter(colors)
assert iter(it) is it
print(next(it))  # red
print(next(it))  # green
try:
    next(it)
except StopIteration:
    print("迭代结束")
```

迭代器通常是一次性的、只能向前走。上面的 `it` 已经耗尽，因此再次消费它不会得到元素；但原来的列表 `colors` 是可重复迭代的容器，再次对列表发起迭代仍能得到两个颜色：

```python
assert list(it) == []

for color in colors:
    print(color)  # 仍会依次打印 red、green
```

需要从同一容器重新遍历时，可再次调用 `iter(colors)`；只有迭代器 `it` 自己不会自动倒回起点。

字典直接迭代键；需要值或键值对时明确写 `prices.values()` 或 `prices.items()`。不要在遍历字典或集合的同时改变其大小；这可能抛出异常或产生难以理解的结果，先收集要改的键通常更清楚。

## 生成器与 `yield`

包含 `yield` 的函数是生成器函数。调用它时不会立即执行函数体，而是得到一个生成器对象；每次 `next()` 执行到下一个 `yield`，产出一个值并暂停，局部变量和执行位置会保留。函数返回或运行到末尾后，迭代结束。

```python
def read_positive(numbers):
    for number in numbers:
        if number > 0:
            yield number

stream = read_positive([-2, 4, 0, 7])
assert next(stream) == 4
assert list(stream) == [7]  # 已经消费了第一个值
```

生成器适合把数据处理串成按需消费的流水线，尤其是输入很大或可能提前停止时。它不是“免费加速”：如果最终必须把所有结果用 `list()` 收集，内存优势就会消失；如果需要随机访问、长度或多次遍历，列表可能更合适。生成器表达式是轻量写法：`(n * n for n in range(10))`；列表推导式 `[n * n for n in range(10)]` 则立即建立列表。

## `enumerate()` 与 `zip()`

不要用 `range(len(items))` 只为了同时得到索引和值；`enumerate()` 直接表达意图，并可用 `start=` 改变起始编号。

```python
for position, name in enumerate(["Lin", "Mori"], start=1):
    print(position, name)
```

`zip()` 将多个可迭代对象按位置配对，返回一个迭代器；默认在最短输入耗尽时停止。长度必须相等且不允许静默丢数据时，可使用支持该约束的 `zip(..., strict=True)`（Python 3.10+），或先明确验证长度。

```python
names = ["Lin", "Mori"]
scores = [95, 88]
for name, score in zip(names, scores, strict=True):
    print(f"{name}: {score}")
```

## 三种常见推导式

推导式适合“从一个或多个可迭代对象，经过短小、直观的转换或筛选，得到一个容器”。

```python
numbers = range(6)
squares = [n * n for n in numbers if n % 2 == 0]
letters = {letter.lower() for letter in "Ada Ada" if letter.isalpha()}
name_lengths = {name: len(name) for name in ["Lin", "Mori"]}
```

- 列表推导式返回 `list`，保留生成顺序并允许重复；
- 集合推导式返回 `set`，会去重，不能依赖结果顺序；
- 字典推导式返回 `dict`，冒号左侧是键、右侧是值；重复键后写入的值会覆盖前一个值；
- 生成器表达式使用圆括号，按需产生值，不立即建立结果容器。

把条件放在 `for` 后面，把结果表达式放在最前面：

```python
raw_words = ["  tea ", "", "cake  "]
clean = [word.strip() for word in raw_words if word.strip()]
assert clean == ["tea", "cake"]
```

若表达式需要多层嵌套、很多副作用、异常处理、日志，或读者必须反复拆解执行顺序，就改用普通 `for` 循环。推导式不应承担修改外部状态的任务；不要写成 `[items.append(x) for x in source]`。如果输入可能无限或非常大，不要用列表推导式一次性物化，优先使用生成器表达式或分批处理。

## 可观察例子：按标签汇总分数

```python
rows = [
    ("python", "Lin", 95),
    ("python", "Mori", 88),
    ("sql", "Aya", 91),
]

python_rows = [(name, score) for topic, name, score in rows if topic == "python"]
scores_by_name = {name: score for _, name, score in rows}
topics = {topic for topic, _, _ in rows}

for index, (name, score) in enumerate(python_rows, start=1):
    print(index, name, score)
```

这里使用元组表示一行记录，列表推导式筛选记录，字典推导式建立按姓名查找的索引，集合推导式去重主题；`enumerate()` 负责显示编号。每个容器都有明确职责。

## 练习

先写生成器 `valid_rows(lines)`：输入一个字符串可迭代对象，每项类似 `"python:Lin:95"`；逐个产出解析后的 `(topic, name, score)` 三元组。再写 `summarize(rows)`：输入这些三元组，返回一个字典，键是主题，值是该主题下的姓名集合。要求：

1. `valid_rows()` 用 `split(":")` 解构每行，并把分数明确转换为 `int`；格式不完整、分数无法转换或不在 `0` 到 `100` 范围内的行不产出；
2. `summarize()` 接收三元组而不是重新解析原始字符串；同一主题和姓名重复出现时只保留一次；
3. 至少用一种推导式完成清晰、无副作用的转换；
4. 先用 `parsed_rows = list(valid_rows(lines))` 保存一次性生成器的结果，再用 `enumerate(parsed_rows, start=1)` 打印有效记录；
5. 从 `parsed_rows` 分别构造 `names` 与 `scores` 两个等长列表，再用 `list(zip(names, scores, strict=True))` 得到姓名—分数对；至少准备一个格式错误、一个越界分数和一个重复样本，并断言最终汇总字典与姓名—分数对。

## 成功标准

- 我能解释 `list`、`tuple`、`dict`、`set` 的主要取舍，并知道字典默认迭代键、集合不承诺顺序。
- 我能区分对象的别名、浅复制和深复制，并能预测嵌套列表的修改是否会互相影响。
- 我能正确解释 `sequence[start:stop:step]` 的边界，以及 `sorted()` 和 `list.sort()` 的区别。
- 我能说明“可哈希”与“不可变”不是完全同义，并判断一个元组是否可作字典键。
- 我能用 `iter()` / `next()` 观察 `StopIteration`，并解释生成器为什么只能向前消费。
- 我能根据数据规模和是否需要随机访问、多次遍历，说明何时选列表、何时选生成器。
- 我的推导式短小、无副作用；遇到复杂控制流时会改用普通循环。

## 常见陷阱

- `a = b` 不是复制；先用 `a is b` 检查是否为同一对象。
- `[[0] * 3] * 3` 会重复引用同一行；需要独立行时使用 `[[0] * 3 for _ in range(3)]`。
- `list.sort()` 原地修改并返回 `None`，不要写 `result = items.sort()`。
- `dict` 的“有序”不代表可以按整数索引访问；按键取值仍需 `mapping[key]`。
- `set` 和字典键要求可哈希；包含列表的元组也不可哈希。
- 迭代器被 `list()`、`sum()`、`in` 或一次循环消费后，不能自动倒回起点。
- `zip(a, b)` 默认静默截断到较短输入；数据完整性重要时明确使用 `strict=True` 或自己检查。
- 列表推导式立即建立结果；面对大数据、无限流或可提前停止的流水线，考虑生成器表达式或生成器函数。
- 推导式中不要塞入打印、写文件、修改外部列表等副作用；可读性优先于字符数。
