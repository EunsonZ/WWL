# 数据、训练、验证与保存恢复

<!-- deep-review-02 -->
> [!tip] 本轮深化：从当前概念继续追问
> 训练闭环除了参数，还包含优化器、随机数和数据位置。先验证断点后“同一个下一步”，再检查变长数据和累积窗口是否仍对应同一目标。 深化与验证：[[AI/12-PyTorch/05-变长批处理Packing与有效Token归一化|变长批处理Packing与有效Token归一化]]；[[AI/12-PyTorch/07-完整训练状态恢复与可复现实验|完整训练状态恢复与可复现实验]]。


训练循环是一份协议：哪些样本进入损失、怎样归一化梯度、何时更新参数、验证是否隔离、退出后能否恢复。API 的顺序只是协议的表面。本页沿下面现有的同一批分类数据追踪一次 `forward → loss → backward → step`，然后问：这一步之后退出，怎样使恢复后的下一步仍是原来的下一步？

先修只需要 [[AI/12-PyTorch/01-张量存储索引广播与设备#三份形状合同|张量 01 的轴与线性层合同]]、[[AI/12-PyTorch/01-张量存储索引广播与设备#dtype 与 device 的真正边界|类别标签的 dtype]]，以及 [[AI/12-PyTorch/02-自动微分模块与参数管理#手算一次再调用 backward|自动微分 02 的链式法则与梯度累积]]。01 的六元素转置例解决存储问题，02 的标量平方损失解决求导问题；这里换成一批两类样本，是为了把已注册参数、优化器和数据顺序放进同一轮训练，并不把这三组数当作同一任务。

## 数据进入模型之前

`Dataset` 定义如何拿到一个样本，`DataLoader` 负责取样、组批和可选多进程。变长序列通常要在 `collate_fn` 里 padding；相应 attention mask 和 loss mask 不同。缺失值插补、标准化和词表学习只能拟合训练集。验证集不做随机训练增强。

多进程加载的随机种子、重复样本和迭代式数据分片应单独检查。先用 `num_workers=0` 跑通，才能分清错误来自数据本身还是子进程环境。最后一个 batch 可能较小，平均 loss 应按样本数或有效 token 数加权。

## 一个不依赖外部数据的训练片段

下面保留原有 96 个样本的构造：每个样本四个实数特征，目标由 $x_{i0}+0.5x_{i1}>0$ 是否成立决定。真为类别 1，假为类别 0；只有前两维进入造标签规则，模型仍接收全部四维。`shuffle=True` 决定每轮取样次序，因此下文追踪的是循环实际给出的第一批，不把它悄悄换成 `x[:16]`。

| 对象 | 本例 shape / 类型 | 每根轴或每个值的意思 |
| --- | --- | --- |
| 全量 `x` / `y` | `[96,4]` 浮点 / `[96]` long | 96 个样本；每个样本四个特征和一个类别 ID |
| 第一批 `xb` / `yb` | `[16,4]` / `[16]` | 本批 16 个样本，标签只能为 0 或 1 |
| `model.weight` / `model.bias` | `[2,4]` / `[2]` | 两个类别各一行权重及一个偏置，共 10 个可学习数 |
| `logits=model(xb)` | `[16,2]` | 每个样本对两类分别给原始分数 |
| `loss` | `[]` 标量 | 本批 16 个目标的平均负对数概率 |

`nn.Linear(4,2)` 计算 $S=XW^\mathsf T+b$；偏置 `[2]` 对全部 16 个样本共享。分类目标 `[16]` 是索引，既不是 `[16,1]` 回归值，也不是需要手工展开的 one-hot。张量 01 的广播规则在这里兑现为 `[16,2]+[2]→[16,2]`，任务合同由交叉熵进一步限定。

```python
import torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset

torch.manual_seed(7)
x = torch.randn(96, 4)
y = (x[:, 0] + 0.5 * x[:, 1] > 0).long()
loader = DataLoader(TensorDataset(x, y), batch_size=16, shuffle=True)
model = nn.Linear(4, 2)
optimizer = torch.optim.AdamW(model.parameters(), lr=0.03)
for epoch in range(5):
    model.train()
    total_loss, total_n = 0.0, 0
    for xb, yb in loader:
        optimizer.zero_grad(set_to_none=True)
        logits = model(xb)
        loss = nn.functional.cross_entropy(logits, yb)
        loss.backward()
        optimizer.step()
        total_loss += loss.detach().item() * yb.numel()
        total_n += yb.numel()
    print(epoch, total_loss / total_n)
```

### 沿第一批走完一次更新

先固定这次 `xb,yb` 和更新前的 $W,b$，逐行读循环内部，暂不换下一批：

| 当前操作 | 本批发生的变化 | 尚未发生什么 |
| --- | --- | --- |
| `model.train()` | 指定训练模式；本例只有 Linear，模式不改变其公式 | 不等于反传，也不取代清梯度 |
| `zero_grad(set_to_none=True)` | 清去上一步参数梯度，使本步从空梯度开始 | 参数值没有更新 |
| `logits=model(xb)` | 用当前 $W,b$ 产生 `[16,2]` 分数，记录前向图 | 标签尚未计分 |
| `cross_entropy(logits,yb)` | 从本批每行的正确类别取概率，平均成标量 | 尚未写入参数 `.grad` |
| `loss.backward()` | 将这个平均目标的梯度累积到 weight `[2,4]`、bias `[2]` 的 `.grad` | 参数值仍是前向时的值 |
| `optimizer.step()` | AdamW 用这些梯度及优化器状态更新同一组参数和自己的矩估计、步数 | 不会自动清除 `.grad` |
| `loss.detach().item()` | 取出本批更新前已经算好的 loss，按 16 个样本加到日志 | 没有重新评估更新后的参数 |

本例没有类别权重、label smoothing 或忽略目标。令 $P_{ic}=\operatorname{softmax}(S_i)_c$，$Y_{ic}=\mathbf1[c=y_i]$，其中 $i=0,\ldots,15$、$c=0,1$，则同一批的计算链为

$$L=-\frac1{16}\sum_{i=0}^{15}\log P_{i,y_i},\qquad
G=\frac{P-Y}{16}\in\mathbb R^{16\times2},$$
$$\nabla_W L=G^\mathsf T X\in\mathbb R^{2\times4},\qquad
\nabla_b L=\sum_{i=0}^{15}G_i\in\mathbb R^2.$$

例如权重 $W_{1,0}$ 的梯度是 $\frac1{16}\sum_i(P_{i1}-\mathbf1[y_i=1])X_{i0}$；bias $b_1$ 的梯度少了特征因子 $X_{i0}$，汇总同一批所有样本的责任。它与 [[AI/80-实践/09-从一句话到学习与生成/01-一句话的目标更新与生成#程序实际执行的概率、梯度和一次更新|一句话的共享 bias]] 保持同一个 `p-y` 与求和关系；改变的是输入由位置编号变成四维特征、七个词的目标变成两类目标，分母由五个有效 token 变成 16 个样本，更新器由 SGD 变成 AdamW。不能把那次学习率 8 的数表拿来预测本次更新量。

第一次 `step` 时历史矩为零。按本片段使用的 [PyTorch 2.10 AdamW 默认合同](https://docs.pytorch.org/docs/2.10/generated/torch.optim.AdamW.html)，$\beta_1=0.9,\beta_2=0.999,\epsilon=10^{-8}$，未显式覆盖的 weight decay 为 $\lambda=0.01$。对 weight 或 bias 中任一个标量 $\theta$，把刚才的梯度记为 $g$，第一步有

$$m_1=0.1g,\quad v_1=0.001g^2,\quad \widehat m_1=g,\quad\widehat v_1=g^2,$$
$$\theta_1=(1-0.03\times0.01)\theta_0-0.03\frac{g}{|g|+10^{-8}}.$$

这是默认设置下第一步的数学表达；实际浮点执行可有舍入差异。循环中的 bias 也交给同一优化器且没有单独参数组，因此也受这份衰减设置影响。第二步开始，$m,v$ 包含第一步历史，不能再套用这个首步简式。`backward()` 给出了 $g$，`step()` 才使参数和历史改变；两者合起来才完成一次学习更新。

要检验更新后同一批的概率或 loss，应保留这次 `xb,yb`，在 `step()` 后另做一次前向。循环打印的是各批更新前 loss 的样本加权汇总，不是 epoch 末同一模型重新扫完整训练集的指标；本例 96 恰好整除 16，每轮六个 batch、五轮共 30 次更新。保持 `total_loss += loss * yb.numel()` 的写法，是为了换成不能整除的样本数后仍按实际样本数归一化。

这是训练机制演示，不含独立测试集，因此不能据此报告泛化。完整 train/dev/test 与 CNN 实验在 [[AI/80-实践/07-PyTorch与核心公式CPU实验/00-CPU实验与使用说明|CPU 实验]]。

交叉熵接收原始 logits，不要提前 softmax。多标签问题不是普通多类问题：一个样本可同时属于多个类别，应考虑逐类 `BCEWithLogitsLoss` 和独立阈值。回归则必须防止广播误配和目标尺度失衡。

## 优化器选择与有效步数

SGD 用梯度方向更新；动量平滑历史方向。Adam 用一阶和二阶矩估计逐坐标调整步长。AdamW 把权重衰减从损失梯度中解耦，因此“在 Adam 的 loss 中加 L2”通常不等同于 AdamW。学习率调度器的 `step()` 是按 optimizer update、epoch 还是验证事件执行，必须按所选调度器的接口固定。

梯度累积时，把 K 个 micro-batch 的贡献合成一次更新；不是每批都先 `optimizer.step()` 再说自己在累积。若各批有效 token 数不相等，应加总逐 token loss 并除以总有效 token 数，而不是平均各批的均值。遇到无有效标签的批次，要明确跳过规则，避免除以零。

## 验证与 checkpoint

刚才一批用于更新参数；验证要回答的是固定当前参数在未参与这些更新的数据上怎样表现。本片段尚未切分数据，给同一批再算 loss 只是更新检查。要得到验证指标，需另建隔离数据集；验证循环不调用 `backward()` 或 `step()`，也不能在验证数据上拟合预处理。当前模型仅有 Linear，`train/eval` 的数值公式相同；迁移到含 Dropout/BatchNorm 的模型后，模式本身会改变前向行为。

验证先 `model.eval()`，再用 `torch.inference_mode()`。验证 loss、指标和训练 loss 应分别记录。早停只能看验证集。保存最佳模型时，要保存实际状态快照；仅执行 `best_state = model.state_dict()` 可能保留随训练继续变化的张量引用，需深拷贝或立即写入独立文件。

只推理通常保存模型 `state_dict` 加结构/预处理配置；完整恢复还要保存优化器、调度器、AMP scaler、步数、随机状态、数据位置和环境身份。恢复随机种子并不恢复已消耗的数据流。

把快照位置固定为“第一批的 `optimizer.step()` 已完成、下一批尚未用于前向”。此时本例的下一步依赖四组可以核对的对象：

| 快照内容 | 恢复时怎样接回本例 | 漏掉后会改变什么 |
| --- | --- | --- |
| 模型结构、weight/bias 快照 | 重新建立 `Linear(4,2)`，加载这一步之后的状态 | 分数函数或参数起点改变 |
| AdamW 状态与已完成更新数 | 新优化器绑定新模型参数，再加载同一参数组的矩、step 与超参数 | 同样梯度仍可能得到不同更新 |
| 实际 RNG 状态 | 在模型重建等消耗随机数的操作之后、下一次随机操作之前恢复 | 重新设 seed=7 会回到随机序列起点 |
| 数据身份、已选顺序及游标 | 确保下一批仍是原排列中后续的 16 个样本 | 从头建 `iter(loader)` 可能重新洗牌或重复数据 |

本例还没有 scheduler、AMP scaler 或梯度累积窗口；它们不在这段程序里。迁移到使用这些机制的训练时，应保存实际使用的状态；若在累积窗口中间断点，未完成的梯度及窗口进度也需要处理，不能只记录 epoch。这里选择更新边界，恢复后下一次先 `zero_grad()`，不沿用旧计算图。

因此，“已保存模型”与“能继续同一个下一步”要分别验收。原片段没有 checkpoint 实现，也没有可恢复的 DataLoader 游标；不能只加一次 `torch.save(model.state_dict())` 就声称完整恢复。沿 [[AI/12-PyTorch/07-完整训练状态恢复与可复现实验#最小状态清单要和你的目标对应|恢复 07 的状态清单]]，先用单进程和可重放取样顺序固定下一批，再扩展 worker/预取情形。

已有实验提供两种不同范围的核对。[[AI/80-实践/07-PyTorch与核心公式CPU实验/00-CPU实验与使用说明#CNN 为什么先用横线和竖线|CNN 保存加载]] 检查选定权重落盘后同一输入的输出一致，它更换为图像任务，验证的是推理往返。[[AI/80-实践/08-深层机制数值实验/00-数值实验导航与验收#按问题读测试|深层机制实验的恢复测试]] 中 `test_14_exact_cpu_resume_with_dropout_and_adam` 则在固定 `[6,3]` 输入和 `[6,1]` 回归目标上，用含 Dropout 的小模型、Adam、模型与优化器深拷贝快照及 CPU RNG 状态比较下一步 loss 和参数逐元素一致；它使用内存快照，没有测试 checkpoint 文件的原子写入，也没有 DataLoader 顺序或多机恢复。换模型是为了让遗漏随机状态和优化器状态能够显出后果，不能把这项历史 CPU 结果称为本页 96 样本分类器已经完成了恢复实验。

加载只使用可信来源，显式设置合适的 `map_location` 与受限加载选项。`weights_only=True` 减少反序列化攻击面，不意味着可以不检查文件大小、来源和运行资源。断点先写临时文件、校验后原子替换，避免中途断电留下“名字正确、内容截断”的文件。

**验收：** 在固定 CPU 条件下比较“连续训练 N 步”和“训练 M 步、保存、恢复到 N 步”的参数与日志。先在断点后的下一步核对相同样本 ID、学习率、前向 loss、梯度与更新后参数；只看到加载成功或 loss 继续下降不够。浮点设备或算法变更可能只能要求容差一致，不能要求任意环境逐位相同。

**改变条件再检查：** 若只将本批 16 改成 8，权重仍是 `[2,4]`、bias 仍是 `[2]`，均值梯度的分母和每轮更新数改变；不应给每个样本再造一套参数。若把任务改成每个位置预测一个 token，目标、词表轴及有效分母也要重新声明，沿 [[AI/12-PyTorch/05-变长批处理Packing与有效Token归一化|变长批处理与有效 token]] 继续。若只恢复 weight/bias，保留同一批再更新一次，能否保证与连续训练相同？不能：AdamW 的矩和 step 可能已经不同；恢复的正确问题是“同一个状态与下一批能否得到同一个下一步”，完整方法返回 [[AI/12-PyTorch/07-完整训练状态恢复与可复现实验|训练状态恢复 07]]。
