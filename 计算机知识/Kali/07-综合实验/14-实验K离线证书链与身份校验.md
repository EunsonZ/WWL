# 实验 K：离线证书链与身份校验

**先修与目标：** 先读 [[计算机知识/Kali/03-Web与API安全/10-TLS证书与服务配置评估|TLS 的信任、身份、用途和时间]]。本实验让你逐个改变这些条件，观察真实 OpenSSL 的接受或拒绝，而不是启动网络服务、忽略证书错误后只看能否连接。

## 输入、代码与运行边界

代码真源是 [[计算机知识/Kali/07-综合实验/代码/tls_verify_lab.py|tls_verify_lab.py]]，模型版本 `tls-v3.1`；判读器的独立反例在 [[计算机知识/Kali/07-综合实验/代码/test_tls_verify_lab.py|test_tls_verify_lab.py]]。需要 Python 3.10+ 标准库和**已有**的 OpenSSL 3.x 命令行。本轮实际环境为 Python 3.13.5、OpenSSL 3.5.5，不代表所有 3.x 版本都已测试。

脚本仅在独立临时目录生成短期 EC 教学私钥、证书与中间文件，目录限制为 700、生成后私钥限制为 600。目录隔离和权限限制不等于对恶意本机管理员的保护。结束后删除临时文件，不承诺存储介质上的安全擦除。不读取你的证书、不修改系统信任、不监听端口、不查询网络、不安装依赖。

这是**动态合成输入**：每次生成的新密钥和有效期可以不同，不能要求输出 PEM 摘要与前一轮相同。稳定合同是证书拓扑、SAN、用途和各个反例的预期结果。不要将短有效期、固定教学序列号或无口令临时密钥策略用于真实 CA。

## 第一步：先写预测，再运行

拓扑为教学根 → 教学中间 CA → 叶证书。根只在这次验证命令中被显式信任；中间以 `-untrusted` 提供，不能因名字里有 CA 就当信任锚。叶 SAN 包含 `web.lab.test` 和 `127.0.0.1`，EKU 为 serverAuth。[^verify][^generation]

在运行前预测三个问题：把参考名字改成 `other.lab.test` 会怎样；把用途改成客户端会怎样；完全不要求验证参考名字时，能否仍通过链校验。最后一个是重要反例：通过较弱的检查，不代表通过你真正想要的检查。

按 [[计算机知识/Kali/07-综合实验/01-离线实验准备与夹具说明|准备页]] 将本版整体复制到一个新的实验目录。不要覆盖旧实验记录。以下沿用默认路径：

```bash
cd "$HOME/kali-lab/code"
python3 -B tls_verify_lab.py
```

输出 JSON 含模型、运行时 OpenSSL 版本、准备命令、每个案例命令与结果、私钥权限和临时目录清理结果，**不含私钥内容**。依赖缺失、版本方言不支持或证书准备失败会明确退出，不能记成“负例成功”。没有网络服务时本实验照常工作。

需要保留报告时，使用一个新生成的输出目录，并明确检查退出状态：

```bash
(
  set -eu
  cd "$HOME/kali-lab/code"
  run_dir=$(mktemp -d "$HOME/kali-lab/output/tls-v3.XXXXXX")
  if python3 -B tls_verify_lab.py > "$run_dir/report.json" 2> "$run_dir/stderr.txt"; then
    printf '本次报告：%s/report.json\n' "$run_dir"
  else
    rc=$?
    printf '实验未通过，退出码=%s；保留本次输出：%s\n' "$rc" "$run_dir" >&2
    exit "$rc"
  fi
)
```

## 第二步：逐项解释 11 个案例

| 案例 ID | 预期 | 被改变的条件 |
| --- | --- | --- |
| `valid_dns_identity` | 接受 | 正常 DNS 参考身份 |
| `valid_ip_identity` | 接受 | 正常 IP 参考身份 |
| `wrong_dns_identity` | 拒绝，X.509 错误 62 | DNS 名不符 |
| `wrong_ip_identity` | 拒绝，错误 64 | IP 不符 |
| `missing_intermediate` | 拒绝，错误 20 | 缺少路径构建所需中间证书 |
| `unrelated_trust_anchor` | 拒绝，错误 20 | 换成另一教学根 |
| `wrong_extended_key_usage` | 拒绝，错误 26 | serverAuth 叶被用于 sslclient |
| `before_validity` | 拒绝，错误 9 | 验证时间早于这条链的有效期 |
| `after_validity` | 拒绝，错误 10 | 验证时间晚于叶有效期 |
| `chain_without_identity_check` | 接受，但不是完整服务验收 | 没有请求校验参考身份 |
| `changed_signature_byte` | 拒绝，错误 7 | DER 证书的签名字节被改变 |

错误码与本版 CLI 判读由 OpenSSL 文档和本轮实际输出支持；准备命令与案例是原创教学设计。[^verify][^errors] `before_validity` 可能先在根证书深度报错，不能谎称每次都只验证了叶的时间条件。`depth` 是链中的位置，不是 HTTP 重定向次数。

签名破坏反例保留了能解析的证书外形。能打印名字与有效期不等于签名仍有效。查看证书字段和验证签名是两个不同阶段，不能相互替代。[^generation]

## 第三步：检查“失败是不是预期的失败”

本轮审阅发现，最初测试器只按非零退出码认定负例拒绝，理论上会把“不支持参数”也算成证书拒绝。现已改为核对预期 X.509 错误码和验证失败诊断；未知选项、错误原因不同、空成功输出均不能通过。保存了修复前的独立合成反例，不把改进后的标准反投射到最初记录。

```bash
cd "$HOME/kali-lab/code"
python3 -B -m unittest -v test_tls_verify_lab
```

这组测试只验证结果判读、日期解析、依赖错误和导入行为，**不替代前面的 11 个真实 OpenSSL 案例**。错误文本语法不符合本工具支持范围时应显式失败并人工核对，不能删掉错误原因断言来迁就输出。

## 能迁移什么，不能推出什么

能迁移的是：明确参考身份和信任输入、保持正例可用、分别改变一个条件、把运行失败与正确拒绝分开。在线 `s_client`、curl 和浏览器采用同样证据分层，但还需要另行检查握手、私钥持有、协议、撤销、代理和应用行为。

本实验没有验证 OCSP/CRL、浏览器策略、实际服务器、TLS 性能或企业证书治理。验证前后系统信任都不变。发现问题后回到 [[计算机知识/Kali/03-Web与API安全/10-TLS证书与服务配置评估|TLS 课程的错误分支]] 写有限结论，不写“HTTPS 全部安全”。

## 自检与答案定位

“链校验成功但参考名字不符”应引用哪个案例？对照 `chain_without_identity_check` 与 `wrong_dns_identity`。为什么缺中间和错误根都可能报 20？同一类路径构建失败可以有不同输入原因，需保留命令和链结构。负例返回 2 但提示 Unknown option，能否通过？不能，检查根本未按预期进行。答案也可从判读器的独立测试找到。
