## 四、数学：从公式正确到解释正确

### 4.1 Adam：分子小了，比例不一定小

位置：`数学/40-微积分与优化/04-SGD-Momentum-Adam与AdamW.md`。

原例子给出 `g₁=2`、`β₁=.9`、`β₂=.999`，两项矩从零初始化，数值本身正确：

\[
m_1=0.2,\qquad v_1=0.004,\qquad \hat m_1=2,\qquad \hat v_1=4.
\]

问题出在随后的解释：将偏差修正理解成“避免首步约缩小十倍”。忽略 epsilon 时：

\[
\frac{m_1}{\sqrt{v_1}}\approx3.16227766,\qquad
\frac{\hat m_1}{\sqrt{\hat v_1}}=1.
\]

未经修正的一阶矩确实缩小，但分母也缩小，而且缩小的方式不同。一般首步比例为：

\[
\frac{1-\beta_1}{\sqrt{1-\beta_2}}\operatorname{sign}(g_1).
\]

这不是只改一句话即可利用完的例子。它可以训练一种可迁移的思考方式：**当一个量出现在比例、归一化或复合函数里，不能只分析局部一个因子的变化。** 可将其链接回归一化、尺度不变性和有效学习率，但不需要新增优化器课程。[S2]

### 4.2 DFT：全局表示、不易读和信息丢失是三回事

位置：`数学/70-信号处理与多模态数学/02-采样定理波形STFT与Mel频谱.md`。

完整复数 DFT 可逆，不能直接说“整段做 DFT 会丢失什么时候出现”。考虑两个位置不同的脉冲：

\[
x=[1,0,0,0],\quad y=[0,1,0,0].
\]

其复数谱分别为：

\[
X=[1,1,1,1],\quad Y=[1,-i,-1,i].
\]

幅度都为 1，却有不同相位；逆变换能恢复各自位置。本轮计算重建误差均在约 `1.2e-16` 以下。

真正需要区分的是：完整变换是否保留信息；仅保留某些分量后是否丢失信息；表示是否适合人直观观察局部结构。STFT 的意义是提供局部时频表示，不是简单修复 DFT 必然的信息遗失。[S3]

同样的区分可以帮助理解低秩近似、量化、embedding 和可视化：**看不出来，不等于信息不存在；某种显示被压缩，也不等于原始表示同样被压缩。**

### 4.3 频谱名称不能替代单位和归一化

多模态实验 `one_sided_power_spectrum()` 当前返回单边原始 `|DFT|²`。对于某些特征提取，这完全可以是一种约定；但它不自动等于满足 Parseval 的时域能量，也不自动是带每赫兹单位的 PSD。

N=8 的单位正弦、矩形窗，实测三个和分别约为 4、32、16：时域平方和、双边原始平方幅度和、单边原始平方幅度和。数值不同本身不是错误，未交代关系才是可理解性问题。采样率、DFT 归一化、窗和单边处理都应出现在解释中。[S4]

因此改造单没有要求“给所有 Mel bin 乘二”。那样可能修好了一个并未承诺的能量定义，却破坏原来的特征约定。

## 五、AI：指标是否真的测到了自己声称的东西

### 5.1 RAG 的 Recall 被单相关项例子掩盖

位置：`AI/80-实践/05-RAG评测与私有服务/rag_service.py:evaluate_retrieval`。

实现按“返回结果与 gold 有非空交集”加 1。只有一个 gold 时，Hit 与该查询 Recall 恰好相同，于是现有小测试全通过。两个 gold 只找回一个时，程序仍报告 `recall_at_k=1.0`，而 Recall 为 0.5。[S5]

改造应同时修定义、计算、测试和结果消费方。进一步说，RAG 的 gold 集合也必须解释：它们是任一个都足够的替代证据，还是需要联合起来的多个条件？“命中了多少相关块”和“证据是否足以回答”不是同一个指标。

这是让库更高级的一个低成本方向：不是增加更复杂检索算法，而是让同一评测表里的每个数字都有可靠语义。

### 5.2 无效输出必须能成为可统计的失败

同文件的 `answer()` 先验证输出，再返回；`evaluate_generation()` 把它放在处理验证失败的 `try` 之外。将生成器替换为返回 `{}` 后，评测直接抛出 `ValueError`，不会计算格式失败率。成功返回的结果又被重复验证。

所以当前测试不能证明“系统能测量坏格式比例”；它只说明正常 stub 的输出合法。应先定义每次请求的 raw response、验证结果和错误分类，再聚合全部适用案例。不能把失败悄悄从分母中移走，也不能用宽泛捕获把编程错误涂成“模型失败”。

这一模式具有普遍性：任何评测先筛掉失败请求，再在幸存结果上汇报总体成功率，都可能发生口径偏移。对本库应以实际调用链和分母解释为准，而不是只看指标名称。

### 5.3 内容快照不是算法版本

原 RAG 索引删除退款文档后 chunk 数从 8 变成 6，但 revision 仍是 `demo-index-v1`。如果这个值代表代码版本，它可以保持不变；问题是 trace 还需要能定位本次检索使用的内容快照。

内容、分块参数、权限版本和算法版本不应混在一个泛泛 revision 字段里。增加可追踪性也不能以公开私密正文或 ACL 为代价。此项属于追溯合同完善，不是“检索结果已经被证明错误”。

### 5.4 PPL 截顶使更差的模型看起来一样差

位置：`AI/80-实践/01-微型Transformer预训练/tiny_transformer.py:evaluate_model`。

原实现 token 加权 NLL 的处理值得保留，但 PPL 使用 `exp(min(nll,20))`。NLL=25 时：

\[
\text{报告值}\approx4.85165\times10^8,\quad
\text{真实 }e^{25}\approx7.20049\times10^{10}.
\]

相差约 148.4 倍。工程上避免输出溢出是合理目标，但不能通过悄悄改变指标定义解决。应保留 NLL／log-PPL，明确超范围状态；显示截顶另用字段，并保持输出格式合法。

这个案例可与 DPO 反例共同解释：**训练目标、理论定义、实现数值和展示数字之间，每一层都可能引入不同语义。**

## 六、实现：正确的正常路径不能替代输入合同

### 6.1 非零位置、空缓存和未来信息

位置：`AI/20-LLM/50-实现/tiny_decoder.py:CausalSelfAttention.forward`。

当 `cache=None`、长度 3、`start_pos=5` 时，query 位置为 5、6、7，key 却标作 0、1、2，于是第一 query 的 mask 允许看到全部 key。实测其注意力权重约为 `[0.3803,0.3759,0.2439]`；改变第三 token 后，第一位置输出最大变化约 0.7727。

正常的从零 prefill 和逐 token cache 测试不覆盖这条分支。最小正确修复可以只是拒绝当前不支持的调用；不必为这一点重建推理框架。核心自检应是“未来输入变化不能影响过去输出”，它比固定某一组注意力权重更贴近因果合同。

### 6.2 稳定性要检查运算顺序

位置：`tiny_train_generate.py:sample_from_logits`。

有限 logits `[1000,999]` 和正有限温度 `1e-308` 在 `logits/T` 处溢出，随后 `inf-inf` 产生 NaN。先中心化能够处理这个特定例子。它与上一轮 Softmax 的问题不是同一行代码，却有相同根源：只知道某个稳定公式的名字，没检查完整计算路径。

修复仍要说明极端异号输入下中心化本身可能超范围。不能从“本反例修好了”跳到“所有有限输入都已稳定”。

### 6.3 余弦：真零向量与数值下溢不同

位置：`retrieval_lab.py:cosine_similarity`。

与自身比较时，`[1e200,1e200]` 返回 NaN，`[1e-200,0]` 被判成零向量。这两者都不是数学意义上的零向量，正确 cosine 都为 1。

对于纯方向比较，可先按分量尺度归一化，再求范数和点积；配合非有限输入检查及相应容差。仅在分母加 epsilon 不能解决平方、累加和范数乘积的溢出。此问题应同步回数学页，避免正文继续将“零分母保护”笼统命名为稳定工程近似。

### 6.4 最短路：图论中的无穷与 float inf

位置：`graph_algorithms.py:dijkstra_distances`。

`a→b=1e308`、`b→c=1e308` 都是允许的有限权重，但候选长度超出浮点范围，c 留在 inf。BFS 仍能到达 c。

不必为教学实现支持任意大数；必须的是解释并执行范围合同。可以选择保守拒绝超范围累加，也可以分别表示超范围和不可达。若有较短替代路径，遇到某条溢出候选就拒绝是保守策略而非唯一策略，需要说清。

### 6.5 概率结构保证依赖“同一个键”的定义

位置：`retrieval_lab.py:_stable_hash`、`BloomFilter`。

程序对 `repr(value)` 做确定性散列，并接受任意 object。两个相等但插入顺序不同的字典表示不同；加入前者后查后者，实测 False。

准确诊断不是“Bloom filter 出现了理论禁止的随机假阴性”，而是“接口把 Python 对象相等与 repr 字节相等混在一起”。不同编码自然是不同键。任意 object 的 repr 也可能包含进程相关信息，不能由底层 digest 确定就推断输入编码跨进程稳定。[S8]

本轮应先缩小到明确的字符串／字节键或必要的规范编码，不新建通用序列化工程。

## 七、安全：警告与权限边界必须分开

### 7.1 checkpoint 加载不能自动降级

原 `load_checkpoint()` 在受限 `weights_only=True` 调用抛出 TypeError 后自动重试无该参数调用。用 mock 证实了两次调用；没有加载任何真实 pickle。

在不支持受限加载的旧环境里，这使默认路径进入更宽的反序列化能力。警告文字“只处理可信来源”不是用户明确授权，也不能保证所有文件都满足来源条件。应默认停止并报告兼容性问题；必要的可信旧格式转换独立处理。受限加载本身也不应被夸大为完整沙盒。[S6]

### 7.2 resolve 之后，原链接已经不是链接

原 LoRA 路径函数先 resolve，再检查 is_symlink。临时目录中的内部链接被接受，返回的是普通目标路径。

这个证据只证明“禁止链接”的字面承诺没有被执行，不证明能逃出产物根目录；原 containment 仍有作用。应选择并明确真实政策：允许根内规范化链接，或在正确阶段拒绝原路径／组件中的链接。同时说明竞态边界。[S7]

这两项体现同一种维护原则：**安全说明应描述代码实际执行的限制，不是代码旁边的一句期望。**

## 八、对可理解性的进一步改造，不增加知识覆盖

### 8.1 用少量贯穿案例，代替大量互不相干的例子

可在已有内容中形成四条链：

“Softmax→浮点→温度采样→交叉熵→梯度检查”；
“DFT→相位→可逆表示→谱特征→信息损失”；
“检索→指标定义→坏输出→证据支持→可复现 trace”；
“算法输入合同→键相等／浮点范围→反例→测试”。

每条链使用已有页，必要时补中间解释和明确关系，不新增课程。

### 8.2 将读者真正需要跨越的台阶写出来

不应只问“本页是否有定义／公式／例子”，还要问：哪个符号首次出现？哪个中间式被跳过？这个反例破坏的是哪条前提？代码哪个分支体现定义？同一个词在前后是否变了含义？

例如 Adam 一页的真正台阶不是记住两个帽子，而是认识到分子分母的偏差共同决定方向；DFT 一页则是区分变换、显示和丢弃信息。这类台阶通常只需几段精确解释，胜过增加一串术语链接。

### 8.3 保留已成熟的内容，别被整改冲动破坏

统计章节已经包含独立性、配对和聚类层面的限定；投影／SVD 已有推导与低秩边界；哲学专题已有命题、反例和来源台账；RAG 已区分结构引用与事实支持。新合同明确要求保留并兑现这些优点，而不是再造平行体系。

“更高级”的一个重要标志，是能够准确地说“这里本来就做对了，不需要动”。

## 九、两份文件如何分工

`AGENTS.md` 放长期不变量：启动与权限、文件职责、理解标准、数学与数值合同、证据、字段、链接、代码安全、检查分级、批次交付和生命周期。它不承担全部历史任务列表。本次文件控制在约 20 KB，给默认指令容量留下空间；实际全局和嵌套指令仍须检查。[S1]

`CHANGE.md` 放一次性任务：冻结新主题、修复具体问题、继承上一轮未解决问题、机器契约 v2、16 页元数据试点、六域原内容改造、语义链接与哲学回填、真实工作入口和最终删除条件。它必须由 AGENTS 主动要求读取，不能依赖自动发现。[S1]

删除条件不是“目录看起来整洁”或“任务做了一大半”，而是问题有处理结果、验证可定位、未授权改动已回滚、长期规则已落地，并在日志中保存验收证据。秘密和已确认实质错误不能通过换状态逃避。
