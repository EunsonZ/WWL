# 复杂度模型、渐近分析与摊还分析

## 本课目标

学完后，你应该能够：

- 在写复杂度前明确输入规模、基本操作和讨论的情形；
- 区分 `O`、`Ω`、`Θ`，不把它们误当作精确耗时；
- 区分最坏、平均（期望）与摊还代价；
- 用求和和记账法分析动态数组扩容；
- 说明 RAM 模型结论与缓存、I/O 等现实成本的边界。

## 1. 复杂度不是速度的口号

“算法是 `O(n)`”缺少三个答案：`n` 是什么、算什么动作、讨论什么情形？在线性表中找目标值时，可把 `n` 定义为元素数，把“比较当前元素和目标”定义为一步。目标在首位只需一次比较；目标不存在则要比较 `n` 次。

复杂度在同一代价模型中描述**随规模增长的趋势**，用于排除无法扩展的方案。它不直接回答“这台电脑会运行几毫秒”，也不自动包含网络、磁盘、解释器、垃圾回收、缓存未命中或锁竞争。

> [!tip] 写下复杂度前先问
> 1. 输入规模是元素数、字节数、字符串总长度，还是图的边数？
> 2. 基本步骤是比较、一次数组读写、哈希，还是一次磁盘请求？
> 3. 要的是最坏、对某分布的期望，还是操作序列的摊还代价？

## 2. RAM 模型：可比较的简化，不是硬件说明书

常见的 word-RAM 模型假定：一个机器字可容纳常见值和索引；加减、比较、按下标访问一个机器字的成本为常数；随机访问不因地址远近而改变成本。因此已知数组下标的一次读写是 `Θ(1)`，扫描 `n` 个槽位是 `Θ(n)`。

它刻意压平现实差异：

| 被压平的现实 | 为什么会改变实测时间 | 应补充什么 |
| --- | --- | --- |
| 缓存与内存层级 | 连续扫描和随机指针追逐的未命中率不同 | 说明局部性，在目标机测量 |
| 大整数、长字符串 | 一次“比较/复制”可能要处理很多字节 | 把位数、键长或对象大小列为参数 |
| 分配与回收 | 分配器、页缺失、GC 的延迟会波动 | 单列分配次数、峰值空间与延迟分布 |
| 磁盘、网络、GPU | 一次远端访问远非普通内存读写 | 使用 I/O、通信或带宽模型 |

这不推翻渐近结论：`Θ(n)` 的顺序扫描通常比 `Θ(n²)` 的全量成对处理更能扩展。但两个同为 `Θ(n)` 的方案，连续数组通常比随机链式追逐更容易利用缓存。详见 [[计算机知识/30-计算机系统/04-缓存局部性带宽与延迟|缓存、局部性、带宽与延迟]]。

## 3. 渐近记号给出函数边界

### 先用小规模看增长，再读符号

先假设每轮都把候选数量减半。下面的表只是在数“要减几轮”，不要求先背对数：

| 初始候选数 `n` | 反复减半到 1 的轮数 |
| ---: | ---: |
| 1 | 0 |
| 2 | 1 |
| 4 | 2 |
| 8 | 3 |

所以当 `n` 翻倍时，轮数通常只多 1；这正是 `log₂ n` 在本课中的直觉。第一次阅读先能解释这张表即可。下面的 `c`、`n₀` 和量词定义是**二刷时用于严格说明“增长同阶”**的工具，不必把它们误当作某台机器的计时公式。

令步骤数为 `T(n)`，当 `n` 足够大时：

- `T(n) ∈ O(f(n))`：存在 `c > 0` 和 `n₀`，对所有 `n ≥ n₀` 有 `T(n) ≤ c·f(n)`；这是上界。
- `T(n) ∈ Ω(f(n))`：存在 `c > 0` 和 `n₀`，对所有 `n ≥ n₀` 有 `T(n) ≥ c·f(n)`；这是下界。
- `T(n) ∈ Θ(f(n))`：同时是 `O(f(n))` 和 `Ω(f(n))`；这是同阶的紧确界。

例如 `T(n) = 3n + 7`。当 `n ≥ 1`，它不大于 `10n`，也不小于 `3n`，故为 `Θ(n)`。忽略常数和低阶项是因为它们不改变增长类别，不是因为常数永远不重要。

| 形式 | 直觉例子 | 不应推出的结论 |
| --- | --- | --- |
| `Θ(1)` | 已知下标的一次访问 | 固定纳秒或恰一条指令 |
| `Θ(log n)` | 每轮把范围缩小固定比例 | 无序数据也能二分 |
| `Θ(n)` | 每项至多检查一次 | 每项实际处理成本完全相同 |
| `Θ(n log n)` | 约 `log n` 层、每层处理 `n` 项 | 必然胜过小输入上的任何平方算法 |
| `Θ(n²)` | 全量成对比较 | 必然不能使用 |

> [!warning] `O` 不是“平均”的符号
> 最坏时间可以是 `O(n)`，平均时间也可以是 `O(n)`。`O` 只陈述上界；“最坏”“期望”或“摊还”必须另写。

## 4. 最坏、期望与摊还回答不同的问题

对规模为 `n` 的输入，设实际代价为 `C(x)`：

- **最坏代价**是合法输入中的 `max C(x)`，给出单次请求的保证；
- **平均/期望代价**是相对指定分布 `D` 的 `Eₓ∼D[C(x)]`，不是最好和最坏的中点；
- **随机算法的期望**还须对算法自身随机性取期望，不能与输入分布混为一谈；
- **摊还代价**约束任意合法操作序列的总成本，无须输入随机。

### 手工例子：顺序查找

假定长度 `n` 的表中目标必然存在、且每个位置等概率。第 `i` 个位置需要 `i` 次比较：

```text
(1 + 2 + ... + n) / n
= n(n + 1) / (2n)
= (n + 1) / 2
= Θ(n)
```

若目标不存在的概率为 `p`，必须把其 `n` 次比较按 `p` 加入期望。若真实查询偏向热门元素，均匀分布并不合适；报告“平均复杂度”时应写清命中率和分布。

## 5. 从循环到求和，而不是数花括号

```text
for i from 0 to n - 1:
    do constant work
```

总成本为 `Σ 1 = n`，即 `Θ(n)`。

```text
for i from 0 to n - 1:
    for j from 0 to i:
        do constant work
```

内层次数为 `1 + 2 + ... + n = n(n + 1)/2`，即 `Θ(n²)`。而 `value ← 1`、每轮令 `value ← 2 × value` 直到 `value ≥ n` 时，运行约 `log₂ n` 轮，故为 `Θ(log n)`。循环嵌套不必然平方；应写总执行次数或不变量。

## 6. 摊还分析：一次昂贵，不等于每次昂贵

动态数组容量满时，追加需要申请更大连续区并复制已有元素，一次可花 `Θ(n)`；但若容量每次翻倍，从空表追加前 `m` 个元素时（`m ≥ 2`），所有扩容复制量至多为：

```text
1 + 2 + 4 + ... + 2^floor(log₂(m - 1)) < 2m
```

当 `m = 0` 或 `m = 1` 时没有旧元素需要复制；上式不适用，因为 `log₂(m-1)` 在 `m=1` 会变成 `log₂ 0`，但结论仍由直接计数成立。再加上 `m` 次写入新元素，总成本小于约 `3m`，即 `Θ(m)`；所以每次追加的**摊还**成本为 `Θ(1)`。某一次满容量追加仍是最坏 `Θ(n)`，不能把“摊还常数”偷换成“每次最坏常数”。

### 记账法

给每次普通追加收取固定数量的“虚拟硬币”：一枚支付本次写入，额外硬币随元素保留，下一次扩容时共同支付复制。只要增长倍率是固定且大于 1，就可选一个固定收费使账户不为负。硬币不是实测时间，而是总成本有线性上界的证明。

若容量每次只增加 1，复制总量是 `1 + 2 + ... + (m - 1) = Θ(m²)`，摊还追加反而为 `Θ(m)`。所以结论依赖实现策略，而非“名字叫动态数组”。

## 7. 空间也要说明口径

空间 `O(1)` 通常指不含输入的辅助空间；输出、递归调用栈、缓存、预留容量是否计入必须写清。还要说明元素是否固定字长。动态数组逻辑长度为 `n`，容量可大于 `n`：用未使用槽位换取了追加的摊还代价和潜在的峰值空间。

## 常见误解与边界

- **“`O(1)` 一定比 `O(n)` 快。”** 小输入、常数、缓存未命中和 I/O 都可能反转实测结果。
- **“平均不需要假设。”** 平均永远相对某个分布；未说明分布就不可审计。
- **“摊还就是概率。”** 摊还通常对任意合法序列给出确定性总成本界；期望依赖概率。
- **“两个循环必是平方。”** 若一个指针全程只前进，总次数可以线性。
- **“RAM 的 `O(1)` 说明数据在缓存。”** 它不保证缓存命中、页面驻留或分配成功。

## 练习

1. 为未排序表中的第一次匹配定义规模与基本操作，给出最好、最坏和“均匀存在”的期望比较次数。
2. 分析每轮令 `i ← 2i` 与每轮令 `i ← i + 2` 的循环；解释为何不属同一增长级别。
3. 手工列出动态数组追加前 10 个元素的复制量，验证总量小于一个常数乘以 10。
4. 比较连续扫描一百万个固定宽度整数与沿一百万个随机节点的 `next` 行走：它们在 RAM 模型中各是什么量级？再列出两项缓存现实差异。

## 成功标准

- 你能在写 `O(...)` 前说明参数、基本操作和情形；
- 你能区分上界、下界、同阶、最坏、期望和摊还；
- 你能证明翻倍扩容的总复制量线性，并指出单次最坏代价；
- 你能说明同阶算法仍要考察局部性、元素大小与目标环境测量。
