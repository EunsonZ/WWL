# 标准库容器与算法：复杂度只是选择的一半

> **学习位置**：[[计算机知识/00-开始/课程地图/02-C++-课程地图|C++课程地图]] · **适用边界**：C++20；ABI、容器实现与后续标准不混同。

## 先按访问模式选择，而不是按名称熟悉程度

`vector` 连续存储，适合遍历和随机访问；中间插入删除需要移动元素。`deque` 分段存储，首尾操作方便，但不是整段连续缓冲区。`list` 节点独立，已知位置时插删可为常数级，却要付出指针、分配和较差局部性的成本。

有序关联容器提供按比较关系组织的查询；无序关联容器依赖哈希和相等关系，通常有平均常数级查找，但最坏情况、扩容及攻击输入必须考虑。标准规定接口和复杂度要求，不要求每种实现都采用你见过的那一种树或桶布局。

## 迭代器能力决定算法是否合法

输入迭代器适合单向消费，前向迭代器支持多遍遍历，双向迭代器可后退，随机访问迭代器支持常数级跳转，连续迭代器再提供更强布局性质。`std::sort` 需要随机访问能力，所以不能直接对 `list` 迭代器使用；链表有自己的排序成员操作。

区间通常写成 `[first,last)`，空区间由二者相等自然表示。尾后迭代器不是最后一个元素，不能解引用。半开区间之所以重要，是它让长度、拼接和二分边界可以使用同一套代数。

## 失效规则是正确性约束，不是性能提示

`vector` 扩容会使旧存储上的指针、引用和迭代器失效。即使没有扩容，某些插入删除也会让受影响位置的迭代器失效。无序容器 rehash 主要影响迭代器，引用和指针的具体保证与擦除等操作必须分别查文档；不能用一句“unordered_map 操作都会失效”概括。

```cpp
for (auto it = values.begin(); it != values.end(); ) {
    if (*it < 0) it = values.erase(it);
    else ++it;
}
```

对 vector 逐项擦除可能退化为二次搬运，通常可以采用 erase-remove 惯用法或 C++20 的合适 `erase_if` 接口。`remove_if` 自身只重排逻辑保留区间，不改变容器大小；物理删除是后续容器操作。

## 比较器与哈希器要满足语义规律

排序比较器通常要求严格弱序。`a<=b` 不是合格的“升序比较器”，因为同一个值与自身比较会为真。浮点含 NaN 时，普通 `<` 未必满足希望的全域排序关系，需要限制输入或定义显式排序策略。

无序容器要求相等键得到相同哈希。若改变键中参与哈希或比较的字段，元素可能仍在旧桶里但按新键找不到；因此容器通常限制直接修改键。哈希值不同不能证明业务不同，哈希值相同也不能证明值相等。

## 惰性 Ranges 的状态和生命周期

Ranges 将“区间”和“算法”组织成更可组合的接口，views 常按需计算，不一定立即产生独立容器。一个 view 可能借用底层数据，也可能依赖谓词捕获；返回 view 时必须检查底层容器和捕获对象的寿命。

```cpp
auto positives = values | std::views::filter([](int x){ return x > 0; });
```

这不是一个独立保存所有正数的新数组。随后修改 `values`、让迭代器失效、或在并发线程无同步地改数据，都可能破坏使用前提。惰性也意味着计算发生在消费时，而不是创建管道时；有副作用的谓词会让行为更难推断。

## 数值算法与并行执行策略

`accumulate` 的初始值决定累积类型，`std::accumulate(v.begin(),v.end(),0)` 可能在 `int` 中累加，即使容器元素更宽。选择正确初值并检查范围，比最后把结果转成 `long long` 更重要。

并行或可重排归约不必保持逐项求和顺序，浮点加法不满足精确结合律，结果可能变化。执行策略也有异常处理和调用约束，不能把加上 `par` 当成所有循环的安全加速方式。

## 练习与答案

只需要最小的 10 个元素，为什么不一定完整排序？可以考虑大小为 10 的堆、`partial_sort`、`nth_element` 后排序前缀，分别比较输入规模、是否需要稳定性、是否允许修改原数组和输出顺序。用算法规格选择实现，而不是一律 `sort`。

一个列表有一百万个整数，链表插入是常数时间就一定更快吗？若插入前还需找到位置，搜索成本仍在；即使位置已知，分配、缓存和访问模式也可能主导。复杂度给出增长趋势，机器模型解释常数项与瓶颈。
