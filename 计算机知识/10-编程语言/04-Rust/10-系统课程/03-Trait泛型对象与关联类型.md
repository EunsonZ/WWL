# Trait 与泛型：把能力、实现选择和抽象成本分开

> **学习位置**：[[计算机知识/00-开始/课程地图/03-Rust-课程地图|Rust课程地图]] · **适用边界**：Rust 2021 edition 兼容示例；2024 edition 差异另行标识。

## Trait 表达可调用能力，但规律仍需约定

一个 `T: Ord` 的函数可以使用全序比较接口；一个 `T: Iterator` 的函数可以按约定逐项取得元素。编译器能检查实现是否提供必要成员，但不能对任意用户代码证明比较的传递性、哈希与相等的一致性或迭代器是否终止。

```rust
fn maximum<T: Ord>(left: T, right: T) -> T {
    if left >= right { left } else { right }
}
```

这里参数按值进入，返回一个拥有值，另一个值会按规则清理。若希望借用而不移动，应重新设计引用版本并说明返回引用的关系，而不是只在实现内部补几个 `&`。

## 关联类型与泛型参数不同

`Iterator` 使用关联类型 `Item`，使某个迭代器实现有一个明确的输出元素类型。泛型 trait 参数可以表达同一实现者针对不同输入类型的多种关系。选择关联类型还是参数，应问“这个角色由实现唯一决定，还是调用场景需要多种实例”。

关联常量、默认方法、supertrait、泛型关联类型和 const generics 进一步表达约束。GAT 可以让关联类型本身带生命周期等参数，适合借用输出与接收者相关的接口；它不是自动解决所有借用迭代器设计的万能按钮。

## 静态分派、opaque 类型和动态分派

泛型函数通常按具体类型单态化，增加内联机会但可能增加代码体积。返回位置 `impl Trait` 隐藏具体类型，调用者只知道约定能力，但同一个返回实现通常仍对应一个确定具体类型，不能把两个不相关类型随意放进两个分支返回。

`Box<dyn Trait>` 或 `&dyn Trait` 使用动态分派，适合运行时异构实现。不是所有 trait 都满足 dyn compatibility；泛型方法、某些 Self 用法和关联特征等会影响可用性。常见实现具有数据指针及方法表相关信息，但其布局不是稳定的 C ABI。

选择静态或动态不应只看一张快慢表。开放扩展性、二进制边界、编译时间、代码尺寸、分配和调用频率都需要权衡。

## 闭包的 Fn 家族由使用方式决定

`Fn` 可通过共享访问调用，`FnMut` 需要可变访问，`FnOnce` 可以消费自己而只保证调用一次。能力存在包含关系：能重复只读调用的闭包，也可以用在只要求调用一次的地方。

`move` 决定捕获方式，不直接决定闭包一定只实现 `FnOnce`。一个 move 闭包若只读取所拥有的字符串，仍可能多次调用；如果把捕获字符串作为返回值移走，则会消费捕获状态。

```rust
let prefix = String::from("item:");
let describe = move |n: i32| format!("{prefix}{n}");
assert_eq!(describe(1), "item:1");
assert_eq!(describe(2), "item:2");
```

## 迭代器的所有权轨迹

`iter()` 产生共享引用，`iter_mut()` 产生可变引用，`into_iter()` 的行为由接收类型决定，常见拥有容器会交出元素。适配器通常惰性，`map` 创建后未消费，不代表内部副作用已经执行。

```rust
let numbers = [2_i32, -1, 4];
let total: i64 = numbers.iter().copied()
    .filter(|n| *n > 0).map(i64::from).sum();
assert_eq!(total, 6);
```

`copied` 只适用于可复制元素；`cloned` 调用克隆协议，可能昂贵。先扩大类型再求和可避免中间窄类型溢出，但最终总和仍需与输入上界一起验证。

## 一致性规则与 newtype

orphan/coherence 规则限制任意为外部类型实现外部 trait，避免依赖组合产生互相冲突的含义。newtype 用本地包装类型创建清楚的语义边界，例如 `Meters(u32)` 与 `Milliseconds(u32)`，同时提供受控转换。

`Deref` 适合指针式抽象，不应只为省写 `.inner` 就让所有包装类型自动暴露内部能力。`From` 表达合适的不可失败转换，`TryFrom` 表达可能失败的转换；`AsRef` 与 `Borrow` 的合同也不完全相同，后者与相等和哈希等语义关系尤其相关。

## 练习与答案

写一个接收任意“可迭代字符串切片”的函数，比直接接收 `Vec<String>` 有什么收益？调用者可以传多种来源，不必先物化拥有容器。代价是签名可能更复杂，错误信息与借用关系更难读。若 API 只用于一个小程序，具体类型反而可能更清晰；抽象应服务真实复用。
