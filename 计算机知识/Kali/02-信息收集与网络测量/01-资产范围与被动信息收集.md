# 资产范围与被动信息收集

**先修关系：** [[计算机知识/Kali/00-导航与方法/02-授权范围与风险分级|授权范围与风险分级]]；[[计算机知识/Kali/01-系统与网络基础/06-TCPIP路由DNS与TLS|TCPIP路由DNS与TLS]]。

## 先证明资产归属，再收集细节

开放来源情报（OSINT）指从可合法访问的公开来源收集、评估和关联信息。它不意味着信息可靠，也不意味着可以无限制聚合个人资料。安全评估的目标是确认组织自己暴露的域名、服务与配置线索，不是给个人建立侵扰性画像。

一个域名出现在证书日志中，只说明某个时间点有相应证书记录；共享 IP、云租户、CDN 与历史解析都可能破坏“同 IP 就同所有者”的推断。把候选资产与授权资产分开，后者必须由范围文件或负责人确认。

## 一条资产记录至少包含什么

建议使用字段：候选标识、来源、取得时间、来源记录时间、归属依据、授权状态、置信度和下一步验证。不要把“搜索到”直接填成“允许扫描”。置信度是证据评价，不是任意写一个小数装作概率模型。

课程示例：证书记录出现 `api.lab.test`，内部台账只批准 `web.lab.test`。正确处理是把前者列为待确认对象；不能因为它“看起来属于同一组织”就交给自动扫描器。

## 工具如何分工

**theHarvester** 聚合域名、主机等信息，来源与参数决定是否仅访问第三方数据源，还是进一步进行 DNS、截图或主动检查。Kali 当前帮助使用 `theHarvester`；小写同名入口在所读文档中标为弃用。[^s1]

```bash
# 只读取帮助，不访问目标
theHarvester -h
# 以下是操作形态：必须先设置书面授权域名，并确认第三方服务的数据政策
# theHarvester -d "$DOMAIN" -b crtsh -l 20 -f ./output/harvester
```

不能为了“结果更多”直接选择所有来源；部分需要 API 密钥、收费账户或包含不适合本次任务的数据。密钥应保留在本机受限配置中，不放入 Vault 和压缩包。

**Amass / Subfinder** 更偏域名资产发现；**Recon-ng** 用模块和工作区组织收集；**Maltego** 用实体关系与转换表达关联；**SpiderFoot** 可以自动关联多个来源。这里给的是选型层，不保证每个模块都默认被动或不外传查询内容。要审阅模块/transform 说明、第三方去向、缓存和速率，再决定是否使用。当前安装入口由 `apt show` 和 Kali 工具目录确认。[^s2]

**whois / RDAP** 回答注册信息问题，不直接证明实际运营者、资产当前用途或测试授权。隐私代理、信息脱敏与托管关系会限制结论。不要把历史个人联系方式复制到分享笔记。

## 从线索进入受控验证

先做去重与规范化，再核对当前 DNS、证书或资产台账。去重不能只按 IP：同 IP 可能承载许多虚拟主机；也不能仅按小写 URL 合并所有路径，因为某些应用路径区分大小写。

每次从被动来源转为实际访问，都跨越了方法边界。截图、端口连接、目录探测和漏洞模板执行已经是主动动作。下一步见 [[计算机知识/Kali/02-信息收集与网络测量/02-DNS域名与证书信息|DNS 与证书信息]]，最后交给 [[计算机知识/Kali/02-信息收集与网络测量/03-Nmap主机发现与端口状态|范围固定的网络测量]]，而不是让发现工具自动递归扩张目标。

## 反例与自检

“第三方数据库说 2024 年该 IP 运行某服务，所以今天仍有相同漏洞。”这里缺少当前性、归属、补丁和配置证据。它只能成为待核查假设。

自检：一个工具标榜 OSINT，却自动打开收集到的每个网站，它还是纯被动吗？对目标而言已产生直接访问；对第三方而言查询本身也可能被记录。方法标签应按实际行为写，不按工具营销名称写。

## 从一条线索到一项可测资产的去重规则

将资产标识和来源分开保存。同一域名可能解析到多个地址，同一 IP 可能服务多个租户，同一证书可能覆盖多个名字；不能简单按 IP 去重后抹掉业务边界。建议记录合成资产 ID、原始名字、地址族、观察时间、来源类别、归属证据、允许端口和当前状态。

例如证书记录出现 `archive.lab.test`，它只能作为历史名字线索；再查询 DNS 才得到当前解析观察；再由资产负责人确认，才能把具体服务放入批准范围。三个步骤是证据累积，不是把搜索结果自动升级为授权。

被动工具的结果也要保存查询条件。外部搜索平台看不到一条记录，可能源于采样、索引更新或访问权限，不能推成资产不存在。反之，搜索页面中的历史 IP 也不能直接作为今天的扫描目标。

## 证据表怎样避免过度收集

公开来源中的个人信息、仓库路径或内部命名不必全部复制到知识库。只保存支持本次结论所需的最小字段，必要时用局部摘要或脱敏截图，并保留合法的来源定位。范围模板负责授权，资产表负责观察，两者不应混成一个无边界“目标大全”。

工具选择遵循输入到输出的合同：theHarvester 偏向公开信息线索，Amass/Subfinder 等偏向域名发现，不同模式的请求对象与数据源不同。后续受控查询必须回到 [[计算机知识/Kali/02-信息收集与网络测量/02-DNS域名与证书信息|DNS 响应判读]]，而不是因为名称出现在工具输出里就默认归属已确认。
