# CS:APP 3e 官方主题对应与来源边界

这张表回答一个窄问题：CS:APP 第三版某个章节/二级主题，在 WWL 应从哪里读、带着哪个问题去读、回来能补上什么，及其当前边界是什么。它不把“出现相同关键词”算作覆盖，也不以页面数换算掌握度或学科完成率。路线页中的概念例是 `int xs[3]={2,5,1}` 与 `sum(xs,3)`；构建实践使用独立的可运行例 `uint32_t values[4]={7,11,23,59}` 与 `sum_u32(values,4)`，输出 `100`。二者共享“数组求和”的教学角色，不共享类型、布局、输入、符号名或本机观察结果。

**状态含义**：`已有` 指已定位到连续主解释和至少一个可检查例子或适当的练习；`部分` 指概念或相邻机制已有，但这里承诺的连接、平台实践或专有细节尚未定位；`未定位` 指本次盘点没有找到可承担该承诺的页面。`核验` 只说明本次是否已把官方目录和目标页的阅读承诺交叉核对；它不是“内容的全部事实均已外部认证”。

> [!important] 什么来源实际可得
> 本表依据 [CS:APP 3e 官方目录与前言](https://csapp.cs.cmu.edu/3e/pieces/preface3e.pdf)（十二章、Part I–III、Appendix A 的编号与主题）、[书目页](https://csapp.cs.cmu.edu/3e/about.html)、[勘误](https://csapp.cs.cmu.edu/3e/errata.html)、[学生资料](https://csapp.cs.cmu.edu/3e/students.html)、[实验页](https://csapp.cs.cmu.edu/3e/labs.html) 与现有 WWL 正文。公开的目录、辅助材料和无解自学实验不等于取得商业正文、教师包或解答；因此本库写原创解释和新例，不复制原题、答案或整章文字。CS:APP 3e 的 x86-64/C/gcc/Linux 语境也不自动覆盖当前 arm64/macOS/Mach-O 观察。

> [!note] 怎样使用一行
> 先读“去读/带问”，只读目标页指定的机制；回来完成“回来补”的一句话。若状态是“部分”或“未定位”，不要把相邻页当作承诺已经兑现。表中“实践”是验证/实践关系，不是先修关系；“反例”是用来收紧结论的情况，不是另一篇平行课。

## 覆盖边界和下一次扩展的依据

当前最明确的承重缺口不是“缺少十二章标题”，而是以下四个可检查桥接点：同一 C 符号跨构建/装载、结果合同下的 C 循环优化、`EINTR`/短 I/O/信号回收、同一请求在三种服务模型的所有权。它们分别由本路线所列四个原创实践入口承担；实践尚未实际运行或平台不匹配时，应保留 `partial`，不升级本表状态。

以下项目暂不冒充由 CS:APP 对应完成：Windows 或 Darwin 内核细节、AArch64/RISC-V ABI、完整保守 GC、现代 C/C++ 内存模型、NUMA/GPU 细节、TLS/HTTP2/QUIC、CGI/完整 Web 部署、分布式一致性和生产安全。它们可以与本路线比较，但各自需要独立来源、对象模型和验证。
