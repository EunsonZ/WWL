# 异常、文件 I/O 与上下文管理

这一课把「失败」当作程序输入的一部分：只处理你知道如何恢复的错误，始终关闭已打开的资源，并把文件写入做得可检查、可恢复。它适合命令行脚本、小型数据处理程序和配置读写代码。

## 学完能做什么

- 读懂异常层级，针对具体异常使用 `try` / `except` / `else` / `finally`；
- 用 `raise ... from ...` 保留底层原因，并定义领域自己的异常；
- 用 `pathlib.Path` 和 `with` 安全处理文本、二进制、JSON、CSV；
- 识别路径遍历、不可信反序列化，以及「写到一半」这三类常见 I/O 风险。

## 1. 异常不是普通的分支

语法正确的代码在运行时仍可能失败，例如文件不存在、权限不足、数据格式错误。异常对象按类继承：所有异常都在 `BaseException` 之下；日常应用错误通常在 `Exception` 之下。`KeyboardInterrupt`、`SystemExit` 等不在 `Exception` 分支中，因此不要使用裸 `except:`，也不要为方便而吞掉 `Exception`。

从具体到一般安排处理器；第一个匹配的处理器获胜：

```python
from pathlib import Path

path = Path("settings.json")

try:
    raw = path.read_text(encoding="utf-8")
except FileNotFoundError:
    print("还没有设置文件，使用默认设置")
except PermissionError as exc:
    raise RuntimeError(f"没有读取权限：{path}") from exc
except OSError as exc:
    # 其他操作系统层面的 I/O 错误：磁盘、设备、路径等。
    raise RuntimeError(f"无法读取 {path}") from exc
else:
    print(f"读取了 {len(raw)} 个字符")
```

`OSError` 覆盖了许多文件系统错误，`FileNotFoundError` 和 `PermissionError` 是它的更具体子类，所以必须排在前面。除非你能真正恢复，未知错误应继续向上传播；在顶层记录后用不带参数的 `raise` 重新抛出。

### `try` 四个部分各自负责什么

| 部分 | 何时运行 | 应放什么 |
| --- | --- | --- |
| `try` | 可能抛出、且你准备处理的最小操作 | 例如一次 `read_text()` 或 `int()` |
| `except` | 匹配到指定异常时 | 恢复、转换为领域错误、或记录后重新抛出 |
| `else` | `try` 没有异常且未提前离开时 | 依赖成功结果的后续动作 |
| `finally` | 无论成功、处理或未处理异常都会运行 | 必须清理的资源；避免 `return` / `break` / `continue` |

把无关代码放进 `try` 会扩大捕获范围。尤其将成功后的解析或业务逻辑放进 `else`，该逻辑发生的异常就不会被前面的 `except` 误当成「打开文件失败」。`finally` 中的 `return` 会遮蔽原本的异常或返回值，通常是 bug。

## 2. 主动报告错误：`raise`、链式原因与自定义异常

库或模块的调用者不需要猜测低层异常如何映射到业务含义。将它转换成清晰、可捕获的领域错误，并用 `from` 保存真正原因：

```python
import json
from pathlib import Path


class SettingsError(Exception):
    """设置文件不可用或不符合本程序要求。"""


def load_port(path: Path) -> int:
    try:
        data = json.loads(path.read_text(encoding="utf-8"))
        port = data["port"]
    except FileNotFoundError as exc:
        raise SettingsError(f"找不到设置文件：{path}") from exc
    except json.JSONDecodeError as exc:
        raise SettingsError(f"设置文件不是有效 JSON：{path}") from exc
    except (KeyError, TypeError) as exc:
        raise SettingsError("设置中缺少 port，或结构不正确") from exc

    if not isinstance(port, int) or isinstance(port, bool) or not 1 <= port <= 65535:
        raise SettingsError("port 必须是 1 到 65535 的整数")
    return port
```

`raise NewError(...) from exc` 让 traceback 明示「直接原因」；它比丢弃原异常更利于诊断。只有在确实不应暴露底层细节时，才审慎使用 `from None`。自定义异常通常直接继承 `Exception`，保持简单；需要调用者作不同恢复时再增加有意义的属性或子类。

### EAFP 的边界

Python 常用 EAFP（先做，再处理预期的失败），例如直接 `path.read_text()` 并捕获 `FileNotFoundError`，避免「先检查、后操作」之间状态变化的竞态。它不等于捕获一切：

```python
# 好：只包住一个预期会失败的转换。
try:
    count = int(user_text)
except ValueError:
    count = 0

# 不好：拼写错误、网络错误、逻辑错误都会静默伪装成 0。
try:
    count = int(user_text)
    count += config["bonus"]
except Exception:
    count = 0
```

预检查仍有价值：它可改善用户提示、避免昂贵操作，或实施访问控制；但安全决定不能只依赖 `exists()`、字符串前缀或一次检查结果。

## 3. `pathlib` 与文件模式

优先以 `Path` 表示路径：`/` 拼接路径片段，可读性和跨平台语义都优于手写分隔符。`Path.read_text()` / `write_text()` 适合小文本；大文件用 `open()` 逐行迭代，避免一次读入内存。

```python
from pathlib import Path

report = Path("output") / "report.txt"
report.parent.mkdir(parents=True, exist_ok=True)

# 文本模式：得到 str；明确编码，避免依赖机器默认值。
report.write_text("第一行\n第二行\n", encoding="utf-8", newline="\n")
with report.open("r", encoding="utf-8", newline=None) as file:
    for line in file:
        print(repr(line))

# 二进制模式：得到 bytes；不要传 encoding。
payload = Path("packet.bin")
payload.write_bytes(b"\x89PNG\r\n\x1a\n")
assert payload.read_bytes().startswith(b"\x89PNG")
```

文本模式（`"r"`、`"w"`、`"a"`、`"x"`）读写 `str`，二进制模式加 `"b"` 并读写 `bytes`。`"w"` 会截断既有文件，`"x"` 仅在目标不存在时创建，`"a"` 追加；选择模式前先想清楚恢复策略。读文本时 `newline=None` 会把常见行尾统一为 `\n`；写入可用 `newline="\n"` 固定可移植输出。`encoding="utf-8"` 应显式写出；遇到外部数据的编码错误，应将 `UnicodeDecodeError` 当成可报告的数据问题，而不是盲目忽略。

## 4. `with` 与上下文管理器

文件、锁、网络连接等资源必须及时释放。`with` 会在离开代码块时调用上下文管理器的退出动作，即使块内抛出异常；它通常比手写 `try` / `finally` 更短也更可靠。

```python
from pathlib import Path

def first_nonempty_line(path: Path) -> str:
    with path.open("r", encoding="utf-8") as file:
        for line in file:
            text = line.strip()
            if text:
                return text
    raise ValueError(f"文件没有非空行：{path}")
```

这里 `return` 发生时文件仍会关闭。只有面对不支持上下文管理协议的旧接口，才用 `try` / `finally` 手动释放，并把释放动作放在 `finally`。

## 5. JSON 与 CSV：标准库的安全读写

JSON 适合交换基本结构（对象、数组、字符串、数值、布尔、空值），不是任意 Python 对象格式。解析不可信 JSON 时，捕获 `json.JSONDecodeError`，再验证字段和类型；合法 JSON 也可能不符合你的业务结构。

```python
import json
from pathlib import Path

data = {"name": "Ada", "enabled": True, "tags": ["python", "io"]}
target = Path("profile.json")

with target.open("w", encoding="utf-8", newline="\n") as file:
    json.dump(data, file, ensure_ascii=False, indent=2)

with target.open("r", encoding="utf-8") as file:
    loaded = json.load(file)

assert loaded["name"] == "Ada"
```

CSV 是表格格式，不自动保留 Python 类型。使用 `csv` 时打开文件要传 `newline=""`，并让 `DictReader` / `DictWriter` 处理列名；从 CSV 得到的值默认是字符串，数值须显式转换和验证。

```python
import csv
from pathlib import Path

target = Path("scores.csv")
rows = [{"name": "Ada", "score": 98}, {"name": "Lin", "score": 87}]

with target.open("w", encoding="utf-8", newline="") as file:
    writer = csv.DictWriter(file, fieldnames=["name", "score"])
    writer.writeheader()
    writer.writerows(rows)

with target.open("r", encoding="utf-8", newline="") as file:
    scores = [
        {"name": row["name"], "score": int(row["score"])}
        for row in csv.DictReader(file)
    ]
assert scores[0]["score"] == 98
```

> [!warning] 不要对不可信输入使用 `pickle.load()`。pickle 格式不是安全边界，反序列化恶意数据可执行任意代码。跨信任边界优先 JSON，并在解析后验证结构与范围。

## 6. 临时文件与原子替换（进阶选读）

> [!info] 第一遍可以先跳过
> 前五节已经足以完成异常处理、常见文件读写与资源关闭。可靠替换、崩溃一致性和对抗路径输入涉及操作系统语义与安全边界；需要写重要配置、接受用户路径或准备进入测试与工程实践时，再学习本节和下一节。后续可结合 [[计算机知识/10-编程语言/01-Python/14-测试调试与代码质量|测试、调试与代码质量]]，用失败测试验证中断、非法路径与清理行为。

不要自己以可预测名称创建临时文件；使用 `tempfile`，它会以安全方式创建文件。修改重要文件时，常用模式是：在**同一目录**写入临时文件、完整关闭（必要时 `fsync`）、再用 `os.replace()` 替换目标。读者看到的会是旧文件或新文件，而非通常的半截内容。

```python
import os
import tempfile
from pathlib import Path


def atomic_write_text(target: Path, text: str) -> None:
    target.parent.mkdir(parents=True, exist_ok=True)
    temp_name: str | None = None
    try:
        with tempfile.NamedTemporaryFile(
            mode="w",
            encoding="utf-8",
            newline="\n",
            dir=target.parent,
            prefix=f".{target.name}.",
            delete=False,
        ) as temp:
            temp_name = temp.name
            temp.write(text)
            temp.flush()
            os.fsync(temp.fileno())
        os.replace(temp_name, target)
        temp_name = None
    finally:
        # 若写入或替换失败，清理由本函数创建的残留临时文件。
        if temp_name is not None:
            Path(temp_name).unlink(missing_ok=True)


atomic_write_text(Path("output/settings.json"), '{"theme": "dark"}\n')
```

这降低中断时留下截断文件的风险，但不是万能的崩溃一致性协议：目录元数据持久化、文件权限/所有者保留、跨文件系统替换、并发写者和 Windows 上的占用行为都需要按部署环境额外设计。调用前先备份重要数据，或保留版本化副本。

这里的“同一目录”“跨文件系统”和“符号链接”依赖操作系统层的挂载与权限语义；需要继续追根时，分别回看 [[计算机知识/20-操作系统/01-Linux/03-目录结构挂载与文件系统|目录、挂载与文件系统]] 和 [[计算机知识/20-操作系统/01-Linux/06-用户权限进程与作业控制|文件与目录权限]]。

## 7. 路径遍历：把用户输入限制在根目录内（进阶选读）

用户输入的 `../`、绝对路径和符号链接都可能让「下载目录」外的文件被访问。以下例子把候选路径解析后限制在指定根目录；不在根目录内就拒绝。它适合读取已有的受控文件，但涉及对抗性攻击者、符号链接竞态或高权限操作时，还应使用操作系统级别的目录句柄/权限隔离。

```python
from pathlib import Path


def safe_child(root: Path, user_name: str) -> Path:
    base = root.resolve()
    candidate = (base / user_name).resolve()
    try:
        candidate.relative_to(base)
    except ValueError as exc:
        raise ValueError("路径必须位于允许的目录内") from exc
    return candidate


uploads = Path("uploads")
print(safe_child(uploads, "report.txt"))
# safe_child(uploads, "../../private.txt") 会抛出 ValueError。
```

`Path.resolve()` 会访问文件系统；不要把这个例子误解为只做字符串检查即可安全。若业务只允许单个文件名，最简单的边界通常是拒绝含路径分隔符的输入，并从受控 ID 映射到服务器端已有文件名。

## 动手练习：安全地导入成绩单

写一个 `load_scores(path: Path) -> list[dict[str, object]]`：

1. 用 `with` 和 `csv.DictReader` 读取 UTF-8 CSV，且传 `newline=""`；
2. 每行必须有非空 `name`，`score` 必须能转换为 0–100 的整数；
3. 缺少文件时抛出自定义 `ScoreFileError`，并用 `from exc` 保留 `FileNotFoundError`；
4. 格式错误要说明行号；不要用裸 `except`，也不要把所有错误改成空列表；
5. **进阶选做**：将合格结果用上面的原子写入思想保存为 JSON，并把用户提供的文件名限制在练习目录内。测试时只在临时练习目录操作，保留原 CSV。

### 成功标准

- 正常 CSV 读入后，返回的每项都含 `name: str` 与 `score: int`；
- `missing.csv` 的异常是 `ScoreFileError`，并能在 traceback 中看到原始原因；
- `score=101`、`score=abc`、缺列都被清楚拒绝；
- 导入后文件句柄已关闭：Windows 上也能重命名或删除测试 CSV；
- **进阶选做**：输出失败时不会产生半截 JSON，且 `../../secrets.csv` 不能通过你为导入目录设置的路径边界。

### 安全与恢复

- 练习仅使用新建的 `python-io-practice/` 目录和无敏感数据的样例；不要覆盖真实设置、数据库或密钥文件。
- 先复制输入文件；原子替换只改善单一目标文件的可见一致性，不能代替备份或版本控制。
- 若练习失败，删除你创建的输出 JSON 与同目录、以 `.<目标文件名>.` 开头的残留临时文件；原 CSV 保持不动。
- 不记录或展示包含个人资料、令牌、密码的异常全文；向用户展示错误时保留可操作信息，日志则应按系统的隐私规则处理。
