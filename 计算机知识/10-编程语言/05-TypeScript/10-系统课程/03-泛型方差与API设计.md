# 泛型、方差与 API 设计：保留输入和输出的关系

> **学习位置**：[[计算机知识/00-开始/课程地图/05-TypeScript-课程地图|TypeScript课程地图]] · **适用边界**：strict 模式；ES2022 运行语义；Node 与浏览器环境区分。

## 泛型不是把 any 换一个字母

`function first<T>(xs: readonly T[]): T | undefined` 表达返回值与输入元素类型之间的关系。若写成 `unknown[] -> unknown`，这种关联会丢失；若写成 `any[] -> any`，检查会被削弱。类型参数只出现一次且没有表达关系时，通常应反思是否真的需要泛型。

```ts
function get<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}
const item = { id: 7, title: 'memo' };
const title = get(item, 'title'); // string
```

`K` 不是任意字符串，而是具体对象键集合的子集。`T[K]` 保留了选中键与对应值类型之间的关系。约束只说明可用能力：`T extends {length:number}` 不允许函数凭空返回任意具有 length 的新对象，因为调用者的 `T` 可能还要求别的字段。

## 方差从读写权限推导

假设 `Dog` 可替代 `Animal`。一个只生产 Dog 的函数也可以当作只要求生产 Animal 的函数使用，这是返回方向的协变。一个能处理所有 Animal 的消费者可以用于只会给它 Dog 的地方，参数方向相反，是逆变。若容器既读又写，两个方向组合通常要求更严格的约束。

TypeScript 为兼容 JavaScript 生态存在有意的非健全边界，例如可变数组赋值与方法参数检查规则不能直接等同于理想化完全安全的类型系统。`strictFunctionTypes` 对普通函数参数与某些方法声明有不同处理。公共 API 尽量使用 `readonly T[]` 表示不写入的集合，用函数类型属性表达回调约束，并给潜在别名修改写测试。

## 推导失败时先改接口，不先加断言

如果一个泛型函数接受宽泛联合并根据运行时条件返回不同类型，检查器不一定能证明每条分支对应条件类型的关系。可以使用重载表达有限种调用形状，或把复杂转换拆成验证后的专用函数。重载签名对调用方开放，实现签名只服务实现；实现仍必须真正满足每个重载承诺。

默认类型参数适合常见情景，过度默认成 `any` 却会掩盖错误。`satisfies` 用于检查值满足某个类型约束，并通常保留更多表达式自身的类型信息；它不是深冻结，也不是运行时验证。`as const` 有助于保留字面量和只读元组，但它同样不冻结真实对象。

## 把单位和权限放进模型

结构化类型下，`UserId` 与 `OrderId` 若都只是 number 的别名，仍然容易混用。品牌类型可以在静态层区分它们，但品牌必须由可信构造函数创建；一次 `as` 就能绕过，因此不能充当认证措施。单位也应明确：毫秒与秒、字节与字符数不能只因为都是 number 就混用。

 API 输入尽量接收完成工作所需的最小能力，输出则给出明确保证。例如只读分页接口不应要求调用者提供一个可以删除数据库的“大服务对象”。这种能力最小化能降低测试成本，也与操作系统最小权限原则相通。

## 练习与答案

实现 `mapValues<T, U>`，说明它保存哪些关系、丢失哪些具体键信息。再设计只读与可写盒子，分别尝试把 Dog 盒子赋给 Animal 盒子，并构造“经别名写入非 Dog”反例。正确答案不是背诵“数组协变”，而是画出读写路径，说明哪条路径可能破坏原持有者的假设。
