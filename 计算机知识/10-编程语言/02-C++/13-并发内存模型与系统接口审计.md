# C++ 深化：并发、内存模型与系统接口审计

> 阅读定位：C++20 核心；原有工具与仓库内容保留。返回 [[计算机知识/00-开始/课程地图/02-C++-课程地图|C++ · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## 正确性是事件之间的关系

读写共享状态时，先画事件图：线程 A 写数据、发布标志；线程 B 观察标志、读取数据。mutex 的解锁与后续正确获取建立同步关系；原子的 release/acquire 需要消费者读到相应发布链，才能把普通数据写入传递过去。把共享变量声明 volatile 不会建立这个关系。

```cpp
#include <atomic>
#include <cassert>
#include <thread>

int main() {
    int payload = 0;
    std::atomic<bool> ready{false};
    std::jthread producer([&] {
        payload = 42;
        ready.store(true, std::memory_order_release);
    });
    std::jthread consumer([&] {
        while (!ready.load(std::memory_order_acquire)) {
            std::this_thread::yield();
        }
        assert(payload == 42);
    });
}
```

这里 payload 只写一次且写在发布前，消费者观察到发布后才读。例子只展示同步，不是推荐用忙等设计生产队列；没有公平调度的前提时也不能保证等待的实际时长。真实队列通常使用条件变量或恰当的原子等待机制，并明确停止协议。

## condition_variable 等的是谓词

正确模式是持锁检查谓词，在循环或带谓词 wait 中等待，唤醒后重新检查。通知可以被多个消费者竞争、出现虚假唤醒或在未等待时发生，因此“收到一次通知等于有一项工作”是不成立的。关闭状态也要纳入谓词，否则退出时可能永远等不到下一条消息。

线程生命周期和任务生命周期必须绑定。`jthread` 在析构时请求停止并 join，但任务仍须合作检查停止条件；它不会强行撤销任意系统调用和外部副作用。锁内避免未知回调与长时间阻塞，减少死锁和尾延迟风险。

## false sharing 与原子成本

两个互不相关的计数器若落在同一缓存行，不同核心的更新也可能触发一致性通信，这叫 false sharing。它是性能问题，不等于数据竞争。原子变量仍有缓存一致性、争用与排序代价，单看源码操作数无法比较吞吐。

ABI、调用约定、名称修饰、异常传播、对象布局和标准库实现影响跨模块兼容。一个 C ABI 包装层可以收窄边界，但不能自动解决不同分配器、编码、结构体版本和并发合同。SIMD 与别名限制也应建立在已验证的对象与对齐前提上。

## 验收

为一个有界工作队列写清空、满、关闭、生产者失败、消费者失败五类状态。测试不能只重复跑很多次，应强制构造关键交错。ThreadSanitizer 可提供竞争证据，但无法证明不存在死锁或业务竞态；把结果与锁顺序分析、事件图和超时测试结合。
