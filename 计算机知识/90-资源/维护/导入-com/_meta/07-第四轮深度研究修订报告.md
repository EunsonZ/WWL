## 修正和澄清的关键问题

旧 Rust 异步页原先把“丢弃 Future”过于直接地解释为取消。本次区分实际 Future 的拥有者和运行时任务句柄：丢弃 Tokio JoinHandle 通常会脱离任务，不自动取消任务；abort 是取消请求，观察清理完成仍需相应等待，阻塞工作另有限制。旧 Rust 生命周期页同时澄清移动 String 元数据不因该动作本身搬迁堆缓冲区，不能和指向内联字段的自引用混为一谈。

旧 C++ 并发页补明单个 atomic 对象的操作、复合读改写、多个对象的不变量和无锁进度是不同保证。编译原理旧页增加直接的 LR 课程依据，保留 LLVM/MLIR 链接但标清后续 IR/后端用途。

新 Python 属性查找页在核验中进一步限定数据描述符读取优先级：只有 setter 的描述符不能按“同时具有 getter 的数据描述符”路径解释读取，并增加实际反例测试。SLR 表中的输入结束符使用行内代码，避免普通 `$` 被误当公式定界符。事务发件箱模型同时拒绝空身份/幂等键、布尔金额和超出 SQLite 整数范围的输入，并将关键列声明为非空。

这些修订的依据放在各专题正文，集中索引见 [[计算机知识/90-资源/维护/导入-com/_meta/round4/01-研究证据与版本边界|研究证据与版本边界]]。本轮整理 **95 条来源记录**，包括规范、官方实现文档、高校课程讲义及明确署名的一手工程资料；引用和教学模型分别标明角色。语言实验采用 C17、C++20、TypeScript 5.8.3 等实际记录的环境；PostgreSQL 17 文档结论不冒充本机实测结果，浮动网页的查阅日期也不等同于安装版本。
