# 常见问题与排错

> [!danger] 出现数据异常时先停手
> 不要连续批量保存、同步、Lint、导入、移动或重命名。先复制整个 Vault 到独立位置，记录当前时间、设备和症状，再查看 File Recovery、Sync version history 或 Git。Sync 会传播错误，不是独立备份。

## 60 秒分流

| 症状 | 第一检查 | 下一步 |
| --- | --- | --- |
| Markdown 显示奇怪 | 切 Source mode；查围栏、空行、缩进、YAML | [[#Markdown 与编辑视图]] |
| 链接/反向链接不对 | 查目标名称、路径、别名、Excluded files | [[#链接、嵌入与图谱]] |
| Search/Bases 少结果 | 查属性类型、路径、过滤器和排除规则 | [[#搜索、属性与 Bases]] |
| 某插件命令消失/界面异常 | Restricted mode、插件启用、版本和平台 | [[#社区插件与主题]] |
| 移动端和桌面不同 | 查插件 Mobile 标记、工具栏和隐藏侧栏 | [[#移动端]] |
| 启动慢/卡顿 | 查看 Startup time，关闭高成本视图/插件 | [[#性能与启动]] |

## 标准排错阶梯

按顺序进行；问题消失时停在那一级，记录改变了什么。

1. **写下复现步骤**：在哪个 Vault、设备、文件、视图，做什么动作后出现什么。
2. **保护数据**：独立复制 Vault；涉及自动化/批量写入时额外保留 `.obsidian`。
3. **确认版本**：Settings → General 查看 Obsidian app version 和 installer version；核对插件版本。
4. **完全重启**：保存后关闭应用再开；仅切换插件开关不一定完全卸载所有运行状态。
5. **Restricted mode**：Settings → Community plugins → Turn on and reload，禁用全部社区插件。
6. **默认外观**：切回 Default theme，关闭所有 CSS snippets。
7. **新/沙盒 Vault 复现**：用最少内容和默认配置重复同一动作。
8. **定位插件**：若 Restricted mode 下正常，一次启用一个插件；插件很多时先启用一半做二分排查，每轮重载。
9. **收集证据**：Command Palette → `Show debug info`；Settings → General → Advanced 查看 Startup time。
10. **报告**：附最小样例、预期/实际、版本、平台、Restricted mode 结果和复现频率。

> [!warning] 不要把删除 `.obsidian` 当第一步
> `.obsidian` 包含插件、主题、快捷键和工作区配置。若怀疑配置损坏，先关闭 Obsidian并备份整个 Vault，再在副本/临时 Vault 中验证；不要在唯一副本上试探性删除。

## Markdown 与编辑视图

### 为什么 Source、Live Preview、Reading view 不一样？

- Reading view 完整渲染 Markdown。
- Live Preview 是编辑模式，会在光标附近显示源码标记。
- Source mode 是编辑模式，持续显示源码。
- 代码语法高亮、行内脚注、HTML 和插件渲染在三者间可能不同。

排查顺序：切 Source mode → 检查未闭合反引号/数学围栏 → 检查列表缩进 → 检查 YAML → 切默认主题/关闭 CSS → Restricted mode。

### 一个回车为什么在阅读视图合并？

Markdown 把单回车视为软换行。需要新段落时空一行；需要同段硬换行时用行尾两个空格或 `Shift+Enter`；检查 Editor → Strict line breaks。

### 后半篇都变成代码/引用/Callout？

- 检查代码围栏是否成对，开头三个反引号必须有结尾。
- 嵌套代码示例外层用四个或更多反引号。
- 引用/Callout 每行前需正确使用 `>`；退出引用后空一行。

### YAML/Properties 变红或丢类型？

- frontmatter 必须从第一行 `---` 开始并以 `---` 结束。
- `key:` 后要有空格；列表项以 `- ` 开始。
- 内部链接写成 `"[[笔记]]"`。
- 日期用 `YYYY-MM-DD`，复选框用 `true/false`，数字不带单位。
- 在 Properties view 查同名属性是否被设置成不同类型；见 [[Obsidian知识/90-资源/02-参考/03-属性字典|03-属性字典]]。

### 粘贴网页格式混乱？

- 普通粘贴可能把 HTML 转为 Markdown，行为受 Editor 设置影响。
- 用 `Cmd/Ctrl + Shift + V` 做无格式粘贴，再手工补链接/标题。
- 大段网页内容先放实验页，检查图片是外链还是已复制附件。

## 链接、嵌入与图谱

### 内部链接点不开

1. 切 Source mode 检查是否为 `[[目标]]` 或 `[文字](路径.md)`。
2. 用 Quick Switcher 搜目标名和 alias。
3. 同名文件较多时写 Vault 相对路径：`[[文件夹/目标]]`。
4. 标题链接检查标题文字；块链接检查 `^block-id`。
5. 检查 Settings → Files and links → Excluded files。

### 重命名后出现断链

- 优先在 Obsidian 内重命名/移动，并开启或确认 Automatically update internal links。
- 系统文件管理器、Git 批量操作和外部脚本可能绕过链接更新。
- Search 查旧文件名；Outgoing links 查未解析目标；Git diff 检查改动范围。

### Backlinks 里“Linked”和“Unlinked”有什么区别？

- Linked mentions 真正包含指向当前笔记的内部链接。
- Unlinked mentions 只是出现了同名文字，是候选关系，不应一键全部转换。
- 同名词、常用词和别名可能产生误报；逐条判断语义。

### 嵌入没有更新或只显示链接

- 嵌入前必须有 `!`：`![[目标#标题]]`。
- 确认源文件/标题/块仍存在，且不在 Excluded files。
- 插件生成视图可能只在 Live Preview/Reading view 渲染。
- 重载 Vault；Restricted mode 下测试是否为社区插件渲染。

### 图谱中没有线/节点太多

- Graph 只根据内部链接画边；Mermaid/Canvas 线、普通文本提及不会自动变为 Graph 边。
- 检查 Existing files only、Orphans、Attachments、Tags 和 Search filter。
- 先用 Local Graph 观察当前笔记；全局图谱加 `path:`/`tag:` 过滤。
- 不要为图谱美观添加无意义链接。

## 搜索、属性与 Bases

### Search 找不到附件名

普通内容搜索主要面向笔记/Canvas。使用 `file:.pdf`、`file:名称` 或 `path:"附件目录"`；检查 Excluded files。

### `OR` 不生效

使用大写 `OR`，并用括号明确组合：`会议 (项目A OR 项目B)`。打开 Search settings → Explain search term 检查解析。

### `[property:value]` 没结果

- 在 Properties view 确认实际属性名、类型和值。
- 文本值是否有空格/大小写差异；列表项是否独立。
- 空属性用 `[property:null]`；空字符串 `""` 和空列表 `[]` 不算 null。
- 先查询 `[property]`，再逐步增加 `:value`。

### Base 显示不完整/排序奇怪

- Base 只显示满足 Source/filter 的文件；逐层暂时移除过滤器定位。
- 同名属性必须类型一致；数字 `4` 与文本 `4/5` 无法可靠同排。
- 检查属性是否只存在于 Dataview inline field，而不是 Obsidian Property。
- Base 是视图；直接打开源 `.md` 确认真实属性。

### Dataview 有结果，Bases 没有（或相反）

Dataview 可读取自己的 inline field `Key:: Value` 和隐式文件字段；Bases 主要围绕 Obsidian Properties/文件属性。把需要跨两者使用的数据写成标准 Properties，避免两套元数据真相。

## 社区插件与主题

### 什么是 Restricted mode？

打开后所有社区插件被忽略，但安装文件仍保留。它适合判断问题是否由第三方代码引起，也适合敏感 Vault。旧教程可能称 Safe mode。

### 插件无法启用

1. 核对插件 manifest 的 `minAppVersion` 与当前 Obsidian。
2. 核对 Desktop only；Local REST API with MCP 当前 manifest 为桌面专用。
3. Settings → Community plugins 检查是否已安装且 toggle 开启。
4. 手动 Check for updates；社区插件不会自动更新。
5. 完全重启；查看通知/开发者控制台错误。
6. 不要从未知来源手动复制 `main.js` 覆盖商店版本。

### 插件升级后异常

- 查插件 release notes 和 Issues；保留出现问题时的版本号。
- Restricted mode + 默认主题复现。
- 只启用该插件和其明确依赖，在临时 Vault 复现。
- 恢复插件旧版属于高级操作；先备份配置和数据，优先遵循项目仓库说明。

### Templater/QuickAdd/DataviewJS 脚本能否直接复制？

不能仅凭帖子/视频流行度信任。Templater 可执行 JavaScript 和系统命令；DataviewJS 拥有插件级访问；QuickAdd Macro/脚本可串联写入。逐行理解、审计来源、限制目标到实验区，并确保有独立备份。

### Linter 改了大量文件

- 立即停止继续 Lint；不要再全库保存。
- 查看 Git diff/备份，区分格式变化与语义变化。
- 在单个故意混乱实验页调规则，一次只启用一组。
- 需要恢复时按精确文件回退，不用 destructive reset 覆盖其他用户修改。

### 主题/CSS 导致界面异常

切 Default theme → 关闭全部 CSS snippets → 重载。若恢复，逐个启用定位；主题和 snippet 只应改变外观，不应保存关键语义。

## 移动端

### 找不到 Ribbon/右键/侧栏

- 移动端没有桌面的 Ribbon；Ribbon 动作位于导航栏的 Open menu。
- 右键通常改为长按。
- 左右侧栏默认隐藏，打开后通过顶部下拉切换视图。
- 编辑时底部是可定制 Mobile toolbar；可加入全局命令。

### 顶部下拉触发了错误动作

Settings → Mobile/Toolbar → Configure mobile Quick Action，重新选择 `Command palette: Open command palette` 或需要的命令。

### 插件标注 Mobile 但体验不同

`isDesktopOnly: false` 只说明 manifest 未限制桌面，不保证：

- 所有命令都有触控入口；
- 桌面快捷键能使用；
- 大索引/复杂图表在手机性能相同；
- 调用 Git、外部命令、字体、OCR、网络的能力相同。

把插件命令加入移动工具栏，使用小型样例验证；关键工作流保留原生/手动路径。

### 移动端同步后配置不一致

先区分内容文件、`.obsidian` 配置、插件文件、插件数据和设备专属设置。不要连续在多设备同时改同一配置；等同步完成，再逐台检查插件、主题、工具栏和 Hotkeys。

## 性能与启动

### 启动变慢

1. Settings → General → Advanced → Startup time 计时器。
2. 记录 Total、Vault、Workspace、Core plugins 等阶段。
3. 关闭大型 Canvas/Graph/搜索结果和过多恢复标签页，保存简洁 Workspace。
4. Restricted mode 对比；再逐个启用高索引/高自动化插件。
5. 检查 Dataview/Tasks 查询是否返回数百上千项；设置路径和 `LIMIT`。
6. 检查 Vault 是否包含大量非笔记文件或附件；合理使用 Excluded files，但别把它当安全边界。

### 编辑时卡顿

- 在新空笔记/Source mode 测试，排除当前文档过长或复杂嵌入。
- 关闭实时高成本查询、复杂 DataviewJS、超大 Tasks 列表、Excalidraw/PDF 面板。
- 默认主题、无 CSS、Restricted mode 分层比较。
- 移动端把大型仪表盘替换为路径更窄的查询。

## 恢复、同步与备份

### File Recovery

- Settings → Core plugins → File recovery → Snapshots → View。
- 输入文件名，检查快照，优先 Copy 到新笔记对比；确认后再 Restore。
- 快照只覆盖支持的本地文件类型、按设备保存并有保留期；它不是完整备份。

### Obsidian Sync version history

使用 Sync 时，可从文件上下文菜单或 Sync 设置查看版本历史/删除文件。先确认设备同步完成状态，避免一边恢复一边在另一设备继续修改。

### Git

Git 适合审计文本与恢复明确版本，但前提是已有提交。附件、插件配置、未跟踪文件、remote 和凭据策略需另外设计；不要运行会覆盖整个工作区的 destructive reset 来恢复单个文件。

### 独立备份

真正备份应是与工作目录隔离的一向副本/版本化备份。若多设备同步，选择一个主要设备执行备份只是管理习惯；同步服务本身并没有“主设备”概念。
