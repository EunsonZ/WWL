# 安全实验与重置

Obsidian 的优点之一是数据主要保存在普通文件中；但批量插件、同步和外部自动化仍可能快速修改许多内容。Playground 鼓励试错，也要求你能解释修改范围和恢复路径。

## 安全边界

### 可以放心改

- [[Obsidian知识/30-实践/01-实验区/Markdown/00-Markdown实验室|10-实验区]] 中的课程样例。
- 自己创建的练习笔记。
- 当前课程明确指定的单个文件。

### 操作前先确认范围

- Linter 的“格式化整个 Vault”。
- Importer 的批量导入。
- 批量属性修改、重命名、移动和删除。
- 社区插件的任意命令。
- Git commit、pull、push 和自动同步设置。
- REST、脚本或其他外部程序的写入操作。

### Playground 不要求你做

- 配置 Git remote。
- 开启自动 push/pull。
- 购买或启用 Obsidian Sync、Publish。
- 把 API key、私钥或密码写入笔记。

## 四种恢复能力不是一回事

| 能力 | 适合什么 | 不代表什么 |
| --- | --- | --- |
| 系统回收站 | 找回刚删除的文件 | 不是版本历史 |
| File Recovery | 查看本机保存的 Markdown/Canvas 历史快照 | 不覆盖 Base、图片、数据库，也不是独立备份 |
| Git | 查看可审计 diff、提交与分支历史 | 没有 remote 时不是异地备份 |
| Sync | 跨设备同步 | 不自动消除冲突，也不能替代独立备份策略 |

进一步阅读：[[Obsidian知识/20-功能/01-官方插件实验室/08-File Recovery与Sync边界|File Recovery 与 Sync 边界]]、[[Obsidian知识/20-功能/02-社区插件实验室/11-Obsidian-Git|11-Obsidian-Git]]。

## 安全试错练习

1. 在 [[Obsidian知识/30-实践/01-实验区/Markdown/01-自由草稿纸|自由草稿纸]] 增加一行容易识别的文字。
2. 用 File Recovery 查看该文件的历史状态。
3. 用 Git 插件或版本控制界面查看 diff，但不要提交或回滚。
4. 手工撤销刚才的一行。

> [!success] 成功标准
> 你能说清当前变化在哪个文件中，并且至少知道一种不覆盖其他文件的恢复方法。

## 如何重置课程样例

优先选择最小范围：

1. 先用撤销恢复当前编辑。
2. 已关闭文件时检查 File Recovery。
3. 如果样例受 Git 跟踪，先查看该文件的 diff，只恢复目标文件。
4. 不要使用会重置整个仓库的破坏性命令。
5. 不确定时保留现状，在新笔记继续实验。

> [!warning] 不要重置整个 Vault
> “让样例恢复原样”不值得冒覆盖个人笔记、其他 agent 修改或未提交工作的风险。恢复之前先查看精确文件和 diff。

### 恢复备份与分享副本

个人恢复备份按自己的备份策略私密保存；供 AI 或他人审阅的副本只包含本次问题需要的文件。二者用途不同：精简的分享副本通常不足以恢复整个工作环境。[File recovery 官方说明](https://obsidian.md/help/plugins/file-recovery)指出，它只恢复 `.md` 和 `.canvas`，快照保存在库外的设备状态中；复制 Vault 文件夹也不等于带走了这些快照。

以下是分享检查清单；当前库没有 `scripts/share_vault.py`，不要把不存在的脚本当作导出入口。

1. 在库外建立新的本地副本目录，按精确白名单复制需要的正文、代码、测试、依赖说明及必要的图源和静态图片。保留相关相对路径，核对被正文引用的附件仍在；不覆盖已有副本，也不跟随符号链接搬入其他目录。
2. 对照本次范围检查副本。通常不需要 `.venv`、插件运行包、工作区/会话、同步配置、认证信息或无关资料。调试插件时只提供所需 manifest、脱敏设置片段及必要日志，不整份复制可能含凭据的 `data.json`。
3. 排除原始资料目录后，还要检查派生数据。`.smart-env` 的索引或嵌入、`.makemd` 的数据库及其他持久状态可能保留源路径、内容或关系；不需要它们的分享副本直接排除这些文件。它们在主库中可能仍有用途，不能据此删除主库原件，也不能仅凭发现嵌入就断言能还原原文。
4. 只在副本中复查被排除的目录名、派生路径引用和敏感字段，并检查正文与附件内容；只记录文件类别、命中数和处理决定，避免把完整命中内容再贴到对话或报告中。无法解释的二进制/数据库若非本次必需，先排除；没有匹配到几个关键词不等于已证明无敏感信息。
5. 使用已有归档工具生成一个新的本地归档后，再核对归档条目及必要附件，确认与已检查的副本一致。`.gitignore` 不控制手工复制或打包；本地生成归档也不等于获准上传。

练习只使用合成文本：解释为什么“导出没有密钥”不能证明“先前分享过的密钥已失效”。副本过滤与轮换旧凭据是两个不同动作，后者需要在可信环境中另行确认。

外部自动化的详细分层策略见 [[AGENTS]]。发现与批量文本使用文件工具，需要 Obsidian 语义时使用原生 CLI；REST、插件和 MCP 只有明确点名授权才可调用。Local REST API 的本机配置可能包含凭据，必须保持忽略与受控权限，不能进入课程、分享副本或 Git。
