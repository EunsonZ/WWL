# 09 · 正则表达式综合实战

## 挑战目标

完成三个小任务：从稳定日志格式提取字段、规范化日期文本、重排姓名列表。重点不是把所有逻辑塞进一条表达式，而是完整走过“样本 → 规则 → 匹配 → 验证 → 边界说明”的流程。

- [[编程知识/30-实践/01-正则表达式实验区/02-练习场|练习场]]；
- [[编程知识/30-实践/01-正则表达式实验区/04-5分钟运行与测试模板|运行与测试模板]]；

## 通用提交模板

每个任务都填写：

```text
目标引擎与版本：
标志（flags）/ API：
输入范围与最大长度：
模式：
捕获组：
正例及结果：
反例及结果：
边界例及结果：
已知限制：
不用正则时的替代方案：
```

## 任务 A · 提取固定格式日志

样本格式：

```text
2026-08-31T09:30:15Z level=ERROR code=E104 message=request timeout
```

要求：

1. 完整匹配一整行；
2. 命名捕获 `timestamp`、`level`、`code`、`message`；
3. `level` 只允许 `INFO`、`WARN`、`ERROR`；
4. `code` 是一个大写字母后跟三位 ASCII 数字；
5. `message` 可以包含空格，但不能跨行；
6. 写明表达式只验证时间戳形状，不验证日历与时区语义。

反例至少包括：缺失 `level`、小写等级、两位错误码、缺失消息。

> [!tip] 分层处理
> 如果日志字段顺序可能变化，先用日志格式解析器或按空格/键值对分词，再逐字段校验，通常比一条巨型正则更可靠。

## 任务 B · 规范化日期文本

将以下两种输入重排为 `YYYY-MM-DD`：

```text
31/08/2026
31-08-2026
```

要求：

1. 同一个查找模式接受 `/` 或 `-`；
2. 日、月、年分别捕获；
3. 分隔符在同一个日期中必须一致；
4. 给出目标工具所需的替换模板；
5. `31/13/2026` 即使形状匹配，也必须在后续日期解析中失败。

这个任务会用到捕获分隔符和反向引用。若目标引擎不支持反向引用，拆成两个明确模式，或交给日期解析库。

## 任务 C · 重排姓名列表

输入：

```text
Lovelace, Ada
Turing, Alan
Hopper, Grace Brewster
```

输出：

```text
Ada Lovelace
Alan Turing
Grace Brewster Hopper
```

要求：

1. 姓位于第一个逗号前，名位于逗号后；
2. 允许逗号后有一个或多个普通空格；
3. 行首行尾不能被吃进姓名；
4. 写明这个简化规则不覆盖复姓、姓名后缀、带逗号组织名和所有国际姓名习惯；
5. 批量替换前先预览所有命中。

## 加分任务 · 找出重复单词

在不区分大小写的情况下寻找相邻重复 ASCII 单词：

```text
This is is a test.
The the result is ready.
```

这是可选扩展，不影响前三个必做任务的完成判定。考虑：

- 捕获组与反向引用；
- 中间允许的空白；
- 单词边界；
- 忽略大小写 flag；
- 该规则为何不等于完整的自然语言重复检测。

## 加分任务 · 同一测试集的双引擎回归

运行 [[编程知识/30-实践/01-正则表达式实验区/05-Python差异断言.py|Python 差异断言]] 与 [[编程知识/30-实践/01-正则表达式实验区/06-JavaScript差异断言.js|JavaScript 差异断言]]，然后补一条自己的业务样本。报告应明确：

1. 两种引擎的版本；
2. `\\w`、`\\d` 与点号在 Unicode 输入上的实际差异；
3. 命名组和替换模板的方言差异；
4. JavaScript 中带 `g` 的 `test()` 为什么不适合单值校验；
5. 你的线上部署究竟以哪个运行时的测试结果为准。

若实际任务在 Linux 文本流水线中完成，再为 `grep` 或 `rg` 单独写一组小样本；不要把 Python 或 Node.js 的通过结果外推成命令行工具的通过结果。Linux 的工具、选项和写入边界见 [[计算机知识/20-操作系统/01-Linux/05-文件目录与文本处理命令|文件、目录与文本处理命令]]。

## 自检

- [ ] 每个任务都写明了引擎、版本、标志或 API。
- [ ] 我把关键样本写成可重复运行的断言，并且当前全部通过。
- [ ] 每个模式都有正例、反例和边界例。
- [ ] 我能逐段解释模式，不依赖“试出来了”。
- [ ] 我区分了文本形状验证与日期、姓名等业务语义。
- [ ] 我没有对原始样本执行不可恢复的批量替换。
- [ ] 我检查了输入长度与可能的回溯路径。
- [ ] 若代码需要同时支持 Python 和 JavaScript，我已分别运行并记录双引擎断言，而不是只在在线测试器中高亮过一次。

完成后再打开 [[编程知识/30-实践/01-正则表达式实验区/03-练习答案与解释#综合实战参考|综合实战参考]]。参考答案不是唯一答案；如果你的模式更短但接受了更多错误输入，应以测试结果而不是字符数量判断优劣。

## 成功标准

你能在目标引擎中复现三个任务的预期结果，关键断言全部通过，并能清楚说明每个表达式的引擎边界、业务边界、性能边界和替代工具。
