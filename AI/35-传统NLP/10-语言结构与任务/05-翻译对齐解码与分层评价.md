# 翻译：对齐、条件解码与意义保持分别验什么

原文`米拉送给莉娜一本红书。她感谢她。`可以保留前课的身份歧义；如果可见语境已经确认收书者感谢送书者，译成`Mira gave a red book to Lena. Mira thanked Lena.`就把感谢方向换了。人物、书和动作词几乎全在，仍没有保住所选解释。这个问题不靠多画一张Transformer图解决。

[[AI/20-LLM/20-架构/07-编码器解码器与多模态接口#4. Encoder-decoder：先理解源序列，再生成目标序列|已有encoder-decoder]]负责源记忆、目标因果前缀与cross-attention shape；[[AI/20-LLM/10-原理/02-自回归建模Logits损失与困惑度|LM目标]]负责条件概率和teacher forcing。本课新增翻译的输入/对齐单位、真实受限解码输出、词面与角色/否定/语境评价，不重写神经网络前向或声称已训练通用翻译器。

## 翻译任务先带上源语境

定义源文本x、可见语境c、目标语言约定及候选y。概率模型通常给
$$p_\theta(y\mid x,c)=\prod_{t=1}^{T+1}p_\theta(y_t\mid y_{<t},x,c),$$
其中y_{T+1}=EOS。最大概率解码是在模型内选序列；翻译保真是语言/证据问题，二者目标相关但不相等。训练条件似然的正确前缀不等于实际生成前缀；参数、训练语料、语言方向和被看见的上下文都必须记录。[SLP3第13章§13.3–13.4](https://web.stanford.edu/~jurafsky/slp3/13.pdf)是本接口的一手参照。

本包条件x固定为上述中文，人物对照米拉↔Mira、莉娜↔Lena在输入词典给定；c可为unknown，或已经提供的`THANK(recipient,giver)`约束。unknown时两种身份分析都保留，不能硬给唯一参考再把另一读法一律判错。只有明确所选c时，下面的角色参照才有意义。

## 句子、词与子词的对齐不互相代替

句对齐可以是1↔1、1↔多句甚至空对应；本练习把整段两句作为一个固定对齐segment，不把句序换掉后仍逐行zip。词对齐是源位置与目标位置间的关系 $\mathcal A\subseteq I_x\times I_y$，允许一对多/多对一；不存在翻译也可标NULL。不要求是双射，更不从同一字符串猜同一指代。

源第一句的教学词单位固定为`米拉 / 送给 / 莉娜 / 一 / 本 / 红 / 书 / 。`，目标为`Mira / gave / a / red / book / to / Lena / .`。给定人工对齐：米拉→Mira、送给→gave与to、莉娜→Lena、一/本→a、红→red、书→book、句号→句号。本是汉语量词，不能因英文没有一个独立classifier token就宣布漏译；a与一本是当前表达的对应，而非所有“本”都必须译a。两种词序也不要求所有对齐线不交叉。

该表是已声明的教学分析，不是从attention热图学习出的gold。一个attention行是带权混合，归一并不保证它就是语言学对齐；翻译可能省略、重排或组合。用于训练/评测的人工对齐有规范与分歧；LLM子词拆分后还需到语法词/字符的映射，不能拿子词下标直接比本表。真实平行语料需许可、来源/版本、文档切分、去重复与训练重叠检查；本包不把原创短文叫真实新闻语料。

## 有限条件模型也能完整检查解码

为了让“模型打分”和“搜索出错”各自可核，本实践给有限候选集合Y及正整数质量w(y)，令p(y|x,c)=w(y)/Σw。它是人工指定的有限条件模型，不是神经MT训练结果，也不是由其语义正确性自动生成概率。

把每个目标词序列加EOS，构前缀树。令M(s)为以s为前缀的全部候选概率和，根M(ε)=1；在M(s)>0处定义下一词概率q(t|s)=M(st)/M(s)。孩子对应的候选互不交且覆盖父集合，所以Σ_t q=1。沿一条完整y+EOS的概率乘积首尾相消为M(y+EOS)/M(ε)=p(y)。这证明该前缀模型归一、链式目标与直接候选质量一致；不证明其质量符合语言事实。

一个独立短句解码夹具，源语境为“莉娜感谢米拉”，目标候选质量如下：

| 候选 | 质量/概率 |
| --- | ---: |
| `Mira praised Lena .` | 3/10 |
| `Mira thanked Lena .` | 3/10 |
| `Lena thanked Mira .` | 4/10 |

greedy第一步选Mira(.6而非Lena.4)，下步两项并列按词典序选praised，最终.3；全候选MAP为Lena句.4，beam width2在本有限树也保留到它。这是一个搜索失败的精确例，不是beam2对一般翻译最优的保证。有限集合直接穷举时间随总候选词数增长，真实词表V/长度T的全树有指数规模，不能把夹具的可枚举当成通用解码法。

再将整段译文模型的最高质量故意给“感谢方向反了”的候选，精确MAP仍会选错意思。更彻底的搜索修不了错误模型偏好。length penalty会改变搜索目标；本次只按含EOS的原始序列概率，不另加长度奖励。模型外的人类语境与事实核对不能从一个最大概率值省略。

## 自动词面指标先公开计分口径

所有候选都在**英文目标侧**与同一英文参考比，不用中英原文直接逐词重叠。计分先按英文词/独立标点分词，再lowercase；不分词中文、不去标点、不去冠词、不做词干归一。评价单元是整段一个segment，n-gram可跨句号；若按逐句累积而不跨边界，会得到别的分数，应重新记录。

对固定参考r，候选c的n-gram计数C_c(g)，截断匹配
$$M_n=\sum_g\min(C_c(g),C_r(g)),\quad D_n=\max(|c|-n+1,0),\quad p_n=M_n/D_n.$$
多个参考时min中的参考计数改成各参考最大值；本正式输入只用一个参考。截断防止重复同一个参考词无限刷分。段长c>0、参考长r，短句惩罚 $BP=\exp(\min(0,1-r/c))$；BLEU_N=BP×exp((1/N)Σ_{n=1}^N log p_n)。本次报告BLEU1与BLEU4，取0–1尺度、等权、无平滑、无effective-order；任何p_n=0则该阶BLEU为0，若D_n=0则该阶未定义/null而不暗改N。空候选另记0，仍保留长度。所有正式对照长度≥4。

[Papineni等2002，§2.1–2.3，pp312–315](https://aclanthology.org/P02-1040.pdf)给截断n-gram、几何均值与BP。原论文主要用于足量语料系统比较，不能把本例单段值当总体质量认证；本次未跑或冒称SacreBLEU默认配置。语料BLEU应先跨segment加分子/分母及长度，再计算，不等于逐句BLEU算术平均。

## 同词袋仍能感谢反了，正确改写也会掉分

固定c为收书人感谢送书人，参考是`Mira gave a red book to Lena . Lena thanked Mira .`。实践实际比较：

- 正确原样：同参考。
- 正确被动：`Lena was given a red book by Mira . Lena thanked Mira .`，GIVE三角色/书属性/THANK方向与极性同参考，表面语序/词形却不同。
- 角色反向：`Mira gave a red book to Lena . Mira thanked Lena .`，与参考词袋完全相同，BLEU1=1；THANK两角色换了。
- 否定改变：`Mira gave a red book to Lena . Lena did not thank Mira .`，改变THANK极性，不能仅按人物相同宣布事实保留。
- 增加态度：`Mira gave a red book to Lena . Lena reluctantly thanked Mira .`，在本片段的核心GIVE/THANK事实中角色和极性相同，却增加了不情愿态度；“核心事实相同”不等于完整语用/附加内容相同。

程序按受支持构式真正解析每条英文，再转统一实体框架比较，未从candidate名字`correct`直接填语义分数。被动句按角色表重排；否定与reluctantly在槽位中实际保存；不在片段里的引语、讽刺和礼貌含意仍需另一任务。`请把门关上`译作命令`Close the door.`或礼貌问句`Could you close the door?`的合适性取决于说话关系/请求场景；只保留“关门”命题不足以评价施为和礼貌，当前程序不会自动给它打人类语用分。

为什么不可以“多看BLEU4就解决”？高阶词序比unigram更敏感，但仍不提供一般正确性保证。任取固定一处角色错误，后面给参考/错误译文追加同样的长且无关正确叙述，至多常数个词位置改变。对固定n≤4，受影响n-gram位置数至多n乘改变位置数，长度趋大时p_n→1，BP=1，BLEU4→1；关键角色错误仍存在。实践只跑几个固定padding长度核机制，一般极限理由在此给出，不以三点枚举代证。

评测因此保留三栏：词面匹配、类型/角色/否定/量词等指定事实、语境/语用是否多说或少说。前课A/C的反模型会让高重叠译文改变真值；同一事实在一个模型同真也不能当作所有语境等义。人工评价也需明确任务、评审语言能力、可见源语境与分歧，不以“人看过”当统一金标准。

## 把错误带回原主解释

回[[AI/20-LLM/10-原理/03-Embedding表示与语义空间#语义空间的有用边界|Embedding边界]]时，带一对同词袋却不同THANK方向的原始输出；它检验的是谁做什么，不是两个句子是否同题。回[[AI/20-LLM/70-工程应用与工具链/08-混合检索重排RAG误差分解与证据#引用有三个不同正确性问题|检索证据]]时，核引用究竟支持哪组角色、否定与量词，不让相关命中代替支持。

回encoder-decoder与采样页，带有限模型的greedy/MAP差距与“精确MAP仍错”分别诊断搜索和模型；大型训练若要继续，实践入口给许可平行语料、文档切分、tokenizer、checkpoint、语言方向和保留测试接口，不把它包装成本包已执行。当前三课已形成原#163语义/篇章/量词/翻译的连续代表链；更广自然语料语义标注、通用MT效果与真人语用判断仍按对象另验。

## 迁移题

1. 对齐中“一/本→a”和“送给→gave/to”分别违反了函数或双射的哪种想当然？为何attention归一不证明这份词对齐正确？
2. 从三候选.3/.3/.4自己构第一/第二层前缀概率，写greedy、完整MAP与本例beam2结果。若最大质量改给错误意思，搜索更全能否保真？
3. 角色反向译文为什么BLEU1=1？正确被动译文为什么可能更低？列出指标外必须核的事件字段。
4. 候选只有3个token、要求N4时，本口径怎样报告？在一个很长段末保留同一关键否定错误，为何BLEU4仍可接近1？这是否证明BLEU毫无系统比较价值？
5. 源语境未给代词所指，能否拿唯一A_R参考把A_G译文一律叫错？若语境指定A_R，保留人物/动作却改加reluctantly或therefore，各多了承诺什么？

## 题解与核查路线

1. 一本的两个源单位共指一个目标a，是多对一；送给同时对应gave/to，是一对多。对齐应为位置关系，不是单值函数或双射；数量词、冠词与构式的实现也语言特异。attention归一只约束权和，不证明每格对应语言学对齐或人物身份。
2. 第一层Mira质量.6、Lena.4；Mira后praised/thanked条件概率各.5。greedy依词典序选praised，完整串概率.6×.5=.3；Lena路径后续唯一，概率.4。MAP与本例beam2得到`Lena thanked Mira .`，.4；两者在此一致不证明一般beam2最优。把段落模型最大质量指定给角色反向候选，精确MAP仍选它，须改变模型/证据使用而非只加搜索宽度。
3. 反向候选与参考每个词/标点计数均同且等长，p1=BP=1。被动改了was/given/by与词序，词面可更低却保留GIVE三角色。还需核实体身份、事件谓词/触发对齐、论元角色、书属性、时点/极性，以及附加态度/篇章关系。实际固定反向BLEU4≈.678650268，比正确被动≈.408960147高，不能据此翻转语义参照。
4. D4=0优先使固定N4未定义/null；不是平滑成非0或悄悄降N，空候选另按明定约定为0。固定数量错误影响至多常数个n-gram，长公共部分使分子/分母比例趋1，关键否定/角色错误却保留。这否定“高BLEU即可认证每个事实”，不否定明确同语料/分词/参考/统计协议下的系统比较用途。
5. 不可以；unknown时A_R/A_G均在允许集合，应记录多参考/多分析或保持歧义，另评未决。指定A_R后加reluctantly增加态度，加therefore增加篇章结果承诺；保留人物与核心事件还不够保证这些附加内容有源支持。一般语用需源上下文、语言能力与评审分歧，本小程序不冒认已自动评定。
