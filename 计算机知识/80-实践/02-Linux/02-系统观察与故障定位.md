# 系统观察与故障定位

本练习只收集当前系统的非敏感结构信息。提交或分享结果前删除用户名、主机名、公网地址、序列号、无线网络名称和设备唯一标识。

## 第一部分：画出系统分层

按可用性运行：

```bash
uname -a
cat /etc/os-release
ps -p 1 -o pid,comm,args=
printf 'configured-login-shell=%s\n' "${SHELL-unknown}"
ps -p "$$" -o pid,comm,args=  # Bash 中 $$ 是 shell PID；按当前 shell 文档核对
```

回答：发行版与 kernel 是同一个版本吗？PID 1 是谁？当前交互 shell 又是谁？`SHELL` 是配置或继承的登录 shell 路径，不能证明当前执行进程；用 `ps` 观察 PID/命令，若进程不可见、命令不可用或在子 shell 中 PID 语义不同，就记录未知并查当前 shell 手册。参考 [[计算机知识/20-操作系统/01-Linux/01-计算机系统与Linux分层|Linux 分层]]。

## 第二部分：文件系统和存储

```bash
lsblk -f
findmnt /
df -h /
df -i /
```

在物理机或完整 VM 中，画出：块设备 → 分区 → 文件系统 → 根挂载点。若根文件系统是 overlay、tmpfs，或当前环境是容器，改为画出“可见文件系统 → 根挂载点 → 容器边界”，并明确记录：容器内证据不能可靠映射宿主块设备，不能为了补齐图而读取或修改宿主存储。

## 第三部分：进程、服务和日志

```bash
ps -eo pid,ppid,user,state,comm --sort=pid | head
```

在 systemd 系统上选择一个无敏感信息的服务：

```bash
systemctl status systemd-journald --no-pager
journalctl -u systemd-journald -n 20 --no-pager
```

不要为了让示例“成功”而启动、停止或启用服务。非 systemd 环境记录“此命令不适用”，而不是把它当作 Linux 损坏。

## 第四部分：网络层次

```bash
ip -brief link
ip -brief address
ip route
ss -lnt
```

分享输出前先脱敏。回答：接口是否存在？是否有地址？默认路由是否存在？监听 socket 是否说明防火墙和远端访问一定正常？

## 写一份最小故障报告

选择一个无破坏性的现象，例如“某命令不存在”或“某测试域名无法解析”，按以下模板：

```text
现象：
复现命令：
预期：
实际与退出码：
系统层次：shell / PATH / 权限 / 服务 / 网络 / 存储 / 驱动
只读证据：
最小可回退变更：
变更后验证：
恢复：
```

排错主线见 [[计算机知识/20-操作系统/01-Linux/10-网络存储日志与故障排查|网络、存储、日志与故障排查]]。

## 成功标准

- [ ] 我能区分发行版、kernel、PID 1 和 shell；
- [ ] 在物理机/完整 VM 中，我能指出根文件系统所在的设备和挂载点；在容器或 overlay 环境中，我能指出根挂载并解释为何无法从容器内可靠映射宿主块设备；
- [ ] 我没有为了观察而修改服务或设备；
- [ ] 我能把网络问题定位到接口、地址、路由、DNS、socket 或远端之一；
- [ ] 报告包含复现、退出码、证据和回退；
- [ ] 分享前已经脱敏。
