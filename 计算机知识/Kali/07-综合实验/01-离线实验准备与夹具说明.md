# 离线实验准备与夹具说明

**先修关系：** [[计算机知识/Kali/01-系统与网络基础/04-Shell文件权限与文本处理|Shell文件权限与文本处理]]。

## 这里提供什么，不提供什么

本包的全部实验数据均为合成数据。`07-综合实验/夹具` 包含一条 TCP 会话的 PCAP、六条 JSONL 日志、两条公开教学口令的 SHA-256、五项候选表、小型路径字典、静态 Web 文件、正反例文本、教学 Pod YAML 和两个 Nmap XML 示意文件。**合成日志不是静态服务器自动产生的日志，PCAP 也不是本次实际抓包。** 它们演示相同概念，但来源不同。

没有真实凭据、恶意软件、内存镜像、磁盘镜像、无线握手、手机 APK、AD 或数据库靶机。课程中需要这些输入的地方明确标注为自备授权材料，不能拿附带静态 HTTP 服务冒充它们。

## 复制到独立实验目录

首先将压缩包解到 Vault 根目录。在 Linux 的 Bash 中，进入解压后 `计算机知识/Kali/07-综合实验` 目录，确认当前目录包含 `代码` 和 `夹具`，再运行：

```bash
pwd
ls
# 目标须为新目录；已存在时停止，不要为了重做练习删除旧证据。
LAB="$HOME/kali-lab"
if [ -e "$LAB" ] || [ -L "$LAB" ]; then
  printf '目标已存在；选择新的实验目录并同步修改后续路径。\n' >&2
else
  mkdir -m 700 "$LAB" && \
  cp -R -- 代码 "$LAB/code" && \
  cp -R -- 夹具 "$LAB/fixtures" && \
  mkdir -m 700 "$LAB/output"
fi
```

确认复制确实完成后再继续；若失败，检查失败位置而不是假定所有目录都已建立。以上适用于你控制的本机目录，不是抵御其他用户竞态替换的完整沙盒。课程后续默认 `LAB=$HOME/kali-lab`，改路径时必须相应替换。

## 文件合同和预期

| 输入 | 数据合同 | 最小检查点 |
| --- | --- | --- |
| `http-lab.pcap` | Ethernet/IPv4/TCP，小端经典 PCAP，10 帧 | 1 条连接、1 个 GET `/health`、200 响应 |
| `access.jsonl` | 每行一个对象，状态为整数 | 6 条，200×3、403×1、404×1、500×1 |
| `hashes-sha256.txt` | 两行小写十六进制、无用户名字段 | 五项候选能匹配两条 |
| `files/positive.txt` / `negative.txt` | 无害标记文本 | 前者有两个标记，后者缺第二个 |
| `nmap-before.xml` / `nmap-after.xml` | 显式标记 SYNTHETIC 的示例 | 8000 从 open 变 closed，不是扫描实测 |
| `iac/pod.yaml` | 不可部署的教学配置 | 镜像域为 example.invalid，安全字段有意不完整 |

详细预期与逐文件摘要见 [[计算机知识/Kali/07-综合实验/夹具/expected.json|expected.json]]。固定时间戳是 **2024-01-01 UTC** 的教学设定，和本包编写/测试日期无关。

## 无网络的第一步

```bash
cd "$HOME/kali-lab/code"
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_offline_lab.py
PYTHONDONTWRITEBYTECODE=1 python3 offline_lab.py \
  --fixtures "$HOME/kali-lab/fixtures"
```

需要 Python 3.10 或更高版本及可用的标准库 `sqlite3` 模块（某些极简构建可能未带该模块）；当前实际测试版本见 [[计算机知识/Kali/90-来源与维护/05-v3深度审阅与变更记录|v3 验收]]，并未在所有支持版本逐个运行。没有自动安装、端口监听或联网。检查报错必须保留，不能将缺少文件解释为“测试无发现”。

原始夹具不可就地编辑；变体写到 output，记录从什么输入改变了哪一处。内容快照版本为 `1.0`；代码或夹具修改后，按 [[计算机知识/Kali/07-综合实验/09-实验代码合同与复现|复现合同]] 重新核查，不把旧 expected 文件继续当成真值。

## v2 新增模型与夹具：和原版并存，不混写证据

`fixtures/v2/` 的内容版本为 `reasoning-v2.0`，包括路由案例、三份合成扫描 XML、授权决策表、时间线、检测计数、记录格式案例及独立清单。原版 `1.0` 夹具与生成器按字节保留；实验 A–F 保持原输入和核心流程，正文可补充解释，但不改写旧实验输出。v2 授权模型中对象身份和角色有独立定义，不能与原版所有权表拼接成历史记录。

原有 `cp -R` 步骤会一并复制新增代码和 v2 子目录。已经有 v1 实验目录时，选择一个新的独立目录，不直接覆盖自己已有输出，并相应修改后文路径。无网络的新增入口为：

```bash
cd "$HOME/kali-lab/code"
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_reasoning_lab.py
PYTHONDONTWRITEBYTECODE=1 python3 reasoning_lab.py
```

## v3 动态输入：临时证书与临时事务库

原复制步骤也会复制 K/L 的源码及 `validate_status.jq`。已经有 v1 或 v2 实验目录时，选择新目录并同步修改后续命令，不覆盖原来的输出。K/L 不向固定夹具目录写入，也不需要下载靶场。

[[计算机知识/Kali/07-综合实验/14-实验K离线证书链与身份校验|K]] 需要 Python 与已安装的 OpenSSL 3.x；本轮只验证所记录的具体版本。它在专属临时目录生成证书与密钥，报告不含密钥，结束清理目录。不是安全擦除保证；不要在真实材料目录改写生成路径。[[计算机知识/Kali/07-综合实验/15-实验L事务幂等与并发控制|L]] 需要 Python 3.11+ 的标准库 sqlite3，真实创建临时数据库，但这不等于附带 PostgreSQL、Redis 等服务器靶机。

额外的 `test_cli_workflows.py` 需要已安装 jq；它检查小型 JSON 值流合同，并独立复核正文数值。缺少依赖会报错，不自动安装，也不作为通过。全部具体入口、模型版本、临时写入与未支持范围见 [[计算机知识/Kali/07-综合实验/09-实验代码合同与复现|代码合同]]。
