# 知识表示：事实、规则、统一、归结与查询

“已知Ada是Ben的家长，Ben是Cora的家长，能否推出Ada是Cora的祖先？”这是显式事实与规则的推理问题。我们要知道哪些对象被谈论、谓词是什么意思、规则承诺什么，以及查询结果由哪些前提推出。文本向量相似可以帮检索相关片段，但相似度本身不定义逻辑蕴含，也不替代这个知识库。

先回顾[[数学/10-数学语言与基础/03-集合映射命题与合法推理|谓词、量词、充分条件]]，然后在这里建立一个小而完整的符号系统。本页选择经典逻辑与有限、无函数的正向规则子集；它不把缺失事实自动当现实世界中的否定。

## 一个事实和规则知识库

事实与规则如下。规则变量均隐含全称量词，每次应用前可以改名成新的局部变量。

```text
F1: Parent(Ada,Ben)
F2: Parent(Ben,Cora)
R1: Parent(x,y) -> Anc(x,y)
R2: Parent(x,y) AND Anc(y,z) -> Anc(x,z)
```

这里Anc意在表达“由至少一条Parent边连接的祖先关系”；R1/R2只要求这些路径对应的Anc为真，并未排除其他Anc关系。把Anc恰好取成路径闭包，要另加后述最小数据库约定；不把自己作为零步祖先。Parent是我们给定的关系名称；规则只编码传递推导，不认证事实是否来自可信记录。R1为确定Horn规则：多个正原子前提推出一个正原子结论；R2同样如此。

## 语法与语义先分开

命题逻辑中，原子p、q取真或假，用¬、∧、∨、⇒组成句子。一阶逻辑增加对象、变量、常量、函数与谓词。项是变量x、常量Ada，或函数项f(x)；谓词`Parent(x,y)`形成原子句。变量要受量词绑定才成为闭句，例如 $\forall x\forall y(Parent(x,y)\Rightarrow Anc(x,y))$。

一个**模型**给出非空论域及常量、函数、谓词的解释；公式在该解释下具有真值。知识库KB是一组闭句。$KB\models q$（蕴含）表示每个使KB全真的模型都使q真；$KB\vdash q$ 表示某推理过程写出了q的形式证明。**可靠性（soundness）**要求推得的都被蕴含，**完备性（completeness）**要求被蕴含的能被推得；两者不同。可满足表示至少一个模型使所有句子真。若KB本身矛盾，在经典逻辑中没有满足模型，因而蕴含任意句子；它不能作为可靠业务答案的依据。

开放世界下，“未证明Anc(Cora,Ada)”不等于证明其否定。有限数据库或规划器可显式约定闭世界，把未列出原子当假；这是一项额外模型约定。唯一名称（Ada、Ben、Cora互不同）、论域只含这三名人物，也不是一般一阶逻辑自动给出的事实；有限实验会明确采用这些数据库约定。

先固定规则模式怎样套到这两个事实，再沿同一替换计算结论。

## 统一是保持同一变量含义的替换

统一（unification）找替换 $\sigma$ 使两个项或原子应用替换后完全相同。最一般统一者MGU尽量不额外限定未被要求的变量；它不是按字面字符串相似度匹配。来自不同规则的变量先标准化分离，避免同名局部变量被意外绑定。

手算 `P(x,f(y))` 与 `P(Ada,f(Ada))`：谓词名称和元数一致；首参数要求x↦Ada；次参数函数名称f一致，再要求y↦Ada，得到 $\sigma=\{x\mapsto Ada,y\mapsto Ada\}$。代入两边均为 `P(Ada,f(Ada))`。

### 用同一替换走完正向与反向推演

回到R1：`Parent(x,y)`与F1统一为{x↦Ada,y↦Ben}，同一替换也要作用到结论`Anc(x,y)`，才得到`Anc(Ada,Ben)`。R2中y同时出现在两个前提中；选Parent(Ada,Ben)后，另一个前提必须成为Anc(Ben,z)，不能把第二次出现的y重新猜成别的人。

| 正向轮次 | 使用的前提与替换 | 本轮新增 |
| --- | --- | --- |
| 初始 | F1，F2 | 两个Parent事实 |
| 第1轮 | R1，{x↦Ada,y↦Ben}及{x↦Ben,y↦Cora} | Anc(Ada,Ben)，Anc(Ben,Cora) |
| 第2轮 | R2，{x↦Ada,y↦Ben,z↦Cora} | Anc(Ada,Cora) |
| 第3轮 | 没有能产生新原子的规则实例 | 停在不动点 |

查询 `Anc(Ada,Cora)` 为可推得；查询 `Anc(Ada,Who)` 返回Who=Ben、Cora。反向链也可复算：要证Anc(Ada,Cora)，选R2，把x=Ada,z=Cora，剩子目标Parent(Ada,y)与Anc(y,Cora)；F1统一y=Ben，再由R1及F2证Anc(Ben,Cora)。反向搜索可能选错规则或循环，逻辑规则可靠不等于搜索策略必然终止。

有限常量、无函数、只含确定Horn规则时，可能的基原子有限，正向链单调增加原子，终止于最小模型（最小不动点）。可靠性可按轮次归纳：事实被KB蕴含；某轮前提均被蕴含，规则在每个模型真，故新结论也被蕴含。对这个有限ground Horn子集，正向闭包给出所有被蕴含的正原子；不是在解决完整一阶逻辑。加函数f后可有 `P(a) -> P(f(a)) -> P(f(f(a))) ...`，有限终止理由失效。一般一阶逻辑蕴含只有半判定性质，证明不存在未必会停。[AIMA 作者第9章讲义，PDF第8、24–28、43–46页](https://aima.cs.berkeley.edu/slides-pdf/chapter09.pdf)用于定位这项边界与推理路线。

### 统一为什么会失败

上面的成功依靠同一变量始终取同一个项。若两个位置提出冲突要求，或要求变量包含自身，规则就不能用这次匹配产生结论。

`P(x,x)` 与 `P(Ada,Ben)`不能统一：第一位迫使x=Ada，第二位还要求Ada=Ben，在本实验不同常量项的语法体系中失败。若忽略“同一变量每次出现必须一致”而分别匹配，会错误成功。一阶理论中的等式推理则是额外机制，本实验并未实现它。

**Occurs check** 禁止把变量绑定到包含自身的有限项。试图统一x与f(x)，会要求有限项t=f(t)；右侧高度比左侧大1，不存在有限语法树解。较隐蔽的链 `P(x,f(x))` 与 `P(f(y),y)` 先有x=f(y)，随后要求y=f(f(y))，仍必须拒绝。检查要在已有替换解引用后进行，不能只在原字符串中查变量。[Stanford Logic Programming，Unification（变量改名与occur check段）](https://logical.stanford.edu/logicprogramming/miscellaneous/unification.html)明确给出变量绑定、发生检查与局部变量改名的算法条件。某些语言允许循环的rational tree，那已是不同项语义，不能假称为本文的有限一阶项。

## 归结如何可靠地消去一个互补文字

文字是原子或其否定，子句是文字的析取。命题归结规则为

$$
\frac{P\lor A\qquad \neg P\lor B}{A\lor B}.
$$

其可靠性逐模型证明很短：若模型使P假，为让首前提真就必须使A真；若P真，为让第二前提真就必须使B真；无论哪种，A∨B真。A或B可以是空析取，空子句恒假。一次只消去一对互补文字；不能从 `{p,q}` 与 `{¬p,¬q}` 同时消去两对而得空子句，因为赋值p=true,q=false使两前提都真，它们并不矛盾。正确的一次归结得到q∨¬q或p∨¬p这种永真子句。

一阶版本先统一互补原子并把同一个替换用于**两子句余下全部文字**：从 `¬Parent(x,y)∨Anc(x,y)` 和 `Parent(Ada,Ben)`，MGU为{x↦Ada,y↦Ben}，归结得Anc(Ada,Ben)。变量必须先标准化分离；要处理完整一阶归结完备性还涉及因子化、公平策略与正确的子句转换，本实验不声称实现完整定理证明器。

要证明 $KB\models q$，可把 $KB\land\neg q$ 化为子句并反驳。上例查询Anc(Ada,Cora)的完整链为：

```text
C1 Parent(Ada,Ben)
C2 Parent(Ben,Cora)
C3 ¬Parent(x,y) ∨ Anc(x,y)
C4 ¬Parent(u,v) ∨ ¬Anc(v,w) ∨ Anc(u,w)
C5 ¬Anc(Ada,Cora)             # 取查询的否定
C6 Anc(Ben,Cora)             # C2,C3，x=Ben,y=Cora
C7 ¬Anc(Ben,w) ∨ Anc(Ada,w)  # C1,C4，u=Ada,v=Ben
C8 Anc(Ada,Cora)             # C6,C7，w=Cora
C9 空子句                    # C5,C8
```

空子句说明KB与查询否定不可同时为真。命题逻辑有限饱和归结的反驳完备性见 [Stanford Introduction to Logic，第6章6.3–6.4，Resolution](https://logical.stanford.edu/intrologic/chapters/chapter_06.html)。本文给了这条查询的全部证据，但没有把归结完备性大定理的完整证明伪装成本页已有推导。

一般一阶转子句还要消蕴含、否定内移、变量改名、Skolem化及分配。Skolem化保可满足性，通常不与原句在原签名下逻辑等价；例如“∀x∃y喜欢(x,y)”需新函数y=f(x)，不能用一个固定常量充当所有x的见证。等号需要等号公理或专门推理；缺它的纯归结系统不能自行证明所有带等式结论。

## 回到祖先问题：本节最强结论

对给定F1/F2/R1/R2，我们已给出Anc(Ada,Cora)的正向推演、反向子目标链和归结反驳链，所以这项正结论被KB蕴含。统一负责使规则与前提结构一致；归结的空子句证明KB与查询否定不能同时为真。统一成功本身不认证前提为真，也不把任一未成功的搜索当成否定证明。有限正Horn闭包的完整性限于前述子集；一般一阶推理的终止边界仍适用。

现在只改变一个条件：暂去掉F2，人物与R1/R2保持不变。先写剩余Parent与新产生的Anc，再判断还能否证明Anc(Ada,Cora)。随后换成另一种表面情境：只知道“如果设备过热就报警”和“设备已报警”，是否能反推出设备过热？用一个真假赋值解释，和祖先规则的反向搜索作比较。

> [!success]- 参考解：缺前提与倒箭头分别在哪里失败
> 去掉F2后，只剩Parent(Ada,Ben)，R1只新增Anc(Ada,Ben)；没有Parent(Ben,…)或Anc(Ben,Cora)让R2推出Anc(Ada,Cora)。这说明该正原子不被剩余正向闭包证明，开放世界下不能升级为其否定。报警题令P表示过热、Q表示报警，P=false、Q=true满足P⇒Q与Q，却使P假；反向搜索应寻找某条能推出目标的规则并证明其全部前提，不能反转原规则的蕴含方向。

**题1：** KB只有P⇒Q和Q，能推出P吗？不能。P=false,Q=true满足KB，是反模型。反向链不是把蕴含箭头任意反过来。

**题2：** 未推得Anc(Cora,Ada)，能回答“否”吗？在原开放一阶知识下只能说“不被当前正向闭包证明”，没有推出¬Anc(Cora,Ada)。在显式有限最小数据库约定下可以回答该关系不在结果表中，但需保留这个约定。

**题3：** 把C4中u,v与另一规则的x,y直接复用可不可以？规则各自量词作用域局部，调用前应换新变量；同名字并不授予跨规则相等关系。先改名再做统一，才能避免意外捕获。

## 主课之后：换对象时重查合同

祖先正结论已经证明，以下分别继续三个问题：事实分区后怎样补齐跨分区前提；对反方向查询Anc(Cora,Ada)，未推出、表内无匹配和材料不足各能说到哪里；有限项统一移到类型树后保持了什么。每段保留自己的输入与条件，读完再回到本节的证明和否定边界。

## 闭包与分区合并

若F1与F2分放在两台机器，两边各自推理到停止，把结果合在一起就够了吗？先保持原人物与R1/R2不变。本节的输入是可信的Parent事实，只增不删；两副本最终会收到全部事实，没有函数、新人物、默认规则或恶意状态。查询记为 $q^+=Anc(Ada,Cora)$；下一节的静态问题仍是 $q=Anc(Cora,Ada)$，两者不要混用。

### 一次推理、完整闭包与闭合状态

令人物集合 $V=\{Ada,Ben,Cora\}$，有限基原子集合为

$$
H=\{Parent(x,y),Anc(x,y):x,y\in V\},\qquad |H|=18.
$$

这里保留谓词身份：Parent(Ada,Ben)与Anc(Ada,Ben)是不同元素。环境先取幂集 $(\mathcal P(H),\subseteq)$。对任意 $S\subseteq H$，一次同步推理是

$$
T(S)=S\cup\{Anc(x,y):Parent(x,y)\in S\}
\cup\{Anc(x,z):Parent(x,y),Anc(y,z)\in S\}.
$$

右侧前提都从本轮开始的S读取。令 $S_0=S,\ S_{n+1}=T(S_n)$，首次不再变化所得集合记作 $Cl(S)$。一次T可能尚未饱和；$Cl$才是完整闭包；满足 $Cl(S)=S$ 的S称为闭合状态。任意S的定义允许Anc作为种子，但本节两分区实际只从F1/F2产生状态，不能把任意Anc种子说成已核实的亲属事实。

T保留旧原子，每次严格变化至少增加一个H元素，故同步迭代至多 $18-|S|$ 次严格增加便停止。如果实现改为逐条规则的工作列表，须公平地处理所有已满足前提的规则实例，且没有遗漏的待重算依赖；有限状态只限制严格增加次数，不保证一个永远跳过R2的调度器会给出完整闭包。

三个性质分别回答不同问题：

- **扩张性：** $S\subseteq Cl(S)$，因为每轮保留S。
- **单调性：** $S\subseteq U\Rightarrow Cl(S)\subseteq Cl(U)$。正规则在S中成立的全部前提在U中仍成立，故T保序；逐轮归纳并取稳定结果即得。
- **幂等性：** $Cl(Cl(S))=Cl(S)$。第一次已使全部规则封闭，再算不会新增。

还需要一个最小性事实：任意闭合Z若包含S，则逐轮归纳得到 $T^n(S)\subseteq Z$，因此 $Cl(S)\subseteq Z$。这说明闭包是包含输入的**最小闭合状态**，为后面的join证明提供依据。

### 两个局部闭包的并集漏了哪一步

缩写 $P_{AB}=Parent(Ada,Ben)$、$P_{BC}=Parent(Ben,Cora)$，$A_{AB},A_{BC},A_{AC}$分别指对应的Anc原子。下表仍保留Parent与Anc两列；每行“新增”区别消息带来的输入与推理的结论。

| 对象或动作 | Parent输入 | Anc结果 | $q^+$的当前成员值 |
| --- | --- | --- | --- |
| 副本1收到 $D_1=\{P_{AB}\}$ | $P_{AB}$ | 尚未推理，空 | false |
| 副本1执行R1后停止，$S=Cl(D_1)$ | $P_{AB}$ | $A_{AB}$ | false |
| 副本2收到 $D_2=\{P_{BC}\}$ 并执行R1后停止，$U=Cl(D_2)$ | $P_{BC}$ | $A_{BC}$ | false |
| 收到两闭包，只做普通并集 $S\cup U$ | $P_{AB},P_{BC}$ | $A_{AB},A_{BC}$ | false |
| 对该并集再执行R2 | 同上，没有新Parent | 新增 $A_{AC}$ | true |
| 再一轮无新增，得到 $G=Cl(D_1\cup D_2)$ | 同上 | $A_{AB},A_{BC},A_{AC}$ | true |

漏掉的唯一原子是 $A_{AC}$。其跨分区实例正是R2的 $x=Ada,y=Ben,z=Cora$：Parent(Ada,Ben)来自副本1，Anc(Ben,Cora)由副本2的F2经R1产生。两边各自算完时都没有这组完整前提。

因此

$$
Cl(D_1)\cup Cl(D_2)\subsetneq Cl(D_1\cup D_2).
$$

Cl单调，却不保持这里的普通并集。令 $b(X)=\mathbf 1[q^+\in X]$，只传两个局部闭包的查询位并做OR，会得到 $b(S)\lor b(U)=false$，而 $b(G)=true$。OR本身交换、结合、幂等，但这两个布尔位丢掉了组成新规则实例的前提。修复可以传原Parent后重新饱和，也可以传足够的闭合推理状态并采用下面的join；“查询随事实增长保持”不能证明任意输出摘要都足够合并。

### 换成闭合状态后，join为什么需要再闭包

数学上的上确界总依赖所在环境，定义回查[[数学/12-离散数学与逻辑/02-关系函数等价类与偏序#5. 最小与极小、上界与上确界|最小上界及其环境]]。令

$$
\mathcal C=\{S\subseteq H:Cl(S)=S\}.
$$

| 偏序环境 | 两元素的join | 两个局部闭包S、U的合并 |
| --- | --- | --- |
| 全部基原子集合的幂集 $\mathcal P(H)$，按包含排序 | 普通并集 $S\cup U$ | 是该环境的最小上界，但不闭合 |
| 只含闭合状态的 $\mathcal C$，仍按包含排序 | $S\sqcup_{\mathcal C}U=Cl(S\cup U)$ | 得到G，补上 $A_{AC}$ |

证明第二行：由幂等性，$Cl(S\cup U)\in\mathcal C$；由扩张性，它包含S和U，因而是上界。任取闭合共同上界Z，$S\cup U\subseteq Z$；由单调性和Z闭合，$Cl(S\cup U)\subseteq Cl(Z)=Z$。所以它确实是最小上界。

交换性来自并集交换；幂等性来自S闭合。结合性可用下式看清：

$$
Cl(Cl(X)\cup Y)=Cl(X\cup Y).
$$

一边由 $X\subseteq Cl(X)$ 得到包含；另一边令 $W=Cl(X\cup Y)$，由单调性 $Cl(X)\subseteq W$ 且 $Y\subseteq W$，再用W闭合得到反向包含。故对三个闭合状态S、U、W，

$$
(S\sqcup_{\mathcal C}U)\sqcup_{\mathcal C}W
=Cl(S\cup U\cup W)
=S\sqcup_{\mathcal C}(U\sqcup_{\mathcal C}W).
$$

于是顺序、分组和重复旧状态不改变最终join。读者可取第三个状态为 $G=Cl(D_1\cup D_2)$，复算 $(S\sqcup U)\sqcup G=S\sqcup(U\sqcup G)=G$；收到S、U、S或U、S、S，结果也都是G。一般结论依靠上述证明，不能由这一条消息轨迹替代。

实现若维护闭合状态，每次收事实d可更新为 $Cl(S\cup\{d\})$，每次收闭合状态U则更新为 $Cl(S\cup U)$。若维护原事实，先并合事实，再公平地重新饱和。两种方案都只上升。设停止新增后的真实Parent集合为 $D^*$，每个副本最终获得全部 $D^*$，只接收由这些事实可靠推出的状态，并完成公平推理，则它的结果既不超过 $Cl(D^*)$，又包含 $D^*$ 的最小闭包，故最终等于 $Cl(D^*)$。有限H保证推理有限；最终传播保证数据能到达。这不是一个可由本地观察算出的统一网络截止时刻。永久遗漏最后事实或漏掉规则重算，ACI都不能补救。到[[计算机知识/65-分布式系统/02-复制一致性与可见性历史#闭合推理状态与原事实分别怎样合并|复制页的同一两分区对象]]对照G-Counter所保存的写者信息与这里所保存的推理前提。

### 未收到的事实，让否定何时才能定案

已经推出 $q^+$ 时，固定正规则和只增事实使这项正结论保持。若尚未推出，则考虑在有限时刻t、只收到D₁并算得S的副本1：

| 消息历史 | 截至t的本地观察 | 后续事实与消息 | 全部事实的最终闭包 |
| --- | --- | --- | --- |
| H₀：副本2没有F2，此后也无新事实 | 收到D₁，Anc只有 $A_{AB}$；无完整性信号 | 副本2最终确认其批次为空 | 不含 $q^+$ |
| H₁：副本2已有F2，但消息延迟到t之后 | 完全相同 | F2最终送达，重算R1/R2 | 含 $q^+$ |

H₀是拿掉F2的反事实输入，不是声称原两事实任务里F2实际不存在。算法截至t看到相同本地历史，就不能在两条历史中做出不同的可靠判定；若此时给出针对全部事实、永不撤回的否定，就会在H₁中错。等待固定时长、本地队列为空或本地推理已饱和，都不排除H₁。

合法定案须补足范围与完成条件。例如为**指定的封闭批次**预先确定两个来源及其最终序号；取得两来源的批次完成确认，并确实收齐这些序号内的记录，再完整饱和，才能依据[[AI/13-搜索推理与规划/05-知识表示规则归结与查询#改成有限最小数据库时多承诺了什么|有限最小数据库合同]]回答该批次中 $q^+$ 存在或不存在。完成标记可能先于数据到达，必须核实缺口已经补齐；未来批次不在这次否定范围。若清单预先已经明确列出F1和F2，副本1则已知道输入还缺F2，更不能提前否定。

增长关系的路径证据与否定所需的完成信息，可对照 [Hellerstein、Alvaro，Keeping CALM，§1.3–2.2](https://arxiv.org/html/1901.01930v2)。本节只证明上述有限Horn模型与不可区分历史，不把无需全局完成确认的正结果等同于不需通信、线性一致、容量安全或完整CALM定理。

## 同一查询：未推出、表内无匹配与证据不足

系统没有找到某关系，能否回答它不存在？先固定对象与问题：$q=Anc(Cora,Ada)$，即“Cora是Ada的祖先吗”。知识库证明、查表与材料检索有不同输入，下面保持问题不变，逐次声明可访问范围和否定合同。

### 两个模型把开放世界的未决定算清

沿用F1/F2/R1/R2；R1与R2分别是 $\forall x\forall y(Parent(x,y)\Rightarrow Anc(x,y))$ 和 $\forall x\forall y\forall z((Parent(x,y)\land Anc(y,z))\Rightarrow Anc(x,z))$。构造两个经典一阶模型，论域均取 $D=\{Ada,Ben,Cora\}$，三个常量分别解释为对应对象：

| 模型 | Parent的扩展 | Anc的扩展 | $q$ |
| --- | --- | --- | --- |
| $M_0$ | {(Ada,Ben),(Ben,Cora)} | {(Ada,Ben),(Ben,Cora),(Ada,Cora)} | 假 |
| $M_1$ | 再加(Cora,Ada) | $D\times D$，全部九个有序对 | 真 |

逐项检查：两模型都有F1、F2。$M_0$中R1的两条前提边都在Anc中；R2唯一前提同时成立的三元组为(Ada,Ben,Cora)，结论(Ada,Cora)也在Anc中。$M_1$中Anc含全部有序对，所以R1/R2的任意真前提都有真结论；三条Parent边成环，每一对对象也确实有至少一步路径，包括绕环回到自己。这个环是所列形式规则允许的构造，不是现实亲属事实。

因此 $M_0\models KB\land\neg q$，$M_1\models KB\land q$，得到 $KB\not\models q$ 且 $KB\not\models\neg q$。选这三个互异对象只为展示反模型；原KB没有自动得到唯一名称、封闭论域或亲属无环公理，也没要求所有模型取最小闭包。每个模型仍给每个闭句二值真值；“KB未决定”说的是不同模型之间不一致，**不是经典逻辑里出现了SQL的UNKNOWN真值**。

### 改成有限最小数据库时多承诺了什么

现在显式增加查询合同：论域仅这三名人物，常量互异，Parent表完整且只有F1/F2，Anc结果表恰好是至少一步路径的最小闭包，未列关系按假处理。表中只有 $M_0$ 的三个Anc对，故 $q$ 不在表中，可以回答“在这个已完成的数据库中，Cora不是Ada的祖先”。这个否定来自完成/闭世界约定；若表只是部分记录，就不能删掉范围限定而说现实关系不存在。

### SQL与RAG分别把没有放在哪里

为接上SQL现成算例，把关系键1约定为(Ada,Ben)、键2约定为(Cora,Ada)；NULL表示某记录的关系键尚未给定，并不是第三个人。查询合同改为在当前键表中寻找等值匹配。复算[[计算机知识/55-数据库/10-系统课程/03-SQL查询语义与窗口函数#把反连接的三种结果逐行算完|outer={1,2,NULL}、rhs={1,NULL}]]：

| 外层键 | NOT IN | 等值NOT EXISTS | 最强的表内结论 |
| --- | --- | --- | --- |
| 1 | FALSE | FALSE | 找到一行等值条件为TRUE的记录 |
| 2（对应$q$） | UNKNOWN | TRUE | 没有等值条件为TRUE的匹配行；含NULL的右表不足以令NOT IN为TRUE |
| NULL | UNKNOWN | TRUE | 外层键未给定，普通等号没有TRUE匹配；不能据此否定某个确定关系 |

WHERE过滤FALSE与UNKNOWN是行选择合同，不使二者同义。[PostgreSQL 17 §9.24.1/9.24.3](https://www.postgresql.org/docs/17/functions-subquery.html)直接规定EXISTS的行存在判断及NOT IN遇NULL的结果；本表采用含NULL的非空rhs，不能把外层NULL这一行的结果照搬到所有查询形状。NOT EXISTS取反的是“有没有使指定条件为TRUE的行”；右表NULL可能来自字段缺失，外连接的NULL可能是无匹配补行，空聚合的NULL还可能是无输入结果。每种NULL都需回到来源，不能统称“现实关系不存在”；外层非空守卫和空值相等比较的区别保留在SQL主例。

RAG则对同一$q$检查可访问材料，而不枚举KB全部模型或当前表全部行。[[AI/20-LLM/70-工程应用与工具链/08-混合检索重排RAG误差分解与证据#同一关系的三种材料条件|三种固定材料条件]]分别允许“必要证据未召回”“所召回材料未支持$q$”“有效材料明确支持$\neg q$”。空top-k只能报告当前可访问材料的证据不足，不推出全库或现实不存在；否定材料也要绑定对象、范围与版本。

问题仍是$q$。甲系统只有F1/F2/R1/R2；乙系统采用上面的完整有限最小数据库；丙系统运行上述SQL，取外层键NULL。分别写最强回答，标出依据来自模型、结果表、查询条件还是材料覆盖，并给一个反模型或逐行SQL结果支持理由。最后换成RAG只召回“Cora与Ada参加了同一次活动”，能否把答案升级为“不是祖先”？

## 深化：把统一迁移到类型树

### 把有限项方程迁移成HM类型方程

上面的 `P(x,f(y))` 与 `P(Ada,f(Ada))` 依靠同构造器、同元数与同一变量的一致替换成功；把同样的有限树方程搬到类型对象层：

| 类型语法 | 一阶项编码 | 保持的结构 |
| --- | --- | --- |
| 类型变量α | 项变量α | 可由替换绑定的未知量 |
| 基础类型Bool | 零元构造器Bool | 固定构造器，不是待猜对象 |
| τ₁→τ₂ | 二元构造器Arrow(τ₁,τ₂) | 有次序的输入、输出子树 |

这里的保解集限于同一类型签名：项替换的值也必须是类型语法编码的像，只使用允许的基础类型与Arrow等类型构造器；不能把f(Ada)之类非类型项塞进替换。逐构造器递归编码类型树，替换也逐项编码，则编码后再替换等于替换后再编码；因此在这个限定域内，两侧相等的类型替换恰对应编码后的有限项替换。Bool在这里是构造器，α是解方程的变量；AI规则中的对象变量与程序的类型变量所属对象层不同，变量标准化和绑定身份仍须按各自作用域处理。

共同方程为 $\alpha\to\beta=\beta\to\gamma$，编码成 `Arrow(α,β)=Arrow(β,γ)`，拆为α=β、β=γ。先作 $\sigma_1=\{\alpha\mapsto\beta\}$，再作 $\sigma_2=\{\beta\mapsto\gamma\}$；组合 $\sigma_2\circ\sigma_1$ 表示先应用σ₁再应用σ₂，得到规范化替换 $\sigma=\{\alpha\mapsto\gamma,\beta\mapsto\gamma\}$，γ保持自由。代入原两边均为 `Arrow(γ,γ)`。任一解都令三个变量相等，因此可由再替换γ为某个有限类型得到；这是此方程的最一般解，没必要额外固定为Bool。自由变量的保留不自动授予let泛化，仍须看环境。

到[[计算机知识/70-编译原理/10-系统课程/11-类型统一泛化与值限制#一次逐行统一：f(f x)|f(f x)的类型约束]]检查这两种箭头要求从哪里产生，再到[[计算机知识/70-编译原理/10-系统课程/11-类型统一泛化与值限制#occurs check 为什么不可省|自应用的有限类型失败]]。反向回到本页的间接绑定 `x=f(y), y=f(x)`：先代入x=f(y)，第二式变为y=f(f(y))。若 $h(t)$ 是有限树高度，每套一层f高度增1，此式要求 $h(t)=h(t)+2$，不可能。类型式 $\alpha=Arrow(\alpha,\beta)$ 同理：右树高度为 $1+\max(h(\alpha),h(\beta))>h(\alpha)$，不是因为某段代码碰巧栈溢出。

有限树统一拒绝循环；rational tree允许有限图表示某些无限循环展开；显式递归类型还要规定折叠/展开及类型等价规则。后两者不是删除occurs check便完成的HM扩展。`x x`在本页HM核心中无类型，不推出一般程序递归非法；递归绑定需另外声明语言规则。

还要分开三个判断：$\sigma(P(x))=\sigma(P(Ada))$是结构统一；$KB\models P(Ada)$是全部模型的蕴含；$\Gamma\vdash e:\tau$是指定类型系统对程序的判断。空KB中前两原子可由x↦Ada统一，但取P扩展为空的模型就反驳蕴含。类型方程有解也须与语法产生约束、环境及泛化规则一起使用，更不能证明业务规格或终止。

**迁移题：** 在上述有限树语法中，把共同方程改为 `Arrow(α,Bool)=Arrow(Bool,γ)`，写MGU；再把 `Pair(x,y)=Pair(f(y),f(x))` 拆分，给具体失败约束。参考解：第一题α↦Bool、γ↦Bool，两边为Arrow(Bool,Bool)；第二题先x=f(y)，代入剩式后y=f(f(y))，没有有限树解。若另行声明允许循环图，需重新讨论解的对象与等价规则，不能沿用这项无有限树解结论去否定所有扩展语法。

"""Fixed-input comparison for finite models, SQLite and existing finite-tree unify.

Run from this directory with Python 3.10+: python3 -B query_contract_examples.py
No service, files or network are opened. SQLite uses a disposable memory database.
Finite-model checks enumerate rule instances, not all first-order models.
The fixed expected answers are in the companion knowledge representation page; this module
reports observations without deriving an oracle from the solver it exercises.
"""
from itertools import product
import json
import sqlite3

from symbolic_ai_lab import Fun, Var, apply, unify

DOMAIN = ("Ada", "Ben", "Cora")
FACTS = frozenset({("Ada", "Ben"), ("Ben", "Cora")})
QUERY = ("Cora", "Ada")
MODELS = {
    "M0": (FACTS, frozenset({("Ada", "Ben"), ("Ben", "Cora"), ("Ada", "Cora")})),
    "M1": (FACTS | {QUERY}, frozenset(product(DOMAIN, repeat=2))),
}

SQL = """
WITH outer_values(x) AS (VALUES (1), (2), (NULL)),
     rhs(y) AS (VALUES (1), (NULL))
SELECT o.x,
       o.x NOT IN (SELECT y FROM rhs),
       NOT EXISTS (SELECT 1 FROM rhs AS r WHERE r.y = o.x),
       o.x IS NOT NULL AND NOT EXISTS (
           SELECT 1 FROM rhs AS r WHERE r.y = o.x)
FROM outer_values AS o
ORDER BY o.x IS NULL, o.x
"""


def finite_models():
    """Test every assignment to the universally quantified rule variables."""
    result = {}
    for name, (parent, anc) in MODELS.items():
        r1_failures = [[x, y] for x, y in product(DOMAIN, repeat=2)
                       if (x, y) in parent and (x, y) not in anc]
        r2_failures = [[x, y, z] for x, y, z in product(DOMAIN, repeat=3)
                       if (x, y) in parent and (y, z) in anc and (x, z) not in anc]
        result[name] = {
            "facts_true": FACTS <= parent,
            "r1_failures": r1_failures,
            "r2_failures": r2_failures,
            "query_true": QUERY in anc,
            "parent": sorted(parent),
            "anc": sorted(anc),
        }
    return result


def sql_rows():
    with sqlite3.connect(":memory:") as connection:
        rows = connection.execute(SQL).fetchall()
    return {"engine": "SQLite", "version": sqlite3.sqlite_version, "rows": rows,
            "encoding": "SQL FALSE=0, TRUE=1, UNKNOWN=None; not PostgreSQL execution"}


def render(term):
    if isinstance(term, Var):
        return term.name
    return term.name if not term.args else term.name + "(" + ",".join(map(render, term.args)) + ")"


def observe(left, right, tracked):
    sigma = unify(left, right)
    if sigma is None:
        return {"input": [render(left), render(right)], "unifiable": False}
    return {"input": [render(left), render(right)], "unifiable": True,
            "normalized_variables": [render(apply(v, sigma)) for v in tracked],
            "equal_after_apply": apply(left, sigma) == apply(right, sigma),
            "applied": [render(apply(left, sigma)), render(apply(right, sigma))]}


def finite_tree_examples():
    a, b, c = map(Var, ("alpha", "beta", "gamma"))
    x, y = map(Var, ("x", "y"))
    ada, boolean = Fun("Ada"), Fun("Bool")
    f = lambda t: Fun("f", (t,))
    arrow = lambda s, t: Fun("Arrow", (s, t))
    pair = lambda s, t: Fun("Pair", (s, t))
    return {
        "atom": observe(Fun("P", (x, f(y))), Fun("P", (ada, f(ada))), (x, y)),
        "arrow": observe(arrow(a, b), arrow(b, c), (a, b, c)),
        "changed_constructor": observe(arrow(a, boolean), arrow(boolean, c), (a, c)),
        "indirect_occurs": observe(pair(x, y), pair(f(y), f(x)), (x, y)),
        "type_occurs": observe(a, arrow(a, b), (a, b)),
        "constructor_conflict": observe(Fun("Bool"), Fun("Int"), ()),
        "unifiable_not_entailment": observe(Fun("P", (x,)), Fun("P", (ada,)), (x,)),
    }


def main():
    report = {"models": finite_models(), "sql": sql_rows(), "trees": finite_tree_examples()}
    print(json.dumps(report, ensure_ascii=False, indent=2))


if __name__ == "__main__":
    main()
