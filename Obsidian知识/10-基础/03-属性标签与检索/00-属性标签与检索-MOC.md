# 属性、标签与检索

> [!abstract] 本模块的主线
> 把一篇普通 Markdown 笔记变成“既能读，也能被筛选、排序和重新组织的数据”。完成后，你应该能回答：**文件夹、链接、标签、属性、搜索和 Base 各自解决什么问题？**

## 从这里开始

1. [[Obsidian知识/10-基础/03-属性标签与检索/01-属性类型|属性类型]]：认识文本、列表、数字、复选框、日期、日期时间和标签。
2. [[Obsidian知识/10-基础/03-属性标签与检索/02-嵌套标签|嵌套标签]]：用 `/` 建立轻量的状态与主题层级。
3. [[Obsidian知识/10-基础/03-属性标签与检索/03-核心搜索语法|核心搜索语法]]：从关键词走到路径、属性、任务和布尔组合。
4. [[Obsidian知识/10-基础/03-属性标签与检索/04-快速切换器书签与大纲|快速切换器、书签与大纲]]：区分“打开、保存入口、在文内跳转”。
5. [[Obsidian知识/10-基础/03-属性标签与检索/05-Note-Composer-合并与拆分|Note Composer：合并与拆分]]：把长笔记拆成原子笔记，把碎片合并为主题笔记。
6. [[Obsidian知识/10-基础/03-属性标签与检索/06-安全重构与链接维护|安全重构与链接维护]]：移动、重命名、检查链接、撤销和恢复。
7. [[Obsidian知识/10-基础/03-属性标签与检索/07-检索挑战|检索挑战]]：只看题目，使用准备好的甲、乙、丙样例找答案。

## 一张决策表

| 手段 | 最适合回答的问题 | 本模块示例 |
| --- | --- | --- |

| 内部链接 | 它具体关联哪一篇笔记？ | [[Obsidian知识/30-实践/01-实验区/数据/乙-阅读卡片\|乙-阅读卡片]] |

| MOC | 我希望别人按什么顺序理解它们？ | 当前这篇导航页 |

> [!tip] 最小可持续 schema
> 教程笔记使用 `type / level / status / module / order / plugins / tags`；实验数据根据类型增加 `topics / created / rating / due / progress / fixture_reviewed / related`。不需要为了“整齐”给每篇笔记塞入所有字段。

## 先观察准备好的数据

- [[Obsidian知识/30-实践/01-实验区/数据/甲-晨间笔记|甲-晨间笔记]]：日期型记录；有复选框、数字、日期和列表。
- [[Obsidian知识/30-实践/01-实验区/数据/乙-阅读卡片|乙-阅读卡片]]：来源型记录；有作者、评分、完成日期和相关链接。
- [[Obsidian知识/30-实践/01-实验区/数据/丙-项目记录|丙-项目记录]]：项目型记录；有优先级、截止日期和进度。

打开 Properties view 或执行命令 **Show all properties**，比较三篇笔记同名属性的类型是否一致。然后打开 [[Obsidian知识/40-视图/02-Bases/00-MOC-Bases|Bases 导航]]，观察同一批文件如何变成表格、卡片或列表。

## 15 分钟体验路线

- [ ] 打开甲、乙、丙，比较它们顶部的属性。
- [ ] 在搜索中输入 `path:"Obsidian知识/30-实践/01-实验区/数据"`。
- [ ] 加上 `[status:active]`，观察结果减少。
- [ ] 点击一个嵌套标签，观察父标签和子标签的关系。
- [ ] 打开 [[Obsidian知识/40-视图/02-Bases/示例笔记目录.base|示例笔记目录]]，切换“表格”和“卡片”视图。
- [ ] 在甲中把 `energy` 从 `4` 改成 `5`，回到 Base 观察变化，再改回 `4`。

## 检查结果

完成本模块后，你应该能用一句话解释：

> Base 不是把笔记搬进数据库；它读取 Markdown 文件与属性，并保存一份可复用的视图定义。

还应该能做到：

- 看到属性时知道它的类型，而不是把所有值都当字符串；
- 用 `#状态/子状态` 表达层级，同时保留真正的实体链接；
- 用 Search 逐步缩小结果，而不是靠记忆翻文件夹；
- 在重命名或拆分前检查反向链接，并知道如何撤销或从 File recovery 恢复；
- 用 Quick Switcher、Bookmarks 和 Outline 解决三种不同的导航问题。
