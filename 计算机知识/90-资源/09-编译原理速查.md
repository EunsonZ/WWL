# 编译原理速查

这页用于把报错、IR、优化、目标代码和运行时现象放回同一条证据链。它压缩术语和边界，不替代语言规范、目标 ABI、链接器文档或具体编译器版本的实现说明。先固定源代码 revision、命令行、工具版本、目标三元组/ISA 与输入；“生成了二进制”不证明语义、性能或部署兼容性。

## 阶段、对象与最早可诊断问题

| 阶段 | 主要输入 → 输出 | 核心对象/不变量 | 最早可靠诊断的问题 | 尚不能证明 |
| --- | --- | --- | --- | --- |
| 预处理/词法 | 字符流 → token | token 有类别、位置；注释/空白通常不入语法 | 非法字符、token 形状、宏展开后的文本 | 文法结构、名称或类型正确 |
| 语法分析 | token → parse tree / AST | 树符合文法；AST 丢弃无关表面细节但保留结构 | 括号/分隔符、产生式不匹配、优先级/结合性 | 变量存在、调用合法、运行结果 |
| 语义分析 | AST + 符号表 → 带类型 AST | 名称绑定唯一；类型、作用域、控制流约束成立 | 未声明名、重定义、类型不匹配、不可达/缺返回（按语言规则） | 优化有效、机器 ABI 正确 |
| IR 构建与验证 | 已分析程序 → IR / CFG | 每个基本块有入口；边与 terminator 一致；SSA 值单定义 | IR 结构、支配、类型或控制流不变量破坏 | 变换保持语义、一定更快 |
| 优化 passes | IR → IR | 每个 pass 保持既定语义；分析结果与 IR 版本匹配 | pass 前后 verifier 失败、非法重写、分析失效 | profitability、目标机最终指令形状 |
| 指令选择/寄存器分配 | IR → 汇编/目标文件 | 指令满足目标 ISA；虚拟值被物理寄存器或 spill 覆盖 | 不支持的特性、约束冲突、目标特定 codegen 错误 | 链接成功、动态库可加载 |
| 汇编/链接 | `.o` + 库 → 可执行文件/共享库 | 符号按规则解析；重定位被静态解析或保留 | 未定义/重复符号、库顺序、ABI/架构不匹配 | loader 能找到动态依赖、程序逻辑正确 |
| 加载/执行/JIT | 文件/字节码/IR → 进程内可执行代码 | 映射、重定位、权限、运行时契约满足 | 缺库、入口/符号解析、装载格式、JIT guard/deopt 失败 | 结果正确、热路径已优化 |

**最快定位顺序：**先保存第一条错误和完整命令；再确认失败发生在 source、IR、object、link、load 还是 runtime。后阶段报错不能反推前阶段完全正确，例如链接通过也不证明 C++ ABI、数据竞争或数值语义正确。

## 核心对象与不变量

| 对象 | 速记 | 必须守住的事 |
| --- | --- | --- |
| lexer / token stream | 把字节按语言词法切分 | 最大吞噬、关键字分类、源位置与 Unicode/编码策略必须由语言定义，而非“看起来像字符”。 |
| parser / AST | 根据文法构造层级结构 | precedence、associativity 与歧义消解属于语法契约；AST 不是源文本的逐字副本。 |
| symbol / type environment | 名称到声明、类型、存储类别等信息 | 同一作用域绑定、遮蔽、泛型/重载解析和生命周期规则必须可追溯。 |
| IR | 适于分析和变换的程序表示 | 定义—使用关系、类型、内存/异常/副作用模型必须明确；不同 IR 不能默认等价。 |
| CFG / basic block | 控制流图；块内除末尾外无分支 | 每条边对应 terminator；入口、可达性与异常边也要纳入图。 |
| SSA | 每个 SSA value 恰好一次定义 | 多路径汇合用 `phi` 选择“沿哪条前驱边来的值”；变量名相同不等于 SSA value 相同。 |
| data-flow facts | 到达定义、活跃变量、常量、范围等 | lattice、transfer function、合流算子和不动点方向要匹配问题；事实过期不能复用。 |
| pass pipeline | 变换与分析的有序组合 | 每个 pass 的前置条件、保持/失效的分析、验证点与目标版本要记录。 |
| machine code / object | 指令、节、符号、重定位 | 指令编码、calling convention、对齐、节权限与目标架构必须一致。 |

## 文法、控制流与数据流术语

| 术语 | 一句话 | 常见误解 |
| --- | --- | --- |
| FIRST(X) | 从 `X` 可推导句子的首个 terminal 集；必要时含 `ε` | FIRST 不是“X 后面第一个 token”。 |
| FOLLOW(A) | 在某句型中可紧跟非终结符 `A` 的 terminal 集；开始符号含 EOF | FOLLOW 用于预测/归约条件，不决定任意 CFG 的后继。 |
| LL / LR | 自顶向下预测 / 自底向上移进归约的分析家族 | 文法可被某算法处理，不等于语言语义或实现性能已解决。 |
| dominance | 从入口到 `n` 的所有路径都经过 `d`，则 `d` 支配 `n` | 支配是 CFG 概念；不等同于执行次数更多或文本位置更早。 |
| immediate dominator | 严格支配 `n` 中最接近 `n` 的节点 | 支配树不是原 CFG，也不编码所有边。 |
| `phi` | 在块入口、按前驱边选择 SSA 值的伪操作 | 它不是普通运行时函数调用；边与 value 的配对不可乱序。 |
| liveness | 某点之后存在不被重定义就使用该值的路径 | 活跃不等于“现在有值”或“对象仍有语言级生命周期”。 |
| worklist | 将事实变化的节点重新排队，直到不动点 | 终止依赖有限高度/单调性等条件；队列顺序影响效率，通常不改结果。 |
| alias analysis | 两个指针/引用是否可能指向同一内存位置 | `may-alias` 不能当 `must-alias`；保守未知会阻止一些重排。 |
| escape analysis | 对象/引用是否逃出可局部推理范围 | 未逃逸可能允许栈分配或标量替换，但仍受异常、线程和语言语义约束。 |
| register allocation | 给 live range 分配物理寄存器，冲突则 spill | 寄存器数不是唯一成本：调用约定、指令约束、spill/reload 和调度也影响结果。 |

## 变换的三道门：合法、收益、可观测

| 边界 | 要问的问题 | 典型反例 |
| --- | --- | --- |
| **legality（合法性）** | 在语言、IR 内存模型、异常/volatile/原子、别名与 UB 假设下，改写是否保持可观察语义？ | 把可能别名的 load/store 交换；删掉有副作用调用；忽略浮点舍入或 NaN 语义。 |
| **profitability（收益性）** | 目标机、profile、代码尺寸、寄存器压力、缓存和编译预算下，值得做吗？ | 循环展开合法却造成 I-cache 压力或 spill；融合减少访存却降低并行度。 |
| **validation（验证）** | 哪个 checker、测试、差分、sanitizer、IR dump、反汇编或 profile 支持此结论？ | 单元测试通过却未覆盖未定义行为；出现 SIMD 指令却不知道热点是否执行。 |
| **observability（可观测性）** | 用户/调用者可观察到什么：输出、异常、I/O、时序、原子顺序、ABI？ | “结果数值相同”却改变异常时机、写日志次数、锁顺序或动态符号。 |

优化通常需要先过 legality，再由成本模型决定 profitability；它们都不是“编译器很聪明”的同义词。profile-guided、JIT 或 autotune 决策还要绑定具体输入、硬件和版本。

## compile、link、load、execute：不要混用

| 动作 | 产物/责任 | 典型失败 | 和相邻阶段的分界 |
| --- | --- | --- | --- |
| compile | 源/IR 编为汇编或目标文件；每翻译单元可独立进行 | 语法、类型、目标 feature、代码生成 | 不解析跨对象全部符号，也不把动态依赖映射进进程。 |
| assemble | 汇编文本编码成 object | 指令/伪指令、节、目标架构 | 常被 driver 吸收；不是 link。 |
| link | 合并 object/library、解析符号、处理 relocation，产出可执行文件或库 | undefined/duplicate symbol、库顺序、目标/ABI 不兼容 | 可留下动态 relocation；不负责在某台机器找到共享库。 |
| load | OS loader 把镜像/依赖映射，完成或延迟完成动态重定位 | loader 找不到库、符号版本/架构不匹配、权限/格式错误 | 已加载不代表入口逻辑、配置或数据正确。 |
| execute | CPU 从入口执行，运行时完成初始化、调度、GC/异常等 | 崩溃、断言、数据竞争、错误输出 | 成功退出不等于覆盖所有行为或性能目标。 |
| JIT | 运行时基于字节码/IR/profile 生成并安装机器码 | guard 失败、deopt、代码缓存、运行时 ABI | 既不是纯 compile 也不是 OS load；需区分编译事件与实际热路径执行。 |

**relocation（重定位）**：object 中“此处地址/偏移尚未知”的记录及其修补规则；**symbol resolution（符号解析）**决定引用绑定到哪一定义；**ABI**规定跨二进制边界的调用约定、布局、名称、异常等契约。三者相关但互不替代。静态链接、动态链接、PIC/PIE、lazy binding 的具体行为以平台、链接器和安全策略为准。

## 只读证据命令与记录模板

以下命令只读取本机文件或生成到临时目录；先在副本或明确的 build 产物上操作，绝不以它们替代测试。不同工具链选项不同，运行前先看 `--help`，并在记录中保留**实际命令、退出码、版本、目标与输入 hash**。

```bash
# 版本与目标：只读
clang --version
clang -print-target-triple
llvm-config --version

# 将临时产物隔离到系统临时目录；替换为自己的无敏感示例路径。
tmpdir="$(mktemp -d)"
clang -O2 -S -emit-llvm ./example.c -o "$tmpdir/example.ll"
clang -O2 -S ./example.c -o "$tmpdir/example.s"

# 查看而不改写既有二进制。
llvm-objdump -d --demangle ./program
llvm-readelf -Ws -r ./program
```

`mktemp -d` 目录是临时证据，不应放入 Vault 或提交。若涉及真实项目，额外记录：源码 commit/dirty 状态、`compile_commands.json` 或构建日志、链接库路径与版本、OS/CPU/GPU、优化级别、target triple/`-march`，以及测试和 profile 的输入规模。反汇编证明的是该文件中的指令，IR dump 证明的是某 pipeline 点的表示；二者都不自动证明运行时走到了该路径。

这些入口是继续追踪“具体版本的 IR 与编译路径”的起点，不能把某版本文档的细节外推到所有版本或其他编译器。

| 生态/规范 | 关注对象 | 官方入口 |
| --- | --- | --- |
| LLVM | IR 语义、pass、目标后端 | [LLVM Language Reference](https://llvm.org/docs/LangRef.html) · [LLVM Tutorials](https://llvm.org/docs/tutorial/) |
| MLIR | 多层 dialect、operation、类型与验证 | [MLIR Language Reference](https://mlir.llvm.org/docs/LangRef/) |
| WebAssembly | 可验证字节码、模块、实例、执行语义 | [WebAssembly Core Specification 2.0](https://www.w3.org/TR/wasm-core-2/) |
| CPython | bytecode 与解释器可观察证据 | [Python `dis` documentation](https://docs.python.org/3/library/dis.html) |
| PyTorch | `torch.compile` 的前端、图与后端行为 | [PyTorch `torch.compile`](https://docs.pytorch.org/docs/stable/generated/torch.compile.html) |
| Triton | Python DSL 到 GPU kernel 的编译与调参接口 | [Triton documentation](https://triton-lang.org/main/) |

PyTorch 与 Triton 页面中的图捕获、guard、fusion、kernel 选择和支持矩阵是版本化行为；GPU 框架的“已编译”还必须和实际 device、shape、dtype、fallback、kernel trace 及数值/梯度测试分开取证。
