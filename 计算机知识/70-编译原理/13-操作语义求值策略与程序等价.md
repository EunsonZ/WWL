# 操作语义：同一个函数调用，为什么可能有不同结果？

`(λx:Bool.true) a` 的函数体不使用 x。编译器能直接删掉 a 的计算吗？先回答 a 是否可能发散、是否有副作用，以及语言何时求实参。本课固定一个纯语言，把“运行”变成可检查的关系，再讨论改写许可。既有 [[计算机知识/70-编译原理/11-优化正确性语义保持与验证测试|优化正确性]] 讨论真实 IR 的溢出、异常与可观察行为；这里给出更小的正式对象，不把模型许可直接移植到 LLVM。

## 1. 先固定语法、自由变量和值

类型与表达式采用以下有限树语法，箭头右结合，应用左结合：

```text
T ::= Bool | T → T
 e ::= x | true | false | λx:T.e | e e | if e then e else e
 v ::= true | false | λx:T.e
```

x 是变量名，T 是类型，e 是表达式，v 是已经完成的值。函数体可以仍含计算；`λx:Bool.if x then false else true` 已经是值，因为此处不在 λ 下求值。这称为弱求值。类型注解对运行没有动作，但给下一课检查用。当前没有整数、状态、异常、I/O、子类型或 let 多态。

自由变量集合 FV 按结构定义：FV(x)={x}，布尔常量为空；FV(e₁e₂)=FV(e₁)∪FV(e₂)；条件式是三项的并集；FV(λx:T.e)=FV(e)\{x}。FV(e)=∅ 称闭项，即完整程序；`λx:Bool.y` 是开项，`λx:Bool.x` 是闭项。此处变量本身不是值。

`e[x:=s]` 表示只替换 e 中自由出现的 x。变量 x 换成 s，其他变量与常量不变；应用和条件逐个递归。λ 分三种：绑定名就是 x 则停止；绑定名 y≠x 且 y∉FV(s) 则递归；若 y∈FV(s)，先把该层绑定改成全新的 z，再递归。z 必须避开 e、s 中全部名字和 x；名字集合有限，名字空间无限，因此总能找到。

例如 `(λy:Bool.x)[x:=y]` 应为 `λz:Bool.y`，其自由变量仍是 {y}。若机械换成 `λy:Bool.y`，本来引用外面的 y 变成了参数，这叫变量捕获。α 转换只改变一个绑定及由它绑定的出现，不改变自由名字，也不跨过内层同名绑定。`λy:Bool.(λy:Bool.y)` 的外层 y 改成 z，内层仍保持 y。两个仅差这种合法改名的项记为 e≡αe′。Cornell 2021 教材的 [Capture-Avoiding Substitution](https://courses.cs.cornell.edu/cs3110/2021sp/textbook/interp/subst_lambda.html) 提供无类型 λ 的绑定问题；本课额外保留 Bool 注解，实验实现支持开项的完整避捕获替换。

### 绑定身份与观察对象的对照

先读[[哲学与文化/20-论证知识与规范/04-量词有效性与反模型#自由变量、绑定变量与捕获|量词代入的自由引用]]，带回外部 y=甲 时“有支持者”与“有自我支持者”的区别；本节只迁移绑定规则。

| 构造与对象 | 哪些出现由外部决定 | 合法 α 改名的范围 | 错误后果在哪里观察 |
| --- | --- | --- | --- |
| ∀/∃ 绑定变量，构成对论域的判断 | ∃y R(x,y) 中的 x；代入后 ∃z R(y,z) 中的 y | 选定量词及它绑定的出现；自由引用和内层另一个同名绑定不改 | 固定同一关系和外部赋值，比较公式真假 |
| λ 绑定参数，构成函数 | λy:Bool.x 中的 x；代入后 λz:Bool.y 中的 y | 选定 λ 及它绑定的参数使用；不跨内层同名 λ | 先闭合自由变量，再在同一调用下比较返回值 |
| 声明在词法作用域建立 binding | 某一作用域中指向外层声明的 use | 选定 SymbolId 的声明与 use-def 边；重新检查新名字会否改变别的边 | 比较每个 use 指向的实体；运行后果还须按语言规则检查 |

量词不是函数调用，声明也不自动具有此处 λ 的运行规则。共同条件是：改名字不能改变出现的绑定身份，代入时不能把原自由引用误绑到内部构造。工程中的具体检查见[[计算机知识/70-编译原理/05-作用域名称解析与符号表#按 SymbolId 改名并检查捕获|所选 SymbolId 的改名范围]]；返回时指出为何内层遮蔽不随外层改名。

## 2. 小步规则决定下一处求值

`e→e′` 是执行一个规则后的项；`→*` 是零步或有限多步。为了避免“所有子式同时算”，用一个洞的求值上下文 E 指定求值位置。E[e] 是把 e 放进洞。

| 策略 | 允许的上下文 | β 规则 |
| --- | --- | --- |
| CBV，按值调用，左到右 | E ::= □ \| E e \| v E \| if E then e else e | (λx:T.e) v → e[x:=v] |
| CBN，按名调用 | E ::= □ \| E e \| if E then e else e | (λx:T.e) a → e[x:=a] |

两种策略都有 `if true then a else b→a`、`if false then a else b→b`，以及上下文闭包：若 r→r′，则 E[r]→E[r′]。上下文规则不进未选分支或函数体。CBN 的函数位置仍需要先求到 λ，但不先求实参；参数每次使用可重复计算，区别于带共享缓存的按需调用。

这里的 CBV 上下文允许先求实参，即使函数位置是布尔值；最终 `true false` 没有 β 规则。实验忠实采用这一定义。每个闭项至多一步的确定性，可按最外构造分类：应用先选择函数、再实参、再β，三者互斥；条件先选择条件求值或真假分支；值无步。α 新名字可能有多种，但结果在 α 等价意义下相同；实验用确定的新名策略给出唯一字节结果。

令 a=`(λy:Bool.y) false`，t=`(λx:Bool.true) a`：

| 策略 | 第0步 | 第1步 | 第2步 |
| --- | --- | --- | --- |
| CBV | t | (λx:Bool.true) false | true |
| CBN | t | true | 已结束 |

![函数位置、实参和β替换的不同顺序](assets/semantics-strategies.svg)

图中 a 就是上表的同一个 a；CBV 的额外一条边不是“结果更正确”，而是语言规则规定必须走。跟算：`(λx:Bool.if x then false else true) false` 先 β 得 `if false then false else true`，再得 true。完整轨迹有三个项、两次转换，见 [[计算机知识/70-编译原理/81-语义类型与程序证明实验|轨迹与代码]]。

## 3. 终止、卡住和发散要分开

值是完成；不是值却无规则可走叫 stuck（卡住），例如 `true false`；存在无限转换链叫发散。有限步预算耗尽只表示还没得到结论，不能证明发散。

上面的有限 Bool STLC 核心，闭良类型程序会终止；这需要归一化定理，进展与保持本身不够，下一课解释边界。为了展示策略差异，**明确另加递归扩展** `fix e`，规则为 `fix (λx:T.e)→e[x:=fix (λx:T.e)]`，并允许在 `fix E` 中求值。其类型要求参数 `e:T→T`，结果为 T。

令 δ=`fix (λz:Bool.z)`，则 δ→δ→…，这条自环给出数学上的无限链，而非从超时推断。令 u=`(λx:Bool.true) δ`：CBV 永远先算 δ；CBN 一步得 true。该扩展仍可保持类型安全，却不保持终止。无类型 Ω=`(λx.x x)(λx.x x)` 也发散，但它不属于当前带有限类型注解的良类型核心，不能冒充此核心的反例。

## 4. 何谓“程序等价”？先声明观察与上下文

对固定策略，在纯闭 Bool 程序上定义观察 Obs(e)：终止于 true/false 记对应值；无限执行记 div；有限卡住记 stuck。函数值不能仅按打印文本比较，必须把它放入调用环境观察。

对同类型、闭良类型的 e、e′，若对每个使 C[e]、C[e′] 成为闭 Bool 程序的良类型**程序上下文** C，都有 Obs(C[e])=Obs(C[e′])，称上下文等价。C 是语言任意合法单洞程序构造，允许把洞放到 λ 体等处；与只指定“下一步在哪里算”的 E 不同。类型、策略及是否含 fix 都是此定义的参数。计时、内存与步数不在当前观察中。

在含 fix 的 CBV 扩展中，u 与 true 不等价，空上下文已区分 div 与 true；CBN 则会直接删去未使用的 δ。对任意 a 的 `(λx:T.e) a→e[x:=a]`，CBV 只有 a 为值时才把这条 β 化简列为运行规则。带效果的真实语言还须保留 I/O、异常、状态与求值次数；不能从这个纯模型推出删掉所有未使用参数的优化正确。

### 同一闭合上下文怎样区分捕获结果

回到 `(λy:Bool.x)[x:=y]`，记正确结果 f=`λz:Bool.y`，错误结果 g=`λy:Bool.y`。绑定身份决定了下表，而不是拼写决定它：

| 项 | 体中 y 的身份与 FV | 只对自由 y 作 [y:=false] | 再应用于 true |
| --- | --- | --- | --- |
| f=λz:Bool.y | y 引用外部，FV(f)={y}；z 是参数，体未使用它 | f₀=λz:Bool.false | (λz:Bool.false) true → false |
| g=λy:Bool.y | y 引用该 λ 参数，FV(g)=∅ | g₀=λy:Bool.y，替换遇到同名绑定停止 | (λy:Bool.y) true → true |

外部环境同为 y=false，实参同为 true。先闭合是必要的：直接运行开项 f true 只能得到无求值规则的自由 y，不能把它称为已经返回 false。上述两次调用均为闭项；函数和实参都已是值，因此本课的弱 CBV β 规则各走一步。这个有限观察不使用 fix、状态或异常。

若把两项放进同一个程序上下文，可写 `C[□]=(λy:Bool.(□ true)) false`，逐步得到：

```text
C[f] = (λy:Bool.((λz:Bool.y) true)) false
     → (λz:Bool.false) true → false
C[g] = (λy:Bool.((λy:Bool.y) true)) false
     → (λy:Bool.y) true → true
```

C 的外层 λ 有意实现同一外部赋值；第二行中内层同名 λ 遮蔽它，所以外层 β 替换不能进入该绑定。这是给开项补足观察环境，不能误称为合法 α 改名。按上面针对闭项的等价定义，正式比较的是 f₀ 与 g₀：同一闭 Bool 调用上下文 `D[□]=□ true` 已区分它们，故不等价。找到一个区分上下文足以否定等价；偶然在某个调用下返回一样则不足以证明所有上下文等价。

在 Γ={y:Bool} 下，f 和 g 都可具有 Bool→Bool；闭合后的 f₀ 和 g₀ 在空环境下也同型。进入[[计算机知识/70-编译原理/14-类型安全替换引理与进展保持#同型反例与三种不同的保持承诺|替换引理的三种保持承诺]]，带回“引理保证的是哪个类型判断，哪个行为结论还需要另证”。返回本节应能指出 f 和 g 的自由 y 身份差异，并从同一 C 推到两个值。名称解析读者可继续[[计算机知识/70-编译原理/05-作用域名称解析与符号表#按 SymbolId 改名并检查捕获|重命名的身份检查]]，把这处错误定位为一条引用边被改向。

## 5. 练习与解答

1. 求 `(λy:Bool.if x then y else x)[x:=y]`。解：先改绑定 y 为 z，得到 `λz:Bool.if y then z else y`；自由 y 保留，两处 x 都替换。
2. `λx:Bool.true false` 是值还是卡住？解：外层是值，弱求值不进函数体；但类型检查应拒绝。对它应用后，才会走向卡住。
3. 若两项都在100步预算内没结束，能声称上下文等价吗？解：不能；可能在101步返回相反值，也可能某个调用上下文区分它们。有限测试既不判定发散，也不量化全部上下文。

### 换一组名字的迁移题

在同一个互助模型中，令 ψ(p)=∃q R(p,q)，把自由 p 换为 q。程序侧令 h=`λq:Bool.if p then q else false`，做 `[p:=q]`。分别给出正确结果与盲目按文本替换的结果，标明每个 q 的绑定身份，选择一个赋值或调用来区分它们，并判断程序两结果是否可同型。最后将原程序的 p 换为常量 false，说明前述冲突是否仍存在。题目不指定新名字或求解顺序。

> [!success]- 可核参考答案
> 任选原式中未出现的新名，例如 r。逻辑正确结果 ∃r R(q,r)，其中 q 由外部赋值，r 由该 ∃ 绑定；错误结果 ∃q R(q,q) 的两个 q 均由内部 ∃ 绑定。在 q=甲 时，正确式检查甲行，有乙作见证而真；错误式检查两个对角格，均假。常项 a 指甲时 ψ(p)[p:=a]=∃q R(a,q)，a 不受量词绑定。
>
> 程序先将原 λ 的绑定 q 及条件分支中由它绑定的 q 改名，得正确结果 `λr:Bool.if q then r else false`，FV={q}；其中条件 q 来自代入项，引用外部，分支 r 是参数。错误结果 `λq:Bool.if q then q else false`，条件与分支的 q 都成了参数，FV=∅。给外部 q=false，两项闭合后都应用于 true：正确项 → `if false then true else false` → false；错误项 → `if true then true else false` → true。原程序在 Γ={q:Bool},p:Bool 下、两结果在 Γ 下均为 Bool→Bool；同型不消除此反例。其他能区分的同一赋值/调用及合法新名也正确。
>
> 若直接做 `[p:=false]`，FV(false)=∅，不须为这次代入改 λ 参数名，得到 `λq:Bool.if false then q else false`；分支 q 仍绑定到原 λ。α 改名依然可以做，但不是避开此常量所必需的步骤。

这条绑定检查也供[[数学/12-离散数学与逻辑/01-命题谓词量词与形式证明#5. 量词推理不能把特殊对象当任意对象|形式逻辑的合法代换]]复用。若从[[AI/13-搜索推理与规划/05-知识表示规则归结与查询#统一是保持同一变量含义的替换|有限树统一与替换组成]]来，先分清对象：统一求解有限项等式中的同一变量，α 改名维护绑定身份，推导有效性要求规则及模型条件；统一成功本身不证明量词推理有效，也不证明程序行为等价。返回该页时保留它的变量身份与替换组成合同，不把本节当第二份统一算法。
