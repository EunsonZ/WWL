# 17 · 强连通分量、凝聚 DAG 与工作列表不动点

## 本课目标

学完后，你能把有向图中相互可达的循环区域分解为强连通分量（SCC），证明凝聚图必然是 DAG；能把“有环无法一次拓扑排完”改写为单调数据流的工作列表不动点计算；并看见 SCC/工作列表如何连接到编译器控制流图（CFG），而不把这座桥误解为完整编译器实现。

## 1. 直觉：环内要反复传播，环之间可按方向推进

在任务依赖、调用关系或程序控制流中，`u` 可达 `v` 不表示 `v` 可达 `u`。若两个方向都可达，两者在“循环传播”的意义上属于同一块。SCC 先把这些块找出；再把每块缩成一个超节点，得到的图没有环，才能用 DAG 的顺序看块之间的依赖。

这里延续 [[计算机知识/50-数据结构与算法/07-图的表示BFS-DFS与拓扑排序|图的表示、BFS、DFS 与拓扑排序]]的邻接表、DFS 完成顺序和 DAG 前提。

## 2. 定义：SCC 是极大的相互可达集合

对有向图 `G=(V,E)`，若 `u` 有路径到 `v`，写作 `u ⇝ v`。顶点集 `C` 是 SCC，当且仅当：

1. 任意 `u,v∈C` 都有 `u⇝v` 且 `v⇝u`；
2. `C` 是极大的：不能再加入一个外部顶点仍满足第 1 条。

“极大”不是“顶点数最多”；一张图可有多个大小不同的 SCC。单顶点也是 SCC，无论是否有自环，因为长度 0 路径使顶点可达自身。

“相互可达”是等价关系：自反、对称、传递。因此 SCC 对 `V` 构成唯一分区：每个顶点恰属于一个分量。等价关系与分区的数学语言见 [[数学/10-数学语言与基础/03-集合映射命题与合法推理|集合、映射、命题与合法推理]]。

## 3. Kosaraju：两次 DFS 为什么能切准分量

Kosaraju 算法的步骤是：

```text
1. 在 G 上做完整 DFS，记录每个顶点的完成顺序。
2. 将所有边反向，得到 G^R。
3. 按第 1 步完成顺序的逆序，在 G^R 上从尚未访问顶点启动 DFS。
4. 每棵第二遍 DFS 树就是一个 SCC。
```

反向不会改变 SCC 内的相互可达性，但会反转分量之间的边。第一遍的逆完成顺序保证，第二遍总是先从当前凝聚图中的源分量开始；在反图中它没有通向其他未分配分量的边，不会跨界收集。分量内部仍相互可达，所以又不会漏收。

邻接表中，两次 DFS 各访问每个顶点和每条边常数次，建反图也是 `Θ(|V|+|E|)`，总时间 `Θ(|V|+|E|)`，附加空间同阶。递归 DFS 还依赖语言调用栈能容纳图深度；大图可用显式帧栈。

## 4. 凝聚图为什么必然是 DAG

为每个 SCC 建一个超节点。若原图有 `u→v`，`u` 与 `v` 属于不同 SCC，则在超节点之间加边，并去掉自环和重边。

反证：假设凝聚图有环 `C1→C2→...→Ck→C1`。每个分量内部相互可达，分量之间又有环边，所以所有 `Ci` 中的顶点都相互可达，它们本应是同一个极大 SCC，与“不同分量”矛盾。因此凝聚图无环。

这个结果允许在分量层做拓扑排序、依赖传播或自底向上汇总；但每个有环分量内部仍然需要迭代或专门规则，“缩点”没有把环内语义消失。

## 5. 从 CFG 到数据流方程

编译器常把一段直线执行、中间无分支目标的指令组成基本块；节点是基本块，边表示可能的下一步，得到控制流图 CFG。循环使 CFG 有环，因此许多信息不能只按一个拓扑序扫一次。“指令如何改变机器状态”的系统背景见 [[计算机知识/30-计算机系统/06-指令系统汇编与程序执行|指令系统、汇编与程序执行]]；本课只建立图算法到 CFG 分析的桥梁。

以“可能到达当前块的定义”为例。每个块 `b` 有：

- `GEN[b]`：在块内最终生成、可传到块末的定义；
- `KILL[b]`：被本块重新定义覆盖的其他定义；
- `IN[b]`：所有前驱 `p` 的 `OUT[p]` 并集；
- `OUT[b] = GEN[b] ∪ (IN[b] - KILL[b])`。

这是前向 **may** 分析：并集表示“存在一条路径可能到达”，不是“所有路径一定到达”。后者往往使用交集且需要不同初值；把 `∪` 换成 `∩` 就声称算的是同一件事，是语义错误。

## 6. 工作列表：只在输入可能变化时重算

```text
将所有块放入 worklist，IN/OUT 从分析规定的底元素开始
while worklist 不空：
    b = pop(worklist)
    new_IN  = join(OUT[p] for p in predecessors[b])
    new_OUT = transfer_b(new_IN)
    若 IN[b] 或 OUT[b] 变化：
        保存新状态
        把 b 的尚未在队列中的后继加入 worklist
```

对有限定义集 `D`，状态空间可看成按包含关系排序的幂集 `P(D)`。若初值为空集，`join` 和传递函数单调，每次改变只会向上增长，而有限高度不能无限上升，所以终止。终止时所有方程都不再改变，得到不动点；从底开始的这类迭代得到最小不动点。

不变量是：队列外且输入未变化的块无需重算；一个块的 `OUT` 变化后，所有可能受影响的直接后继必在队列中或将被入队。去重入队不改结果，但能避免同一块在多个前驱连续变化时堆积多个待处理副本。

## 7. 复杂度前提和不能过度承诺的地方

SCC 有清晰的线性图复杂度。一般工作列表则还依赖：状态格的高度，每次 `join`/传递的代价，顶点处理顺序，以及是否使用位集合批量运算。可用“块求值次数、状态改变次数、后继重新入队次数、前驱合并次数”比较调度策略，不要只报一次毫秒数。

SCC 顺序可用来优先在一个循环区域内收敛，再沿凝聚 DAG 传播；但它不能保证“每个块只计算一次”。非单调传递函数可能震荡或不终止；无限高抽象域可能需要 widening，这些都不在本课有限幂集模型的保证内。

## 8. 完整例子：环中重定义

CFG 为 `entry→loop`、`loop→body`、`body→loop`、`loop→exit`。`entry` 生成 `x@entry`，`body` 重新定义 `x`，因而生成 `x@body` 并杀死 `x@entry`。

1. 初次到 `loop`时，`IN[loop]={x@entry}`；
2. `body` 产生 `OUT[body]={x@body}` 并回到 `loop`；
3. 重算后 `IN[loop]={x@entry,x@body}`；
4. 再传一轮无新元素，达到不动点；`exit` 的入口两个定义都可能到达。

`loop` 和 `body` 位于同一 SCC，`entry` 与 `exit` 各是单顶点 SCC。凝聚 DAG 只说块之间的方向；环内仍需要上述重复传播。

## 练习

1. 对边 `a→b,b→a,b→c,c→d,d→c,d→e` 列出 SCC，画凝聚图并给出一个拓扑序。
2. 用“若凝聚图有环则分量应合并”写一段完整反证，明确极大性在哪一步被违反。
3. 将上述 reaching-definitions 例子手工执行到不动点，记录每次状态改变和重新入队。
4. 运行 [[计算机知识/80-实践/05-数据结构与算法/09-图分解与数据流不动点/README|图分解与数据流不动点实验]]，用固定种子图的互相可达参考实现验证 SCC，再观察工作列表的求值/入队计数。
