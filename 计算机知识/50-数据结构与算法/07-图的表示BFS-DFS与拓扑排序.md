# 图的表示、BFS、DFS 与拓扑排序

## 本课目标

学完后，你应该能把“对象及关系”准确建模为图，选择合适的存储方式，并说明遍历不会重复处理顶点的原因。你还应能判断何时图有向、何时无向，何时存在环，以及为什么只有有向无环图（DAG）才有拓扑序。

本课只使用**伪代码**讨论算法；可运行实现、输入解析与性能测量属于 `计算机知识/80-实践/05-数据结构与算法/` 实践目录。

## 1. 先建模：顶点、边与方向

图记为 $G=(V,E)$：$V$ 是顶点集合，$E$ 是边集合。顶点可以是网页、课程、任务、城市或文档 chunk；边表达“相连”“依赖”“可到达”等关系。**边的语义由题目决定，不能从图形外观猜出。**

| 类型 | 一条边的写法 | 关系含义 | 常见例子 |
| --- | --- | --- | --- |
| 无向图 | $\{u,v\}$ | `u` 与 `v` 对称相连 | 社交好友、双向道路 |
| 有向图 | $(u,v)$ 或 `u → v` | 从 `u` 指向 `v`；反向未必成立 | 任务依赖、网页链接、状态转移 |
| 加权图 | 边附带权重 $w(u,v)$ | 关系还有距离、代价或概率 | 路网距离、网络时延 |

无向边 `u—v` 在存储时通常要写成两条邻接记录：`u` 的邻居里有 `v`，`v` 的邻居里有 `u`。有向边只写 `u` 的出边；若还要快速查询谁指向 `v`，则另建入边表或反向图。

> [!warning] “图”不是总能当树
> 树是连通、无环的特殊无向图（根树再额外指定根和方向）。一般图可不连通、可有多个路径和环；把树的“父节点唯一”假设搬到一般图，会导致遗漏或无限循环。

## 2. 表示选择：先问查询，再算空间

设 $n=|V|$、$m=|E|$。顶点可用 `0..n-1` 的紧凑编号，也可用外部 ID 映射到该编号；映射本身的时间、内存和错误处理是工程成本，不在下表的纯图复杂度中。

| 表示 | 保存什么 | 空间 | 枚举 `u` 的邻居 | 查询 `u→v` | 适合 |
| --- | --- | ---:| ---:| ---:| --- |
| 邻接表 | 每个顶点的一段邻居序列 | $O(n+m)$ | $O(deg(u))$ | 通常 $O(deg(u))$ | 稀疏图、遍历、索引的候选边 |
| 邻接矩阵 | `n×n` 的存在/权重表 | $O(n^2)$ | $O(n)$ | $O(1)$ | 稠密图、极频繁的存在性查询 |

邻接表遍历所有邻居时，所有列表长度之和为 `m`（有向图）或 `2m`（无向图），所以一次完整 BFS/DFS 的边扫描是 $O(m)$。邻接矩阵即便边很少，也要在每个顶点扫描整行，完整遍历会是 $O(n^2)$。

### 工程代价：大 O 没有替你选布局

- 连续数组式邻接表通常有较好空间局部性；散落的小对象/指针链可能带来分配次数、间接寻址与缓存未命中。缓存与布局的边界见 [[计算机知识/30-计算机系统/04-缓存局部性带宽与延迟|缓存、局部性、带宽与延迟]]。
- 矩阵地址计算简单，位集合/布尔矩阵还可能批量处理，但 $n^2$ 存储会很快成为内存与带宽成本；不要仅因 `O(1)` 查询就忽略它。
- 图若会动态增删边，数组重分配、去重、边 ID、并发读写和快照一致性都可能比遍历公式更重要。多执行流不能无同步地共同写 `visited` 或邻接表，见 [[计算机知识/30-计算机系统/05-并发并行SIMD与加速器|并发、并行、SIMD 与加速器]]。

## 3. BFS：按距离层扩张，而不是“永远找最短路”

广度优先搜索（BFS）使用 FIFO 队列。对一个无权图，若每条边都算一步，首次发现顶点 `v` 的路径长度就是从起点 `s` 到 `v` 的最少边数；加权边的最短代价问题不能直接套用 BFS。

### 不变量与 `visited` 时机

维护下列不变量：

1. 已入队顶点都已被标记 `visited`，且每个顶点至多入队一次；
2. 队列中的顶点按与 `s` 的非递减边数距离排列；
3. 从队首取出的顶点 `u` 时，`dist[u]` 已是最短边数距离。

因此应当在**入队时**标记，而非出队时。伪代码：

```text
BFS(graph, source):
    for each vertex v:
        visited[v] = false
        dist[v] = undefined
    visited[source] = true
    dist[source] = 0
    queue = [source]

    while queue is not empty:
        u = dequeue_front(queue)
        visit(u)
        for each v in graph.neighbors(u):
            if not visited[v]:
                visited[v] = true       // 发现时立即占位
                dist[v] = dist[u] + 1
                enqueue_back(queue, v)
```

### 逐步例子

对有向边 `A→B, A→C, B→D, C→D, D→E` 从 `A` 做 BFS：

| 时刻 | 队列（左端先出） | 已确定的距离 | 发生的事 |
| --- | --- | --- | --- |
| 初始 | `[A]` | `A:0` | 标记并入队 `A` |
| 取 `A` | `[B,C]` | `B:1, C:1` | 发现两名一跳邻居 |
| 取 `B` | `[C,D]` | `D:2` | 首次发现 `D` |
| 取 `C` | `[D]` | 不变 | `D` 已标记，不能二次入队 |
| 取 `D` | `[E]` | `E:3` | 发现 `E` |

**反例：出队才标记。** `B` 与 `C` 都会看到未标记的 `D`，于是 `D` 被重复入队；图越密，重复工作越多。即使最后过滤重复输出，也已破坏“每顶点一次”的复杂度证明。并行 BFS 还需要原子“首次发现”或分层去重；仅把单线程伪代码分给线程并不正确。

### 为什么最短边数成立

起点距离为 0。假设队列先取出的顶点距离不递减，那么从距离 $k$ 的 `u` 新发现的 `v` 距离为 $k+1$；任何更短到 `v` 的路径必须先经过距离不超过 $k$ 的前驱，它应更早被处理并已发现 `v`。所以首次标记的距离不能比真实最短距离大，也显然不会比它小。

这只证明**无权/等权边的边数最短**。把“高速路 1 分钟”和“小路 1 小时”都当一条边会给出错误的最小时间答案。

## 4. DFS：沿一条分支走深，再回溯

深度优先搜索（DFS）可用只存顶点的显式栈得到一种合法遍历，但其发现/完成顺序未必复现递归 DFS 的“先沿一条未访问边走到底，再回溯”语义。若需要这套语义，一个稳妥做法是让每个已发现但未完成的顶点占一个**帧**，帧保存顶点和邻居迭代器/游标；这样能在子调用完成后准确回到父顶点的下一条边，并始终至多保留每个顶点一个帧。递归写法更短，但其隐式调用栈仍会随搜索深度增长；函数调用、栈帧和尾调用不是固定保证的细节见 [[计算机知识/30-计算机系统/03-ABI调用约定与静态动态链接|ABI、调用约定与静态/动态链接]]。

```text
DFS(graph, source):
    for each vertex v:
        visited[v] = false
    visited[source] = true
    visit(source)                       // 发现时的前序访问
    push(stack, frame(source, cursor=begin(graph.neighbors(source))))

    while stack is not empty:
        frame = top(stack)
        u = frame.vertex
        if frame.cursor == end(graph.neighbors(u)):
            pop(stack)                  // u 的所有邻居已检查，回溯/完成 u
            continue
        v = dereference(frame.cursor)
        advance(top(stack).cursor)      // 这条边只检查一次
        if not visited[v]:
            visited[v] = true
            visit(v)
            push(stack, frame(v, cursor=begin(graph.neighbors(v))))
```

此实现按邻接表的存储顺序检查邻居，并与同一顺序的递归前序 DFS 一致：发现 `v` 后立即转入 `v`，直到一个栈帧没有未检查邻居才回到其父帧。这里假定 `begin`、`advance` 与 `end` 的游标操作在该邻接表示上为常数或摊还常数；若邻接表是数组，也可用 `next_index`，但必须明确数组下标访问为 $O(1)$。相邻表顺序不同会给出不同但同样合法的 DFS 顺序，因此测试或文档不能把某一个顺序当作图的唯一真相。

DFS 的不变量是：每个栈帧保存一个已发现但尚未完成的顶点及其下一个待检查邻居；从栈底到栈顶的顶点组成当前搜索路径，已标记顶点至多入栈一次。每个顶点标记一次、每条邻接记录检查一次，时间为 $O(n+m)$；`visited` 和至多为当前深度的显式帧栈合计为 $O(n)$ 额外空间。若只从一个源开始，不可达顶点不会被访问；要覆盖所有连通分量，应对每个未访问顶点再启动一次 DFS。

## 5. 有向环与拓扑排序

若 `u→v` 表示“完成 `u` 后才能做 `v`”，则一个合法拓扑序把每条边都排成 `u` 在 `v` 前。它存在**当且仅当**图是 DAG；一个有向环要求每个顶点都排在自己的前面，矛盾。

### Kahn 算法：不断取入度为零的顶点

入度是指向顶点的边数。下面伪代码的核心不变量是：队列外、尚未输出的每个顶点的 `indegree` 等于来自尚未输出顶点的入边数。

```text
TOPOLOGICAL_SORT(graph):
    indegree[v] = 0 for every vertex v
    for each edge u -> v:
        indegree[v] += 1
    ready = every v with indegree[v] == 0
    order = []

    while ready is not empty:
        u = remove_one(ready)
        append(order, u)
        for each v in graph.neighbors(u):
            indegree[v] -= 1
            if indegree[v] == 0:
                add(ready, v)

    if length(order) != number_of_vertices(graph):
        report "有向环，无法给出完整拓扑序"
    return order
```

**正确性直觉。** 每次输出的 `u` 没有来自剩余图的前驱，不会违反任何尚未满足的依赖；删除 `u` 的出边后，新入度为零者的所有前驱都已输出。若过程卡住却仍有顶点，剩余有限有向图中每个顶点都有剩余前驱；沿前驱不断倒推必会重复顶点，形成有向环。

### 例子与非唯一性

若边为 `解析→建索引`、`清洗→建索引`、`建索引→检索`，一开始 `解析` 与 `清洗` 都是零入度。`[解析, 清洗, 建索引, 检索]` 和 `[清洗, 解析, 建索引, 检索]` 都正确；拓扑排序通常不唯一。若再加入 `检索→解析`，形成环，算法会在输出部分顶点后没有零入度顶点，必须报告失败，不能返回一个看似完整的顺序。

常见反例是把**无向边**拿来做拓扑排序：任意无向边若强行视作双向边，两个端点立刻构成长度 2 的有向环。另一个反例是只检测“排序输出长度不对”却继续执行依赖任务；应把环、涉及的任务和恢复/人工拆环路径作为独立错误处理。

## 6. 图在真实系统中的去向

- Web 链接、知识图谱和服务依赖可用图表达，但“可达”不等于可信、可访问或最新；权限与证据仍是另一层。
- RAG 可把文档、chunk、版本与引用关系表示为图，或使用倒排/向量索引寻找候选；图边和相似度都只是候选信号，不能跳过 ACL、版本和事实核验。见 [[AI/20-LLM/70-工程应用与工具链/02-Embedding-Chunking与最小RAG#精确定义与四类边界|最小 RAG 的索引与边界]]。
- 构建系统与任务调度常用 DAG；拓扑序解决前置顺序，不自动解决资源限制、失败重试或并行安全。并发执行前还要评估共享状态、同步与端到端开销。

## 练习

1. 为“课程先修关系”“好友关系”“单行道道路”各选择有向/无向图，并用一句话定义边的方向。
2. 对 $n=10^6,m=3\times10^6$ 的稀疏图，比较邻接表和邻接矩阵的量级；再写出一个会让你考虑矩阵的查询模式。
3. 用上文 `A→B,A→C,B→D,C→D,D→E` 手工写出 BFS 每轮队列与 `visited`。随后把标记移到出队，指出 `D` 的重复入队点。
4. 为 `A→B,B→C,C→A,D→E` 运行 Kahn 算法，说明哪些顶点能输出、为什么剩余部分证明有环。
5. 解释“从一个起点 DFS 完毕”为什么不证明整个图已遍历；给一个不连通图反例。

## 成功标准

- 你能从关系语义选择边方向，并在无向邻接表中写出两侧记录；
- 你能用 $n,m,deg(u)$ 推导两种表示的空间和常见查询成本；
- 你能说明 BFS 为什么入队即标记、为何得到无权最短边数而非加权最短代价；
- 你能指出 DFS 的栈空间与遍历顺序依赖邻居顺序；
- 你能用入度不变量解释 DAG 才有拓扑序，并把环视为需处理的错误条件。
