# 核心搜索语法

> [!goal] 你将学会
> 用核心 Search 搜索正文、文件、路径、标签、属性、标题块和任务，并通过引号、布尔运算、分组、排除与正则逐步缩小结果。

## 从最小查询开始

| 目标 | 查询 | 说明 |
| --- | --- | --- |
| 一个词 | `Obsidian` | 搜索包含这个词的笔记 |
| 完整短语 | `"下一步行动"` | 词序与空格作为整体 |
| 文件名 | `file:晨间` | 只匹配文件名 |
| 文件夹 | `path:"Obsidian知识/30-实践/01-实验区/数据"` | 限制到路径 |
| 正文 | `content:"核心观点"` | 只匹配正文内容 |
| 标签 | `tag:#playground/sample` | 搜索标签分支 |
| 属性 | `[status:active]` | 搜索属性值 |
| 标题 | `section:"下一步行动"` | 在同一标题区段中匹配 |
| 块 | `block:"下一步行动"` | 在同一 Markdown 块中匹配 |
| 未完成任务 | `task-todo:` | 仅未完成任务行 |
| 已完成任务 | `task-done:` | 仅完成任务行 |

> [!tip] macOS 与 Windows/Linux
> 默认打开 Search 的快捷键通常是 macOS `Cmd+Shift+F`，Windows/Linux `Ctrl+Shift+F`。若不同，请从 Command palette 搜索 “Search: Search in all files”，或在 Settings → Hotkeys 查看本机绑定。

## 布尔组合

空格相当于同时满足多个词。显式组合更容易读：

```text
Obsidian AND 属性
source OR project
status -archived
(source OR project) AND [fixture_reviewed:false]
```

- `OR` 必须大写。
- `-` 表示排除紧随其后的条件。
- 括号控制组合顺序。
- 含空格的值用双引号包裹。

## 面向样例的查询

把以下查询逐条复制到 Search：

```text
path:"Obsidian知识/30-实践/01-实验区/数据"
path:"Obsidian知识/30-实践/01-实验区/数据" [status:active]
path:"Obsidian知识/30-实践/01-实验区/数据" tag:#playground/sample/project
path:"Obsidian知识/30-实践/01-实验区/数据" [fixture_reviewed:false]
path:"Obsidian知识/30-实践/01-实验区/数据" task-todo:
```

预期结果：第一条有三篇；第二条是甲与丙；第三条只有丙；第四条是甲与丙；最后一条会找到仍有未完成任务的样例。

## 属性值的 OR

如果要搜索状态是 `active` 或 `processed`：

```text
[status:active OR processed]
```

如果想组合多个完整属性条件，也可写：

```text
([status:active] OR [status:processed]) path:"Obsidian知识/30-实践/01-实验区/数据"
```

复杂查询旁边的三点菜单可使用 **Explain search term** 检查 Obsidian 如何理解它。若结果和预期不一致，先拆回两个简单查询，再逐步组合。

## 区分行、块与区段

```text
line:(项目 下一步)
block:(项目 下一步)
section:(项目 下一步)
```

- `line:` 要求词出现在同一行。
- `block:` 要求词出现在同一个 Markdown 块，例如同一列表项或段落。
- `section:` 要求词出现在同一标题控制的区段。

它们适合减少“两个词都在一篇很长笔记里，但其实毫无关系”的误报。

## 正则表达式是最后一步

斜杠包裹正则：

```text
/2026-09-0[1-9]/
```

正则强大但不易读。能用属性、路径或标签表达时，优先使用结构化条件。只有需要匹配格式变体时再用正则。

## 嵌入一个动态查询

在任意笔记中插入以下代码块，阅读视图会显示实时结果：

````markdown
```query
path:"Obsidian知识/30-实践/01-实验区/数据" [status:active]
```
````

这适合轻量仪表盘；如果需要列、排序、卡片和可编辑属性，使用 [[Obsidian知识/40-视图/02-Bases/00-MOC-Bases|Bases]]。

## 检查结果与复原

- 简单搜索从 1 个条件开始，确认结果后再增加条件。
- 查询只读，不会修改文件；从结果勾选任务则会修改源任务行，需要留意。
- 保存为 Bookmark 的搜索仍只是入口，不会复制结果。
- 清空搜索框即可复原；不要为了“清理搜索结果”删除源文件。
