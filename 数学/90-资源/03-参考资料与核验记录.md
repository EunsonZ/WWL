# 参考资料与核验记录

这页记录课程中不同类型结论应如何核验。它不是“链接越多越可靠”的清单：定义和定理、经验规律、软件实现、硬件性能需要不同证据。

## 证据层级

| 结论类型 | 首选证据 | 课程中的写法 |
| --- | --- | --- |
| 数学定义、定理与推导 | 正规教材、讲义或原始论文；课程内给出假设与推导 | 明确对象、条件、等式方向和反例 |
| AI 架构的提出与数学形式 | 原始论文、作者实现、模型技术报告 | 区分“论文定义”与后续工程变体 |
| 工具格式和 API | 官方规范、官方文档、固定 commit 源码 | 记录版本/commit 和核验日期 |
| 模型质量与行为 | 有对照、样本定义和不确定性的评测 | 不把单一 benchmark 当普遍能力证明 |
| 显存、速度和吞吐 | 实际硬件、精度、batch、上下文、后端和日志 | 报告环境和测量方式，不承诺通用数值 |

## 稳定数学来源路线

这些来源用于建立学科框架；引用时应指向具体章节或定理，而不是只写书名。

- 线性代数：Gilbert Strang 的线性代数课程与教材；数值低秩问题还应核对 SVD 和 Eckart–Young–Mirsky 定理的假设。
- 概率统计：概率公理、条件概率、期望方差、估计和置信区间应来自标准概率统计教材；模型评测还要说明抽样单位和重复性。
- 微积分与优化：链式法则、方向导数、Jacobian 与反向模式自动微分分别核对；优化器的工程默认值不是数学定理。
- 信息论：熵、交叉熵、KL 与互信息采用清楚的随机变量/分布定义；KL 的两个参数不可交换。
- 数值计算：浮点结论应以 IEEE 754 语义和数值分析为基础；具体 GPU dtype 与指令支持另查硬件文档。
- 信号处理：采样定理要求带限等条件；STFT、Mel、扩散 SDE 的工程实现不能从一条连续数学公式直接推出。

## AI 相关原始来源入口

数学课只保存数学结论，架构和工具的版本化证据集中到 [[AI/90-资源/05-官方资料与版本核验记录]]。课程应优先连接：

- Transformer、Attention 与 MoE 的原始论文或作者资料；
- RoPE、LoRA、QLoRA 等方法的原始论文；
- GGUF、CUDA、safetensors 的官方规范或编程指南；
- `llama.cpp`、Unsloth、LLaMA-Factory、Heretic 的官方仓库和固定版本源码。

## 核验记录模板

在快速变化的实施页中保留以下字段：

```yaml
verified: YYYY-MM-DD
software_version: "精确版本或 commit"
model_revision: "精确 revision 或不适用"
operating_system: "系统与版本"
container_image: "镜像与 digest，或不适用"
hardware: "CPU、GPU、显存"
verification_level: "静态阅读 / CPU 运行 / GPU 运行 / 未运行"
```

不要填写猜测值。没有运行 GPU 就写“硬件跳过”，没有固定模型 revision 就不能声称可复现。

## 反例：四种常见证据越界

1. 数学上证明 softmax 概率和为 1，不等于模型输出事实正确。
2. LoRA 更新矩阵是低秩的，不等于能力变化也只发生在一个简单低维语义方向。
3. 某次 24 GB GPU 实验成功，不等于任意 7B 模型、上下文和 batch 都适配 24 GB。
4. Heretic 在一个提示集上降低拒答且 KL 较小，不等于安全、合规或所有能力保持不变。

## 练习与成功标准

任选一条课程结论，把它归入“数学、架构、工具实现、模型行为、性能”之一，并写出最合适的证据。成功标准是不会用源码链接证明数学定理，也不会用数学推导代替行为评测。
