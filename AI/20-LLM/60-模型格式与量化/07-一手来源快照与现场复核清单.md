这一站不再教一遍数学，而是回答三个工程问题：当前课程的稳定结论根据什么，快速变化的部分固定到哪个 ref，以及哪些结论必须到目标机器上实测。

## 1. 核验日期与证据等级

下表的远程 HEAD 在 **2026-09-02** 通过官方 Git 仓库读取核对。commit 是“当时看了什么”的坐标，不是兼容或正确性证明。

| 证据等级 | 能支持的结论 | 不能支持的结论 |
| --- | --- | --- |
| 论文 | 方法目标、假设、原始实验 | 当前库 API、任意新模型/硬件的质量与速度 |
| 固定规范/源码 | 该 commit 的字节布局、预设映射、选项存在性 | 已经构建、目标后端一定能运行 |
| 结构/toy 验证 | 受限样例的边界检查或数学现象 | 真实模型转换、量化或质量 |
| 真实模型+目标后端 | 本 manifest 固定条件下的加载、内存、速度与评测 | 其他模型、硬件、驱动、上下文或任务下也相同 |

## 4. 实施当天的复核清单

1. 重新查官方仓库 HEAD，把实际使用的 40 位 commit 写入 manifest；不只记分支名。
2. 从固定 checkout 读转换器/量化器/运行时的 `--help`、build target 与架构支持；不盲拷本课程命令形状。
3. 记录模型 revision、全部输入/输出哈希、config/tokenizer/chat template、转换参数与实际 tensor type 统计。
4. 若使用 imatrix/calibration，记录数据 revision、许可、tokenizer、语言/任务/长度覆盖与生成选项；评测集与校准集分离。
5. 分开验证文件结构、token 序列、高精度转换基线、量化损失、RAM/VRAM、prefill/decode/TTFT 与任务失败切片。
6. 在目标 CPU/Metal/CUDA/Vulkan 后端上实测；不将别人硬件或另一个 commit 的排名外推。
7. 不就地覆盖上游权重或高精度 GGUF。任一门失败时隔离可重建派生物，保留 manifest 和脱敏失败证据。

## 5. 本次明确未实测的边界

> [!warning] 文档核验不是运行证据
> 本次没有下载模型，没有构建 `llama.cpp`/bitsandbytes/GPTQ/AWQ，没有转换、量化、加载、推理或性能测试，也没有 CUDA GPU 证据。因此本次只能声称“一手资料与课程表述已对齐”，不能声称某架构、量化类型、内核、命令或性能在当前主机上已通过。

## 练习：把一条“最新量化表”降级成可审核结论

选一条不下载权重的虚构声明：“最新 `Q4_K_M` 在所有 NVIDIA GPU 上比 BF16 快 2 倍且无质量损失。”按下列顺序改写：

1. 列出缺失的模型 revision、`llama.cpp` commit、GPU/driver/Toolkit、后端、context/batch、prefill/decode 和质量指标。
2. 把“所有”改成“在这份 manifest 的条件下”。
3. 把“无损失”改成事先定义的阈值、配对区间与禁区失败。
4. 若没有原始证据，将结论标记为“待验证”，不继续转述为事实。
