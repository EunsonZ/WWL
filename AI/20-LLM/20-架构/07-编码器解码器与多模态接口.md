# 编码器、解码器与多模态接口

<!-- deep-review-02 -->
> [!tip] 本轮深化：从当前概念继续追问
> 编码器/解码器描述可见性与信息流，不规定所有生成方式。跨模态连接器和离散去噪模型分别改变信息瓶颈与生成路径，仍须定义条件分布。 深化与验证：[[AI/30-VLM/03-视觉语言对齐信息瓶颈与反事实评测|视觉语言对齐信息瓶颈与反事实评测]]；[[AI/20-LLM/80-研究拓展/02-离散扩散语言模型与自回归对照|离散扩散语言模型与自回归对照]]。


“Transformer”不是只有一种数据流。encoder-only、decoder-only 和 encoder-decoder 的主要差别，不是名字，而是**每个位置允许看见什么信息、输出怎样被使用、是否有 cross-attention**。多模态模型又在这个基础上增加视觉或音频编码器，以及把不同模态表示接入语言模型的接口。

> [!important] 第一阶段范围
> 本课是已经交付的**共享接口导论**：用 shape 和数据流解释 encoder、decoder、cross-attention、视觉前缀与 projector。它不提供真实图像预处理代码、VLM 权重、训练、GPU 实验或模型评测；这些仍属于 [[AI/30-VLM/00-VLM-MOC|VLM 第二阶段课程地图]]。理解本页不等于完成 VLM 课程。

## 学习目标

读完后，你应该能够：

1. 用 attention mask 区分 encoder-only、decoder-only 与 encoder-decoder；
2. 画出三类架构的输入、隐藏状态和输出路径；
3. 解释 self-attention 与 cross-attention 的 Q/K/V 分别来自哪里；
4. 追踪图像从像素到视觉 token，再到语言 logits 的完整数据流；
5. 根据任务、延迟与输入类型选择拓扑，并识别常见接口失败。

## 1. 先从“能看见谁”开始

给定 4 个 token：`A B C D`。

### 双向 self-attention

每个位置都能看见所有非 padding 位置：

```text
      被看见的位置
      A B C D
查询 A ✓ ✓ ✓ ✓
位置 B ✓ ✓ ✓ ✓
     C ✓ ✓ ✓ ✓
     D ✓ ✓ ✓ ✓
```

这适合为完整输入建立上下文表示，但如果直接用于 next-token 训练，位置 B 会偷看未来的 C、D。

### 因果 self-attention

第 $t$ 个位置只能看见自己和之前的位置：

```text
      被看见的位置
      A B C D
查询 A ✓ · · ·
位置 B ✓ ✓ · ·
     C ✓ ✓ ✓ ·
     D ✓ ✓ ✓ ✓
```

这使 decoder 能按从左到右的因果顺序预测下一个 token。mask 的精确定义与 attention 计算见 [[AI/20-LLM/20-架构/02-注意力MHA-MQA与GQA|注意力、MHA、MQA 与 GQA]]。

## 2. Encoder-only：把完整输入编码成上下文表示

### 数据流

```text
input tokens
  └─ embeddings + position information
      └─ N × encoder block
          ├─ bidirectional self-attention
          └─ FFN
      └─ contextual states [B,T,d_model]
          ├─ token-level head：标注、抽取
          ├─ pooled head：分类
          └─ embedding head：检索/相似度
```

encoder-only 的每个输出位置已经汇入左右文，因此适合理解完整输入。经典 BERT-type 模型是这个类别的历史例子。

### 精确定义边界

- “encoder-only”描述 Transformer 主干拓扑，不表示只能做编码格式转换；
- 它默认不包含按 token 自回归展开的生成解码循环；
- 可以在顶部接不同任务头，但任务头必须与训练目标相匹配；
- 若要生成文本，需要另加生成机制或采用不同拓扑，不能仅把分类 head 换成词表矩阵就假定会生成。

## 3. Decoder-only：把前缀继续向右生成

### 数据流

```text
prompt token ids [B,T]
  └─ embeddings
      └─ N × decoder block
          ├─ causal self-attention
          └─ FFN
      └─ LM head → logits [B,T,V]
          └─ 选下一个 token
              └─ 追加到序列并重复
```

Llama-type 模型是现代 decoder-only 自回归模型的学习主线，详见 [[AI/20-LLM/20-架构/05-Llama主线与模型家族比较|Llama 主线与模型家族比较]]。

### 关键性质

- 训练时可并行计算多个位置的 next-token loss，因为 causal mask 阻止偷看未来；
- 生成时仍需逐步决定新 token，先前位置的 K/V 可放入 KV cache；
- prompt、指令、检索文本、图像 token 等常被组织成同一前缀；
- “能接收完整 prompt”不代表 prompt 内部是双向编码：因果 mask 下，较早位置看不到较晚位置。

## 4. Encoder-decoder：先理解源序列，再生成目标序列

encoder-decoder 模型有两条序列：源输入 $X$ 和目标前缀 $Y_{<t}$。

```text
source tokens X
  └─ bidirectional encoder
      └─ encoder memory H
                         ┌─────────────────────┐
target prefix Y_<t      │                     │
  └─ causal decoder     │                     │
      ├─ self-attention │                     │
      └─ cross-attention: Q 来自 decoder，K/V 来自 H
          └─ FFN → logits → next target token
```

### Cross-attention 的精确定义

设 decoder 当前隐藏状态为 $D\in\mathbb{R}^{B\times T_y\times d}$，encoder memory 为 $H\in\mathbb{R}^{B\times T_x\times d}$：

$$
Q=DW_Q,\qquad K=HW_K,\qquad V=HW_V
$$

$$
\operatorname{CrossAttention}(D,H)=
\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_h}}+M\right)V
$$

输出长度跟随 query，所以 shape 的序列维是 $T_y$，而每个目标位置可以读取 $T_x$ 个源位置。padding mask $M$ 应屏蔽源序列中的 padding；decoder 自身还需 causal mask。

### 适用直觉

翻译、摘要、语音转文字等“有一份完整源输入，再产生目标序列”的任务天然适合这种拓扑。经典 T5-type 模型是文本 encoder-decoder 的历史例子。带源/目标token单位与可见语境去[[AI/35-传统NLP/10-语言结构与任务/05-翻译对齐解码与分层评价|翻译任务、对齐与分层评价]]，回来区分cross-attention混合、人工词对齐、解码概率与意义保持；那里的有限条件模型仅为可穷举机制实验，没有重新训练本页Transformer或自动认证语用。

## 5. 三类架构对照

| 维度 | Encoder-only | Decoder-only | Encoder-decoder |
| --- | --- | --- | --- |
| 主 self-attention | 通常双向 | 因果 | encoder 双向；decoder 因果 |
| cross-attention | 通常没有 | 通常没有 | decoder 读取 encoder memory |
| 主要输出 | 上下文化表示/任务 head | next-token logits | 条件生成 logits |
| 输入输出序列 | 一条输入 | 同一序列持续追加 | 源序列与目标序列分开 |
| 常见任务 | 分类、抽取、embedding | 开放式生成、对话、代码 | 翻译、摘要、条件生成 |
| 生成缓存 | 通常不是核心 | self-attention KV cache | decoder self KV + 可复用 encoder K/V |
| 风险 | 任务 head 不匹配 | 逐 token 解码延迟 | 两套主干与 cross-attention 成本 |

这里的“通常”很重要：研究模型会组合或修改这些结构。判断一个 checkpoint 时，应读取精确配置和论文，而不是只凭任务名。

## 6. 多模态接口：把像素变成语言模型能读取的表示

语言模型接收的是向量，不会直接理解 JPEG/PNG 字节。一个常见 VLM 数据流是：

```text
image bytes
  └─ decode + resize/crop/normalize
      └─ image tensor [B,C,H,W]
          └─ vision encoder
              └─ patch/features [B,N_v,d_v]
                  └─ projector / resampler
                      └─ visual tokens [B,N'_v,d_lm]
                          └─ 接入 language model
                              └─ text logits
```

其中：

- $N_v$：视觉 patch 或特征的数量；
- $d_v$：视觉编码器输出宽度；
- $d_{lm}$：语言模型残差流宽度；
- projector 解决宽度/表示空间不匹配；
- resampler 还可能改变视觉 token 数，以控制计算与保留信息。

图像、采样、频域和多模态数学的进一步入口见 [[数学/70-信号处理与多模态数学/00-信号处理与多模态数学-MOC|信号处理与多模态数学 MOC]]。

## 7. 三种常见多模态连接方式

### 7.1 Prefix / token 拼接

把投影后的视觉 token 放到文本 token 之前或插入占位符位置：

```text
[视觉 1][视觉 2]...[视觉 N][用户文本 1][用户文本 2]...
```

随后由 decoder-only language model 统一做 causal self-attention。

**优点**：接口统一，可复用语言模型块。

**代价**：视觉 token 占上下文并增加 attention 成本；因果顺序会影响谁能看见谁。

### 7.2 Cross-attention 注入

视觉编码器生成 memory，语言 decoder 在若干层用 cross-attention 读取：

```text
vision encoder ──> visual memory ─────────┐
text decoder ──> self-attention ─> cross-attention ─> logits
```

**优点**：视觉 memory 与文本序列分开，接口边界清楚。

**代价**：需要新增 cross-attention 参数、缓存和实现支持。

### 7.3 Resampler / 查询 token

用固定数量的可学习查询从大量视觉特征中提取较短表示，再拼接或 cross-attend。

**优点**：控制视觉 token 数。

**代价**：压缩可能丢失小字、细粒度位置或密集物体信息。

真实 VLM 可能组合这些方式。要核验的不是营销名称，而是视觉编码器、预处理器、projector/resampler、插入位置、特殊 token、attention mask 和语言模型版本是否配套。

## 8. 一个实际 shape 例子

假设一张图像被分成 $14\times14=196$ 个 patch，视觉编码器输出：

$$
H_v\in\mathbb{R}^{1\times196\times768}
$$

语言模型宽度是 $d_{lm}=4096$。一个逐 token 线性 projector 可将：

$$
[1,196,768]\rightarrow[1,196,4096]
$$

若再与 20 个文本 token 拼接，进入 language model 的序列长度是：

$$
T=196+20=216
$$

这会让语言模型 self-attention 处理 216 个位置，而非只处理 20 个文本位置。如果 resampler 把 196 个视觉 token 压到 32 个，则总长度变成 52，但是否保留足够图像细节需要任务评测，不能只看算力节省。

向量宽度变换与 batch/sequence shape 可回看 [[数学/20-线性代数与几何/01-向量矩阵与张量|向量、矩阵与张量]] 和 [[数学/20-线性代数与几何/02-矩阵乘法线性映射与Einsum|矩阵乘法、线性映射与 Einsum]]。

## 9. 多模态接口的完整核对清单

### 输入预处理

- 图像解码、颜色空间、通道顺序；
- resize、crop、padding 与长宽比策略；
- 像素范围、均值/方差归一化；
- 多图顺序、视频帧采样、音频采样率；
- 是否包含 OCR/区域坐标等额外输入。

### 表示接口

- vision/audio encoder 的精确型号与 revision；
- patch/帧/音频 token 数和输出宽度；
- projector、resampler 或 cross-attention 参数；
- 模态特殊 token、占位符与位置编号；
- attention mask 是否允许文本读到全部模态 token。

### 输出与验证

- 语言 tokenizer、chat template 与停止 token；
- 多图编号或区域引用是否对齐；
- 图像旋转、极端长宽比、小字、空白图、损坏文件的行为；
- 模态缺失时是否正确报错；
- 输出是模型推断，不是可验证的像素事实。

## 10. 设计权衡

| 决策 | 可能收益 | 代价/失败风险 |
| --- | --- | --- |
| Encoder-only | 完整输入双向表示，适合分类/检索 | 不自然支持逐 token 开放生成 |
| Decoder-only | 统一前缀与生成接口，扩展性强 | 生成串行；长前缀与视觉 token 成本高 |
| Encoder-decoder | 源/目标分离，cross-attention 清晰 | 参数、缓存和实现更复杂 |
| 更多视觉 token | 保留更细空间信息 | attention、显存与延迟增加 |
| Resampler 压缩 | 控制视觉序列长度 | 可能丢失小目标或文字细节 |
| Cross-attention | 模态 memory 与文本序列分离 | 需要额外层和运行时支持 |
| 共享语言主干 | 可利用已有语言能力 | 模态对齐未必充分，可能忽略视觉输入 |

## 11. 常见失败模式

1. **mask 泄漏**：decoder 训练时看到未来 token，loss 异常好但生成失败。
2. **padding 未屏蔽**：encoder/cross-attention 把 padding 当有效内容。
3. **Q/K/V 来源接反**：cross-attention 输出长度或语义不对。
4. **把 encoder 输出直接当文本 token id**：向量表示和离散 token 编号是不同对象。
5. **projector 宽度不匹配**：$d_v$ 没映射到 $d_{lm}$，残差或 attention 无法工作。
6. **预处理器与权重不匹配**：颜色、尺寸、归一化或 patch 规则不同，虽能运行但质量严重下降。
7. **特殊 token / chat template 不匹配**：图像占位符数量与视觉特征不一致。
8. **只加载语言权重**：遗漏 vision encoder/projector，模型可能忽略图像或直接报错。
9. **视觉 token 过多**：上下文、prefill 延迟与显存快速上升。
10. **过度压缩视觉 token**：小字、表格或密集场景信息丢失。
11. **把流畅回答当图像证据**：模型可能基于语言先验产生幻觉，需用可定位样本评测。
12. **把产品能力外推到任一 checkpoint**：同一家族的文本与多模态变体不能混用。

## 12. 练习：为三个任务选择拓扑

对以下任务分别选择 encoder-only、decoder-only、encoder-decoder 或带多模态接口的组合，并画出数据流：

1. 判断一段评论是正面还是负面；
2. 把一篇英文报告翻译成中文；
3. 读取一张带表格的截图并生成中文摘要。

每个任务都要写：

- 输入和输出；
- self-attention mask；
- 是否需要 cross-attention；
- 关键中间张量的序列维与宽度；
- 一个最可能的失败模式；
- 一个可观察的验收样本。

### 成功标准

- 任务 1 能说明 encoder-only + 分类 head 是自然选择，同时承认其他拓扑也可完成；
- 任务 2 能画出 encoder memory 与 decoder cross-attention，或对选择 decoder-only 给出可检验理由；
- 任务 3 至少包含图像预处理、vision encoder、projector/resampler 和语言生成；
- cross-attention 中 Q 来自 decoder，K/V 来自 encoder memory；
- 没有把图像文件字节、像素张量、视觉 token 和文本 token id 混为一层；
- 验收不只看“程序返回 200”，还检查分类标签、翻译忠实度或表格内容定位。

## 13. 小结

- encoder-only 用双向上下文建立表示；decoder-only 用因果 mask 生成；encoder-decoder 用 cross-attention 连接源与目标；
- cross-attention 的 Q 来自解码侧，K/V 来自编码侧 memory；
- VLM 需要从像素预处理、视觉编码、投影/重采样一路接到语言模型；
- 多模态能力不是只加一个 `<image>` 字符串，预处理器、特殊 token、权重和 mask 必须配套；
- 具体模型的拓扑、模态、分辨率、模板与许可证会变化，应通过 [[AI/90-资源/05-官方资料与版本核验记录|官方资料与版本核验记录]] 和固定模型卡核验。
