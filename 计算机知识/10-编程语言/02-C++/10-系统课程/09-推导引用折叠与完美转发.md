# 把模板推导逐行算清：auto、decltype 与完美转发

> **本页要解决**：T&& 何时是右值引用，何时是转发引用？

>
> **阅读入口**：[[计算机知识/10-编程语言/02-C++/10-系统课程/00-C++系统课程索引|本学科主索引]] · [[计算机知识/00-开始/全局导航/11-难点导读与研究证据|全局难点导读]]。

**版本、模型与证据边界**：示例以 C++20 编译；标准条文采用固定草案 N4861，库契约与特定实现性能分开讨论。

## 三个很像的声明，问的却不是同一个问题

```cpp
int x = 7;
const int cx = 8;
auto a = cx;
auto& b = cx;
decltype(auto) c = (x);
```

`a` 是一个独立的 `int` 值；`b` 是 `const int&`；`c` 是 `int&`，会别名到 `x`。`auto` 主要借用模板实参推导的规则，`decltype(auto)` 则使用 `decltype` 规则。不要把它们都读成“编译器知道，所以不用管”。涉及所有权和借用时，省略写出的类型恰好是最值得核对的部分。[^cpp-deduce]

## 先确定表达式类别，再推导类型

命名变量的表达式通常是左值，即使变量的声明类型是右值引用。`int&& r = 3;` 之后，表达式 `r` 是左值，`std::move(r)` 才是 xvalue。`std::move` 本身不移动字节、不分配存储，也不保证后面一定调用移动构造，它只是产生允许参与相应重载选择的表达式。[^cpp-move]

对 `decltype(e)`，未加括号的标识符表达式、某些成员访问有特殊规则，取得被命名实体的声明类型；其他表达式按值类别决定结果：左值为 `T&`，xvalue 为 `T&&`，prvalue 为 `T`。因此 `decltype(x)` 是 `int`，`decltype((x))` 是 `int&`。括号不改变变量本身，却改变了适用的 `decltype` 规则。[^cpp-decltype]

### 返回值上的一个危险差别

```cpp
auto value() {
    int local = 9;
    return local;           // 返回 int 值
}
// 不要使用：
// decltype(auto) dangling() {
//     int local = 9;
//     return (local);      // 推导为 int&，指向已经结束的局部对象
// }
```

后一个例子是需要被审计拒绝的设计，不是因为 `decltype(auto)` 总是不安全，而是它忠实保留了你不该返回的引用。正确做法从返回合同开始：调用方要拥有值，还是要短期借用一个由别处保证寿命的对象？见 [[计算机知识/10-编程语言/02-C++/10-系统课程/10-借用视图失效与异常提交|视图与生命周期]]。

## T&& 的两种身份

```cpp
template<class T> void inspect(T&& value);
template<class T> void fixed(const T&& value);
```

第一种在 `T` 由本次调用推导且满足规则时是转发引用；第二种带有 `const`，不是相同形式的转发引用。类模板的成员使用已经由类实例确定的 `T&&`，也不能一概当作转发引用。[^cpp-deduce]

对第一种，传左值 `x` 时先推导 `T = int&`，于是形参表面成为 `int& &&`，引用折叠得到 `int&`；传 `const int` 左值时得到 `const int&`；传临时整数时 `T = int`，形参为 `int&&`。折叠规则可以记成：组合中出现左值引用，最终通常折为左值引用；只有右值引用与右值引用组合保留右值引用。

| 调用实参 | 推导出的 T | 形参最终类型 | 函数体中 `value` 表达式 |
| --- | --- | --- | --- |
| `x` | `int&` | `int&` | 左值 |
| `cx` | `const int&` | `const int&` | 左值 |
| `7` | `int` | `int&&` | 左值 |

最后一列最容易被漏掉：函数体里的命名参数都是有名字的表达式，不能因为声明有 `&&` 就假定继续传递时仍是右值。

## 完美转发究竟保留哪一部分

```cpp
#include <utility>

template<class T>
decltype(auto) relay(T&& value) {
    return target(std::forward<T>(value));
}
```

这里的 `target` 是示意依赖名称，完整可编译用例在实验文件。`std::forward<T>` 根据推导到的 `T` 选择保留左值，还是恢复相应的右值类别。把它换成 `std::move(value)` 会不加区分地允许消耗调用方传来的左值；直接传 `value` 又会丢失右值类别。

但“完美”不包含所有程序语义：转发不延长对象寿命、不使同一对象可以被安全移动多次，不推断异步回调需要的拥有关系，也不能把无类型的花括号初始化列表随意推导为任意 `T`。包装器的异常规格、约束、重载可见性和返回类别仍要设计。

返回 `decltype(auto)` 仅在需要保留 `target` 的引用结果、且其寿命合法时适用。返回 `auto` 会更偏向值语义，但也可能产生复制、切片或不可复制类型错误。选择依据是接口合同，不是哪个关键字更高级。

## const 会怎样影响移动

`std::move(cx)` 的类型保留 `const`，通常是 `const int&&`；对类对象同理。常见移动构造函数接收 `T&&`，不能从 `const T&&` 修改源对象来转移资源，所以重载选择可能退回复制。不能看到 `std::move` 就把性能报告中的复制次数写成零。

`noexcept` 又是另一份合同：它影响库在异常保证下可选择的操作。某些容器扩容时，为保留强异常保证，面对可能抛异常的移动构造会选择可用的复制；但具体保证要看元素类型和操作条款，不能简化为“所有 vector 总是复制或总是移动”。

## 编译期验收，而不是猜输出

使用 `static_assert(std::is_same_v<...>)` 检查推导结果；为接收 `T&`、`const T&`、`T&&` 的重载记录所选分支；正向用例编译通过，真正应拒绝的调用必须编译失败。不要用 `typeid(...).name()` 作为引用和 cv 限定完整保留的唯一证据。

**练习**：`auto&& z = cx;` 的结果是什么？答案是 `const int&`。为什么 `relay(x)` 不应自动转移 `x` 的资源？因为调用方传的是可继续使用的左值，转发应保留该关系。与 [[计算机知识/10-编程语言/04-Rust/10-系统课程/09-借用检查中的量词方差与重借用|Rust 的重借用]] 对照，两者都在控制访问关系，但 C++ 转发不会提供 Rust 同样的静态借用检查。
