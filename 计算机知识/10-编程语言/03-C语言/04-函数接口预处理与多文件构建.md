# C：函数接口、预处理与多文件构建

> 阅读定位：C17 核心；扩展和标准版本差异单独注明。返回 [[计算机知识/00-开始/课程地图/01-C语言-课程地图|C语言 · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## 把“别人能依赖什么”放在头文件

一个 `.c` 文件通常形成一个翻译单元。公共头文件只暴露必须共享的类型、函数声明和常量约定，内部函数用文件作用域 `static` 限制可见范围。外部链接允许链接器把多个单元中的引用对应到定义；作用域则决定源代码中名字何时可见，两者不是一回事。

头文件用 include guard 避免同一单元重复包含。不要在公共头文件随意放非 `static` 的对象定义，否则可能在多个单元产生重复定义。用 `extern int counter;` 声明，在一个 `.c` 中定义 `int counter=0;`；更稳健的设计往往是隐藏全局可变状态，通过函数操作。

```c
#ifndef COUNTER_H_INCLUDED
#define COUNTER_H_INCLUDED
#include <stddef.h>
struct Counter;
struct Counter *counter_create(void);
void counter_destroy(struct Counter *p);
size_t counter_value(const struct Counter *p);
#endif
```

不完整类型使调用者不能依赖内部布局。创建和销毁必须成对，并约定空指针、失败、线程安全和谁拥有对象。跨动态库边界尤其要避免在一个运行时分配、在不兼容的另一个运行时释放。

## 宏为何不是普通函数

`#define SQUARE(x) ((x)*(x))` 补齐括号仍无法解决重复求值：`SQUARE(i++)` 会展开出两次副作用。能用函数或 `static inline` 表达的运算优先用函数。宏适合条件编译、少量生成式代码和预处理阶段选择，代价是调试与类型检查更弱。

`#ifdef` 检查宏是否定义，不检查运行时变量真假。头文件包含、条件编译、字符串化 `#`、记号拼接 `##` 和可变参数宏需要知道用途，但不应把复杂控制流藏在宏里。`_Generic` 可按表达式类型选择分支，仍需理解被选择表达式及宏参数的求值规则。

## 函数指针把行为作为参数

排序比较器、事件回调和分配器接口可以传入函数指针。常见模式是“函数指针 + `void *context`”，让回调携带调用者状态；context 的生命期至少覆盖回调的使用期间。异步注册回调后立刻销毁 context，会把生命周期错误推迟到另一条执行路径。

比较整数时不要简单返回 `a-b`，减法可能溢出。使用 `(a>b)-(a<b)` 表达三路比较。变参函数不能获得每个实参的可靠类型描述，格式串、默认提升、`va_start`/`va_arg`/`va_end` 必须匹配；新接口能用明确结构体表达时，不必选变参。

## 构建诊断练习

把计数器拆成 `.h`、实现 `.c`、测试 `.c`，分别编译再链接。故意漏掉实现文件，应看到链接错误；把函数参数类型改错，应在声明检查阶段暴露。最后解释 `const`、`static`、`extern` 分别约束哪一个维度。C 与 C++ 在链接、初始化和类型规则上并不完全相同，不能仅把后缀改为 `.cpp` 就认为语义不变。
