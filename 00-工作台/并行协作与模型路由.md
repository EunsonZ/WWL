# 并行协作与模型路由

稳定边界见 [[AGENTS|AGENTS.md]]；内容审校见 [[00-工作台/维护指南|维护指南]]。本页是按需操作说明，不是每个子代理必须全文读取的提示词。写在文件里的规则不等于已实现的检查器，也不等于客户端已具有相应能力；启动前核对实际工具与本批证据。

## 1. 先选问题，再选并行宽度

一个任务交付一个可验收的读者问题，可以涉及多篇页，也可以结论为无需改动。不要把段落数、文件数或代理数当成果数。同一失败机制的机械修正可以合批；困难前提与普通润色可以分开；源码、测试和文档镜像要保持一致交接。

三种工作尺度：普通小修用任务消息和相关备份；几个相关问题使用小型交接记录；大量独立问题才使用最多 32 个子线程和一份库外批次清单。没有足够独立问题，不拆出无意义工作填满容量。

并行的理论下限受总工作量与关键依赖链共同限制。用 W 表示总有效工作、L 表示最长依赖链、p 表示并行数，忽略协调等开销时已有 T ≥ max(W/p, L)。因此，把所有前提判断留给一个根代理，不能靠增加作者解决。

日常跨层案例以少量作者、独立审阅者和单发布者滚动交付：任务只列问题、确切候选写集合、关键输入、反例/复算验收及未覆盖层。共享定义、图文和源码镜像作为同一组合验收；不因容量尚有空位扩大范围。审阅标准答案时同时寻找合法的替代解法，避免将作者预期方法变成未声明的评分约束。

## 2. 启动时确认四个实际边界

协调者确认主库根、不可变输入快照、候选工作区和最终发布位置，记录当前适用规则版本。非 Git 库从库根启动；独立工作区带入必要的同版根约定及适用嵌套指令。Codex 的指令发现与工作目录、项目根有关，并在运行开始时构建；修改文件不能自动刷新已有会话。[1]

确认客户端实际暴露的子代理工具、可用模型/effort、有效并发上限、结果通知、关闭行为、工作目录和权限。不能给工具加它未接受的参数。请求值与实际值分开记录；无法观察就写 `not_observed`，不以角色名证明真实路由。

项目配置以最多 32 个打开的子线程为目标，主线程不在该配置计数中。该配置是会话上限，不是跨会话的全局锁；本批另开的执行/审阅会话和任何后代也须计入人工维护的 32 槽预算，不通过多主会话放大并发。这不是 32 个请求必定同时计算的保证，也不是新增账户额度。具体上限与权限受客户端和现场约束。[2]

2026-09-15 本批工具实际声明可用并发为 26 槽，包含主代理；这与项目的 32 子线程目标分开记录。本批没有完成 32 路运行验收，下一次启动仍须读取现场额度。

四个 `wwl_*` 角色默认只读，返回发现、补丁或审阅结果。角色文件不固定模型及 effort，让任务级路由有机会生效；实际支持仍须核验。自定义角色中的固定模型/effort 有自身优先级，父会话实时权限覆盖也可能重新施加给子会话。[3]

真正并行写入使用经验证的独立工作区或已有 Git worktree。不将候选库连接到主库同步，也不启动 32 个 Obsidian 实例。可共享受控的只读基线和非敏感依赖；写区不能用可写硬链接共享原文件。最小切片缺少实验必需资源时，测试须在完整集成视图复核。只读自定义角色不能靠提示词变成写者：需要写文件时，使用客户端确实支持的独立写会话/内建执行角色，工作根指向该隔离区，并携带任务和同版约定。不能让它共享可写主库，再假称目录约定提供了隔离。worktree 有助于分开文件状态，但不自动限制其他工具权限。[4]

如果客户端只能共享工作目录，采用 32 路以内的只读取证、分节提案和审阅，再由受控集成步骤应用补丁；如实记录实际写入并行较低。禁止为弥补缺失能力新造一个常驻调度平台。改指令/配置的迁移批与使用新规则的内容批分开，旧运行先保全、核对并结束或明确接续。

## 3. 一个资源池，不设永久部门

根协调者只确定问题边界、授权、预算分配和发布；领域作者及审阅者自己完成内容判断。每个工作者可在授权包中自主完成定位、取证、修订与局部验证，不必每步请示。允许直接向指定依赖方澄清事实；涉及前提或交付变化，把结论记到本任务产物，不仅留在聊天中。

为减少根代理逐消息调度，可以一次授权一个很小的待办束：明确问题、精确候选写范围、下一项准入条件、最多尝试及预留。工作者完成当前项后，可在同一授权与能力范围继续下一项。换模型需要新的可核对尝试；不因持有待办束就允许自行生出后代或占有整域。存在写冲突的任务不得同时授予。

32 槽的一种**假设性工作快照**如下，只适合已有足够问题、审阅比作者工作更短的阶段，不是默认组织编制：

| 当前有价值的工作 | 槽数 | 一种可能的路由构成 |
| --- | ---: | --- |
| 独立候选作者 | 16 | 16 Terra，复杂任务按实际难度替换 |
| 正在复核具体产物的审阅者 | 8 | 6 Terra、2 Sol |
| 定位、原文核对、独立测试准备 | 6 | 4 Luna、2 Terra |
| 关键阻塞或短接口解题 | 2 | 1 Sol、1 Astra |

合计 32，主协调者另计。同领域也可同时有多个作者写不同最终文件；文件所有权只持续到当前候选交接结束，不占有整门学科。不同领域或问题簇按实际 ready 工作共享容量；不为每簇新增经理。需要组合整合时，由某个已有作者兼任临时整合者，不叠一层专职汇报代理。

没有待审产物时不启动八名空等的审阅者；可用这些容量做独立验证准备。预先独立推导期望值或写测试，不破坏其后来审阅的独立性；参与作者候选写作才不能再冒充独立审阅。

每有可用结果或阻塞变化，收取必要短回执，释放不再复用的线程，优先处理解锁关键路径的审阅、已承诺返工和发布收尾，然后派发新作者与独立取证。不要因调度方便就把 32 项绑成一次全等；若实际工具只能按集合等待，按真实依赖与大致耗时拆成小型独立集合并披露限制，不能伪称事件驱动已实现。客户端不支持工作者直连时传递产物引用和短问题，不虚构点对点工具；不得为此搭建消息服务。

作者准入看待审工作量，不看固定稿件数。积压超过当前审阅者约一轮能处理的量、最老稿反复被插队或根代理忙于抄写报告时，把新作者容量转给审阅/整合。只在有实际任务时占槽；不要暂停整个领域来处理一个阻塞。空等线程仍可能占打开额度；保存续接信息后按客户端能力关闭，不假装暂停就释放配额。优先级要兼顾最老待审项，不能让长尾永远让路。CPU、内存、网络和共享 API 限额另行约束昂贵测试，32 名读者不等于同时跑 32 次全库测试。

## 4. 任务、尝试、输入版本分别处理

多人任务包至少说明：读者问题、完成标准、精确写集合、关键输入、禁止项、风险与复核要求。由 agents 生成，人不用填写。模型、effort、会话、费用及重试放在运行尝试中，不改变无关任务的内容契约。

| 输入 | 怎么使用 | 什么时候需要等待或复核 |
| --- | --- | --- |
| 固定旧基线 `base` | 使用明确的旧字节与相关前提 | 不因另一个作者正在改它而自动等待；最终组合若改变相关前提，必须重新验收。 |
| 新产物 `artifact` | 绑定生产者、具体输出及实际哈希 | 正式消费者须拿到已接受的具体版本；审阅者可读待审版本。缺失文件不能作为空输入就绪。 |
| 普通背景 | 给定位，不一律进入阻塞图 | 真正影响结论的前提不能被降为背景以绕过检查。 |

上游尚待审时，下游仍可并行查来源、准备测试、写不依赖该前提的部分。确有提前价值时，可明确授权一个低返工成本的暂定草稿，绑定待审版本并标记为推测性候选；不能把它标为正式就绪、继续层层扩散或直接发布。上游接受后核对实际差异，重新签收受影响部分，而不是把等待变成唯一工作方式。

两个任务只读对方旧版本且不破坏共同前提，可以并行。真正互相需要尚未形成的新定义，应先解决共同前提或合并紧密部分，不删依赖制造假 DAG。高扇出前提明确且比全文更容易核验时，可以先审一个短约定，再让下游使用；短约定含对象、符号/单位、条件、边界及依据，最终正文必须实现它。普通任务不加接口层。

**两个候选各自通过，不等于组合通过。** 两篇互相删除重复解释、同时变更计量口径或同时弱化前提，可能产生无文本冲突的语义缺口。只对真正受影响的定义、删除责任、指标或引用承诺做组合审阅，不把所有双链都纳入发布组。

涉及“库中不存在”“只有此处定义”或新增别名的任务，还要保存相关检索范围与方法，发布前对现场及本批候选重跑该检索。它检查新增文件造成的遗漏，不要求每页建立全库目录哈希或概念注册表。无法穷尽搜索时明确范围，不输出全库否定性保证。

任务路由变化只产生新尝试；关键输入、写范围或验收变化需要重新绑定对应契约。人的保护边界与当前权限在发布时复核，不能靠旧授权继续写。交接允许新作者使用旧候选，但要绑定其版本并保留责任；旧尝试撤销后即使迟到也只能作为材料，不能覆盖现作者；撤销记录不等于远端调用已停止，也不抹掉费用。

## 5. 按能力需求选模型，按推理需求选 effort

下表是待本库校准的路由起点，不是四模型的通用能力排序。先使用确定性工具；难题可直接选强模型，不强迫逐级试完便宜型号。

| 任务 | 起始候选 | 不适用或升级原因 |
| --- | --- | --- |
| 枚举、哈希、路径、镜像、金额算术 | 脚本 | 模型定位问题，脚本执行确定规则。 |
| 已给片段的定位、提取、候选别名 | Luna/low | 语义含混、长材料分散或否定性查证改 Terra/Sol；不能由一次廉价搜索证明不存在。 |
| 证据确定的局部解释与普通例子 | Terra/low 或 medium | 真正复杂推导或接口变化再选更强能力。 |
| 普通解释的独立复核 | Terra/medium | 风险和验证难度提高时选 Sol/Astra，不把所有审阅固定为 Sol/high。 |
| 跨页符号、工程边界、统计与数学复算 | Sol/medium 或 high | 可配对比较 Astra/low 或 medium；比较完整成本与缺陷，而非单价。 |
| 高影响前提、困难研究阻塞 | Astra/medium 或 high | 更高 effort 仅在有新方法、推理仍是瓶颈且预算允许时使用。 |

客户端可用范围取交集；2026-09-15 已打开的官方 API 页面列出 Astra 的 low/medium/high/xhigh/max，Sol、Terra、Luna 另支持 none，但本库日常只取 low/medium/high，不把 API 枚举直接当成本机配置支持。[5][6][7][8]

一次失败先分清：资料没找到、输入漏页/过期、需求矛盾、工具权限、输出截断、限流、格式错误，还是推理不足。只对最后一类考虑增加 effort 或更强模型；其他失败修对应环节。一次局部修复之后继续尝试，要有新的证据、方法或能力变化，并在原读者问题下累计费用，不换任务 ID 重置预算。

角色可以复用职责，但审阅不沿用作者的完整对话作为默认上下文。给问题、候选、必要原文、明确标准即可；有工具支持的独立上下文才称独立会话，不能自造不存在的 `fork_context` 参数。稳定规则可复用，但不用重复上下文来追求缓存；缓存命中需看实际用量。[9]

## 6. 经济性：完整成本、在途预留、有限比较

2026-09-15 已打开四个官方模型页面并核对以下价格。下表为官方直连 API、标准服务、短上下文、每百万文本 token 的美元参考价，**不是 Codex 订阅账单或你的实际成本**。[5][6][7][8]

| 模型 | 非缓存输入 | 缓存读取 | 缓存写入 | 总计费输出 |
| --- | ---: | ---: | ---: | ---: |
| Luna | 0.20 | 0.02 | 0.25 | 1.20 |
| Terra | 2.00 | 0.20 | 2.50 | 12.00 |
| Sol | 4.00 | 0.40 | 5.00 | 20.00 |
| Astra | 10.00 | 1.00 | 12.50 | 50.00 |

表内 Luna、Terra、Sol 的缓存写入价按各模型页给出的普通输入价 × 1.25 计算；Astra 页列明 12.50。此表说明报价口径，不证明当前客户端请求采用该服务档。

旧批次绑定当时的价格文件及其哈希。长上下文、服务档、地区、工具和提供方可能改变报价；Sol 页面说明当前促销价至少延续至 2026-11-21，之后须重新核对。实际模型或服务档未知时不给精确总额，不默认为 standard；订阅消耗与直连美元估算分开报告。[10]

按每个实际请求计价，再汇总至原读者问题。计费输出包含适用 reasoning tokens，不只统计可见回答，也不重复加一次 reasoning。输入总量中的普通、缓存读和缓存写不可重复计数。[11]

相同提供方/计费作用域内同一请求重复导出应只结算一次；同一提示的新请求、真实重试、超时后仍产生的调用都要计入。ID 冲突需调查，缺 ID 不凭文本相同猜测去重。协调、共享取证和工具费用在批次账上只记一次；归因到问题时不可再次加入总额。未知费用保留未知，不当成零。

派发前由唯一预算控制者预留作者、必要审阅与收尾费用；可把互不重叠的预留额度委托给任务束，但不得让多个工作者分别使用同一份“余额”。已确认支出 + 在途预留 + 新工作和其收尾预留，不能超过已授权额度。预算缩小时停止新增可选工作，保留审阅门槛，不为了省钱发布未审稿。

费用计算的输入口径、可用命令与限制见 [[scripts/MODEL_COST|离线费用说明]]；`model_cost.py` 是离线算术，不是硬熔断。没有实际用量、工具/步数上界或可验证取消能力，就不能承诺硬金额上限；只承诺有限范围与明确停止规则。不得擅自从订阅转 API、购买额度或创建密钥。不同模型可能共享限额，遵循实际响应与有界退避，避免 SDK 和上层双重重试及 32 路同步重试。[12]

经济性看“完成且验收的问题”的全成本，同时保留未完成、返工及弃稿费用。Astra 可能用更少步骤解决难题，但不预设它一定比 Sol/high 便宜；Luna 单价低也不代表复核后成本低。只在实际任务样本上比较相邻候选，不穷举四型号乘所有 effort。

## 7. 产物与回执：短消息，可追溯原件

一批只保留一个协调者维护的权威清单，放在库外。工作者在自己的尝试目录输出补丁、原文定位和检查结果；没有写权限就通过工具结果返回，由集成者原样保存。工作者不共写队列、总日志或 `CHANGES.md`。

回执是产物，不是第二个共享状态库。交付摘要采用下面的短格式，详细证据另给定位；严重缺陷不能因摘要长度被截掉：

```text
任务 / 尝试 / 适用规则与实际输入版本：
处置：candidate | accept | reject | no_change | blocked
产物：路径与哈希，或可保存的补丁；没有产物明确说明
解决了什么 / 影响哪些前提或调用页：
证据与检查定位；未运行及未覆盖范围：
阻塞与最小下一步：
实际模型/effort、请求标识与用量：可观察值；否则 unknown
```

协调者从真实会话结果取得身份与状态，核对精确字节，不把作者自己填的 `accept` 当成独立签收。清单只引用必要事实，不反复把完整报告粘回主上下文。单页小修可在会话完成这些信息，不强制创建 JSON。

派发前登记尝试意图与范围，派发后补实际线程/请求 ID。发生崩溃、超时或状态未知时先核对已运行工作，不直接重发相同任务。迟到结果、撤销和费用分开处理。恢复靠清单及产物，不靠模型记忆；未确认当前主库发布者之前只做候选工作。

## 8. 审阅是可执行标准，不是投票

作者在动手前知道完成标准。审阅者看具体候选与原始依据，核对必要推导、来源吻合、受影响连接和声明的验证。先自行检查再读作者的自评；发现可定位的问题才退回，不为个人文风偏好无限往返。

纯机械、可确定验证的改变可以使用合适检查与发布者核对；修改定义、公式、因果、计量口径、代码语义或关键链接含义就不是机械改动。`publish`、`research` 或“只改一个字”等标签都不能降低内容门槛。

参与同一候选写作或替作者决定关键修补方案的会话，不作为该候选唯一独立审阅者。不同型号不代表不同外部证据；同型号的独立检查也不应一律否定。关键来源须实际打开，关键推导须能复算，不能让很多作者共用一个未经核对的取证摘要再把一致意见当多份证据。可复用原文的同版定位和确定性检查，但不能把一份解释性摘要的反复引用算多重独立来源；高影响断言的审阅者须回到原始证据。

验收绑定具体输出与输入；产物修改后原签收不覆盖新字节。可以只重新核对实际差异，但须记录新依据。一个审阅者可逐项处理多份小稿，独立稿逐份签收，不绑成“最后一篇过了才全组过”。

争议先确定来自证据、定义、计算、价值判断还是任务范围。可用原文或实验解决的不要升级成多模型辩论；仍然困难才给强模型一个窄问题。无法裁决时保留争议与边界。模型裁判存在位置和篇幅偏好，评分须与真实依据和人的评价校准，不能当成客观真值。[13]

## 9. 小组发布，不冻结全库

先在库外组装最小完整的候选组：例如新定义及所有被它实际改变的本批应用；未改变前提的其他文章独立发布。入链很多不自动意味着要改所有邻接页；但删除、重命名或定义责任转移必须检查真正受影响的引用。

发布前检查：目标旧版本仍匹配；关键输入与最终组装相容；具体签收覆盖拟发字节；没有越界修改；相关结构、源码镜像、语义及验证要求满足。发布者做这些窄检查，不重新承担全部领域审阅。新增语义改动即使由发布者提出，也回到适用复核，不夹带进“合并”。

人的无关页面修改不阻塞本组；目标或关键输入变了，旧请求先失败。随后用旧基线、人的当前版本和候选进行三方比较，保留人的改动，重新验收受影响差异；不能刷新哈希后当旧检查仍有效。

哈希检查与写入之间仍有竞态。只在本组目标的写入、未保存编辑、同步及自动格式化得到实际控制后发布；做不到就交候选。一个本地文件替换不等于多文件原子事务，不能靠锁文件保证跨设备互斥。发布控制只由一个已确认的主库写者持有，不为此搭建分布式锁服务。

中断前留存旧/新字节和应用顺序。恢复时逐文件分辨旧版、预期新版、第三种内容；新版不重复应用，第三态先保全停止。回滚只处理本批仍匹配输出的文件，并核对整组一致性。完成后记录发布版本与尚未验证的层，不把检查器的通过写成“知识正确”。

## 10. 检查器与降级方式

当前工具从实际 `--help` 与测试确认能力；具体能力和未实现边界见 [[scripts/COORDINATION|协作检查说明]]，静态结构检查见 [[scripts/CHECKS|维护检查说明]]。这些脚本说明的状态须在本批集成后用实际结果复核。若存在 schema 1 的 `plan/snapshot/audit/stale`，它们是结构与字节检查，不是就绪、审阅或发布批准；`base_matches` 尤其不能证明未来输入已经产生。新 schema 或 `release-check` 未实现并通过针对性测试前，不得当它们已经可用。

多人新版本交接宜采用小型局部契约：任务范围与验收绑定任务，实际输入绑定尝试，验收绑定产物，发布绑定候选组。无关路由与队列排序不影响内容有效性；保护和权限变化仍生效。记录字段必须有实际检查或恢复用途，不制造无用途的编号系统。

检查器缺少必要能力时，退回只读提案、明确的人工/代理版本核对和单发布者小组整合；不能忽略报错扩大自动发布。未知字段、schema 或权限条件须报错或明确不支持，不静默丢弃保护字段。未实现的功能只登记在实际结果的待办中，不伪造配置键。

## 11. 人的反馈与长期校准

一批给人的结果只说清：解决了哪些卡点、值得读的几处差异、需要人判断的真正冲突、未验证项及撤销范围。不要把 32 份工作报告交给人整理。人的一次自然反馈先定位到问题，不自动扩大成全库改造。

内容试点优先沿现有链调查：Attention → KV Cache → 系统带宽；统计目标量 → RAG 指标 → 实验；CMake → 链接 → ABI。路径由现场检索确认；问题是待调查场景，不预先断言原文有错。文化与组织分析保留相反假设和来源限制，不将并行写作变成批量同质化。

分别观察找得到、看得懂、能迁移：能否定位目标段；能否复算例子；换一个条件能否判断边界。没有人的实际反馈就标未测，不替用户填掌握度。不要将插件图谱密度、字数增长或笔记数量作为收益。链接格式与实际目标参考官方说明，阅读效果须实际检验。[14]

用已有用量和时间记录，比较同类任务的首次接受、严重缺陷、完整费用、端到端耗时、审阅积压及人的必要分钟。比较并发时先固定任务与路由；比较模型时固定基线和标准，后跑者不看前者答案。小样本用于找方向，不宣称精确成功率；没有必要建立遥测平台。用量下降而严重缺陷上升不是成功；小样本零错误也不证明没有风险。开到 32 后验收吞吐不增、尾部变慢或重试增多，就缩回瓶颈前的并发。

达到真实问题的完成标准就停。文风返工、无新证据的循环尝试、重复全库扫描或维护清单成为主要成本时，先删步骤、缩小工作包，不继续加规则。可选试验缺能力时明确 deferred，不牵连已验收的独立正文；必要质量门槛未满足时仍不发布相关候选。
