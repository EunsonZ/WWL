# 反馈线性化与零动态：看见输出之外的状态

先读 [[控制论/10-系统课程/16-反馈线性化相对阶与零动态#一个非平凡坐标变换，把失效留在眼前|第16课的三状态模型与坐标变换]]，自己预测：只把内部参数 σ 从−1改为+1，理想反馈的输出是否改变？哪个状态和哪一个输入会增长？再读下列曲线与结果。模型全部状态、输入和输出均无量纲，时间 τ=t/t₀，默认 t₀=1s；这些变量没有被认作硬件SI读数。CSV中 t_s=τt₀，s_scaled=dy/dτ，真实时间变化率为s_scaled/t₀。若更改t₀，只改变这个合成对象的时间尺度，未建立实物参数证据。

原坐标与正规形的关系是 (y,s,η)=(x₁,x₂+x₁x₃,x₃)，逆变换 x=(y,s−yη,η)。对象满足 y′=s，s′=η+(1−y²)u，η′=ση+y。控制请求 u_cmd=(ν−η)/(1−y²)，ν=r″−2(y−r)−3(s−r′)；零目标r=0，跟踪例r=0.1sin(0.5τ)。源码分别写原坐标和正规形RHS，并比较两条数值积分路线；未以正规形的输出漂亮代替完整对象检查。

## 从输入到有限结果

[input.json](input.json) 声明初值、参考、时间、输入上限和五例语义；[zero_dynamics_lab.py](zero_dynamics_lab.py) 是标准库真源，[[控制论/80-实践/07-反馈线性化与零动态/code-sync/zero_dynamics_lab|源码阅读镜像]] 与之逐字相同。Python3.10以上即可执行，不需安装科学计算库。在本目录运行，输出必须使用**尚不存在**的目录：

```sh
python3 -B zero_dynamics_lab.py --input input.json --output-dir /private/tmp/wwl-zero-my-run
```

本次作者执行通过已有的 `/private/tmp/numerical_guard.py --threads 1 --timeout 60 -- python3 -B zero_dynamics_lab.py --input input.json --output-dir <新目录>` 限制并发与时限。结果先产生于新目录，再保留到 [results/summary.json](results/summary.json)；实际环境与耗时在 [run-output.txt](run-output.txt)。本次Python3.14.7/macOS CPU执行约0.111s、进程观测峰值RSS约24.7MB；这是运行记录，不是对未来参数的内存上限证明。

| 入口 | 输入/内部参数 | 有限结果与边界 |
| --- | --- | --- |
| minimum | σ=−1，理想请求，零目标 | 301行到τ=6；全时幅度证明给请求界0.3838178171<上限1，所以同一解也满足实际限幅对象。 |
| nonminimum | σ=+1，理想请求，零目标 | 301行到τ=6；输出与minimum相同，内部η约21.51608。这是允许无限请求的比较模型，不能称可实现控制。 |
| saturated | σ=+1，真实输入截到[−1,1] | 221行；定位至τ≈4.382870904、y=0.8即停止，没有此后饱和曲线。 |
| tracking | σ=−1，正弦参考，理想请求 | 301行到τ=6；全时请求界0.2183058538<1，内部响应和误差均有解析基准。 |
| singular_initial | y₀=1,s₀=0,η₀=.02 | 仅τ=0一行；分母为0，不计算控制请求，不求RHS，不伪造后续轨迹。 |

五例共1125条轨迹行；其中minimum和tracking共602行属于有全时幅度证书的两个入口。证明在正文，代码只检查当前参数的充分幅度界与有限数值一致性。nonminimum的无限请求与saturated的真实限幅严格分开。

[trajectories.csv](results/trajectories.csv) 保存原坐标、正规形、参考、误差、输入分母、请求/实际输入、输出加速度与状态。初始停止行的请求、实际输入、ν、加速度和可实现判断字段留空，表示未定义，不表示0。`actuator_feasible`只判断该点请求是否落在上限内，不把有限行全部通过当作全时证明。`case_status`对整条有限入口标出终止原因。

[events.csv](results/events.csv) 的4行包含两个τ=2.94的首个**导出点**超上限观察、饱和guard停止、奇异初值停止。首个导出超限点不是精确首次饱和时间。guard使用最后一个RK4子步上的二分定位；这是数值事件估计，缩步误差另列，不能因为guard残差极小就宣称事件时间精确。现有守卫|y|=0.8小于反馈奇异边界1，保证成功完成的数值阶段没有靠穿过奇点继续运行。

## 用不同路线重算，而不是只重复一张图

每例RK4子步取0.02、0.01、0.005、0.0025，统一导出0.02网格；交付CSV采用0.005路线。独立原坐标也取0.005，再经T映射回正规形。比较使用同一时刻的共同导出网格；guard末点不同时间不放进状态误差，末时刻差单列在 [step-errors.csv](results/step-errors.csv)。

| 核对对象 | 当前观测 | 能支持的结论 |
| --- | --- | --- |
| 三条完整理想轨迹与正文解析解 | 最大尺度状态差≤6.70×10⁻¹⁰ | 指定初值/参考/参数的RHS与积分实现一致。 |
| 原坐标积分后映射 vs 正规形积分 | 所有共同网格最大差≤1.25×10⁻¹⁰ | 两条不同坐标的有限实现吻合；它们仍共用RK4，未冒充独立算法。 |
| J_T f_original vs f_normal | 同状态/实际输入最大差≤5.05×10⁻¹⁵ | 当前导出点验证变换后的对象导数。 |
| 饱和缩步状态差0.005 vs0.0025 | 约6.50×10⁻⁷；guard时刻差约1.65×10⁻⁷τ | 限幅折点与事件的有限数值误差；没有用光滑阶数硬套折点。 |
| 初始奇点 | 一行、状态initial_singular_stop | 明确拒绝执行无定义反馈。 |

数学解析基准是外部模态p=2y+s、q=y+s，零目标下p=p₀e⁻τ、q=q₀e⁻²τ，内部η由一阶受迫方程积分得到。跟踪例先把参考及其一阶导数从(y,s)减去，再算p/q；内部解析包含正弦受迫项。源码 `analytic` 与正文交出相同可手算解，源码 `safe_bound` 则重新计算全时请求充分界。一般相对阶/零流形结论没有从CSV拟合出来。

独立核查者可以用自选自适应RK45/Cash–Karp或高阶Taylor积分原式(10)，用新的事件定位路线，与交付0.02网格和终止时间比较；还应直接重算Lie导数、Jacobian行列式、内部解析及请求界。若使用本文源码复建，只能叫复现；若另写积分器，还要说清它仍共享哪些方程或解析基准。改变条件的任务与可核答案在 [[控制论/10-系统课程/16-反馈线性化相对阶与零动态#撤去方法提示，检查隐藏责任|正文末尾]]，包含σ=0、另一初值/上限、零流形限幅失效、换输出η后的相对阶3。

可执行的条件变化入口：复制input.json到新文件，把 `time_scale_s` 改为2，横轴应在同一τ结果下变成双倍秒数；把公共初值改为[0.08,−0.02,0.01]可重算输出模态与内部解；把 `actuator_limit` 改为0.5，minimum/tracking仍要重新通过充分界、饱和事件会提前或改变。运行输出用新目录。程序拒绝非有限参数、未对齐网格、错误case语义或无法证明保护例请求上限；拒绝不等于数学上一定不能控制。

## 证据接口与外推边界

一般定义/正规形的原始依据为 Al Hokayem与Gallestey [ETH作者讲义](https://people.ee.ethz.ch/~apnoco/Lectures2018/NLSC_lecture_notes_2018.pdf) §6.2（Definition6.4、Theorem6.7、零动态，PDF索引113–119）；局部/全局区别参见§6.4及Remark6.14（索引122–123）。正文三状态合成对象、反例与幅度界是显式推导，可直接逐式复算。

本包没有硬件、采样保持、估计器、实时执行或真人理解证据。若接实际设备，记录原状态/端口物理尺度、模型误差、参考产生和所需导数、状态获取、真实施加输入、时间戳、饱和/域事件及原始数据；然后重新证明相应可实现域与闭环条件。这个接口不作为理论审阅等待项。
