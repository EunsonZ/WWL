# 模板不是文本替换：推导、重载和约束的逐步分析

> **学习位置**：[[计算机知识/00-开始/课程地图/02-C++-课程地图|C++课程地图]] · **适用边界**：C++20；ABI、容器实现与后续标准不混同。

## 从一个泛型函数开始

```cpp
template<class T>
T twice(T value) { return value + value; }
```

编译器从调用推导 `T`，检查表达式是否成立，再形成相应实例。它不是把源代码字符串直接替换一遍的宏。不同类型实例可能生成多份机器码，也可能被优化合并；泛型抽象不保证没有编译成本或代码体积成本。

传值推导通常去掉顶层 const 和引用；传引用时保留更多限定信息。数组传值参数常发生退化，而 `T(&)[N]` 可以保留数组长度。遇到推导疑问时，先写出参数模式，再把实参类型和值类别代入，不要只凭 `auto` 外观猜测。

## 转发引用与引用折叠

在适当的模板推导语境中，`T&&` 是转发引用。传左值 `int x` 时，`T` 可以推导为 `int&`，折叠后参数为 `int&`；传右值时，`T` 为 `int`，参数为 `int&&`。规则可记为“组合中只要出现左值引用，折叠结果通常是左值引用；两个右值引用才折叠为右值引用”。

```cpp
template<class F, class... Args>
decltype(auto) invoke_logged(F&& f, Args&&... args) {
    return std::forward<F>(f)(std::forward<Args>(args)...);
}
```

示例省略日志，重点是用 `forward` 恢复调用者提供的值类别。`std::move` 无条件把表达式转向可移动类别，而 `forward<T>` 依赖推导得到的 `T`。不是所有 `T&&` 都是转发引用：`const T&&` 或已经固定类型的类模板成员参数需要另行分析。

## `auto`、`decltype` 和悬空返回

`auto x = expr` 通常按值推导；`auto&` 明确引用；`decltype(expr)` 依据表达式形式和值类别确定结果，尤其 `decltype(x)` 与 `decltype((x))` 对未加括号名字可能不同。`decltype(auto)` 常用于保留返回表达式的精确类型，但也更容易把局部对象的引用返回出去。

泛型封装不能只问“是否避免复制”，还要问“保留下来的引用活多久”。零拷贝但悬空的接口不是优化，而是失去正确性。

## 重载决议先判断能否调用，再比较优劣

概念上可以分为候选查找、模板推导与替换、可行性判断、转换序列比较、模板及约束相关排序。隐式转换构造函数可能扩大候选集合，因此单参数构造通常要考虑 `explicit`，避免一个整数无意变成资源拥有对象。

ADL 会根据实参关联的类型和命名空间寻找函数，它使某些泛型扩展自然成立，也可能引入意外候选。公共头文件避免大范围 `using namespace`，减少名称污染。依赖名、两阶段查找、`typename` 与 `template` 消歧是读大型模板库的必备知识，不宜只记报错后加关键词的经验。

## Concepts 改善接口表达，但不自动证明语义

```cpp
#include <concepts>
template<std::integral T>
T increment(T value) { return value + 1; }
```

这个约束拒绝非整数类型，但并不证明 `value+1` 不溢出。要求某个 `operator<` 存在，也不等于证明它满足严格弱序。语法约束由编译器检查，代数规律和资源协议仍需要设计、文档与测试。

C++20 的 `requires` 表达式可以说明一个表达式存在、返回类型满足条件、某操作不抛出等。对老代码，需要理解 SFINAE 和 `enable_if`，但新接口不必为了“高级”故意写更难懂的替换失败技巧。

## 泛型的组织边界

模板定义通常需要在实例化点可见，因此常放头文件；显式实例化可以控制实现暴露和代码生成，但减少可自由实例化的类型集合。类模板支持偏特化，函数模板通常借助重载而不是函数偏特化；参数包与折叠表达式用于表达可变数量操作。

`constexpr` 允许在满足条件时进行常量求值，不保证每次调用都发生在编译期；`consteval` 要求相应调用进行即时常量求值；`constinit` 约束静态或线程存储对象的初始化，不等于对象之后不可修改。

## 练习与答案

函数 `template<class T> void f(T&&)` 分别接收 `int` 左值、`const int` 左值和临时整数，参数最终分别是 `int&`、`const int&`、`int&&`。在函数体中直接使用参数名，三个表达式仍都是左值；只有显式转发才恢复原始分类。

设计一个支持“任何可以相加类型”的 `sum`，为什么还需要指定初始值和溢出策略？类型可加只证明语法成立，不确定零元素结果、单位、结合律、精度和数值边界。泛型越广，语义契约越不能省略。
