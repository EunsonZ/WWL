# 网络：以太网、Wi-Fi、交换与链路边界

> 阅读定位：协议以明确 RFC 为依据；模型例题注明假设。返回 [[计算机知识/00-开始/课程地图/09-计算机网络-课程地图|计算机网络 · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## 交换机为什么不等于路由器

二层交换机根据收到帧的源 MAC 学习“这个地址在哪个端口”，再按目标 MAC 查表转发。未知单播和广播可能被泛洪到相关端口。表项会老化，拓扑环路还可能令帧持续循环，所以需要适当的环路控制机制。路由器则根据网络层目的地址和路由表选择下一跳，不只是“大号交换机”。

现代交换式全双工以太网与早期共享介质碰撞域不同，不能用 CSMA/CD 解释所有当代以太网吞吐。Wi-Fi 共享无线介质，有碰撞避免、退避、确认和隐藏终端等问题；信号满格不代表没有争用和重传。

## VLAN 是逻辑广播域，不是完整安全策略

VLAN 可以把同一交换基础设施划分为多个二层域，trunk 携带标签区分流量。跨 VLAN 通信通常需要三层转发。错误的端口配置、允许列表和管理平面仍会破坏预期边界；“划了 VLAN”不自动等于完成认证、加密和最小权限。

广播发现适用于局部范围，规模扩大后广播成本、地址表与故障域都要考虑。STP 类机制防止某些二层环路，但收敛、冗余利用和具体部署还受协议与设备配置影响。

## ARP 解决的是本跳地址，不是域名

IPv4 主机先用目的 IP 与本机前缀判断是否直接交付。若目标不在本地链路，帧的目的 MAC 通常是网关的 MAC，而 IP 目的地址仍是最终远端。ARP 用于获得相应本地 IPv4 下一跳的链路地址；IPv6 使用邻居发现等机制，不是简单继续用 ARP。

例如主机 `192.0.2.10/24` 访问 `198.51.100.20`：主机通常解析网关 MAC，把远端 IP 分组交给网关。每经过一个路由跳，本地帧可能被重新构造；不是从源机器一直拿同一张以太网帧穿越整个互联网。

## 错误检测不等于真实性验证

奇偶校验、Internet checksum 和 CRC 的数学结构与检测能力不同。CRC 擅长检测相应错误模式，但攻击者可重新计算它，不能提供密码学完整性和身份认证。链路确认也只说明本跳接收情况，不等于应用处理完成。

## 扩展与练习

至少了解 MTU、jumbo frame、链路聚合、广播/组播、全双工/半双工、无线接入认证、漫游、功率与信道干扰。练习画出两个子网间一个分组每跳的 IP 与 MAC，指出哪部分变化、哪部分通常保持，以及 NAT 出现后又改变什么。只有在受控实验网络中修改 VLAN 和路由，不对现用网络盲目套命令。
