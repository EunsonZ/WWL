# 01 · 编译、链接与 CMake

## 本课目标

把“编译失败”分成可检查的阶段：预处理展开文本，编译器把一个翻译单元变成目标文件，链接器解析跨文件符号并生成可执行文件或库。CMake 不替代编译器；它生成或驱动底层构建系统。

本课只讲“怎样调用并观察现成的 C++ 工具链”。若要继续追问词法、语法、语义分析、IR、优化和代码生成内部怎样工作，请进入 [[计算机知识/70-编译原理/00-编译原理-MOC|编译原理 MOC]]；两门课共享构建产物，但不重复维护同一套理论。

## 第一个 target

<!-- code-sync: ./toolchain.cpp -->
```cpp
#include <iostream>

int main() {
    std::cout << "C++ compiler, linker, and CMake agree.\n";
}
```

对应的课程级构建描述是同目录的 `CMakeLists.txt`：

<!-- code-sync: ./CMakeLists.txt -->
```cmake
cmake_minimum_required(VERSION 3.20)
project(cpp_learning_examples LANGUAGES CXX)

include(CTest)

set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)
set(CMAKE_EXPORT_COMPILE_COMMANDS ON)

function(enable_course_warnings target)
  if(MSVC)
    target_compile_options(${target} PRIVATE /W4 /permissive-)
  else()
    target_compile_options(${target} PRIVATE -Wall -Wextra -Wpedantic)
  endif()
endfunction()

foreach(example IN ITEMS toolchain types_functions lifetime raii stl move errors concurrency layout)
  add_executable(${example} ${example}.cpp)
  enable_course_warnings(${example})
  if(BUILD_TESTING)
    add_test(NAME ${example} COMMAND ${example})
  endif()
endforeach()

find_package(Threads REQUIRED)
target_link_libraries(concurrency PRIVATE Threads::Threads)
```

先用 `cmake --version` 和目标编译器的版本命令确认二者确实存在；缺少 CMake 与“CMake 存在但找不到 C++ 编译器”是两类不同问题。确认工具后，在本目录运行：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --target toolchain
./build/toolchain
```

预期输出为 `C++ compiler, linker, and CMake agree.`。如果 CMake 命令本身不存在，先回到当前平台经审阅的工具链安装说明；如果配置阶段找不到编译器，再记录 `cmake --system-information` 中的候选编译器路径。不要用修改系统默认编译器或全局 include/lib 路径的方式碰运气。

## 诊断顺序

1. **配置失败**：CMake 找不到编译器、依赖或生成器；读首次报错及 cache 中实际选到的工具。
2. **编译失败**：单个 `.cpp` 的类型、头文件或语法有问题；错误位置通常在源文件。
3. **链接失败**：声明存在但定义没有参与目标、库顺序错误、ABI 不兼容；检查 target 的源文件和 `target_link_libraries`。
4. **运行失败**：程序启动后才出现；用测试、调试器和 sanitizer，而不是继续改 CMake。

配置后打开 `build/compile_commands.json`，能看到每个翻译单元实际使用的编译器、标准、include 路径和选项。它比“我记得 CMake 应该这样编译”更可靠。`PUBLIC`、`PRIVATE`、`INTERFACE` 描述的是依赖使用要求怎样沿 target 图传播，不是源文件访问权限：一个库的公共头文件若依赖另一个库的头文件，相关 include/链接要求往往要公开传播；只影响本库实现的依赖应保持 `PRIVATE`。

> [!note] 单配置与多配置生成器
> `-DCMAKE_BUILD_TYPE=Debug` 对 Ninja/Unix Makefiles 这类单配置生成器生效；Visual Studio、Xcode 等多配置生成器通常在构建/测试时用 `--config Debug` 选择配置。判断方式是看 CMake 配置摘要和生成器，而不是假定所有平台产物都位于同一目录。

> [!warning] 不要用全局 include/lib 路径掩盖依赖
> CMake target 应显式声明自己的 `target_include_directories`、编译特性和链接依赖。能在你电脑上“偶然找到”的头文件，不是可复现构建。

## 练习与成功标准

在 `toolchain.cpp` 中将输出改成你的短消息，重新构建指定 target；再从 `build/compile_commands.json` 找到它的完整编译命令。成功标准：只改源文件时 CMake 自动只重编该 target，命令包含 C++20 与本课 warning 选项，且删除 `build/` 后重新配置仍可完成。链接、加载与 ABI 的下一层解释见 [[计算机知识/30-计算机系统/03-ABI调用约定与静态动态链接|ABI、调用约定与静态/动态链接]]。
