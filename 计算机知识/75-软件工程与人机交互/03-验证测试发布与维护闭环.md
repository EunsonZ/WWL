# 验证测试发布与维护闭环：每条证据只回答一个范围

**读者问题：预约测试全部通过，为什么仍要有发布门和维护记录？** 测试给出的是固定规格、实现、输入与环境下的证据。软件交付还要问规格是否解决任务、组件组合是否符合承诺、失败后能否恢复；这些问题不能相互代替。

## 先独立设计预期，再运行实现

本课源码 [reservation.py](reservation.py)实现不可变预约记录与顺序内存状态，测试 [test_reservation.py](test_reservation.py)读取需求课的区间规则。实现用两个端点不等式判断重叠；测试的小规模oracle枚举被占用的分钟集合，比较集合交集，避免用相同公式抄出预期。oracle仍依赖同一规格；若半开区间政策本身选错，两者一起通过也无法发现。

| 证据 | 实际检查的命题 | 不能推出什么 |
| --- | --- | --- |
| 固定边界例 | 邻接通过、交叠拒绝、非法类型拒绝 | 所有输入和所有策略正确 |
| 有限枚举oracle | 09:00后四个候选区间两两组合的接受结果符合分钟占用模型 | 连续时间、跨日、数据库隔离正确 |
| 顺序状态性质 | 创建失败不写入；取消释放；旧快照不受后续操作改变 | 网络重试幂等、真实认证或并发安全 |
| 独立功能验收 | 从需求而非实现列出未满足项 | 人理解界面、团队协作完成 |

源码与逐字镜像在[[计算机知识/75-软件工程与人机交互/81-预约模型源码测试与原型镜像|源码测试和原型镜像]]一起交接。Python测试课已解释性质、差分、mock与测量，本页只把这些证据映射到预约承诺，不再复制那套课程。

```mermaid
flowchart LR
    R[规格及风险] --> T[独立预期与失败样本]
    T --> I[实现与组合验证]
    I --> G[按风险决定发布]
    G --> O[运行观察及事件]
    O --> R
```

## 发布门与故障表必须针对具体承诺

若交付范围只是课内模型，输入/状态测试及镜像一致即可支持“可运行教学模型”。若范围是供人预约的服务，还需认证、持久化、并发冲突、恢复、客户端和任务验收；它们未实现时应保留未完成，而非删去需求变绿。

| 故障点 | 期望行为与检查方法 | 本切片状态 |
| --- | --- | --- |
| 冲突检查抛错前后 | 拒绝不改变活动预约；比较前后快照 | 有标准库测试 |
| 两请求同时占同区间 | 最多一个提交；实际数据库双会话验收约束/锁/重试 | 未实现、未执行 |
| 已提交但响应丢失 | 同意图重放原结果；界面保持未知状态直到确认 | 有合同提案，未实现 |
| 通知重复/积压 | 同事件id不重复产生不可逆效果；积压报警 | 有架构分析，未实现 |
| v2迁移后降版本 | 保留v2数据与规则，禁止旧写路径违反缓冲 | 有变更演练题，未部署 |

验证“按规格实现”可以发现程序错误；确认“规格满足人的任务”需要用户与利益相关者证据。一个人写代码、模型审核、自动测试不能证明团队沟通与真实用户验收。

## 从事件返回可复现改进

模拟维护事件：用户投诉“按取消后还能看到预约”。先分开服务器实际状态、旧客户端缓存和通知副本；收集预约id、相关时间、规则/服务/客户端版本及已脱敏状态，不索取咨询原因。教学假设复现为旧响应覆盖新状态。修复可采用版本条件/请求序号，补“旧响应晚到”的组合回归，并验证有权取消和失败反馈仍成立。责任人向受影响者说明范围与恢复；这不是现实事故记录。

维护类型不同：纠错修当前缺陷；适应变化如服务开放时段；完善如减少操作；预防如减小模块耦合。名称本身不决定优先级：预约错位导致到场失败，可比“新增日历视图”优先。给每个问题一个能复现的输入、预期、实际、影响与关闭证据，避免把“已提交修复”写成“已恢复”。

## 练习与答案

测试只断言创建后记录数加一，删掉重叠校验仍全部通过。应增加什么？答案是需求R2的正反例与独立oracle，再试已知错误变体以验证测试能拒绝它；记录数不是“不冲突”的证据。反例是把所有网络调用mock成成功：测试会通过，但响应丢失和提交失败从未出现。

## 电子电路往返：测试证据、热状态与寿命条件

去 [[电子电路/54-制造可靠性与生命周期/02-制造故障与生产测试#覆盖率的分母与漏检的条件概率|制造测试的故障宇宙]]，带有限模型故障集合F、测试检测子集D、真实缺陷基率d及条件灵敏度s。软件分支覆盖与硬件stuck-at覆盖都要先说分母，但分支不是物理缺陷；100%可测模型覆盖不自动成为100%实际出货可靠性。回本页用规格之外的独立故障注入/观察条件设计验证，再回电子页核测试端口、治具、电压温度及采样窗口，DFT改变物理可控可观通道，不只是增加软件用例。

寿命概率另有对象。去 [[电子电路/54-制造可靠性与生命周期/04-热可靠性与失效机理#寿命分布与尚未失效的样本|非修复寿命与删失]]，定义τ为失效时间（h），S(t)=P(τ>t)，h(t)=f/S（h⁻¹）。只有常危险率λ模型才有S=e⁻λt、MTTF=1/λ；零失败不是λ确为0。温度模型的P（W）、θ（K）、Rθ（K/W）、Cθ（J/K）给热状态，不直接给寿命年数；去 [[电子电路/54-制造可靠性与生命周期/04-热可靠性与失效机理#从温度到失效，需要机制和标定|机制与温度加速]] 保留绝对K、激活能及同机制标定范围。循环疲劳的次数也不能当秒。[NIST指数寿命模型](https://www.itl.nist.gov/div898/handbook/apr/section1/apr161.htm) 与 [Arrhenius模型](https://www.itl.nist.gov/div898/handbook/apr/section1/apr151.htm) 是这些条件的原始对照，教学数值不是器件认证。

版本追溯还需去 [[电子电路/54-制造可靠性与生命周期/06-版本BOM维护与可持续性#追溯是一个带版本的关系|BOM、批次与实物]]：同固件字节可以装在不同BOM/批次板上。软件回滚不还原焊接/物料的物理历史；替代批准表不能改写已安装事实。返回本页发布门记录精确需求、实现、测试和实物版本，按差异复用未受影响证据，补受影响的热/时序/保护观察；通过Python有限模型不等于实物测试完成。

**迁移1。** 常危险率教学λ=.001 h⁻¹，100 h可靠度多少？若10个器件100 h内零失败，能直接把实际λ改0吗？**答案：** 在该模型下S=e⁻.1≈.904837；零失败只有有限曝光证据，不排除小正λ，不能宣称无限寿命。若高温换了失效机制，也不能用旧激活能把测试小时无条件折算使用年数。

**迁移2。** 12个原始故障中10可测且全部检出，换“同值”电容后预约式软件回归全过，能写“新BOM全覆盖且热寿命已验证”吗？**答案：** 可测覆盖10/10、原始覆盖10/12需同时披露；软件回归未观察偏压容量/ESR、环路、热路或真实缺陷总体。保留旧实物记录、新增BOM差异与受影响回归，实际未测项仍未知；给出有界足够测试目标并解释缺陷分布也可，不能靠名称转移信用。
