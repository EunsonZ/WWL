# 转封装、转码、裁剪与客观对比

## 目标与预测

脚本先生成 FFV1 + PCM 的近乎无损 NUT 参考文件，再完成三条不同路径：`-c copy` 转封装到 Matroska；重新编码为 H.264 + AAC；从 1 秒处截取 1.5 秒并做 160×120 的空间裁剪。运行前先预测哪一步会解码/编码、哪一步改变像素、哪一步只改变容器。

理论入口：[[计算机知识/60-数据编码与媒体系统/10-封装格式Codec-Container-Mux-Demux|Codec、Container、Mux 与 Demux]]、[[计算机知识/60-数据编码与媒体系统/14-FFmpeg常用转码裁剪拼接字幕与音频处理|FFmpeg 常用操作]]。

## 运行源码

在本目录执行 `bash ./02_transcode_compare.sh`。所有输入仍是合成媒体；PSNR/SSIM 只比较未裁剪、尺寸相同的参考视频与 H.264 视频。

<!-- code-sync: ./02_transcode_compare.sh -->
```bash
#!/usr/bin/env bash
set -euo pipefail

for tool in ffmpeg ffprobe; do
  if ! command -v "$tool" >/dev/null 2>&1; then
    printf 'SKIP: %s is not available in PATH\n' "$tool" >&2
    exit 77
  fi
done

if (( $# > 1 )); then
  printf 'usage: %s [new-output-directory]\n' "$0" >&2
  exit 64
fi

if (( $# == 1 )); then
  output_dir="$1"
  [[ -n "$output_dir" && "$output_dir" != / && ! -e "$output_dir" ]] || {
    printf 'refusing existing or unsafe output directory: %s\n' "$output_dir" >&2
    exit 73
  }
  [[ -d "$(dirname -- "$output_dir")" ]] || {
    printf 'output parent does not exist\n' >&2
    exit 73
  }
  mkdir -- "$output_dir"
else
  temp_base="${TMPDIR:-/tmp}"
  temp_base="${temp_base%/}"
  output_dir="$(mktemp -d "$temp_base/workwithllm-ffmpeg-compare.XXXXXX")"
fi

output_dir="$(cd -- "$output_dir" && pwd -P)"
printf '%s\n' 'WorkWithLLM FFmpeg comparison lab' > "$output_dir/.lab-marker"

source_media="$output_dir/source-lossless.nut"
remuxed_media="$output_dir/remuxed.mkv"
compressed_media="$output_dir/transcoded.mp4"
cropped_media="$output_dir/trimmed-and-cropped.mp4"
for path in "$source_media" "$remuxed_media" "$compressed_media" "$cropped_media"; do
  [[ ! -e "$path" ]] || {
    printf 'refusing to overwrite: %s\n' "$path" >&2
    exit 73
  }
done

ffmpeg -hide_banner -loglevel warning -nostdin -n \
  -f lavfi -i 'testsrc2=size=320x240:rate=25:duration=4' \
  -f lavfi -i 'sine=frequency=660:sample_rate=48000:duration=4' \
  -map 0:v:0 -map 1:a:0 -c:v ffv1 -level 3 -c:a pcm_s16le \
  -shortest "$source_media"

ffmpeg -hide_banner -loglevel warning -nostdin -n \
  -i "$source_media" -map 0 -c copy "$remuxed_media"

ffmpeg -hide_banner -loglevel warning -nostdin -n \
  -i "$source_media" -map 0:v:0 -map 0:a:0 \
  -c:v libx264 -preset veryfast -crf 30 -pix_fmt yuv420p \
  -c:a aac -b:a 64k "$compressed_media"

ffmpeg -hide_banner -loglevel warning -nostdin -n \
  -i "$source_media" -ss 1 -t 1.5 \
  -map 0:v:0 -map 0:a:0 -vf 'crop=160:120:80:60' \
  -c:v libx264 -preset veryfast -crf 23 -pix_fmt yuv420p \
  -c:a aac -b:a 64k "$cropped_media"

ffmpeg -hide_banner -loglevel info -nostdin \
  -i "$source_media" -i "$compressed_media" \
  -filter_complex \
  "[0:v]split=2[refp][refs];[1:v]split=2[distp][dists];[refp][distp]psnr=stats_file=$output_dir/psnr.log[p];[refs][dists]ssim=stats_file=$output_dir/ssim.log[s]" \
  -map '[p]' -map '[s]' -f null /dev/null \
  2> "$output_dir/metrics-summary.log"

for path in "$source_media" "$remuxed_media" "$compressed_media" "$cropped_media"; do
  base="$(basename -- "$path")"
  ffprobe -v error -show_format -show_streams -of json "$path" \
    > "$output_dir/$base.probe.json"
  bytes="$(wc -c < "$path" | tr -d ' ')"
  printf '%s bytes=%s\n' "$base" "$bytes"
done

printf 'PASS: outputs=%s\n' "$output_dir"
printf 'objective-metrics=%s\n' "$output_dir/metrics-summary.log"
```

## 如何读结果

先比较四份 `*.probe.json`：NUT 与 Matroska 中的 `codec_name` 应保持 FFV1/PCM，这支持 `-c copy` 未重编码；MP4 变为 H.264/AAC；裁剪结果应约 1.5 秒且视频为 160×120。再看终端的字节数和 `metrics-summary.log` 末尾的 PSNR/SSIM summary。

PSNR 与 SSIM 是在固定参考、对齐帧和同尺寸下计算的客观差异指标，不等于人类主观质量，也不能跨内容直接推出某个 CRF 的普遍质量。音频没有在本例中计算质量指标。文件更小也不自动表示编码更高效：参考文件使用了不同 codec 和目标。

本机 2026-09-03 使用 `ffmpeg/ffprobe 9.0.1` 真实完成 4 秒 FFV1/PCM 生成、NUT→Matroska stream copy、H.264/AAC 转码、时空裁剪及 PSNR/SSIM 计算。未测试硬件编码器、字幕、拼接、VMAF、可变帧率真实素材或损坏输入。

## 练习、成功标准与恢复

把 H.264 的 CRF 从 30 改为 20，在一个全新目录运行，比较文件大小、PSNR 与 SSIM；只对这两个同源输出作局部结论。

- [ ] 能用 codec 字段证明 remux 保持码流类型，而不是只看扩展名；
- [ ] 能用 duration 与尺寸证明时间截取和空间裁剪生效；
- [ ] 能同时报告 CRF、preset、输入、大小与指标，不把单个数当成普遍排名；
- [ ] 已有输出目录被拒绝，没有使用 `-y`。

恢复方式见 [[计算机知识/80-实践/07-媒体编码与FFmpeg/00-媒体编码与FFmpeg实践-MOC#完成标准与恢复|统一恢复边界]]。
