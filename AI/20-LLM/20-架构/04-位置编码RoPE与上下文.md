# 位置编码、RoPE 与上下文

<!-- deep-review-02 -->
> [!tip] 本轮深化：从当前概念继续追问
> RoPE 的相对位置等式要求固定内容向量与频率规则；它不保证整个模型任意平移不变，也不保证距离增大时相似度单调下降。缓存续写还需真实位置偏移。 深化与验证：[[AI/20-LLM/20-架构/11-RoPE相对位置缓存偏移与长度外推|RoPE相对位置缓存偏移与长度外推]]；[[AI/20-LLM/20-架构/12-MLA线性注意力与状态空间的记忆取舍|MLA线性注意力与状态空间的记忆取舍]]。


内容相同、顺序不同的句子可能含义完全不同。单靠 Q/K 的内容点积，没有显式的“相隔几步、谁在前谁在后”信号；causal mask 只规定不能读未来，也没有告诉模型两个过去 token 相隔 1 步还是 1000 步。位置方法的任务，就是把顺序和距离结构带进注意力。

本课重点是 RoPE，以及它和上下文长度、KV cache、外推证据之间的边界。目标不是记某一代模型的配置值，而是建立可以检查任何 checkpoint 的方法。

> [!abstract] 本课目标
> 完成后你应该能：
>
> - 区分绝对位置向量、相对位置偏置和 RoPE 的作用位置；
> - 解释 RoPE 的二维旋转、shape 不变量和相对位移关系；
> - 分开“数学可计算位置”“配置允许长度”“训练覆盖长度”和“评测可靠长度”；
> - 为上下文扩展设计包含质量、边界和资源成本的证据链；
> - 识别 position id、padding、cache 复用与 RoPE 配置不一致的失败模式。

## 1. 位置方法在回答不同问题

| 方法族 | 典型做法 | 信息进入哪里 | 需要注意的边界 |
| --- | --- | --- | --- |
| 学习式绝对位置 | 为位置 `p` 查一个向量并加到 token 表示 | attention 前的 hidden state | 表长通常是显式上限；超出后没有已学向量 |
| 固定正弦/余弦位置 | 用多频率函数产生位置向量并相加 | attention 前的 hidden state | 公式可延长，但可靠外推仍需评测 |
| 相对位置 bias | 按 query-key 距离向 score 加偏置 | attention score | 分桶、截断和方向约定决定远距离行为 |
| RoPE | 按位置旋转 Q/K 的二维特征对 | Q/K 点积之前 | 频率、配对布局、旋转维度与缩放都是 checkpoint 契约 |

这些方法不是只要贴上名字就完全确定。即使都称为 RoPE，也可能在频率基数、只旋转部分 head 维、二维配对方式、position id 和长上下文缩放上不同。

## 2. RoPE：把特征两两看成小指针

设一个 attention head 的 query/key 维度为 `D_h`，取其中偶数个维度 `D_rope` 两两配对。第 `j` 对是二维向量，位置 `p` 让它旋转角度：

$$
\phi_{p,j}=p\,\theta_j.
$$

旋转矩阵为：

$$
R(\phi)=
\begin{bmatrix}
\cos\phi&-\sin\phi\\
\sin\phi&\cos\phi
\end{bmatrix}.
$$

于是：

$$
\widetilde q_{p,j}=R(p\theta_j)q_{p,j},
\qquad
\widetilde k_{p,j}=R(p\theta_j)k_{p,j}.
$$

RoPE 通常不作用于 V。它也不改变张量 shape：

$$
Q,K:\ B\times H\times T\times D_h
\longrightarrow
\widetilde Q,\widetilde K:\ B\times H\times T\times D_h.
$$

二维旋转保持每对特征的长度；它改变的是方向以及之后的 Q-K 点积关系。

## 3. 为什么点积出现相对位移

位置 `m` 的 query 与位置 `n` 的 key，在第 `j` 个二维块上的点积满足：

$$
\widetilde q_{m,j}^{\mathsf T}\widetilde k_{n,j}
=q_{m,j}^{\mathsf T}R((n-m)\theta_j)k_{n,j}.
$$

这条关系说明：两边各自用了绝对位置角 `mθ_j`、`nθ_j`，但点积里显式出现的是相对位移 `n-m`。完整推导和假设见数学权威页，本页关注它没有证明的事情：

- 它没有证明模型会自动学会所有长距离算法；
- 它没有证明任意大的位置都与训练分布相似；
- 它没有证明有限精度实现对任意大角度都同样准确；
- 它没有决定 causal、padding 或窗口可见性，这些仍由 mask 控制。

### 一个二维数值例

令基础 query 与 key 都是 `(1,0)`，频率 `θ=π/2`。

- query 在位置 `m=1`，旋转后为 `(0,1)`；
- key 在位置 `n=3`，旋转后为 `(0,-1)`；
- 二者点积为 `-1`。

相对位移是 `n-m=2`，对应相对旋转角 `π`，把 `(1,0)` 转为 `(-1,0)`，点积同样为 `-1`。这个例子只展示恒等关系，不代表实际模型只有一个频率或二维 head。

## 4. 多频率为什么重要

一种常见的逆频率形式是：

$$
\theta_j=\text{base}^{-2j/D_{rope}},
\qquad j=0,1,\ldots,D_{rope}/2-1.
$$

不同 `j` 像转速不同的钟：高频块对短距离变化敏感，低频块在更长范围内缓慢变化。模型可以组合多个尺度的旋转特征。

但是上式只是一个常见约定。真实 checkpoint 还可能指定：

- `base` 或等价的 `rope_theta`；
- 旋转全部还是部分 head 维；
- 相邻配对还是前后半轴交错配对；
- position id 从哪里开始、padding 是否占编号；
- 是否采用位置、基数、频率或分段缩放；
- attention score 是否还有额外缩放。

这些配置必须与训练时和权重预期一致。只加载权重而错用 RoPE 约定，shape 仍会全部正确，但数值语义已经错位。

## 5. “上下文长度”至少有四层含义

| 层次 | 它回答什么 | 单独能证明什么 |
| --- | --- | --- |
| 数学/算子可计算 | 位置函数和内核能否接受位置 `p`？ | 只能证明没有立即越界或拒绝 |
| 配置/服务允许 | 配置和运行时最大接受多少 token？ | 证明接口上限，不证明模型质量 |
| 训练覆盖 | 训练或继续训练见过怎样的长度分布？ | 提供分布依据，但不自动覆盖所有任务 |
| 评测可靠 | 在哪些长度、任务和指标上仍满足目标？ | 只对给定评测条件提供经验支持 |

所以“把配置从 4K 改到 32K”首先只是修改允许范围；“程序在 32K 不报错”只是可执行证据。只有训练方法、位置配置和分长度评测共同支持，才可以谈某个明确任务上的可用扩展。

> [!important] 上下文窗口还要说明 token 预算口径
> 有的接口把 prompt 与输出共享一个总窗口，有的服务还设置单独的最大输出、保留系统提示或工具结果。讨论“32K”时要问：tokenizer 是什么、输入多少、预计输出多少、服务端是否截断、滑窗或保留前后片段。

## 6. 为什么超过训练长度会失败

RoPE 公式可以为很大的 `p` 计算角度，但模型可能遇到多种分布外变化：

1. **未见过的相位组合**：各频率在更远位置形成训练中少见的联合模式；单个频率还具有周期性，不能把“能算 sin/cos”当作无限唯一位置编码。
2. **距离统计改变**：训练主要在短序列上，模型可能学会偏爱近邻或依赖固定位置习惯。
3. **任务本身更难**：从 4K 增到 32K 不只是位置数字变大，干扰项、检索候选和跨段依赖也显著增加。
4. **有限精度误差**：大位置乘频率、角度归约、sin/cos 和 cache dtype 都可能增加数值误差；具体影响依实现而定。
5. **系统限制**：KV cache、attention 计算、调度和服务端截断可能先于位置公式成为瓶颈。

因此“外推失败”不一定只有一种症状：困惑度可能逐步升高，检索可能在某些位置区间骤降，生成可能重复或忽略远处约束，也可能只是显存耗尽或延迟不可接受。

## 7. 上下文扩展方法：改变映射，不提供万能保证

常见思路可按“怎样把新位置映到旋转角”分类：

### 位置插值

把扩展后的 `p` 压缩为较小的有效位置，例如用 `p/s` 进入原频率公式。直觉是让新最大位置落回训练过的角度范围。代价是相邻位置的角差也被压小，局部分辨率和原有行为可能改变。

### 频率或基数缩放

调整 `θ_j` 的频率分布，使部分维度转得更慢；也可能按频率、位置或目标长度分段处理。不同方案对短距离保持、长距离分辨率和过渡区有不同取舍。

### 继续训练或长上下文微调

让模型实际接触扩展后的长度与位置配置，通常比只改配置提供更强证据。但效果仍取决于长数据质量、长度采样、优化预算和评测覆盖。

这些类别故意不绑定某个易过时的库字段或模型版本。同名缩放在不同运行时可能有不同参数语义；应以 checkpoint 配置、训练说明和当前实现源码为准。

## 8. KV cache 与位置必须保持同一契约

在自回归 decode 中，每层会缓存历史 K/V。使用 RoPE 时，历史 K 必须以正确的位置语义参与以后每个 query 的点积。工程上要同时保证：

- position id 连续或符合架构定义；
- 新 query/K 使用与历史 cache 一致的频率和缩放；
- cache 的 token 顺序、窗口偏移和位置编号没有错位；
- 截断或 sliding window 后，逻辑位置是否重编号符合该实现契约；
- prefix/cache 复用时，token 内容、位置配置和模型权重完全兼容。

如果服务运行中更改 RoPE 缩放或 position-id 规则，已有 cache 通常应失效并重建。仅因 K/V 的 shape 没变就继续复用，会得到“能运行但注意力位置关系错误”的隐蔽故障。

KV cache 仍随可见长度线性增长：

$$
\text{cache elements}=2BLT_kH_{kv}D_h.
$$

所以位置公式允许 128K，不代表设备装得下相应 cache，也不代表读取 128K 历史的单 token 延迟可接受。头共享与字节估算见 [[AI/20-LLM/20-架构/02-注意力MHA-MQA与GQA|注意力、MHA、MQA 与 GQA]]。

## 9. Padding、packing 与 position ids

真实 batch 中序列长度不同，常见错误是让 padding 方式偷偷改变有效 token 的位置编号。

例如同一句 3-token 文本左侧补两个 pad：

- 若有效 token 的 position ids 仍应为 `0,1,2`，就不能简单把物理列号 `2,3,4` 无条件当位置；
- pad key 必须被 attention mask 屏蔽；
- 若只取“最后一列 logits”，要确认最后一列确实是每条序列的最后有效 token。

sequence packing 把多篇文档放进同一物理序列时，还要决定新文档 position id 是否重置、文档间是否可见，以及训练目标是否跨边界。position ids 正确而 document mask 错误，仍会发生跨样本信息泄漏。

## 10. 怎样验证长上下文声明

一个有说服力的验证不应只靠单次 “needle in a haystack”。建议形成下面的证据梯度：

1. **配置与实现核对**：tokenizer、最大输入/输出、RoPE 参数、position ids、mask、cache dtype 与内核都记录清楚；
2. **边界冒烟**：在上限前后测试，确认没有静默截断、位置回绕、OOM 或 cache 越界；
3. **长度分桶损失/困惑度**：观察从训练内到扩展区的退化曲线，而不是只报平均值；
4. **受控检索**：改变 needle 位置、数量、干扰项和答案格式，避免固定模板被猜中；
5. **组合任务**：测试多跳、跨段约束、长文摘要一致性和引用定位，而不只测原样复制；
6. **真实目标任务**：用实际文档长度与输出要求做回归，并检查事实性和遗漏；
7. **资源曲线**：同时记录首 token 延迟、decode 延迟、吞吐、峰值内存与并发条件。

至少报告训练内短长度、过渡长度、目标最大长度及临界边界。一个任务在 32K 成功，不能外推为所有 32K 输入都可靠；单个样本失败也要先排除截断、模板、token 计数和位置配置错误。

### 一个完整的声明模板

比“支持 32K”更可靠的表述是：

> 在指定 tokenizer、checkpoint、RoPE 配置和运行时下，服务接受总计不超过 32K token；模型在 4K/8K/16K/32K 的给定检索与真实任务集上达到所列指标。32K 之外未验证；prompt 与输出共享预算；资源曲线在指定硬件和 batch 下测得。

这个模板迫使“接口能力、模型质量和资源代价”同时出现。

## 11. 数值稳定与实现核对

RoPE 理论使用实数旋转，实现却使用有限精度：

- `p×θ_j` 的计算精度会影响大位置角度；
- sin/cos 的角度归约由数学库或 kernel 决定；
- Q/K 可能以较低精度存储，但角度或中间计算使用更高精度；
- 不同二维配对布局即使 shape 一样，也不能混用；
- cache 量化误差会在长历史读取中叠加到 score。

不能仅从 dtype 名称推断整条管线。要分别核对输入、角度计算、旋转乘加、cache 存储和 score 累加精度；数值概念见 [[数学/60-数值计算与量化/01-二进制浮点精度与数值稳定性|二进制浮点精度与数值稳定性]]，设备实现从 [[计算机知识/40-并行与异构计算/01-CUDA/00-CUDA-MOC|CUDA MOC]] 继续。

## 12. 常见失败模式

| 失败或误解 | 可见症状 | 可靠修正 |
| --- | --- | --- |
| 把 RoPE 加到 V | 位置语义与 checkpoint 不匹配 | 核对架构；常见 RoPE 只旋转 Q/K |
| 奇数个旋转维度或错误配对 | shape 可能过关，数值完全错 | 核对 `D_rope` 为偶数及配对布局 |
| position id 与 padding 列号混用 | 同一句随 padding 方式改变输出 | 为有效 token 构造符合契约的位置编号 |
| 更改缩放后复用旧 KV cache | 长对话突然重复、错位或退化 | 使 cache 失效，以统一配置重建 |
| 只提高 `max_length` | 程序接受长输入但质量下降 | 核对位置方案、训练覆盖并做长度分桶评测 |
| 只测一个 needle | 得到漂亮但脆弱的单点结果 | 改变位置、干扰、数量、措辞并加入真实任务 |
| 混淆字符数和 token 数 | 实际输入提前越界或被截断 | 用部署所用 tokenizer 现场计数 |
| 只报最大长度，不报输出预算 | prompt 占满后无法生成所需答案 | 明确总窗口、最大输出和服务保留项 |
| 只关注数学外推，不测资源 | 可算但 OOM 或延迟不可用 | 报告 cache、峰值内存和延迟随长度曲线 |
| 把相对位移恒等式当能力证明 | 过度声称“无限上下文” | 分开数学性质、训练分布和经验评测 |

## 13. 练习

### 练习 A：二维 RoPE

令 `q=(1,0)`、`k=(0,1)`、`θ=π/2`。

1. 分别计算 `m=0,n=1` 时旋转后的 q、k 与点积；
2. 用相对旋转 `R((n-m)θ)` 核对；
3. 交换 `m,n` 后，相对角怎样变化？这是否保证点积数值不变？

### 练习 B：审查 8 倍扩展

一个 checkpoint 主要在 4096 token 内训练。某运行时把最大长度改成 32768，并启用一种 RoPE scaling。写一张验收表，至少包含：

1. 必须固定和记录的配置；
2. 4K、8K、16K、32K 各测什么；
3. 怎样检查静默截断与输出预算；
4. 怎样报告 KV cache、延迟和 batch 条件；
5. 哪些结论即使测试通过也不能声称。

### 练习 C：找 cache 错位

服务先按缩放 A 完成 10K-token prefill，随后热更新为缩放 B，但保留原 cache 继续 decode。解释：

1. 为什么所有张量 shape 都可能仍然正确；
2. 为什么新 query 与历史 K 的位置语义不再一致；
3. 最小安全恢复动作是什么。

<details>
<summary>核对要点</summary>

- 练习 A：`q` 保持 `(1,0)`；位置 1 的 `k=(0,1)` 再转 90° 得 `(-1,0)`，点积为 `-1`。相对角为 `π/2`，可得到同一结果。交换位置使相对角变号，但同时 q/k 内容角色未必对称，不能笼统保证相同点积。
- 练习 B：答案应同时覆盖 tokenizer、权重、RoPE/position-id/mask/cache 配置，长度分桶的损失、检索与真实任务，以及资源曲线；不能声称无限长度或所有任务都无退化。
- 练习 C：缩放不改变 shape，却改变位置到角度的映射。旧 K 和新 Q 不再位于同一坐标约定；应清空并用统一配置重建 cache/prefill。

</details>

### 成功标准

- [ ] 我不会把配置上限、训练长度和可靠评测长度写成同一个数字。
