# 正则表达式速查表

> [!important] 使用前先确认
> 写明目标语言或工具、正则引擎与版本、标志（flags）、调用 API，以及本次是搜索、完整匹配、全部查找还是替换。下面是常见语义，不是所有引擎的永久统一规范。第一次运行可直接使用 [[编程知识/30-实践/01-正则表达式实验区/04-5分钟运行与测试模板|5 分钟运行模板]]。

## 字符与字符类

| 模式 | 常见含义 |
| --- | --- |
| `abc` | 字面文本 `abc` |
| `.` | 任意一个字符，默认常不含换行 |
| `\.` | 字面点号 |
| `[abc]` | `a`、`b`、`c` 中的一个 |
| `[^abc]` | 不是 `a`、`b`、`c` 的一个字符 |
| `[A-Z]` | 一个 ASCII 大写字母；前提是未用标志扩大 Unicode 大小写折叠 |
| `[0-9]` | 一个 ASCII 数字 |
| `\d` / `\D` | 数字 / 非数字，Unicode 范围依引擎 |
| `\w` / `\W` | 单词字符 / 非单词字符，定义依引擎 |
| `\s` / `\S` | 空白 / 非空白，定义依引擎 |

## 位置与边界

| 模式 | 常见含义 |
| --- | --- |
| `^` | 字符串或多行模式下的行开头 |
| `$` | 字符串或多行模式下的行结尾 |
| `\b` | `\w` 与 `\W` 之间，或字符串边缘与 `\w` 之间；`\w` 依引擎与标志 |
| `\B` | 非单词边界 |
| `\A` | 绝对开头；Python/PCRE 常见，JavaScript 提案与运行时支持须分开核验 |
| `\Z` / `\z` | 绝对结尾，拼写、语义和可用版本依引擎 |

2026-09-06 复核：JavaScript 的 Buffer Boundaries 仍为 Stage 3 提案；Node 22.16.0 的 Unicode 模式不接受 `\A`。实测与来源见 [[编程知识/10-基础/01-正则表达式/02-字符类边界与转义#锚点约束位置|锚点版本边界]]。

严格校验优先使用目标语言的完整匹配 API。Python 的 `$` 可以停在最终换行之前；不要只凭 `^...$` 四个字符就假设所有引擎的最终换行行为一致。

## 量词

| 模式 | 次数 |
| --- | --- |
| `x?` | 0 或 1 个 `x` |
| `x*` | 0 个或更多 `x` |
| `x+` | 1 个或更多 `x` |
| `x{3}` | 恰好 3 个 `x` |
| `x{3,}` | 至少 3 个 `x` |
| `x{3,5}` | 3 到 5 个 `x` |
| `x*?`、`x+?` | 常见回溯引擎中的惰性量词 |

量词只修饰前一个模式单元。重复整个片段时使用分组，例如 `(?:ab)+`。

## 分组与选择

| 模式 | 含义 |
| --- | --- |
| `(abc)` | 捕获组 |
| `(?:abc)` | 非捕获组 |
| `a\|b` | `a` 或 `b` |
| `\1` | 常见编号反向引用，支持度依引擎 |
| `(?P<name>...)` | Python 命名组 |
| `(?<name>...)` | JavaScript 等引擎的命名组 |

## 环视

| 模式 | 含义 |
| --- | --- |
| `(?=x)` | 后面必须是 `x` |
| `(?!x)` | 后面不能是 `x` |
| `(?<=x)` | 前面必须是 `x` |
| `(?<!x)` | 前面不能是 `x` |

环视通常不消费字符。后行断言的支持度和长度限制差异尤其大。

## 常见标志（flags）

| 意图 | Python | JavaScript |
| --- | --- | --- |
| 忽略大小写 | `re.IGNORECASE` | `i` |
| 多行锚点 | `re.MULTILINE` | `m` |
| 点号跨换行 | `re.DOTALL` | `s` |
| 全部查找 | `findall` / `finditer` | `g` |
| Unicode 相关语义 | Python 3 `str` 默认；`re.ASCII` 可收窄部分字符类 | `u` 或 `v`，具体能力依语法与版本 |
| 注释/扩展模式 | `re.VERBOSE` | 无直接内建同等标志 |

## 替换引用

| 环境 | 编号组 | 命名组 |
| --- | --- | --- |
| Python `re.sub` | `\g<1>` | `\g<name>` |
| JavaScript `replace` | `$1` | `$<name>` |
| 编辑器 | 常见 `$1` 或 `\1` | 必须查工具文档 |

## 设计顺序

1. 列正例、反例、边界例；
2. 确定搜索、完整匹配或全部查找；
3. 写稳定字面前缀与后缀；
4. 用具体字符类描述字段；
5. 加精确或有限量词；
6. 只在需要时加入捕获；
7. 再考虑交替、环视和反向引用；
8. 核对引擎、版本、标志、API 与替换语法；
9. 测试近似失败输入与长度上限；
10. 记录已知限制和解析器（parser）/ 字符串 API 替代方案。

## 排错顺序

- 表达式是否被宿主字符串再次转义？
- 使用的是搜索还是完整匹配 API？
- `g`、`m`、`s`、`i`、`u`、`v` 等标志是否正确？
- JavaScript 是否在复用带 `g` / `y` 的 `RegExp.test()`，从而受 `lastIndex` 影响？
- 量词到底修饰哪个单元？
- `|` 的左右分支是否都受到锚点约束？
- 点号是否意外跨行或没有跨行？
- `\d`、`\w`、`\b` 的 Unicode 语义是否符合预期？
- 替换模板引用组的语法是否属于目标工具？
- 是否从更长字段中意外截取了一部分？
- 是否有嵌套量词、重叠分支或无上限输入？

## 何时换工具

- 固定前后缀：字符串 `startsWith` / `endsWith`；
- 固定分隔符：`split`，但先确认转义与空字段规则；
- JSON、CSV、HTML、URL、日期：对应解析器；
- 嵌套语法：词法器、解析器或成熟库；
- 不可信且无界输入：先限制长度，必要时选择线性时间引擎；
- 业务有效性：正则之后继续用业务代码验证。

- [MDN `RegExp.prototype.test()`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/test)：`g` / `y` 与 `lastIndex` 的状态性；
