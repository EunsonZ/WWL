# 学习路线与先修诊断

> [!tip] 使用这张路线图
> 先从[[AI/00-开始/05-问题驱动知识图谱与难点导航|问题驱动知识图谱]]定位困难，再用[[AI/00-开始/06-统一符号形状与公式阅读方法|符号与形状手册]]补工具，按[[AI/00-开始/07-学科覆盖矩阵与分层学习清单|覆盖矩阵]]区分入门、机制深化和实验验证。跨域数学内容从[[数学/00-数学-首页|数学首页]]进入；本目录的[[AI/11-数学与统计桥梁/00-数学与统计桥梁-MOC|数学桥梁]]只提供 AI 语境下的衔接。


这不是考试，也不是筛选门槛。它用来找出你此刻最短的下一步：先补一项会直接阻塞实验的能力，其余内容在遇到真实问题时再回来学习。

## 先做十分钟诊断

| 我目前能否做到 | 如果“还不能” | 通过的可观察证据 |
| --- | --- | --- |
| 用 Python 读取一个 UTF-8 文本、处理错误并写出结果 | [[计算机知识/10-编程语言/01-Python/00-Python基础-MOC\|Python 基础]]的 01—05 | 能解释使用的是哪个解释器和输出文件在哪里 |
| 创建项目环境并辨认依赖安装到了哪里 | [[计算机知识/10-编程语言/01-Python/09-venv与虚拟环境原理\|venv]]、[[计算机知识/10-编程语言/01-Python/12-包管理器选择锁定与迁移\|工具选择]] | 能从空目录按说明重建，不提交 `.venv` |
| 用命令行确认路径、进程、权限、磁盘和日志 | [[计算机知识/20-操作系统/01-Linux/00-Linux基础-MOC\|Linux 基础]] | 先用只读证据定位，而不是复制高权限命令 |
| 说清向量、概率、导数各在 AI 中解决什么问题 | [[数学/01-数学学习路线\|数学学习路线]]、[[数学/02-AI数学应用索引\|AI 数学应用索引]] | 能说出用途、一个假设和自己尚未理解处 |
| 区分训练、验证、测试与真实使用 | [[AI/10-机器学习与深度学习基础/00-机器学习与深度学习基础-MOC\|机器学习与深度学习基础]] | 能指出一个数据泄漏或评估错配风险 |
| 说明模型、数据、权重、密钥和服务的不同风险 | [[AI/00-开始/04-环境安全许可证与资源边界\|环境、安全、许可证与资源边界]] | 不把敏感文件或受限资产放进 Git |

如果前两项尚未完成，请先走 Python 与 Linux 路线。AI 课程不会替代程序、文件和依赖的基础，但会在你准备好后给它们一个明确的应用问题。

## 四条分层路线

> [!important] 先修是按目标触发，不是一次性清单
> 阅读概念与完成 CPU 小实验，不以 C++、CUDA 或指定显存为前置；训练、长上下文/多模态推理、原生后端和服务才逐步触发系统、CUDA、资源预算与网络边界。遇到阻塞时，只补直接解释该阻塞的一层，并把仍未知的条件记录下来。

### 路线 A：先理解，再实验（推荐起点）

适合：有高中数学和基础编程，尚未系统学习机器学习。

1. 完成 [[AI/00-开始/01-AI知识地图|AI 知识地图]] 的六行练习；
2. 进入 [[AI/10-机器学习与深度学习基础/00-机器学习与深度学习基础-MOC|机器学习与深度学习基础 MOC]]；
3. 遇到矩阵、概率、梯度或数值误差时，跳到 [[数学/02-AI数学应用索引|AI 数学应用索引]] 的对应入口；
4. 用 [[AI/80-实践/00-AI实践-MOC|AI 实践 MOC]] 运行一个小数据、小目标、小评估的实验；
5. 再选择已完成的 LLM 分支，或进入 VLM、语音、扩散的核心课程，再按地图选择进阶方向。

**完成标准：** 你能用自己的话解释数据划分、基线、损失/目标与评估的不同职责，并写出一个失败例子。

### 路线 B：LLM 应用与工程理解

适合：想读懂提示、上下文、RAG、工具调用、推理成本和模型服务的读者。

1. 先完成路线 A 的共同基础；
2. 阅读 [[AI/20-LLM/00-LLM-MOC|LLM MOC]]；
3. 当输入输出变长、成本上升或吞吐下降时，阅读 [[AI/00-开始/03-8GB-16GB与24GB实践路线|资源路线]]，并回到 [[计算机知识/30-计算机系统/00-计算机系统-MOC|计算机系统]]；
4. 只有在明确数据、网络和访问边界后，才进入本地服务或 API 集成。

**完成标准：** 你能区分“模型能生成文本”“检索系统提供来源”“工具实际执行动作”，并说明每一层分别怎样失败。

> [!tip] 先理解 LLM，不等于现在就读 C++ 源码
> 这条路线先解决 token、上下文、检索、评测与推理成本等**理解问题**；它不要求你立刻编译 `llama.cpp` 或阅读大型 C++ 仓库。只有当目标变成“构建后端、定位内存/并发问题或修改源码”时，再先完成 [[计算机知识/10-编程语言/02-C++/00-C++-MOC|C++ MOC]] 的语言、所有权、测试与调试主线，并补 [[计算机知识/30-计算机系统/00-计算机系统-MOC|计算机系统 MOC]]。届时应把源码阅读当作独立的进阶项目，保留构建日志、版本和可回退的小改动。

### 路线 C：多模态生成与理解（核心课程已补齐）

适合：目标是图文、语音、音频或图像生成，且现在愿意先完成共同基础、选题和风险设计；不把“看起来像”当作可靠评估。

> [!note] 已有可连续阅读的课程，真实模型实验另行核验
> VLM、语音与扩散现有各三篇核心/深化课程和本地图示，可以连续阅读；附带 CPU 小例只验证部分数学。真实多模态模型的训练、部署与 GPU 评测仍需另行完成，不能由读完正文替代。

1. 先完成路线 A；
2. 选择 [[AI/30-VLM/00-VLM-MOC|VLM 课程地图]]、[[AI/40-语音与音频模型/00-语音与音频模型-MOC|语音与音频模型课程地图]] 或 [[AI/50-扩散模型/00-扩散模型-MOC|扩散模型课程地图]]，只写下一个具体任务与它的输入、输出和禁止自动决定的事项；
3. 补齐 [[数学/70-信号处理与多模态数学/00-信号处理与多模态数学-MOC|信号处理与多模态数学]] 中与当前模态有关的表示；
4. 写一页实验设计：记录来源、同意、版权、失败样本、人类复核规则，并分别记录已读原理、已运行小例与尚未运行的真实模型实验。

**当前完成标准：** 你能写出一个不应由模型单独决定的情形，说明为什么离线相似度或主观观感不够，并区分已读原理、已运行的 CPU 小例和未运行的真实模型实验。

### 路线 D：性能、训练与 GPU

适合：已完成基础实验，开始遇到显存不足、吞吐、编译或加速问题。

1. 用 [[AI/00-开始/03-8GB-16GB与24GB实践路线|显存路线]]缩小任务，而不是先升级硬件；
2. 先把目标分开：只想解释资源账本时，学习 [[计算机知识/30-计算机系统/00-计算机系统-MOC|计算机系统]] 和 [[计算机知识/40-并行与异构计算/01-CUDA/00-CUDA-MOC|CUDA]] 的概念即可；只有要编译原生扩展、调试后端或阅读源码时，才把 [[计算机知识/10-编程语言/02-C++/00-C++-MOC|C++]] 作为必经前置；
3. 用可重复测量区分数据 I/O、CPU、显存、GPU 计算和网络瓶颈；
4. 只在已知许可、费用和数据边界后考虑云资源或多机。

**完成标准：** 你能给出一次测量的硬件、软件、精度、batch、输入形状、时间口径和失败条件；“更快”不再是没有上下文的结论。

## 五个实践入口：稳定课程之外的可修改空间

课程页解释概念；实践页才放可以改、可以重置的材料。按这一顺序使用五个实验入口：

1. [[计算机知识/80-实践/01-Python/00-Python实验室|Python 实验室]]：文件、环境与测试习惯；
2. [[计算机知识/80-实践/02-Linux/00-Linux实验室|Linux 实验室]]：命令、进程与故障证据；
3. [[计算机知识/80-实践/03-C++/00-C++实验室|C++ 实验室]]：编译、内存与原生程序；
4. [[计算机知识/80-实践/04-CUDA/00-CUDA实验室|CUDA 实验室]]：GPU、并行程序与系统性能观察；
5. [[AI/80-实践/00-AI实践-MOC|AI 实践 MOC]]：数据、模型、评估与 AI 工程边界。

不同机器上，后四项的可用性会变化；不能运行 GPU 实验时，仍可学习概念、阅读日志、运行 CPU 小样本和写实验计划。不要为了“完成路线”绕过安全、许可或费用门禁。

## 练习：为自己选下一条路线

写下三句话：

1. 我现在最想回答的一个具体问题；
2. 上表中阻塞我的第一项能力；
3. 本周可以完成的一个小而可验证的动作。

**成功标准：** 这个动作不要求下载未知权重、不需要 root 权限、不触及真实敏感数据，且能在结束时说明“做了什么、得到什么、还不能说明什么”。
