# Note Composer：合并与拆分

> [!warning] 先读再操作
> “提取当前选区”会创建文件并改写当前笔记；“将当前文件合并到另一个文件”还可能删除被合并的源文件。请只在你自己创建的练习副本中操作，不要直接合并甲、乙、丙样例。

## 什么时候拆分

一篇笔记出现以下信号时，可以考虑提取：

- 某个段落有独立标题、能被其他笔记复用；
- 多处需要链接到同一个概念，而不是复制这段文字；
- 当前文件同时承担多个主题，Outline 已很难浏览；
- 一个项目段落逐渐成长为独立项目。

拆分的目标不是让每句话都成为文件，而是让值得独立链接、独立演化的内容拥有自己的地址。

## 安全的拆分实验

1. 新建 `Obsidian知识/30-实践/01-实验区/Note-Composer-练习.md`，写入：

```markdown
# Note Composer 练习

## 临时记录

这是一段可以独立复用的概念说明。

## 保留在原文

这段仍留在练习文件中。
```

2. 选中“临时记录”标题和段落。
3. 打开 Command palette，执行 **Note composer: Extract current selection**。
4. 将新文件命名为 `提取练习-可复用概念`，目标目录仍选 `Obsidian知识/30-实践/01-实验区/`。
5. 检查原位置是否出现指向新文件的链接，以及新文件是否包含选中内容。
6. 在新文件查看 Backlinks，确认练习文件指向它。

> [!tip] 模板位置
> Note Composer 可配置“提取笔记的模板文件”和默认保存位置。教学练习保持简单；真实工作流可让提取后的概念笔记自动带 `type`、`status` 等属性。

## 什么时候合并

合并适合：

- 两篇笔记实际表达同一个概念；
- 一个临时捕获已经被正式笔记吸收；
- 重复笔记会让内部链接与搜索结果分裂。

不适合：

- 只是主题相关；相关内容应该用链接连接；
- 尚未决定哪个标题、属性和内容是主版本；
- 源文件包含独立的反向链接语境，合并后可能丢失意义。

## 合并前检查清单

- [ ] 打开两篇文件，逐段比较，不只比较标题。
- [ ] 查看源文件的 Backlinks、aliases 与属性。
- [ ] 明确保留哪个文件名与路径。
- [ ] 确认内部链接自动更新设置符合预期。
- [ ] 确认有 Undo、File recovery 或 Git 快照可恢复。
- [ ] 只在当前练习副本上执行第一次合并。

## 可选合并实验

再创建 `Obsidian知识/30-实践/01-实验区/Note-Composer-临时碎片.md`，写一行无关紧要的练习文本。在碎片文件中执行 **Note composer: Merge current file with another file**，目标选择刚才的 `提取练习-可复用概念`。

执行后立刻检查：

1. 目标内容是在顶部还是底部；
2. 源文件是否已被删除；
3. 指向源文件的链接是否更新到目标；
4. 目标 frontmatter 是否仍符合你的 schema；
5. 是否出现重复 H1 或重复段落。

## 为什么不能把合并当“剪切粘贴”

普通剪切粘贴只搬正文；Note Composer 还参与链接更新和文件生命周期。它能降低重构成本，却不会替你判断属性冲突、重复标题、别名含义或内容顺序。

## 复原

练习完成后，先关闭指向练习文件的标签页，确认它们没有需要保留的内容，再删除三个练习文件。若结果不符合预期，优先 Undo；已经跨过 Undo 历史时，使用 File recovery 恢复指定文件，或用 Git 比较差异。
