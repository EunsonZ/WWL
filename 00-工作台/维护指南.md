# 维护指南：先解决读者的问题

稳定边界见 [[AGENTS|AGENTS.md]]；多人分工按需查 [[00-工作台/并行协作与模型路由|并行协作与模型路由]]。人直接提出疑问或指出相关页面即可，日常阅读不需要先读维护文件。

## 一次修改应让哪里更好

先定位卡点与已有主解释。历史计划、测试方法数和当时回执分别对照当前版本，不能因文件存在、变过或测试通过就判整页已正确。能回答就给准确位置；有缺口再补关键跳步、针对性图例或明确连接。不要为统一文风批量重写，也不把下面的标准变成每页固定标题。

科学与技术在需要处连接现象、物理对象、数学模型、计算方法和代码行为，解释转折的旧约束、新方法、收益与代价。社会经济以科普和认知建构为主，解释组织、政治制度、税收、金融、汇率与贸易怎样影响家庭、企业、政府及国内外循环；区分会计关系、因果解释和价值判断，写清时期、制度前提、受益者与承担者，保留替代解释。

## 内容、入口与记录各司其职

| 当前处理的内容 | 优先解决的问题 |
| --- | --- |
| 概念、课程与推导 | 对象和符号是否清楚，关键推导是否合法，直觉与形式表达能否相互解释，边界与反例是否充分。 |
| 实践、代码与数据 | 输入和参数可找到，读者能改变一个条件并观察结果；区分教学模拟、实际执行与硬件测量。 |
| 首页、MOC 与学习路线 | 告诉读者为什么从这里进入、必要前提在哪、下一篇兑现什么；连接已有主解释，避免复制整章。 |
| 剪藏、参考资料与历史原稿 | 保全原文、身份与出处；需要时另作归纳或校注，不将原稿悄悄改成当前结论。 |
| 个人任务、批注与学习记录 | 只记录人的真实问题、行动与反馈，不代填掌握度，不把代理队列变成用户待办。 |

这是处理方式，不要求补分类属性或照搬四套平行目录。教程回答如何开始，解释页回答为什么，操作指南完成具体任务，参考页提供可查合同；只在真实读者需要不同入口时分开。沿用现有学科、`Clippings/`、`资料/`、`TaskNotes/`、`00-工作台/` 与历史日志的职责，不为一轮修改重排全库。

## 主解释、来源与连接

一个主解释服务多条路线，应用页保留必要回顾。完整证明、关键口径和源码各有清楚的真源；源码改变时同步相关测试和 `code-sync` 镜像。去重后仍有完整定义，不能两篇互指已删内容。同页多轮追加的解释应合成一份主叙述，保留独有条件和既有引用；原始对话的恢复、校注与知识核查分别处理。

关键、争议及易变断言给直接支持它的来源与必要版本、时期、条件；技术事实优先官方文档、源码、标准或原始研究。代理摘要不能代替原始依据。分清事实、推论、假设、规范性判断与未知，不为普通常识堆引用。

链接说明是先修、证明、应用、比较还是反例，并核对目标段兑现承诺。新建、合并、改别名前查正文与同义表达，整合时复查相关候选。移动或改名处理受影响的入链、嵌入、锚点和配置，不手工维护反向链接。[1]

## 图例、实验与阅读出口

图先回答具体问题：空间关系用二维或必要的三维，数量变化用坐标图，拓扑或流程用关系图。写清对象、单位、方向与假设，分清时间、信息流、依赖与因果。数值图保留生成依据，SVG保留title/desc，颜色不是唯一提示；交互保留静态入口，不要求每页配图。

关键案例尽量用同一对象贯穿图、公式、数值与代码。实验说明可改哪个参数、观察什么及模型限制；按需要用预测或条件变化检验解释，不要求每篇附题。初学路线可在示范后逐步撤去步骤，并问这一步依赖什么前提、为什么成立；熟悉者可直接尝试迁移题。答案接受符合题设的等价方法，不强加未声明的限制；模型走读不能证明真人理解。

普通 Markdown、公式和笔记链接构成阅读底座，Canvas、Bases 与既有插件辅助导航和展示，关键解释不只存于临时卡片或插件状态。常规直接编辑文件，需要确认显示或客户端行为时才用可用的 Obsidian，不强制新装工具。[2][3]

## 属性只记录真实含义

`stage` 保持数字；`aliases`、`sources`、`prerequisites` 保持列表，只填真实别名、来源与必要先修。旧属性不批量清洗，缺省表示未记录。已有内容状态与证据状态分别处理，局部核查不认证整页；不补虚构日期、学习时间或掌握程度。[4]

## 实际改进与验证

语义不变的小修由作者自查。重要定义、推导、因果、数量、代码行为及关键先修变化，由未参与该论证或行为修改的人或代理独立核对，按需复算或执行，只扩大到受影响的必要上下文。数学核定义域、单位、类型与索引；统计核目标量、分母与不确定性；性能核负载、环境与口径。

只查实际影响：正文不默认跑维护工具测试；代码查相关行为与镜像；结构、共享属性、工具或配置变化查受影响引用并做适用结构检查。命令见 [[scripts/CHECKS|维护检查说明]]，环境按需查 [[scripts/ENVIRONMENT|本地维护与绘图环境]]。静态、执行、来源、显示与理解各有证据，不能互相代替。

缺依赖、硬件或客户端时完成可做部分；依已有授权处理必要安装，缺少必要授权时不安装，说明未运行范围。用户明确要求不运行时，实验只说明接口、预期观察和记录位置，不得自行升级为实际运行；未验层不阻塞可独立交付。不要靠放宽例外隐藏新错误。条件不变的检查可注明复用；充分验证后停止追加检查。

## 候选接收到实际 Obsidian 主库

此处只给接收协议，不表示当前候选已经进入用户主库。用户已明确说明会及时保存时，整合者遵循该安排，不把不可观测的未保存缓冲区变成每批额外确认门槛；仍需辨认实际 vault 与相关同步/自动写者。只有观察到目标字节漂移、并发冲突或第三态时才保全相关目标并停止该组，不冻结无关工作。

1. 区分候选工作根、实际主库目录和目标 Obsidian 窗口，记录候选/目标版本与精确文件。先检查目标当前字节；人的新改动做局部合并，第三态先保全并停止，不能整文件覆盖。
2. 先用库外的两页临时夹具或同样小的独立组试行。客户端打开接收页，分别核对一个 wikilink、一个标题或块引用、一项 frontmatter，以及一处实际已有附件或嵌入；从入口到目标再返回，记录预期与观察到的落点和显示。
3. 在临时接收页做一处容易识别的小修改，确认客户端读取到新字节。需要同步证据时，只沿用户已有同步路径观察这一组目标；未能访问的设备或通道记为 `notrun`，不从文件存在推断成功。
4. 清理只撤除本次仍完全匹配的临时页面和引用；不匹配的第三态保留并交接。回执分开写文件应用、静态检查、客户端显示、同步、恢复和真人阅读层，不能以其中一层替代另一层。

现有原生界面可完成此试点；若使用 CLI、URI、REST、MCP 或插件，先确认它已存在、可用且已获本次授权。没有实际客户端时，本协议和库外夹具只是一份可执行候选，客户端/同步/真人层明确为 `notrun`。

## 人的编辑、整合与完成

人继续正常编辑；当前已授权整合者落库前看最新差异，保留批注和新内容，只协调有冲突的目标文件。共享主库同一时刻一名整合者，可明确交接。按需用已有 Git 或局部备份保全，回滚不覆盖他人新版本。

达到完成标准就交付，无须改动或有理由的分歧也可成为结果。阶段完成或交接时一次简报，实际变更在已有 [[CHANGES|CHANGES.md]] 留入口即可，不另造逐页日志、任务表或状态机。读者入口呈现问题与正文，历史回执从原记录追溯。
