C++ 的难点不在于记住多少语法，而在于每个抽象都跨越了语言、构建工具、资源所有权和机器执行方式。按当前需要从唯一系统索引进入：首个程序接到一份可运行的测量记录，再沿值语义、泛型和工程边界走到独立调用方；大型仓库与 `llama.cpp` 是可选的后续应用，不是所有读者的课程终点。

> [!abstract] 完成后的能力
> 你将能区分预处理、编译、链接和运行；说明对象、引用、指针、生命周期和资源所有权；读懂常见 STL/模板/移动语义；用 sanitizer 与调试器定位问题；理解线程同步、ABI、缓存和 SIMD 的边界。把这套能力用于 `llama.cpp` 模型加载、图构建、后端分发与采样循环，是可选的大型仓库应用。

## 最常混淆的边界

| 不要混为一谈 | 区别 |
| --- | --- |
| 指针 / 所有权 | 指针只表示可访问地址；所有权回答谁负责资源何时释放。 |
| `std::move` / 移动发生 | `std::move` 只是把表达式转成右值；实际是否移动取决于目标类型和重载。 |
| 原子 / 无锁 / 正确 | 原子操作避免特定数据竞争，不自动构成正确协议，也不保证无锁。 |
| C++ ABI / C ABI | C++ 名字改编、异常、类布局等跨编译器风险更高；稳定插件边界常取窄的 C ABI。 |
| “零拷贝” / 不分配 | 它通常只意味着某一段传递不复制；仍可能分配元数据、做页映射或发生设备传输。 |

## 终点验收：能小幅扩展 llama.cpp

此处验收只适用于主动选择大型仓库应用分支的读者，不是 C++ 首次程序或数值组件路线的必达终点。首target、累计主线和当前独立数值应用的停靠点见上方唯一系统索引。

- [ ] 我能用项目文档列出的预设和隔离 `build/` 配置 `llama.cpp`，并保存 CMake 配置输出。
- [ ] 我能从 CLI/server 的入口定位参数解析、模型加载、context 建立、decode/eval 与采样循环，而不是从随机 kernel 文件开始。
- [ ] 我能区分公共 API、`llama` 层、`ggml` 图与后端实现，并说明一个符号的所属层。
- [ ] 我能针对一个小改动先找到现有测试或新增最小回归测试，再运行目标测试与 sanitizer 构建。
- [ ] 我不会把本机模型、下载链接、访问令牌、绝对个人路径或巨型构建目录写入仓库。
