# Web 边界、安全与全栈协议：类型不能跨过网络自动延续

> **学习位置**：[[计算机知识/00-开始/课程地图/05-TypeScript-课程地图|TypeScript课程地图]] · **适用边界**：strict 模式；ES2022 运行语义；Node 与浏览器环境区分。

## 一份类型定义不是一条可靠协议

前后端共享 `User` 接口可以减少字段拼写错误，但部署版本可能不同，网络内容可能被修改，数据库也可能存在旧数据。服务端必须验证请求，客户端也应验证关键响应。协议至少定义字段类型、可选与空值、单位、版本兼容、最大长度、错误格式与重试语义。

JSON 无法直接保留 Date、Map、Set、BigInt、undefined 或自定义原型。日期字符串应注明时区与格式，大整数可用约定好的字符串表示。序列化与反序列化是显式转换，不是 `JSON.parse(...) as Model`。

## 浏览器安全边界

不可信文本应进入文本节点或安全的模板转义路径，而不是拼接进 `innerHTML`。HTML、URL、CSS 和 JavaScript 字符串属于不同语境，不能用同一套字符替换处理。CSP 等机制提供纵深防御，不是允许忽略输出编码的理由。

CORS 控制浏览器脚本能否读取跨源响应，不是服务端身份认证。攻击者可以用非浏览器客户端请求接口。Cookie 的 `HttpOnly`、`Secure` 与 `SameSite` 各有边界；身份验证、授权、CSRF 防护和会话失效应独立设计。不能把“前端按钮隐藏了”当作资源授权。

## 服务端输入与资源控制

上传文件要限制大小、数量和实际类型，不仅检查扩展名。用户提供的 URL 可能触发服务端访问内部资源，需按业务限定目标与网络权限；重定向、DNS 变化和协议处理也属于边界。路径、SQL、shell 和日志各有不同注入风险，避免把外部字符串直接嵌入另一种语言。

错误响应不应暴露数据库连接串、堆栈中的密钥或内部路径；日志也要脱敏。类型系统无法阻止开发者把 token 打印出来，因此审计必须覆盖实际数据流。

## 缓存与状态同步

HTTP 缓存依赖响应头、验证器和请求语义。客户端状态库缓存、服务端缓存与浏览器缓存不是同一层。缓存键遗漏用户或权限维度，可能导致数据串读；更新成功后只改本地缓存，也可能与其他客户端状态分离。

乐观更新先展示预测结果，再根据服务端结果确认或回滚。多个请求交错时，旧响应可能覆盖新状态，应使用版本号、请求标识或服务端条件更新。这里的核心问题与数据库丢失更新相同，不是某个前端框架特有的技巧。

## 练习与答案

设计一个修改昵称接口：输入长度按业务选择字素、码点或字节限制；服务端从会话确定用户身份，而非信任 body 中的 userId；参数绑定写数据库；输出时按 HTML 语境转义；并发更新带版本条件。解释每一层各防什么、不能防什么。若只给接口加 `type UpdateName = {name:string}`，上述问题没有一个会自动全部解决。
