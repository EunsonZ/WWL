# 并行与异构计算 MOC

本栏目连接 CPU 并发、SIMD、GPU、CUDA 和 LLM 推理实现。目标不是先背 GPU 术语，而是学会判断任务在什么硬件上执行、数据在哪里、同步发生在哪里，以及瓶颈来自计算还是搬运。

## 推荐起点

1. 先读 [[计算机知识/30-计算机系统/05-并发并行SIMD与加速器]]，分清并发、并行、SIMD 与 SIMT。
2. 进入 [[计算机知识/40-并行与异构计算/01-CUDA/00-CUDA-MOC]]，从宿主/设备边界学到 kernel、内存、同步、精度和性能。
3. 在 [[计算机知识/80-实践/04-CUDA/00-CUDA实验室]] 用小 kernel 建立可观察证据；没有 NVIDIA Toolkit 或 GPU 时保留硬件跳过，不伪造运行结果。
4. 回到 [[AI/20-LLM/50-实现/04-llama.cpp构建后端与调用链]]，观察 CPU、CUDA 与混合 offload 如何接入同一推理调用链。

## 共同心智模型

```text
问题和数据布局
      ↓
CPU 控制流与主机内存
      ↓ 传输 / 映射 / 调度
GPU grid、block、thread、warp
      ↓
global/shared/register 等资源
      ↓
同步、归约、数值精度与结果验证
      ↓
profile 后再优化
```

“kernel 成功启动”只证明提交路径没有立即失败；正确性还需要 CPU 参考、边界输入、同步后的错误检查和数值容差。“GPU 利用率高”也不等于工作有效，必须同时看吞吐、延迟、带宽、算力和输出质量。

## 容器与原生系统边界

容器复用宿主机 Linux 内核与 NVIDIA 驱动，容器内提供 CUDA runtime/toolkit 和用户空间依赖。Ubuntu 原生环境往往按发行版/厂商组合维护；Arch 原生环境要特别核对 rolling kernel、headers、DKMS、驱动模块和完整升级。共同先修：

## 练习与成功标准

任选一个向量加法 kernel，画出输入从主机到设备再回到主机的路径，标出两个可能的同步点和三个可能失败的位置。成功标准是能解释：数据传输、kernel 执行和结果复制为什么必须分别计时与验错。
