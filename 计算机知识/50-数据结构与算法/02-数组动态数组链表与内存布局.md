# 数组、动态数组、链表与内存布局

## 本课目标

学完后，你应该能够：

- 用长度、容量、首地址与索引不变量解释三种线性结构；
- 推导数组随机访问与中间更新的代价；
- 说明链表局部重连为何需要“已找到节点/前驱”这个前提；
- 把访问模式、局部性、引用稳定性、空间和实现风险一起纳入选择。

## 1. 逻辑序列与物理表示不是一回事

序列 `[A, B, C]` 只说明逻辑顺序。固定数组、动态数组和链表都能表示它，却让“取第 `i` 个”“在开头插入”“旧引用是否仍有效”付出不同代价。

| 结构 | 核心表示 | 擅长的操作 | 典型代价（固定宽度元素、RAM 模型） |
| --- | --- | --- | --- |
| 固定数组 | 固定长度的连续槽位 | 随机访问、顺序扫描 | 下标访问 `Θ(1)`；中间腾位置最坏 `Θ(n)` |
| 动态数组 | 连续槽位 + length + capacity | 末尾追加、随机访问 | 追加摊还 `Θ(1)`；扩容那次最坏 `Θ(n)` |
| 单链表 | 节点值 + next 链接 | 已知前驱后的局部重连 | 定位第 `i` 个 `Θ(n)`；重连 `Θ(1)` |

若元素复制本身需要处理长字符串或大对象，以上“移动一个元素”的成本还应乘以元素大小或另设参数。

## 2. 固定数组：索引是地址计算

令首元素地址为 `base`，元素宽度为 `w` 字节。合法索引 `i` 满足 `0 ≤ i < length`，其地址为：

```text
address(i) = base + i × w
```

无需从第 0 个元素走到第 `i` 个，所以在 RAM 模型中按下标读写为 `Θ(1)`。索引越界不是“访问到空位”：它违反该数组的边界；安全运行时会报错，低级语言可能造成未定义行为。

数组不变量是：

1. 有效索引恰为 `0` 到 `length - 1`；
2. 槽位按固定步长连续；
3. 逻辑顺序由索引递增定义，不是由值大小定义。

### 手工例子：中间插入

```text
索引:       0   1   2   3   4   5
插入前:     A   B   C   D   _   _
在索引 1 插入 X 后:
            A   X   B   C   D   _
```

为保留 `B, C, D` 的相对顺序，必须从后向前移动它们，避免覆盖 `B`。需移动 `length - index` 个元素：末尾且有空位时为 0，开头则可能为 `n`，故中间插入/删除最坏为 `Θ(n)`。

## 3. 动态数组：length 不等于 capacity

动态数组通常维护：

```text
buffer   → 当前连续存储区起点
length   → 对用户可见的元素数
capacity → 已分配槽位总数，且 length ≤ capacity
```

当 `length < capacity`，末尾追加写 `buffer[length]` 后递增长度；满时则分配更大连续区，按原顺序复制/移动旧元素，更新 `buffer` 与 `capacity`，再写入新元素。按固定倍率增长时，复制总量的摊还证明见 [[计算机知识/50-数据结构与算法/01-复杂度模型渐近分析与摊还分析|复杂度模型、渐近分析与摊还分析]] 的“摊还分析”一节。

关键不变量：

1. `0 ≤ length ≤ capacity`；
2. `buffer[0]` 到 `buffer[length - 1]` 恰是逻辑序列；
3. 其余预留槽位不属于当前序列；
4. 扩容后逻辑顺序不变，但 `buffer` 地址可能改变。

第四条解释指针、引用、迭代器和视图失效：它们若指向旧区，扩容后不可靠。C++ `std::vector` 属于这种思路，具体增长策略不是标准固定承诺。见 [[计算机知识/10-编程语言/02-C++/05-struct类模板与STL|struct、类、模板与 STL]]。

Python `list` 也提供按下标和追加体验；其对象表示、预留策略与精确字节成本取决于当前解释器。把“像动态数组”作为心智模型即可，不要把某版本实现细节当成语言契约。语义入口见 [[计算机知识/10-编程语言/01-Python/04-容器迭代器生成器与推导式|Python 容器、迭代器、生成器与推导式]]。

## 4. 连续布局与缓存现实

连续元素具有空间局部性：读取一个元素时，邻近的一段缓存行通常也会抵达；顺序遍历更容易复用它们，并让硬件预取识别模式。

```text
连续数组: [A][B][C][D][E] ...
随机节点: [A|next] → 远处 [B|next] → 又一处 [C|next]
```

链式遍历的下一地址依赖当前节点，难预测、难预取，并且节点常有额外指针和独立分配成本。这不是“数组总更快”：随机索引、巨大工作集、频繁中间更新或元素内含分散对象都可能改变结果。应先分析工作负载，再在目标环境测量。见 [[计算机知识/30-计算机系统/04-缓存局部性带宽与延迟|缓存、局部性、带宽与延迟]]。

## 5. 单链表：顺序由 next 维持

```text
head → [value: A | next] → [value: B | next] → [value: C | null]
```

无环、长度为 `n` 的单链表满足：

1. `head` 指向第一节点，空表则为 `null`；
2. 从 `head` 沿 `next` 恰好访问 `n` 个不同节点后到达 `null`；
3. 每个 `next` 只指向唯一后继或 `null`；
4. 沿链接访问的顺序就是逻辑顺序。

### 已知前驱后的局部插入

已知 `prev` 指向 `B`，要在 `B` 和 `C` 间插入 `X`：

```text
插入前: head → A → B → C → null
1. X.next ← B.next
2. B.next ← X
插入后: head → A → B → X → C → null
```

必须先保存原后继；若先改 `B.next`，`C` 的入口会丢失。仅更新常数链接，所以已知前驱时为 `Θ(1)`；但“在第 `i` 位插入”通常要先从 `head` 走 `i - 1` 步找到前驱，总成本仍为 `Θ(n)`。

双向链表再保存 `prev`，使已知节点处的删除和反向移动更方便，却增加指针空间、更新步骤和不变量。哨兵节点可统一空表边界分支，但不改变按位置查找的线性代价。

## 6. 按操作序列选择，而非按名称背表

| 需求 | 先问什么 | 常见倾向 |
| --- | --- | --- |
| 高频按整数下标读取 | 是否需要随机访问 | 数组/动态数组 |
| 末尾追加后顺序扫描 | 能否接受偶发扩容、旧引用失效 | 动态数组 |
| 已持有稳定节点，常在附近插删 | 节点句柄的生命周期能否保证 | 链表/节点式结构 |
| 大量固定宽度元素顺序处理 | 是否受缓存/带宽限制 | 连续布局常占优 |
| 地址/迭代器必须跨增长稳定 | 失效规则和所有权是什么 | 节点式、分块式或预留容量 |

不要用“链表插入 `O(1)`”省略定位前提，也不要因“数组连续”忽略中间移动、峰值容量或失效规则。结构选择是对操作序列、正确性约束和资源预算的建模。

## 常见误解与边界

- **“容量就是元素数。”** 对动态数组不成立；空槽位是为未来追加预留的资源。
- **“链表插入总是常数。”** 只有节点或前驱已经在手时成立。
- **“链表不移动，所以总快。”** 指针、分配和缓存未命中可能更贵。
- **“扩容只变容量。”** 底层地址可能更换，旧引用可能失效。
- **“连续容器意味着所有对象内容连续。”** 仅元素槽位连续；元素引用的字符串或其他对象可仍然分散。

## 练习

1. 画出长度 5、容量 8 的动态数组；在索引 2 删除元素，标出为保持紧凑顺序要移动的元素。
2. 假定容量满时翻倍，记录前 8 次追加后的 `(length, capacity)`，标出可能导致旧地址失效的步骤。
3. 对 `A → B → C → null`，按两步链接更新在 `B` 后插入 `X`；解释若失去原后继为何 `C` 不可达。
4. 为一千万固定宽度读数选择主结构：常按下标读、顺序扫描、末尾追加。分别写出渐近代价、局部性和引用失效方面的理由与限制。

## 成功标准

- 你能由地址公式和边界解释数组随机访问；
- 你能区分动态数组的长度、容量、一次扩容与摊还追加；
- 你能维护链表可达性不变量，并指出局部插入的前提；
- 你会同时比较操作序列、元素/指针开销、局部性和引用稳定性。
