# 社区插件的安全与选型

## 原生替代

先检查核心插件是否已解决需求：Properties/Bases、Search、Templates、Daily Notes、Canvas、Backlinks、File Recovery 和 Workspaces 能覆盖大量常见场景。

## 安装与启用状态

WorkWithLLM 的历史课程快照曾预装所需插件，其中多数默认关闭；这不说明 WWL 具有相同插件文件或状态。安装只把发布文件放入某个 Vault；启用才会执行第三方代码。Restricted mode 开启时，所有社区插件都会被忽略，但文件仍保留。开始前在 WWL 的 Settings 中逐项确认。

## 安全观察实验

本实验只读，不切换插件：

1. 打开 Settings → Community plugins。
2. 观察 Installed plugins 列表和每个开关。
3. 查看可定位的作者、仓库、版本、移动端支持、发布记录与独立安全证据。不要把目录展示、下载量或任何第三方分数当作权限隔离或完整安全审计。
4. 在 [[Obsidian知识/90-资源/02-参考/05-社区插件选型矩阵|05-社区插件选型矩阵]] 找到同一插件的原生替代、网络能力与数据写入方式。
5. 在 [[Obsidian知识/20-功能/02-社区插件实验室/13-插件实验报告|13-插件实验报告]] 记录“为什么需要它”和“不用它会怎样”。

## 成功标准

- 能区分安装、启用和 Restricted mode。
- 能指出插件是否联网、执行代码、批量写文件或保存凭据。
- 能先给出一个核心功能替代方案。

## 信任检查表

- 是否来自 Obsidian Community directory 的正式版本？
- 作者、源码、许可证和最近更新是否清楚？
- 是否支持当前 Obsidian 与目标设备？
- 是否会联网、执行 JS/系统命令或启动 server？
- 是否会覆盖、删除、重命名或批量改写文件？
- 禁用后数据是否仍可读？
- 是否已有独立备份或 Git commit？

> [!warning] 社区插件没有细粒度权限沙箱
> 官方明确说明，插件继承 Obsidian 的文件与网络访问级别，可能访问计算机文件、联网或安装程序。目录扫描不是权限隔离。

## 禁用与恢复

- 实验结束后关闭该插件开关，不必立即卸载。
- 若出现异常，先保存文件，再开启 Restricted mode，重载 Obsidian 后复测。
- 使用 File Recovery 或本地 Git diff 恢复实验文件；不要删除 `.obsidian` 作为第一步。
- 插件缓存、生成文件和凭据必须按各专页说明单独处理。
