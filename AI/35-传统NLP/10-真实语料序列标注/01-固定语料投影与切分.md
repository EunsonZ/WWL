# 固定语料投影与切分：先决定什么叫一条样本

UD English EWT r2.16 的固定来源是官方 GitHub tag：[`UD_English-EWT` r2.16](https://github.com/UniversalDependencies/UD_English-EWT/tree/r2.16)，commit `4c89b5833a70aa5ed3a00bad2f23f57992cc7df8`。实际读取 `en_ewt-ud-{train,dev,test}.conllu` 三个文件；`README.md` 的许可段写明 **annotations and database rights** 为 CC BY-SA 4.0，并指定出处。实验保存其原字节 SHA-256：train `3fb78e…b7e7b`、dev `531a54…4f29e`、test `e266e5…55cd`、README `099677…4f29e`、LICENSE `b3d1b0…5ae7`。

这里有一个必须保留的上游版本冲突：固定 README 的第 2 行仍写 `v2.15 -- 2024-11-15`，但其 changelog 在第 85 行列 `2025-05-15 v2.16`；tag 和三个固定 CoNLL-U 文件决定本实验版本，不能假称 README 题头也已更新。README 还明确底层文本来自多方，部分可能受 Google、Yahoo、Penn 等权利约束。因此本候选的 `results.json` 只发布无 `FORM`、句 ID、文档 ID 和逐 token 预测的聚合结果；不把可重构文本的预测 JSON 当作“无文本派生产物”。网页的年份、README 文件头或许可说法若日后变化，重跑应以这里固定的原字节与 hash 为准，而不是把网页快照、文本权利与标注数据库许可混作一个断言。

## 文档级子集，但不改官方拆分

每个 `# newdoc id = ...` 开始一个文档。我们只保留 `int(sha256(newdoc_id),16) mod 4 == 0` 的**整个**文档，随后才把该文档内句子投影。规则不看词性、长度或模型分数；train、dev、test 仍分别从它们自己的官方文件选择。此次运行得到：

| 官方集合内的固定子集 | 文档 | 句 | 整数 token |
| --- | ---: | ---: | ---: |
| train | 130 | 3,113 | 45,820 |
| dev | 73 | 325 | 4,075 |
| test | 81 | 492 | 7,181 |

训练/开发/测试的保留文档 ID 两两不交。程序内部以 `(doc_id, sent_id)` 绑定每句；聚合发布的 `results.json` 不写这些标识，也不写原 token。sentence accuracy 在预测每句时直接逐句计算，不依赖句 ID 的全局唯一性。文档边界避免同一篇网页的一部分训练、另一部分测试，但不能证明不同文档的文字不重复。

CoNLL-U 每个普通 token 是 10 列。程序只接受 ID 为十进制整数的行，使用第 2 列 `FORM` 和第 4 列 `UPOS`：`1\tAl\tAl\tPROPN...` 投影成 `(Al, PROPN)`。`1-2` 这类 multiword-token range 只是表面词范围，不是一个可带独立 UPOS 的词；`3.1` 这类 empty node 也不是普通表面 token。两者明确排除，不能悄悄算进分母。空句不进入本实验。

### 练习

1. 为什么不按句子 hash 切分？**答案：** 那会把同一文档相邻句分给不同集合，破坏这里想限制的文档泄漏；它可属于另一项明确标名的句级实验。
2. range 行的字符串看起来像一个词，为什么不能把它作为 HMM 的一个 observation？**答案：** 本协议要的是 UD 的整数语法 token 与它的 UPOS；range 行是另一个表面范围层。混入它会改变序列长度和标签定义。

从FORM/UPOS走向句法结构，接[[AI/35-传统NLP/10-语言结构与任务/02-真实依存基线计数势与投射解码|真实依存计数基线]]：另用许可明确覆盖文本的Swedish-Talbanken固定版本，保留原HEAD与完整DEPREL，按原文档身份限制拆分；本页EWT的FORM/UPOS投影本身不含依存监督。新任务输入参考词性、评价结构附着，不能把它称本页HMM的端到端后级成绩。
