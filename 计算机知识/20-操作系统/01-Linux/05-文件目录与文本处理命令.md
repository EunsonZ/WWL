# 05 · 文件、目录与文本处理命令

Linux 把目录、普通文件、设备、管道和链接都放进同一个文件系统命名空间。命令行工作最重要的习惯不是记住很多缩写，而是先确认“我在哪里、我要作用于哪个精确路径、这个命令会不会覆盖或删除”。本课从可恢复的演练目录开始，覆盖日常文件管理、文本查看与管道处理，以及 `tar` 配合 `gzip`、`xz`、`zstd` 的归档压缩。

本课承接 [[计算机知识/20-操作系统/01-Linux/04-Shell命令行与帮助系统|Shell、命令行与帮助系统]] 的引用、glob、管道和重定向；路径为什么可能跨越设备、挂载点与文件系统，见 [[计算机知识/20-操作系统/01-Linux/03-目录结构挂载与文件系统|目录结构、挂载与文件系统]]；权限与进程边界见 [[计算机知识/20-操作系统/01-Linux/06-用户权限进程与作业控制|用户、权限、进程与作业控制]]。

## 学完能做什么

- 解释绝对路径、相对路径、`.`、`..`、隐藏文件和 shell 的 glob 展开；
- 使用 `pwd`、`ls`、`cd`、`mkdir`、`touch`、`cp`、`mv`、`rm`、`rmdir`、`ln`、`stat`、`file` 管理和检查文件；
- 使用 `find` 做实时、可控的目录树搜索，知道 `locate` 为什么可能过时；
- 使用 `cat`、`less`、`head`、`tail` 查看文本，再用 `grep`、`rg`、`sort`、`uniq`、`cut`、`paste`、`tr`、`wc`、`tee`、`xargs` 组成可检查的流水线；
- 区分归档和压缩，安全地创建、列出、解包 `.tar.gz`、`.tar.xz` 和 `.tar.zst`；
- 处理空格、换行和 NUL 分隔的文件名，知道何时必须使用引号、`--`、`-print0` 和 `xargs -0`；
- 在隔离的练习目录里验证结果，并通过显式路径、备份或版本控制保留恢复路径。

## 1. 先建立安全边界

### 1.1 路径是命令的真正输入

路径由目录项组成，用 `/` 分隔。以 `/` 开头的是绝对路径，例如 `/var/log`；不以 `/` 开头的是相对当前工作目录的路径，例如 `notes/today.txt`。`.` 表示当前目录，`..` 表示父目录；`~` 是 shell 对当前用户主目录的展开，不是 Linux 内核的特殊目录名。

```text
/srv/project/README.md    # 绝对路径，从根目录开始
./notes/today.md          # 相对路径，从当前目录开始
../shared/data.csv        # 先到父目录，再进入 shared
```

命令作用于“当前目录”还是“给出的路径”经常不同。开始任何批量操作前，先运行 `pwd`，再运行带有明确目录参数的 `ls`。不要在不确定位置时用 `..`、`*` 或宽泛的绝对路径猜测目标。

### 1.2 隐藏文件不是安全文件

名称以 `.` 开头的目录项通常称为隐藏文件。普通 `ls` 不显示它们；`ls -la` 才会显示隐藏项以及 `.`、`..`。隐藏只影响默认显示，不表示内容不可读，也不表示可以随意删除。特别小心 `~/.config`、`.ssh`、`.git` 和项目中的 `.env`：其中可能有配置、密钥或版本历史。

```bash
ls -la -- .
ls -la -- .config
```

### 1.3 `--`、引号和 glob

许多 GNU 命令把 `--` 解释为“选项结束”；其后的内容即使以 `-` 开头，也作为文件名或其他操作数。它不能替代确认目标，但可以避免文件名被当成选项。

```bash
touch -- '-draft.txt'
cp -- '-draft.txt' 'draft copy.txt'
```

空格、制表符、换行和 `*` 等字符会被 shell 特殊处理。把路径整体放进双引号，变量展开仍然可用；需要完全禁止变量、命令和反斜杠展开时使用单引号。

```bash
file='meeting notes.txt'
stat -- "$file"
```

`*`、`?`、`[abc]` 是 glob（通配模式），由 shell 在命令启动前展开：

```bash
ls -- *.txt       # 当前目录中匹配的名称被逐个传给 ls
ls -- 'report *.txt'  # 引号后是字面文件名，不是 glob
```

glob 默认不匹配以 `.` 开头的名称；`*` 也不会跨目录。没有匹配项时，不同 shell 的行为可能不同，所以批量命令不要只依赖肉眼猜测的 glob。先用 `printf '<%s>\n' ./*.txt` 或 `find` 预览，确认列表后再执行会写入、移动或删除的动作。

### 1.4 在专用演练目录里工作

下面的演练目录由 `mktemp -d` 创建为一个新的、唯一的临时目录。执行第一行后，务必核对第二行输出确实指向你准备好的练习位置。这里的 `LAB` 只是 shell 变量；每次使用它都用 `"$LAB"` 引号包住。

```bash
LAB="$(mktemp -d -t linux-file-lab.XXXXXX)" || exit 1
printf '练习目录：%s\n' "$LAB"
mkdir -p -- "$LAB/inbox" "$LAB/work" "$LAB/archive"
pwd
printf 'alpha\nBeta\nalpha\n' > "$LAB/inbox/sample.txt"
touch -- "$LAB/inbox/meeting notes.txt" "$LAB/inbox/.secret-example"
```

这里的重定向 `>` 会创建或覆盖目标文件，因此只对刚建好的演练目录使用。若要追加，使用 `>>`，但也要确认目标路径。练习结束可以逐个删除自己创建的文件，再用 `rmdir` 删除空目录；不要用递归删除去“清理一切”。

## 2. 文件与目录的基本命令

### 2.1 定位与浏览：`pwd`、`ls`、`cd`

| 命令 | 常用写法 | 作用与注意 |
| --- | --- | --- |
| `pwd` | `pwd -P` | 打印工作目录；`-P` 显示解析符号链接后的物理路径，`pwd -L` 保留逻辑路径（shell 也可能有内建版本）。 |
| `ls` | `ls -la -- "$LAB"` | 列目录项；`-l` 看权限、所有者、大小、时间，`-a` 包括隐藏项，`-h` 让大小更易读。它默认不递归。 |
| `cd` | `cd -- "$LAB/inbox"` | 改变当前 shell 的工作目录；`cd -` 回到上一个目录，`cd` 单独运行通常回主目录。 |

```bash
pwd -P
ls -lah -- "$LAB" "$LAB/inbox"
cd -- "$LAB/inbox"
pwd
cd -
```

`ls -l` 中以 `d` 开头的条目通常是目录，以 `l` 开头的是符号链接，但不要仅凭颜色判断类型；用 `file` 或 `stat` 进一步确认。目录内容很多时，先限制精确目录，不要对未知的根路径递归列出。

### 2.2 创建：`mkdir`、`touch`

```bash
mkdir -- "$LAB/work/reports"
mkdir -p -- "$LAB/work/2026/09"
touch -- "$LAB/work/2026/09/empty.txt"
```

`mkdir -p` 会按需创建父目录；拼写错误时也可能在当前位置生成一棵你不想要的目录树，所以仍需检查 `pwd` 和路径。`touch` 在文件不存在时创建空文件，存在时默认更新时间戳，并不会清空内容；创建前若路径已存在，要先用 `stat` 确认。

### 2.3 复制与移动：`cp`、`mv`

```bash
cp -i -- "$LAB/inbox/sample.txt" "$LAB/work/sample-copy.txt"
cp -a -- "$LAB/inbox" "$LAB/work/inbox-backup"
mv -i -- "$LAB/work/sample-copy.txt" "$LAB/work/sample-renamed.txt"
```

`cp` 复制内容，`cp -a` 尽量保留目录结构、链接和属性；复制目录必须明确使用递归/归档语义。`mv` 在同一文件系统内通常是改名或移动，跨文件系统时可能表现为复制后删除。目标已存在时，两者都可能覆盖目标内容（交互选项和系统版本细节有差异），所以教学和实务中先使用 `-i`，或者复制到一个带唯一时间/版本标记的新目录，再用 `diff` 或校验和检查。

如果目标是目录，`cp source dest/` 和 `mv source dest/` 通常会把 `source` 放入该目录，而不是把它改名为 `dest`。目标路径不应靠猜测；GNU Coreutils 的 `-T`/`--no-target-directory` 只禁止把最后一个参数作为目标目录特殊处理，`cp -T source existing-file` 仍可覆盖已有普通文件。覆盖策略须另选并核对当前工具版本：例如交互 `-i` 或其支持的不覆盖选项；不覆盖是否返回失败也有版本差异。先预览和备份，不能用 `-T` 承诺“目标必须不存在”。见 [GNU target directory](https://www.gnu.org/software/coreutils/manual/html_node/Target-directory.html)。

### 2.4 删除：`rm`、`rmdir`

```bash
rm -i -- "$LAB/work/sample-renamed.txt"
rmdir -- "$LAB/work/reports"
```

`rm` 解除目录项与文件的链接；对普通文件通常没有“回收站”语义。`rmdir` 只删除空目录，失败时反而提供了一个安全提示：先检查目录里有什么。`rm -r`/`rm -R` 会递归处理目录树，`rm -f` 会抑制提示和部分错误；把它们合在一起会显著扩大误删后果。本课不把 `rm -rf` 当作清理方案，也不要把它与 `/`、`..`、`*`、变量或未知挂载点组合。

删除前采用三步确认：

1. `pwd -P` 确认当前目录；
2. `ls -la -- 精确目录` 或 `find 精确目录 -maxdepth 1 -print` 预览；
3. 只对明确列出的目标使用 `rm -i --`，重要内容先复制到带日期的备份或交给 Git。

如果误删，立刻停止继续写入该文件系统，不要把“恢复工具”当成保证；恢复取决于文件系统、备份、快照和是否被新数据覆盖。可恢复的替代办法是把待清理内容先移入同一演练目录的 `trash-YYYYMMDD`，确认无误后再逐个用 `rmdir` 或 `rm -i` 处理。

### 2.5 链接与元数据：`ln`、`stat`、`file`

```bash
ln -s -- ../inbox/sample.txt "$LAB/work/sample-link.txt"
stat -- "$LAB/inbox/sample.txt" "$LAB/work/sample-link.txt"
file -- "$LAB/inbox/sample.txt" "$LAB/work/sample-link.txt"
```

`ln -s` 创建符号链接：它保存一个目标路径，目标移动或删除后可能变成悬空链接；相对链接通常相对于链接所在目录解析。没有 `-s` 的硬链接让两个目录项指向同一个 inode，通常不能跨文件系统，也不能对目录随意创建。删除其中一个名字不会立即删除数据，只要还有其他硬链接且进程没有打开它。

`stat` 报告 inode、权限、大小、时间和链接数等元数据；`stat` 的具体格式选项在 GNU/Linux 与 BSD/macOS 之间可能不同，先看 `man stat`。`file` 根据内容特征判断文件类型，不是安全审计或反病毒证明；不可信文件仍可能包含恶意内容，打开、解压或执行前必须保持谨慎。

## 3. 搜索文件：`find` 与 `locate`

`find` 从指定起点实时遍历目录树，适合可靠、可复现的结果。先只打印，再考虑把结果交给其他命令：

```bash
find "$LAB" -type f -name '*.txt' -print
find "$LAB" -type f -size -10k -print
find "$LAB" -maxdepth 2 -type d -print
```

`-name '*.txt'` 中的 glob 必须加引号，否则会在 `find` 看到它以前就被当前目录展开。`-type f` 只匹配普通文件，`-type d` 只匹配目录；可以组合 `-not`、`-mtime`、`-size` 等条件。目录树大或权限复杂时，用 `-maxdepth`、精确起点和清晰条件缩小范围。

把结果交给命令执行时，优先使用 `-exec ... {} +`，它由 `find` 正确传递每个路径：

```bash
find "$LAB/inbox" -type f -exec file -- {} +
```

`-delete`、`-exec rm ...` 和 `xargs rm ...` 都具有删除副作用。即使结果看似正确，也必须先把同样的条件与 `-print` 运行一次，核对数量、目录和文件名；本课练习不要求递归删除。

`locate` 查询预先建立的文件名数据库，通常比扫描整个文件系统快，但数据库可能没有更新，所以“找不到”不等于文件不存在，“找到”也不等于当前路径仍然存在。不同发行版的数据库位置、更新命令和权限策略不同；先用 `man locate` 或发行版文档确认，不要为了更新数据库而修改系统目录。

## 4. 查看文本而不破坏它

| 命令 | 示例 | 适用场景 |
| --- | --- | --- |
| `cat` | `cat -- "$LAB/inbox/sample.txt"` | 小文件一次输出；多个文件会连续拼接。不要把未知的大文件直接倾倒到终端。 |
| `less` | `less -- "$LAB/inbox/sample.txt"` | 分页、搜索和退出；按 `q` 退出，`/词` 搜索，`n` 跳到下一处。 |
| `head` | `head -n 5 -- file` | 查看开头若干行；也可按字节数。 |
| `tail` | `tail -n 5 -- file` | 查看末尾若干行；`tail -f` 适合观察仍在增长的日志，按 `Ctrl-C` 停止。 |

这些命令只读文件，但把输出重定向到同一个输入文件会先截断它：`cat file > file` 会破坏内容。需要留存输出时写入演练目录中的新文件，并检查新旧路径不是同一个。

```bash
head -n 2 -- "$LAB/inbox/sample.txt"
tail -n 2 -- "$LAB/inbox/sample.txt"
less -- "$LAB/inbox/sample.txt"
```

查看二进制或包含控制字符的文件要谨慎：终端可能被转义序列改变显示。先使用 `file`、`wc` 或专门工具识别格式；不要把凭据、私钥、生产日志直接粘贴到公共终端或笔记。

## 5. 文本流水线

流水线 `A | B` 把 A 的标准输出连接到 B 的标准输入。每一步都先单独验证，再组合；用 `tee` 保存中间结果，避免“管道看起来成功但不知道哪一步错了”。

### 5.1 匹配：`grep` 与 `rg`

```bash
grep -n -- 'alpha' "$LAB/inbox/sample.txt"
grep -F -n -- 'a.b' "$LAB/inbox/sample.txt"  # -F 表示字面字符串
rg -n --glob '*.txt' 'alpha|Beta' "$LAB"
```

GNU `grep` 默认把模式当作基本正则表达式；`-F` 做固定字符串匹配，`-E` 使用扩展正则，`-i` 忽略大小写，`-n` 显示行号，`-l` 只列出匹配文件，`-v` 取反。模式以 `-` 开头时，用 `--` 分隔选项；不可信模式应先按字面匹配，避免正则表达式造成意外结果。

`rg`（ripgrep）是独立于 GNU grep 的递归搜索工具，默认尊重 `.gitignore` 并跳过隐藏目录和二进制文件；需要时可以明确写 `--hidden`，再用 `--glob` 排除或包含特定模式。两者的选项与正则引擎并不完全相同，脚本要锁定实际工具并阅读对应的 `man`/`--help`。

### 5.2 排序与计数：`sort`、`uniq`、`wc`

```bash
sort -- "$LAB/inbox/sample.txt"
sort -- "$LAB/inbox/sample.txt" | uniq -c
wc -l -w -c -- "$LAB/inbox/sample.txt"
```

`sort` 按当前 locale 排序；需要可复现的机器处理时可显式使用 `LC_ALL=C sort`，但这可能改变人类语言排序。`uniq` 只合并相邻重复行，所以通常先 `sort`；若想保留原顺序，不能直接套用 `sort | uniq`。`wc -l` 计换行符而不是“看起来的行数”，`-w` 与 `-c` 的定义也受实现和编码影响，统计 Unicode 字符时不要把字节数当字符数。

### 5.3 列与字符：`cut`、`paste`、`tr`

```bash
cut -d, -f1,3 -- "$LAB/inbox/data.csv"
paste -- "$LAB/inbox/left.txt" "$LAB/inbox/right.txt"
tr '[:lower:]' '[:upper:]' < "$LAB/inbox/sample.txt"
```

`cut -d, -f1,3` 按单个分隔字符取字段，简单 CSV 中可用；含引号、嵌套逗号或换行的真正 CSV 不应靠 `cut` 解析，应使用 CSV 感知工具。`paste` 按行并排合并文件，文件行数不同时要核对空缺。`tr` 做字符集合的逐字符转换或删除，不能把它当作一般字符串替换器；字符类受 locale 影响。

### 5.4 保存中间结果：`tee`

```bash
rg -n -- 'alpha' "$LAB" | tee -- "$LAB/work/matches.txt"
rg -n -- 'Beta' "$LAB" | tee -a -- "$LAB/work/matches.txt"
```

`tee` 同时把输入写到标准输出和文件。默认 `tee file` 会覆盖目标，`tee -a file` 才是追加；输出文件必须是演练目录中明确的新路径。对包含秘密的管道不要随手 `tee` 到日志，日志本身也属于需要保护和清理的副本。

### 5.5 从输入构造参数：`xargs`、空格与 NUL

传统的 `for name in $(...)` 或 `ls | xargs ...` 会在空格、换行、引号等文件名上出错。Unix 文件名不能包含 NUL 字节，因此可靠的文件名流通常用 `find -print0` 配 `xargs -0`：

```bash
find "$LAB/inbox" -type f -print0 \
  | xargs -0 -r -n 1 file --
```

这里的 `-r`（GNU xargs 的 `--no-run-if-empty`）避免没有输入时仍运行一次；`-n 1` 让演练输出易读。对于可用 `find -exec` 表达的工作，优先 `-exec ... {} +`，少一层解析。不要把不可信文件名拼进 `sh -c '...'`；如果确实需要 shell 语法，必须把路径作为独立 positional argument 传入并理解注入风险。

## 6. 归档与压缩：`tar`、`gzip`、`xz`、`zstd`

归档是把多个文件组织成一个容器；压缩是减少数据体积。`tar` 主要负责归档，可以调用 `gzip`、`xz` 或 `zstd` 压缩，后缀通常帮助读者识别格式，但不能代替验证。

### 6.1 先列出，再解包

```bash
tar -cf "$LAB/archive/files.tar" -C "$LAB/inbox" .
tar -tf "$LAB/archive/files.tar"
```

GNU `tar` 常用动作是：`-c` 创建、`-t` 列表、`-x` 解包；`-f` 后面紧跟归档文件名，`-C` 改变后续路径的工作目录。创建归档前尽量从明确的父目录配合 `-C`，避免把当前目录之外的绝对路径或意外的 `..` 一起打包。

查看压缩归档内容时可以：

```bash
tar -tzf "$LAB/archive/files.tar.gz"
tar -tJf "$LAB/archive/files.tar.xz"
tar --zstd -tf "$LAB/archive/files.tar.zst"
```

先 `-t` 检查成员名，再解到一个新建的恢复目录：

```bash
mkdir -p -- "$LAB/restore"
tar -xzf "$LAB/archive/files.tar.gz" -C "$LAB/restore"
find "$LAB/restore" -maxdepth 2 -print
```

来自不可信来源的归档可能含有绝对路径、`..` 路径、符号链接或大量文件。不要直接在主目录、项目根或系统目录解包；先列表检查，使用隔离目录，并在解包后检查实际落盘路径和链接目标。

### 6.2 三种压缩器

```bash
gzip -k -- "$LAB/archive/files.tar"
xz -k -- "$LAB/archive/files.tar"
zstd -k -- "$LAB/archive/files.tar"
```

`gzip`、`xz` 和 `zstd` 通常压缩一个文件，`-k` 保留未压缩的原文件（具体选项以本机 `--help` 为准）；它们不是目录打包器。常见组合是 `.tar.gz`（或 `.tgz`）、`.tar.xz`、`.tar.zst`，也可以由 GNU `tar` 直接创建：

```bash
tar -czf "$LAB/archive/files.tar.gz" -C "$LAB/inbox" .
tar -cJf "$LAB/archive/files.tar.xz" -C "$LAB/inbox" .
tar --zstd -cf "$LAB/archive/files.tar.zst" -C "$LAB/inbox" .
```

解压单个压缩文件时不要覆盖唯一副本；可先复制到演练目录，并检查输出文件名：`gzip -dk -- file.gz`、`xz -dk -- file.xz`、`zstd -dk -- file.zst`。不同发行版对 `zstd` 与 GNU `tar` 的集成版本可能不同，运行 `tar --help` 确认是否支持 `--zstd`。

## 7. 综合练习：只在上面打印并核对的 `$LAB` 中操作

1. **路径与目录练习**：用 `pwd`、`mkdir -p`、`cd` 建立 `inbox/raw` 和 `inbox/ready`，再用 `ls -la` 确认隐藏示例文件仍可见。
2. **安全复制与链接**：复制 `sample.txt` 到 `work/`，给副本改名；为它建立一个符号链接，用 `stat` 和 `file` 比较原文件、副本、链接三者的差异。
3. **文件名健壮性**：创建至少一个含空格、一个以 `-` 开头的文件名；用带引号的路径和 `--` 对它们执行 `stat`、`file`、`mv -i`，不得依赖未加引号的 glob。
4. **文本流水线**：用 `rg` 或 `grep` 找出 `sample.txt` 中的 `alpha`，通过 `tee` 保存结果；用 `sort | uniq -c` 统计重复行，用 `wc` 报告行、词和字节数，并写下一句解释 `uniq` 为什么要在 `sort` 后面。
5. **搜索与归档**：用 `find ... -print0 | xargs -0 ... file --` 检查所有演练文件；创建一个 `.tar.gz`，先 `tar -tzf` 查看清单，再解到 `restore/`，最后比较恢复目录中的文件名和内容。确认 `locate` 的结果可能滞后，并记录一次实际观察。

### 成功标准

- [ ] 能在每次批量操作前说出当前 `pwd` 和精确目标路径；
- [ ] 能解释 `--`、引号、glob、隐藏文件、空格文件名和 NUL 分隔的关系；
- [ ] 能区分复制、改名、符号链接、硬链接、归档与压缩；
- [ ] `find` 的匹配结果在交给 `xargs` 或其他命令前已经预览；
- [ ] 没有在练习目录之外运行递归删除，也没有把 `rm -rf` 当作恢复或清理办法；
- [ ] 能列出归档成员后再隔离解包，并从 `restore/` 找到原来的含空格文件名；
- [ ] 能在误操作时说明停止写入、寻找备份/快照、保留证据并寻求恢复工具，而不是继续覆盖现场。

## 8. 参考来源与版本边界

命令选项会因 GNU/Linux 发行版、BSD/macOS 版本和外部工具版本而异。以本机 `man command`、`command --help` 和发行版手册为准；本课的概念和安全原则不依赖某个特定 shell。

- [GNU Coreutils 手册](https://www.gnu.org/software/coreutils/manual/coreutils.html)：`pwd`、`ls`、`mkdir`、`touch`、`cp`、`mv`、`rm`、`rmdir`、`ln`、`stat` 等 GNU 工具。
- [`file` 工具官方仓库与文档](https://github.com/file/file)：`file` 命令的内容类型识别实现与版本信息。
- [GNU Findutils 手册](https://www.gnu.org/software/findutils/manual/html_mono/find.html)：`find`、`locate`、`xargs`，含 `-print0` 与 NUL 安全处理说明。
- [GNU Grep 手册](https://www.gnu.org/software/grep/manual/grep.html)：固定字符串、正则表达式、递归搜索和退出状态。
- [GNU Tar 手册](https://www.gnu.org/software/tar/manual/tar.html)：归档、列表、解包以及 `gzip`、`xz`、`zstd` 集成。
- [ripgrep 官方仓库与文档](https://github.com/BurntSushi/ripgrep)：`rg` 的实现、忽略规则、选项和版本信息。
- [Linux man-pages 项目](https://www.kernel.org/doc/man-pages/)：Linux 系统调用与用户空间命令手册页的官方项目入口；本课涉及命令的本机细节以 `man` 为准。
