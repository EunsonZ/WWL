# 03 · 量词、分组与选择

## 本课目标

控制模式单元的重复次数，明确量词的作用范围，并用分组和选择表达结构，而不是堆叠含糊的通配符。

## 量词只修饰前一个模式单元

这里的“模式单元”是正则中的一个小块，例如一个字面字符、一个字符类，或一整个分组。量词只控制紧挨着它左边的那个小块。

| 量词 | 次数 |
| --- | --- |
| `?` | 0 或 1 次 |
| `*` | 0 次或更多 |
| `+` | 1 次或更多 |
| `{m}` | 恰好 m 次 |
| `{m,}` | 至少 m 次 |
| `{m,n}` | m 到 n 次 |

例如：

```regex
ab+
```

表示一个 `a`，后跟一个或多个 `b`；它不是让整个 `ab` 重复。要重复整个片段，需要分组：

```regex
(?:ab)+
```

## 捕获组与非捕获组

圆括号有两个常见作用：

1. 改变结构和量词范围；
2. 记录子匹配，供提取或替换使用。

```regex
(ab)+
```

这是捕获组。若只需要结构，不需要保存内容，优先使用非捕获组：

```regex
(?:ab)+
```

可以先把非捕获组记成：**只打包，不保存结果**。分组编号为什么会变化，会在 [[编程知识/10-基础/01-正则表达式/04-捕获引用与替换]] 结合真实捕获结果解释。

## 选择分支要注意作用范围

竖线 `|` 表示“左边或右边”：

```regex
cat|dog
```

如果想匹配 `.jpg` 或 `.png` 文件名，可以写：

```regex
^[A-Za-z0-9_-]+\.(?:jpg|png)$
```

括号把选择限制在扩展名内部。下面这个表达式的含义不同：

```regex
^[A-Za-z0-9_-]+\.jpg|png$
```

它相当于 `(^[A-Za-z0-9_-]+\.jpg)|(png$)`：左分支只要求从开头匹配到 `.jpg`，没有被结尾锚点约束，所以 `abc.jpg-extra` 也能先匹配 `abc.jpg`；右分支则接受任何以 `png` 结尾的字符串。交替的优先级较低，复杂分支应显式分组。

## 可选片段

问号修饰一个分组时，可以让整段出现 0 或 1 次：

```regex
^https?://
```

这里只有字符 `s` 可选，因此匹配 `http://` 或 `https://`。若可选的是整个前缀：

```regex
^(?:https?://)?example\.com$
```

它允许有或没有协议部分。

## 精确量词优先于宽泛量词

当格式已知时，明确上限通常更可靠：

```regex
^[A-Z]{2}-[0-9]{4}$
```

比下面的模式更接近业务规则：

```regex
^.+-.+$
```

宽泛的 `.*` 与 `.+` 会接受大量意外字符，也更容易与后续模式产生回溯。不要因为短就默认更好。

## 可观察例子：版本号

目标：匹配 `v1`、`v1.2` 或 `v1.2.30`，最多三段数字。

```regex
^v[0-9]+(?:\.[0-9]+){0,2}$
```

拆解：

- `v[0-9]+`：前缀与第一段数字；
- `(?:\.[0-9]+)`：一个点号加一段数字；
- `{0,2}`：后面的整体最多重复两次。

它不会匹配 `v1.`、`v1.2.3.4` 或 `version1`。

## 练习

写一个表达式匹配以下订单编号：

```text
PO-2026-0042
SO-2026-1200
```

规则：

- 前缀只能是 `PO` 或 `SO`；
- 年份恰好 4 位 ASCII 数字；
- 序号恰好 4 位 ASCII 数字；
- 必须完整匹配。

再增加两个反例，写进 [[编程知识/30-实践/01-正则表达式实验区/02-练习场#练习 3 · 订单编号|练习场]]。

## 成功标准

- 我能解释量词修饰的是哪个单元。
- 只为结构分组时，我会使用 `(?:...)`。
- 使用 `|` 时，我会检查每个分支受到哪些锚点和上下文约束。
- 我优先写有上限、与业务形状一致的量词。
