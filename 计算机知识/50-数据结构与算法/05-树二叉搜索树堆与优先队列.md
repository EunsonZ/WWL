# 05 · 树、二叉搜索树、堆与优先队列

## 本课目标

学完后，你应该能够：

- 用根、边、父子、叶、深度和高度描述树，而不把“树形画法”当成结构本身；
- 写出二叉搜索树（BST）的排序不变量，并用它分析查找、插入和删除；
- 解释 BST 为何会退化成链表，以及平衡与随机化想解决的是什么；
- 区分堆的“父子优先级”与完全排序，掌握数组表示、上浮和下沉；
- 根据操作需求在排序数组、BST、堆和哈希表之间做有边界的选择。

## 1. 树是一种父子关系，不是磁盘上的目录图标

树由节点和边构成，选定一个**根**后，每个非根节点恰有一个父节点；从根到任一节点有唯一简单路径，因此没有环。没有子节点的节点是叶；节点到根的边数可称深度；节点到最深后代的最长边数可称高度（教材可能在“节点数/边数”上采用不同约定，讨论前要说明）。

```text
        8                 根
      /   \
     3     10             3、10 是 8 的孩子
    / \      \
   1   6      14          1、6、14 是叶
```

一棵树的节点数为 `n` 时恰有 `n - 1` 条边。文件系统目录结构看起来像树，但硬链接、挂载点、符号链接和 namespace 会让“路径视图”不再是一个简单的单一树；相关边界见 [[计算机知识/20-操作系统/01-Linux/03-目录结构挂载与文件系统|目录结构、挂载与文件系统]]。

## 2. 二叉搜索树：不变量先于操作

每个 BST 节点最多两个孩子。对任意节点 `x`，它的左子树所有键都小于 `x.key`，右子树所有键都大于 `x.key`；相等键放哪里、还是以值覆盖，必须由接口明确。这个**全子树**不变量比“左孩子小、右孩子大”更严格。

例如下列树是 BST：

```text
        8
      /   \
     3     10
    / \      \
   1   6      14
      / \
     4   7
```

中序遍历（左子树、节点、右子树）会得到有序序列 `1, 3, 4, 6, 7, 8, 10, 14`；这是检查不变量的有力工具，但“遍历结果刚好有序”不能替代每次更新后维护结构的责任。

```text
FIND(root, key):
    current = root
    当 current 不为空：
        若 key 等于 current.key：返回 current
        若 key 小于 current.key：current = current.left
        否则：current = current.right
    返回不存在

INSERT(root, key):
    沿与 FIND 相同的比较路径走到一个空孩子位置
    把新节点接在该位置；或按重复键规则更新已有节点
```

路径长度至多为树高 `h`，所以查找和插入是 `O(h)`。一棵节点分布良好的树高度近似 `log n`；这才是常见 `O(log n)` 说法的前提。

## 3. 删除为什么要分三种情况

删除叶节点只需断开父边。删除只有一个孩子的节点，可让父节点直接接到那个孩子。删除有两个孩子的节点时，常用做法是选其右子树的最小节点（中序后继）或左子树的最大节点（前驱）来替换，再在原位置删除那个至多有一个孩子的节点。

手算例：删除上图的 `3`，右子树最小键是 `4`。用 `4` 替代 `3` 后，再删除原来叶位置的 `4`，仍能保持左边小、右边大的全子树不变量。不要只把 `3` 的左孩子接到 `6` 左边而不检查全部范围；那种局部拼接极易把本应在右子树的键放错位置。

## 4. 反例：有序插入会把普通 BST 变成链表

按 `1, 2, 3, 4, 5` 的顺序插入一棵未平衡 BST，所有节点都只长右孩子：高度变成 `n - 1`，查找、插入、删除都退化为 `O(n)`。这不是实现“太慢”，而是不变量只保证排序，没有限制形状。

随机插入常使平均形状较好，但不为最坏情况提供承诺；输入可被预测或故意排序时尤其不够。下一课的 AVL、红黑树等在更新时主动保持高度边界；有时也会选随机化树结构。若需求只是精确键查找且不需要顺序或范围查询，哈希表常更合适，见 [[计算机知识/50-数据结构与算法/04-哈希表集合与冲突处理|哈希表、集合与冲突处理]]。

## 5. 堆：只承诺顶部最优，不承诺全局有序

**最小堆**满足：每个节点的键不大于它的孩子；最大堆反过来。这是局部父子不变量。因此最小堆根必为最小值，但兄弟节点、不同分支节点并不一定按大小排序。

反例：下图是合法最小堆，`5` 和 `3` 的相对位置却并非从左到右有序：

```text
        1
      /   \
     5     3
    / \
   9   7
```

完全二叉树可紧凑地存在数组中。若从 0 开始编号，节点 `i` 的父节点是 `(i - 1) // 2`，孩子是 `2i + 1` 与 `2i + 2`（存在时）。这带来良好局部性，也避免每个节点保存两个子指针。

```text
PUSH(heap, item):
    把 item 放到数组末尾
    当 item 比父节点更优：与父节点交换（上浮）

POP_MIN(heap):
    记录根；把最后一项移到根；缩短数组
    当根比更优的孩子差：与两个孩子中更优者交换（下沉）
    返回原根
```

`peek` 读取根是 `O(1)`；`push`、`pop`、改变优先级后修复通常为 `O(log n)`，因为只沿一条树高路径移动。把 `n` 个无序元素自底向上建堆可做到 `O(n)`，并非逐个 `push` 的 `O(n log n)`；原因是大多数节点靠近叶子、下沉距离短。

## 6. 优先队列是接口，堆是常用实现

优先队列的语义是“反复取得最高或最低优先级项目”，常见操作是入队、查看最优、取出最优。堆很适合它，但优先队列不等于“按插入顺序的 FIFO 队列”，也不等于“随时可按任意键快速查找”。

| 主要需求 | 结构起点 | 典型代价与限制 |
| --- | --- | --- |
| 取最小/最大并不断加入 | 二叉堆/优先队列 | `peek O(1)`，加入和取顶通常 `O(log n)`；内部并非全排序。 |
| 所有元素保持全排序、经常顺序遍历 | 平衡搜索树或排序数组 | 选择取决于插入频率与范围查询；排序数组插入可能移动很多元素。 |
| 精确键查找 | 哈希表 | 平均快，但没有键顺序与最小值语义。 |
| 区间、前驱后继、按序枚举 | 平衡 BST | 维护有序关系，代价通常是对数级更新。 |

Python 的 `heapq` 提供堆操作，但“优先级相同如何稳定、任务是否可比较、取消/更新任务怎样处理”仍是应用协议问题；Python 容器的哈希与迭代语义见 [[计算机知识/10-编程语言/01-Python/04-容器迭代器生成器与推导式|Python 容器、迭代器、生成器与推导式]]。C++ 中应阅读具体容器适配器和比较器契约，而不是把一种 STL 容器的失效规则套给另一种，参见 [[计算机知识/10-编程语言/02-C++/05-struct类模板与STL|struct、类、模板与 STL]]。

## 练习

1. 在纸上把 `5, 2, 8, 1, 4` 插入 BST；写出中序遍历，再删除根 `5` 并验证剩余序列仍有序。
2. 写出有序插入 `1` 到 `6` 形成的 BST 高度，并比较它与一棵近似平衡树的查找路径长度。
3. 给数组 `[1, 5, 3, 9, 7]` 画出最小堆；为什么不能仅凭数组不是完全升序就说它不合法？
4. 为“下载任务先处理最短估计时间”设计优先队列条目。再说明任务时间相同、任务取消、时间估计改变时，接口还需决定什么。

## 成功标准

- 你能用 BST 的全子树不变量判断一棵树是否正确，并解释中序遍历为何有序；
- 你能说明普通 BST 的 `O(log n)` 依赖高度，而有序输入可令其退化；
- 你不会把堆误称为已完全排序的数组，且能手算一次上浮或下沉；
- 你能根据“取最优”“按键找值”“范围查询”选择不同结构，而不是只比较名称。
