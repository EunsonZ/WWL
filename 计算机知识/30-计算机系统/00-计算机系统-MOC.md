# 计算机系统 MOC

<!-- ROUND3 NAV START -->

> [[计算机知识/00-开始/课程地图/07-计算机组成原理-课程地图|计算机组成原理课程]]。原专题与实验在下方继续保留。
<!-- ROUND3 NAV END -->


这门课回答一条贯穿编程、Linux、数据库、媒体处理和本地模型推理的问题：**源代码怎样变成真实机器上的进程，数据又怎样从文件或网络穿过内核、内存和处理器，最后形成可观察的结果？**

你不需要先会汇编，也不需要先安装高级剖析工具。课程从二进制、函数和数组直觉出发，建立一条端到端机制链：

```text
值与指令的位模式
  → ISA、寄存器与 CPU 执行
  → ABI、特权级、异常与系统调用
  → 进程、线程、调度与虚拟内存
  → 缓存、内存序、并行与数据移动
  → 受控 I/O 接口
      ├─ 打开文件：open(path) → VFS path walk / mount / dentry / inode
      │              → open file description → 进程 FD 表项
      │              → read/write(fd) → VFS / 文件系统
      │              → page cache / writeback 或 direct I/O
      │              → block layer / driver / device queue / DMA / 介质
      ├─ 文件映射：mmap(fd) → 建立 VMA 与文件偏移关系
      │              → 后续访问的 page fault → page cache / 文件系统 / 存储
      └─ 网络：socket FD → socket → TCP/UDP / IP / qdisc → driver / NIC queue / DMA → 对端
  → 观测、可证伪归因与性能闭环
```

> [!important] 数据路径不等于课程编号
> 表中 `08 → 10 → 11 → 12 → 13` 是从入口机制逐步增加存储细节的**阅读顺序**，不是一次文件请求实际向下穿栈的先后次序。还要区分 `open(path)` 的路径解析与 FD 建立、`read/write(fd)` 的已打开对象 I/O，以及 `mmap(fd)` 后由访问触发的缺页路径；网络则从 socket FD 分支，不经过普通文件的 path walk、inode 数据路径或持久介质。

> [!abstract] 学完后的能力
> 你将能沿层次解释“慢、占内存、打不开、写完却丢失、网络不通、并行结果错误”等现象；能区分抽象接口和具体实现；能选择证据定位一层，而不会从单个指标直接跳到结论。

## 开始前的 10 分钟诊断

首读只要求你能读懂变量、函数、数组与简单终端输出。不要因为尚不会汇编、内核调试或性能工具而推迟开始。先用下列检查选择路线：

- 若“虚拟地址、文件描述符、线程”都陌生，先走下方“新手最小系统模型”，首读只做纸面练习；不要把二十课误当成必须一次线性读完的清单。
- 会在终端中进入指定目录并执行 `python3 --version` 时，可做实践中的 Python 轨。
- 会读第一个编译错误，且 `cmake --version` 可用时，可做 C++20 轨；否则先读 [[计算机知识/10-编程语言/02-C++/01-编译链接与CMake|C++ 编译、链接与 CMake]]。
- 任何实验命令都在它自己的目录执行。看到路径不符、需要 `sudo`、要写真实用户数据或输出目录已存在时，先停止并回到实验的安全边界。

### 新手最小系统模型

`01 → 06 → 08 → 02 → 09 → 12 → 11 → 15`

完成后，你应能画出“源代码/指令 → 用户态与系统调用 → 进程地址空间 → FD/VFS → page cache/设备”的路径，并能为一个慢或失败的现象指出下一条可采集证据。随后按问题补 `03`（ABI）、`04/07/16—18`（处理器与内存性能）、`10/13/14`（I/O、文件系统与网络）、`19/20`（隔离与时间）。

## 四条问题路线

### 1. 从源代码到执行

读 `01 → 06 → 07 → 03 → 08 → 09`。你会把语言语义、机器指令、ABI、链接、加载、特权切换和调度串起来。C++ 应用入口是 [[计算机知识/10-编程语言/02-C++/00-C++-MOC|C++ MOC]]。

### 2. 从内存到性能

读 `02 → 04 → 05 → 07 → 09 → 15`。重点区分虚拟地址与物理驻留、cache line 与 page、并发与并行、吞吐与尾延迟。随后可进入 [[计算机知识/80-实践/06-计算机系统/03-缓存局部性benchmark/README|缓存局部性 benchmark]]。

### 3. 从路径到持久化

读 `08 → 10 → 11 → 12 → 13 → 15`，并用下面的数据路径核对每一层：

```text
打开阶段：
open(path)
  → syscall → VFS path walk / mount / dentry / inode
  → open file description → process FD table entry

已打开 I/O：
read/write(fd)
  → FD table → open file description / kernel file object
  → VFS / filesystem
  → page cache / writeback 或 direct I/O
  → block layer / driver / device cache → durable medium

文件映射：
mmap(fd)
  → 建立 VMA 与文件偏移关系
  → 后续访问发生 page fault
  → page cache / filesystem / storage
```

“`write` 返回”“另一个进程能读到”“文件系统元数据一致”“断电后一定存在”是不同主张。`fsync` 也必须结合文件、父目录、文件系统、挂载选项、设备缓存和硬件语义说明，不能写成跨平台绝对承诺。Linux 的操作入口见 [[计算机知识/20-操作系统/01-Linux/03-目录结构挂载与文件系统|目录结构、挂载与文件系统]]；可恢复实践见 [[计算机知识/80-实践/06-计算机系统/05-文件系统原子替换与fsync/README|文件系统原子替换与 fsync]]。

### 4. 从媒体文件到输出或网络

读 `10 → 11 → 12 → 13 → 14 → 15`，再进入 [[计算机知识/60-数据编码与媒体系统/18-从文件系统到媒体流水线的数据路径|从文件系统到媒体流水线的数据路径]]。这条路线解释 page cache、demux/decode 队列、背压、编码和 socket 为什么会共同影响 FFmpeg 的吞吐与音画同步。

## 五条进阶问题路线

### 5. 从语言实现到本机程序

读 `01 → 06 → 03 → 02 → 08 → 17`，再进入 [[计算机知识/70-编译原理/00-编译原理-MOC|编译原理 MOC]]。编译器负责把语言结构变成 IR、指令、section 与 relocation；系统课程负责解释 ABI、装载、地址空间、分配器和执行环境。两者共享对象，但不能把“IR 合法”当成“进程一定正确运行”。

### 6. 从容器中的性能问题到宿主机证据

读 `19 → 09 → 02 → 16 → 17 → 18 → 10 → 20 → 15`。先区分 namespace/cgroup 中看到的视图与宿主机资源，再检查地址翻译、分配器、NUMA/设备亲和性、I/O 和时钟；容器内指标不能自动代表物理机器全局状态。需要把嵌套页表和 virtqueue 算到具体地址与 index 时，接 [[计算机知识/30-计算机系统/24-虚拟化执行地址翻译与虚拟IO推演|虚拟化执行、地址翻译与虚拟 I/O 推演]]。

### 7. 从逻辑门到可量化 CPU

先按**组成原理课程子页**读 `01 布尔/时序 → 02 算术 → 03 数据通路 → 04 流水线`，再用 [[计算机知识/30-计算机系统/21-逻辑电路整数运算与CPU性能推演|逻辑电路、整数运算与 CPU 性能推演]] 做一次综合：从状态机和加法器，走到指令数据通路、流水线节拍、冒险罚时和 Amdahl 上界。随后用 [[计算机知识/30-计算机系统/22-缓存地址翻译一致性与存储层级推演|缓存、地址翻译、一致性与存储层级推演]] 将计算模型延伸到一次 load。这里的 `01—04` 均指 [[计算机知识/30-计算机系统/10-组成原理系统课程/00-计算机组成原理系统课程索引|组成原理课程索引]] 内的编号。

### 8. 从 cache miss 到 DRAM 与可靠性

读 `04 → 16 → 18`，先用 [[计算机知识/30-计算机系统/23-DRAM组织行缓冲刷新与ECC|DRAM 组织、行缓冲、刷新与 ECC]] 建立 bank/row/column、row buffer、refresh 与 ECC 的主解释，再做 [[计算机知识/30-计算机系统/22-缓存地址翻译一致性与存储层级推演|存储层级综合推演]]，把 DRAM 放回 TLB/cache/page-fault 的条件路径。教材中的 toy 映射不能用于猜真实机器地址映射。

### 9. 从 `execve` 到可观察输出

读 `03 → 06 → 08 → 02 → 09 → 12`，再做 [[计算机知识/30-计算机系统/25-从可执行文件到一行输出的端到端执行链|从可执行文件到一行输出的端到端执行链]]。这条路线以 `write(1,"hi\\n",3)` 为固定案例，逐层区分 ELF 装载、按需取指、系统调用返回、pipe 消费和最终呈现；输出改成文件或 socket 后，再接 `11/14`。

## 六组容易混淆的边界

| 不要混为一谈 | 关键区别 |
| --- | --- |
| API / ABI / ISA | 源码接口 / 二进制协作约定 / 处理器可见指令与状态 |
| 虚拟地址 / 物理页 / RSS / PSS | 进程命名空间 / 实际页框 / 进程驻留统计 / 共享页按比例统计 |
| CPU cache / page cache | 处理器缓存行 / 内核按页缓存文件内容；粒度、所有者和刷新规则不同 |
| path / dentry / inode / FD | 名字表达 / 路径缓存对象 / 文件系统对象元数据 / 进程访问句柄 |
| 并发 / 并行 / SIMD / SIMT | 时间重叠 / 同时执行 / 一条指令处理多元素 / GPU 线程组式执行模型 |
| ready / complete / visible / durable | 就绪通知只表示当时可尝试 I/O，仍可部分完成或返回 `EAGAIN` / 操作已达某完成点 / 其他观察者可见 / 故障后仍保存 |

## 配套实践与证据等级

[[计算机知识/80-实践/06-计算机系统/09-RISC-V特权态与系统调用/README|让一次ecall真正往返U/S]]将本课08的特权级与系统调用接到QEMU执行：逐指令跟踪陷入、寄存器保存、分发和返回，并比较未知调用与非法CSR。它运行真实RV64指令，尚无分页、调度或内存隔离，不代表完整内核课程。

- [[计算机知识/80-实践/06-计算机系统/00-计算机系统实践-MOC|计算机系统实践 MOC]]：数据表示、`mmap`、缓存、FD/pipe/`dup` 与文件系统原子替换。
- [[计算机知识/80-实践/03-C++/04-布局缓存与并行归约/README|C++ 布局、缓存与并行归约]]：把系统概念放进编译、CTest、计时与反汇编证据。
- [[计算机知识/90-资源/06-计算机系统速查|计算机系统速查]]：按 CPU、内存、I/O、文件系统和网络分层回忆与排障。

阅读实验结论时标出证据等级：

| 等级 | 能证明什么 | 不能自动证明什么 |
| --- | --- | --- |
| static | 文档、源码或配置结构自洽 | 真实运行路径已发生 |
| toy / CPU | 小输入上的机制和结果可复算 | 生产规模、Linux 专属或硬件路径 |
| Linux-specific | 指定内核/文件系统上的观察 | macOS、其他内核和其他挂载选项相同 |
| hardware | 指定 CPU、设备或加速器的测量 | 另一台机器或负载仍有同样收益 |
| manual | 人工交互或产品验收 | 已形成自动回归保证 |

性能实验先验证正确性，再固定输入、预热、重复并报告分布。绝不把一次更快、工具中出现某项能力或命令退出 0 写成普遍性能保证。

### 稳定课到可观察证据的覆盖图

| 课程 | 最小证据 | 当前边界 |
| --- | --- | --- |
| 01 | 数据表示与对齐实验 | 证实本编译器的输出，不是稳定序列化格式 |
| 02 | `mmap` 与进程级缺页计数 | 不暴露物理页，不保证 major/minor 数值 |
| 03 | C++ 编译/链接实验与静态工具 | 当前主要是编译与符号证据 |
| 04 | 缓存局部性 benchmark | 时间差是端到端样本，不等于直接计数 cache miss |
| 05 | C++ 并行归约实验 | CPU 结果不能继承给 GPU/SIMT |
| 06–07 | 纸面追踪加静态编译/反汇编对照，并可回到既有构建、装载与运行入口 | 尚无微架构内部观测；一段汇编或一次运行不直接证明流水线/缓存内部状态 |
| 08 | 纸面入口时序及 QEMU 中受控的 U/S `ecall` 往返 | 已有教学特权轨迹；尚无生产内核跟踪或宿主机特权设置验证 |
| 09 + 12 | FD、`pipe`、`fork`、`dup2` 实验 | 只证 POSIX 正常路径，不证调度次序 |
| 10 | 数据路径图和只读系统观察 | 无真实 DMA/驱动故障注入 |
| 11–13 | 临时目录中的原子替换与 `fsync` 实验 | 证正常返回和可见内容，不证突然断电后持久 |
| 14 | 本机 loopback 数据路径和纸面时序 | 尚无本域网络实验，不证真实链路行为 |
| 15 | 性能调查卡、基线与可证伪假设 | 尚无统一生产负载；工具输出不自动等于因果 |
| 16–18 | 地址翻译、分配器与拓扑的受控观察 | 计数和拓扑来自当前平台；不证明另一台机器或生产负载相同 |
| 19 | namespace/cgroup/虚拟化的只读探测或纸面边界图 | 不创建容器、不修改资源限制，也不证明云平台实现细节 |
| 20 | 单调时钟、墙上时间和 deadline 的受控实验 | 不模拟真实跨主机漂移，不把一次 NTP 状态当成全程同步证明 |
| 21–22 | 逐拍/逐地址综合表与独立小算例 | 数字是声明前提的教学构造，不是特定 CPU 实测 |
| 23 | DRAM bank 状态机、toy 地址映射与 ECC 边界 | 未探测真实 DIMM 映射、时序、刷新停顿或错误注入 |
| 24 | 两阶段地址手算与 split virtqueue 所有权表 | 未启动 VM，不证明某 hypervisor/transport 的真实退出次数与零复制 |
| 25 | ELF→取指→write→pipe 责任链与失败反例 | 未运行 syscall trace，不证明最终终端、文件或网络后端的时序 |

## 结课成功标准

- [ ] 我能从源代码追踪到指令、进程和系统调用，并区分 API、ABI 与 ISA。
- [ ] 我能区分虚拟内存、物理驻留、CPU cache、page cache、存储和持久化。
- [ ] 我能解释 path、目录项、inode、打开文件描述和 FD 之间的关系。
- [ ] 我能说明 `write`、`flush`、`fsync`、原子替换和崩溃一致性的不同保证与平台前提。
- [ ] 我能沿 I/O 或网络数据路径指出队列、复制、同步和背压可能出现的位置。
- [ ] 我会先建立基线与可证伪假设，再选择观测工具并只改一个变量。
- [ ] 我能把一个量化模型或媒体文件从 SSD 到 CPU/GPU/网络的路径画出来，并明确哪些环节尚未被实测。
- [ ] 我能解释 TLB、分配器、NUMA、容器资源视图和时钟选择怎样改变性能结论的适用边界。
- [ ] 我能手算一个状态机逐拍轨迹、一个 cache/DRAM 地址拆分和一次 GVA→GPA→HPA 翻译，并逐项声明 toy 前提。
- [ ] 我能从 ELF program header 追到一次 `write` 的返回值，区分内核接受、消费者读取、最终呈现和持久化。
