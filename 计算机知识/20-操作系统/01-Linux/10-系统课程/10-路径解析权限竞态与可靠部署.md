## 路径检查为什么会与实际访问脱节

假设程序允许读取 `/srv/uploads/` 下的文件。先做字符串前缀检查，再调用 `open`，至少有三种不同问题：`/srv/uploads-evil/` 也有同样前缀；`..` 和符号链接改变实际解析位置；检查结束后、打开之前，其他进程可能替换某个路径分量。前两种是名称解释错误，第三种是检查与使用之间的竞态（TOCTOU）。修好其中一种，不代表其他两种自动消失。

把路径转换成绝对规范路径再检查，只能描述检查当时的解析结果，不会冻结整个名称空间。文件名是可变关系，已打开的 FD 才把后续操作绑定到一个具体打开对象；但拿到 FD 后仍要核验对象类型和业务授权。

## dirfd 缩小问题，openat2 约束解析过程

先可信地打开根目录获得 `dirfd`，再相对它访问，比依赖进程当前工作目录更明确。但普通 `openat` 本身不阻止通过 `..` 或符号链接逃离这个目录。

Linux `openat2` 允许约束整个解析过程。`RESOLVE_BENEATH` 要求解析留在目录之下；`RESOLVE_IN_ROOT` 则把该目录当本次解析的根来解释绝对路径和 `..`。二者语义不同，不应不加分析地一起设置。`RESOLVE_NO_SYMLINKS` 禁止路径各分量的符号链接；普通 `O_NOFOLLOW` 只影响最后分量。魔术链接、跨挂载点是否允许也应显式决定。[^openat2]

```text
输入路径
  → 明确允许的相对路径语法
  → 可信 dirfd + 内核解析限制
  → 得到 fd
  → fstat 核验对象类型/所有者等必要属性
  → 在这个 fd 上执行操作
```

`openat2` 自 Linux 5.6 提供，但运行机器和用户态接口仍要检测。安全依赖这些限制时，遇到不支持不能静默退回“字符串前缀加 open”；应拒绝此操作，或使用已经单独论证安全的兼容实现。本库没有把自行遍历目录的短代码冒充通用安全替代品。

这些限制也不是授权系统：一个允许目录内的硬链接仍可能指向不应暴露的数据；命名空间约束不证明文件内容可信，之后的解析器还要考虑大小、编码、资源限制和格式验证。

## 权限按哪个对象检查

普通文件的 `r/w/x` 控制内容读取、写入和执行；目录的 `r` 主要关系到列出名字，`x` 是沿目录搜索/穿越，`w` 关系到改变目录项。删除文件通常由父目录的写和搜索权限及 sticky 等规则决定，而不是只看文件本身是否可写。把文件改成只读，不足以防止有权限的人删除它。

`umask` 参与新对象模式的形成，不会追溯修改旧文件，也不能代替 ACL、有效身份、capabilities 或挂载选项的检查。容器内的 root 与宿主权限如何对应，要结合 user namespace、能力集和挂载边界判断；容器名称空间不是自动等价于虚拟机隔离。[^path]

部署服务时还要追踪“谁能修改父目录、配置文件、可执行文件及其解释器/依赖”。只保护最终二进制而让低权限用户可写启动脚本目录，整体信任链仍可能被改变。

## Shell 重定向本质是按顺序操作 FD

```bash
command >out 2>&1
command 2>&1 >out
```

第一行先把 FD1 指向 `out`，再让 FD2 复制当前 FD1，所以两类输出都进文件。第二行先让 FD2 指向原来的 FD1，再重定向 FD1，因此标准错误仍走原来的输出。`2>&1` 不是一个持续追踪 FD1 的变量引用，而是当时进行的描述符复制。它与 [[计算机知识/20-操作系统/01-Linux/10-系统课程/09-FD共享epoll与非阻塞状态机|FD 与 OFD]] 是同一个机制的 Shell 表达。[^bash]

引用变量如 `"$path"` 是为了避免分词和通配展开；它不自动阻止把以 `-` 开头的值解释成选项，适用的命令还需正确使用 `--`。`set -e` 在条件、管道、子 Shell 等上下文有规则和例外，不是“任意失败都退出”的证明；`pipefail` 改变的是管道退出状态。关键部署步骤应显式检查错误、保存必要诊断并设计可重复执行的清理，而不是靠几个 Shell 开关替代状态机。

## 可靠替换与安全替换是两个维度

可信同目录里创建临时文件、写完内容并同步、重命名替换、同步父目录，是一种常见的单文件发布流程；崩溃持久性、错误分支和权限元数据见 [[计算机知识/20-操作系统/02-操作系统原理/10-系统课程/11-崩溃一致性与恢复状态机|文件替换与崩溃状态机]]。这里还要问：临时文件是否由程序独占创建？父目录能否被其他用户修改？是否无意改变权限、所有权、ACL 或扩展属性？替换是否跨文件系统？

即使单文件替换具有合适原子性，多文件部署也不自动整体原子。可以先发布一个完整版本目录，再切换受控入口；但旧进程已打开的 FD、已映射页面、动态配置读取和数据库 schema 兼容性仍需要过渡协议。数据库迁移不能靠回滚一个符号链接撤销，跨层保证见 [[计算机知识/85-综合贯通/04-跨层保证与反例矩阵|保证与反例矩阵]]。

## 自检与安全实验

实验只在临时目录创建普通文件和符号链接，演示“安全目录内的链接可解析到目录外”“路径替换后旧 FD 仍引用旧内容”，并验证两种重定向顺序。它不访问系统敏感文件，不设置特权，不执行真实部署，也不声称已测试 `openat2` 的所有内核竞争情形。

练习：一个文件不可写但其父目录可写，能否删除？一个 FD 的 `fstat` 检查通过后，把 FD 丢掉再按原路径重新打开会丢失哪项保证？为什么 HTTPS 传来一个文件名，也不能让这个名字自动安全？最后一问连接 [[计算机知识/35-计算机网络/10-系统课程/11-TLS身份验证重放与信任边界|身份认证与业务授权]] 和 [[计算机知识/10-编程语言/05-TypeScript/10-系统课程/10-运行时边界状态机与取消安全|运行时输入边界]]。
