# 03 · 指针、引用、const 与生命周期

## 本课目标

不再把指针当成“更难的变量”。指针是可为空、可重新指向的地址值；引用通常是已绑定对象的别名。两者都**不表达所有权**。每一次解引用都要先回答：对象还活着吗、地址有效吗、访问范围合法吗？

<!-- code-sync: ./lifetime.cpp -->
```cpp
#include <iostream>

void increment(int& value) {
    ++value;
}

int main() {
    int score = 41;
    int* address = &score;
    const int& read_only = score;

    increment(*address);
    std::cout << read_only << "\n";
}
```

此程序里 `score` 活到 `main` 结束，所以 `address` 与 `read_only` 都有效。`const int&` 限制通过该引用修改，不会使对象不可变；`address` 仍可修改它。

## 先画生命周期，再选语法

| 需求 | 常见表达 | 先检查 |
| --- | --- | --- |
| 必须有、无需转移对象 | `T&` / `const T&` | 调用期间对象是否存在 |
| 可选观察、可重绑定 | `T*` / `const T*` | 是否为 null、指向范围是否合法 |
| 转移唯一所有权 | `std::unique_ptr<T>` | 谁接管、何时销毁 |
| 共享所有权 | `std::shared_ptr<T>` | 是否确实有多个独立拥有者 |

返回局部变量的**值**通常安全；返回它的引用、指针或 `string_view` 通常是悬垂访问。把地址打印出来、在一次运行中“看起来能用”，不构成正确性证明。

生命周期风险不只来自函数返回。`vector` 扩容、容器删除、所有者移动/析构、映射解除和跨线程异步执行都可能让旧地址或 view 失效。读回调代码时要把“回调何时执行”与“捕获对象活到何时”画在同一条时间线上；`[&]` 捕获局部引用后让任务逃出作用域，是常见悬垂来源。

## 练习与成功标准

让 `increment` 再调用一次，并尝试把参数改为 `const int&`，观察编译器拒绝修改。成功标准：能指出该错误是 const 正确性问题，而不是链接问题；随后阅读 [[计算机知识/10-编程语言/02-C++/07-错误测试调试与Sanitizer|Sanitizer]]，了解如何捕捉更多运行时越界与 use-after-free。
