这里讨论模型投入实际程序后才出现的闭环：**输入经过程序编排，按权限从资料库检索，把有限证据交给 LLM，程序验证结果，再用离线评测和运行记录观察退化。** 这不是“接上向量数据库就完成了 RAG”，也不是把 JSON 当成事实保证。

## 系统边界先于工具名

| 部件 | 应负责 | 不应假装负责 |
| --- | --- | --- |
| LLM | 在给定 token、聊天模板、采样参数和上下文下生成候选文本或结构 | 保存权威事实、执行权限判断、保证引用/事实正确 |
| 程序（orchestrator） | 身份与权限、输入长度、检索编排、prompt 组装、schema 校验、重试、审计与执行前确认 | 让未验证的模型文本直接变成数据库查询、支付或系统命令 |
| 数据库/对象存储 | 原始文档、元数据、权限、版本、删除/保留策略 | 自动产生“语义相关”或消除过时和错误资料 |
| 搜索/向量索引 | 在已授权候选中按关键词、向量或混合排序召回 chunk | 理解最终任务、保证 chunk 支持答案、替代访问控制 |
| 评测与观测系统 | 固定测试集、比较版本、记录延迟/错误/成本信号 | 证明所有真实用户场景都安全或有效 |

> [!warning] 先守住数据与动作边界
> 检索文档、用户输入和模型输出都是**不可信数据**。它们不能修改程序权限，也不能越过数据库行级/租户隔离。任何有副作用的动作还应经过确定性业务规则、确认步骤和最小权限服务账号。

## 学习路径

1. [[AI/20-LLM/70-工程应用与工具链/01-HuggingFace与PyTorch工具链|Hugging Face 与 PyTorch 工具链]]：知道每个库在数据、模型、训练和加速层中的职责，先固定 chat template。
2. [[AI/20-LLM/70-工程应用与工具链/02-Embedding-Chunking与最小RAG|Embedding、Chunking 与最小 RAG]]：把检索看成受权限约束的候选发现，并运行不下载依赖的最小例子。
3. [[AI/20-LLM/70-工程应用与工具链/03-结构化输出Schema与错误恢复|结构化输出、Schema 与错误恢复]]：让程序校验“形状”，并区分可重试、不可重试和人工复核。
4. [[AI/20-LLM/70-工程应用与工具链/04-评测回归与可观测性|评测、回归与可观测性]]：分开测检索与生成，在不记录敏感正文的前提下发现退化。
5. [[AI/20-LLM/70-工程应用与工具链/05-私有部署认证TLS与边界|私有部署、认证、TLS 与边界]]：把本机服务限制在 loopback，理解认证、授权、TLS 和停止/恢复分别解决什么问题；本路线不提供公网暴露方案。
6. [[AI/20-LLM/70-工程应用与工具链/06-Agent工具调用状态与最小循环|Agent 工具调用、状态与最小循环]]：把模型建议保留为候选，让状态、权限、幂等键与终止条件由程序控制。
7. [[AI/20-LLM/70-工程应用与工具链/07-生产推理安全资源与许可证|生产推理：安全、资源与许可证]]：在真实模型接入前，以容量、日志、供应链和三份许可证记录做 Go / No-Go 门禁。

## 版本与可复现性清单

每次把真实工具接入前，记录模型仓库 ID 和 revision、tokenizer 与 chat template、框架/依赖版本、embedding 模型与索引版本、chunk 策略、评测集版本、硬件和运行日期。这里列举的工具资料均为**易变实现细节**：基础核验日为 **2026-09-01**，实施当天必须重核其 release、接口、许可、平台兼容性和默认网络行为，入口见 [[AI/90-资源/05-官方资料与版本核验记录|官方资料与版本核验记录]]。

## 工程完成标志

- 能说明一个请求在 LLM、程序、数据库和搜索索引之间分别做了什么；
- 能把检索指标与回答/引用指标分开报告，且测试集没有泄漏到提示或训练；
- 能为每次 prompt 或 chat template 变更保存模板、tokenizer、特殊 token、`add_generation_prompt`、采样/停止条件和固定离线回归集，而不是只保存可见文字；
- 输出不合格时会停止在程序边界，留下无敏感正文的失败原因；
- 能比较新旧版本并回滚模型、prompt/template、索引、Schema 或规则中的一个明确版本；有副作用的 Agent 动作还必须同时通过权限、确认和幂等门禁。
