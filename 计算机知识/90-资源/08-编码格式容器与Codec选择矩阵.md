# 编码格式、容器与 Codec 选择矩阵

先分层再选名字：序列化决定数据如何表示，压缩减少体积，加密保护机密性，容器承载多条流与元数据，codec 编解码媒体内容。`.mp4`、`.json` 或“支持某格式”都不是完整兼容性证明；版本、profile、播放器、硬件和许可证需现场复核。

## 非媒体数据层

| 类别 | 例子 | 主要优点 | 代价/陷阱 | 适合 |
| --- | --- | --- | --- | --- |
| Text serialization | JSON、CSV、TOML、YAML | 可读、调试和跨语言容易 | 体积大、类型/精度/规范化陷阱；YAML 不可信输入不可直接反序列化 | 配置、公开 API、人工审阅交换 |
| Binary serialization | CBOR、MessagePack、Protocol Buffers、Avro | 紧凑、类型和 schema 可控 | 工具链与 schema 演进复杂；跨语言实现需测试 | 稳定服务协议、事件、批量数据 |
| Compression | gzip、zstd、LZ4、Brotli | 降低存储和传输 | CPU、延迟、随机访问与压缩比权衡；压缩不是加密 | 文本、归档、传输层优化 |
| Encryption | AEAD（如 AES-GCM、ChaCha20-Poly1305） | 机密性、完整性、认证 | 密钥管理、nonce 唯一性、轮换和元数据泄露；不要自造算法 | 机密数据与备份，需配合密钥管理 |

## 容器与媒体 codec

| 层/格式 | 开放性/许可（需复核） | 质量/延迟倾向 | 兼容性与典型选择 |
| --- | --- | --- | --- |
| Matroska (`MKV`) | 开放规范；codec 许可另算 | 功能丰富，可低延迟配置 | 字幕、章节、多音轨强；部分网页/硬件生态不如 MP4。 |
| ISO BMFF (`MP4`/`MOV`) | 标准族；具体 codec/专利另算 | 可流式化/快速启动需正确 mux 选项 | 设备、网页和编辑软件广；容器支持不代表任意 profile。 |
| WebM | 开放 Web 媒体组合；具体 codec 仍需看实现 | 面向网络，常见低延迟配置 | 浏览器友好但老设备/专业软件兼容需测试。 |
| MPEG-TS (`TS`) | 标准族；codec 许可另算 | 面向传输和抗错误，不追求最小体积 | 广播、HLS 分片；随机访问和元数据体验较弱。 |
| H.264/AVC | 标准开放可读；编码/分发专利许可需复核 | 质量/体积成熟，硬件广，编码延迟可调 | 最大兼容性常选；不是免许可。 |
| H.265/HEVC | 标准公开；专利池/地区/产品许可复杂 | 比 H.264 更高压缩效率，编码更重 | 新设备较好，网页/软件支持和许可必须核验。 |
| AV1 | 开放、免版税目标生态；实现/专利声明仍需法律复核 | 高压缩效率，软件编码可能慢；硬件解码改善延迟 | 新网页/分发有吸引力；旧设备兼容不稳。 |
| VP9 | 开放 Web 生态常用；具体专利风险仍应复核 | 质量/体积较好，硬件支持分布不一 | WebM/YouTube 生态；通用编辑链需实测。 |
| ProRes / DNxHR | 厂商/行业 codec；许可和软件支持分别确认 | 中间码质量高、易编辑，体积大 | 后期制作与交换，不适合低带宽发布。 |

## 图像、音频、视频快速矩阵

| 媒体 | 低损/高兼容候选 | 高压缩候选 | 关键决策 |
| --- | --- | --- | --- |
| 图像 | PNG（无损、透明、图表）；JPEG（照片、有损） | WebP、AVIF | 透明、动画、浏览器/编辑器版本、解码 CPU 和许可声明。 |
| 音频 | WAV/PCM（无损但大）；FLAC（无损压缩） | AAC、Opus、MP3 | 语音/音乐、端到端延迟、采样率、硬件/浏览器与专利许可。 |
| 视频 | FFV1/无压或 ProRes/DNxHR（生产中间码） | H.264、HEVC、AV1、VP9 | 发布兼容、码率、硬件编解码、直播延迟、色彩/字幕/音轨和许可。 |

## 选择流程

1. 写清读者和交付：浏览器、移动端、剪辑、归档、直播还是内部数据交换。
2. 先定是否需要可读、schema 演进、随机访问、无损、加密和多流；再选容器与 codec。
3. 用目标设备/浏览器/播放器的真实样本测试：打开、seek、字幕、多音轨、色彩、音画同步、首帧时间、CPU/电量。
4. 记录版本、profile、编码参数、来源许可证与再现命令；“开放格式”不自动等于所有实现免费或兼容。
