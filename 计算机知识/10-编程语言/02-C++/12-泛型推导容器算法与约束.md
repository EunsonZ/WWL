# C++ 深化：从类型推导到可维护的泛型接口

> 阅读定位：C++20 核心；原有工具与仓库内容保留。返回 [[计算机知识/00-开始/课程地图/02-C++-课程地图|C++ · 课程地图]]；全域入口 [[计算机知识/00-开始/全局导航/00-总学习地图|计算机知识库 · 总学习地图]]。

## auto、模板推导与引用折叠

`auto x = expr` 通常得到一个新对象，推导中可能去掉顶层 const 和引用；`auto& x` 借用对象，`const auto&` 只读借用；`decltype(auto)` 按 decltype 规则保留更精确的类别，也因此容易意外返回引用。使用“更聪明”的推导前，先说明到底想复制还是借用。

模板中适当位置的 `T&&` 可以是转发引用，接收 lvalue 时 T 可能推导为引用类型，随后通过引用折叠得到正确结果。`std::forward<T>(x)` 按推导的信息传递值类别；无条件 `std::move(x)` 可能擅自移动调用者仍希望保留的对象。普通非推导场景的 `Widget&&` 则不是转发引用。

## concepts 检查接口形状，也需要语义约定

concepts/requires 可以表达“支持比较、能迭代、可以转换”等编译期要求，改善重载选择与诊断。但一个能返回 bool 的 `<` 不自动满足排序算法要求的严格弱序。若比较器在不同调用间随机改变答案，类型检查会通过，算法合同仍被破坏。

默认优先使用清晰的具体接口。模板适合静态多态和可复用算法，虚函数适合运行时开放的实现集合；`variant` 适合已知的有限替代项，`any` 进行类型擦除但失去许多静态约束。继承表达替代关系，不该仅为复用几行实现而滥用。多态基类的析构和对象切片必须专门考虑。

## 容器与迭代器是配套合同

vector 提供连续存储和良好局部性，插入或删除可能搬移元素；deque 的分段存储和失效规则不同；list 的节点稳定性需要用额外分配与较差局部性换取。map 与 unordered_map 在有序遍历、范围查询、哈希质量和重哈希失效上不同。不要只按“查找 O(1)”选型。

算法通常用半开区间 `[first,last)`，空区间可自然表示。`std::sort` 不稳定，`std::stable_sort` 保留等价元素的相对顺序；排序后进行二分查找还要求比较关系一致。ranges 让管道组合更清楚，但惰性 view 可能借用已经销毁的对象。视图像一张路线说明，不一定是结果数据的快照。

## 标准库的完整位置

除了容器和算法，还应知道 iterator、utility、tuple、optional、variant、string_view、span、chrono、filesystem、format、随机数、数值算法、智能指针、并发和原子库。C++20 的 ranges、concepts、coroutines、modules 解决不同层次的问题；协程提供挂起机制，不自带完整调度器，模块支持还要按工具链核对。

较少见但重要的内容有 ADL、重载解析、模板特化、SFINAE、constexpr/consteval、ODR、RTTI、虚继承、allocator、pmr、对齐和 placement new。应先能解释它解决什么问题和引入什么风险，再追求技巧性写法。

## 练习

实现一个返回满足条件的首个元素位置的算法，分别接受 vector 和 list。解释为什么不能假设随机访问，为什么返回迭代器后要约定容器生命期，以及空结果该如何表达。为自定义比较器验证 irreflexive 与传递性等关键性质。
