# 面向对象、数据类与类型标注

> [!abstract] 本课要回答什么？
> 当几份数据必须一起变化、且需要由同一套规则维护时，怎样用类表达它？何时只需函数、字典或 dataclass？类型标注能帮我们发现什么，又**不能**保证什么？

## 学完后你能做到

- 区分类（class）与实例（对象），并读懂 self、属性和方法；
- 让相关状态与操作靠近，但不把每个概念都包装成类；
- 分清继承的“是一个”关系与组合的“有一个/使用一个”关系；
- 在合适的地方实现 __repr__、__len__ 等特殊方法，而不把双下划线当成普通命名风格；
- 用 property 保住数据约束，用 @dataclass 少写样板代码；
- 理解 ABC、Protocol、泛型和静态类型检查器各自解决的边界问题。

## 先选简单工具，而不是先选类

类把**数据**与操作这些数据的**行为**捆在一起。官方教程也将类描述为把数据和功能打包的方式：每个实例可以保存自己的属性，并使用类定义的方法改变状态。[Python 类教程](https://docs.python.org/3/tutorial/classes.html)

这很有用，但不是“看见名词就建类”的理由。先问：

| 情况 | 通常先用什么 | 原因 |
| --- | --- | --- |
| 一个一次性的转换 | 函数 | 输入、输出清楚，不需要长期状态 |
| 松散的外部 JSON 数据 | dict / TypedDict（后续再学） | 字段可能不完整或会变化 |
| 一组稳定字段，主要是传递和比较 | @dataclass | 少写构造、显示、比较等样板 |
| 状态、约束和多次操作必须一起维护 | 普通类 | 可把规则放在改变状态的入口处 |
| 多种实现都要满足同一能力 | 函数参数、Protocol 或小型 ABC | 依赖能力，而不是复杂的继承树 |

> [!tip] 一个实用默认值
> 先写函数与清晰的数据结构；只有当它们反复一起出现、并且确实有不变量要维护时，再提炼成类。避免为了“面向对象”而增加层级。

## 类、实例、属性、方法与 self

class 是创建一类对象的蓝图；调用 ClassName(...) 会得到一个具体实例。实例属性属于各自的对象；方法是写在类中的函数。调用 account.deposit(20) 时，Python 会把 account 自动作为方法的第一个实参传入；按惯例把这个形参命名为 self。

~~~python
class BankAccount:
    bank_name = "示例银行"  # 类属性：所有实例都可通过类查到它

    def __init__(self, owner: str, opening_balance: int = 0) -> None:
        self.owner = owner                 # 实例属性：每个账户各自保存
        self._balance = opening_balance    # _ 是“内部使用”的约定，不是访问控制

    def deposit(self, amount: int) -> None:
        if amount <= 0:
            raise ValueError("存款金额必须大于 0")
        self._balance += amount

    def balance(self) -> int:
        return self._balance


alice = BankAccount("Alice", 100)
bob = BankAccount("Bob")
alice.deposit(20)

assert alice.balance() == 120
assert bob.balance() == 0
assert alice.bank_name == "示例银行"
~~~

这里的 owner 和 _balance 必须各自不同，所以在 __init__ 中写为 self.owner、self._balance。bank_name 放在类体里，是一个共享的默认值；只有确实应共享的常量或配置才这样写。

> [!warning] 易踩坑：可变的类属性
> members = [] 写在类体中会让**所有实例共享同一个列表**。每个实例都应有自己的列表时，在 __init__ 中写 self.members = []；使用数据类时改用 field(default_factory=list)，见下文。

## property：让读取像属性，让写入仍受规则保护

外部使用者希望写 account.balance，但你仍要拒绝负数或不合法格式。property 把“读取/赋值时要执行的逻辑”放在一个属性接口后面：不需要让调用者到处手工校验，也不需要先暴露可随意修改的内部变量。

~~~python
import math

class Celsius:
    def __init__(self, value: float) -> None:
        self.value = value  # 会进入 setter，而不是绕过检查

    @property
    def value(self) -> float:
        return self._value

    @value.setter
    def value(self, new_value: float) -> None:
        if isinstance(new_value, bool) or not isinstance(new_value, (int, float)):
            raise TypeError("温度必须是非布尔数值")
        try:
            value = float(new_value)
        except OverflowError as exc:
            raise ValueError("温度超出可表示范围") from exc
        if not math.isfinite(value):
            raise ValueError("温度必须是有限值")
        if value < -273.15:
            raise ValueError("温度不能低于绝对零度")
        self._value = value

    @property
    def fahrenheit(self) -> float:
        return self.value * 9 / 5 + 32


today = Celsius(20)
assert today.fahrenheit == 68
# today.value = -300  # ValueError
for invalid in (float("nan"), float("inf"), -300):
    try:
        today.value = invalid
    except ValueError:
        pass
    else:
        raise AssertionError("无效温度应被拒绝")
assert today.value == 20  # 失败赋值保留原状态
~~~

fahrenheit 只有 getter，是只读的派生值；value 有 setter，集中维护约束。不要为了把所有字段都“藏起来”而机械加 property：没有规则、没有兼容性需求的普通数据字段直接公开，往往更容易读。

## 继承与组合：优先组合，谨慎继承

继承表示较强的“**是一个**”关系：子类可复用或覆写父类的行为。查找属性时，Python 会沿着基类链继续查找；子类也可以覆写父类方法。[Python 关于继承的说明](https://docs.python.org/3/tutorial/classes.html#inheritance)

~~~python
class Animal:
    def speak(self) -> str:
        return "..."


class Dog(Animal):
    def speak(self) -> str:
        return "汪"


assert Dog().speak() == "汪"
assert isinstance(Dog(), Animal)
~~~

如果子类只是为了复用一点实现，继承往往会让耦合变重。更常用的默认方案是**组合**：一个对象“有一个”或“使用一个”协作者。

~~~python
class ConsoleNotifier:
    def send(self, message: str) -> None:
        print(message)


class OrderService:
    def __init__(self, notifier: ConsoleNotifier) -> None:
        self.notifier = notifier  # 组合，而不是 “OrderService 是 Notifier”

    def place(self, order_id: str) -> None:
        self.notifier.send(f"已创建订单 {order_id}")
~~~

组合使 OrderService 不必继承通知器，也便于以后换成邮件、测试替身或静默通知器。多重继承还涉及方法解析顺序（MRO）；在还不需要它时，保持单继承或组合会更容易维护。

## 特殊方法（dunder）：对接 Python 的语言协议

__repr__、__len__、__iter__、__eq__ 这类双下划线名字叫特殊方法（常称 dunder）。它们不是普通“私有方法”，而是 Python 在 repr(obj)、len(obj)、for x in obj、a == b 等语法或内置函数中调用的协议入口。

~~~python
class Playlist:
    def __init__(self, songs: list[str]) -> None:
        self.songs = songs

    def __len__(self) -> int:
        return len(self.songs)

    def __repr__(self) -> str:
        return f"Playlist(songs={self.songs!r})"


mix = Playlist(["晨光", "夜航"])
assert len(mix) == 2
assert repr(mix) == "Playlist(songs=['晨光', '夜航'])"
~~~

边界是：只在对象确实符合该协议语义时实现它。例如 __len__ 应表示自然的长度；__eq__ 应表示你希望的相等性；不要为“好看”而直接调用 obj.__len__() 或随意发明 __magic__ 名字。优先使用 len(obj)、repr(obj) 等正常接口。

## @dataclass：数据为主的类

dataclasses 会根据**带类型标注的字段**生成一些特殊方法，例如 __init__() 和 __repr__()；字段出现的顺序也决定这些生成方法中的字段顺序。[dataclasses 官方文档](https://docs.python.org/3/library/dataclasses.html)

~~~python
from dataclasses import dataclass, field


@dataclass
class Book:
    title: str
    pages: int
    tags: list[str] = field(default_factory=list)

    def is_long(self) -> bool:
        return self.pages >= 400


book = Book("Python 入门", 320)
assert book.tags == []
assert book.is_long() is False
~~~

Book("Python 入门", 320) 的构造方法和可读的 repr 不必手写；方法仍然可以照常定义。default_factory=list 的关键是：每次新建 Book 都得到新的列表，避免共享可变默认值。

@dataclass(frozen=True) 会阻止对字段重新赋值，适合表现为不可变的值对象；它**不等于深度不可变**，其中的列表等可变对象仍可被修改。默认比较、排序、哈希、slots 等生成策略都有具体规则，应当按模型语义选择，不要为追求“性能”或“不可变”盲目打开选项。

## ABC 与 Protocol：两种“我需要什么能力”的表达（进阶选读）

> [!info] 第一遍先掌握组合即可
> ABC、Protocol 和后面的泛型主要用于多人项目、框架边界与静态类型检查。第一次学习类时，能用普通类、组合、property 和 dataclass 完成小模型就已经达标；本节及后面的泛型小节可以稍后回看。

有时系统需要的不是某个具体类，而是“能保存”或“能发送”的对象。

- ABC（抽象基类）是运行时的继承契约。继承 ABC 并标记 @abstractmethod 后，未实现所有抽象方法的子类不能被实例化。它适合框架确实需要共享基类实现或明确层次时。[abc 官方文档](https://docs.python.org/3/library/abc.html)
- Protocol 主要服务于**静态结构化子类型**（静态鸭子类型）：对象不必声明继承它，只要有兼容的方法签名，类型检查器就可接受它。它很适合让业务代码依赖小能力而非具体实现。[typing.Protocol 官方文档](https://docs.python.org/3/library/typing.html#typing.Protocol)

~~~python
from abc import ABC, abstractmethod
from typing import Protocol


class Storable(ABC):
    @abstractmethod
    def save(self, text: str) -> None:
        """子类必须提供保存行为。"""


class Notifier(Protocol):
    def send(self, message: str) -> None: ...


class ConsoleNotifier:
    def send(self, message: str) -> None:
        print(message)


def announce(notifier: Notifier) -> None:
    notifier.send("完成")


announce(ConsoleNotifier())  # 静态检查器可接受：不必显式继承 Notifier
~~~

Protocol 默认不是运行时校验器。即使加上 @runtime_checkable 后拿它做 isinstance，检查也只是很浅的属性存在性检查，**不会验证参数和返回值的类型签名**。因此它不能取代输入验证、认证或业务规则。

## 类型标注：描述意图，交给静态工具检查

类型标注写在变量、参数和返回值旁边：

~~~python
def add_tax(price: float, rate: float) -> float:
    return price * (1 + rate)


names: list[str] = ["Ada", "Guido"]
~~~

它告诉读者和类型检查器 add_tax 期望什么、产生什么。Python 运行时**不会因为标了 float 就自动拒绝字符串**；官方 typing 文档明确说明，运行时不强制函数和变量标注，类型检查器、IDE、linter 等第三方工具可以使用它们。[typing 官方文档](https://docs.python.org/3/library/typing.html)

### 进阶选读：用泛型保留类型关系

泛型用一个类型变量表达“输入和输出保持同一种未知类型”，而不是把它们硬写成 object：

~~~python
from collections.abc import Sequence
from typing import TypeVar

T = TypeVar("T")


def first(items: Sequence[T]) -> T:
    if not items:
        raise ValueError("items 不能为空")
    return items[0]


assert first([10, 20]) == 10       # 推断为 int
assert first(["a", "b"]) == "a"  # 推断为 str
~~~

list[str] 表示元素预期都是字符串；Sequence[T] -> T 则保留调用处的具体类型。现代 Python 3.12 还支持 `def first[T](...) -> T:` 这样的新泛型语法；为了阅读较旧项目，本课先使用 TypeVar 形式。泛型解决的是静态表达与工具推断，不会在运行时逐个检查列表里的元素。[typing 泛型说明](https://docs.python.org/3/library/typing.html#generics)

> [!important] 类型检查器不是运行时保证
> 类型检查器能在运行前发现很多“把 str 当 int”“漏处理 None”之类的不一致，但它只检查被纳入检查的代码和它能理解的路径。网络请求、JSON、用户输入、插件返回值和不受你控制的库仍是运行时数据：在边界处解析、验证并处理异常，不能因为写了 user_id: int 就跳过检查。

## 把这些工具放在一起：一个小设计

下面的代码刻意没有建“大而全的用户体系”：User 是稳定数据，用数据类；通知依赖的是能力，用 Protocol；输入边界仍在运行时检查。

~~~python
from dataclasses import dataclass
from typing import Protocol


@dataclass(frozen=True)
class User:
    name: str
    email: str


class Notifier(Protocol):
    def send(self, destination: str, message: str) -> None: ...


def subscribe(raw_email: str, notifier: Notifier) -> User:
    email = raw_email.strip()
    if "@" not in email:  # 示例校验；真实邮箱规则应按产品需求设计
        raise ValueError("邮箱格式不正确")

    user = User(name="新用户", email=email)
    notifier.send(user.email, "订阅成功")
    return user
~~~

这里 Notifier 的标注帮助替换实现和测试；if "@" not in email 才是运行时的业务检查。二者合作，不互相替代。

## 常见误区

| 误区 | 更准确的做法 |
| --- | --- |
| “所有字段都必须私有，并配 getter/setter。” | Python 没有真正的私有字段语法；无规则的普通数据可直接公开，有约束或兼容性需要时再用 property。 |
| “继承是复用代码的首选。” | 只有稳定的“是一个”关系才继承；仅为协作或替换实现时，优先组合与小接口。 |
| “@dataclass 会验证 title: str。” | 它利用带标注的字段生成方法，但通常不检查字段实际类型；需要时自行验证或使用专门的校验层。 |
| “写了标注，程序就安全。” | 标注主要供静态工具使用；外部输入仍要在运行时验证、处理异常。 |
| “Protocol 可以做完整的运行时接口验证。” | 默认只用于静态检查；运行时可检查版本也不能验证方法签名类型。 |
| “双下划线方法是高级命名。” | 它们是语言协议挂钩；只实现有明确语义、并由 Python 调用的特殊方法。 |

## 动手练习：组合书籍数据与阅读进度

这个练习刻意让 dataclass 和 property 分工，避免“dataclass 字段与同名 property 互相覆盖”的陷阱：

1. 建立 `@dataclass(frozen=True) BookInfo`，字段为 `title: str` 与 `total_pages: int`。它负责保存以数据为主、创建后不应随意改变的书籍信息。
2. 建立普通类 `ReadingProgress`。它的 `__init__(self, book: BookInfo, current_page: int = 0)` 先保存 `book`，再通过 `self.current_page = current_page` 进入下面的 setter。
3. 在 `ReadingProgress` 中用 `_current_page` 保存内部值，用 `current_page` property 读取；setter 要拒绝小于 0、超过 `self.book.total_pages` 的值，并在接受后写入 `_current_page`。
4. 新建只读属性 `is_finished`，当当前页等于总页数时为 `True`。
5. 写函数 `show_progress(progress: ReadingProgress) -> None`，输出书名、当前页与总页数。核心练习到这里已经完成。
6. **进阶选做**：写一个 `ProgressReporter(Protocol)`，声明 `report(progress: ReadingProgress) -> None`；再写 `ConsoleReporter`，并新增 `report_progress(reporter: ProgressReporter, progress: ReadingProgress) -> None`。这个函数依赖 Protocol，而不是具体类。

> [!warning] 不要声明同名字段和 property
> 不要在同一个 dataclass 里既写 `current_page: int`，又定义 `current_page` property。dataclass 会检查类属性并生成构造方法，property 也是类属性描述器；直接重名会造成令人意外的默认值或字段顺序错误。初学阶段用本练习的清晰分工：`BookInfo` 使用 dataclass，带持续约束的 `ReadingProgress` 使用普通类和 `_current_page`。

### 成功标准

- [ ] `BookInfo("Python 入门", 320)` 能被两个不同进度对象复用，而两个 `ReadingProgress` 实例的当前页互不影响。
- [ ] `current_page = -1` 与超过 `progress.book.total_pages` 都会抛出 `ValueError`。
- [ ] `current_page == progress.book.total_pages` 时 `is_finished is True`，且不能直接给 `is_finished` 赋值。
- [ ] `show_progress(progress)` 能输出正确书名与页数。
- [ ] **进阶选做**：`report_progress(ConsoleReporter(), progress)` 可以工作，并能说明 Protocol 为什么不要求显式继承。
- [ ] 你能指出一处仍须做运行时校验的外部输入，并解释为什么类型标注不够。
