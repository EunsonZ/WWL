# 从一句话到学习与生成

**读者问题：** 同一句话在训练时一次算完、生成时却逐个词出现；哪些格子能看、哪些格子要负责，为什么不是同一件事？本页用一个短序列贯穿可运行的、受限的**位置条件 softmax 模型**。它没有 attention，也不读取输入词 ID，因而**不是 Transformer**；它让概率、交叉熵、梯度、一次 SGD 与用自身前缀的 EOS 停止可逐数复算。完整 Transformer 是本科加深入口，不是开始本页的硬先修：[[AI/20-LLM/20-架构/01-Transformer完整数据流|完整数据流]]。

![序列、责任与位置失败图](lm-learning-map.svg)

图的替代文字：五个输入格从左到右是 `<BOS>、我、爱、蓝、猫`，右移标签是 `我、爱、蓝、猫、<EOS>`；位置 logits 与共享 bias 经 softmax 产生概率并汇总梯度；生成按自己的前缀长度取下一个 token，在 EOS 停止。toy 读取位置但不读取词内容。

## 先作直观预测：一条短序列的五个名字

令完整 token 为 $z=(\text{BOS},\text{我},\text{爱},\text{蓝},\text{猫},\text{EOS})$。训练输入 `shift` 是前五格，标签是右移一格：

| 名称 | 这条序列中的内容 | 作用 |
| --- | --- | --- |
| `shift` | BOS, 我, 爱, 蓝, 猫 | 同一次前向的输入 |
| `firstanswer` | 我 | BOS 后的第一个目标 |
| `teacherprefix` | BOS, 我, 爱 | 训练第三次预测时的真实前缀 |
| `generatedprefix` | BOS, 我, 喜欢 | 部署时模型先前自己给出的前缀，可能不同 |
| `EOS` | EOS | 也是一个可学目标；生成到它才可按约定停止 |

所以训练位置 2 从 `teacherprefix=(BOS,我,爱)` 预测 `蓝`；生成时若已走到 `generatedprefix=(BOS,我,喜欢)`，下一个条件分布是另一件事。teacher forcing 是观测序列似然的并行计算方式，并不保证模型在自己造成的前缀上同样正确。**可停点：** 现在应能在不看下文的情况下写出 `shift`、右移标签、EOS 与两种前缀各是什么；做不到先停在这里。

## 再看机制：四种 mask 各守一条边界

| mask / 标记 | 问题 | 本例的责任 | 不能替代谁 |
| --- | --- | --- | --- |
| causal attention mask | query 能读哪些 key？ | 位置 $i$ 只能读 $j\le i$，防止偷看未来 | 不忽略 padding，也不决定损失分母 |
| padding / key mask | 哪些输入格不是真实 token？ | 补齐批次的 PAD 不能成为可读 key | 不阻止本句读未来 |
| document / packing mask | 拼接样本能否跨文档读？ | 阻止句 A 把句 B 当作前缀 | 不指定标签是否监督 |
| loss mask（`ignore_index`） | 哪些位置对参数负责？ | 仅有效标签进入交叉熵与分母 | 不改变 attention 可见性 |

本页 toy 的标签合同采用 `ignore_index=-100`：它是**标签值**，表示“这个目标不计损失”，程序先跳过它，因而它是被接受的合法标记而非要拒绝的标签。这与书中某个教程可写的 `include` 布尔掩码不同；`include=False` 是选择规则，不能把 `-100` 当词表内 token、再去取概率。现有 `AI/80-实践/01-微型Transformer预训练/tiny_transformer.py` 则以词表内 `pad_id` 作为 PyTorch `ignore_index`；从本 toy 迁移时须把本页的 `-100` 转换成该 tokenizer 的 `pad_id`，不能把两个数值合同混用。令有效标签集合为 $V=\{t:y_t\ne-100\}$，则

$$L=-\frac{1}{|V|}\sum_{t\in V}\log p_\theta(y_t\mid z_{\le t}),\qquad |V|>0.$$

两个局部批各有 $S=8$ 个槽位，有效目标数分别为 2 与 6；若各自 NLL 和为 $1.0$ 与 $10.2$，全局 token 平均是 $(1.0+10.2)/(2+6)=1.4$。它不是两个局部均值 $(1.0/2+10.2/6)/2=1.1$，也不是把后者的 $10.2$ 除以 batch size 2。程序检查全批无有效目标时拒绝除零。

梯度共享同一参数时是相加而不是二选一：$\nabla_\theta(L_A+L_B)=\nabla_\theta L_A+\nabla_\theta L_B$。若框架先把每个微批除以自己的有效数，累积时需按各自有效数加权，才能等于整个批次的 token 平均。

### 程序实际执行的概率、梯度和一次更新

程序参数是 $A\in\mathbb R^{T\times V}$（位置 logits）和共享词表偏置 $b\in\mathbb R^V$，故 $z_{tv}=A_{tv}+b_v$、$p_{tv}=\operatorname{softmax}(z_t)_v$。它刻意不把 $x_t$ 送进分数函数；`inputs` 仍用于说明 shift 合同。这正是“固定位置能背答案、改位置会失败”的受限反例，绝非语言理解模型。

对 `BOS 我 爱 蓝 猫 → 我 爱 蓝 猫 EOS`，$T=5,V=7$，初始 $A=b=0$，故 $p_{0,\text{我}}=1/7\approx0.142857$，$L=\log7\approx1.945910$ nat。有效标签的梯度为

$$\frac{\partial L}{\partial A_{tv}}=\frac1{|V_{\rm valid}|}(p_{tv}-\mathbf1[v=y_t]),\qquad \frac{\partial L}{\partial b_v}=\sum_t\frac{\partial L}{\partial A_{tv}}.$$

第二式中的 `+=` 是共享 bias 汇总所有有效位置的路径，shape 是 $A:(5,7)$、$b:(7)$。运行一次学习率 $8$ 的同步 SGD 后，位置 0 的 `我` 概率从 $0.142857$ 升高，复算损失降低；程序断言这两个事实。随后从 `[BOS]` 贪心地按已生成前缀长度取位置 0、1、… 的 logits，实际轨迹为 `BOS → 我 → 爱 → 蓝 → 猫 → EOS`，选出 EOS 即停止。它使用“自己的前缀长度”，但因 toy 不读取词 ID，改变内容而不改长度不会改变答案，这正是故意失败。

## 没有方法提示的联合条件迁移

> 两条独立句子被放进同一次训练计算：左句是 `BOS 我 爱 EOS`，右句是 `BOS 你 爱 EOS`，末尾为了组成张量补了一个空位。写出一份可交付的边界说明：哪些 token 可以成为哪些预测的上下文、空位怎样不影响学习、总损失怎样报告，以及若第一句运行时改用模型先前输出会改变什么。

<details><summary>答案</summary>

document / packing mask 阻止跨句读取；padding/key mask 令 PAD 不能作 key，loss mask 把 PAD 标签写为 `-100`。分母是两句中所有非 `-100` 标签数，而不是句数。sampled prefix 来自模型随机变量，条件分布与数据前缀不同；这是部署覆盖问题，不能把它误说成 causal mask 失效。

</details>

## 两个反例与可复算入口

**反例一：只用 causal mask。** 若 PAD 仍可作 key 或标签，模型会学习无意义的补齐格，指标分母也被稀释。

**反例二：位置而非内容。** 令相同输入 token `爱` 分别在位置 0 与 1；测试把位置 0 的最大概率词设为 `我`、位置 1 设为 `猫`，输出不同。这证明位置参数能改变分布；反过来，颜色 `蓝` 改成 `红` 而提示长度仍为 5 时，本 toy 仍给相同预测，因为它不读取内容。加位置表不等于实现相对位置、RoPE 或 Transformer。

运行 `python3 lm_toy.py -v` 会执行 softmax 概率、交叉熵、`p-y` 梯度、共享 bias 汇总、SGD、贪心 EOS 生成、接口拒绝和位置/内容反例。四种 mask 在本程序只以责任谓词模拟，**没有执行 attention**；真正 attention 的可见性验证要到本科入口。它只用标准库，既不下载模型，也不训练真实网络。
