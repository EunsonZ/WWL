# Web平台开发：从文档到可靠交互

**读者问题：HTML文档怎样变成可靠交互与请求状态？** 这条路线用一个原创课程查询与阅读列表回答：浏览器先解释文档中的结构和原生控件，CSS决定它们占据的位置，事件表达人的意图，状态模型决定界面，Fetch把远端的异步结果带回来。它选择Web平台方向，未覆盖移动、嵌入式、游戏平台或全部计算机本科知识单元。

项目的任务是“查到课程，加入阅读列表，知道查询是否仍在等待”。课程名称、分钟和故障场景全部是合成教学材料，不是真实课程目录；阅读列表只在页面内存中，刷新清空，查询服务器没有写入业务。

按表中顺序读是默认路线，也可先跑80，再用失败现象找解释。输入框默认“Web”返回两门，35与50分钟；加入两门总量85分钟，移除35分钟的一门后剩50分钟。这是贯穿算例，不代表教学时长评估。

需要先理解 `await` 与宿主异步调度时，去读 [[计算机知识/10-编程语言/05-TypeScript/04-Promise事件循环并发与取消|Promise、事件循环与取消主解释]]。这里用普通JavaScript模块，并不要求先学TypeScript高级类型。网络来源不是可信类型时，去读 [[计算机知识/10-编程语言/05-TypeScript/10-系统课程/07-Web边界安全与全栈协议|Web协议与安全边界]]；本课只实现这个小接口的运行时验证。

[HTML表单规范](https://html.spec.whatwg.org/multipage/forms.html)是原生控件行为依据；本项目的任务选择、状态图和算例属于原创设计。相关命令通过与否在实验页按层写清，不以模型执行证明真人理解或WCAG符合性。
